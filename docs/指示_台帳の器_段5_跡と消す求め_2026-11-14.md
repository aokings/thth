1. **跡の試験**（§2）: git の commit どうしの差・判断の記録の書き換えの赤・取り込みの跡・判断から版と元の記録へたどる、の試験が通る（先に赤を見る）。
2. **実物でたどる**: こぴちゃの過去の 2 つの commit（`8ead0fc`・`3398d6d28`）の差が、期待した記録だけを出す。MMR の訂正とキョンシーの監査を、判断から「対象の版」と「元の記録」へたどれて、その判断が今の版に効くかが出る。
3. **消す求めの試験**（§3）: 見本の台帳に住所を 1 つ書き、訂正し、判断の理由にも書き、材料に出し、封をしてから、消す。消したあと、台帳のフォルダ（`.git/` を除く）のどこにも、住所の字も、住所を含む版の指紋も無い。結果の記録に、場所ごとの「消した・消していない・確かめていない」と、再現できない世代の範囲が出る。git の履歴は「確かめていない」のまま、「消し終わっていない」と言い続ける。
4. **柵**: 番号が消えると赤。判断の記録を書き換えると赤（消す求めの結果に載った範囲だけ通す）。止めるは消す求めのあとも効いたまま。「消した」の印だけでは消し終わりにならない。

重い穴 = 消したはずの中身か、その指紋が器の記録に残る・消す求めを装って「止める」や「だめ」を外せる・消す求めを装って受け入れなしの中身が CI を緑で通る・番号が消えたのに緑。

## 2. 跡

### 2.1 git の commit どうしの差

- `thth register diff <前>..<後>` は、今は器の控えの名どうし。台帳のフォルダが git の作業木のとき、`<前>`・`<後>` に commit（か `HEAD`・枝の名）を受ける。器は、宣言の置き場に入るファイルだけを `git show <commit>:<道>` で取り出し、repo の外の一時の置き場に並べて読む（作業木は変えない。git は読むだけの命令に限る。シェルを通さない）。
- 出す物は控えどうしの差と同じ: 足した・変わった・退役した・消えた記録（種類と番号）。内側の単位を持つ種類は、単位の指し先の足した・消えたも出す。**番号が消えたら赤**。ただし §3 の結果の記録に載った番号は赤にしない。
- 変わった記録には、結びの候補（`J.candidates` の形）を付ける。器は結ばない。
- git の作業木でない台帳・その commit に宣言の置き場が無いときは、「取り出せない」と言う（控えの名で打ち直す道を添える）。
- `subprocess` を使う部品が 1 つ増える。`tests/test_register_base.py` の `SUBPROCESS_ALLOWED` に足し、理由を注に書く。git は決まった場所の物だけを使い、PATH もシェルも使わない（`seal.py` の openssl と同じ決め方）。

### 2.2 判断の記録は足すだけ

- `thth register check --against <前>` で、判断の記録（`.thth/judgments.jsonl`）が `<前>` の時点の記録の**続き**（前の全バイトが今の頭と同じ）でなければ赤（`judgments_rewritten`）。`<前>` は commit か控えの名。
- §3 の消す求めで書き換えた行は、3.4 の印の形になっていて、封が言う「消す求めの結果」に載っていれば、その行だけ続きの比べから外す（前の行と、問い・対象の番号・結論・日時・番号が同じであることは見る）。

### 2.3 取り込みの跡

- 取り込み（`adopt`）・束の取り込み（`merge`）のたびに、控えの目録（`snapshots/<控えの名>.json`）に、束の sha256（今ある目録の指紋でよい）に加えて「集めた者」（`--by`）と「検めた者」（`--checked-by`。無ければ空で、検めていないと出る）を残す。今 `--by` があれば、足すのは `--checked-by` だけ。
- `thth register links <記録>` と `diff` の出力に、その版がどの取り込みで入ったか（控えの名・日時・集めた者・検めた者）を出す。

### 2.4 判断から、版と元の記録へたどる

- `thth register links <記録>` の判断の一覧に、判断ごとに: 対象の版・依る所の指紋・**今の版に効くか**（効く・古い・消えた指し先）・元の記録（`inspects` で作られた判断なら、元の表の種類と行の番号。命令で足した判断なら、誰が・いつ）を出す。
- 元の記録は元のまま置く。器は索引だけを持つ（今のとおり）。

## 3. 消す求め

命令は `thth register erase`（4 つの動詞）。4 種類の記録は `.thth/erase/<求めの番号>/` に 1 つずつ JSON で置く（判断の記録とは別の置き場。足すだけ）。

### 3.1 求め — `erase request <記録> [--field <欄>] [--unit <単位>] --by <誰> --why <理由の種類>`

- 持つ物: 求めの番号・誰が・いつ・何を（記録の番号・欄・単位）・理由の種類（`personal`・`rights`・`mistake`・`other`）。
- **持たない物: 消したい中身そのもの。** `--why` は種類の語だけで、文を取らない（文に中身を書いてしまうのを防ぐ）。
- 求めを置いただけでは、何も消えない。出口には効かない（出すのを止めたいなら、別に「止める」を足す。求めの出力でそう知らせる）。

### 3.2 範囲の判断 — `erase scope <求め> --versions <all・current・控えの名…> --confirm`

- 本人の判断（二段: 1 回めは消える範囲の見積りを出すだけ。`--confirm` で置く）。持つ物: どの番号の・どの欄の・どの版まで。
- 範囲は求めより広げられない（求めに無い番号・欄は断る）。
- 見積りに出す物: 3.3 の場所の一覧と、**再現できなくなる世代**（その版を入力にしていた封の世代の、出し口と番号）。

### 3.3 実行 — `erase run <求め>`

範囲の判断がある求めだけ。器が自分で手を入れる場所は、**台帳のフォルダの中の、今の本文と器の記録**。場所ごとに結果を付ける。

| 場所 | 器がすること |
|---|---|
| 今の本文 | 欄を消す求めなら、その欄の値を空にして書く（表は `row_set` と同じ「変える行だけ」の書き方・枚はまとめての入れ替え）。記録ごと消す求めなら、行（枚）を除く。番号は 3.5 の「消した番号」に残す |
| 前の版（`.thth/kept/objects/`） | 範囲の版の中身を持つ物を除く。表は枚ごとの控えなので、その枚の前の版が全部「取り出せない」になる（ほかの行の前の版も道連れ。見積りで言う） |
| 控えの目録（`snapshots/`） | 除いた物の sha256 を目録から外し、「消した」と記す（指紋を残さない） |
| 訂正と結びの跡 | 旧い文・新しい文のうち範囲に入る文を除く。結びそのもの（どの指し先からどの指し先へ）は残す |
| 判断の記録 | 範囲の版を対象にした行を、3.4 の印の形に書き換える |
| 封と材料の控え（`.thth/seals/`） | 範囲の版を載せた封から、その項目の指紋・版・行の指紋を外す。署名は合わなくなる（その出し口は、受け入れ直すまで封なし） |
| 段取りの控え（`.thth/batch/`） | 範囲の中身の sha256 を持つ段取りと済んだ記録から、その指紋を外す |
| 書き出した材料 | **器は書き出し先を知らないこともある。** 封の「書いたファイル」の道が台帳のフォルダの中ならそこから除く。外なら「確かめていない」 |
| 共通の台帳・ほかのメディアが採った版 | 「確かめていない」（その台帳で同じ求めを起こす、と知らせる） |
| git の履歴・ほかの clone・配った頁・持ち出した写し | 「確かめていない」（器は書き換えない。持ち主の手） |

- 途中で止まっても打ち直せる（場所ごとに結果を置いてから次へ。済んだ場所はやり直さない）。
- 消す前に、範囲の版の指紋の一覧を**メモリの中だけ**で作り、消し終わりの確かめ（3.6）に使う。ファイルに書かない。

### 3.4 判断の行の印の形

範囲の版を対象にした判断の行は、次の形に書き換える（行の数と順は変えない）:

- 残す: `id`（元のまま）・`question`・`target.record`（と `unit`・`value` の指し先。ただし指し先そのものが消す中身から作られた指紋を含むなら、その部分を除く）・結論にあたる語・`at`・誰が・いつまで。
- 除く: 対象の版・依る所の指紋・確かめた中身（`content`）・理由の説明の文（理由の**種類**は残す）・`seen`。
- 足す: `"erased": {"request": "<求めの番号>"}`。
- **止める・だめは、印の形になっても効く**（番号に付く判断なので、対象の版が無くても狭める向きには効く）。**よい・止めないは、印の形になったら効かない**（対象の版を確かめられないので、広げない）。
- 読む入口（`parse_judgments`・`J.read`）は、`erased` を持つ行について「番号が中身から作った物と合うか」を見ない。代わりに、`.thth/erase/<求め>/` に範囲の判断と結果があり、その行の番号が結果に載っていることを見る。載っていなければ断る。

### 3.5 結果と残り — `erase status <求め>`

- 持つ物: 場所ごとの「消した・消していない・確かめていない」・消した範囲（番号・欄・版の**数**）・消した番号の一覧・書き換えた判断の行の番号・**再現できない世代**（出し口と世代の番号の範囲）。
- **持たない物: 消した中身・その指紋。**
- 「確かめていない」が 1 つでも残る間、状態は「消し終わっていない」。持ち主が外の場所を確かめたら `erase done <求め> --place <場所> --by <誰>` で 1 つずつ結果を付ける（「消した」か「消さない」と決めた、のどちらか）。全部に結果が付いて初めて「消し終わり」。
- `check` と `health` は、消し終わっていない求めを数えて出す。

### 3.6 消し終わりの確かめ（器が自分でする）

`erase run` の最後に、台帳のフォルダ（`.git/` を除く。`.thth/` を含む）の全部のファイルを読み、メモリの中の一覧（範囲の版のバイト・sha256・器の指紋）がどこにも無いことを確かめる。あれば、その場所を「消していない」として結果に残し、rc を 0 にしない。

### 3.7 封と CI との関わり（偽の消す求めで柵を抜けさせない）

- 消す求めで判断の記録と封が書き換わるので、**その出し口は、受け入れ直す（`accept`）まで封なし**（CI は赤）。広げる向きには何も効かない。
- 受け入れ直した封は、「消す求めの結果」（求めの番号・書き換えた行の番号・前に配った判断の記録の頭の指紋）を中に持ち、持ち主の鍵で署名される。CI の「前に配った世代の続きか」の比べは、**署名の合った封が言う行だけ**を、3.4 の形の書き換えとして通す（その行の問い・対象の番号・結論・日時・番号が、前に配った物と同じであること）。行が減っている・載っていない行が変わっている、は今までどおり赤。
- つまり、鍵を持たない者が消す求めの記録を置いても、CI は通らない。鍵を持つ者（持ち主）でも、止める・だめの行を外すことはできない（行は残り、狭める向きに効いたまま）。
- 世代の番号は戻さない（増えるだけ）。

### 3.8 言うこと（出力と privacy の文の元）

- 消したあと、「過去の判定を全部再現できる」とは言わない。再現できない世代を結果に出す。
- git の履歴・配った頁・ほかの clone・相手の手元は、器は確かめていない。確かめるのは持ち主。
- release の便で privacy に足す文（この段では書かない。申し送りの「release の便で直す物」に足す）: 訂正の跡に旧い文が残る・出さない欄は指紋だけ・消す求めに応える口と、消したあと再現できなくなる範囲。

## 4. 宿題に回す物（この段ではしない）

- 内側の単位（1 枚の JSON の中の 1 行）だけを前の版から消すこと。この段では、枚の前の版ごと除く。
- 共通の台帳をまたいだ消す求めの連動。
- 取り込みの記録（こぴちゃの catalog・MMR の配信の情報）を器に入れるか（設計 §12 のまま）。
