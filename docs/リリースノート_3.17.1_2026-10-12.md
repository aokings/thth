# リリースノート 3.17.1（`thth where`・`thth thread` の X の行に投稿者のフォロワー数・投稿数）

2026-10-12。報告 r20261012-4409f401（関東レーン・masaru 10/12「フォロワー数の多いアカウントである必要がある」）。**下書き・未配布**（push・release・tag は masaru の一言で）。

## 足したこと

- X の読み取り（`READ_FIELDS`）の `user.fields` を `username,public_metrics` にした。今も `expansions=author_id` で投稿者を取っているので、**同じ呼び出しの同じ user に数が付くだけ**——呼び出しの数も返る投稿の数も変わらない（料金は返った resource ごと・fields は resource を増やさない、という読み。expansions の user が別に課金されるかは一次資料に書いていない）。1 日 60 本の数え方も予算も変えない。
- 行の鍵 `author_followers`（`followers_count`）・`author_posts`（`tweet_count`）。int か None。**無い・型が違う（文字列・真偽・負）・`includes` が無いときは None**（0 にしない）。
- **X 以外の媒体の行も鍵はあって None**（`replies`・`has_replies` と同じく、`where` の行の鍵は媒体でそろえる）。`thth thread` の `root` と `messages`、`thth list show --json` の行にも同じ鍵が入る。MCP `where_to_appear` は CLI の `--json` をそのまま返すので同じ鍵が通る。
- 画面: `thth where` の行は `@alice（仮名）  フォロワー 1.2 万  本文…`、`thth thread` の行は `@alice（仮名・他者・フォロワー 1.2 万）id=…`。数が無い行には何も足さない。

## 保存しない

この数は候補を選ぶその場でだけ使う（本文・username と同じ扱い）。台帳・runs・engagements・study には書かない（runs は従前どおり件数だけ）。

## 確かめていないこと

- 実 API では未試験（試験は偽の HTTP）。`public_metrics` の形は一次資料どおりに読んでいる。
- expansions の user が別に課金されるか（一次資料に無い。今も username のために expand しているので、足す費用はゼロの見込み）。
