目当て: 照合が合わない日と、断られた札がある日だけ THTH運用を起こす。移し終えるまでは、今のやり方（毎朝 06:40 の起こしで THTH運用が手で並べる）を続ける。

- 失敗の日だけ thth/ops を急ぎで起こす。成功の日は染めと化学へ 1 行。表の終わりの翌朝に thth/ops へ 1 回

## 今、毎朝 LLM がしていること（台帳 #11）

1. 前の日の束が終わったかを見る: VM で `thth bookmark batch-status sometokagaku-hatenablog`
2. 承認を照らす: Mac で `hub approve verify <承認番号> --target <target>` を打ち、「照合 ok」と rc 0 を確かめる
3. 1 段目（見込みだけ）を出す: VM の `/srv/thth/repos/sometokagaku` で `thth bookmark batch sometokagaku-hatenablog data/hatena/batch/<日付>.jsonl`。出てくる `digest:` が表の値と同じかを見る
4. 2 段目で並べる: 同じ命令に、確認の digest・`--by "<承認の書き方>"`・`--production` を付ける
5. 染めと化学（SilentCat）へ伝言で知らせ、台帳 #11 を直して push する
6. 鳴った起こしを消し、3 日先の起こしを足す（枠が 3 本しかない）

VM の命令は `ssh wt 'env THTH_ROOT=/srv/thth /srv/thth/app/bin/thth …'` の形（ssh の一行ではログインの設定を読まないため）。

## 仕事にしたときの形（推し）

- **起こさない日**: 前の日の束に「断った・結果不明・期限切れ」が 0、承認の照合が ok、digest が表と同じ。このとき並べて、SilentCat へ 1 行の伝言（返事不要）を送って終わる
- **起こす日（THTH運用宛て。並べない）**:
  - 承認の照合が ok でない（rc が 0 でない・期限切れ・target が合わない）
  - 1 段目の digest が表と違う
  - 前の日の束に「断った」か「結果不明」か「期限切れ」がある
  - その日の束のファイルがあるのに、表にその日が無い
- **何もしない日**: 表にもファイルにもその日が無い（表の終わりを過ぎた日）。表の最後の日の翌朝だけ「承認の分が終わった」を THTH運用へ 1 回知らせる（次の承認を取りに行くため）
- 台帳 #11 の書き足しは仕事ではしない。THTH運用が週に 1 回まとめて書く（仕事の記録を読んで）

## 承認の照合を仕事の中に残す形（推し）

承認の表を機械で読めるファイルにして、仕事は毎朝その表の行を照らす。表に無い日の札は並べない。

## 台本の持ち主（推し）

- **台本（仕事の手順）は h2d の持ち物**にして、媒体ごとの違いは表に入れる。関東のはてブ（調べ書の 2、毎朝 07:40）も同じ台本に乗る形が良い
- **表は、その媒体の札を並べている者の持ち物**: 染めと化学は THTH運用、関東は アスモン関東
- 前提が変わったら: 媒体ごとに手順が分かれていく（たとえば札の作り方まで仕事に入れる）なら、台本も各媒体の持ち物にした方が良い。その代わり、直す所が媒体の数だけ増える

## 移るときの段取り

- 仕事が 1 回、起こさない日を回したら（並べて伝言まで）、THTH運用が束の状態を見て確かめる。そのあとで THTH運用は起こしの継ぎ足しをやめる
- それまでは、VM の起こし（remind-thth-ops-1123-0640・1124-0945・1125-0640）を残し、同じ日に二重に並べないよう、仕事の初回の日を伝言で決める
- 同じ日の束を二度並べたときに THTH が断るかは確かめていない。初回の日を決めるのはそのため
