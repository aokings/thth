## 1. ランキングの説明（Transparency Center）

出所: https://transparency.meta.com/features/explaining-ranking/ig-threads-feed/
**頁の更新日: 2025-03-07**（取得日 2026-09-11）。**1 年半前の記述**であることに注意。

フィードは **9 つの予測**を組み合わせると書かれている。括弧内は入力シグナルの例
（頁に列挙されているもの）。

| 予測 | 入力シグナルの例 |
|---|---|
| 投稿にいいねする可能性 | 過去 1 週間のエンゲージメント／過去 15 分のいいね／**著者とのエンゲージメント率** |
| スクロールして通り過ぎる可能性 | 過去の閲覧時間（複数期間） |
| プロフィールを訪れる可能性 | プロフィールのタップ／ページの規模 |
| 次の投稿をクリックする可能性 | **返信へのエンゲージメント（6 時間以内）**／タップ回数 |
| **返信を書く可能性** | 過去 1 か月に作った投稿数／**過去 1 週間の返信数** |
| 投稿をクリックする可能性 | **いいね対インプレッション比**／国別エンゲージメント |
| 著者のプロフィールを訪れる可能性 | 過去 28 日のプロフィールタップ |
| クリック後にいいねする可能性 | 滞在時間／返信へのいいね（過去 1 か月） |
| パーマリンクの閲覧時間・投稿の閲覧時間 | インプレッション数／**過去 84 日の時間帯別閲覧** |

フィードは「フォロー中のアカウントのコンテンツと**おすすめをブレンド**」。
「フォロー中」に切り替えると**おすすめは出ず、時系列順**になる。

### ここから言えること・言えないこと

- **「エンゲージメント率的なもので評価されている」は、公式の記述と整合する。**
  「**著者とのエンゲージメント率**」「**いいね対インプレッション比**」が
  入力シグナルとして明記されている（masaru の見立て 2026-09-11）。
- **「返信の往復が効く」も整合する。** 予測の 1 つが「返信を書く可能性」で、
  その入力に「過去 1 週間の返信数」がある。ただし**それが露出を増やすとは
  書かれていない**——予測であって、報酬の設計は書かれていない。
- **「投稿数を絞ると回復する」は、この頁に書かれていない。** 比率のシグナルから
  人が推論した話であって、公式の記述ではない。**仮説として立てるのはよいが、
  公式に裏付けがあるとは書かない。**
- **時間帯**については「過去 84 日の時間帯別閲覧」が入力にあるだけで、
  「何時に出すとよい」は書かれていない。

## 2. 指標の定義（Threads Insights API）

出所: https://developers.facebook.com/docs/threads/insights/（取得日 2026-09-11）

**うちの台帳が記録している数の、公式の定義。**

| 指標 | 定義（原文） | 単位 |
|---|---|---|
| `views` | "The number of times your post was played or displayed" | 投稿 |
| `likes` | "The number of likes on the post" | 投稿 |
| `replies` | "The number of replies on the post" | 投稿 |
| `reposts` / `quotes` / `shares` | 再投稿・引用・共有の数 | 投稿 |
| `clicks` | "The number of times people clicked on URLs you shared" | **アカウントのみ** |
| `followers_count` | フォロワー総数 | アカウント |

**効いてくる制限が 4 つ。**

1. **投稿単位の指標は "lifetime"（累計）。** うちが 1h・6h・24h の刻みで採って
   いるのは**累計のスナップショット**であって、その時間帯の増分ではない。
   `collect.py` のコメントと一致している。
2. **`clicks` は投稿単位では取れない**（アカウント単位のみ）。記事へ渡すのが
   目的の投稿でも、**どの投稿から踏まれたかは分からない。**
3. **入れ子の返信の指標は取れない**（"do not capture nested replies' metrics"）。
   **連投（返信でつなぐ形）の 2 段目以降の返信が、この経路では見えない可能性がある。**
   → **要確認。** うちの連投はまだ 1 本も公開していないので、実物で確かめる前の段階。
4. `REPOST_FACADE` の投稿には**空の配列が返る**。うちの取得は
   `{"data": []}` を「取れて 0 件」として通す（2026-09-11 の修正で、
   `data` が無い・null・配列でない場合だけを失敗にした）。**この仕様と整合している。**

アカウント単位の `since`/`until` は **2024-04-13 より前には効かない**。
`follower_demographics` は**フォロワー 100 人以上**が要る（うちは 4 人）。

## 3. この資料の扱い

- **公式でも「いま時点の真実」ではない。** ランキングの頁は 2025-03-07 更新で、
  **1 年半前**。仮説の根拠に使うときは**この日付ごと**引くこと。
- **書かれていないことを「書かれている」にしない。** とくに投稿本数・時間帯は
  この 2 つの資料には無い。
- **指標の定義（§2）とランキングの説明（§1）は、証拠としての強さが違う。**
  定義は API の仕様なので確かめられるが、ランキングの説明は**相手の自己申告**で、
  検証手段がこちらに無い。
