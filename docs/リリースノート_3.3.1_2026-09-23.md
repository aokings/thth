## 何が変わったか

09-22 20:03、asmon-kanto-threads の公開で `threads_publish` が HTTP 500（`is_transient=true`）を返しました。container は作成済みで、媒体には出ていませんでした。道具は「結果が分からない」で inflight を残し、21 時間、毎回の実行が止まりました。復旧は `inflight.json` を手で消す操作でした。

3.3.1 の約束は 1 行です。**結果が分からないまま止まるのは、媒体に問い合わせても分からないときだけ。**

1. **公開の直後（Threads）**: 公開が 5xx・時間切れ・接続断で終わったら、inflight を残す前に container の状態を最大 3 回（20 秒おき）問い合わせます。
   - `FINISHED`（まだ出ていない）: 公開を **1 回だけ**再試行します。それも失敗なら inflight を残します。
   - `PUBLISHED`（出た）: 自分の最近の投稿から、公開時刻の前後 10 分で本文の指紋が一致する 1 件を探して post_id を書き戻します。見つからなければ inflight に `published_unlocated` を書いて止まります。
   - `ERROR`・`EXPIRED`（出ていない）: inflight を解き、実行記録に `publish_failed_remote_error` を残します。原稿は approved のまま残り、次の実行が新しい container から出します。
   - 問い合わせの失敗・`IN_PROGRESS` のまま: 従来どおり inflight を残します。
2. **毎回の実行の最初**: inflight が残っている本番の実行は、止まる前に 1 回だけ媒体に問い合わせます。決まれば道具が解いて先へ進みます。
   - `FINISHED`（まだ出ていない）で、container を作ってから 24 時間未満、いまの原稿が公開したときの指紋と一致するとき: **新しい container を作らず、同じ container を 1 回だけ**公開して書き戻します。1 つの container は 1 つの投稿にしかならないので、前回の 500 の要求があとで通っていても投稿は 1 本で済みます。条件が 1 つでも欠ければ公開せずに止まります。公開の応答が分からなければ次の実行に任せます（再試行しません）。
   - `ERROR`・`EXPIRED`・24 時間を過ぎた `FINISHED`: 出ていないとして解き、select から（承認の検査を通り直して）新しい container で出し直します。
   - `PUBLISHED`: 自分の最近の投稿から書き戻します。
container の無い媒体（Mastodon・Bluesky・X）は、自分の最近の投稿に本文の指紋が一致する投稿がちょうど 1 件あるときだけ解きます。0 件では解きません。決まらなければ従来どおり止まり、死活通知の理由は `inflight_unresolved` になります。
3. **人の口 `thth inflight <account> show|resolve`**: `show` は中身（原稿・始まり・container_id と post_id の有無・最後の問い合わせ結果）を出します。本文と token は出しません。`resolve --not-published` か `--published <post_id>` に `--by <名前>` を付けて解きます。二段確認で、解く前に控え `inflight.resolved-<日時>.json` を state に残し、変更ログに `inflight_resolved` を書きます。MCP には出していません。
4. **運用通知の記録を 30 日**: 送り終えた運用通知の事象を outbox に 30 日残します（送り終えた事象が 50 件を超えたら古い順に畳みます）。`thth board` と `thth observe` に「最後に送った運用通知: 時刻・状態・理由・受領した役割」を出します。

## 運用セッション向け: inflight で止まったら何をするか

1. まず何もしない。次の実行（10 分以内）が媒体に 1 回問い合わせ、決まれば道具が自分で解いて進みます。
2. 止まり続けたら `thth inflight <account> show` で中身と「最後の問い合わせ」を見る。
3. 媒体の画面（自分の投稿の一覧）で、その原稿が出たかどうかを自分の目で確かめる。
4. 出ていなければ `thth inflight <account> resolve --not-published --by <名前>`、出ていれば `--published <post_id> --by <名前>`。表示された digest を `--confirm` に付けてもう一度打つ。
5. `inflight.json` は手で消さない（控えと変更ログが残らず、出ていたときに 2 度出ます）。
