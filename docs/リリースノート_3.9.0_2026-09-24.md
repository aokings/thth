## 何が変わったか

1. **投稿ごとのクリックを目的に依らず**（A）: `thth analytics-report <account> --per-post-clicks [--since 30d]`。goal を問わず、一意のリンク先の投稿（`unique_url_72h`・前後 72 時間で 1 本の投稿しか使っていないリンク先）を並べる。goal の層（`--by goal`）とは混ぜない——層に分けず、行に goal も持たない。goal を書く口が無かった頃の投稿（unrecorded）も、リンク先が記録にあれば並ぶ。各行に 72h のクリック（投稿日を含む 3 暦日）・クリック率（/24h views）・窓の後の 7 暦日のクリック（参考）・窓の前の 3 暦日のクリック（`clicks_before_post`）・窓の中の割合（分母つき）。全体に合計・中央値・窓の中の割合（投稿ごとの中央値と最小）。**窓の前と後は窓の和に足さない**。同じリンク先を使うほかの投稿の窓の日は、前にも後にも数えない。`clicks_before_post` が 1 以上なら「THTH を通していない投稿か Threads の外のクリックが混ざっている可能性があります（原因は言えません）」の 1 行（`clicks_before_post_present`）。`--by goal` の click にも行ごと・全体の `clicks_before_post`。
2. **検索の語の当たり率と候補**（B）: `thth where … --also <語>` は語ごとの「取れた件数・also に合った件数・当たり率」を当たり率の高い順に（`also_hits`）。合った件数 0 の語に「also に合った投稿が 0 件（直近 n 日）」。`--suggest` は語の候補を、自分のデータ（地図の点・原稿の topic と原稿の goal の本数・過去の自分の投稿で 24h の likes＋replies の中央値が高かった topic）を先に、次に also に合った投稿の本文から数えた語（漢字・カタカナ・英字の 2〜12 字の連なり・検索語と also の語と数字だけの語と取れた投稿の username を除く・2 投稿以上・上位 10・「その場の人が書いた語」）。依存は足していない（正規表現だけ）。**語と数だけで、本文・username・post_id・author_key は返さない。候補も当たり率も保存しない**（runs の 1 行は従前どおり語と件数だけ）。MCP の `where_to_appear` には足していない。
3. **`--aggregate` の速さ**（C）: `rate_by_span`（n ÷ 返った投稿の期間〔最古〜最新〕の日数・1 日で底上げしない）と、その分母（n・期間の時間）。n < 20 は `rough: true`。期間が 0 は `span_zero`・時刻が無ければ `no_timestamp`（null と理由）。返った件数が要求数に届かず、期間が 24 時間未満で n が 5 以上なら `cannot_say: more_may_exist`（これで全部か、もっとあるかは区別できない）。媒体が 1 回の検索で返す件数の上限の値は一次資料で未確認と書く。従前の `per_day` はそのまま残した。

## 各 project のセッション向け

1. クリックを確かめるときは `thth analytics-report <account> --per-post-clicks --since 30d`（goal を問わない・unrecorded の投稿も並ぶ・goal の層とは別の表）。
2. `clicks_before_post` が 1 以上の投稿は、THTH を通していない投稿か Threads の外のクリックが混ざっている可能性がある（窓の和には入っていない・原因は道具には言えない）。
3. 監視語や検索の語を選ぶ前に `thth where <account> <語…> --also <語>` で当たり率を見て、0 件の語は外す候補にする。
4. `--suggest` で語の候補（自分のデータが先・その場の人が書いた語が後）。候補は保存されないので、使う語は人が監視語（`watch_words`）や地図の点に足す。
5. `--aggregate` の速さは `per_day` ではなく `rate_by_span`（n と期間の時間つき）で比べる。`more_may_exist` が出た語は「これで全部」とは読まない。
