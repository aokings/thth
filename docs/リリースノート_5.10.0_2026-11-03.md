# THTH 5.10.0（2026-11-03）


## 測っているふりを無くす・済んだ糸を雑音にしない（設計 効果測定と連動 §7 段 6）

書き手: THTH開発の書き手（Opus）。設計の正本は `docs/設計_効果測定と連動_2026-11-03.md` の §7（7.1 の 1・2・6・7、7.2、7.3 の段 6）。

**読むだけは変わらない。** THTH は糸の宣言のファイルに書かない（`closed` を書くのは今までどおり窓口）。Meta も GA4 も呼ばない。

### 契約 `thth.scenario/1` の変わったところ（足すだけ）

- `threads[].state` に値 **`done`** を足した（`active`・`stalled`・`done`・`closed`）。
- `threads[]` に鍵 **`done`** を足した（`done` 以外の糸では `null`）。中身は `since`（最後の動き・無ければ `started` かファイルの時刻）・`since_from`・`days`・`label`（「全部の段が済んだ（閉じるか広場に置く）」）。
- `next[].kind` に `plaza` を足した（done の糸の 2 行目）。
- seeds（`report_type: "scenario_seeds"`）の列 4 の行に `state`（`closed` か `done`）と `done_at`（done の糸の最後の動き・closed の糸では `null`）。`closed_at` は done の糸では `null`。投稿の列の媒体の節に `metric_unavailable: true`（取れない媒体だけ）。
- 鍵の名前を変えたもの・消したものは無い。

### 変えたこと

1. **返信を数える段は名でなく印で決まる。** 段に `replies_within_hours=` を書けば、名が何でも（例 `engage`）`warm` と同じく返信の数と、返さないまま時間を越えたものを数える。これまで `engage` の段は印を黙って受け取り、告知と同じ投稿を本数として数えて、出した瞬間に ✓ になっていた（本番で返信を測っている糸は 0 本だった）。`warm` は印が無くても今までどおり既定の 24 時間で数える。表示の段の名は窓口が書いた名のまま（`engage` は「n 段目」）。返信を数える段に SNS 以外の媒体を書くと `stage_medium_unknown`。その段で止まったときの言葉は「n 段目の返信の対応が止まっている」。
2. **全段を満たした糸は `state: done`。** 7 日（`stale_after_days`）動かなくても停滞に倒さない。`next` は「closed を糸のファイルに 1 行（任意・期間の区切り）」と「`thth plaza post <口座> --kind measure --from scenario <project> <id> …`」。`closed` があれば今までどおり `closed`（done より先）。配信の台帳が conflict の原稿があるときだけは、確かめることがあるので今までどおり停滞。
   - `thth events` に **`scenario_done`**（続いている状態）。id は `"ev_" + sha256("thth.scenario/1|<project>|<id>|done")[:24]`。done の糸には `scenario_stalled` を出さない。
   - dashboard の要対応に「済んだ糸」（`scenario_done`）の 1 行。押すところは「広場に置く／閉じる／開く」。`scenario.n_campaigns_done` を足した。キャンペーンの詳細にも「広場に置く」。
   - `thth observe` の「広場に置く」の候補と seeds の列 4（「閉じた・済んだ糸の続き」）は、`closed` に加えて done の糸も入れる。**窓は closed と同じ**（observe は 30 日・seeds は `--days`）で、done の糸は**最後の動き**（`done.since`）で測る。done は `closed` を書くまで続く状態なので、短い窓（例 3 日）で消すと置く機会を逃すため。
3. **時刻を過ぎて出ていない原稿を dashboard の要対応に**（`publish_overdue`・原稿 1 本に 1 行・題は原稿の頭）。定義は morning の `overdue_items` と同じ 1 か所（`morning.overdue_hours`: 承認済み・post_id 無し・`publish_at` から 1 時間を越えた・返信待ちは除く）。出さない期限を過ぎた原稿（`not_after_passed` の行がある）は重ねて出さない。
4. **seeds で媒体として取れない数は `metric_unavailable:<媒体>`。** views は `goals.REACH_METRICS` に views のある媒体だけ（Bluesky・Mastodon は views を持たない）。今までは `below_min_n`（n が 5 未満）と出ていた。返信は全部の媒体で取れるので今までどおり。
5. skill `thth-flow` の段の名の説明に「返信を数えたい段は `replies_within_hours=` を書く（名は自由）」を 1 行。dashboard の型（`skills/thth/dashboard/*.html`）の種類と状態の表に `scenario_done`・`publish_overdue`・`done`。

### 監査のあとの直し（Fable・同じ版のうちに）

- **時刻を過ぎた原稿の行から、出られない理由の分かっている原稿を除いた。** held の原稿（`core.held_items_for_account`＝morning の `held_items`・はてなの `delivery_held` と同じ集合）と、出さない期限を過ぎた原稿（`report.schedule` の `expired`・events の 7 日の窓に依らない）は `publish_overdue` に出さない（別の行で出る）。判定は `morning.overdue_hours(row, now, held=…)` の 1 か所。morning の `overdue_items` は `held` を渡さないので今までどおり（held の原稿が `held_items` と `overdue_items` の両方に出るのは前から）。
- **広場に置いた糸の `scenario_done` は要対応から外す**（`plaza_moments._posted_threads` と同じ判定・非表示も置いたに数える）。置いていない done の糸は今のまま。糸の `state` は done のまま。
- **返信の段が 0 件のまま止まったら「返信が来ていない（n 日）」**。返していない返信があって止まったときの「返信の対応が止まっている」と分けた（`_next` の `wait` と `replies` の区別と同じ）。
- 文書: skill `thth` の宣言の書き方（`replies_within_hours=` は `warm` に限らない・`done`）と events の種類（`scenario_done`）・要対応の `publish_overdue`、`README.en.md`、`docs/調べ_JSONの欄_2026-10-15.md`。

### 本番で変わること（見込み）

- kopicha `num-04-matcha` と asmon `youkou-2027` の `- engage: threads,x replies_within_hours=48` は、告知の本数ではなく返信を数える。返信が 0 件か、48 時間を越えて返していない返信があれば ✓ が外れ、現在の段が `engage` に戻る（次の一手は「返信を待つ」か「返していない返信 n 件」）。返信があって返していれば `done` になり、停滞の代わりに要対応に「済んだ糸」が 1 行出る。**✓ が変わるので kopicha・関東に 1 行知らせる**（設計 §7.3）。
