## 約束の固定（最優先）: 他の持ち主の情報を漏らさない

- **project 範囲の書き込みは他の持ち主から読めない**: 読む口はすべて `plaza.access()` を通る（CLI の `list`・`show`・`reply`・`update`、MCP の 5 本、observe の 0 段と次の一手）。無い id と読めない id は同じ `plaza_not_found`。CLI も読む側を名指しする（`--as`）。`thth board` は広場を読まない（leak probe）。
- **open は参加した持ち主どうし**: 1 件が見えるのは、置いた持ち主と読む持ち主の**両方**が参加しているときだけ。置いた持ち主が外れれば他の持ち主からは消える。
- **他の持ち主が読むのは写しだけ**: 写し（`open_copy`・返信の `open_text`・観測の `open_columns`）は置く時点・open に切り替える時点に、書いた持ち主の返信の台帳から他人の本文（8 字以上の一致）と username を、加えて `@名前`・`author_key` の形（16 進 16 桁）・SNS の投稿 URL を落として作る。account 名・by・宣言の投稿 ID・除外された ID は写しに入れない。自分の投稿は先頭 60 字と permalink まで。台帳が読めなければ写しを作らない（`redaction_unavailable`）。
- **open に出す文に他の人の `@名前` があれば断る**（`third_party_handle`・§9-7）。自分の handle（threads・bluesky・mastodon の形）は許す。
- leak probe: `test_他のprojectからは一覧にも1件にも出ない`・`test_他の持ち主のproject範囲は読めない`（MCP）・`test_openの写しは他人の情報を落とす`（他人の username・本文・author_key・他人の ID・自分の投稿 ID・account 名・by・threads.net の URL が他の持ち主の応答に無い）・`test_サーバ型の利用者の1枚でも自分の範囲だけ`（observe）・`test_boardは広場を読まない`。単変異 1〜3 で固定。

## 設計から外れた点・解釈した点

1. **CLI の `show`・`reply`・`update` に `--as <account|project>` を必須にした**（設計 §4 の表には無い）。VM の CLI は複数の持ち主の台帳を持つので、名指しが無いと他の持ち主の project 範囲まで読めてしまう。管理者の全件の読みは `thth admin plaza list|show`。
2. **媒体・企画の範囲の記録の鍵は `scope_note`**（CLI は `--scope`・MCP は `scope`）。§9-5 は「scope を必須」だが、記録の `scope` は既に project／open の範囲の鍵として使っているため。
3. **施策 1 件に宣言を媒体ごとに複数並べる**（`--declaration` を繰り返す・MCP は `declarations` の配列で宣言そのもの）。設計 §4 は `--declaration <file>` 1 つ。「同じ measure を媒体ごとの列で並べる」（§5）ためにこう読んだ。宣言の account は置く account と同じ持ち主だけ。
4. **追試（`trial`）は `tried` と並べて足した**（`tried` は残した）。`trial` の結果は必須、本文とリンクは任意。
5. **`kind_detail` は finding で任意**（§9-1 に必須とは書かれていない）。finding 以外に付けたら断る。
6. **変更ログに `plaza_left` を足した**（設計 §6 の 5 つに無い）。参加の取り消しを `plaza_joined` の逆向きで書くと読み違えるため。退出の片づけは `plaza_updated`（`account_left`）で残す。
7. **open の 1 件は、置いた持ち主が参加から外れたら他の持ち主から見えなくなる**（設計は「不参加の持ち主は open を読めず、出せない」まで）。外れた持ち主の書き込みを出し続けない側に倒した。
8. **新着の窓は observe の第 2 段と同じ**（前回の観測から・無ければ前日 JST。account ごとに違えば最も古い始まり）。account 1 本の observe ではその account の書いたものを数えない。project 全体の observe では全部数える。
9. **「まだ試していない媒体」は account 単位**（宣言の account と、`tried`・再現した／しなかった `trial` でつながった施策の宣言の account を「試した」とする）。判定はどれでもよい（adopted に限らない）。
10. 自分の投稿の permalink は送った記録（`state/<account>/sent/`）に `https://` の `permalink`／`url` があるときだけ出す。無ければ null（媒体に問い合わせない）。
