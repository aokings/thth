### sync（見てほしいこと 3）【読】

- 他人の変更を消す道は見つからなかった: force も reset も無い。push は `refs/heads/<枝>:refs/heads/<枝>`（`+` なし）
- ぶつかりは merge の途中のまま人に返し、次の `thth sync` は `sync_in_progress` で止まる（勝手に abort しない）
- `tampered` はやり直さずに止める。やり直すのは `stale_head`・`box_not_next`・`fetch first`・`non-fast-forward` だけで、3 回まで
- clean でなければ pull もしない（追跡していないファイルも数える）。push は commit だけを送るので、未 commit を巻き込まない
- `--no-edit` は merge の commit を黙って作る。利用者の設定 `pull.ff=only` では `sync_failed（pull）` に、`commit.gpgsign` では鍵の問いで待ちになりうる【未】

### 庭（見てほしいこと 4）【読】

- build に載るのは `buyable`（`visible`・販売中・在庫 1 以上）だけ。欄が欠けた行は載らない側に倒れる。載せる文（題・商品名・値段・読んだ時刻）は全部 escape し、店の URL は https の形だけ。試験「公開で買える商品だけ」が緑【動】
- `--out` に `index.html` という名の symlink があると、その先を上書きしてから検査で断る（書く前に symlink を見たほうがよい）
- publish の digest は URL と全ファイルの道と SHA-256 を縛る（12 桁・48 bit）。二段目はフォルダを読み直して作り直すので、一段目のあとに中身が変われば通らない
- 残るすき間: THTH の検査と monban-vault がフォルダを読む間のすり替え。monban の返す `head` は目録（`{"v":1,"files":…}` を詰めた JSON）の SHA-256 なので、THTH の側で同じ値を計算して見比べれば閉じられる
- stop は確認なしで monban-vault を呼ぶだけ。THTH の手元の状態に頼らない。Edge は 451 を `no-store` で返す（次の要求から効く・monban の設計案 §15.4）

### monban への知らせの種【未・ブラウザで試していない】

XML と SVG の内部 DTD の entity（`<!ENTITY e "<meta xmlns='…' http&#45;equiv='refresh' …/>">` を本文で `&e;`）は、字面に `http-equiv` が出ない。Edge の検査（字面の `/http-equiv/i`）を抜けるかもしれない。THTH の側は `xmlns` の `http:` で偶然止まるが、`&#38;#58;` の二重の崩しで抜ける。持ち主は monban-vault を直に呼べるので、塞ぐ場所は Edge（xml と svg で `<!DOCTYPE`・`<!ENTITY` を断る、など）。monban の担当へ知らせる。

## 「仮・朝に覆せる」のうち、覆すと大きく作り直しになる所（見てほしいこと 6）

### 6. 直したほうがよい（新）: html.parser とブラウザで、注の終わりの読み方が違う【動】

Python 3.12.10 の html.parser は、次の 4 つを「まだ注（か印の塊）の中」と読むが、ブラウザはそこで注を終える。だから、その後ろに置いたタグが検査に見えない。

| 書き方 | THTH の検査 |
|---|---|
| `<![CDATA[><img src="https://…/x.png" onerror="x()">]]>` | 通る |
| `<!-- a --!><img src="https://…/x.png"><!-- b -->` | 通る |
| `<!--><img src="https://…/x.png"><!-- b -->` | 通る |
| `<!---><img src="https://…/x.png"><!-- b -->` | 通る |

- 害の大きさは前の 4 と同じ: 外の画像と `on…=` は monban の CSP が止めるので、「出したら壊れて見える」まで。script・form・iframe などは字面の検査（`_ACTIVE_RAW`）が先に止めるので、この道でも通らない【読】
- Python の版で結果が変わる（新しい版は注の終わりをブラウザに寄せている）。同じ頁が端末によって通ったり断られたりする
- 直し方の案: HTML では `<![` を断る・注の中身に `>` を含む注と `--!>` を断る（字面で）。上の 4 つを parametrize に足す

### 7. 直したほうがよい（新）: 普通の頁を誤って断る所【動】

| 普通の書き方 | 結果 | 理由 |
|---|---|---|
| `<link rel="canonical" href="https://…">` | `garden_external_refused` | 読みに行かないリンクだが、`link href` を外の資源と見る |
| `itemtype="https://schema.org/Product"` | `garden_external_refused` | 商品の頁でよく使う印。読みに行かない |
| `<blockquote cite="https://…">` | `garden_external_refused` | 読みに行かない |
| `<img alt="a < b">` | `garden_markup_refused（broken tag）` | 属性の値の中の `<` を壊れたタグと見る |
| CSS の `content:"Note: "` | `garden_external_refused（css url）` | 引用符の中の `語:` を URL の scheme と見る |
| 改行もタグも無く `R&D` のような `&` つきの語で終わるファイル | `garden_markup_refused（broken tag）` | 読み手が続きを待つ |
| 注の中の `<form>` の字 | `garden_active_refused` | 字面の検査（安全な側の誤り） |
| SVG の `style="…"` と中の `<style>` | `garden_markup_refused（style）` | Inkscape や Illustrator の出す SVG は多くがこれ。svg は置ける種類のままだが、実際に通る SVG は少ない |

- build の作る頁・OGP の meta・`<a>` の外のリンク・mailto・tel・data: の画像・srcset・picture・sitemap.xml・DOCTYPE つきの SVG は通る【動】
- 今の build はどれも出さないので、段 1 の間の害は小さい。手で作った頁や LLM の作った頁を `garden check` に掛けると当たる。目録の直し方（「相対の道で指す」）は canonical や itemtype には合わない
- 直し方の案: `cite`・`itemtype` を URL の属性から外す。`link` は `rel` が canonical・alternate・me などのときは外の先を許す。CSS の文字列は `url(`・`image-set(`・`@import`・`src:` の中だけを見る。SVG の style は「効かないかもしれない」を言ったうえで通すか、断る文に SVG の直し方（属性に書き直す）を足す

### 気づき（新）

- SVG の `<animate attributeName="href" to="javascript:…">` と `fill="url(https://…)"` は通る【動】。`to`・`values`・`fill` などは URL の属性に入っていない。CSP が止める
- XML の `<?xml-stylesheet … href="s.xml"?>` は通る【動】。XSLT の本体は `xsl:template` が「template」として偶然断られるが、template を使わない書き方（簡略の形）は試していない【未】。XSLT で `http-equiv` を組み立てて Edge の字面の検査を抜ける道がありうるので、前の「monban への知らせの種」（DTD の entity）と一緒に monban の担当へ知らせる。THTH の側は xml と svg で `<?xml-stylesheet` を断るのが手堅い
- `remote.monban.vcs` で遠隔の口そのものを替える設定は見ていない【読】。とても珍しいので気づきに留める
- `sync_remote_redirected` の点検は `thth sync` と `thth sync status` の入口で 1 回。点検と pull の間に設定が変わる道は、利用者自身の手なので数えない
