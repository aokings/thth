## 1. adapter の枠組み

### 1-1. 1 媒体になるために実装するもの

- 型の正本は `thth/adapters/base.py`。クラス `Adapter`（`thth/adapters/base.py:339`）を継いで、次を埋めると 1 媒体になる。
  - 必須に近いもの: `from_account()`（`base.py:529`・台帳と鍵から組み立てる）、`publish()`（`base.py:537`）、`insights()`（`base.py:609`）、`whoami()`（`base.py:619`）。

- クラス属性で媒体の性質を言う（呼ぶ側は媒体名で分岐せず、これだけを見る）。

## 2. facebook の今

### 2-1. できること

- 媒体名 `facebook`。1 ページ = 1 口座。台帳の `page_id`（数字）が正本で、`handle` にも同じ値（`thth/account_cli.py:258-261`）。`page_id` が無い・数字でなければ組み立てを断る（`thth/adapters/facebook.py:269-280`）。
- 宛先は `graph.facebook.com` か loopback の試験先だけ（`facebook.py:103-125`）。版は `v26.0` の 1 か所（`facebook.py:51`）。
- 投稿（`facebook.py:407-463`）:
  - 文 → `POST /{page_id}/feed`。本文の最初の URL を `link` に渡す（`facebook.py:401-405`）。
  - 返信 → `POST /{reply_to}/comments`（権限 `pages_manage_engagement`・`facebook.py:253`）。
  - 画像 1 枚 → `POST /{page_id}/photos` の multipart（`facebook.py:760-` `publish_photo`）。jpeg・png・gif、4,000,000 バイトまで（`facebook.py:89-92`）。
  - 再試行しない。失敗は permission・publish_definite・publish_ambiguous に振り分ける。
- 削除: `DELETE /{post_id}`、`success: true` のときだけ成功（`facebook.py:465-497`）。`thth retract` が `DELETE_PERMISSION`（`facebook.py:251`）を見て通す。
- 読み取り: 最近の投稿 `GET /{page_id}/posts`（`facebook.py:569`）、根の 1 件（`facebook.py:550`）、コメントの頁を辿る（`facebook.py:520-548`・100 件×50 頁で loud に止める `facebook.py:85-86`）。
- 数: 反応・コメント・シェアの数と、表示（`post_media_view` を views と読む・L3）（`facebook.py:585-634`）。取れないものは 0 で埋めず `unavailable` に理由を書く。
- doctor の probe（読み取りだけ）: ページの確認・`/debug_token` の権限と期限・投稿の一覧・コメント・数。書き込みの権限は `/debug_token` に乗っているかだけで言う（`facebook.py:662-746`）。
- `CAPABILITIES` は recent_posts・thread_read・views・link_preview の 4 つ（`facebook.py:235`）。
- 予約: THTH 側の予約（queue の `publish_at` と timer の `thth run`）は媒体を問わないので FB にも効く（`thth/core.py:158-165`・`core.py:415-428`）。**Meta 側の予約投稿（scheduled_publish_time）は使っていない。**
- 本番の実績: こぴちゃのページで認可（D）と 1 本の投稿（E）が通った。post_id `1361492233719922_122096173233535853`（`docs/手順_FBページと広告_2026-10-28.md:63-70`・【打った】）。

### 2-3. 保存する鍵の形

- 保存するのは**ページの鍵だけ**。ユーザーの鍵は保存しない（`thth/adapters/auth_facebook.py:14-15`）。
- `.token` の中身（`auth_facebook.py:254-277`）: `access_token`（ページの鍵）・`obtained_at`・`user_id`＝`username`＝ページの id・`page_name`・`page_tasks`・`scopes`／`scopes_source`（response・requested・unknown）・`login_mode`（config_id か scope）・期限（下）。
- 認可の流れ: code → 短い鍵 → 長い鍵 → `/me/accounts` から台帳のページを選ぶ → `/debug_token`（アプリの鍵で訊く）→ ページの鍵の `/me` が台帳の id と同じなら保存（`auth_facebook.py:203-278`）。
- app.env の 3 行 `META_APP_ID`・`META_APP_SECRET`・任意 `META_LOGIN_CONFIG_ID`（`thth/appenv.py:76-83`）。構成の ID があれば `config_id`、無ければ `scope`（`auth_facebook.py:154-161`）。求める権限の一覧は `facebook.py:62-72`（ページの 9 つ。Instagram・広告の権限は入っていない。構成のほうは 19 個 `docs/手順_FBページと広告_2026-10-28.md:59`）。
- 戻り先は `https://thth.me/callback/` だけ（`auth_facebook.py:60,125-126`）。

### 2-4. 期限と data_access_expires_at

- `TOKEN_NO_EXPIRY = True`（`facebook.py:250`）。`/debug_token` の `expires_at` が正の数ならそれを `expires_in` に採り、0 か訊けなければ `no_expiry: true`（`auth_facebook.py:266-274`）。`oauth.token_age_and_remaining()` は `no_expiry` で `remaining_days` を None にする（`thth/oauth.py:516-529`）。
- `data_access_expires_at`（データに触れる期限・通常 90 日）は `.token` に**書くだけ**（`auth_facebook.py:275-277`）。thth の中で読む所は無い（`grep` で書く 1 か所と試験 `tests/test_facebook_auth.py:78,133` だけ）。
  - **doctor も maintain も期限を知らせない。** probe が出すのは `expires_at` だけ（`facebook.py:704-706`）。maintain は `no_expiry` を「期限なし・ok」と言う（`thth/maintain.py:163-208`）。
- 本番の値: `expires_at=0`・権限 20 個（`docs/手順_FBページと広告_2026-10-28.md:67`）。

### 2-5. 文字数の上限が仮の 500

- `queuefile.MEDIA_LIMITS` に facebook の行が無く、既定の 500 に落ちる（`thth/queuefile.py:17-18,219-231`）。数え方も既定（`base.Adapter.count_text` ＝ Threads の数え方・`thth/adapters/__init__.py:66-75`）。台帳の `char_limit` で口座ごとに上書きはできる（`queuefile.py:227-230`）。
- 手順書の記録: 「FB の本当の上限と media_traits の行を足す」（`docs/手順_FBページと広告_2026-10-28.md:74`）。

### 2-6. 10/29 に分かった穴（手順書 `docs/手順_FBページと広告_2026-10-28.md:71-75`）

1. **page_id 不一致のエラーにページ名が出ない。** 該当する所は 3 つ:

3. 認可のログを VM の `/tmp` に置いたら途中で消え、受け取りも止まった（原因未確認・`docs/手順_FBページと広告_2026-10-28.md:75`）。

## 8. 計画を立てる者が知っておくべき、この repo の決まりと地雷 10 個

1. **本番は release の枝、公開は tag。** main への push は本番を変えない（Claude が押してよい）。release を進める・tag・Worker の deploy は、CI が緑のあと masaru の「出して」で押す。Worker が先・VM があと（`CLAUDE.md`「誰が push…」・申し送り :54）。
2. **release の push は `git push origin "${sha}:refs/heads/release"`。** zsh で `$sha:release` と書くと `:r` 修飾子で壊れる（`CLAUDE.md`「事故が起きた操作」）。
3. **試験は rc を見てから進む。** `| tail` を挟むと落ちても進む。書き手を並べるときは `-n 4`、全件は 1 回にまとめる（`CLAUDE.md`・申し送り :55・10/28 に load 184）。
4. **VM の操作の型**: `ssh wt '…'` では `env THTH_ROOT=/srv/thth /srv/thth/app/bin/thth`。`pkill -f`／`pgrep -f` の型に自分の命令が入ると ssh ごと止まる。state を書く前に `cp -a` で控える（`CLAUDE.md`・申し送り :56）。
5. **同じ repo を開発と運用が同時に触る。** 運用のレーンは THTH のコードを直さない。git add はパス明示、reset・checkout --・stash・commit -a はしない（`CLAUDE.md`・申し送り :57）。
6. **秘密を会話・出力・追跡されるファイルに出さない。** app secret は 10/29 にクリップボード経由で VM に入れた（手順書 :51-55）。鍵の値は `redact` に登録し、例外文に URL を入れない作り（`thth/adapters/facebook.py:30-34`・`auth_facebook.py:41-43`）。新しい口も同じ作法が要る。
7. **足したユースケースは消せない・審査は「口を全部作ってから」。** 録画に、申請した権限が実際に動く画面が映っていないと落ちる。審査員は LLM を持たない前提で、ブラウザで自分で試せる口が要る（手順書 :10,13・事実と方針 :20-29）。
8. **お金が動くものは masaru の承認。** 広告を作る・予算を変える・止めるは投稿と同じく承認の印を通す（手順書 :178）。既定は「出さない」に倒す前例（X の投稿の本数は既定 0 `thth/budget_x_posts.py:5-6`）。止めても Meta 側の配信は止まらない点に注意。
9. **THTH は CLI の道具の提供者。** 利用者とその LLM を疑わず、暴走は機械（guard・柵）で止める（`thth/guard.py:1-4`）。Web は見る・止める・鍵だけ。自動の返信はしない（手順書 :149）。外の人も自分の LLM から承認なしで出せるのが本来の姿。
10. **媒体の制約を言う前に原文を読む・解放の条件そのものを書く。** 「Meta の制約」と THTH 自身の決まりを取り違えた前例がある（`docs/整理_Meta承認で…_2026-10-12.md:3`・`docs/点検_絞りすぎ_2026-10-15.md`）。コードの注にも L2（公式を読んだ）・L3（そう読めるだけ）・未確認の印を付ける作法がある（`facebook.py:6-23`）。FB の「未確認」の点（`expires_at` 0 の意味・`/posts` の上限・投稿 id の形・`post_media_view` を views と読むこと）は本物で確かめる残り。
