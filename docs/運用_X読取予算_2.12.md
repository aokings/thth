# X の月次読取予算（管理者）

masaru が上限を決め、CLI または管理者 MCP の `thth_admin_budget_set` で設定します。X の認可前でも設定できます。既定は USD 0 で、有料読取を行いません。これは読取の推定額の制限で、X の請求総額や Console の支出制限と同じではありません。

```sh
thth admin budget x --json
thth admin budget x --monthly 3 --currency USD --by masaru
thth admin budget x --monthly 3000 --currency JPY --rate 150 --rate-source '管理者指定の出所・日付（例示値）' --by masaru
```

最後の 150 は換算指定の書式例で、現在の為替ではありません。JPY は正の JPY/USD レートと出所・日付を必ず指定します。金額とレートは小数文字列で扱い、MCP でも `monthly`・`rate` は文字列です。MCP の引数は `monthly`、`currency`（省略時 USD）、`rate`、`rate_source`、`by` です。管理者資格情報を各呼出と保存直前に確かめます。user MCP と HTTP に setter はありません。変更ログ `budget_set` に前後の設定と変更者を記録します。

表示は **推定計上（請求実費ではない）** です。[単価と一次資料](X料金_2026-09-20.md) を参照してください。未測定 usage は null、理由は `usage_not_observed` です。現在の実装対象は認可・refresh の本人確認 `users/me` です。将来の X 投稿・採集 adapter を追加したものではありません。

認可 code または refresh token を交換する POST より前に、User 1件ぶんを予約します。既定 0・不足時は `budget_exhausted`、JPY 換算の資料が欠ける場合は `missing_rate` で止まり、token POST を送りません。認可 URL を開いて code を受け取る前に予算を設定してください。本人読取が一度返った後に本人不一致や保存失敗になっても、その読取の推定計上は取り消しません。

月は UTC です。POST 送信前に月が変わったら新月の枠を再確認します。POST を送った後は元の予約で本人確認を続け、推定額は予約月へ一度だけ計上します。予約月・読取送信月・推定計上月を別に記録します。上限や通貨・レートの変更は過去の USD 計上や未確定予約を消しません。

本人読取の送信後 timeout、読取結果不明、途中終了では予約を保持し、再起動しても勝手に返金しません。未送信だと分かる本人読取だけ予約を解放します。未確定の枠を自動で再送・解除する口はありません。必要なら管理者が媒体と台帳を照合して運用を判断します。上限を下げて既計上・予約を下回った場合は超過を表示し、追加読取を止めます。

台帳は `state/_admin/budget_x.json`、mode 600 です。読取は未設定のファイルを作らず、壊れた JSON や不正な実体も初期値へ置き換えません。設定保存・ログ永続化の失敗は拒否または不確定として返します。実 API・本番請求との検証は、このローカル実装の試験とは別です。
