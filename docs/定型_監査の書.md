# 監査の書の雛形（release の関門が読む・設計「監査と審査の機械化と前向きな断り」§6・段 D）

この雛形を写して `docs/監査_<版>_<日付>.md` に置く（例 `docs/監査_5.12.0_2026-11-05.md`）。置き場は `docs/` の直下で、
`監査_` で始まる名前にする。関門（`python3 tools/release_gate.py`）は、その版の commit にある `docs/監査_*.md` の
うち、1 行目が `---` で始まるものだけを読む（頭の形ができる前の監査の書は読み物として残し、関門は見ない）。

## いつ要るか

前の tag からの差分が **危ない領域** に触る版だけ（masaru 2026-11-03・設計 §8 の 2）。危ない領域の表の正本は
`tools/release_gate.py` の `DANGER_AREAS` の 1 か所（server_writes・server_reads・guard・plaza_redact・leave・
callback/・privacy／terms・承認の口）。触らない版は、決まる柵（CI の全件試験・互換の柵）だけで通る。

## 頭の欄（機械が読む）

- `range`: `前の tag..監査した commit`。tag の名前か commit の番号（短くてよい）。関門は、危ない領域に触った
  commit が、この範囲（`前の tag` より後で `監査した commit` まで）に入っているかを見る。
- `dangers`: 閉じていない「危ない」の数。0 でなければ関門が止める（`release_audit_dangers_open`）。
- `waived`: 危ないを残したまま出す理由。書けば dangers が 1 以上でも通る（masaru の承認を取ってから書く）。
- `fixed`: 監査のあとに直した commit。ここに並べた commit は、範囲の外でも覆ったものとして数える
  （直しのたびに監査をやり直さなくてよい）。
- `auditor`: 監査した者（作った者と別の者。例 Fable・Codex・別のセッションの呼び名）。

`#` から後はその行の注で、関門は読まない。

## 本文

確かめた深さの印（【動】動かして確かめた／【読】読んで確かめた／【未】未確認）を付けて、「出す前に直す」
「出したあとでよい」「気づき」に分けて書く。「危ない」と数えるのは「出す前に直す」の項目。
