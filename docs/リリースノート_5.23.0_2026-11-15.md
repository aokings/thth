# THTH 5.23.0（2026-11-15）

台帳の器の次の版です。にがみラボが 5.22.0 で見つけたつまずき 2 つと、こぴちゃと NIGAMI が共通の台帳の出典を採れなかった所を直しました。別の者の検収（`~/Developer/thth-work/audit-s12/答え_5.23.0の検収_2026-11-15.md`）の危 1・軽 2・軽 3 も直しています。

| 件 | 中身 |
|---|---|
| 控えと別の checkout を指す `--path` | `<台帳>` を受ける命令に `--path <フォルダ>` を足しました（上の段の `add` を除く。2 段の命令の `row add`・`row set` には付きます）。本体・作業木・配信の作業木で台帳のフォルダの場所が違っても、控え直さずに確かめ・受け入れができます。指した道はその 1 回の命令の間だけ使い、控え（`registers/<名前>.json`）は書き換えません |
| 台帳の中の名乗り | 別の道が同じ台帳かは、台帳の中の名乗り `.thth/register.json` で確かめます。中身は `{"schema": "thth.register_name/1", "register": "<名前>"}` の 2 つの欄だけです。控えの道そのものなら名乗りが無くても今までどおり通ります。控えの道の台帳の名乗りが控えの名前と違うときも断ります |
| 名前の要る命令にフォルダの道 | `check`・`show`・`kinds`・`links`・`use`（`--outlet` なし）・`confirm` などは、`<台帳>` にフォルダの道を渡すと、名乗りから控えの名前を引きます。名乗りが無ければ、控えの道が同じ控え（1 つだけ）の名前を使います |
| 断り `register_path_other` | 名乗りの名前が違う（`other_name`）・控えの道でないのに名乗りが無い（`undeclared`）・名乗りが崩れているか symlink（`declaration`）のとき、何も読まず何も書かずに止めます |
| `--json` は 1 つの JSON | `thth register … --json` は、stderr に報告の 1 行（report_channel）を足しません。stdout も `2>&1` でまとめた出力も 1 つの JSON として読めます。報告の 1 行は JSON の `report_channel` の欄に入ります。入るのは断り（rc 2）と、赤の結果（rc 1 の `verify --outlet all` の赤・`export --check` の違い・`accept --outlet all` の断り）です。`--json` でないときの出力は今までどおりです |
| 分け合う出し口で読者が `common` を持てる | `dest_shared_with` の組（段 10）で、読者の出し口が `common` を持てるようにしました。共通から採った物を書く `common/*` を読者の置き場の型に数え、内の出し口の種類の置き場の型と重なれば今までどおり overlap で断ります。内の出し口の `common` は今までどおり断ります（要るまで開けない） |
| 大文字小文字の重なり（検収 危 1） | 置き場の型の重なりは、両方の型を NFC・小文字にそろえ、`./`・空の段を解いてから比べます。macOS の既定の置き場では `Common/` と `common/`、`Data/` と `data/` が同じフォルダなので、前は内の材料が読者の型のフォルダに置けました（`Data/` と `data/*` の形は段 10 からありました） |

名前ごとの状態（`register_state/<名前>/` の認めた記録・下書きの控え）は名前で引き、道ごとには分けません。認めた記録は行の中身の指紋で引くので、中身の違う checkout では認めたと読まれません。

にがみラボが包みの台本（checkout ごとに HOME を替えて控え直す形）をやめるには、台帳の repo に `register/.thth/register.json`（名前 nigami）を 1 枚置いて commit します。

- 全件の試験 `python -m pytest -q -n 4`: rc 0（書き手の手元・11/15）。

残した点:
- 下書きの承認のときの読み直し（`recheck`）は、控えの道の台帳を読みます。作業木で作った下書きは、控えの道の中身と違うか控えの道が無いと、承認で断られます（安全な向き）。
- 中身の違う checkout で `confirm` すると、行の認めた記録（行の番号 → 指紋 1 つ）が上書きされ、もう片方の checkout の同じ行は「認めていない」になります（安全な向き。検収 軽 1）。
- `--path` で打った命令の記録（admin の記録）には、どのフォルダかが残りません（検収 軽 4）。
- `--json` で report_channel を JSON に入れる直しは、register の命令だけです。ほかの `thth … --json` は今までどおり stderr に行が出ます。
- 受け入れや確かめの 1 段め（rc 1）の JSON には、report_channel の欄を入れていません。断りでなく、二段確認の 1 段めだからです。
