# 下調べ: 画面（MCP Apps）を段 K のリモート MCP に足すとき（2026-11-27・THTH括り 第4）

足すかどうかは THTH開発 第24 が決める。ここは「足すなら何が要るか」を、枝 `worktree-mcp-ui`（THTH画面 第1 の申し送り b7d9728d）と、この枝の `callback/src/mcp.js` を読んで比べただけ（動かしていない）。

## 結論（短く）

部品（4 枚の HTML と表）はそのまま使えるが、**つなぎ目が 4 つずれている**。足すのは中くらいの仕事で、Worker に触るので出すのは審査のあと。

## ずれ

1. **道具の名と組が違う。** 画面の表（`mcp/ui/catalog.json`）は stdio の道具の名で書いてある。リモートの道具（`callback/src/mcp-tools.js`）と重なるのは `thth_board`・`thth_morning` と、名の違う `analytics_report`（リモートは `thth_analytics_report`）だけ。
   - 予定の一覧（queue）: `thth_queue`・`thth_draft_list` はリモートに無い。`thth_board` だけ当たる。
   - 下見（preview）: `thth_preview` がリモートに無い。
   - 確定のカード（confirm）: 表は stdio の `thth_retract_request`・`thth_schedule_request`・`thth_bookmark_request` 向け。リモートの書く道具は `thth_approve`・`thth_hold`・`thth_revoke`・`thth_withdraw` で、どれも表に無い。
   - 数字（numbers）: `thth_summary` はリモートに無い。`thth_morning`・`thth_analytics_report` は当たる。
   → 表に「リモートの道具 → 画面」の欄を足すか、リモート用の表を別に持つ。
2. **答えの形が 1 段深い。** 画面は `structuredContent` の一番上（`.items`・`.status`・`.digest`・`.posts`）を読む。リモートの答えは `{command, rc, output: <CLI の --json>, workspace}` で、中身は `output` の下。加えて、VM の答えが遅いと `{status: 'pending', request_id}` が返り、あとで `thth_result` を呼ぶ。→ 画面が `output` を開く・pending を描く（`thth_result` を画面だけの道具として呼ぶ）か、Worker が画面用に包み直す。
3. **リモートは状態を持たない。** 画面の設計（§2）は「`initialize` で client が画面に対応すると言ったときだけ `_meta.ui` を足す」。リモートの `/mcp` は 1 回ごとの POST で、`initialize` の中身を覚えていない。→ 対応の有無を Connector の接続の行に控える（`initialize` のとき）か、いつも足す（対応しない client は `_meta` を無視する前提）かを決める。前者は今の柵（画面に対応しない client には 1 字も足さない・`test_mcp_ui_fence.py`）と同じ考え。
4. **確定の作りが違う。** 画面の設計（§3）は画面だけの道具 `thth_ui_confirm`（道具の名・digest・番号だけ）で 2 段目を呼ぶ。リモートの書く道具はもう 2 段で、2 段目は同じ道具に `confirm`（Worker が出した値。approve は 1 段目を見せた控えだけ）を付けて呼ぶ。→ リモートでは `thth_ui_confirm` を作らず、画面が同じ道具を `confirm` 付きで呼ぶ形が素直（Connector の控えがそのまま歯止めになる）。画面の表の確定の行を、この形に合わせ直す。

## Worker の側に足す物（足すと決まったら）

- `initialize` の答えに `resources: {}`、`resources/list`・`resources/read` で 4 枚の HTML（計 約 48 KB）を返す。HTML は Worker の module に文字として入れる（stdio と同じ物・作り直さない）。
- `tools/list` の画面を付ける道具に `_meta.ui.resourceUri`（3 の決め次第）。
- 柵: 画面に対応しない client の `tools/list` が今と 1 字違わない・HTML に外への通信が無い・答えに秘密が出ない（今の柵 6 に足す）。
