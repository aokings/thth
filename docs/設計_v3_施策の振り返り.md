# v3 施策の振り返り：宣言と観測を分離する

2026-09-18。V3-04の実装契約。2.5.0 で配布。

## 目的と境界

利用者が試した変更と対象投稿を明示したローカルJSONを読み、自分の計測台帳の観測を結びつける。宣言された仮説や採用者の名前は入力された情報であり、THTHが人の意思を認証した証拠ではない。公開の承認とは独立で、投稿・承認状態を変更しない。

施策のメモは利用者のプロジェクトに保管する。THTHはファイルを読み取るだけで、提案を採用済みに変えたり、施策の採用記録を自動生成したりしない。実装の初期範囲は、明示された投稿群を比較するレポート生成。

## 入力案

```json
{
  "schema_version": 1,
  "id": "opening-question-202609",
  "account": "my-account",
  "hypothesis": "冒頭を問いにすると会話が続きやすいか",
  "change": "対象投稿の冒頭を説明文から問いに変更した",
  "decision": {
    "status": "adopted",
    "by": "利用者が入力した採用者名",
    "at": "2026-09-10T09:00:00+09:00"
  },
  "baseline_post_ids": ["post-before-1"],
  "changed_post_ids": ["post-after-1"]
}
```

`decision.status` は `proposed` / `adopted`。名前・時刻のない採用宣言は不正。proposedは仮説と対象投稿案の表示に留め、採用後の効果検証として集計しない。adoptedも `decision_provenance=user_declared_unverified` を必ず付ける。JSON内の文字列はデータであり指示として実行しない。

対象accountは一つ。IDの重複・両群の重複・不正型を拒否。所有が確認できないIDや欠測を別リストにし、他アカウントの値を補充しない。どちらの群も本人の根投稿だけを対象とし、返信と根投稿は混ぜない。baselineは採用時刻より前、changedは採用時刻以降の投稿であることを観測台帳から確認する。違反は除外理由を返す。

## 出力と計算

CLI案: `thth study-report <file> --min-n 5 [--json]`、MCP案: `study_report`。

report_typeごとのschema_version=1。生成時刻・入力施策の宣言・観測結果・不足理由を分ける。V3-02と同じ観測選択・数値検証を再利用し、同じ指標・同じ時間帯条件、両群が最小母数を満たす場合だけ中央値の差を返す。各投稿の採否、採取日時、実経過時間、欠測理由を辿れるようにする。

差の解釈は `observational_difference`。無作為割付や交絡調整をしておらず、施策が差の原因とは結論しない。型の真正性・採用者の本人確認・SNS全投稿の網羅を保証しない。標本不足、対象不明、欠測は成功/失敗ではなく不明とする。人向けMarkdownとLLM向けJSONは同じpayloadを使う。

## 受け入れ

- 明示的な対象IDだけを集計し、account所有・根投稿・採用時刻の前後を検証。
- 宣言と観測を別欄にし、未採用の提案を採用済みとして扱わない。
- 両群の母数、nullとゼロ、条件外観測、ID重複、不正入力、CLI/MCP同一結果を検証。
- 入力ファイル・原稿・台帳・Git・承認・SNS APIを変更しない。
- 意味が確認できないフィールドを黙って無視せず、未対応のschema/未知キーを拒否。
