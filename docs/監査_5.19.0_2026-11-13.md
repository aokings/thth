## 気づき

1. 【動】【読】**承認のあとは台帳を読み直さない。下書きの本文も読み直しの対象でない。** 承認のあとに催しが中止になっても、予約から出る側が見るのは出さない期限（`not_after`）だけ（`thth/select.py`・`from_register` を読むのは `cli.py`・`register/draft.py`・`register/recheck.py` の 3 つ）。下書きの本文に「12月25日は終日お休みします」と書き足しても、行が変わっていなければ承認は通る（本文を整える前提の作りどおり）。計画の言う「承認の時の読み直し」とは合う。本物の店で回すときは、「承認から出るまでのあいだに行が変わったら止める」を足すか決めたい。
2. 【動】**二段の digest は、1 段目を見なくても作れる。THTH の側の認めた記録を書ける者は、認めたにできる。** digest は台帳の名前・行の番号・中身の指紋の sha256 の頭 12 字で、自分で計算した値を `--confirm` に渡すと 1 回で確定できた。認めた記録（`register_state/<名前>/confirmed.json`）に指紋を手で書くと、臨時の行が材料に使えた。どちらも「同じ機械の同じ利用者とその LLM は疑わない」という THTH の立て方の内で、台帳の側（git の repo・ほかの人も書ける）からは偽れない。二段は「全文を見せる」ための段で、鍵ではない。
3. 【動】**違うと言われた行を直して「推測」に戻しても（同じ番号）、二度と聞かれない。** 店の行に no と答えたあと、名前を直して `confirmed: 推測` に戻すと、穴の一覧には出るが、29 日のあいだ `ask` は 1 度も選ばなかった（no と答えた穴の番号 `guess:<行>` がずっと外される）。直した行は新しい番号で置くか、`register confirm` を直に打てば進む。穴の手がかりにその一言があると迷わない。
4. 【動】**聞く上限は台帳ごと。** 1 人の持ち主の 2 つの台帳（見本の喫茶と雑貨）で同じ日に `ask` を打つと、合わせて 6 問出た。privacy とリリースノートは「1 日 3 問まで」。持ち主ごと・project ごとにまとめるか、文を「台帳ごとに」と直すか。
5. 【動】**落ちる所が 3 つある（Python の例外がそのまま出る・秘密は出ない）。** (a) `private_fields: date` と書いた臨時の行で `register draft` と `register paste` が `AttributeError`。(b) 問いの記録に `id` の無い行があると `ask`・`questions`・`answer` が `KeyError`（壊れた記録は `register_question_log_invalid` で断るはずの所）。(c) `register draft --by` に形の違う名前を渡すと `ValueError`（ほかの命令は `register_args_invalid（by）` で断る）。
6. 【動】**project の違う口座への下書きは、注意の 1 行だけで通る。** 台帳の project が `sample`、口座の project が `nigamilab` で、下書きは rc 0 で書かれた（`notes` に「出す先が合っているか確かめてください」）。店 A の事実が店 B の口座に出る道なので、断る側に倒すか、`--allow-other-project` のような旗にするか。
7. 【動】**`register paste --json` には、場所の URL と管理する人が入る。** 貼る文（`text`）と人の読む形には入らない。privacy の「場所の頁の URL と、誰が管理するかは、貼る文に入れません」とは合う。持ち主の LLM がこの JSON をそのまま外に貼らないよう、欄の名前で分けるか（`place_url`・`place_admin_by`）、`notes` に一言。
8. 【動】**台帳のフォルダを THTH の `register_state/<名前>/` の中に置くと、`register remove` と `leave` で消える。** `register add --path` は THTH の置き場の中の道を断らない。わざとそこに置かない限り起きない。逆に、認めた記録の置き場が symlink のときは消さずに残す（消した物の並びに `state` が入らない）ので、置き場に symlink が 1 つ残る。
9. 【動】**道の柵は、末尾に改行の付いた URL を通す。** `https://connect.squareup.com/v2/locations\n` が `check_request` を通った（Python の `urlsplit` が改行とタブを落とすため）。呼ぶ側は URL を渡せず、道は定数と形を検査した id から組むので、今この形を作る道は無い【読】。打つ側（`urllib.request`）も末尾の改行を落として同じ道に出る【動】。BASE・STORES の柵も同じ作り。柵の頭で制御文字を断ると、あとで道を足すときに安心。
10. 【読】**在庫を数える種類が、出してよい品の合わせて 50 を超えると、読み全体を断る（`pos_read_limit`）。** 種類の多い店（色とサイズのある物販）では、部門ごとに出すと届きやすい数。断りは直し方を言うが、本物の店で数を見て決め直したい。
11. 【読】**行の `source` に `register`（レジから）の語がある。** 今は THTH が台帳に行を書く道は無く、レジの値から行を作るのは持ち主の LLM だけ。THTH がレジから台帳に写す道を作るときは、privacy の「この下書きには、店の頁もレジも使いません」を直す。
12. 【読】**スマレジの「店の取り違え」の検査は効かない。** 鍵のファイルの `shop_id` に入るのは台帳の契約 ID そのもので、レジから返った値ではない。鍵は契約ごとなので、違う契約の鍵は鍵を取る所で 401 になり、害は無い。
