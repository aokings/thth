# リリースノート 3.1.1（退出・取り下げ・自分の除外・通知の案内ほか）— 下書き

2026-09-23。**版は据え置きです**（`thth/VERSION` は 3.1.0 のまま・tag は未作成・release も deploy もしていません）。3.1.0 の実機で見つかったものの直しです。依頼は [依頼 3.1.1](依頼_3.1.1_退出と取り下げと自分除外_2026-09-23.md)（件 5〜7 は kopicha セッションの実測から追加）。

## 退出（`thth account leave`）

- **同じ本人の別 account があっても、Mastodon と X の退出が最後まで通ります。** これまでは同じ instance の同じ利用者（user_id が同じ）の別台帳があるだけで「共有」と見て、失効の手前（`worker_revoked`）で止まっていました。失効は渡した token の値だけに効くので、共有と見るのは token の値やファイルが同じときだけにしました。退出する account の token だけを失効させ、別 account の token と台帳には触りません。
- token の値・ファイルが同じときは、これまでどおり `shared_credential_revoke_refused` で失効を断ります（停止は戻さず、再試行用の認証情報も消しません）。
- Threads と Bluesky は従前どおりです（接続の解除は本人の設定）。

## 取り下げ（`thth retract`・承認を通る取り下げ）

- **Mastodon の投稿を取り下げられるようになりました**（`DELETE /api/v1/statuses/:id`）。Threads・X と同じ二段承認で、DELETE は 1 回だけ・再試行しません。
- 要る scope は `write:statuses` で、道具が認可で求める scope に既に入っています（認可のやり直しは要りません）。token に乗っていなければ DELETE を投げずに「`thth auth <account>` をやり直してください」で止まります。
- 媒体にもう投稿が無いとき（404）は `post_missing` で止まり、記録は変えません。応答の id が取り下げを頼んだ投稿と一致しないときも、取り下げたとは言いません。

## 毎朝の一枚（`thth morning`）

- **絡みに行く先に自分が出なくなりました。** 同じ project の同じ媒体の全 account（同じ本人の別台帳を含む）の投稿を除きます。件数と異なりは除く前のままで、除いた本数を `own_excluded` に出します。`morning <account>` と 1 本を名指ししても、同じ project の他の台帳を見ます。
- **時刻超過に名前が付きました。** 予定の段に `overdue_items`（ファイル名・予定時刻・経過時間・先頭 60 字、古い順に最大 10 件、全体の数は `n`）を出し、1 枚の画面にも「時刻超過: <file> <publish_at>（<経過>h）」と並べます。次の一手に「超過」の候補が加わります（本文は作りません）。
- **返していないものの窓が、台帳の `collect_days`（既定 14 日）になりました。** これまでは 7 日固定でした。窓の残りが 24 時間を切った行に `window_edge: true` と「⚠ 窓まで <n>h」が付きます。

## 返信を読む（`thth replies <account>`）

- **同じ repo を持つ他 account の投稿の返信を出さなくなりました。** これまでは、置き場を共有する他 account の返信まで自分の分として返していました（kopicha-bluesky で Threads の返信が並んだ）。`--json` の各行に `account` と `medium` が入り、読まなかった他 account のファイルの本数を `counts.other_account_files` に出します。`--post` の指定は従前どおりです。

## 運用通知

- `thth run` の「運用通知に未完了があります」の案内に account 名が入り、そのまま打てる形（`thth notifications status <account>`）になりました。
- `thth notifications status` や `test` を account 無しで打つと、汎用の失敗文ではなく `account_required` と正しい打ち方を出します（rc 2）。

## 変わらないもの

- 版・tag・配布・Worker（callback/）は変えていません。
- 退出の規律（停止を戻さない・唯一の再試行資格を消さない）と、毎朝の一枚の規律（読むだけ・分母・静的な理由・本文を作らない）はそのままです。
