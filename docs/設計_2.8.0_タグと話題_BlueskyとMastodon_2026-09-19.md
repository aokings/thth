# 設計 2.8.0: タグと話題——Bluesky・Mastodon を試金石に

2026-09-19。masaru の言葉: 「トピックやハッシュタグはフォロワーが少ないところからアカウントを立ち上げるための頼りの綱。とくに Mastodon と Bluesky は Threads みたいな審査がないなら、全面的に対応して試金石としたい」。
本書は契約を固定する。実装は Codex。裁定が要る点は §6。

## 0. 現在地（2026-09-19 に実測・L1）

| | Threads | Bluesky | Mastodon |
|---|---|---|---|
| 話題の印 | `topic_tag`（本文の外・1 投稿 1 つ） | 本文中の `#語`＋**`richtext.facet#tag` を投稿側が付ける**（付けないとただの文字） | 本文中の `#語`（サーバが自動で拾う） |
| 投稿 | 対応済み（`topic:` 欄） | **未対応**: `build_facets` は URL の facet しか作らない | 本文に書けば効く |
| 観測 | `--search`（App Review 待ちで自分の投稿のみ） | `searchPosts` を語で（1 頁） | `/api/v2/search type=statuses`（1 頁） |
| lint | `hashtags: true` | 台帳 `hashtags: false` → `#語` を**弾く** | 同じく弾く |

つまり Bluesky・Mastodon では「タグを付けて出す」がいま**できない**（lint で止まり、通っても Bluesky ではタグにならない）。

## 1. 目指すもの

フォロワーが少ないアカウントが、**人が既に集まっている話題に正しく載る**こと。Threads の使い方文書 §「トピックの選び方」の規律（人が使っている語を選ぶ・自分で作った語は誰も見ていない・1 投稿 1 話題）を、両媒体にそのまま持ち込む。

審査が無いので、**投稿 → 観測 → 比較の一巡を両媒体で先に回し**、Threads の App Review が通ったときに同じ形で受けられるようにする（試金石）。

## 2. 投稿側（2.8.0）

### 2.1 原稿の書き方——`topic:` 1 つを媒体の流儀に写す

- 原稿の front-matter は今までどおり **`topic:` 1 つ**（媒体ごとに違う書き方をさせない）。
- **Threads**: `topic_tag` に（現状どおり）。
- **Bluesky**: 本文の**末尾に改行 1 つを挟んで `#語`** を足し、`richtext.facet#tag`（`tag` は `#` 抜き）を付ける。字数（300 grapheme）は**タグ込み**で数える。既に本文に同じ `#語` があれば足さず、その位置に facet を付ける。
- **Mastodon**: 本文の末尾に `#語` を足す（facet は不要）。字数（500）はタグ込み。
- 語の正規化は `queuefile.normalize_topic()` を共有するが、**Threads 用の 50 字上限は他媒体に適用しない**（媒体ごとの検査へ振り分ける・Bluesky は 64 grapheme／640 bytes）。媒体の禁則（Bluesky: 空白不可・64 grapheme・`#` 抜きで facet／Mastodon: 空白不可・英数と `_`・Unicode 文字可）を adapter が検査して、通らなければ **lint で loud reject**（黙って落とさない）。
- `hashtags: false` の台帳では `topic:` があっても `#語` を足さない（文体規約を優先）——**その代わり lint が「この媒体では topic が効かない」と 1 行言う**。
- **承認の指紋は「公開される本文」で計算する**（Codex の実装中の発見・2026-09-19）。末尾に `#語` を足すなら、`thth approve` の一段目は**足した後の本文**を見せ、digest もその本文で取る。「A を見せて B を承認する」を作らない（設計 v1 の二段承認の規律）。したがって 2.8.0 より前に承認された Bluesky／Mastodon の原稿で、新たに末尾タグが付くものは `approval_stale` として**再承認が要る**（本文の変換が無い原稿と Threads の既存の指紋は維持）。`hashtags` の設定が一段目と二段目の間で変わって表示本文が変われば、以前の digest では通らない——これを意味試験で固定する。

### 2.2 本文中の `#語`（`topic:` とは別）

- 台帳 `hashtags: true` のとき、本文中の `#語` は Bluesky では**全部**に `facet#tag` を付ける（URL の facet と同じ機構・UTF-8 バイト位置）。Mastodon はそのまま。
- `#語` の数の上限は台帳で（既定 3。超えたら lint）。数えるのは**本文中の出現数で、`topic:` から自動で足した分を含む**。`topic:` と同じタグが本文に既にあれば足さない。

### 2.3 台帳

- masaru-bluesky・masaru-mastodon の `hashtags` を **true** に（運用の操作・§6-1）。
- `max_hashtags`（既定 3）を台帳に足す。無ければ既定。

## 3. 観測側（2.8.0）——両媒体は審査無しで世間が読める

`thth where`／`where_to_appear`（設計「自分の泉」§2.3）と `thth topics --search` を、タグを軸にできるようにする。**保存するのは集計だけ**（既存の規律。本文・username は捨てる）。

### 3.1 Bluesky

- `searchPosts` に **`tag` パラメータ**（`#` 抜き・複数可）と `q` の組み合わせ。`sort=top|latest`、`since/until`。1 頁で足りなければ `cursor` で最大 N 頁（台帳 `search_pages`・既定 4・上限 10）。
- 出すもの: 既存の観測（n・投稿者の異なり数・直近時刻）＋**タグ付き投稿の割合・その語と同時に使われている他のタグ上位 5**（自分の語を決める材料）。
- トレンドの口は **`app.bsky.unspecced.getTrends`／`getTrendingTopics` として存在する**（Codex の実装前照合 2026-09-19・L2）。`unspecced` は仕様未確定で変わりうるので**今回は使わない**（訂正: 当初「無い」と書いたのは誤り）。熱さは `searchPosts` の直近 24h の n と投稿者の異なり数で。取得上限（頁数・件数）と観測範囲を必ず出力し、世間全体の総数とは呼ばない。`searchPosts` は `q` 必須・`tag` は AND・`since` 含む／`until` 含まない・`cursor` は全件を保証しない。

### 3.2 Mastodon

- **`GET /api/v1/timelines/tag/:hashtag`**（そのタグの公開タイムライン・ローカル/連合）と **`GET /api/v1/trends/tags`**（インスタンスが見ているトレンド・`history` に 7 日の日次 uses/accounts）を足す。既存の `/api/v2/search` は `type=hashtags` も使い、語に近いタグの候補と `history` を出す。
- 出すもの: 3.1 と同じ形＋トレンドの `history`（日ごとの投稿数・アカウント数・**インスタンスの視界での値**と明記）。
- 連合の見え方はインスタンス依存なので、`observed_from: <instance>` を必ず添える。

### 3.3 共通の形

- `where_to_appear` の出力に `by_tag[]`（`tag`・`n`・`distinct_authors`・`latest_at`・`co_tags[]`・`observed_from`・`window`）を足す。既存の鍵は変えない。
- 保存: 既存の観測の棚（`thth topics --note`）に **人が** 記録する形はそのまま。自動で溜める定期観測（Threads の C4 に当たるもの）は **両媒体でも今回はやらない**——まず手動の一巡を試金石にする（§6-3）。

## 4. 比較側（2.8.0）——タグの効果を自分の台帳で

- 実測の行に `topic`（既存）に加え、Bluesky/Mastodon では**実際に付けたタグ**を `tags: [...]` として残す（採集時点の値）。
- `analytics-report --compare-previous --by topic` は既存。`--by tag`（タグ有り／無し・タグごと）を足す。`min_n` 未満は `null`。率は出さない。

## 5. 順番と検収

1. 2.1・2.2（Bluesky の tag facet・Mastodon の末尾タグ・lint）——**投稿が正しくタグになる**ことを実機で 1 本ずつ確かめる（masaru-bluesky・masaru-mastodon に 1 本ずつ・masaru の承認）。Bluesky はタグの feed に載るか、Mastodon は `#語` のタイムラインに載るかを目で見る。
2. 3.1・3.2（観測）——`thth where` が両媒体でタグの材料を出す。
3. 4（比較）。
4. 一巡: 語を選ぶ → タグ付きで出す → 24h 後に `after` と `analytics-report` で読む → 記録。これを両媒体で 1 回ずつ通し、`thth-notes` に残す。
- 検収条件: 意味を確かめるテスト（facet のバイト位置が UTF-8・日本語タグ・上限超え・`hashtags: false` の扱い・観測の集計に本文が残らない）、変異、実機 1 本ずつ、2.7.0 の probe 回帰。
- 一次資料（Codex が読み、URL・取得日・引用を残す）: AT Protocol `app.bsky.richtext.facet`／`app.bsky.feed.searchPosts`、Mastodon `timelines/tag`・`trends/tags`・`search`。両媒体の規約（Bluesky ToS・各インスタンスの rules）で「公開投稿の集計を自分の台帳に残す」に制限が無いかを 1 度確認（Meta ほどの縛りは無いはずだが **未確認・L3**）。
