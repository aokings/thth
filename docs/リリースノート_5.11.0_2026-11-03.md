**読むだけは変わらない。** 新しく書くのは「置いた本人が隠す」ときの広場の 1 件と変更ログだけ（管理者の非表示と同じ所）。Meta も GA4 も呼ばない。

### 契約の変わったところ（足すだけ）

- `thth plaza post` の答えに `report_type: "plaza_post_preview"`（`--preview` のとき）。鍵は `preview`・`posted: false`・`plaza_id: null`・`account`・`project`・`kind`・`scope`・`evidence_level`・`visibility_default`・`from`・`observed`・`view`（置く本人に見える原本、open なら他の持ち主に見える写し）・`digest`（open のときだけ・二段目の digest）。open のときは `visible_to_other_owners` も（一段目と同じ中身）。
- MCP `thth_plaza_post` に `preview`（boolean）。
- `thth scenario show <project> <糸>` の答え（`thth.scenario/1`）に `threads_clicks`。dashboard campaign の `outcomes.threads_clicks`（と、言えないときの `outcomes.cannot_say.threads_clicks`）。
- plaza の `--from scenario` の観測（`tool_numbers.numbers`）に `threads_clicks`（数と分母と理由だけ）。open の写しにも同じ鍵（原稿の名前・post_id・リンク先は持たない）。5.10.0 までに置いた書き込みは持たないので、その写しの digest は変わらない。
- seeds（`report_type: "scenario_seeds"`）に列 `clicks`（「クリックの多かった告知（Threads・72h）」・訪問の列の次）。返信の列の媒体の節に `nonzero`、返信の数を返信の台帳から数えた行に `replies_source: "ledger"`。
- project の dashboard（`thth dashboard <project>`）に `site_referrers`。
- 鍵の名前を変えたもの・消したものは無い。

### 変えたこと

1. **`thth plaza post … --preview`（置く前に見る）。** 範囲（project・owner・open）を問わず、`plaza.post` が作る本文・観測の欄・道具の下書き・範囲の既定（組に入っていれば owner）まで作って表示し、**何も書かない**。重複と 24 時間の上限は `STORE.load()` で読むだけで確かめる（ロックを取らない・置き場も `.lock` も作らない・変更ログにも書かない）。表示は open の一段目と同じ道（`plaza_cli._emit_preview`・rc 1・断りに数えない）。`--json` も同じ。open なら二段目の digest も出し、「`--preview` を外して `--confirm <digest>`」で置ける。open の二段確認そのものは今までどおり。
   - MCP `thth_plaza_post` の `preview: true` も同じ（MCP から open に出せないのは今までどおり）。
   - `thth observe` の「広場に置く」の候補（`plaza_moments`）に `preview_command`（同じ命令に `--preview`）を足し、morning の表示で「まず見る（何も書かない）: …」の 1 行を命令の前に出す。skill `thth-flow` の命令の例にも「まず `--preview`」。
2. **置いた本人が自分の 1 件を隠す口: `thth plaza hide <id> --as <account> --reason <理由> --by <名前>`。** 隠し方は管理者の `thth admin plaza hide` と同じ（`hidden` に時刻・誰・理由。本人のときは `by_poster: true`）。`STORE.update` の中で `viewer_for_target(account).owns(record.project, record.account)` を確かめ、他の持ち主の id は無い id と同じ `plaza_not_found`。同じ project の別の account からも隠せる。変更ログは `plaza_hidden`（`diff.hidden_by: [null, "poster"]`）。戻すのは管理者。`plaza_hidden` の断りの文を「非表示の書き込みです（管理者か、置いた本人が隠しました）」に直した。
3. **Threads の投稿ごとのリンクのクリックを、糸の show・dashboard campaign・seeds・plaza の観測に。** 1 本の数は `click_attribution.Index.for_account(...).attribute(post_id, posted)`（`thth map`・observe と同じ計算・`basis: unique_url_72h`・投稿日を含む 3 暦日）。数に入れるのは `basis` があり `clicks_72h` が null でない投稿だけで、言えない投稿は理由ごとの本数（`reasons`）。連投は先頭の post_id。**GA4 の訪問（`site_visits`）とは別の欄**で、足さない・混ぜない。Threads 以外の媒体は `clicks_72h: null` と `per_post_clicks_unavailable:<媒体>`。分母は「クリックを言える本数（`n`）／糸の Threads の本数（`of`）」（seeds は窓の中の自分の Threads の本数）。中身は新しい `thth/thread_clicks.py` の 1 か所。
   - plaza の `--from scenario` は、言えたクリックが 1 本でもあれば「観測あり（observed）」の根拠に入れる（道具の実測なので）。
4. **`site_visits` の控えの `referrers` を project の dashboard にサイトの数として**（糸には結ばない）。host は scheme・`user@`・path・`?`・`#`・port を落として小文字に整え、ホスト名の形に合わないもの（`(direct)`・空・path だけ・文）は捨てて、行数と sessions だけ `dropped` に数える。同じ host に整った行は足す。出すのは host と sessions だけ（サイトごとに多い順・20 まで・残りは `more`）。取れなかった窓は `referrers_unavailable`。
5. **seeds の返信の列に「1 件以上あった本数／n」（`nonzero`）と、返信の数の出所。** 返信の数が 24h の刻みでなく返信の台帳から数えたものなら行に `replies_source: "ledger"`。`after_cli.reaction_lookup(account, with_source=True)` で取る（既定の形は変えない・`who_cli` の出力は今までどおり）。

### 設計から外した所・決めた所

- `--preview` の rc は open の一段目と同じ 1（同じ道にしたため）。範囲が project でも 1。
- 本人が隠した 1 件の `hidden` に `by_poster: true` を足した（管理者の非表示と見分けるため。鍵を足すだけで、読み方は同じ）。
- `thth plaza hide --as` は account だけ（project 名は `invalid_account`）。変更ログの account を決めるため。
- 媒体の節（`other_media.<媒体>.cannot_say`）の理由は媒体名を付けない `per_post_clicks_unavailable`（媒体名は節の鍵）。媒体名つきの `per_post_clicks_unavailable:<媒体>` は塊の `cannot_say` の列と seeds の列の `cannot_say` に出す。dashboard の型の理由の表（`THTH_REASON`）が符丁を引けるようにするため。
- dashboard の型（`skills/thth/dashboard/campaign.html`・`project.html`）は理由の表に符丁を足しただけで、クリックと参照元の欄はまだ描いていない（`--json` には出ている）。
- 試験の作り物の `reaction_lookup`（`lambda account: …`）は、v590 に加えて v5100 の 3 か所も `**kw` を受ける形に直した（seeds が `with_source=True` を渡すため）。
