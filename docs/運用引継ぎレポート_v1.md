# 運用引継ぎレポート v1

`thth handoff-report ACCOUNT [--json]` または `thth handoff-report --project PROJECT [--json]`。
MCP は `operations_handoff` に account / project の一方を渡す。同じ構造化結果から Markdown を作る。

ローカル queue、sent、inflight、通知 outbox、healthcheck の保存記録だけを読み、同期・API・秘密設定読取・承認・再試行・書き込みは行わない。
`generated_at` はこの読取時刻。evidence の `local_modified_at` はファイル更新時刻であり、SNS の取得時刻ではない。鮮度と remote の最新状態は常に未検証。

- blocked: inflight 記録が存在する。既存の安全な reason / next_action code を添える。自動的に再送しない。
- unknown: 読めない重要記録がある、または判断材料がない。
- review_required: 下書き、1時間超の予定超過、型外、通知未処理、保存された失敗のいずれか。現在も障害中とは断定しない。
- waiting: ローカルに承認済み待機原稿がある。承認指紋、Git 一致、公開可能性、timer 正常を保証しない。

queue の件数は account で絞る。帰属できない型外はファイル名を出さず `unattributed_malformed` に集計する。読み取り失敗時の部分集計は出さず null にする。通知記録なしは未処理ゼロにしない。SMTP受付と受信者への配送完了は別。

投稿本文・ユーザー名・通知先メールアドレス・絶対パス・生の例外を出力しない。project 解決では account 台帳のメタデータを読むが、その外の運用記録や token/env は読まない。読み取れない台帳があれば scope_complete=false。

既定呼出では前回セッションとの差分を出さない（`--since-last-read` は保存済みsnapshotとの差分を出すが、間の全イベントは復元しない）。未返信数、スレッド連投状態、token有効性、現在のtimer稼働は対象外として明記する。サーバ型の利用者認証境界はこのローカルコマンドでは実装しない。

`evidence.queue`はrepo未設定でも5鍵（availability、freshness、local_modified_at、observed_at、remote_current_verified）を固定する。未設定はmtime=null、freshness=not_applicable、remote_current_verified=false。

## schema_version 1 で追加された鍵（2.6.0）

A8: 各 account の `cannot_say_details` は既存 `cannot_say` と同じ位置の text と、英小文字アンダースコア code。既存運用理由コードはそのまま code にする。

A4: `handoff-report account --since-last-read` で account の `changes_since` を先出し。保存済み snapshot と今回の値を比べ、queue 件数・inflight・通知 event/state・run・最後の投稿・sent 件数の変化だけを出す。未知→0 は差分数値 null。`sent_count` と通知 `last_event_id` も追加。

書込は CLI の `--mark-read --by 名前` の組だけ。名前は自己申告で本人確認ではない。state/account/handoff_cursor.json を通常ファイル・0600・原子的置換で1世代保存する。読取・書込とも symlink/FIFO を拒否。rootから各ディレクトリを保持したdir_fd相対で開き、祖先の検査と利用の間のsymlink差替も追わない。cursor 不在/不正/異なる schema は changes_since=null、no_previous_session_cursor。不正は cursor_unreadable も付く。通常呼出の cannot_say は維持。有効な `--since-last-read` のときだけ前回不在理由を除く。

MCP と service/HTTP は `since_last_read` boolean だけ受理し、mark_read/by 書込引数は拒否する。報告の他の read-only 契約は同じ。
