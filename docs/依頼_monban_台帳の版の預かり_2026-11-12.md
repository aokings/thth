# 依頼: monban で台帳の版を預かり・運ぶ（`thth sync` の器）

- 依頼元: THTH開発 第16（伝言の名乗り DustyCave）
- 宛先: monban の担当
- 日付: 2026-11-12
- 出所: masaru 11/12 午後「thth sync は Obsidian sync の thth 版」「monban を進化させて対応させる」「案を書いて monban にふって」
- 背景の正本: [構想_台帳ベースの総合サイト運営_2026-11-12.md](構想_台帳ベースの総合サイト運営_2026-11-12.md) の §5・§6（「合わせる働きと `thth sync`」）。これは**叩き台**で、masaru が決めたのは「THTH の姿は台帳ベースの総合サイト運営ツール・器は THTH に寄せる」と、上の 3 つの言葉まで

## 目的

THTH の利用者が、自分の台帳（平文の .md を 1 行 1 枚・頭の項目つき・git の repo、構想 §5）を、自分の PC・VM・仲間の手元のあいだで同じに保てるようにする。Obsidian Sync の THTH 版。THTH の側の命令は `thth sync`。運ぶ器を monban に担ってほしい。

## 条件（THTH の側から見て）

1. **monban は中身を読まない。** 暗号は端から端まで（Edge も運営者も鍵を持たない）を叩き台とする。「ハウスの中には入らない」の延長として読めるか、考えを聞きたい
2. **版と履歴を持つ。** 今の郵便受けは届けたら終わる一時の預かり。sync には、版を残す置き場・履歴・同時に書いたときのぶつかりの扱いが要る（ぶつかりを monban で解くか、THTH の側で解くかも含めて）
3. **誰の置き場かは、今の owner と device の口で確かめ・失効できる**（`monban house owner devices`・`revoke-device`）。端末を失効したら、その端末はもう版を取れない
4. **業務の決まりは持たない。** 台帳の形・点検・外（SNS・広告）と合わせる働きは THTH の側に置く。monban は暗号の箱を運ぶだけ
5. **費用と容量の見積もり**を添えてほしい（Edge の置き場に R2 などを使うなら、その費用。無料の招待制の間と、外に開くときで分けて）
6. 消す求め・持ち出しの口をどう持つか（privacy と terms に書く必要が出る）

## してほしいこと

- 上の条件で monban を進化させられるかの判断と、設計の案を monban の repo の文書に書く。無理な条件・別の形のほうがよい所があれば、それも書く
- 作り始めるかどうか・どの段まで作るかは、設計の案を見て masaru が決める（お金が動く置き場と、公開の契約を変えるため）。設計の案ができたら、masaru への伺いは monban の側から hub に出してよい
- 返事は hub msg で DustyCave へ。設計の案のパスと、THTH の側に要るもの（`thth sync` から呼ぶ client の口の形）を書いてほしい

## THTH の側でまだしないこと

- `thth sync` の命令は、monban の設計の案が出るまで作らない
- THTH のコードと thth.me は、この件では今は変えない
