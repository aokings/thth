# 依頼: SNS に返信が来たら、担当のセッションを機械で起こす（THTH → h2d、2026-10-20）

依頼元: THTH開発 第6。masaru 10/20「スレッズなどに返信きたら、担当セッションの呼び鈴鳴らして対応促したらどうでしょうか。h2d使うとか」「兎に角一連を機械だけでやれるようにして下さい。llmは返信を考えてセットするところだけ動くように」。

## 目当ての一連（LLM が動くのは ④ だけ）

1. THTH の timer が 10 分ごとに会話を採る（今ある）。
2. **h2d の感知**が、口座ごとに「返していない返信の数」を読む（`thth observe <口座> --json --no-mark --counts-only --no-world` の `sections_by_name.unanswered.value.by_account.<口座>.value.replies.value.n`）。
3. 数が**増えた**ら、h2d の決まりがその口座のレーンを `wake` で起こす（hub の呼び鈴）。
4. 起きたセッション（LLM）が返信を読んで答えを書き、承認して置く（`publish_at` を今にして 2 段で承認）。
5. THTH が承認の場でその場で送る（4.3.0 から）。窓や上限で残った分は timer が出す。

## 今あるもの（手本）

関東の Threads だけ、この一連が動いている: 感知 `thth-kanto-replies`（probe `thth-observe-asmon-kanto-threads`・15 分ごと・`threshold above 0 kind changed`）→ 決まり `asmon-kanto-thth-reply`（`wake` to `asmon/kanto`）。

## 頼みたいこと

1. 下の口座に、関東と同じ probe・感知・決まりを置く（probe と感知は h2d の config。決まりの owner は各レーン）。
2. **鳴らし方を「数が 0 → 1 以上」でなく「数が増えたら毎回」にする**。関東の今の形だと、返していない返信が残っている間に次の返信が来ても鳴らない（kopicha の Threads は 10/20 夕に 9 件たまっている）。増えた分だけを `{source_headline}` に入れられるとよい。減ったとき（返した）には鳴らさない。
3. 夜（23:00〜07:00）は鳴らさず、朝にまとめて 1 回（持ち越しは起こし方の決まりで）。同じ口座で 30 分以内に続いたら 1 通にまとめる（`bundle` か `cooldown`）。
4. 関東の今の決まりも 2・3 の形にそろえてよい（関東のレーンに一言）。

## 起こすときの本文（各レーンが返信を書くための手順）

```
{source_headline}
<口座> に、まだ返していない返信があります。
1. 読む: ssh wt 'env THTH_ROOT=/srv/thth /srv/thth/app/bin/thth replies <口座> --json'
2. 答えを書いて置く: 返信先の post_id を reply_to に、publish_at を今にして queue に置き、2 段で承認する
   （thth.me の口座 inv-… は MCP の thth_send_request か draft_put → schedule_request）
3. 承認の場でその場で出る（THTH 4.3.0）。窓・上限で残った分は timer が出す
```

## THTH の側

足すものは無い（9 口座とも 10/20 に上の値が読めることを確かめた）。出力の形を変えるときは、この依頼の読み口（`sections_by_name.unanswered…replies.value.n`）を壊さない。
