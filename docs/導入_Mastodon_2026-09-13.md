## 1. Threads と何が違うか

| | Threads | Mastodon | 印 |
|---|---|---|---|
| 投稿 | container 作成 → 30 秒待つ → 公開の**二段** | `POST /api/v1/statuses` の**一段** | **L2** |
| 二重投稿の防ぎ | THTH の inflight だけ | inflight ＋ **`Idempotency-Key` ヘッダ**（サーバが 1 時間覚える） | **L2** |
| 返信 | `reply_to_id` | `in_reply_to_id` | **L2** |
| トピック | `topic_tag` | **無い**（渡されても黙って捨てる） | **L2** |
| 会話 | `/conversation`＋頁送り | `/context` の `descendants`。**頁送りは無く 4,096 件・深さ無制限が上限**（token 付き） | **L2** |
| 本文 | 素のテキスト | **HTML**（`<p>`・`<br>`・実体参照）。アダプタが落とす | **L2** |
| views | 取れる | **無い**。`insights` は `likes`・`replies`・`reposts` の 3 つだけ | **L3**（一覧に載っていない、という不在の証拠） |
| 文字数 | 500 固定 | **インスタンスごと**。`/api/v2/instance` の `configuration.statuses.max_characters` | **L2** |
| トークン | 60 日で切れる・`refresh` が要る | **期限が無い**。`refresh_token()` は呼ばない | **L2** |
| サーバ | 1 つ | **インスタンスごとに別**。`instance` が base URL そのもの | **L2** |

失敗の三分類（設計 [設計_THTH_2026-09-08.md](設計_THTH_2026-09-08.md) §3.5）は**Threads とまったく同じ規則**にした（**L1**）:
4xx →`publish_definite`（出ていない・inflight を消す）／timeout・接続断・5xx・200 だが id 無し →`publish_ambiguous`（分からない・inflight を残して人を呼ぶ）。
`before_publish` が断れば `publish_vetoed`（**送信要求の前に返るので、出ていない**）。
container 段が無いので `on_container_created` は**呼ばない**。

## 2. masaru の手でやること（この 3 つだけ）

1. インスタンスを 1 つ選んでアカウントを作る（無料）。**どのインスタンスにするかは、読者がいる場所で決める**（設計 v2 §0）。
2. そのインスタンスの `設定 → 開発 → 新規アプリ`（画面の呼び名は版で違う・**L3**）で application を作り、権限を
   **`read:accounts`・`read:statuses`・`write:statuses`** の 3 つにする。`profile` でも verify_credentials は通る（**L2**）。
   - `POST /api/v1/statuses` は `write:statuses`（**L2**）
   - `/context` は token 無しでも公開投稿は読めるが、**token 付きの方が上限が高い**（60 件・深さ 20 → 4,096 件・深さ無制限）（**L2**）
3. 出てきた access token を貼る: `thth token set <account>`。**値をチャットに貼らない・ログに出さない**（発注 §0-3）。
   保存先と鍵の名前は Threads と同じ（`~/.config/thth/<account>.token`・600・`{"access_token": "…"}`）（**L1**）。

**アプリの登録も token の発行も、道具はやらない**（設計 v2 §4.2「認可とトークン」: Mastodon は `thth auth` の往復を持たず、貼り付けだけ）。

## 3. 台帳に足す項目

```json
{
  "media": "mastodon",
  "instance": "https://<インスタンス>",
  "char_limit": 500
}
```

- `instance` は **scheme から書く**。`mastodon.social` とだけ書くと**名指しで断る**（勝手に `https://` を補うと、書いた人が意図した先と違うところに投げうる）（**L1**）。
- `char_limit` を省いたときの既定は 500（設計 v2 §4.2 の `MEDIA_LIMITS`）。**インスタンスに聞きたいときは `mastodon.char_limit(instance)`**——
  取れなければ**例外を上げる**（500 に黙って落とさない。上限 5,000 のインスタンスで 500 に丸めると、書けるはずの原稿が弾かれる）（**L1**）。
- `visibility` はアダプタの引数で、既定 `public`（`unlisted`・`private`・`direct` も可・**L2**）。未知の語は名指しで断る（**L1**）。
- queue の節は `## mastodon`（`queuefile.extract_section` はそのまま・設計 v2 §4.2）。

## 4. 記録に何が残るか

`conversation()` が返すのは設計 v2 §4.2 の `Message`（dict）:
`message_id`・`username`（`account.acct`）・`text`（HTML を落としたもの）・`timestamp`（`created_at`・UTC のまま）・
`replied_to`（`in_reply_to_id`）・`root_post`（**引数の post_id**。Mastodon の Status は根を持たないので、`/context` を引いた投稿を根とする）・
`medium="mastodon"`・`author_key`・`reply_deadline=None`（**L1**）。

- `author_key` は `sha256("mastodon:" + instance + ":" + account.id)[:16]`。**非可逆**（誰かは戻せない）で、
  **インスタンスを混ぜる**ので別インスタンスの同じ番号は別人になる（**L1**）。
- HTML の落とし方には限界がある（**L3**）: リンクは span 分割を連結するので URL は完全な形で戻るが、
  **画面では省略記号つきで短く見えている**。カスタム絵文字は `:shortcode:` のまま残る。詳しくは `strip_html()` の docstring。
- `insights()` は `{"metrics": {...}, "available": [...]}`。**`views` は入れない**——`views: 0` と書けば「見られなかった」に読めてしまう。
  無い指標は `available` に載らないことで「この媒体は答えられない」と分かる（設計 v2 §4.2「採集と実測の媒体差」）（**L1**）。

## 5. まだやっていないこと（Track 0 の merge のあと）

**このアダプタはまだどこからも呼ばれない。** 配線に要るのは:

| 何 | 値 |
|---|---|
| `REGISTRY` の登録名 | `"mastodon"` → `thth.adapters.mastodon.MastodonAdapter` |
| コンストラクタ | `MastodonAdapter(instance=…, access_token=…, visibility="public", timeout=10.0)`（**全部キーワード引数**） |
| token の鍵名 | `access_token`（Threads と同じ） |
| `token set` の検証 | `whoami()` → `{"user_id": <id>, "username": <acct>}` |
| doctor | `probe()` → `[{"name": "verify_credentials", …}, {"name": "instance", …}]` |
| `capabilities()` | `set()`（topic 無し・views 無し・inbox 無し・quota 無し・refresh 無し） |

`quota()` は None を返す（**L1**）。rate limit ヘッダ（`X-RateLimit-Limit`・`-Remaining`・`-Reset`・既定 300/5 分・**L2**）は
`last_rate_limit` に覚えて `probe()` の detail に出すだけで、**枠としては返さない**——
Threads の `threads_publishing_limit`（今日あと何本投げられるか）と `X-RateLimit-Remaining`（直近 5 分の API 呼び出しの残り）は
**意味が違う**ので、同じ名前で返すと core が「あと 290 本投げられる」と読み違える。
