# 調査: Threads で伸ばす——X の 1 枚から活かすもの（2026-10-12）

書いた人: THTH開発（委任の writer）。依頼: masaru 10/12「threads 運用にも活かしたいです」。元: `docs/調査_Xで伸ばす_会話の見つけ方と書き方と罰の避け方_2026-10-12.md`（以下「X の 1 枚」・§6.1 が決定）。対象: kopicha-threads・asmon-kanto の Threads・nigamilab。Meta の承認は 10/9 に 10 権限すべて（検索・言及・プロフィールも使える）。

証拠の強さ: **L1** 原文・自分のコード／**L2** 公式資料／**L3** 報道・二次／**L4** ブログ／**L5** AI の返答。10/12 に Threads・X へ投稿も操作もしていない。API も叩いていない。公開の資料だけ読んだ。

## 0. 3 行の要約

1. **X の 1 枚の「発見の種類」・書き方の決まり・漏斗・守る線は、そのまま Threads に使えます。** 変えるのは探し方（Threads の検索に演算子は無い・無料・タグが 1 つ）と測り方（Threads はもう `collect` が 1h〜30d の刻みで採っている）だけです。
2. **Threads に X の公開コードのような重みの数字はありません**（L2・無い）。言えるのは公式の 3 点——「返信が Threads の閲覧のほぼ半分」「会話を起こす投稿がおすすめに載りやすい」「クリックベイト・エンゲージメントベイト・転載はおすすめに載らない」——で、どれも方向だけで量は書かれていません。
3. **Threads は数がもう採れるので、X より先に試せます。** 1 番目はトピックタグの有無（`topic` 欄で分けて `after --topic`・`analytics-report --by topic` で読める・道具は足りている）。2 番目は「発見の種類」の比較（`study add` で投稿 id を群に入れる）。14 日で 1 つずつ。

## 4. 罰の線（Threads）

既存の照合（9/16・9/18）と食い違わないように: 他人の本文は保存しない・外の LLM に渡さない・件数も Platform Data（§12(l)）。ここは**行い**の線だけ。

| 区分 | 行為 | 根拠（L2・10/12 読んだ） | THTH の作りがどこで効くか |
|---|---|---|---|
| やってよい | 自分で書いた投稿・返信を人が一本ずつ出す | Developer Policies 2026-02-03 §1.7「利用者に代わって公開するなら事前の同意」 | 二段承認・`approved_sha`。招待の道はオーナーの依頼だけ |
| やってよい | 検索で見つけた枝に、人が選んで返す | 禁止の明文は無い。スパム規定は「高い頻度」と「同じ内容の繰り返し」を見る | `where` は並べるだけ・1 日 2〜3 本・`too_soon`・1 日の上限 |
| 灰色 | 毎日同じ型の投稿 | スパム（2024-06-26）「同じコンテンツを繰り返し投稿」はスパムのサイン。Recommendation Guidelines「転載が主で付加価値のない」 | lint に類似の検査は無い。文は毎回変える |
| 灰色 | 問いかけで終える・反応を求める | 創作者ページ「エンゲージメントベイトはおすすめに載らない」。「意見＋続きの問い」は勧めている——**求めるのでなく会話を起こす** | 「発見の種類」の決まり（無理に問いで終えない） |
| やらない | 「手動か自動化を問わず、非常に高い頻度で」投稿・アクション | スパム規定 | ガード（最短間隔・1 日の上限・連投で停止） |
| やらない | いいね・フォロー・返信の売買・交換 | スパム規定・Developer Policies §2.7 | THTH に無い |
| やらない | 欺瞞的な URL・景品の告知 | スパム規定・創作者ページ | URL は本文と一致させる |
| やらない | 他人の投稿の転載・引用で中身を足さない再投稿 | 創作者ページ「オリジナル」・Guidelines「転載」 | `repost` は所有者が頼んだときだけ |

人が一本ずつ確定する作りは、Meta の線（頻度・繰り返し・売買・同意）のうち「頻度」と「同意」を機械で守り、「繰り返し」と「ベイト」は書く側の決まりで守る、という分担です。

## 5. Threads 向けの試し方

Threads は n がある（asmon は `中学受験` で 6 本すべて 200 views 以上・使い方 §7）。X より先に試せる順:

1. **トピックタグの有無**: 同じ発見の種類の投稿を、`topic:` あり／なしで交互に（1 日 1 本・7 日で 7 本ずつ）。読むのは `thth analytics-report <account> --by topic --compare-previous` と `thth after <account> --topic <タグ>`。見るのは 24h views の中央値と「表示 50 未満の本の割合」。
2. **タグの選び方**（1 の後）: 広いタグ（`中学受験`）と狭いタグ（`豊島岡`）。人がいるかは `where <account> <タグ> --recent`（§3 の①ができれば `--tag`）で直近の時刻を見る。
3. **発見の種類**: `study add '{"finding":"比較"}' <post_id>` で群に入れ、`study-report` で並べる。原稿の欄は足さない。
4. **返信の効果**: `after` の `engagements.reacted` と `one_thing_to_change`（時刻帯）。1 日 2〜3 本の返信を 7 日。
5. **週の本数**（公式は週 2〜5）: 今の本数を `--weekly-goals` で見てから、1 本ずつ増減。

14 日の段取り（Threads 版・1 回に変えるのは 1 つ・masaru は「はい／直して／やめる」だけ）:

| 日 | すること | 記録 |
|---|---|---|
| 1〜2 | 基準値（`after`・`analytics-report --weekly-goals`）。ログアウトで自分の投稿が検索に出るか（X の 1 枚 §8.6 の A〜C と同じ） | 日誌（状態 A/B/C・基準の中央値） |
| 3〜9 | **タグあり／なしを交互に**（上の 1）。返信は今までどおり | `topic` 欄（THTH が記録）・日誌に発見の種類 |
| 10〜14 | 当たった側に寄せ、返信を 1 日 2〜3 本（上の 4・`where` の語は日誌に） | `engagements`（自動）・日誌（語・取得・候補・採用） |
| 15 | 中央値で 2 倍以上の差なら採る。それ未満は「差は見えなかった」と書き、次の 14 日（発見の種類・週の本数）へ | プラザに `--from after` で置く |

## 6. SKILL に足す文の案（Threads 固有・「探す」の X の段の後ろに）

```
**Threads で探す・付ける**（2026-10-12・10/9 の承認で公開の検索が使える）: Threads の検索は語だけで演算子は無い（`"…"`・`-語`・`from:`・`lang:` は効かない）。無料・1 頁・既定 25 本・利用者あたり 24 時間で 2,200 回。絞るのは `--recent`（新しい順）・`--since`・`--also`・`--exclude-engaged`。固有名詞と専門語を 1 語に入れ（「豊島岡 場合の数」）、0 件なら語を短くする（敏感と判定された語は 0 件で返る）。
- トピックタグは 1 投稿 1 つ・本文の `#` でなく front-matter の `topic:`（1〜50 字・`.` と `&` は不可）。「そのトピックに興味がある人に届く」が公式の説明（量は書かれていない）。付けるかどうかは `after --topic`・`analytics-report --by topic` で自分の数で決める。
- 公式が言うのは 3 つだけ: 返信は Threads の閲覧のほぼ半分／会話を起こす投稿がおすすめに載りやすい／クリックベイト・エンゲージメントベイト・景品・転載はおすすめに載らない。重みの数字は無い。
- 測るのは `collect` がもう採っている（24h・72h の views・likes・replies）。X のような採る口の相談は要らない。Threads にいいねの API は無い（`unsupported_on_platform`）。
```

## 7. masaru に決めてほしいこと（推しつき）

1. **`where` の Threads に `--tag`（`search_mode=TAG`）と `--author <username>` を足すか。** 推し: **足す**（API にある引数を渡すだけ・保存しない・使い方の「ブラウザで確かめる」が消せる）。足さないなら、タグの人の多さは今までどおりブラウザで見る。
2. **「発見の種類」の比較を `study add`（投稿 id を群に入れる）で回すか、日誌だけにするか。** 推し: **`study add`**（道具が分母と期間を付ける・決定 4「原稿の欄は足さない」と両立）。日誌だけなら中央値を手で出すことになる。
