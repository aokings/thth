# 調査: 配布の権限分離（E・2026-09-12）

**結論を先に。いま無料でできる「私が迂回できない分離」はありません。**
できるのは **(a) VM 側の書き込み経路を塞ぐ**ことと、**(b) 有料にして本当の境界を
作る**ことの 2 つです。

## 1. 現状（読み取りで確認）

| 調べたこと | 結果 |
|---|---|
| 所有形態 | **個人**（`aokings`）・**private** |
| ruleset | **403 Upgrade to GitHub Pro**（使えない） |
| branch protection（旧 API） | **403 同上**（使えない） |
| GitHub Actions | **有効**（`allowed_actions: all`） |
| environment | **0 件**。private では保護規則に Pro が要る |
| 開発が使う token の scope | `gist, read:org, repo, workflow` |

## 2. その場で塞げる穴——**VM の deploy key が書き込み可**

**→ 2026-09-13 09:5x に塞いだ（案 B 完了）。** masaru が `thth-vm-ro`（read-only）を作り、旧 `thth-vm`（read-write）を
GitHub から削除。運用セッション（mindforest-6f）が `gh repo deploy-key list`・`ssh -T`・`release` の fetch rc=0・
`for-each-ref` で確認。以下は当時の記録。

**VM はこの repo（アプリ本体）を読むだけです。** 配布された版を `fetch` して
`merge --ff-only` するだけで、**書き戻すものがありません**（投稿の書き戻しは
`nigamilab` / `asmon` / `kopicha` の各 repo で、この repo ではない）。

**それなのに鍵は書き込み可です。** つまり **VM から `release` を書き換えられます。**
配布の境界を守りたいのに、**配られる側が配る側になれる**状態です。

**read-only の鍵に差し替えれば塞げます。** ただし**鍵の作り直しは masaru の操作**
です（値を触るため）。手順は「新しい read-only の deploy key を作る → VM の
`~/.ssh` を差し替える → 古い鍵を消す」。**こちらは値に触りません。**

## 3. 「私が迂回できない分離」は、無料では作れません

**理由は 2 つです。**

1. **枝を保護する機能が無い**（ruleset も branch protection も Pro 以上）。
   つまり **`release` への直接 push を GitHub 側で止められません。**
2. **開発（私）は masaru の token を使っています。** GitHub から見れば同じ人です。
   **別の credential にしても、同じ Mac の同じユーザーから読めるなら分離ではありません。**

**「配布用スクリプトにする」「Actions だけで配る規約にする」は分離ではありません**
——規約は私が破れます。

## 4. 選べる案（費用と、守れる相手を書きます）

| 案 | 費用 | **誰から守れるか** | できること |
|---|---|---|---|
| **A. GitHub Pro** | **月 $4 程度** | **私（開発セッション）から守れる** | `release` の ruleset ＋ 承認が要る environment。masaru の操作は**承認を 1 回押すだけ** |
| **B. 鍵を read-only に**（2 節） | 無料 | **VM から守れる**（私からは守れない） | 配られる側が配る側になれない |

| **D. いまのまま** | 無料 | **誰からも守れない** | 私が「意図せず配る」ことは `thth release` の機械検査で減らせるが、**保証ではない** |

## 5. 推薦

**B は費用ゼロで穴が 1 つ減るので、案の採否に関わらずやってよい**と思います。

**A が唯一「私が迂回できない」形です。** 月 $4 で、masaru の操作は承認 1 回。
**C は同じことを無料でやる代わりに、masaru が保守する場所が増えます。**

**D のままでも運用は回ります**（今日ずっと回っていました）。**ただし「配布の権限を
決めた」とは書けません。**

## 6. こちらがやらないこと

**契約の購入・repo の公開化・移管・secret の設置・VM の remote 変更は、独断で
行いません。** 鍵の値にも触りません。**masaru が決めてから、決まった形に合わせて
道具を作ります。**
