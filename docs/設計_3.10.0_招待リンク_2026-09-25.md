# 設計 3.10.0: 招待リンク（審査員と外の人が自分で入れる 1 本の道）

2026-09-25。計画 `docs/計画_Meta申請_2026-09-25.md` の #1。Meta の審査は「審査員が自分のテスト口座でアプリに入れない」と申請ごと落とす。今の THTH は、運営者が VM で `thth account add` と `thth auth` を打ち、10 分で切れる URL を本人に渡す形で、審査員が試験の手順どおりに入れない。

## 0. 約束（1 行）
**運営者が作った期限つきの招待リンクを開けば、その人が自分の Threads（と Bluesky・Mastodon）の口座で認可でき、口座が VM に用意され、承認ページで投稿・返信・削除を試せる。** 運営者が各招待を作る（誰でも即座に使える形にはしない）。

## 1. 流れ
1. 運営者: `thth admin invite create --media threads --project <p> --label <メモ> --expires 30d [--production] --by masaru` → 招待 URL `https://thth.me/invite/<code>` を 1 回だけ表示（code は推測できない長さ・VM には hash だけ）。Worker に招待を登録（VM の署名つき・code の hash・media・期限・使える回数 1）。
2. 本人（審査員）: 招待 URL を開く → Worker が説明のページ（何が起きるか・どの権限を求めるか・privacy と利用規約へのリンク）と「Threads で認可する」ボタン。
3. ボタン → Worker が「認可の準備中（数十秒）」のページを出し、招待を `clicked` にする。**VM の常駐（`thth approval-worker`、既に Worker を定期に見ている）**が `clicked` を拾い、その招待のために口座の枠（名前は `inv-<project>-<短い乱数>`）と認可の session（PKCE は VM で作る・今の `authflow.begin` と同じ）を作り、認可 URL を Worker に返す。ページが認可 URL へ進む。
4. 本人が Threads で承認 → 今の預かり所（relay）→ VM が token を受け取り、口座を有効にする（ハンドルは認可した人から取り、台帳に書く・`account add` と同じ検査）。
5. 完了のページ: 「用意ができました」と、その口座の**承認 secret を 1 回だけ**表示（承認ページで押すときに使う・`approver set` と同じ・PBKDF2 は 100,000）。パスワード管理に保存するよう案内。
6. そのあとは既存の道: 運営者（か LLM のセッション）が下書きを置く → 承認ページの URL が本人に届く（招待の完了ページに「承認ページの URL は運営者から届きます」）→ 本人が secret で承認 → timer か送信で公開。返信・削除も承認ページで。

## 2. 規律
- 招待は 1 回だけ使える・期限（既定 30 日・最長 90 日）・運営者がいつでも取り消せる（`thth admin invite revoke <id>`）。使われた・切れた・取り消された招待は 410。
- 招待 1 本で作れる口座は 1 つ。同じ Threads 口座で 2 回目の招待を使うと断る（既存の口座の認可のやり直しは従前どおり運営者の `thth auth`）。
- 本人の口座は既定で `production: false`（試し撃ち）。審査員の招待は `--production` を付けて本物の投稿を試せるように（運営者の判断）。
- 招待から作った口座も、退出（`thth account leave`）・報告の口・広場・持ち主の組の既存の規律に従う。持ち主の組には入れない（外の人）。
- Worker に置くのは code の hash・期限・状態・VM から返った認可 URL（10 分で消す）だけ。token は今の預かり所と同じく Worker を通らない形のまま。
- 変更ログ: `invite_created`・`invite_used`・`invite_revoked`・`account_added`（via invite）。
- VM の常駐が落ちていると招待が進まない → 招待のページは 2 分待って進まなければ「運営者に連絡を」と出し、運用通知にも 1 回。

## 3. 審査の試験の手順に書くこと（下書きは申請の文へ）
- 招待 URL（審査の間だけ有効・`--production`）と、手順 1〜6 を 5 行で。承認 secret は完了ページで出る。運営者が審査の間、下書きを 1〜2 本置いておく（投稿・返信・削除を試せるように）。

## 4. 試験
招待の作成（code は 1 回だけ表示・VM は hash）・Worker の招待の状態（開く・押す・準備・完了・410）・VM の常駐が clicked を拾って session を作る・認可の完了で口座ができる（ハンドルの照合）・secret の 1 回表示・1 回だけ使える・期限・取り消し・常駐が落ちているときの案内。Worker は Node の試験（Miniflare）、VM は Python の試験。単変異 5 本（招待を 2 回使える／code を VM に平文で残す／期限を見ない／secret を 2 回出す／持ち主の組に入れる）。
