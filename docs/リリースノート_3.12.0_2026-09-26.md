# リリースノート 3.12.0 （承認を関所から選ぶものへ・安全装置・動きの一覧）

2026-09-26。設計: `docs/設計_3.12.0_承認を関所から選ぶものへ_2026-09-26.md`（§9 に夜間の裁定）。

masaru の決定（09-26）:「LLM とユーザの信頼性をこちらが疑うのは越権。私たちは道具の提供者に過ぎない」。
ただし「LLM が暴走して使い方を誤った場合はセーフティが効くようにする」。

**配る順: Worker が先、VM（release）があと。** VM の常駐が新しい口（`/approval/activity/<person>/sync`）を叩くので、Worker が古いままだと一覧が空のまま（壊れはしない）。

## 何が変わったか

### 1. 承認は口座ごとに選ぶ（`approval`）

| 値 | 公開・予約・返信 | 削除 |
|---|---|---|
| `none` | LLM の依頼でその場で出す・刻む | その場で消す |
| `publish` | 承認ページ | その場で消す |
| `all` | 承認ページ | 承認ページ（3.11 と同じ） |

- **台帳に `approval` が無い口座の扱い**: 招待で作った口座（`provenance.created_via: invite`）は `all`（勝手に緩めない）。それ以外（masaru の口座）はこの道を通らないので影響なし。
- 新しく招待で作る口座は `thth admin invite create --approval none|publish|all`（既定 `none`）。**Meta の審査員向けの招待は `--approval all`**。
- `thth_send_request` は `approval: none` ならその場で公開し `post_id`・`permalink` を返す。予約は新しい `thth_schedule_request`。削除は `thth_retract_request` がその場で。
- 直接の公開・削除・予約の記録に `via` と資格の id（`credential_digest` の先頭 12 字）。

### 2. 安全装置（`thth/guard.py`）

| 装置 | 既定 | 超えたとき |
|---|---|---|
| 最短間隔 `min_interval_hours`（返信には掛けない） | 台帳のまま（招待の口座 6） | `too_soon`（`next_at`） |
| 1 日の公開 `daily_max_posts`（返信も数える） | 8 | `daily_limit` |
| 1 日の削除 `daily_max_retracts` | 5 | `retract_limit` |
| 急な連投 `burst` | 10 分に 3 件（公開と削除の合計） | 口座を止める（`account_stopped: burst`） |
| 夜間 `quiet_hours` | 台帳のまま | 今すぐの公開は `quiet_hours` |
| 猶予 `hold_minutes` | 0 | 1 以上なら今すぐの公開をその分の予約にする（`scheduled` の口座だけ） |

- 止めた印は `state/<口座>/guard/stopped.json`（退出の止めとは別・戻せる）。
- `scheduled: false` の口座（今の招待の口座）で予約と `hold_minutes>0` は `schedule_unavailable`（黙って出ない、を避ける）。
- **LLM（MCP の `thth_settings`）から変えられるのは締める向きだけ**。緩めるのは `/activity`（secret）か運営者の `thth account set … --by`。止まった口座の再開も LLM からはできない。

### 3. 持ち主の画面 `https://thth.me/activity`

口座名と承認 secret で入る（`/pending` と同じ入口の作法・失敗 5 回で 15 分閉じる）。出たもの・消したもの・予約・猶予中・止まった理由を新しい順に。操作は secret で確かめる:

- この口座を止める／止めたのを戻す
- 予約・猶予中の投稿を取り消す
- 設定を変える（approval と安全装置の数値）
- LLM の鍵を発行する（1 度だけ表示・前の鍵は無効に）／取り消す

VM の常駐が 1 巡ごとに要約（本文は先頭 60 字まで・1 時間で消える）を Worker に押し上げ、持ち主が頼んだ操作を受け取って行う（実行の前にその人の口座かを確かめ直す）。

### 4. CLI・MCP

- `thth account set <口座> <名前> <値> --by <名前>`（`approval`・`daily_max_posts`・`daily_max_retracts`・`burst_count`・`burst_minutes`・`hold_minutes`・`min_interval_hours`。`burst <件数> <分>` の形も可）
- `thth account resume <口座> --by <名前>`・`thth account status <口座> [--json]`
- MCP: `thth_schedule_request`・`thth_settings`・`thth_account_status`
- 変更ログ: `settings_set`・`schedule_cancelled`・`credential_rotated`・`credential_revoked`・`guard_stopped`・`guard_resumed`

### 5. 09-25 夜の穴

1. 承認の常駐は、ディスクの版が動いたら自分で終わる（75）。`Restart=on-failure` が新しい版で起こす。`thth board` に常駐の版。**3.12.0 を入れる最初の 1 回だけは、古い常駐がこの仕組みを持たないので手で restart する。**
2. `/pending/`・`/activity/` の末尾スラッシュは 308。
3. `/pending/<job>` で入り直すと戻り続けた件（入り直しは `/pending` へ POST・元の job へ 303）。
4. 招待の完了ページで、口座名と secret を同じ form に置く（パスワード管理が正しい組で保存する）。
5. 運営者の `thth admin draft put`・`approval request` は `write_unavailable` の中身を 1 語と次の一手で言う（`root_mismatch`・`unsafe_server_directory`）。MCP・サーバの口は今までどおり。
6. 承認の常駐は入口で `umask 077`。
