## 2. どう直したか（要点だけ）

- **P1-1**: `thth/httpsafe.py` を足し、scheme + host が変わるリダイレクトは追わずに
  `HTTPError` にする（同一 origin でも `https` → `http` の格下げは拒む）。
  mastodon・bluesky・threads・doctor・oauth の `urlopen` をこの 1 本に揃えた。
  `RedirectBlocked` は `HTTPError` の子なので、**アダプタ側の `except` は変えていない**。
- **P1-2**: `_all_pages()` は `https` かつ `base_url` と同じ netloc のときだけ次の頁を
  追う。違えば `RuntimeError`（**型が違うときと同じ扱い**＝部分を成功として返さない）。
- **P1-3/P1-4**: `writeback.set_front_matter_fields()` の入口で鍵と値を検査し、
  改行・復帰・NUL があれば**1 文字も書かずに** `ValueError`。CLI は traceback ではなく
  1 行で rc=2。`post_id` は `postid.is_usable()` ＋制御文字なしを公開の直後に確かめ、
  外れたら **`publish_ambiguous` と同じ扱い**（inflight を残す・再投稿しない）。
- **P2-1/P2-3/P3-2**: MCP は `inputSchema` を正本に必須・型・知らない鍵を検査し、
  `file` は `realpath` して**台帳のどれかの `repo_dir` の下**だけ通す。1 要求の失敗は
  1 要求の error（`-32602`／batch は `-32600`）で、ループは続く。
- **P2-2**: `name_is_safe`／`NAME_RE` を `thth/accounts.py` に 1 つ置き、読む側も通す。
  外れたときの文言は**在る／無いに触れない**（同じ 1 つの言葉）。
- **P2-4**: 認可 URL に `state` を載せ、戻りで照合する。`--code` は別の実行なので、
  出した `state` を `$THTH_ROOT/state/<account>/auth_state.json`（600）に残して**次の
  実行**が照合する（`thth auth` は 2 段になった）。handle の照合は `thth token set` と
  同じものを入れた。
- **P2-5**: `THTH_REQUIRE_SIGNED_RELEASE=1` のときだけ `git verify-commit` を通す。
  **既定は off**——いまの release の commit は無署名なので、無条件に入れると次の配布で
  VM が止まる（設計 §8 の止まる条件）。board は「署名: 未確認」を 1 語出す。
- **P2-6/P3-1/P3-3**: 新規ディレクトリ 0700・伏字の綴りを 3 つ追加・`http://` は
  localhost／127.0.0.1／::1 以外で断る。

**1 つずつ入れて確かめる**手順として書いた。

## 4. 破れなかったもの

攻撃者の目で読んで**穴にならなかった**ところも残す（次の監査が同じ道を歩き直さずに済む）。

- **承認の一線**。`approved_sha`（本文・account・reply_to・topic・publish_at の 5 項目）は
  公開の直前と `pull --rebase` の直後の 2 回照合される。front-matter に注入できても
  **指紋は合わない**ので、P1-3 の経路で「別の本文を承認済みに見せて出す」ことはできない
  （復活するのは `status` の表示までで、そこから先は `approval_stale` で止まる）。
- **二重投稿**。inflight は「出たか分からない」ときに**必ず残る**。今回足した
  `unusable_post_id` もその仲間に入れたので、**記録できないまま消える経路**は増えていない。
- **秘密の出口**。トークンはヘッダにしか載らず（Mastodon）、例外文は `scrub()` →
  `redact()` の 2 枚を通る。P3-1 で綴りを足して、Bluesky の 3 つの鍵も塞いだ。
- **MCP の道具立て**。出ているのは読み取りだけで、`approve`・`throw`・`token`・`auth` は
  1 つも出ていない（`tests/test_mcp.py` が名前の集合で見張っている）。
- **ロックの取得順**。repo → account の 1 経路しかないので、入口が増えてもデッドロックの
  組み合わせは増えない。
