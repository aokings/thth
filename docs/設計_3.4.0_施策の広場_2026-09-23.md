# 設計 3.4.0: 施策の広場（媒体をまたいだノウハウの共有と意見交換）

2026-09-23 19:30。masaru「同一アカウントで複数メディア持っている場合、ノウハウの共有を THTH 上で出来るようにして欲しい。意見交換や実施した施策の見せ合いなど、闊達な場の提供をしたい」。

## 0. 約束（1 行）

**同じ持ち主の媒体どうしで、試した施策と結果を数字つきで見せ合い、言葉を交わせる場を道具が持つ。** 外（他の持ち主）へ見せるのは本人が選んだものだけ。

## 1. いまあるもの（組み合わせて使う）

- 施策の宣言と観測の突き合わせ: `thth study-report <file>`（2.5.0・`docs/設計_v3_施策の振り返り.md`）。宣言（仮説・変えたこと・対象投稿）と自分の計測を結び、両群の分母と `observational_difference` を返す。宣言は利用者の repo のファイル。
- 仮説の棚: `thth topics record-hypothesis`／`hypotheses`（反証の条件・対抗仮説つき）。
- 報告の口（3.1.2）: VM の私有の置き場・秘密の検査・利用者 scope・返事の列・変更ログ。**広場はこの骨を使い回す**。

足りないのは「場」: 媒体をまたいで同じ施策を並べる・他の LLM セッションや人が意見を書く・新着が目に入る。

## 2. 広場に置けるもの

| 種類 | 中身 | 例 |
|---|---|---|
| `measure`（施策） | 仮説・変えたこと・対象（account と投稿 ID の群・媒体ごと）・期間。**観測は道具が付ける**（study-report と同じ計算・分母つき・媒体ごとの列） | 「冒頭を問いにする」を Threads・Bluesky・Mastodon で 1 週間 |
| `finding`（気づき） | 数字を伴わない観察・運用のコツ・失敗談 | 「Mastodon は夜より朝が伸びる気がする（未検証）」 |
| `question`（問い） | 他の媒体・他の持ち主に聞きたいこと | 「Bluesky でタグは効いていますか」 |

- 1 件に**返信の列**（`{at, by, text, kind}`・kind は `comment`／`tried`（うちでも試した・自分の measure へのリンク必須）／`agree`／`disagree`（理由必須））。
- `measure` は後から**結果の更新**（観測の取り直し）と**判定**（`adopted`／`dropped`／`inconclusive`・理由必須）を持てる。

## 3. 見える範囲

- 既定は **project**（同じ持ち主の全 account＝媒体をまたぐ）。kopicha なら threads・bluesky・mastodon の 3 口座と kopicha のセッションが読み書きする。
- 置く人が選べば **open**（広場に参加している他の持ち主にも見える）。招待制（3.0）の利用者どうしの場。**open は 1 件ごとの明示の選択**で、後から project に戻せる（戻したら他の持ち主からは見えない）。
- open に出すとき、道具が**本文と観測から自分以外の人の情報を落とす**: 他人の投稿の本文・username・author_key は入れない（C3・C4 の規律）。自分の投稿は先頭 60 字と permalink まで。
- 参加は持ち主ごとの設定（`thth admin plaza join <project> --by`・既定は不参加）。不参加の持ち主は open を読めず、出せない。
- 管理者は全部読める。問題のある書き込みは管理者が `hide`（理由つき・変更ログ）。

## 4. 入口

| 誰 | CLI | MCP |
|---|---|---|
| 利用者 | `thth plaza post <account> --kind measure\|finding\|question --title … --body-file … [--declaration <study の file>] [--open]`・`thth plaza list <project> [--open]`・`thth plaza show <id>`・`thth plaza reply <id> --kind … --text-file …`・`thth plaza update <id> --refresh\|--verdict …` | `thth_plaza_post`・`thth_plaza_list`・`thth_plaza_show`・`thth_plaza_reply`・`thth_plaza_update` |
| 管理者 | `thth admin plaza join\|leave <project>`・`hide <id> --reason`・`list --all` | `thth_admin_plaza_*` |

- `by` は MCP なら資格情報の actor、CLI なら `--by`（報告の口と同じ）。

## 5. 目に入るようにする（「闊達」の仕掛け）

- `thth observe` の 0 段に「広場: 新着 n（project）・open の新着 m」。`next_steps` に `kind: "plaza"`（返信の付いた自分の施策・判定待ちの施策）。
- **媒体をまたぐ比較の表**: 同じ `measure` を媒体ごとの列で並べる（分母・`observational_difference`・欠測は null と理由）。「Threads では効いたが Mastodon では差が無い」が 1 枚で見える。
- 施策の判定が付いたら、同じ project の他の媒体に「まだ試していない媒体」として `next_steps` に出す（候補の列挙だけ・本文は作らない）。
- skill と description に「施策を試したら広場に置く・他の媒体の施策を読んでから次を決める」を 1 行。LLM が自分から置けるように、報告の口（3.3.0 B）と同じく「置くのは作業の一部」と明言する。

## 6. 記録と規律

- 置き場: VM の私有 `state/_plaza/`（0600・SNS 台帳には書かない・報告の口と同じ骨）。
- 秘密の検査・長さの上限（本文 8,000・返信 4,000）・1 account 1 日 30 件・変更ログ（`plaza_posted`・`plaza_replied`・`plaza_updated`・`plaza_hidden`・`plaza_joined`）。
- 観測は置いた時点と更新時点の値を持つ（後から数字が変わったことが分かる）。数字は道具が付けたものだけを「観測」と呼び、人や LLM が本文に書いた数字は「本文」として区別して表示する。
- 退出（`account leave`）で、その account が置いた project 範囲の書き込みは消える。open の書き込みは「退出した持ち主」の名義で残すか消すかを退出時に選ぶ（既定は消す）。

## 7. 版と順番

3.4.0。3.3.0（止まったら知らせる）→ 3.3.1（inflight）のあと。先に project 範囲だけを出し、open は招待者が 2 組以上になってから有効にする（`plaza join` を 1 組でも実装はするが、UI の案内は project から）。

## 8. masaru の裁定（はい／いいえ・または自由記述）

1. 範囲は「project（同じ持ち主の媒体をまたぐ）」が既定、「open（参加した他の持ち主）」は 1 件ごとの明示の選択。
2. 置けるものは施策（観測は道具が付ける）・気づき・問いの 3 種と、返信（試した／賛成／反対は理由つき）。
3. open に出すとき、他人の投稿の本文・名前は道具が落とす（自分の投稿は先頭 60 字まで）。
4. 観測の段と次の一手に新着と「まだ試していない媒体」を出す。
5. 版は 3.4.0（3.3.1 の次）。まず project 範囲から。
