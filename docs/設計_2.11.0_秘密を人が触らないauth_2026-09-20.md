# 設計 2.11.0: 秘密を人が触らない auth——X を見据えた共通の骨

2026-09-20。masaru の言葉: 「シークレットを LLM に見えないように仕込む作業が毎回煩雑。注意のいる作業のわりに原始的」「X を生やすのも 3.0 の要件。その辺も見据えた作りに」。

本書は契約。実装は Codex（2.10.0 の後）。裁定は §8。

## 0. 現在地（8a1deef・L1）

- Threads: `thth auth <account> --by` が認可 URL を出し、人がブラウザで承認し、**戻り URL を貼る**（`state` 照合 → code → 短期 → 長期 token → `me` で handle 照合）。thth.me の callback は戻り URL を見せるだけ。`maintain` が長期 token を refresh。
- Bluesky: `thth auth` はアプリパスワードを対話で貼る（`create_session`）。
- Mastodon: 人がブラウザでアプリを作り scope を選び、トークンを目で運んで `thth token set` に貼る。今日の `read:search` 不足はこの手順で起きた。
- 共通: 秘密が人の目とクリップボードを通る。手順は媒体ごとに違う。scope は人が選ぶ。

## 1. 目指すもの（3.0 の条件）

**導入は「`thth auth <account> --by 名前` が出す URL をスマホで開いて承認を押す」だけ。** トークンは媒体から VM へ直接届き、人も LLM も値を見ない。scope は道具が要求する。媒体が増えても手順は同じ 1 つ。

## 2. 共通の骨（`thth/authflow.py`・新設）

OAuth 2.0 の認可コード方式＋PKCE を 1 本の流れにし、媒体差は adapter の `AuthProfile` に閉じ込める。

1. **クライアントの用意**: 媒体ごとの client_id／client_secret は VM の `~/.config/thth/apps/<medium>[.<instance>].env`（600・プロジェクト外・2.9.0 の `app.env` と同じ流儀）。Mastodon は instance ごとに **`POST /api/v1/apps` で自動登録**し（人はアプリを作らない）、その結果をここに書く。Threads・X は運営者が開発者ポータルで作った値を 1 度だけ置く（`thth app set <medium>`・既存の `thth app` の延長・`--stdin` で秘密管理ツールから流せる）。
2. **開始**: `thth auth <account> --by 名前` が `state`（32 byte 乱数）と PKCE の `code_verifier` を作り、`state/<account>/auth_state.json`（600・10 分で失効）に保存。認可 URL を 1 行だけ出す（scope は adapter が決める・人は選ばない）。
3. **承認**: 人がスマホで開いて承認。媒体が `https://thth.me/callback/?code=…&state=…` に戻す。
4. **code の受け渡し（2 経路・どちらも可）**:
   - **預かり所（既定）**: thth.me が `code` を `state` に紐づけて **5 分だけ** 預かる（§3）。VM の `thth auth` は開始後に預かり所を 2 秒おきに最長 10 分取りに行き、届いたら人は何もしない。
   - **貼る（後方互換）**: 預かり所が使えないとき、いまと同じく戻り URL を貼る。
5. **交換**: VM が `code`＋`code_verifier`＋client_secret でトークンを取る。**`code_verifier` は VM から出ない**ので、`code` だけを知っても（預かり所や browser 履歴から）トークンにできない。
6. **確認**: 本人確認の API（`me`／`verify_credentials`／`users/me`）で handle を照合（既存 `handle_matches`）。応答の `scope` を `.token` に記録（`scopes_source: "response"`）。
7. **保存**: `.token`（600）に access／refresh／`obtained_at`／`expires_at`／`scopes`。変更ログに `token_set`（2.9.0 のまま）。`maintain` が期限の近いものを refresh（Threads の長期 token と同じ口・adapter の `refresh()` に委ねる）。

## 3. thth.me の預かり所（Cloudflare Worker＋KV・秘密を持たない）

- `GET /callback/?code&state`: `relay:<sha256(state)>` に `code` を **TTL 300 秒**で保存し、「承認できました。ターミナル（VM）が受け取ります。貼り付けは要りません」と表示。KV に置けないときは今の画面（戻り URL を見せる）に落ちる。
- `GET /relay/<state>`: 1 回だけ `{"code": …}` を返して即削除。無ければ 404。同一 IP 60 回/分で 429。
- `code` はログに出さない（Worker のログを切る・URL に載る `code` を `console.log` しない）。
- **預かり所には秘密が無い**: client_secret と `code_verifier` は VM、`code` は一回限り＋5 分＋PKCE 束縛。masaru が他人の秘密の管理者になることも、KV の無料枠を超えることも無い（1 認可 = 1 key）。
- 同じ Worker が `/oauth/client-metadata.json`（§4 Bluesky 用）を配る。

## 4. 媒体ごとの差（`AuthProfile`）

| 媒体 | 方式 | client | scope（道具が決める） | 期限・refresh | 本人確認 |
|---|---|---|---|---|---|
| Threads | 認可コード（PKCE 無し・Meta は非対応） | 開発者ポータルの App（既存 `app.env`） | `scopes.DEFAULT_SCOPES` | 長期 60 日・`maintain` refresh（既存） | `me`（既存） |
| Mastodon | 認可コード＋PKCE | **instance ごとに自動登録**（`POST /api/v1/apps`・`redirect_uris=https://thth.me/callback/`） | `read:accounts read:statuses read:search read:notifications write:statuses` | 期限なし・refresh 無し | `GET /api/v1/accounts/verify_credentials` |
| X | 認可コード＋PKCE（OAuth 2.0 user context・confidential client） | 開発者ポータルの App（`apps/x.env`・運営者が 1 度置く） | `tweet.read tweet.write users.read offline.access` | access 2 時間・`refresh_token` で `maintain` が更新 | `GET /2/users/me` |
| Bluesky | atproto OAuth（PAR＋PKCE＋DPoP） | client_id = `https://thth.me/oauth/client-metadata.json`（Worker が配る） | `atproto transition:generic` | access 短命・refresh・DPoP 鍵は VM | `com.atproto.server.getSession` |

- **X は auth だけを 2.11.0 に入れる**（投稿・読み取りの adapter は 3.0 の別設計）。X の読み取りは有料枠（Free は投稿のみ・月 1,500 本）なので、adapter の設計で費用の裁定が要る。auth の骨はここで揃えておく。
- **Bluesky の atproto OAuth は 2.11.0 で試みる。** DPoP の実装が 1 版に収まらなければ、アプリパスワードの経路を残し、§5 の秘密管理ツール経由を正式な入口にする（次版で再挑戦）。
- Threads の預かり所対応は §3 だけで済む（流れは既存）。

## 5. 逃げ道（残す・正式化する）

`thth token set <account> --by 名前 --stdin` は残す。**秘密管理ツールから流すのを正式な形**として文書に書く（値は画面に出ない・LLM の文脈に入らない）:

```bash
op read "op://THTH/<account>/credential" | thth token set <account> --by masaru --stdin
```

対話で貼る形（tty）も残すが、文書では「最後の手段」にする。

## 6. 観測（2.9.0・2.10.0 との接続）

- `.token` の `scopes` は応答由来（`scopes_source: "response"`）を第一に、無い媒体は `doctor` の probe 由来（2.10.0 §1.5）。`admin tokens` の `missing_scopes` が 3 媒体で出る。

## 7. 順番と検収

1. §3 預かり所（Worker＋KV）——`callback/` の変更・`wrangler` の KV binding・deploy は masaru の一言で Claude。否定ケース: 2 回目の取得は 404・TTL 後は 404・`state` 不一致は 404・code はログに出ない。
