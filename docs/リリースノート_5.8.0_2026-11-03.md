### 足したこと

- **`thth plaza post <account> --kind measure --from scenario <project> <糸の id>`**: 糸 1 本の結果を、**道具が観測として**付けて置く（`tool_numbers`・`source: "scenario"`）。`observed` の印は、道具が自分の台帳から取った数——24h の実測が取れた投稿（`covered_24h`）・訪問の控えの数（`sessions`）・広告の口座の記録で始めた広告（`started`）——が 1 つ以上あるときだけ。糸のファイルの出来事（`article_published` など）や原稿の `status: posted` だけの段の本数は観測の欄に載るが、印の根拠にしない（監査 段4 の 1）。人や LLM の解釈は `--body-file` で、道具の下書きの下に足す（観測の欄には入らない・本文の数字は今までどおり「本文に書かれた数字（観測ではない）」）。
  - 段ごとの本数（済み/要る・SNS の段は媒体ごと）。`thth scenario` と同じ計算。
  - 媒体ごとの反応: 糸の SNS の投稿 1 本ずつを `thth after` と同じ計算（24h の刻みの実測・返信は返信の台帳の他人の数）で読み、媒体ごとに `posts`（分母）・`covered_24h`・指標ごとの `n`／`of`／`sum`／`median`。n が 5 未満なら中央値は言わない（after と同じ）。連投は先頭の投稿で数える。
  - 本記事への訪問: 5.7.0 の `site_visits` の控えから、数と窓（サイトごとの `window`・`as_of`・`by_medium`）だけ。campaign の名前と着地の頁は写さない。**取り込んでいなければ `sessions: null` と `site_visits_not_imported`**（0 と言わない）。
  - 広告の段: 始めた本数・止めたままの本数・通しの予算。使った額と link_click は記録に無いので `null` と理由（`ads_spend_not_recorded`・`ads_clicks_not_recorded`）。`thth ads insights` の数は付けない（置く時点で Meta を呼ばない・決めた数だけを置く）。段が無ければ `no_ads_stage`。
  - 窓: 糸の `started`（無ければ最初の出来事か投稿）から `closed` の日まで（`basis: thread_started_to_closed`。閉じていなければ今まで `thread_started_to_now`）。
  - 使った媒体（`media_tried`）と、宣言したのに 0 本の媒体（`media_declared_untried`）。
  - 写さないもの: 原稿の本文と題・原稿の名前・他人の返信と username・タグの中身。
  - 原稿の台帳が読めなかった（`queue_unreadable`・`account_unreadable`・`repo_unreadable`）ときは `posts_cannot_say` に符丁を入れ、下書きは「反応: 言えない（…）」、digest は「SNS 言えない（…）」と出す（0 本と言わない・監査 段4 の 3）。
  - **open の写し**（他の持ち主に見える）は数と媒体と状態だけ: 糸の id・サイトのホスト名・段の名（既知の語彙の段は日本語の名、ほかは「その他」）・現在の段の名を落とし、出し直しの命令は `thth scenario show <project> <糸の id>` の形だけにする（監査 段4 の 2）。
  - `--from` は種類で引数の数が違う（scenario は 3・ほかは 2）。account を `--from …` の直後に書いても飲み込まれずに account として読む（監査 段4 の 5）。
  - 断り: 置く account と別の project は `from_out_of_scope`、無い id と型（series）は `from_scenario_not_found`（新しい符丁）、引数の数が違う・`--from-window-days` と一緒は `invalid_from`、`--kind finding` は `not_a_measure`。題を省くと「糸「<糸の題>」の結果」、`--how` を省くと `thth scenario show <project> <id>`。
- **observe の次の一手**: 糸を閉じた（糸のファイルに `- <日付> closed`・30 日以内）のにまだ置いていなければ「広場に置く: 糸「…」を閉じた」とこの命令の 1 行（`candidate: "post_scenario"`）。置けば消える。宣言のファイルが 1 つも無い project は台帳を開かず、project ごとに例外を受けるので 1 つの project が壊れていても他の候補は消えない（監査 段4 の 4）。置く口座は SNS の口座を先に選ぶ。project が持ち主の組に入っていなければ、別の project から読めないことと `thth admin plaza owner set <組の名前> <project> <同じ持ち主の project> --by <名前>`（管理者）の案内を添える。
- **`plaza digest` の「糸の結果」**（`scenario_results`）: 2 媒体で再現した数え方とは別に、読める糸の結果を全部並べる。各行に使った媒体・**試していない媒体**（読む側の媒体のうち糸で使っていないもの＋宣言して 0 本の媒体。追試の付いた媒体は外す）・再現した／しなかった媒体・媒体ごとの本数・訪問・広告。本文は出さない。同じ持ち主の組の別の project（関東など）が `thth plaza digest <project>` で読める。
- **MCP** の `thth_plaza_post` に同じ引数（`from_tool: "scenario"`・`from_project`・`from_thread`）。
- skill `thth-flow` の段 4 の「予定」を実際の命令に、skill `thth` のプラザの節に 1 行、json の欄の表（`docs/調べ_JSONの欄_2026-10-15.md`）に `tool_numbers`（scenario）・`scenario_results`・`post_scenario` を足した。
- `thth plaza show` で、道具の数がある施策に「宣言が無いので道具は数字を付けていません」を出さないようにした（after・analytics-report も同じ）。

### 確かめ方

- 試験 `tests/test_v580_plaza_scenario.py`（18 件）。柵をわざと壊して赤を見た: 訪問が無いとき 0 を入れる（`test_段3が無いとき訪問はnullと理由_0と言わない`）・人の本文を観測に入れる／原稿の題を観測に入れる（`test_観測の欄に本文の数字と他人の本文やusernameが混ざらない`）・窓の終わりを今にする（`test_糸の結果を道具が観測として付ける_分母と窓`）。

### 本番で確かめること
