## 段 6 — 書く口と束

### 「済み」の線

1. **差が 1 レコード**（実物の写しで。各メディアの repo は読むだけ。写しは `/Volumes/NexDev/Developer/thth-work/stage6/` の下）: にがみラボの混ざった改行の表（`topic-hubs.csv`。CRLF 14・LF 41・空の行 1）・にがみラボの CRLF の表 1 枚・染めと化学の表 1 枚で、`row add` で 1 行足す・`row set` で 1 欄直す。書く前と後で、触っていないレコードのバイトが全部同じ（レコードごとの sha256 と、ファイルの頭と末尾）。足した行の改行は、その表の決まり（混ざった表では最後のレコードの改行）に合わせ、ほかの行の改行を変えない。
2. **断る物**: 触っていないレコードが 1 バイトでも変わる書き方（引用符の付け直しが要る値・表の欄の数と合わない行）は書かずに断る。`merge` は、(a) 判定が断りの行 (b) 重なる番号 (c) 集めた者と検めた者が同じ (d) 検めた者が無い、の束を入れない（(d) は `--unchecked` を二段で言ったときだけ入れ、取り込みの跡に「検めていない」と残る）。
3. **束の検収の記録を結ぶ**: 束の中の検収の記録が対象の版を示していれば（`inspects` の宣言）、`merge` は取り込みと同時に、新しい版への判断として結ぶ。版を示さない検収の記録は結ばず、「観測しか無い版」として数える。
4. **途中で止める**: 複数の表の束を途中で止めても、読み手には前か後のどちらかが見える（段 2 の試験があれば、束の道で 1 つ足すだけ）。

重い穴 = 触っていないレコードのバイトが変わったのに書いてしまう・検められていない束が黙って入る・版を示さない検収の記録が判断として結ばれる。

### 宿題に回す物

JSON の枚の内側の 1 か所を直す口・YAML の 1 枚を直す口の磨き（段 2 の「元の形式の道具がそのまま書ける」で足りている）。

4. **関門が今と同じ答え**: 出した URL の関門（こぴちゃ・キョンシーラボ・関東の今の台本）と、読者に見える欄の点検（染めと化学の `audit_site.py` の (v)・キョンシーの `public_jargon.py`）について、同じ入力で器の答えが今の台本の答えと同じ（今は違反 0。違反を 1 つ足した写しで、どちらも赤）。今の台本が正規表現や文の読みで見ていて器の部品で言えない所は、「固有として残す決まり」に足す（段 4 の §4 と同じ扱い）。

重い穴 = 出さない欄・使えない記録・止めた記録が材料に書かれる・旧い材料が残ったまま緑・差し込みが使えない値を書く・出した URL が消えたのに関門が緑。

### 7.1 内の道具が読む出し口

出し口の宣言の「読む者」が内の道具なら、選ばずに書く（今あれば確かめるだけ）。**読者に出る出し口の書き出し先と同じフォルダへは書かない**（同じ先を 2 つの出し口が言えば、宣言の読みで断る）。

### 7.2 出さない欄

種類の宣言に `private_fields`（出さない欄の名前の並び）。読者に出る出し口の材料に、その欄の値を書かない（表なら列を空に・枚なら鍵を除く。どちらにするかは 7.4 の伏せ方と同じ宣言）。内の道具の出し口には書く。封の指紋・材料の控えにも、出さない欄の値そのものは入れない（指紋だけ）。

### 7.3 差し込み

- 種類の宣言に `inserts`（差し込みを受ける欄の名前の並び）。その欄の文の中の `{{<種類>:<番号>.<欄>}}` を、出すときに値へ置き換える。
- 置き換えてよいのは、その出し口で**事実として使える**記録の、出さない欄でない欄の値だけ。使えない・留保だけ・欄が無い・出さない欄、のどれかなら、その記録（差し込みを持つ側）ごと材料から外し、理由（`insert_unusable`）を一覧に出す。黙って空にしない・番号のまま出さない。
- 差し込んだ先の版は、材料の控えの入力の版の組に入る（差し込み元が変われば、材料が古くなる）。
- 入れ子（差し込んだ値の中の `{{…}}`）は読まない（字のまま）。1 つの欄に 64 か所まで。

### 7.4 期限と伏せ方

- 種類の宣言に `hide`（`record`＝記録ごと・`field`＝欄だけ（どの欄か）・`unit`＝表の中の行だけ）。使えなくなった物（止めた・期限が切れた・依る所が変わった）を、材料からどの粒で外すか。既定は `record`。
- 見直す日（中身の欄。過ぎても材料に載る・健康の候補に出るだけ）と、判断の「いつまで」（過ぎたら効かない）を分ける。備え付けの店の種類は今の動き（見直し日を過ぎたら使えない）のまま。

### 7.5 使った先 — `thth register used <記録>`

読むだけ。その記録（と版）が、どの出し口の・どの世代の材料に・何として載ったか（封と材料の控えから）、どの記録が「から作った」で指しているか（来歴の控え）。今の版が最後の世代に載った版と違えば「材料が古い」と出す。

### 7.6 出した物の控えと関門 — `thth register published`

- 控え: 出し口ごとの追記だけの表（`.thth/published/<出し口>.jsonl`）。1 行 = 出した URL（か道）・初めて出した世代と日時・今の扱い（出ている・転送・消した）。
- 関門: build のあとの一覧（URL か道の並び。1 行 1 つのファイル。サイトマップから作るのは各メディアの手順）を入力に取り、控えと比べる。**前に出した URL が一覧に無ければ赤**。通すのは、宣言した転送（`redirects`: 元と先の組。許す番号は 301・308 が既定）と、宣言した例外（`gone`: 消すと決めた URL と理由の種類）だけ。二重（同じ URL が 2 度）は赤。新しい URL は控えに足す（`--record` を付けたときだけ書く。付けなければ比べるだけ）。
- 厳しさ（許す転送の番号・二重の扱い・例外）は、出し口の宣言に書く。器は外へ問い合わせない（URL が 200 かは見ない。それは各メディアの門）。

### 7.7 読者に見える欄の点検

- 種類の宣言に `reader_fields`（読者に見える欄）。憲法に `internal_words`（内部の語の並び。字のまま比べる。正規表現は書かせない。512 語まで・1 語 64 字まで）。
- `check` が、読者に出る出し口に載る記録の読者に見える欄から、(a) 憲法の内部の語 (b) この台帳の、読者の出し口に載らない種類の番号（字として現れる物）を拾って赤にする。
- 検査の部品（段 4）と同じ出力の形（呼び名・記録・理由）。

### 7.8 旧い材料

`export` と `verify` は、書き出し先に、材料の控えの一覧に無いファイルがあれば赤（THTH は消さない）。`.` で始まるフォルダの中も見る（段 3 の検収の軽い指摘）。見ない物は、出し口の宣言の `ignore`（道の型）に書いた物だけ。

### 宿題に回す物

データの配布の zip（にがみラボ）の出し口・サイトマップを読む部品・各メディアの build の中での封の写し（段 10・11）。

### 中から直す物
- 書き出し先の重なりは、道をそろえて（NFC・小文字・`.` と `..` を解いて）、入れ子（片方がもう片方の中）も重なりとして断る。
