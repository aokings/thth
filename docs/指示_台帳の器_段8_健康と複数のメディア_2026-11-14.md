## 1. 「済み」の線

1. **健康の試験**（§2）: 見本の台帳で、健康の各項目が、起こした事のとおりの数を出す（先に赤を見る）。`health` は読むだけで、台帳のフォルダの全ファイルの sha256 が前後で同じ。
2. **見本でメディア 2 つと共通の台帳**（§3〜§5）: 足す・指す・採る・止める・外す、を 1 回ずつ。残るべき物が残り、消えるべき物が消える（下の表のとおり、試験が置き場を自分で見て確かめる）。
3. **柵**: 健康と候補の命令は台帳を書き換えない。共通の台帳の出さない欄が、どのメディアの材料にも出ない。メディアを外しても、共通の台帳とほかのメディアが残る。口座を外しても、台帳の控えと判断が残る。
4. **今の `leave` の試験**が、動きの変わる所（最後の口座でも台帳の控えを消さない）を除いて通ったまま。変わる所は、変わったことを言う試験に書き直す。

重い穴 = 外す命令が、言った範囲より広く消す（共通の台帳・ほかのメディア・台帳のフォルダの中）・共通の出さない欄がメディアの材料や持ち出しに出る・健康が台帳を書き換える・候補を出すだけのはずの命令が判断を足す。

## 2. 健康 — `thth register health [<台帳>] [--thin] [--across] [--all] [--json]`

読むだけ。項目は設計 §5.8 のとおりで、どれも「数と、多くて 20 件の例」を出す。数え方を次に決める。

| 群 | 項目 | 数え方 |
|---|---|---|
| 網 | 線の薄い点 | 指す・指されるの合計が 0 か 1 の記録（種類ごと。`--thin` で一覧） |
| 網 | 開いた問いの数と閉じ方 | 問いの記録のうち答えの無い物・閉じた物の理由の種類ごとの数 |
| 判断 | 古くなった判断 | 依る所が今と違う判断（`J.evaluate` が古い） |
| 判断 | 観測しか無い版 | 状態の欄に語があるが、その版に効く判断が無い記録 |
| 判断 | 結び直しの候補 | `J.candidates` |
| 判断 | 書き手だけの読み・同じ者の確かめ | 判断の「誰が」が、その版を書いた者（取り込みの跡の集めた者）と同じ |
| 判断 | 「まだ」の理由の種類ごとの数・調べ直す条件が満たされた問い | 判断と憲法の語から |
| 判断 | 基準だけで通っている記録 | 効いている判断が基準（`--baseline`）だけの記録 |
| 判断 | 範囲か時点が未宣言の値 | 段 1 の印 |
| 判断 | 見直す来歴の控え | 指す欄の `recorded_version` が相手の今の版と違う |
| 封 | 受け入れ待ちの判断 | 封の位置より後ろの広げる判断 |
| 封 | よそから来て効いている「止める」 | 共通の台帳の止めるで、このメディアの材料から外れている記録 |
| 封 | 消し終わっていない消す求め | `erase.unfinished` |
| 期限 | 見直す日を過ぎた・「いつまで」が近い（30 日以内）・過ぎたのに最後の世代に載っている | 判定の日時は `--as-of`（既定は今） |
| 決まり | 1 件も当たらない検査 | `when` に合う記録が 0 の検査（台本に残った廃止の条件が見える） |
| 決まり | 回す途中で止まった検査・確かめられない指し | 検査の結果から |
| 共通 | 採り入れ待ち | 採った版が共通の今の版と違う記録 |
| 共通 | 共通の止めるを確かめられないまま配った | 配った物の控えの印から |

- `--across`: 持ち主の全部の台帳をまたいで、同じ出典らしい物（DOI か URL が同じ。URL は小文字にして末尾の `/` を除く）を並べる。候補を出すだけ。
- `--all --json`: 台帳ごとに 1 行の JSON（群ごとの数だけ）。hub が束ねられる形。網には出ない。
- 重い台帳でも 1 回の読みで終える（段 4 の G1 のたどりを使う）。

## 3. 共通の台帳と、対応の記録

- 共通の台帳は、控えに `role: common` と書いた台帳（持ち主に 1 つ。2 つめは断る）。`thth register add <台帳> --common`。
- 備え付けの種類を足す: `correspondence`（対応の記録: メディアごとの番号と、関係の種類 `same`・`related`・`broader`・`narrower`。関係の種類は必須）・`operator`（運営者の情報。既定で全部の欄が出さない欄）・`account`（口座の名前と向き先。鍵の欄は種類に無く、鍵らしい値は今の「秘密らしい値を断る」で断る）。
- **共通の出さない欄は、どのメディアの材料にも出ない**: 採った記録を材料に書くとき、共通の種類の `private_fields`（段 7）を、メディアの出し口の宣言より先に当てる（メディアの側で外せない）。
- **姉妹リンクの候補** `thth register links --sisters <メディア>`: 対応の記録から、関係が `same` で、相手のメディアの記録が読者の出し口で使える対を並べる。候補を出すだけで、載せるかは別の「出してよいか」の判断（器は足さない）。相手の台帳が手元に無ければ「確かめられない」。

## 4. 足す・退役

- 足す: `thth register add <台帳> --project <メディア>`（今ある命令。2 つめの台帳も同じ）。足したとき、ほかの台帳と「同じ物がありそう」（§2 の `--across` と同じ見方）を並べるだけで、移さない。
- 退役: メディアの記録（共通の台帳の `media` の行があれば）を退役に。記録も出した物の控えも消さない。

## 5. 外す範囲は 3 つ

| 範囲 | 命令 | 消える物 | 残る物（試験が置き場を見て確かめる） |
|---|---|---|---|
| 口座 1 つ | 今の `thth leave <口座>` | その口座の鍵・状態・記録 | **台帳の控えと判断（その project の最後の口座でも）**・メディア・ほかの口座・台帳のフォルダ |
| メディア 1 つ | `thth project leave <メディア>` | そのメディアの全部の口座・THTH の側の台帳の控え | 台帳のフォルダ（`.thth/` の判断・封・控えも）・共通の台帳・ほかのメディア |
| 持ち主の全部 | `thth owner leave` | 全部の口座・THTH の側の台帳の控え・主体 | 全部の台帳のフォルダ |

- どれも二段（1 回めは消える物と残る物の数を出すだけ）。途中の段と、消した種類と数を記録する（今の `leave.py` の流儀）。
- 封の秘密の鍵（`~/.config/thth/register_seal.pem`）は、`owner leave` のときだけ消す。その前に「この鍵で封をした台帳は、ほかの機械で確かめ続けられるが、新しい封は作れなくなる」と知らせる。
- **今の `leave` の動きが変わる**（最後の口座でも台帳の控えを消さない）。リリースノートと privacy に書く（release の便）。
- 持ち出し `thth register export-ledger <メディア> --to <先>`（名前は叩き台）: 台帳のフォルダをそのまま写し、採っている共通の記録の、その版を付ける（共通の出さない欄は付けない）。受け取った側では、付いてきた封は効かない（公開鍵が違う）。
