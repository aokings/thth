## 0. 結論

1. **THTH の Meta のアプリは、ビジネス「株式会社吾徳」にある。** 吾徳はビジネス認証が「認証済み」、技術提供者のアクセス認証も「認証済み」【見た】。アプリ ID 1648991573463758・モードはライブ・ユースケースは「Threads API にアクセス」の 1 つだけ【見た】。
2. **同じアプリに、ページ・広告・Instagram のユースケースを足せる。** 追加の画面に「ページのすべてを管理」「マーケティング API で広告を作成・管理」「同 測定」「同 広告リード」「広告 MCP サーバーで広告を作成・管理」「Instagram でメッセージとコンテンツを管理」が出ている【見た】。公式も「Threads API にアクセス」と「ページのすべてを管理」は同じアプリに置けると書いている【読】。**ただし、足したユースケースは消せない**【読】。
3. **masaru のページ・広告アカウントに THTH から出すだけなら、審査は要らない見込み。** 公式: 審査が要るのは「アプリやアプリにつながったビジネスで役割を持たない人」が使うとき、マーケティング API は「自分が持たない・管理しないデータに触るとき」【読】。masaru はアプリの管理者で、ページの持ち主。Threads の 9/14 と同じ形（役割の人は審査なしで全権限が使えた）。確かめるのは、masaru が許可した鍵の権限の一覧（§2 の手順 5）【未】。
4. **本線が心配していた「開発モードの投稿はほかの人に見えない」は、THTH には当たらない見込み。** アプリはもうライブ（9/23 から）【見た】。それでも、試しの 1 本をログインしていない画面で見る（§2 の手順 6）。
5. **審査を「最大限で 1 回」出すなら、出せるのは THTH が全部の口を作り終えてから。** 録画に、申請した権限が実際に動く画面が映っていないと落ちる（`手順_AppReview_2026-09-14.md` §1.2）。今の THTH には Facebook ページの口が無い（`thth/adapters/` に facebook も instagram も無い）。だから順番は「口を作る → 自分のページで使う → 外の人にも使わせるときに審査」。

## 3. 権限の一覧（最大限）

「今足す」＝ B で足す。「要る口」＝ THTH で作る道具。「審査」＝**外の人に使わせるときに**要るもの。自分のページ・自分の広告だけなら、どれも審査なしで使える見込み（§0 の 3）。依存の関係は公式の権限の参照から【読】。
