## 0. 先に言うこと: 台帳の大半が git の外にある

`.gitignore` は「調べのデータと取得物は手元に置く」で、**許可した物だけを追跡する**形（頭の 1 行 `/*`）。読んで確かめた結果（`git check-ignore`・`git ls-files`）:

## 6. 理由の種類の語・状態の語（原語のまま）

- 照合台帳の行: `status` = `shown`・`held`。`held_kind` = `unresolved`・`release_credits`・`other_version`・`conflict`・`role_differs`・`other_release`。説明は `held_reason_ja`。印は `mark`、次に確かめることは `next_check_ja`、版の文は `version_ja`。
- 版の関係の照合台帳: `held_kind` = `other_version`・`not_found`・`unresolved`・`prose`（上と語の集まりが違う）。
- 組の出し口: `public`・`public_song`（true・false・欄なし）。
- MusicBrainz・Discogs の当たり（`mb.verdict`・`discogs.verdict`）: 「合う」「食い違う」「盤全体…」「片方に無い…」「同定が未決…」など日本語の文で始まる語（`DG_SHORT` が頭の字で読み分ける。読んだ）。
- 棚の進み: `research_status` = `queued`・`collecting`・`merged`・`audited`。

## 10. MMR の本線（とクレジットの経路）に聞きたいこと

1. **`data/*.csv`・`queue.json`・`ledger.json`・記事の本文を git の外に置いているのは、決めた事か。** 器は前の版を取り出せることを前提にしている（訂正の跡・判断の版・共通の台帳を版で使う）。影の台帳を作る段では手元の写しで足りるが、向きを替えるときに台帳を repo（か別の git）に入れてよいか。入れられない理由（大きさ・権利・取得物）があれば知りたい。
2. **今の決まりの正本で、ずれが 3 つある。どれが今の決まりか**: (a) `established` の条件は廃止のままでよいか（台本に残る）、(b) `lab.yaml` の `contextual_cap_types` に journalistic_report と database_record が残るのは、廃止の書き残しか、決め直したのか、(c) 読みの 3 値（一次・二次・未確認）はどの欄で持っているか。
3. **照合台帳の判断は、組（枚）に付けるのか、行（曲）に付けるのか。** `public`・`public_song` は枚、`status` と `held_kind` は行にある。行が 1 つ増えたとき（本線が 5 役割の記録を足したとき）、同じ枚のほかの行の「出してよい」まで見直すのが今の運用か、足した行だけを見るのか。
