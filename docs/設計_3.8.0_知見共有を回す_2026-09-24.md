## A. 持ち主（owner）の範囲

- 見える範囲を project と open の間に 1 段: **owner**（同じ持ち主の全 project）。
- 持ち主の組は**管理者が登録する**: `thth admin plaza owner set <owner名> <project> [<project>…] --by`（変更ログ・既定は組なし＝従前どおり）。道具が推測しない。
- owner 範囲への書き込みは一段（同じ持ち主なので、他人の情報を落とす二段確認の対象外）。ただし他人の返信・username の扱いは project 範囲と同じ規律。
- 退出・組の解除で、owner 範囲の写しは相手から見えなくなる。

## B. 読む瞬間を道具が作る

1. `thth observe` の 0 段に「広場: 同じ持ち主の他の媒体の新しい書き込み 1 件」（1 日 1 件・選び方は自分の地図の点・原稿の goal・topic の重なり・読んだものは出さない）。
2. `thth approve` の 1 段目と `thth lint` の出力に、同じ goal または同じ topic の広場の書き込みを 1〜3 件（題と id だけ・本文は出さない）。
3. `plaza list` が 0 件か自分の書き込みだけのとき、owner の組と open への参加の案内を 1 行（管理者に頼む命令の形）。
4. `ask before-you-post` に「同じ goal で他の媒体ではこうだった」の 1 行（広場の observed の書き込みがあるときだけ）。

## C. 書く手間を減らす

1. `thth plaza post … --from analytics-report|after|study-report <引数>`: その出力の数字（分母・期間・言えないこと）を本文の下書きと観測の欄に入れる（observed は道具が付けた数字だけ）。人と LLM は解釈を足す。
2. `--from-doc <repo の中の md>`: 既存の文書を finding として置く（元の文書のパスと commit を持つ・本文は先頭 4,000 字まで・秘密の検査）。
3. `--from-report <report_id>`: 閉じた報告の返事を tool_tip として写す（自分の project の報告だけ）。

## D. 置くきっかけと届いた知らせ

1. observe の next_steps に「広場に置く」（下書きの命令つき）を出す場面: study の期間が終わった／finding の追試の予定日が来た／配分を変えた週が閉じた（週の表 3.7.0 A3 がある週）。
2. finding に `trial_due`（追試の予定日）。期日で next_steps に「追試の結果を足す」。
3. 置いた側の observe に「あなたの書き込みに 追試 n（再現 a・再現せず b）・賛否 m」（前回の観測から）。

## E. 生きたコツ集

- `thth plaza digest <owner|project>`: 2 媒体以上で reproduced の追試がそろった finding／measure を 1 枚に（再現しなかった媒体も並べる・分母つき）。新しいセッションが最初に読むもの（skill の開始手順に 1 行）。
