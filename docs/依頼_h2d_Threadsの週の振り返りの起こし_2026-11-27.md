# 依頼 THTH運用 → H2D：Threads の週の振り返りを毎週打って各担当を起こす（2026-11-27）

出所: `docs/依頼_THTH開発_週次の振り返りの材料とskill_2026-11-25.md` §4（起こしは THTH運用が H2D に頼む）。開発 #9648（11/25）: 5.30.0 で `thth review weekly` が VM で使える・起こしは「月曜の夜より後」を推す。
目当て: 週が閉じたら、口座ごとの材料を担当が自分で読み、次の週の変更を 1 つ決める（`study add`）きっかけを機械が作る。落ち込みの印（`drop: true`）の口座は本線にも届ける。

## 打つもの

VM で口座ごとに 1 回（ssh の一行ではログインの設定を読まないので、この形で打つ）:

```
ssh wt 'env THTH_ROOT=/srv/thth /srv/thth/app/bin/thth review weekly <口座> --json'
```

- `--week` は付けない（既定が「閉じた最後の週」）
- 11/27 13:30 に 4 口座で打って rc 0・JSON が出るのを THTH運用が確かめた（11/16 の週: kopicha-threads・asmon-kanto-threads は `drop: true`、headlesson-threads・sometokagaku-threads は false）

## 口座と起こす先（推し）

- 今は Threads の試しを回している 2 口座だけ。ほかの口座は、担当が材料を読む段取りができたら足す（表に行を足すだけの形が良い）
- 伝言の中身は、週・`drop` と `drop_units` の要約（口座・シリーズ・企画）と、全文の JSON の置き場（または打つ命令そのもの）。数字の解釈はしない。読むのは各担当の LLM（skill は 5.30.0 の依頼の書 §3）
- 打った命令が rc 0 でない・JSON が読めないときは、各担当でなく THTH運用（thth/ops）を起こす

## いつ（推し）

毎週火曜 09:00（JST）。週は月曜始まりで日曜に閉じ、月曜の夜まで待つと日曜の投稿の 24 時間の数字が揃う（開発 #9614・#9648）。

- 初回は **12/01（火）09:00**。11/23〜11/29 の週が対象になる
- 関東の本数の試し（11/26〜12/02）の判定は 12/03 に関東が自分で打つので、この起こしとは別（重ねてよい）
