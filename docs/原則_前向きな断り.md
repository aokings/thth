# 原則: 前向きな断り（2026-11-03 masaru）

> 「ダメな時は、何故ダメでどうすればOKなのか、どうすればより良くなるのかが提示される必要が有ります。だめという時こそ丁寧で前向きな反応を出す必要があります」
> 「この前向きなディナイは恐ろしく大事なコンセプトです」（masaru 2026-11-03）

THTH の芯の原則の 1 つ。監査・審査・lint・関門・ガード・API の断り・承認の差し戻し・MCP の道具の誤り、THTH が「出さない・通さない・できない」と返すすべての所に当てはまる。商用で監査と審査を機械化する（[`docs/洗い出し_商用_足りないもの_2026-11-03.md`](洗い出し_商用_足りないもの_2026-11-03.md) §3）ときの土台でもある。

## 断るときに必ず出す 3 つ

1. **なぜ**: どの決まりに、どの値が当たったか（符丁と、人が読める 1 文。決まりの出所へのリンクか名前）。
2. **どうすれば通るか**: そのまま打てる直し方（命令・書き換える欄と値）。直し方が利用者の手の外にあるとき（媒体の審査待ち・管理者の操作）は、誰に何を頼めばよいかと、待つ間にできること。
3. **どうすればもっと良くなるか**: 通る最低限の先の一手（例: 上限に当たった → 間隔を空けた予約の形・同じ趣旨で伸びた過去の型）。

## 言い方

- 丁寧で前向きに。責めない。「できません」「不正です」で終わらない。
- 断りは利用者と窓口の LLM が次に進むための道案内として書く。
- 短く。3 つは各 1 行を基本に、詳しくは `--json` の欄と符丁の説明に寄せる。

## 使い勝手を削らない（同じ日の masaru の条件）

- 関門は道具が裏で走らせ、通るときは黙る。止めるときだけ 3 つを出す。
- 同じ確かめを 2 度させない。窓口が覚えることを増やさない（厳しさは道具の出力と lint に寄せる）。

## 機械で守る

- 断りの符丁ごとに、3 つの欄（`why`・`fix`・`better`）が埋まっていることを試験で縛る。新しい断りを足すと、3 つが無ければ試験が赤になる。
- 今ある断りの仕組み（`thth/refusals.py`・`report_channel:` の行・符丁の説明の表）を土台にする。今の断りを全部洗って、3 つのうち欠けているものを数で出すところから始める。
