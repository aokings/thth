# THTH 5.14.1（2026-11-10）

5.14.0 のすぐあとに、`thth dm event` の打ち直しの柵を足す版です（masaru 11/10「入れて」）。新しい断りの符丁は 3 つです（meta_event_already_sent・meta_event_marks_unreadable・meta_event_nth_unused）。

## 足したこと

- **同じ出来事を二度送らない**（`thth dm event`・`thth/meta_events.py`）
  - Meta は出来事の重複を除きません（公式の文書）。そのため同じ購入を二度送ると、広告の計測で二重に数えられます。
  - 同じ口座で、同じ digest（相手・種類・金額が同じ）の出来事は、前に送ってからしばらく（`MARK_WINDOW`・いまは 24 時間）の間、`meta_event_already_sent` で断ります。
    - 日付でなく送った時刻から数えるので、日本時間の 0 時をまたいでも二度送れません。
  - 一段目でも「少し前に送っています」と知らせます。
  - 印は二段目のロックの中で、出来事の POST の直前に置きます。
    - 結果が分からないとき以外（Meta がはっきり断った・会話の窓・権限）は、印を外します。何も数えられていないからです。
    - 結果が分からないときは、印を残します。打ち直しはしません。
  - 同じ相手が同じ金額で本当にもう一度買ったときは、`--nth 2` を付けます。
    - `--nth N` は、N−1 回目を送った印があるときだけ通ります（`meta_event_nth_unused`）。番号を変えるだけで柵を抜けられないようにするためです。
  - 印か、その鍵が読めない・書けないときは、確かめられないので送りません（`meta_event_marks_unreadable`）。
    - 印が残っているのに鍵だけ無いときも断ります。鍵を作り直すと古い印と合わなくなるからです。
  - 時計が戻って印が「未来」に見えても捨てず、窓の中として数えます。
- **残すもの**
  - `state/<口座>/event_sent.json` に、印と時刻を残します。
    - 印は、口座ごとの秘密の鍵（`event_mark.key`・600）で digest を混ぜた HMAC です。
    - 相手の id の候補を持っていても、鍵が無ければ当てられません。
  - 窓より古い印は、読むたびに捨てます。
