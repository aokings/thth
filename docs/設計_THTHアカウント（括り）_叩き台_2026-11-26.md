## 0. 前提（masaru と固めたこと・変えていない）

1. 括りが情報を分ける単位。project・口座・主体・鍵・原稿・承認の台帳・記録・止め・集計は、必ずどれか 1 つの括りに属する。人（持ち主）と括りは別。
2. 漏れは命令ごとでなく置き場で塞ぐ。データは括りごとのフォルダ。命令は 1 つの括りの中に入って動く。またぐのは管理者の一覧だけ（件数と止まりだけ）。
3. 入口は `thth login`。鍵は 1 つの括りにだけ結び付く。どの括りで動くかは鍵で決まる。
4. 単位はレーン。1 レーンは 1 つの括りの鍵だけ。鍵はレーンごとのファイル。
5. masaru のレーンも鍵で打つ形に寄せる。ssh は管理者が直す・調べるときだけ。
6. 共通: コード・Meta アプリ・thth.me の Worker と認可の受け口・timer・版の出し方。
7. 今の物は全部、最初の括り（`main`・持ち主 masaru）に移す。
8. 限り: 管理者は ssh で全部の括りが読める。暗号で塞ぐのは今回やらない。
9. のちに門を monban に寄せられる形にする。

前提のうち、読んで分かったことで**言い方を足したい所が 2 つ**あります（中身は変えません）。

- **前提 2 の「置き場」は `/srv/thth` の中だけでは足りない**【動】。口座の token と env のファイルは、29 口座のうち 28 が VM の `~wt/.config/thth/` にあります（台帳の `token`・`env` が `~` で始まる）。括りのフォルダの外です。新しい括りでは token を括りのフォルダの中に置く決まりにし、`main` の 28 本は当面そのまま、と分けます（§3 の段 5）。
- **前提 4 の「レーンごとのファイル」は、masaru の Mac の上では取り違えを防ぐ柵で、守りの壁ではない**【推】。同じ Mac の同じ利用者（masaru）で動くセッションは、どのレーンのファイルも読めます。masaru の括り同士は「間違えて混ぜない」ための分け、奥さまの括りは「別の機械・別の利用者」で初めて壁になります。§4 に書きます。

## 1. 構造（図に起こせる形）

### 1.1 もの と つながり

```
人（持ち主）  masaru ──┬── 括り main   （今の 9 project・29 口座）
                      └── 括り <新>    （新しい媒体群）
              奥さま ───── 括り <奥さまの>（のちに）

括り ──┬── project ── 口座（SNS・ブログ）── 原稿・承認の台帳・止め・記録

       ├── 鍵（レーンごとに 1 本。括りに結び付く）
       └── 集計（board・morning・広場・地図・週のまとめ）

レーン（例: kopicha の SNS・asmon の関東・asmon の関東データ）
   └── 鍵のファイル 1 つ ── 括り 1 つ    （同じ括りに複数のレーンがあってよい）

共通（どの括りにも属さない）
   コード（app・venv）／Meta・X・はてなのアプリの登録と秘密／thth.me の Worker／
   VM の常駐 2 本と保守の timer／VM→Worker の署名の鍵／X の読みの予算／
   Meta の Webhook の受け口／開発への報告の箱／版の印
```

### 1.2 道（誰がどこを通るか）

```
レーンのセッション ── thth（Mac）── 鍵 ──▶ thth.me（Worker）── 括りの束 ──▶ VM の常駐
                                                                       │ 鍵 → 括り を VM が決める
                                                                       ▼
                                                             括りのフォルダの中だけで動く

口座の timer（VM）── 口座の名前 ──▶ 名前から括りを引く ──▶ 括りのフォルダの中だけで動く

管理者（THTH開発・THTH運用）── ssh wt ──▶ 括りを名指しして入る／括りをまたぐ一覧（件数と止まりだけ）
```

要点は 1 つです。**今のコードは置き場の根を `accounts.thth_root()` の 1 か所から引いている**【読】（44 ファイル・74 か所。`state`・`accounts`・`principals`・`adaccounts`・`registers`・`stores`・`waba`・`owner_state` などは全部ここから）。全口座を歩く所は 40 ファイルあります【読】（`list_account_names()` を呼ぶ所）。この根を「今入っている括りのフォルダ」に差し替えれば、40 ファイルの「全部歩く」は、手を入れずに「括りの中を全部歩く」になります。命令を 1 つずつ直す形にしないのは、このためです。

masaru が退けた「置き場を 2 つに分ける」との違い: 利用者から見える THTH は 1 つ（入口・版・timer・Worker・管理者の一覧が 1 つ）で、括りは THTH の中の台帳に載ります。中の作りとして「括りごとに、今の置き場と同じ形のフォルダを持つ」だけです。

## 2. 置き場の形

### 2.1 目指す形

```
/srv/thth/
  app/  venv/                     共通: コード
  private/                        共通: 管理者の資格・VM→Worker の署名の鍵（今のまま）
  state/_admin/                   共通: X の読みの予算・timer の控え・管理者への知らせ
  state/_webhook/                 共通: Meta の Webhook の受け口（1 アプリに 1 つ）
  state/_reports/                 共通: 開発への報告の箱
  state/_app.lock  worker.json    共通: 版の入れ替えの印
  ws/
    main/
      ws.json                     括りの名・持ち主・作った日（秘密なし）
      accounts/ adaccounts/ principals/ registers/ stores/ waba/
      state/<口座>/…              承認の台帳（approvals.json）・止め（holds.json）・sent・runs・guard
      state/_plaza/ _plaza_reads/ _map/ _invites/ _leave/ _auth/ _repos/ topics.json topic_advice/ threads/
      principal_state/ owner_state/ adaccount_state/ register_state/ …
      repos/ origins/             原稿の repo の写し
      secrets/                    口座の token（新しい括りは必ずここ）
      private/lane-keys.json      この括りのレーンの鍵（hash だけ）
      notifications.json  logs/
    <新>/                         同じ形
```

- 「括りの物」と「共通の物」の線引きは、上の並びが案です【推】。今の `state/` の中で `_` で始まるフォルダは 11（ほかに鍵のファイルが 1 つ）あり【動】、どちらに入るかを 1 つずつ決める表を段 0 で作ります。迷うのは X の読みの予算（アプリ 1 つの枠を全部の括りで分け合う）と Webhook（アプリに 1 つ）で、どちらも共通に置き、括りに渡すのは自分の分の数だけにします。
- **`ws/` が無い置き場は、根がそのまま 1 つの括りとして動く**形を、移す間だけでなくずっと残します【推】。PyPI から入れた外の人の置き場（`~/.thth`）は括りを持たないからです。

### 2.2 口座の名前は、全部の括りを通して 1 つだけ（案）

口座の名前は、Worker の束の名前・timer の単位の名前（`thth@<口座>`）・認可の戻り先の照合にそのまま使われています【読】。括りごとに同じ名前を許すと、この 3 つを全部作り替えることになります。そこで**名前は全体で一意**のままにし、名前から括りを引くのは `ws/*/accounts/<名前>.json` を探すだけにします（写しの表を作らない）。project の名前も同じです（`thth-map@<project>` の timer があるため【動】）。

代償: 新しい口座を作るとき、ほかの括りで使われている名前は「使えません」と断られるので、**その名前がどこかにあることだけは伝わります**。中身は伝わりません。外の人が増えてこれが困るようになったら、Worker の束の名前を「括り＋口座」に作り替える仕事（Worker の中のデータの移し替え）が要ります。

段 5 で分かっていること:

## 4. 鍵と login

### 4.1 鍵の置き場（Mac の側）

- `~/.config/thth/lanes/<repo>-<レーン>.json`（0600・親 0700）。レーンが 1 つだけの repo は `<repo>.json`。hub の伝言の名乗り（`~/.config/agent-mail/`）と同じ名前の付け方です【動: 並びを見た】。
- 中身: `url`・`key`・`workspace`（括りの名・表示と食い違いの検査のための控え）・`lane`・`issued_at`・`expires_at`・`issuer`（今は `thth.me`。のちに monban）。
- 今の `~/.config/thth/remote.json`（1 本だけの鍵）は**消さずに残し、読み続けます**。古い CLI に戻しても動くようにするためです（§8 R3）。

### 4.2 どのレーンの鍵を使うか

1 つの repo に複数のレーンが同居するので、作業フォルダでは決めません。順に:

1. `--lane <名前>`（全部の命令に付けられる旗）
2. 環境変数 `THTH_LANE`
3. どちらも無く、その repo の名前に当たる鍵のファイルが 1 つだけならそれ
4. 2 つ以上あれば `lane_ambiguous` で断り、候補の名前と「`--lane` を付ける」を出す（勝手に選ばない）

Claude Code の Bash は呼ぶたびに新しい shell なので【読: この環境の決まり】、実際には毎回 `--lane` を付けるか、レーンの入口の文書に 1 行書く形になる見込みです。

### 4.3 login

- `thth login --lane <レーン>`。今のブラウザ式（`gh auth login` と同じ形・3.14.2）をそのまま使います【読】。違うのは、ブラウザで入れるものが「口座の名前と口座の secret」から「持ち主の名前と持ち主の secret・どの括りか」に変わる所です。持ち主が括りを 1 つしか持たなければ選ぶ画面は出しません。
- 鍵は括りに結び付き、VM は hash だけを `ws/<括り>/private/lane-keys.json` に持ちます（持ち主・レーンの名・期限・取り消しの印）。今の資格のファイル（`private/report-credentials.json`）には**欄を足しません**（§8 R1）。
- 鍵で打った記録には、今と同じく鍵の id（hash の先頭 12 字）が残ります【読】。それにレーンの名が付きます。

### 4.4 世代をまたぐ扱い

- 鍵はセッションでなく**レーン**の持ち物です。第 N のセッションが終わって第 N+1 が始まっても、同じファイルをそのまま使います。申し送りに鍵の値は書きません（ファイルの名前だけ）。
- 期限は今と同じ 365 日【読: `CREDENTIAL_DAYS`】。切れる 30 日前から `thth doctor` と board に出します。出し直しは `thth login --lane` をもう一度（古い鍵は VM が取り消す）。
- レーンをやめるときは `thth logout --lane`（手元のファイルを消し、VM の鍵を取り消す）。管理者は括りの鍵の一覧（レーンの名・期限・最後に使った日。値は無い）を見て、1 本ずつ取り消せます。

### 4.5 括りの食い違いを断る所（3 か所・権威は VM）

| 所 | 何を見るか | 断り方 |
|---|---|---|
| Worker | 鍵の hash が、頼まれた括りの鍵の表にあるか | 今と同じ 401（表に無い鍵）【読: 今の作りを括りに当てはめるだけ】 |
| **VM（権威）** | 鍵 → 括りを引き、その括りのフォルダに入ってから命令を動かす。頼まれた口座がそのフォルダに無ければ断る | **「その口座はありません」と同じ断り**。ほかの括りにあるのか、どこにも無いのかを見分けられない形にする |
| CLI（手元） | 鍵のファイルの `workspace` の控えと、VM の答えに付く括りの名が違う | `workspace_mismatch`。次の一手は「`thth login --lane` をやり直す」 |

VM の断りを「ありません」と同じにするのは、口座の名前を当てて回る探りに答えないためです。前向きな断り（なぜ・通る直し方・より良くする一手）は守り、直し方は「口座の名前を確かめる・`thth account` で自分の括りの口座を見る」にします。

### 4.6 この鍵で塞げるもの・塞げないもの

- 塞げる: 鍵を持つレーンが、ほかの括りの物を読む・書く・数えること（VM が開かない）。
- 塞げない【推】: masaru の Mac の上で、あるレーンのセッションが別のレーンの鍵のファイルを読むこと（同じ利用者なので読める）。masaru の括り同士の分けは、取り違えを防ぐためのものです。
- 塞げない: 管理者が ssh で入って読むこと（前提 8）。

### 4.7 monban に寄せるとき

鍵から「持ち主・括り・レーン・期限」を引く所を、VM の 1 つの口にまとめます。login の手元の側も 1 つの口にします。のちに monban の login に替えるときは、この 2 つの口の中身と、鍵のファイルの `issuer` を替えます。括りのフォルダと命令の側は変わりません。monban の金庫（枝 sync-garden）は今回読んでいません。

## 5. 今の命令の棚卸し

手元の repo で parser を歩くと、一番上の命令が 102、2 段目まで開くと 255 あります【動】。遠くの道に今出ているのは 67、名指しで断っているのは 22 です【動: `remote.COMMANDS` と `UNSUPPORTED` を数えた】。

下の表の「今」の欄は【読】か【動】、「これから」の欄は案【推】です。**命令 1 つずつの札は段 0 で機械で作り、札の無い命令があれば試験が赤になる**形にします。ここは束ねた見立てです。

### 5.1 括りの中で済み、もう遠くの道にある（67・そのまま）

| 束 | 命令 |
|---|---|
| 出す・消す | `send`・`schedule`（予約）・`retract`・`edit`・`like`／`unlike`・`reply hide`／`unhide` |
| 読む | `posts`・`replies`・`measured`・`collect`・`mentions`・`thread`・`where`・`who`・`embed`・`upcoming`・`profile`・`location`・`topics --search` |
| 口座 | `account status`・`account set`・`queue`・`inflight`・`doctor`・`events`・`summary`・`dashboard` |
| はてな | `bookmark add／edit／delete／batch／batch-status／batch-cancel` |
| Meta | `dm …`・`live …`・`page cta …`・`brand …`・`creators search`・`shop …`・`webhook status／subscribe` |
| 広告（お金が動かない） | `ads doctor／show／insights／estimate／catalog …／leads／network／shop／boost／pause／stop` |

## 6. 柵（括りをまたいで見えない試験）

機械で確かめられることは文で縛らず柵にします。柵は 4 枚です。どれも、**一度わざと壊して赤になるのを見てから**置きます。

### 6.1 置き場を見張る柵（主役）

- 試しの置き場に括りを 2 つ作ります（A と B）。B には、口座・主体・広告の口座・店・台帳・原稿・承認の台帳・止め・sent・広場・地図・報告・token の代わりの偽の値、を一通り置き、名前・本文・ID に**目印の文字列**（ほかに現れない綴り）を仕込みます。
- parser を歩いて全部の命令を拾い（今 255）、A の鍵で入った形で、引数を機械で作って打ちます: 引数なし／A の口座／**B の口座の名前**／**B の project の名前**／`--json` あり・なし。網は塞ぎます（外へ出ようとしたら失敗させる）。
- 見るのは 3 つ:
  1. **B のフォルダの下のファイルを 1 つも開いていない・並びを見ていない**（Python の監査の鉤で、開く・並べる・状態を見るを全部記録し、`ws/B/` の下に触れたら赤）。出力を見るだけの試験と違い、「読んだが出さなかった」も捕まえます。
  2. 出力（標準出力・エラー出力・A の側に書いたファイル）に B の目印が 1 つも無い。
  3. B の口座の名前を渡したときの断りが、どこにも無い名前を渡したときの断りと**同じ符丁・同じ文**である。
- 新しい命令を足して札（括りの中・管理者だけ・括りなし）を付け忘れると赤。引数の作り方が分からない命令は、札の表に例を 1 行書かないと赤。

### 6.2 根の引き方の柵（静的）

`thth_root()` を直に呼んでよいのは「括りの根」と「共通の根」を返す 2 つの口だけ、を構文で検査します。`~/.config/thth` を直に開く所も、許した module の表に無ければ赤。新しい置き場を足す人が、括りの外に物を置けないようにします。

### 6.3 遠くの道の柵

VM の頼みを行う所で、A の鍵に B の口座・B の project・B の原稿の道を渡し、6.1 の 3 と同じ断りになることを全部の操作の名前（今 67＋足す分）で見ます。Worker の試験では、A の鍵で B の括りの束に頼むと 401 になることを見ます。

### 6.4 管理者の一覧の柵

括りをまたぐ一覧の出力を、欄の名前の許した表（括りの名・口座の数・止まっている数・未承認の数・鍵の数と期限）と突き合わせ、表に無い欄・B の目印が出たら赤。「件数と止まりだけ」を機械で守ります。

### 6.5 わざと壊す例

- 主体の兄弟を探す所（`principals.siblings`）を共通の根から歩かせる → 6.1 の 1 が赤。
- 承認の台帳の「ほかの口座で承認済みか」を見る所（`state/` を歩く【読】）を共通の根にする → 6.1 の 1 が赤。
- VM の断りを `not_in_workspace` のような別の符丁にする → 6.1 の 3 と 6.3 が赤。
- 管理者の一覧に口座の名前を足す → 6.4 が赤。

### 6.6 柵で見えないもの

- VM の常駐（招待・動きの一覧・頼みを行う・Webhook）は、括りを順に回る 1 つの process です。「A を回っている間に B の物を持ち越す」は 6.1 の形では出にくいので、常駐には別に「括りを替えるたびに持ち物を空にする」試験を置きます【推】。
- 外の媒体の側でつながっている物（同じ Meta アプリ・同じ X のアプリ）。§8 の R6・R7。

## 7. Worker と thth.me の側・privacy と Meta への説明

### 7.1 Worker【読んだうえの案】

- 今: 頼みは口座の名前で「口座の束」に置かれ、鍵の表も口座ごとです。VM は持ち主ごとに鍵の表を押し上げ、1 回に 64 行までです【読】。括りの鍵を口座ごとの表に写すと、`main` は口座 31 × レーンの数で、すぐ 64 を越えます。
- 案: **括りの束を 1 つ足す**。括りの鍵の頼みは、頼みに括りの名を付けて括りの束に置き、鍵の表も括りごとに持ちます（1 回の押し上げで 64 本まで）。口座の名前は頼みの中身として VM に渡り、口座が括りにあるかは VM が決めます。Worker は口座と括りの対応を持ちません（Worker に置く情報を増やさない）。【作った・括り 第3】束は新しい DO の型を足さず、口座の束と同じ型を名前 `ws:<括り>` で引きます（`:` は口座の名前に無いのでぶつからず、migration も要らない）。束の名は括りだけで、持ち主は入れません: 括りの名は対応表で全体に 1 つで、束の中の鍵の表は押し上げた持ち主ごとに分かれているので、持ち主を名に入れても分けが増えず、持ち主を替えたときに頼みと鍵のファイルが迷子になるだけのためです。頼みは body の `workspace` で束を選び（VM には渡さない）、request_id は `<id>~<括り>`。
- 今の口座ごとの鍵（招待で入った人の鍵・今の `remote.json`）は、そのまま動かします。
- login のページ: 「口座の名前と口座の secret」に加えて「持ち主の名前と secret・括り」の形を足します。【作った・括り 第3】`thth login --lane` が start に括りとレーンの名を足したときだけ、頁は括り・レーンを見せて持ち主の form を出します。括りの持ち主かは Worker でなく VM が対応表で決め、作らなかった理由は login の poll で CLI に返ります。
- 動きの一覧（/activity）: 持ち主ごとのままです。1 人 8 口座までの上限があり【読】、masaru の口座の数とは合っていません。括りを選んで見る形に直すのは、今回の外に置きます。
- 招待・認可の戻り・消してほしいの受け口: Worker は変えません。VM の側で、口座の名前から括りを引いてから動きます。招待には「どの括りに入るか」を VM の側で持たせます（Worker は hash しか持たない【読】）。
- 出す順は今の決まりのとおり **Worker が先・VM があと**。Worker は古い VM の押し上げの形も受け、VM は古い Worker に当たったら古い形で話します（今も同じ作りがあります【読: `_legacy`】）。

### 7.2 privacy・規約・`llms.txt`

直す所【読: `callback/public/privacy/`】:

- 「運営者のサーバーに何を置くか」の節に、**データは持ち主の括りごとに分けて置き、THTH の命令と鍵はほかの括りのデータを読まない**ことを、データと目的の言葉で 1 段足します。
- 「運営者は見ません」のような、あとで崩れる約束は書きません（11/08）。運営者がサーバーを管理していることは今も書いてあるので、そこは変えません。
- 置き場の名前を挙げている所（`adaccounts/`・`waba/`・`waba_state/` など）は、括りのフォルダの中の同じ名前になるので、文はほぼそのままで合います【推】。
- 鍵の説明に、鍵が口座でなく括りに結び付く形があること、取り消しと期限を足します。

### 7.3 Meta への説明

- 審査済みの権限はアプリに付いているので、括りを足しても権限は変わりません（前提 6）。
- 申請の文と録画で「利用者のデータをどこにどう置くか」に触れている所があれば、7.2 と同じ 1 段を合わせます。次の申請は「全部盛りを 1 回で」の決まりなので、直すのは次に出すときに一緒にします。
- **奥さまが自分の Meta の口座（ページ・Instagram）を masaru のアプリにつなぐ形が、今の審査と事業の確認の範囲に入っているかは確かめていません。** Threads の招待の道は今もあります【読】が、ページ・Instagram・広告で持ち主が別の人になる場合の Meta の決まりは、原文を読んでから決めます。ここでは確定したように書きません。

## 9. masaru に決めてほしいこと（結果が大きく割れる 3 つ）

### 問い 1: `main` を `ws/main/` に本当に移すか、今の場所のまま「最初の括り」として扱うか

- **推し: 移す。ただし新しい括りを開いたあと、奥さまが来る前に（段 5）。** 全部の括りが同じ形になり、柵が 1 つの形だけを守ればよくなります。今の場所のままだと、`main` のフォルダの中にほかの括りの `ws/` が入る形になり、「`main` からほかの括りが見えない」は置き場でなくコードで守ることになります（前提 2 と合わない）。
- 代償: 夜に 10〜15 分止める作業が 1 回・R2 の手当て（印と逆向きの台本と通し稽古）・`main` の token が括りの外に残る片寄り。
- **前提が変わったら**: 括りを持つのがずっと masaru だけ（奥さまは来ない・外の人も入れない）なら、移さずに済ませても実害は小さく、仕事は全体の 2 割ほど減り、R2 が丸ごと無くなります。逆に、外の人を早く入れるなら、移すのを段 4 の前（2 つ目の括りを開く前）に上げたほうが、戻すときに巻き込む物が `main` だけで済みます。

### 問い 2: 新しい媒体群を、今の hub と朝の一枚に載せるか

- **推し: 載せない。** hub には `main` の鍵だけを持たせ、新しい括りは管理者の一覧（件数と止まりだけ）で見ます。「互いに共有されないように」の頼みにそのまま合い、「1 レーン 1 鍵」も崩れません。新しい媒体群の未承認や止まりを masaru が毎朝見たいなら、その括りのレーンが自分の朝の一枚を出します。
- 代償: masaru の朝の見る所が 2 つになります。
- **前提が変わったら**: 「見るのは 1 か所がいい」なら、hub に鍵を 2 本持たせることになり、前提 4 の「1 レーン 1 鍵」に hub だけの例外を作ります。hub の置き場に 2 つの括りの数え（原稿の道を含む）が並ぶので、分けたい理由が「読む AI を分けたい」なら崩れ、「人に見せる物を分けたい」だけなら崩れません。

### 問い 3: レーンの ssh をいつ外すか（鍵の道の待ち時間が響いたらどうするか）

- **推し: 並べて走らせ、§5.2 が通ってから外す（段 6）。待ちは先に実測する。** 鍵の道は VM が 10 秒ごとに取りに行く作りなので、1 発目が ssh より遅くなる見込みです。段 3 の初めに、運用のレーンの普段の 1 巡（board → schedule → approve の連なり）で測り、困る数字なら取りに行く刻みを縮めます（Worker の呼び出しの数が増える代償つき）。
- 代償: 段 3〜6 の間、同じレーンに 2 つの道があり、ssh の道は括りを分けません（`main` を全部読める）。新しい括りのレーンには初めから ssh を渡しません。
- **前提が変わったら**: 刻みを縮めても使い物にならない場合は、VM に「鍵 1 本で 1 つの括りにしか入れない近い道」（ssh の鍵に括りを結び付け、打てる命令を THTH だけに絞る形）を足すことになります。仕事が 1 段増え、門が 2 種類になるので、monban に寄せるとき（前提 9）に替える所も 2 つになります。逆に待ちが気にならなければ、段 6 を段 4 と同じ版に上げられます。

推しで進めてよいと見ているので問いにしなかったもの: 口座の名前を全体で一意にする（§2.2）・承認まわりを鍵で通す（§5.2）・お金の動く広告の口は通さない（§5.4）・広場を括りの中だけにする（R8）・開発と運用のレーンは管理者の役（§5.3）。
