# THTH 2.12.0 リリースノート（masaru と、招待されたセッション向け）

2026-09-20 夜。VM の `thth` は 2.12.0、thth.me には承認ページと削除受付の Worker が配布済みです。設計は `docs/設計_3.0_クローズドのサーバ型_2026-09-20.md` §3・§10、運用は `docs/運用_承認relay_2.12.md`, `docs/運用_サーバ書込_2.12.md`, `docs/運用_サーバ退出_2.12.md`, `docs/運用_X読取予算_2.12.md`。

## 一言で

**招待された人が、自分の LLM セッションから投稿を出せるようになりました。ただし承認は人の画面でだけ。** LLM は MCP で下書きを置き、承認を求められますが、digest を渡して承認を完了する口はありません。サーバが thth.me の承認ページに本文と digest を 10 分だけ置き、本人がスマホで開いて**承認 secret**（招待時に渡す 16 文字以上の生成値・パスワードマネージャに保存）を入れて押したときだけ、承認・公開・削除が実行されます。

## 利用者のセッションで使えるもの（`writes: true` の資格情報を持つ MCP）

| 道具 | 何をするか |
|---|---|
| `thth_draft_put` | 本文・publish_at（任意 topic・reply_to）をサーバの queue に下書きとして置く（lint を通す・更新は `draft_id`＋`expected_revision`） |
| `thth_draft_list`／`thth_queue` | 自分の下書きの一覧（revision・verified） |
| `thth_approval_request` | 一段目: 公開される本文と digest を確定し、承認ページの URL を返す。URL は本人に渡す |
| `thth_send_request`／`thth_retract_request` | その場の公開・投稿の削除も同じく承認ページ経由 |
| `thth_request_status` | job の状態（pending／ready／completed／failed／expired／unknown） |

- 承認 URL は応答にだけ出ます。status やログには再掲されません。URL を持つ人は本文を読めますが、承認 secret が無ければ押せません。
- 承認は 600 秒で失効します。承認後にサーバが本文・台帳・資格情報・本人の secret の世代を再確認し、変わっていれば実行しません。
- 結果が不明になった job（送信後に保存が失敗した等）は `unknown` で止まり、自動で再送しません。

## 管理者（masaru）に増えたもの

- `thth admin relay-key init|show --by masaru`: 承認 relay の署名鍵。公開鍵だけを thth.me の secret に置きます。
- `thth admin approver set|revoke|unlock <person> --by masaru`: 承認 secret の発行（tty に 1 度だけ表示）・失効・ロック解除。5 回の連続失敗でロック。
- `thth approval-worker --credentials <設定>`: 承認 job を 2 秒ごとに検査して実行する常駐 process。動いていないと承認後も何も起きません。
- `thth account leave <account> --by masaru`: 退出。停止 → 媒体側の失効（Mastodon・X は API、Threads・Bluesky は本人の設定を案内）→ 所有物の削除 → 記録。部分失敗は停止のまま再試行できます。
- `thth admin budget x --monthly <額> --by masaru` と MCP の `thth_admin_budget_set`: X の読取予算。既定 0（読み取りしない・認可の本人照合も含む）。JPY は換算率の出所付き。推定計上であり請求実費ではありません。
- 読む口は退出の最中だけ `account_leaving` で即座に断ります（待ちません）。

## 変わらないこと

承認の 2 段・digest・`--production`・読む口が SNS 台帳に書かない規律。管理者に書ける道具は予算だけ。承認ページの本文は 10 分の論理保存で、Cloudflare の復旧層までの物理消去は約束しません。

## 2.12.1（2026-09-21 未明・直し 2 件）

- **承認ページで secret を押すと 503 だった**（2.12.0 の配布時に本番で実測）。Cloudflare の workerd は PBKDF2 の反復を 100,000 回までしか受け付けず、600,000 回が `NotSupportedError` になっていた。両側を 100,000 回に揃え、上限内かつ一致することを試験に固定（`3d456fd`）。secret は 32 byte の乱数なので伸長回数は強さを左右しない。thth.me の Worker も再配布済み。本番の承認ページを使い捨ての人で 21 項目実測し全部通過。
- **managed repo の検証が git 自身の短命ファイルと競合して `write_unavailable` になり得た**（CI で再現）。消えた entry は飛ばし、managed repo の git では自動 gc を切る（`b80bd95`）。

### 配布担当の記録（VM 側）

- 2.12.0 が VM に降りた 09-20 20:45 から 09-21 00:30 まで、**全アカウントの timer が `account_stopped` で何もしていなかった**。原因は 2.12.0 の停止 gate が `state/_leave` を辿る途中で `/srv/thth/state` が group 書込可（775）だったのを `unsafe_server_directory` として弾き、それを「停止」と扱ったこと。`chmod 755 /srv/thth/state` で復帰。この間の投稿予定は無く実害無し。道具側の改善（board／doctor に理由を出す・「読めない」と「停止」を分ける）は 2.13 系で扱う。
