# THTH の使い方 — 各プロジェクトのセッションへ（2026-09-09）

THTH（ThreadsThrower）は **Threads へ投稿するための道具**です。nigamilab・asmon 関東・kopicha・サテライトが共有します。作ったのは THTH セッション（統括 Fable）で、置き場は `~/Developer/thth`、実体は VM（`ssh wt` の `/srv/thth`）。

**この文書だけ読めば使えます。**設計書（`docs/設計_THTH_2026-09-08.md`）は作った側の記録なので、読まなくて構いません。

---

## 1. THTH は何をして、何をしないか

**する**: 本文を受け取って Threads に出す。post_id を書き戻す。返信と数（表示回数・いいね・クリック等）を集めて repo に置く。Meta の上限（24 時間で投稿 250・返信 1,000）を超えないように止める。

**しない**: **何を書くかを決めない。** 文体の規約も、頻度も、時刻も、トピックの選び方も、あなたのプロジェクトのものです。THTH は渡された本文を**整形も切り詰めもせず**そのまま出します。

---

## 2. いま使える道（同席）

**masaru がその場にいて「これを出して」と言ったとき、すぐ出せます。**承認はその会話の中で済んでいるので、ファイルも承認欄も要りません。

```bash
# 本文をファイルに書いてから（引数で渡さない。シェルの履歴と引用の事故を避けるため）
scp 本文.txt wt:/tmp/post.txt
ssh wt 'PATH="$HOME/.local/bin:$PATH"; thth send <あなたのアカウント> --text-file /tmp/post.txt'
```

- **`--production` を付けるまで出ません。** 付けずに実行すると「投げるはずの本文」を表示して終わります。**必ず一度これで masaru に見せてから**、`--production` を足して本当に出してください。
- トピックを付けるなら `--topic 苦味`（1 投稿に 1 つ・1〜50 字・`.` と `&` は不可。先頭の `#` は機械が落とします）。
- 返信するなら `--reply-to <相手の post_id>`。
- 出ると `post_id` が返ります。

**守ってほしいこと**: **masaru が読んだ本文と、出す本文を同じにしてください。**「だいたいこんな感じで」で送らない。表示 → masaru が読む → 出す、の順を崩さない。THTH 側は渡されたものをそのまま出すので、ここだけは人の側で守るしかありません。

### 能力の確認

```bash
ssh wt 'PATH="$HOME/.local/bin:$PATH"; thth doctor <あなたのアカウント>'
```

読み取りだけを試して、そのトークンで何ができるかを出します。投稿・返信・削除は呼びません。

## 4. 留守中に出す道（timer が立ってから）

投稿を 1 ファイル 1 本で `docs/sns/queue/<日付>-<slug>.md` に書きます。**いまから書き溜めて構いません。**

```markdown
---
thth: 1
account: nigamilab-threads
publish_at: 2026-09-10T08:00:00+09:00
status: draft
topic: 苦味
reply_to:
post_id:
posted_at:
---
# 経緯や下書きのメモ（THTH は読みません）

## threads

ここが実際に投稿される本文です。500 字まで。
https://example.com/
```

| 欄 | 誰が書くか | 意味 |
|---|---|---|
| `thth: 1` | 固定 | 書式の版 |
| `account` | あなた | 宛先。§6 の表のとおり |
| `publish_at` | あなた | **`+09:00` 必須。** この時刻以降の最初の実行で出る（刻みは 10 分） |
| `status` | **masaru だけ** | `draft` → `approved` で「留守中に出てよい」。**あなたも THTH も書けません** |
| `topic` | あなた | 省略可 |
| `reply_to` | あなた | 返信にするなら相手の post_id |
| `post_id`・`posted_at` | **THTH** | 出たあとに書き戻す。付いたファイルは二度と出ない |

- 本文は **`## threads` の節だけ**。その上には何を書いても読みません。
- 検査は先に走らせられます: `ssh wt '... thth lint <ファイル>'`。文字数・書式・トピックの不備を名指しで返します。**450 字を超えると警告**が出ます（絵文字の数え方が公式と厳密に一致する保証がないので、境界に座らないため）。
- 長すぎても**切り詰めません**。落として理由を返します。
- timer の unit（`.timer`）は手で書かず、`thth systemd <account>` が台帳（`tick_minutes`）から生成します。

## 5. 自分たちで決めてよいこと

台帳（`~/Developer/thth/accounts/<アカウント>.json`）の次の 5 つは**あなたのプロジェクトの判断**です。いま入っている値は統括の当て推量なので、合わなければ言ってください。

| 設定 | いまの値 | 意味 |
|---|---|---|
| `min_interval_hours` | 6 | 前の投稿からこれだけ空ける。`0` で制限なし |
| `quiet_hours` | 22:00〜07:00 | この時間帯は出さない。`null` で制限なし |
| `max_per_run` | 1 | 1 回の実行で出す本数。**`min_interval_hours` が 0 より大きければ、増やしても 1 本しか出ません**（間隔が先に効くため） |
| `tick_minutes` | 10 | timer の刻み。`publish_at` の遅れの上限になる。変えたら `thth systemd <account>` で unit を作り直す |
| `hashtags` | 研究所のみ `false` | 本文中の `#` 語を許すか。**トピックとは別物** |

基盤が強制するのは **Meta の上限だけ**です。頻度も時刻も本数も、あなたたちの声の作り方です。

## 7. 困ったとき

- **「inflight が残っています」で止まる**: 前回「出たか出ていないか分からない」失敗があったということです。**勝手に消さないでください。** Threads の画面で出たかどうかを確かめて、統括（THTH セッション）に伝えてください。二重投稿を防ぐための止まり方です。
- **「既に実行中です」**: 別の実行と重なっています。少し待って再実行してください。
- **本文が長すぎる／トピックが弾かれた**: 理由が名指しで出ます。直して出し直してください。
- **それ以外**: `~/Developer/thth` の THTH セッションへ。設計と実装の責任はそちらにあります。

## 8. 頼みたいこと

1. **使ってみて、書きにくいところを言ってください。**書式はまだ 1 つの repo にも配っていないので、いま変える分には安いです。あとから変えると全 repo を直すことになります。
2. **返信の扱いを決めておいてください。**THTH は返信を出せますが、返す文は毎回 masaru が読みます。中受も苦味も不安の強い領域なので、乗らない話題（効能・合否の見通し・優劣）への返し方を先に決めておくと、その場で困りません。
3. **`docs/sns/queue/` を作っておいてください。**timer が立った日から使えます。
