## 1. 台帳を作る

```sh
thth account add <name> --media mastodon --handle <handle> --instance https://<instance> \
  --project <person> --repo-dir '$THTH_ROOT/repos/_server/<name>' --by masaru
```

`--repo-dir` を省くと `repos/<project>` になります。
それは managed repo ではありません。招待の account では必ず指定します。

作ったら台帳の 2 行を書き換えます。
既定の `~/.config/thth/…` は `THTH_ROOT` の外なので、隔離検査に通りません。

- `env`: `$THTH_ROOT/secrets/<name>.env`
- `token`: `$THTH_ROOT/secrets/<name>.token`

`production: true` は認可のあとに入れます。
予約公開まで進めるなら `scheduled: true` にして、`thth systemd <name>` が出す timer を置きます。

確認は `thth doctor <name> --json` です。

## 2. 認可する

```sh
thth auth <name> --by masaru
```

人向けの URL が 1 行だけ出ます。
本人に渡します。
本人がその媒体に本人のアカウントでログインした状態で開き、承認を押します。
トークンは媒体からサーバへ直接入ります。誰も値を見ません。

ログイン先が違うと `mastodon_identity_mismatch` で断り、何も保存しません。
09-23 に実際に起きて、そのとおり止まりました。

このコマンドは tty を要ります。
本人がスマホしか持っていない場合も、打つのは masaru です。
出た URL をそのまま本人へ送ってください。本人の機械には何も入れません。
URL は運用ログに残しません。

確認は `thth doctor <name> --json` の `auth_via` と `auth_observed_at`、それに `thth admin log --json` です。

## 3. 口座の secret を渡す（招待なら完了ページが出す・手で渡すのは招待を使わない口座だけ）

先に署名鍵が要ります。
`thth admin relay-key init --by masaru` を 1 度だけ実行し、出た公開鍵を Worker の `RELAY_PUBLIC_KEY` に設定します（3.12.0 までの名前は `APPROVAL_PUBLIC_KEY`。Worker は `RELAY_PUBLIC_KEY` が無ければ旧名を読みます）。

```sh
thth admin secret set <person> --by masaru
```

（3.12.0 までの名前は `thth admin approver set`。旧名も同じ口です。）

43 文字の secret が tty に 1 度だけ出ます。
stdout にも引数にもログにも出ません。
ssh 越しなら `ssh -t` で入ってください。tty が無ければ生成前に断ります。

本人はパスワードマネージャに入れます。
ユーザ名を `<person>`、Web サイトを `thth.me` にすると `https://thth.me/activity` で自動入力されます。
LLM には渡しません。

- もう一度 `set` すると新しい世代になり、前の secret は無効です。
- 5 回連続の失敗で本人がロックされます。`thth admin approver unlock <person> --by masaru` で解除します。
- 失効は `thth admin approver revoke <person> --by masaru` です。

## 4. 資格情報を置く

`/srv/thth/private/report-credentials.json` を mode 600 で作ります。
親ディレクトリは 0700 です。

```json
{
  "schema_version": 1,
  "root": "/srv/thth",
  "credentials": [{
    "sha256": "<ランダムな bearer の SHA-256・lowercase hex 64 文字>",
    "expires_at": "2026-12-31T00:00:00+09:00",
    "revoked": false,
    "accounts": {"<name>": "<person>"},
    "writes": true,
    "actor": "<person>"
  }]
}
```

- `sha256` は bearer の digest です。bearer の実値はこのファイルに書きません。
- `accounts` は account 名から project への対応です。台帳の `project` と一致させます。
- `writes: true` と `actor` が無ければ読むだけです。`actor` は `approver set` の `<person>` と同じ綴りにします。
- admin scope に `writes` は付きません。

bearer の実値はサーバの mode 600 のファイルに置きます。
読むのは次の起動口だけです。

## 5. 起動口を置く

`~/.local/bin/thth-mcp-invitee` を作り、本人だけが実行できる権限にします。

```sh
#!/bin/sh
umask 077
export THTH_ROOT=/srv/thth
export THTH_REPORT_CREDENTIALS=/srv/thth/private/report-credentials.json
export THTH_REPORT_TOKEN="$(cat /srv/thth/private/report-token)"
export PYTHONPATH=/srv/thth/app
exec python3 /srv/thth/app/mcp/server.py
```

`umask 077` は省けません。
省くと git が作るファイルが群書込可になり、thth 自身が `managed_git_store_unsafe_mode` でその repo を断ります。

`THTH_ROOT` が 0700 でなければ `private_root_required` で止まります。

本人の Claude Code には stdio の MCP を 1 本だけ登録してもらいます。

```
ssh <server> /home/wt/.local/bin/thth-mcp-invitee
```

### ファイルと mode

| もの | 置き場 | mode |
|---|---|---|
| サーバ root | `/srv/thth` | 0700 |
| 私有ディレクトリ | `/srv/thth/private` | 0700 |
| 資格情報 | `/srv/thth/private/report-credentials.json` | 0600 |
| bearer の実値 | `/srv/thth/private/report-token` | 0600 |
| account の env / token | `$THTH_ROOT/secrets/<name>.env`, `$THTH_ROOT/secrets/<name>.token` | 0600 |
| 署名秘密鍵 | `~/.config/thth/apps/relay-signer.key` | 0600（親 `apps` は 0700） |

## 6. 常駐（worker）を置く

```sh
thth systemd --worker --credentials /srv/thth/private/report-credentials.json
```

unit の本文が標準出力に出るだけです。配置も enable もしません。
内容を読んでから `thth-approval-worker.service` として置き、enable します。
`UMask=0077` が入っていることを確かめます。

常駐が動いていないと、招待の完了・`/activity` の要約と操作・鍵の発行は進みません。

## 7. 通しで確かめる

1. 本人のセッションから `thth_draft_put` で下書きを置く。
2. `thth_send_request` で出す（その場で出て ID とリンクが返る。安全装置に掛かれば符丁で断られる）。
3. `thth_account_status` で結果を読む。
4. masaru 側は `thth board` と `thth admin log --json` で照合する。
予約公開は account の timer が 10 分刻みで拾い、`quiet_hours` と `min_interval_hours` に従います。

## 9. 退出

```sh
thth account leave <name> --by masaru
```

順番は、停止、媒体側の失効、所有データの削除、記録です。

- Mastodon と X は道具が媒体へ失効を投げます。確認できなければ停止のまま残し、同じコマンドの再実行を求めます。
- Threads の接続解除と Bluesky の App Password 削除は本人の設定です。道具がそう案内します。
- 同じ本人の別 account は止まりません。
- Mastodon と X で、同じ instance の同じ利用者の別 account があっても、token の値が別なら退出は最後まで通ります。失効を投げるのは退出する account の token だけで、別 account の token と台帳には触りません（3.1.1）。token の値やファイルが同じときは共有として失効を断ります（`shared_credential_revoke_refused`）。
- 削除できるのは対象 account の専用 token・env・台帳・state と `repos/_server/<name>` です。共有物、全体の app client、署名鍵、変更ログは残します。

確認は `thth admin account <name>` と `thth admin log --account <name>` です。

## 10. 招待リンクで招く（3.10.0・Threads）

1〜3 の手作業（`account add`・`auth`・`approver set`）を、本人が自分で進める 1 本の道にしたものです。
Meta の審査員もこの道で入ります。
設計は `docs/設計_3.10.0_招待リンク_2026-09-25.md` です。

使えるのは Threads だけです。
Bluesky と Mastodon は従前どおり 1〜3 で用意します（`--media` にほかの媒体を渡すと `invite_media_unsupported` で断ります）。

### 前提

- Worker が 3.10.0 に上がっていること（`INVITE_OBJECT` と migration `v5-invite`・`/invite/*`）。上がっていなければ `create` が `invite_registration_rejected` で止まります。
- 署名鍵（§3）と常駐（worker・§6）。招待は常駐が拾います。常駐が止まっていると、本人のページは 2 分で「運営者に連絡してください」に変わります。
- Meta アプリに `https://thth.me/callback/` が登録されていること。招待の認可はこの戻り先を使います。

### 手順

1. `ssh -t` で入り、招待を作ります。

   ```sh
   thth admin invite create --media threads --project <project> --label <控え> --expires 30d [--production] --by masaru
   ```

   招待 URL（`https://thth.me/invite/…`）が tty に 1 度だけ出ます。stdout・ログ・VM の記録には出ません（VM には hash だけが残ります）。
   `--production` を付けた招待で作る口座は、頼まれたときに本当に投稿します。付けなければ試し撃ちです。審査員の招待には付けます。
   期限は 1〜90 日です（既定 30 日）。
2. URL を本人に渡します。公開の場や LLM の会話には貼りません。
3. 本人が開いて押し、Threads で認可すると、口座 `inv-<project>-<6 桁>` ができます。管理者の通知（`account_added`）で分かります。`thth admin invite list` の状態が `used` になります。
4. 本人は完了のページで口座の secret を 1 度だけ見ます。VM も masaru も secret を見ません。見届けたら `approver_set`（via http）が変更ログに入り、一覧の `approver_set` が true になります。
5. 常駐が §4 の資格情報のファイル（`thth worker --credentials` のファイル）に、その口座だけの 1 件を自動で足します。`accounts` は `{"inv-<project>-<6 桁>": "<project>"}`・`scope: user`・`writes: true`・`actor` は**口座名と同じ綴り**（`/activity` の人は口座名で登録されます）・期限は 365 日です。変更ログは `credential_added`（via http）。bearer は乱数で作って hash だけを残し、値は誰にも出しません。
6. 本人は `https://thth.me/activity` に口座名と secret で入り、「LLM の鍵を発行する」で自分の LLM に登録する 1 行を受け取ります（3.12.0）。bearer は 1 度だけ本人の画面に出て、VM には hash だけが残ります（`credential_rotated`・via http）。運営者は bearer を扱いません。
7. あとは本人が自分の LLM から使います。公開・削除・予約は LLM（か本人の CLI）の依頼でそのまま行われます。承認ページはありません（3.13.0）。守りは安全装置（最短間隔 6 時間・1 日 8 件・削除 1 日 5 件・10 分に 3 件で停止・夜間）で、数値は本人が変えられます（LLM の `thth_settings` は締める向きだけ・緩めるのは `/activity`）。台帳に古い `approval` の項目が残っていても読みません。
   運営者の口 `thth admin draft put` は残ります（本人の口座に下書きを置くだけ・出すのは本人）。
8. 退出（§9 の `thth account leave`）の最後に、その 1 件は消えます（`credential_removed`）。

### 審査の間の手順（Meta）

1. `--production` を付けた招待を作り、URL を審査員に渡す。
2. 審査員が認可して secret を受け取り、`https://thth.me/activity` で LLM の鍵を発行して自分の LLM（Claude Code など）に登録する。
3. 審査員は自分の LLM に頼んで投稿・返信・削除をする。運営者は手を出さない（`thth admin log --json` と `thth board` で見守るだけ）。
4. 安全装置と止める操作は `https://thth.me/activity` で審査員が確かめられる。

### 取り消す・確かめる

```sh
thth admin invite list [--json]
thth admin invite revoke <id> --by masaru
```

- 一覧に code は出ません（hash も出しません）。
- 取り消しは Worker が先です。取り消した招待のページは 410 です。認可の途中でも、その code は交換しません。
- 使われた招待は取り消せません（`invite_already_used`）。口座を止めるときは §9 の `thth account leave` です。招待から作った口座も、退出・報告の口・広場の規律は同じです。
- 招待の project は持ち主の組に入れません。組に入っている project では作らず（`invite_project_in_owner_group`）、口座を用意する直前にもう一度見ます。

### 詰まったとき

| 見えるもの | 意味 | すること |
|---|---|---|
| 本人のページが「準備が進んでいません」 | 常駐が 2 分拾っていない | 常駐を確かめる（`systemctl status thth-approval-worker`）。戻れば本人のページは自動で進みます。遅れて拾った招待は、管理者へ運用通知が 1 回届きます（`invite_stalled`） |
| 本人のページに「既に THTH にあります」 | 同じ Threads 口座が台帳にある | 既存の口座の認可のやり直しは §2 の `thth auth` です。招待は別の口座でもう一度押せます |
| 本人のページに「今は口座を用意できません」 | 預かり所・app.env・持ち主の組のどれかで止まった | `thth doctor` と `thth admin plaza owner list` を見る |
| 本人が secret を失くした | 表示は 1 度だけ | §3 の `thth admin approver set <口座名> --by masaru` で再発行し、tty の secret を本人に渡す |
| `invite_registration_unknown` | Worker に届いたか分からない | `revoke` してから作り直す |
| 一覧の口座に資格情報が付かない | 資格情報のファイルが壊れている・無い・100 件ある | ファイルを直す。常駐が次の巡で足します（壊れたファイルには足さず、作りもしません） |
