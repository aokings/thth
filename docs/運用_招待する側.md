## 1. 台帳を作る

```sh
thth account add <name> --media mastodon --handle <handle> --instance https://<instance> \
  --project <person> --repo-dir '$THTH_ROOT/repos/_server/<name>' --by masaru
```

`--repo-dir` を省くと `repos/<project>` になります。
それは managed repo ではありません。招待の account では必ず指定します。

作ったら台帳の 2 行を書き換えます。
既定の `~/.config/thth/…` は `THTH_ROOT` の外なので、隔離検査に通りません。

- `env`: `$THTH_ROOT/secrets/<name>.env`
- `token`: `$THTH_ROOT/secrets/<name>.token`

`production: true` は認可のあとに入れます。
予約公開まで進めるなら `scheduled: true` にして、`thth systemd <name>` が出す timer を置きます。

確認は `thth doctor <name> --json` です。

## 2. 認可する

```sh
thth auth <name> --by masaru
```

人向けの URL が 1 行だけ出ます。
本人に渡します。
本人がその媒体に本人のアカウントでログインした状態で開き、承認を押します。
トークンは媒体からサーバへ直接入ります。誰も値を見ません。

ログイン先が違うと `mastodon_identity_mismatch` で断り、何も保存しません。
09-23 に実際に起きて、そのとおり止まりました。

このコマンドは tty を要ります。
本人がスマホしか持っていない場合も、打つのは masaru です。
出た URL をそのまま本人へ送ってください。本人の機械には何も入れません。
URL は運用ログに残しません。

確認は `thth doctor <name> --json` の `auth_via` と `auth_observed_at`、それに `thth admin log --json` です。

## 3. 承認 secret を渡す

先に署名鍵が要ります。
`thth admin relay-key init --by masaru` を 1 度だけ実行し、出た公開鍵を Worker の `APPROVAL_PUBLIC_KEY` に設定します。

```sh
thth admin approver set <person> --by masaru
```

43 文字の secret が tty に 1 度だけ出ます。
stdout にも引数にもログにも出ません。
ssh 越しなら `ssh -t` で入ってください。tty が無ければ生成前に断ります。

本人はパスワードマネージャに入れます。
ユーザ名を `<person>`、Web サイトを `thth.me` にすると `https://thth.me/approve/...` で自動入力されます。
LLM には渡しません。

- もう一度 `set` すると新しい世代になり、前の承認ページは無効です。
- 5 回連続の失敗で本人がロックされます。`thth admin approver unlock <person> --by masaru` で解除します。
- 失効は `thth admin approver revoke <person> --by masaru` です。

## 4. 資格情報を置く

`/srv/thth/private/report-credentials.json` を mode 600 で作ります。
親ディレクトリは 0700 です。

```json
{
  "schema_version": 1,
  "root": "/srv/thth",
  "credentials": [{
    "sha256": "<ランダムな bearer の SHA-256・lowercase hex 64 文字>",
    "expires_at": "2026-12-31T00:00:00+09:00",
    "revoked": false,
    "accounts": {"<name>": "<person>"},
    "writes": true,
    "actor": "<person>"
  }]
}
```

- `sha256` は bearer の digest です。bearer の実値はこのファイルに書きません。
- `accounts` は account 名から project への対応です。台帳の `project` と一致させます。
- `writes: true` と `actor` が無ければ読むだけです。`actor` は `approver set` の `<person>` と同じ綴りにします。
- admin scope に `writes` は付きません。

bearer の実値はサーバの mode 600 のファイルに置きます。
読むのは次の起動口だけです。

## 5. 起動口を置く

`~/.local/bin/thth-mcp-invitee` を作り、本人だけが実行できる権限にします。

```sh
#!/bin/sh
umask 077
export THTH_ROOT=/srv/thth
export THTH_REPORT_CREDENTIALS=/srv/thth/private/report-credentials.json
export THTH_REPORT_TOKEN="$(cat /srv/thth/private/report-token)"
export PYTHONPATH=/srv/thth/app
exec python3 /srv/thth/app/mcp/server.py
```

`umask 077` は省けません。
省くと git が作るファイルが群書込可になり、thth 自身が `managed_git_store_unsafe_mode` でその repo を断ります。

`THTH_ROOT` が 0700 でなければ `private_root_required` で止まります。

本人の Claude Code には stdio の MCP を 1 本だけ登録してもらいます。

```
ssh <server> /home/wt/.local/bin/thth-mcp-invitee
```

### ファイルと mode

| もの | 置き場 | mode |
|---|---|---|
| サーバ root | `/srv/thth` | 0700 |
| 私有ディレクトリ | `/srv/thth/private` | 0700 |
| 資格情報 | `/srv/thth/private/report-credentials.json` | 0600 |
| bearer の実値 | `/srv/thth/private/report-token` | 0600 |
| account の env / token | `$THTH_ROOT/secrets/<name>.env`, `$THTH_ROOT/secrets/<name>.token` | 0600 |
| 署名秘密鍵 | `~/.config/thth/apps/relay-signer.key` | 0600（親 `apps` は 0700） |

## 6. 承認 worker を常駐させる

```sh
thth systemd --approval-worker --credentials /srv/thth/private/report-credentials.json
```

unit の本文が標準出力に出るだけです。配置も enable もしません。
内容を読んでから `thth-approval-worker.service` として置き、enable します。
`UMask=0077` が入っていることを確かめます。

worker を起動しないと、本人が承認を押しても操作は実行されません。

## 7. 通しで確かめる

1. 本人のセッションから `thth_draft_put` で下書きを置く。
2. `thth_approval_request` で承認 URL を出す。
3. 本人が承認ページで押す。
4. `thth_request_status` で結果を読む。
5. masaru 側は `thth board` と `thth admin log --json` で照合する。

`thth_send_request` は承認の直後に公開します。
予約公開は account の timer が 10 分刻みで拾い、`quiet_hours` と `min_interval_hours` に従います。

## 9. 退出

```sh
thth account leave <name> --by masaru
```

順番は、停止、媒体側の失効、所有データの削除、記録です。

- Mastodon と X は道具が媒体へ失効を投げます。確認できなければ停止のまま残し、同じコマンドの再実行を求めます。
- Threads の接続解除と Bluesky の App Password 削除は本人の設定です。道具がそう案内します。
- 同じ本人の別 account は止まりません。
- Mastodon と X で、同じ instance の同じ利用者の別 account があっても、token の値が別なら退出は最後まで通ります。失効を投げるのは退出する account の token だけで、別 account の token と台帳には触りません（3.1.1）。token の値やファイルが同じときは共有として失効を断ります（`shared_credential_revoke_refused`）。
- 削除できるのは対象 account の専用 token・env・台帳・state と `repos/_server/<name>` です。共有物、全体の app client、署名鍵、変更ログは残します。

確認は `thth admin account <name>` と `thth admin log --account <name>` です。
