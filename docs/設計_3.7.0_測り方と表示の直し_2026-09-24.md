# 設計 3.7.0: 測り方と表示の直し（全メディアの報告 13 件のうち 9 件）

2026-09-24 朝。masaru が 3.6.0 を全メディア（kopicha・asmon-kanto・nigamilab）に伝え、報告の口に 13 件が入った。本書はそのうち測り方・表示・検索の 9 件。知見共有の 4 件は `docs/設計_3.8.0_知見共有を回す_2026-09-24.md`。

## A. 目的（goal）の測り方

### A1. click を投稿単位で（r20260924-5820d911 §1・r20260924-32ae3a65・r20260924-b77b1f09 §1）
- Threads の account 日次 `clicks_by_url`（リンク先ごとの日次クリック）を使う。**あるリンク先を、投稿の前後 72 時間で 1 本の投稿しか使っていないとき**、そのリンク先の、投稿から 72 時間のクリックをその投稿のものとして出す（`basis: unique_url_72h`）。日次の粒度なので、投稿日から 3 暦日（投稿日を含む）を足す（`window: post_day_plus_2`）と明記する。
- 条件を満たさない（同じリンク先を 72h に 2 本以上・リンク先が無い・プロフィールのリンクと同じ）ときは従前どおり `cannot_say`（理由を分ける: `url_shared_72h`・`no_link`・`profile_link`）。
- リンク先の照合は URL の正規化（スキーム・末尾の `/`・`utm_*` を除く・大文字小文字はホストだけ）で。
- 出す場所: `--by goal` の click、`observe` の前回の観測から、地図の自分の層。クリック率（クリック/24h views）も分母つきで。
- lint の知らせ（断らない）: 同じ account で、同じリンク先を前後 72h に使う click の原稿が 2 本以上あれば `url_shared_72h`（r20260924-b77b1f09 の「同じ日の click 2 本」は、この条件で置き換える——同じ日でもリンク先が違えば測れる）。
- **リンクに札を付けて本文を書き換える案（`link_tag: auto`・utm）は入れない**。本文が承認のあとに変わる形になり、承認の指紋の規律と衝突する。リンク先を投稿ごとに分ければ同じことが測れる。

### A2. follow の「比べる日が無い」（r20260924-5820d911 §2）
- follow の投稿が出た日／出ていない日の片方が 0 日（または min-n 未満）なら、`cannot_say: no_comparison_days` と、事実の 1 行「follow の投稿が毎日出ていて、出ていない日がありません（直近 n 日）」。推奨はしない（「作るとよい」とは言わない）。

### A3. 週の表（r20260924-5820d911 §3）
- `thth analytics-report <account> --weekly-goals [--weeks 6]`: 週ごとに目的ごとの本数と followers の増分（週初と週末の差・欠測は null）。観察の表で、因果とは言わない。

## B. 表示の直し

### B1. account の「投稿できません」から、run が自分で直すものを分ける（r20260924-e9ad6256）
- `thth account` の診断を 2 段に: 「run を止めるもの」（inflight・token・held・停止・quiet 以外の門）と「run が自分で直すもの」（repo が upstream より遅れているだけで ahead 0 → 「次の run が取り込みます（遅れ n commit）」）。後者は「投稿できません」に入れない。`board` と食い違わないことを試験で固定。

### B2. `collection_stale_hours` の数え始め（r20260924-59ae563e）
- observe の返信の段に `collection_stale_basis`（何の時刻から数えたか: 最後に返信の取得を試みた時刻か、最後に返信が 1 件以上取れた時刻か）と `since`（その時刻）を添える。text では「返信の取得: 最後に試したのは n 時間前（取れたのは m 時間前）」。定義を実装で確かめてから書く。

### B3. 承認の確定待ち（r20260924-78b4a598）
- `thth approve` の 1 段目（digest を出すだけ）で、`state/<account>/approve_pending.json` に `{file, digest, at}` を残す（本文は残さない・確定・取り消し・本文の変更で消える）。
- queue・board・observe で not_approved を `awaiting_confirm`（1 段目が済み確定が残る）と `not_requested` に分ける。「確定待ち n 本（最短の publish_at）」。
- 確定待ちの原稿の publish_at まで 3 時間を切ったら、observe の next_steps（`kind: confirm_due`・確定の命令の 1 行）と運用通知（増えたときだけ）。
- 1 段目の出力に「確定するまで出ません」を添える（既にあれば位置を目立たせる）。

### B4. lint が手元の Mac のパスを受ける（r20260924-f8944208）
- `thth lint <path>` が、台帳の `repo_dir` に対応しない絶対パスを受けたとき、repo の中の相対パス（`docs/sns/queue/<file>`）に切り出せれば VM のパスに読み替える。読み替えたことを 1 行出し、VM 側の clone が upstream より遅れていれば「VM 側は古い（thth pull で取り込む）」と言う。`preview`・`approve` も同じ読み替え（approve は digest が VM の本文で出るので、読み替えを明示）。

## C. 検索（where）

### C1. `--also`（r20260924-4955cedd）
- `thth where <account> <語> --also <語> [--also <語>…]`: 同じ検索結果のうち、本文にどれかの語を含むものだけを残す。**追加の検索はしない**。「25 件中 also に合ったもの 4 件」を出す。observe の監視語には使わない（CLI の下調べ用）。

### C2. 0 件のときの言い方（r20260924-17e5d890）
- 0 件のときに `zero_or_filtered`：「0 件でした。本当に無いか、媒体が語を受け付けなかったかは区別できません（Threads は、センシティブと判断した語の検索に空の配列を返すと文書にあります）」。短い語・形容詞の扱いは一次資料に記載が無い（未確認）と書く。

### C3. `--aggregate`（r20260924-30ead3ee）
- `thth where <account> <語…> --aggregate [--lexicon <file>]`: 語ごとの件数・期間・1 日あたり・問いの形（「？」で終わる等の静的な判定）の件数、lexicon の分類ごとの件数を返す。本文・username・author_key・post_id は返さない。検索語は数える前に本文から外す。**表示だけで、道具は保存しない**。
- **集計を毎日保存するのは、観測の地図の世間の層と同じ Platform Data の保持にあたる**（照合 `docs/照合_観測の地図_集計の定点観測_2026-09-23.md`）。`--aggregate` の出力に「保存するなら Meta への説明の申請のあとで（世間の層と同じ条件）」の 1 行を固定で添える。広場の measure に observed として貼る口は作らない（世間の層を project の外に出さない条件 §6-7）。

## D. 試験と単変異

- `--aggregate` は表示だけ。保存と広場への貼り付けは、世間の層と同じ条件（Meta への申請）まで入れない。
