## 2. 設計条件 3 つをどう満たしたか

**条件 1（語彙はコードでなくデータ）**: 修正理由の語彙は `topic_models` に**定数として
置いていない。** `build_vocabulary()` は**語彙の入れ物の形**だけを決める。中身
（`unsupported_claim` ほか）は `vocabularies` の記録として保存する。差し替えは記録
1 件（`supersedes` で前の版を指す）。`proposed → shadow → accepted → retired` は
項目ごとの `state` としてそのまま乗っている。

**条件 2（`other` に自由文・件数と内訳）**: `reason_id` が `other` の指摘は `note` が
空だと保存できない。`tally_reasons()` が理由ごとの件数と `other` の内訳（説明の全文）を
返す。**`other` が増えたら語彙を疑う**——`forms` のときは 3 本とも同じ型に落ちたのに
道具が何も言わなかった。

**条件 3（主体違いの判定を並べる）**: `judged_by` が ID の計算に入る。masaru と担当
セッションが同じ段に違う理由を付ければ**別の ID になり、両方残る**（上書きしない）。
一致率はこの 2 件を突き合わせて測る。

## 3. 意図的にそうしたところ

- **`fixed` は「直した」であって「解決済み」ではない。** `DISPOSITION` に解決済みを
  表す値を置いていない（Codex §6.2「修正しただけで解消済みにしない」）。再検査は
  別の記録で `recheck_of` が前の記録を指す。`fixed` には `revised_draft_sha256` が要る。
- **原稿はパスでなく `draft_sha256` で指す**（§6.1）。本文が変われば
  `review_applies_to()` が False——**新しい原稿への「確認済み」を引き継がない**（A03）。
- **未知の語彙版は「対応外」。** `review_support()` は既知の分類へ推測変換せず、
  0 件・問題なしにも変換しない（A05）。`retired` の理由を使った過去の記録は
  **読める**（印だけ付く・§8／A08）。
- **判定主体と検査方式に同じ語彙を使う**（`JUDGE_KIND`）。§7 の
  機械検査／意味評価／人の確認は同じ区別なので、2 か所で別々に育てない。
- **`accepted` にするには含む例と含まない例が要る**（`proposed` のうちは空でよい）。
- `other` が使える状態で無い語彙は作れない——**分類できなかったという事実を記録
  できない語彙**は、語彙の不足を道具が言えなくする。

## 5. CLI（2 つめの commit）

4 つ。すべて `thth/topic_cli.py` の中で完結する（`cli.py` には触っていない）。

| コマンド | 何を |
|---|---|
| `thth topics record-vocabulary --input <json> --by <名前>` | 修正理由の語彙を 1 版登録 |
| `thth topics vocabulary [<vocabulary_id>]` | 登録済みの語彙を読む |
| `thth topics record-review --json-stdin --by <名前> [--draft <原稿>] [--revised-draft <原稿>]` | 検収を 1 件残す |
| `thth topics review <review_id か account 名> [--draft <原稿>]` | 読む |

- `--draft` は**原稿の中身から fingerprint を計算する**（パスは保存しない）。JSON 側の
  `draft_sha256` と食い違えば `draft_mismatch` で断る——**どちらが正しいかは道具には
  決められない。**
- 読むときの出力は §7 の区分（`machine_checks` / `semantic_evaluations` /
  `human_confirmations` / `out_of_scope` / `next_actions`）。`--draft` を渡すと
  `freshness.applies_to_draft` が出る（A03）。
- `other` が 1 件でもあれば `warnings` に出る（設計条件 2）。account 単位で読むと
  `reasons.other.notes` に**説明がそのまま**並ぶ。
- 語彙が手元に無ければ**保存しない**（`unknown_vocabulary`）。手近な版で代用しない。

CLI のテストは `tests/test_review_cli.py` 18 件。**実プロセス**（`bin/thth`）で回す。
出口条件の「実際の原稿修正 1 往復」は `test_原稿修正の1往復を記録できる` が
指摘 → 直す → 再検査までを通す。誤実装 4 つ（語彙が無ければ最新版で代用／食い違う
fingerprint を黙って上書き／`other` が増えても黙っている／原稿が変わっても確認済みの
まま）を入れて、4 つとも落ちることを確認した。**うち 1 つは最初素通りしたので、
棚に別の語彙がある状態で試すようにテストのほうを直した。**
