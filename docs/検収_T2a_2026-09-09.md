## 2. 実装した口

- `thth auth <account> [--redirect-uri URL] [--code CODE]`
  1. `~/.config/thth/app.env`（`THTH_APP_ENV_PATH` で隔離可能）から `THREADS_APP_ID`・`THREADS_APP_SECRET` を読む。無ければ exit 2。パーミッションが 600 でなければ警告して直す。
  2. `accounts/<account>.json` の `redirect_uri`（無ければ exit 2）と `scopes`（無ければ `thth/scopes.py` の既定 11 個）で認可 URL を組み立てて表示する（`https://threads.net/oauth/authorize`。ホストは `THTH_THREADS_AUTH_BASE_URL` で差し替え可能）。
  3. `--code` 省略時は標準入力から 1 行読む。`extract_code()` が `#_` 付き・URL 全体・素の code のどの貼り方でも通す。
  4. 短期トークン（POST `/oauth/access_token`）→ 長期トークン（GET `/access_token?grant_type=th_exchange_token…`）→ `me`（GET `/v1.0/me?fields=id,username`）の順に叩く（ホストは既存の `THTH_THREADS_BASE_URL` を共有）。途中で失敗したら exit 1・`.token` は作らない。
  5. 成功したら `user_id`・`username` だけ標準出力に出し、`~/.config/thth/<account>.token` に `{"access_token","obtained_at","expires_in","user_id","username","scopes"}` を 600・原子的（一時ファイル＋`os.replace`）に書く。`accounts/<account>.json` の `user_id` は自動で書き換えない（設計どおり、masaru が手で写す）。

- `thth refresh <account> [--force] [--check]`
  1. token が無ければ exit 2。
  2. 24 時間未満は `--force` があっても常に拒否（exit 0・「まだ更新できません」）。Meta の公式条件（設計 §2.2）としてハード扱いにした。
  3. 24 時間以上・50 日以内は `--force` が無ければ何もせず exit 0。`--force` なら 50 日未満でも更新する。
  4. 50 日超（または `--force`）なら GET `/refresh_access_token?grant_type=th_refresh_token…` を叩き、成功したら `.token` を書き換える（`obtained_at` を更新）。失敗（4xx 等）は exit 1・`.token` は書き換えない。
  5. `--check` は上記の判定はせず、`{"account","obtained_at","age_days","remaining_days","needs_refresh","can_refresh"}` を JSON で 1 行返すだけ（更新しない・board が使う口）。

## 5. 設計と食い違った点・実装で埋めた空白

1. **`redirect_uri` の置き場**: 発注書は `thth auth` の手順しか書いておらず、
   redirect_uri をどこに持つかは明記が無かった。`accounts/<account>.json` に
   任意項目 `redirect_uri` として持たせ、無ければ exit 2 にした（`REQUIRED_FIELDS`
   には加えていない。他アカウントの台帳生成テストが壊れないようにするため）。
   `nigamilab-threads.json` には設計 §9 の値 `https://nigamilab.com/` を足した。
2. **`scopes` の置き場**: 発注書の指示どおり `thth/scopes.py` に `DEFAULT_SCOPES`
   定数を置き、`accounts/<account>.json` の任意項目 `scopes` があればそちらを
   優先する実装にした。
3. **認可 URL のホストを分離**: `graph.threads.net`（API 呼び出し）と
   `threads.net`（認可 URL の表示のみ・THTH 自身は HTTP アクセスしない）を
   別の環境変数に分けた（`THTH_THREADS_BASE_URL` は既存を流用、
   `THTH_THREADS_AUTH_BASE_URL` を新設）。
4. **24 時間の下限は `--force` でも覆さない**: 発注書の「50 日超で更新。`--force`
   で無条件」と「24 時間以上経過・未失効でないと更新できない」は、素直に読むと
   矛盾しうる（`--force` は「無条件」と書いてあるため）。**24 時間はメタ側の
   ハードな技術的条件（呼んでも失敗するだけ）である一方、50 日は当方の運用しきい値
   なので、`--force` が無条件で覆すのは後者だけとした**。テスト
   `test_4_forceでも24時間未満は覆せない` で固定した。
5. **`refresh --check` の `remaining_days` の基準**: token に保存済みの `expires_in`
   （無ければ 60 日 `5184000` 秒）から「取得時刻＋expires_in − 現在時刻」で計算した。
   実際に Meta が発行する `expires_in` と一致するかは未検証（L3。`thth auth` が
   保存した値をそのまま使う設計）。
6. **`user_id` の自動書き戻しはしない**: 発注書の「masaru が手で探さずに済む」は
   標準出力に出すところまでで、`accounts/<account>.json`（git 管理下）を
   `thth auth` が自動で書き換えることはしていない（意図的。auth はネットワーク越しの
   秘密操作であり、リポジトリの構造ファイルへの書き込みは別の関心事と考えた）。
