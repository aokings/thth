## 3. 直していないもの・限界

- **Codex が「試したが破れなかった」とした一覧**（httpsafe のリダイレクト・`paging.next`・callback の表示・front-matter の改行注入・`send --confirm`・share の白名簿・MCP の名前検査・ファイル権限・配布物）は、今回の証拠の範囲で破れなかっただけで、保証に昇格させていない。
- **承認経路と MCP の一部は Codex 側の自動安全判定で検証が中断した**（Codex の報告どおり）。撤回と連投指紋は開発セッションが自分で確定・修正したが、「未承認の内容が送信される」実証は誰もしていない。
- 秘密の登録簿は**プロセス内**だけ。値を知らない経路（別プロセスの runs・ping 本文）は従来の綴りベースの伏字のまま。
- Mastodon の `unlisted` は「公開」に含めた（URL を知る人は読める・タイムラインに出ないだけ）。
- selfupdate の「署名検証と merge を同じ OID に固定する」強化観点は残る（Codex の指摘・悪用再現なし）。
- 発注書の関数名の呼び違い（`_repo_roots()` → 実名 `ledger_roots()`）と、B の commit コメントの「監査 2026-09-14」は 09-16 の誤記。挙動には関係ない。
