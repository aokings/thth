## 2. F2〜F8 の直し方（判断の分かれ目だけ）

- **F2**: `quotes_in_article` は**指定できるままにして、必ず `not_run` と理由を
  返す**形にしました。「登録可能な検査から外す」ほうではなく、**要求された検査の
  1 つ 1 つが「結果」か「未実行と理由」のどちらかに必ず対応する**ほうを取って
  います（記事 snapshot を受け取る口ができたら実装に差し替える意図を残すため）。
  **この選択が妥当かを見てください。**
- **F3**: `evidence` の型と ID の形を先に検査。**ID でない根拠（URL 等）は禁止
  せず、`unverified_refs` として別に出し、結果を `not_evaluated` にします**
  （「実在を確かめていない」を保持）。
- **F4**: **CLI の登録を `proposed` / `shadow` に閉じました。** 語彙の `accepted` も
  同じく閉じています。あわせて `cases.review_ids` の実在・account・原稿の対応を
  照合します。正式な採用（採用判断の記録）は第 3 段階へ送りました。
- **F5**: 候補の入口で語彙と型の仕様を解決し、**意味の版まで含めて束ねます**。
  解決できない記録は候補に数えず `unresolved_records` に名前で出します。
- **F6**: `draft_series()` を足し、**改訂・再検査・持ち越しの線から系列**を作って
  数えます。線が無ければ系列は分からないので、**「独立」と確定しません**
  （`draft_versions` を別に出します）。
- **F7**: `--draft` 指定時に、現版に当たる記録と **`unreviewed_history`（旧版の
  未解決・持ち越し）を別の欄**に出します。旧指摘を現版の不備とは断定しません。
- **F8**: 鎖を 3 本に分けました——`supersedes`（**同じ版**の同じ指摘への処置）／
  `recheck_of`（その処置が指した**改訂先**の再検査）／**`carried_from`（新しい版
  への持ち越し・新設）**。account の一致と版の関係を照合します。

  対しては、**`provenance`（`production` / `trial` / `unknown`）の欄を足しました。**

  判断しました）。つまり **「区別した」ではなく「区別できるようにした。既存は

## 4. こちらが疑っている点（今回の修正で新しく作った面）

1. **`carried_from` を新設したので、鎖が 3 本になりました。** 増やしたぶん、
   「どれを使うべきか」を間違える余地が増えています。版と account は照合して
   いますが、**「同じ指摘であること」は照合していません**（理由 ID も対象段も
   自由です）。
2. **`draft_series()` は記録の中の線だけで系列を作ります。** 線を書き忘れた
   改訂は、いまも独立 2 件に見えます。**書き忘れを検出する手段がありません。**
3. **`provenance` は自己申告です。** `--provenance production` と書けば本番として
   数えられます。照合するものが無い（原稿の側に印が無い）。
4. **`unreviewed_history` は `deferred` と `unresolved` だけを拾います。**
   `dismissed`（見送り）は拾いません。見送った指摘が新しい版で復活する場合を
   落としている可能性があります。
5. **F4 で `accepted` を閉じたので、いまはどの型も語彙も採用できません。**
   第 3 段階が来るまで「採用」という状態が存在しない、という状態が妥当か。
