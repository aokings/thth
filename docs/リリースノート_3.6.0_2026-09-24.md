2026-09-24。設計は `docs/設計_3.6.0_投稿の目的とつまずきの年表_2026-09-24.md`（A・B・C・D）。材料の報告: **r20260923-7c297144**（kopicha の設計材料 §4）と、kopicha が原稿の本文メモに書き始めた「目的: 誘導／フォロー」（09-24 時点で queue の 19 本）。投稿単位のフォローが API に無いこと（r20260923-08050195・3.3.0 の照合）は変わらないので、follow は投稿単位に割らない。

版を 3.6.0 に上げた（2026-09-24）。

## 何が変わったか

約束は 1 行です。**投稿ごとに目的を 1 つ書けば、道具が目的ごとに、その目的に合う物差しで比べる。** 目的は人と LLM が決め、道具は推測しない。

1. **原稿の `goal:`**: `reach`（表示）・`click`（サイト誘導）・`follow`（フォロー）・`reply`（会話）の 4 語だけ。無ければ書かない（数えるときは `none`＝目的なし）。4 語以外は lint と承認が `goal_invalid` で断ります。**本文のメモ（「目的: 誘導」）は読みません**——front-matter の `goal:` だけが正。連投（`thth: 2`）は束の front-matter に 1 つ（段ごとには書けない）。
2. **承認の指紋に入れない**: 目的は測り方の札で、公開される中身ではありません。承認のあとに書き換えても `approval_stale` になりません。承認のときに目的の控え（`approved_goal`）を書き、公開のときに違っていれば「目的の変更」（`goal_change: {from, to}`）として runs と sent（連投は段の実行記録）に残します。承認の一段目に目的が出ます（digest には入りません）。
3. **`thth send --goal`**: 同席の送信にも付けられます（digest には入らない・sent と runs に残る）。
4. **`thth analytics-report --compare-previous --by goal`**（MCP の `analytics_report` の `by: goal`）: 目的ごとの層（既存の 24 時間の比較）に、目的ごとの物差しが付きます。
   - reach: 24h・72h の views（Threads・X）、likes＋reposts（Bluesky・Mastodon。views は `metric_unavailable`）。
   - reply: 24h の replies と、返信した人の異なり数（自分の account を除く・24 時間の窓が閉じたあとに取った記録があるときだけ）。
   - click: **投稿単位のクリックは言えません**（`per_post_clicks_unavailable`）。click の投稿が 1 本だけの日に限り、その日の日次の clicks（リンク先別を含む）を並べます（2 本以上の日は並べない）。
   - follow: **投稿単位のフォローは言えません**（`per_post_follows_unavailable`）。日次の followers の前日差を、follow の投稿が出た日と出ていない日で並べます。
   - click と follow の日次との並べ方は必ず `observational_difference: true`・`causal: false`（観察の差・因果ではない）。
   - 層は公開の時点の記録から作ります。記録に goal の欄そのものが無い投稿（3.6.0 より前・目的を書く口が無かった頃）は **`unrecorded`**、欄があって目的が無い投稿は `none`（目的なし）。2 つは混ぜず、分母には両方を出します（`--by goal`・observe・地図で同じ）。公開のあとに原稿の `goal:` を書き換えても過去の層は動きません。
5. **observe と地図**: `thth observe` の「前回の観測から」に投稿ごとの目的が出て、主な物差しが先頭に並びます（click・follow は「言えない」の 1 行）。`thth map show` の自分の層に点×目的の表（その話題で目的ごとの本数と主な物差しの中央値）。
6. **広場の施策に目的**: `thth plaza post … --goal <語>`（MCP の `thth_plaza_post` の `goal`）。一覧と 1 件の表示に出ます。
7. **つまずきの年表**: `thth report timeline <project|account> [--since]`・MCP `thth_report_timeline`（読むだけ）。報告の口の記録（置いた日・種類・題・閉じた版・閉じるまでの日数）と、リリースノートの報告 id・「〜の実測から」を日付で並べます。材料は道具の中の記録と repo の docs だけ。集計は最初の報告から数えた日数ごとの件数・始めて 2 週間の件数・閉じるまでの日数の中央値と n。**他の持ち主の報告は出しません**（リリースノートに書かれた他の持ち主の id も拾わない）。新しい持ち主の最初の 2 週間は、広場の open に参加した持ち主の年表の中央値を 1 行（件数と日数だけ・題は出さない・自分も参加しているときだけ）。

## 各 project のセッション向け

1. 原稿の front-matter に `goal: reach|click|follow|reply` を 1 行（無ければ書かない）。本文のメモに書いた目的は道具が読まないので、front-matter へ移す。
2. 連投は束の front-matter に 1 つ。同席の送信は `thth send <account> --goal <語>`。
3. 承認のあとに目的を変えても出る。変えたことは runs と sent に残る（直すなら承認の前が読みやすい）。
4. 比べるのは `thth analytics-report <account> --compare-previous --by goal --json`（MCP `analytics_report` の `by: goal`）。reach は views、reply は replies と返信した人の数。
5. click と follow は投稿単位の数字が無いので「言えない」と出る。日次の並べ方は観察の差で、投稿の効果とは書かない。

## 未確認のこと

- 本物の台帳で `--by goal` を回した実測（試験は偽の台帳だけ）。
- 返信した人の異なり数は、返信の台帳の `timestamp` と `username` に頼る（媒体が返さない行は数えない・自分かどうか分からない行があればその投稿は数えない）。
- 年表の「〜の実測から」は語の一致（project・account の名前を含む行）で結ぶ。名前を書かずに書いた実測は拾えない。
