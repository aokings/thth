# 設計: monban（門番）——hub と THTH が共有する「口を開けないサーバ」の骨（2026-09-27）

状態: **下書き（masaru の確認待ち・着手は Meta の判定のあと）**。切り出し候補 第 2 版（`docs/切り出し候補_ヘッドレス道具の小品_2026-09-27.md`）の §8.5・§9 を受けて、名前を決め、共有の骨を 1 枚にした。コードは触っていない（凍結中）。

## 0. 一文と名前

**monban は、外から入る口を開けないサーバ（家）を、外の人・機械・LLM から使えるようにする門番。** 鍵で人を確かめ、届け物（依頼）を預かって家が取りに来るのを待ち、家の脈を聞き、来訪の帳面を付ける。家の中には入らない。

名前: **`monban`**（門番）。PyPI で空いている（09-27 確認・`gatehouse`・`postbox` は使われていた）。1 語・意味そのもの・日本語の音で masaru が呼びやすい。英語の人にはただの固有名詞でよい（healthchecks が固有名詞であるように）。

門番の 4 つの仕事と、いまの現物:

| 仕事 | 門番のことば | THTH の現物 | hub の現物 |
|---|---|---|---|
| 人と鍵を確かめる | 鍵（key）・合鍵の帳面（key table） | 資格情報（sha256・scope・期限）・`/login/<code>`・`/activity` の発行と取り消し・招待の完了ページ | — |
| 届け物を預かる | 郵便受け（mailbox） | `/api/v1/<operation>`・`Account` DO の `request:<id>`・sync で取りに来る・20 秒の保留・`/result/<id>` | （Agent Mail は別の既製品・§4） |
| 家の脈を聞く | 脈（pulse） | 常駐の版と起動時刻（`thth board`）・`--fail` の ping | `hub pulse <名前> [--fail]`・`pulses:` の期待・朝の判定 |
| 帳面を付ける | 帳面（ledger） | `admin_log`（append-only・presence-only diff・`--by`）・口座の記録の `via`・鍵の id | `hub status post`・約束の台帳（設計中） |

## 1. 三つの部品

```
[Client]  monban CLI / Python lib      外の人の機械・LLM・Mac・ミニ PC
   │ HTTPS（鍵）
[Edge]    monban-edge（Cloudflare Worker + DO）   thth.me の今の Worker を汎用化
   ▲ 署名つき sync（取りに来る・VM から Edge へ）
[House]   monban-house（Python・常駐 library）    VM（wt）の thth-worker と hub-daily が使う
```

- **Client**（`monban` package の `client`）: `login()`（ブラウザ式・`--stdin`）・`logout()`・`call(operation, **args)`（25 秒・202 なら `/result/` を 1 秒おき最長 90 秒・401/429/網の失敗は符丁）・`pulse(name, fail=False, note=None)`（§3.3）。鍵は 0600 に置き、出力から伏せる。THTH の `remote.py` がそのまま原型。
- **Edge**（`monban-edge`・1 Worker・DO SQLite・rate limit）: 鍵の表・郵便受け・login・招待・持ち主の画面・capability URL・データ削除の受け口。**operation の名前と本文の上限を設定で受け、中身は見ない。** THTH の `api.js`・`login.js`・`person-object.js`（`Person`/`Account`/`Login`）・`relay.js`・`invite*.js`・`media*.js`・`deletion*.js`・`activity.js` が原型。
- **House**（`monban` package の `house`）: 署名つき sync で Edge から届け物と操作を取り、**利用側が渡した handlers 表**で行い、結果と要約と鍵の表と脈を押し上げる常駐の骨。THTH の `relay.py`（署名）・`api_requests.py`（届け物）・`activity.py`（要約と操作）・`worker.py`（ループと版の入れ替え）・`guard.py`（安全装置）・`admin_log.py`（帳面）・`secrets_fs.py`・`httpsafe.py` が原型。

## 2. 家と門番の約束（protocol・現物のまま）

- **署名つき sync**（House → Edge・pull）: RSA-3072 PSS・canonical `'thth-approval-v1'\n<method>\n<path>\n<role>\n<subject>\n<operation>\n<ts ms>\n<nonce>\n<sha256(body)>`（**文字列は変えない**・版ずれで壊さないため。monban の版で `'monban-v1'` に改めるのは House と Edge を同時に上げられるときだけ）。headers `X-Thth-Time`/`Nonce`/`Signature` → monban では `X-Monban-*`（Edge は 1 版の間だけ両方受ける）。時刻 ±60 秒・同 nonce 拒否・redirect を追わない。公開鍵は Edge の secret（`RELAY_PUBLIC_KEY`）、秘密鍵は House の `~/.config/<家>/apps/relay-signer.key`（将来 `systemd-creds`）。
- **sync の中身**（人ごと・10 秒・待ちがあれば 2 秒）: 上り `{summary, keys[{sha256, account, expires_at}], results[{request_id, account, status, result}], pulses[{name, at, fail, note}]}`、下り `{requests[{request_id, account, operation, key_sha256, body}], actions[{id, kind, ...}], pending}`。結果は 1 件 128 KiB、下りは 16 件・768 KB まで。
- **郵便受け**（Client → Edge）: `POST /api/v1/<operation>`（`Authorization: Bearer <鍵>`・JSON `{"account", ...}`・48 KB）→ 200 家の答えそのまま／202 `{status: pending, request_id}`／401 `invalid_key`・`key_expired`／429 `too_many_requests`（口座ごと pending 8）・`rate_limited`（鍵 60 回/分・IP 120 回/分）。`GET /api/v1/result/<id>`。届け物は 120 秒・結果は 10 分。Edge は中身を記録しない。
- **鍵**: 発行は Edge（乱数 43 字・1 度だけ人に見せる・hash を House へ）、権威は House（資格情報のファイル・sha256・scope・期限 365 日・revoked）。login は `POST /api/v1/login/start {code_hash, poll_token_hash}` → 人が `/login/<code>` で口座名と secret →「この機械に鍵を渡す」→ `GET /api/v1/login/poll/<code>`（poll_token）で 1 度だけ。
- **持ち主の画面**（`/activity`）: 口座名と secret（PBKDF2-SHA256・100,000 回・salt・世代・5 回で 15 分）。要約を 1 時間だけ持つ。操作（止める・戻す・取り消し・設定・鍵）は House が行う。閲覧は記録しない。
- **脈**（§3.3）: `pulses[]` を sync に載せる（House 自身の脈は sync が来ること自体）。Client からの脈は `POST /api/v1/pulse`（鍵）で Edge が預かり、House が sync で取り、帳面と判定へ。
- **断り**: 符丁 1 語＋`reason`＋`next_at`＋次の一手。**内側の符丁を外側で丸めない**（安全な符丁の集合は足す方向で）。

## 3. 何を共有し、何を利用側が書くか

### 3.1 House が持つ骨（共有）
署名・sync のループ・届け物の冪等な実行・鍵の表の押し上げ・要約の押し上げ・操作の受け取り・脈・帳面（append-only・presence-only・`--by`）・秘密の置き方（0600 原子的書き込み・`redact`・`systemd-creds` への移行）・版が動いたら自分で終わる（`Restart=on-failure`）・umask 077。

### 3.2 利用側が渡すもの（THTH・hub）
| 渡すもの | THTH | hub |
|---|---|---|
| `handlers`（operation → callable(context, body)） | `server_writes.serve` の表（send_request・posts・…） | `status_post`・`promise_put`・`observe`（読むだけ） |
| `summary(person)`（持ち主の画面の要約） | `activity.summary` | 朝の 5 行の元 |
| `events(account)`（安全装置が数える記録） | `sent.records` | — |
| `pulses:` の期待（`media.yaml`） | `thth-run@<口座>` 等 | `kopicha-observe`・`wt-run` 等 |
| 鍵の資格の形（scope・accounts） | 口座 | プロジェクト／セッション |

### 3.3 hub との関係（内向きの半分）
- **脈**: いま `hub pulse` は VM の中で直に打ち、外からは ssh（`設計_hubの脈`・「HTTP の受け口を VM に開けない」）。monban では **Edge が脈も預かる**ので、kopicha のミニ PC や Mac は ssh の鍵なしで `monban pulse kopicha-observe`（鍵 1 本）と打てる。「外に口を開けない」は守られる（Edge は預かるだけ・家が取りに来る）。hub の判定（🔴🟡⚪）はそのまま。
- **状況の掲示板・約束の台帳**: hub の `status post`・`promise` は House の帳面（append-only）を使う。Mac から `hub status post` が ssh で打っているものを、将来は Client → Edge → House でも打てる（ssh を持たない借宿のセッションでも）。
- **Agent Mail**: 既製品のまま。monban は置き換えない（§4）。
- **秘密**: hub の `systemd-creds`（暗号化・平文はサービスの数分だけ）を House の正にし、THTH の署名鍵と資格情報のファイルもそこへ寄せる（段 3）。

## 3.5 他の人が使う形（hosted・healthchecks.io のように）——masaru の問い（09-27）

masaru「他の人がヘッドレスのアプリを作るときに使えるようにしたい。healthchecks.io みたいに」。§1〜§3 のままでは「自分で Edge を立てる人」しか使えない。healthchecks.io のように **登録してすぐ使える** には、次を足す。

### 3.5.1 使う人から見た形（家を持つ人＝ヘッドレスのアプリを作る人）

```
pip install monban
monban house init                      # 署名鍵を作り、公開鍵と家の名前を出す（秘密鍵は 0600・systemd-creds 可）
（ブラウザ）https://monban.example/houses/new に公開鍵を貼って家を登録 → 家の id と持ち主の secret を 1 度だけ
monban house run --handlers ./app.py   # 常駐: 取りに来る・handlers を呼ぶ・脈を打つ・帳面を付ける
```

`app.py` は「operation の名前 → 関数」の表だけ。例:

```python
from monban.house import House
house = House(handlers={"echo": lambda ctx, body: {"echo": body}, "status": my_status})
house.run()
```

使う人（家に依頼する人・その LLM）は `pip install monban` → `monban login`（ブラウザで家の持ち主が許可）→ `monban call <家> echo --json '{"text": "hi"}'`。LLM は薄い MCP（`monban-mcp`・CLI を呼ぶだけ）か、その家のアプリが配る skill で使う。

### 3.5.2 Edge に足すもの（多家）

| 足すもの | 中身 |
|---|---|
| 家の登録口 `/houses/new` | 公開鍵（PEM）と家の名前を受け、家の id（乱数）と持ち主の secret を 1 度だけ出す。Edge は verifier と公開鍵だけ持つ |
| 家ごとの署名鍵 | sync の署名を家の公開鍵で検証（今は 1 つの `RELAY_PUBLIC_KEY`）。`House` DO（家ごと）に公開鍵・rate・脈の期待を置く |
| 家ごとの上限 | 郵便受けの件数・本文の上限・鍵の数・sync の頻度。無料の枠と、超えたら断る符丁（`house_quota`）。課金はしない（まず無料・上限で守る） |
| 家の持ち主の画面 `/houses/<id>` | 鍵の一覧と取り消し・脈の状態・上限・家の削除（secret で入る）。THTH の `/activity` の家版 |
| 招待（家が人を招く） | 今の `/invite/<code>` を家ごとに。招かれた人は口座（家の中の名前）と鍵をもらう。OAuth の預かり所（Threads 等）は**家が要るときだけ**プロファイルを渡す |
| monban 自身の規約と privacy | 「Edge は届け物を 120 秒・結果を 10 分・鍵の hash・公開鍵・脈の時刻だけを持つ。中身は読まない・記録しない」を英日で。データ削除は家の削除 |
| 悪用の守り | IP と鍵と家の rate limit・本文の上限・家の登録に人の確認（メールは使わない → 招待制で始める: masaru が家の登録 code を渡す。開放は後で） |

### 3.5.3 運営の形

- **domain**: monban 用に 1 つ（候補は masaru が決める。thth.me とは分ける——THTH は monban の 1 つの家になる）。
- **1 Worker・DO SQLite・R2 は要らない**（capability URL は THTH 固有の家の機能として家側に残す。Edge の共通部分に入れない）。
- **費用**: Cloudflare の無料の枠で始める。家の数が増えたら有料 plan。**課金の仕組みは作らない**（healthchecks.io も長く無料だった）。
- **支援**: GitHub の issues。SLA は書かない（「as is」）。
- **英語が先**（healthchecks.io の利用者は世界）。文書は英日。

段 1〜3（切り出し・THTH と hub が使う）のあと:

7. 招待制で 2〜3 人に家を持ってもらい、使い勝手レポート（LLM に書かせる）。

### 3.5.5 正直な見立て

- healthchecks.io の「1 行で言える約束」に当たるものは **「口を開けずに、外から使える」**。これは家を持つ人（ヘッドレスのアプリを作る人）に刺さる。ラズパイ・自宅の Mac・会社の VM に、inbound を開けずに CLI と LLM からアクセスする道は今も面倒で、monban はそれを 3 命令にする。
- 弱み: Edge が 1 社（masaru）の運営に依存する。自分で立てる版（§1〜§3）を常に同じコードで出しておくのが、healthchecks.io と同じ答え（hosted と self-hosted の両方）。
- 家の側の handlers は Python だけ（最初は）。他の言語の家は sync の protocol（§2）を公開して任せる。

## 4. やらないこと

- 画面（見る・止める・鍵以外）・メール・プッシュ通知。
- 承認の関所（金庫）。守りは安全装置と停止スイッチ。
- 家の中への口（inbound）。Edge から House へは何も押さない（House が取りに来る）。
- 課金の仕組み・SLA・メールでの支援（issues だけ）。
- LLM の会話の保管・届け物の中身の保管（120 秒の預かりと 10 分の結果だけ）。
- Agent Mail の置き換え・hub の判定の置き換え。

## 5. 段（着手は Meta の判定のあと）

1. **Python package `monban`**（`house`・`client`）を THTH から切り出す: `relay.py`・`api_requests.py`・`activity.py` の sync・`worker.py` のループ・`guard.py`・`admin_log.py`・`secrets_fs.py`・`httpsafe.py`・`remote.py`。THTH は `monban` に依存し、`handlers`・`summary`・`events` を渡す形に。**動きを変えない**（THTH の全件試験がそのまま通る）。名前の互換（`thth-approval-v1`・`X-Thth-*`）は残す。
2. **Edge を汎用化**: `callback/` を `monban-edge/` に移し、operation の表・本文の上限・要約の形・操作の集合を `wrangler.jsonc` の vars か 1 つの設定ファイルに。thth.me はそれで動く（deploy は masaru の手）。
3. **hub が monban を使う**: `hub pulse` を House の帳面に、Client からの `monban pulse` を Edge 経由に。ミニ PC の脈を ssh なしに。秘密を `systemd-creds` へ。
4. **検収**: 別プロジェクトの LLM セッションに `monban` だけで小さな家（例: 「Mac の中のスクリプトを外の LLM から叩く」）を立てさせ、使い勝手レポートを書かせる。Meta の審査員の試験結果も検収に数える。
5. 公開: PyPI `monban`・GitHub `aokings/monban`（Edge も同じ repo）・文書は英日。THTH と hub はその最初の 2 人の利用者。
6〜8. 他の人が使う形（§3.5.4）: 多家の Edge → 招待制で 2〜3 人 → 規約・文書・domain → 開放。

規模（推測）: 段 1 が本体で writer 2〜3 日、段 2 が 1〜2 日、段 3 が 1 日。凍結が解けてから。

## 6. 決めたこと（masaru に確かめる 2 つ・それ以外は推薦で進める）

1. **名前は `monban`**（PyPI 空き）。Edge は `monban-edge`、package は `monban`（`monban.house`・`monban.client`）。
2. **repo は新しく `aokings/monban`**（THTH と hub から切り出し、両方がそれに依存）。THTH の中の `monban/` ディレクトリで始める案もあるが、hub も使うので最初から別 repo。

推薦で進める点: 署名の文字列と headers の互換の残し方（§2）、脈を Edge が預かる（§3.3）、秘密は `systemd-creds` を正に（§3.3）、Agent Mail は置き換えない（§4）。

## 7. 前提が変わったら

- Meta が却下し、審査員の道を「thth.me の画面」に変えねばならなくなったら → Edge の持ち主の画面に「書いて出す・消す」を足す設計（`docs/事実と方針_Meta審査と外の人の道_2026-09-26.md` (d)）に戻る。monban の骨は同じ（画面も同じ郵便受けを叩く）。
- hub が VM を離れる（別の機械・複数の家）なら → Edge は家ごとに署名鍵を持てばよい（`Person`/`Account` DO は家に依らない）。monban は最初から「家は複数」で設計する（sync の `house_id`）。
