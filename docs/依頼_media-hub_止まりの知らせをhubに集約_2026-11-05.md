# 依頼: THTH の止まりの知らせを hub に集約する（2026-11-05・THTH開発 第12 → メディアハブ実装）

masaru 11/05「メディアハブに通知は集約しようぜ」「メールは見ない」。

## なぜ

11/03〜05、kopicha-x の投稿が止まった（根は X の予算の台帳の大きさ・5.12.2 で直した）。知らせは管理者宛てのメールだけで、masaru には届いていないのと同じだった。asmon-kanto-x の鍵も同時に切れていたが、投稿の予定が無く表に出なかった。

## THTH の側（作っている・5.12.3 で出す）

`thth board --json`（schema `thth.board/1` のまま・足すだけ）の各口座の行に `stuck` を足す。

```json
{"stuck": null}
{"stuck": {"code": "token_refresh_failed", "since": "2026-11-03T04:17:00+09:00",
           "what": "何が起きているか 1 行", "fix": "次の一手 1 行"}}
```

- 止まっていなければ `null`。古い版の THTH では鍵が無い（無いものは止まっていない扱いでよい）。
- 夜など投稿を試みなかった回では消えない。本当に解けたら `null` に戻る。
- 秘密の値・本文・宛先は入らない。

## hub の側（頼みたいこと）

- `hub/hub.py` の SNS の点検（`thth board` を読む所）で、`stuck` があれば赤にし、`what` を notes に、`fix` を `next` に出す。`since` からの時間も出す。
- 投稿の予定が無い口座でも赤にする（asmon-kanto-x の形）。`stuck` は「投稿の間」の判定より先に見る。
- masaru が見る一覧と本線に届くようにする。届き方（朝の 1 枚か、`hub status` か、呼び鈴か）は hub の決まりで選んでよい。**止まった当日のうちに**届くこと。朝の点検だけだと遅れるなら、点検の回数の案もください。

## できあがりの確かめ

`stuck` の入った偽の board で赤になり、`next` が `fix` と同じになる試験。THTH が 5.12.3 を出したら、こちらから知らせる。

## そのあと

hub に出るのを確かめたら、THTH の管理者宛ての運用メールを止める（THTH の側でする）。
