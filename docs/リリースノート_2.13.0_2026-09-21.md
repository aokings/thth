instance の実上限、実 upload の処理待ち、媒体での実表示は配布担当による本番実測が必要です。詳細は [添付原稿の手順](原稿_添付_2.13.md) を参照してください。

- 第8段候補: 承認ページが添付を表示。画像は 600 秒の preview capability で `/m/…` から表示し、動画・音声・字幕は種類・長さ・公開 SHA 先頭 12 桁・alt の文字、型付き添付と `post_options` は canonical JSON。CSP は `img-src 'self'` のみ追加。preview の発行に失敗したら session を登録せず `media_preview_unavailable` で止めます。digest と受領は変わりません。実 Worker・実 R2 での表示は未測定です。


- 第9段候補: 招待者の添付。`thth_media_upload_url` が一回限りのアップロード URL（応答にだけ出る・10 分）を返し、`thth_media_complete` がサーバ側で bytes を読み戻して sha256 を照合し、第1段の sanitize を通してから `docs/sns/media/<公開 sha>.<拡張子>` へ commit します。`thth_draft_put` の `media: [{media_id, alt}]` で下書きに付きます（alt 必須・別の actor/account は `media_owner_mismatch`）。控えは Worker へ問い合わせる前に mode 600 で保存し、結果不明は自動再試行しません。参照されない公開ファイルは 1 日後に `thth admin media gc` が commit で消します。上限は image 8,000,000 / video 1,000,000,000 / audio 100,000,000 bytes の暫定です。実 Worker・実 R2 での往復は未測定です。
- 承認 session の `create` だけ JSON 本文の上限を 96 KiB にしました（添付一覧を載せる口だけ・他の口は 64 KiB のまま）。

- 第10段候補: 記録と観測、媒体ごとの網羅表。`sent` と `insights` の行が `media: [{sha256, kind, alt_present, remote_id}]` と `attachment_kinds`（ファイルの種類＋型付きの種類＋`carousel`、無ければ `none`）を持ち、`analytics-report --compare-previous --by attachment_kind` が 1 本を**種類ごとに**数えます（`attached` / `none` / `unknown` が母集団を分割し、`reconciliation` に分母が出ます）。`--by kind`（トピックの棚）は変えていません。**記録の無い投稿は `unknown` で、`none` とは別**です。

- 第10段候補: 媒体ごとの「出せるもの」表を 1 本（`thth/media_capabilities.py`）にまとめ、`thth doctor`（本文と `--json`）・`handoff-report --since-last-read` の `tool.capabilities`・`docs/原稿_添付_2.13.md`・skill の開始手順に同じ内容で出します。値は `supported` / `unsupported: <理由>` / `unverified: <理由>` / `ascii_only: <理由>` / `body_only` の固定語彙で、**「未確認」を「非対応」とは書きません**。`unsupported_attachment: <媒体>/<key>` の `<key>` が表の key の部分集合であることを試験が守ります。表は静的で、provider を叩いた結果ではありません。

- 第10段候補: 第9段の直し 3 件。Worker の転送 mime に音声（audio/mpeg・audio/flac・audio/ogg・audio/wav・audio/x-wav・audio/webm・audio/mp4）を足し、招待者が Mastodon 向けの音声を置けるようにしました。`media_id` は upload subject そのものではなく `'m' + base64url(sha256(subject))[:42]` の一方向の像にしたので、**`media_id` を持つだけでは一回限りの PUT URL を組み立てられません**。multipart PUT の手順（part_size・1 からの連番・最後に complete）を `docs/運用_サーバ書込_2.12.md` に書きました。
