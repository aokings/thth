## 0. 見方の一行と決定（masaru・2026-09-26）

> THTH は、SNS を調べ・投稿し・予約する **CLI ツール**。だから LLM が操作しやすい。MCP と skill はその補助。thth.me とサーバは、CLI を外の人にも届ける裏方。

- 「外部に向けた CLI を用意して臨む」（09-26 昼）。Meta の審査員も外の人も、**`thth` を打てば masaru と同じことができる**。LLM はそれを代わりに打つだけ。
- 「薄い MCP、厚い CLI、これらを skills にラップさせる作り」（09-26 昼）。
- 承認ページは無い（3.13.0）。守りは安全装置（サーバが機械的に守る）と鍵（範囲・期限・取り消し）。

## 1. 三層の役目

| 層 | 何をするか | 何をしないか |
|---|---|---|
| **CLI `thth`（厚い）** | 全部の仕事: 調べる（投稿一覧・返信・数字・言及・語の検索・プロフィール・場所）・出す・返信・予約・消す・設定・状態。手元の repo で動く**手元の道**と、鍵で thth.me 経由で自分の口座を動かす**遠くの道**の 2 つを持つが、**命令の名前・引数・`--json` の形は同じ** | — |
| **MCP `thth-mcp`（薄い）** | CLI を subprocess で呼んで `--json` を返すだけ（今の手元の形をそのまま遠くの道にも）。道具の名前と引数は CLI の写し | 判断・整形・条件分岐・鍵の管理。VM の上で in-process に動く道（今の `server_mode`）は**外の人向けには使わない** |
| **skills（包む）** | LLM に「いつ・どの命令を・どう打つか」を教える 1 枚（`skills/thth/SKILL.md`）。手元の道と遠くの道の違いは「最初に `thth login` をする」だけ、と書く | 命令の意味を skill 側で作らない（CLI の `--help` と `--json` が正） |

**規律**: 新しい機能は「CLI の命令として何か」を先に決める。MCP の道具はその写し、skill はその案内。Web（thth.me）の画面は招待・`/activity`（見る・止める・鍵）・規約だけ。

## 2. 外の人から見た形

```
pip install thth                      # PyPI（3.12.0 から出ている）
thth login                            # 鍵を tty で 1 度だけ入れる（引数・環境変数には出さない）
thth posts inv-xxx-abc123             # 自分の投稿の一覧
thth send inv-xxx-abc123 --text "…"   # 出す（その場・post_id とリンクが返る）
thth send inv-xxx-abc123 --text "…" --reply-to <post_id>
thth replies inv-xxx-abc123           # 返信を読む
thth measured inv-xxx-abc123          # 数字（インサイト）
thth retract inv-xxx-abc123 <post_id> # 消す
thth schedule inv-xxx-abc123 --text "…" --at 2026-09-27T09:00+09:00
thth mentions / topics --search / profile / location search  # 調べる
thth account status inv-xxx-abc123    # 安全装置の数・止まっているか・鍵の期限
thth logout
```

LLM を使う人は `claude mcp add thth -- thth-mcp` と skill の導入だけ。**鍵は LLM に渡さない**（CLI が `~/.config/thth/remote.json`（0600）に持つ。MCP は CLI を呼ぶだけなので鍵を知らない）。

## 3. 作り

### 3.1 遠くの道（CLI → thth.me → VM）

```
CLI ──HTTPS(bearer)──▶ Worker /api/v1/<operation>
                          │ 鍵の hash を照合・回数制限・口座の束（Account DO）に request を置く
                          │ 応答を最長 20 秒待つ（DO の storage を 0.5 秒ごとに見る）
VM（常駐 thth worker）◀── 署名つき sync で request を拾う（待ちがあれば 2 秒ごと・無ければ 10 秒ごと）
   server_writes.execute / 読む口 を、その鍵の資格（scope=その口座）で実行
   結果を sync で押し上げる ──▶ Worker が保留中の HTTP 応答に返す
                          │ 20 秒を超えたら {status: pending, request_id} を返し、CLI は /api/v1/result/<id> を見に行く
```

- **VM に外から入る口は作らない**（今と同じ）。Worker は預かり所で、VM が取りに来る。
- **鍵**: 今の資格情報（`report-credentials.json` の 1 件・sha256・scope・writes・actor・期限 365 日）をそのまま使う。Worker は発行時に hash と口座の対応を Person DO に持つ（今は VM だけが持つ）ので、**Worker で先に断り、VM でもう一度確かめる**（権威は VM）。取り消し・発行し直しは `/activity`（今のまま）。
- **回数制限**: 鍵ごと 60 回／分（Worker）。安全装置（1 日の上限・連投）は VM。
- **request の形**: `{operation, account, ...引数}`（`server_writes` と同じ・48 KB 上限）。応答は CLI の `--json` と同じ形。添付は今の R2 の capability URL の道（`media_upload_url` → PUT → `media_complete`）を CLI が代わりに踏む。
- **記録**: 遠くの道で行ったことは `via: cli`（MCP 経由なら `via: mcp`）と鍵の id つきで口座の記録に残る（今の `via` の続き）。

### 3.2 読む口を足す（VM 側）

今の利用者 scope にあるのは書く口と状態だけ。次を**同じ資格・同じ口座の範囲**で開く。どれも今の CLI の関数を呼ぶだけ（判断を足さない）。

| operation | CLI | 中身 | 注意 |
|---|---|---|---|
| `posts` | `thth posts` | 自分の投稿の一覧（記録・`--refresh` で API） | `threads_basic` の録画 |
| `replies` | `thth replies` | 自分の投稿への返信（記録・`--refresh` で API） | `threads_read_replies` |
| `measured` | `thth measured`／`thth collect` | 数字（記録・`collect` で API） | `threads_manage_insights`。API の呼び出しは口座ごとに 10 分に 1 回まで（連打で Meta の上限を食わない） |
| `mentions` | `thth mentions` | 言及 | 承認済みの権限 |
| `topics_search` | `thth topics --search` | 語の検索（集計・本文は先頭 60 字） | 同上 |
| `profile` | `thth profile` | 公開プロフィール | 同上 |
| `location_search` | `thth location search` | 場所の候補 | 同上 |

### 3.3 招待と鍵の受け取り

- 招待の完了ページに、口座の secret と**アシスタントの鍵**の両方を 1 度だけ出す（今は secret だけ・鍵は `/activity` で発行）。審査員の手順が 1 段短くなる。`/activity` の発行し直し・取り消しは今のまま。
- `thth login` は tty で鍵を読む（`--stdin` も可・引数は断る）。保存先 `~/.config/thth/remote.json`（0600・`{url, account, key}`）。`thth logout` で消す。

### 3.4 手元の道と遠くの道の切り替え

- 口座の台帳が手元にあれば手元の道、無くて `remote.json` があれば遠くの道。両方あるときは手元が先で、`--remote` で遠くを指せる。どちらでもないときは「`thth login` か台帳」と 1 行で断る。
- **命令の名前・引数・`--json` の形は同じ**。遠くの道で使えない命令（`throw`・`run`・`approve`・`auth`・`account add` など運営の命令）は `remote_unsupported` と 1 語で断る。
- MCP（`thth-mcp`）はこの切り替えを知らない。CLI を呼ぶだけ。

### 3.5 skills

- `skills/thth/SKILL.md` に「遠くの道」の節を 1 つ足す: 最初に `thth login`、以後は同じ命令。断りの符丁（`too_soon`・`daily_limit`・`account_stopped`・`remote_unsupported`・`key_expired`）と次の一手。
- 運営の skill（`skills/thth-admin/SKILL.md`）は変えない。

## 6. 決めていないこと（推薦つき・推薦で進める）

- HTTP を 20 秒保留するか、すぐ `pending` を返して CLI が見に行くか → **保留する**（体感 2〜5 秒で返る・録画でも待ちが映らない）。超えたら `pending`。
- 招待の完了ページに鍵も出すか → **出す**（secret と同じ 1 度だけ・パスワード管理に別項目で保存）。
- VM の上の stdio MCP（`thth-mcp-invitee`・ssh 前提）→ **外の人向けには案内しない**。運営者の admin 用の stdio は残す。
- 遠くの道で `thth send` が rehearsal（dry-run）を挟むか → **挟まない**（手元の 2 段は masaru の repo の作法。遠くの道は頼んだらその場で出す・サーバが lint と安全装置で断る）。`--dry-run` は残す（lint の結果だけ返す）。
- `measured` の API 呼び出しの間隔（10 分）→ 推薦のまま始めて見直す。
