## 0. 精読の前提から直す 1 点（第24 に見てほしい所）

精読の推しは「重い承認は承認ページ・軽い操作は MCP Apps」だった。だが **承認ページは 3.13.0（2026-09-26）で消してある**（[設計_3.13.0_承認ページを消す_2026-09-26.md](設計_3.13.0_承認ページを消す_2026-09-26.md)、masaru「不要なところに置かれた金庫なんて邪魔なだけ」）。今の `mcp/server.py` の注にも「公開・削除・予約の 3 本は、頼まれたらその場で行う（承認ページは無い）」とある。

今ある「重い操作の歯止め」は次の 4 つ:

| 歯止め | どこで効く | 人が関わる所 |
|---|---|---|
| 二段の digest（`confirm_required` → 同じ digest で確定） | 記録の無い自分の投稿の削除・はてなブログの予約・はてなブックマーク | 1 段目の中身を持ち主に見せ、言われたら 2 段目 |
| 猶予（口座の `hold_minutes`） | 今すぐの公開 | その間に持ち主が `thth.me/activity` で取り消せる |
| hub の承認の番号（`require_gate: true`） | 確定・公開・予約 | 番号を出すのは hub（4.4.1） |
| 安全装置（最短間隔・1 日の上限・急な連投） | 書くもの全部 | 持ち主が決める |

→ 推しを言い直す: **重い操作の確かめは今の歯止め（digest・猶予・番号・安全装置）のまま、サーバ側に置く。画面はその上で「見せたもの＝確かめたもの」を強める側に回る。** 承認ページを画面で作り直すことはしない（3.13.0 の決めに反する）。
URL の形の elicitation（会話の外のブラウザで人が開く）は、承認ページを戻すのと同じ形になるので、**承認の用途では使わない**（第24 11/27・3.13.0 を開け直す話は出さない）。
- monban が作る秘密の入力口（monban 設計案 第 3 版 26993df）は URL の形を使うが、秘密を入れる用途で承認ではないので、この決めとぶつからない。

## 1. どの道具にどの画面を出すか

画面はサーバが前もって登録した決まった HTML（`ui://thth/…`・`text/html;profile=mcp-app`）。AI が決めるのは道具の引数だけで、画面の文は THTH の結果から描く。

### 1-1. 画面を付ける道具（第 1 弾の推し・4 枚）

| 画面 | 付ける道具（今ある） | 画面に出す物 | 画面から呼べる物 | 重さ |
|---|---|---|---|---|
| **A. 予定の一覧** | `thth_queue`・`thth_board`（手元）／`thth_draft_list`（遠く） | 口座ごとの draft・approved・予約の時刻・型外。次に出るものと時刻 | 絞り込み・並べ替え・1 件を開く（`thth_preview` を画面から呼ぶ） | 軽い・読むだけ |
| **B. 下見のカード** | `thth_preview` | 媒体に投げる本文そのもの（省略・折りたたみ無し）・宛先の口座・日時・文字数と上限 | 無し（見るだけ） | 軽い・読むだけ |
| **C. 確定のカード** | `thth_retract_request`・`thth_schedule_request`（はてな）・`thth_bookmark_request` の **1 段目の結果** | 1 段目が返した本文・宛先・日時・URL・digest を、THTH の結果のとおりに | 「この中身で確定」→ 同じ道具を同じ digest で呼ぶ（画面だけの道具・§3） | 重い・**確かめはサーバの digest**。注: 画面で押した＝人が押した証明ではない（文で 2 段目を頼むのと重さは同じ） |
| **D. 数字の 1 枚** | `thth_summary`・`analytics_report`・`thth_morning` | 公開数・反応の和・返していない返信の数・フォロワーの差・止まっているか。期間・母数・欠測を添える | 期間の切り替え（同じ道具を引数違いで） | 軽い・読むだけ |

### 1-2. 画面を付けない道具

- 今すぐの公開（`thth_send_request`）: その場で出るので、押す前に見せる画面を挟む場所が無い。猶予（`hold_minutes`）のある口座では、結果に「取り消せる時刻と `/activity`」を出す小さな表示までは足してよい（第 2 弾）。
- 他人の投稿の本文を返す道具（`thread_read`・`thth_replies`・`thth_mentions`）: 外の中身を画面に描くと差し込みの的が増える。第 1 弾では付けない。付けるときは「外の中身」の枠を分け、画面の行動の引数にしない（精読 §5 の柵 4）。
- 管理者の道具・広告（`thth_admin_*`・`thth_ads_*`）: 第 1 弾の外。

### 1-3. 部品の表

- 正本は JSON 1 つ（`mcp/ui/catalog.json` を案に）: 部品の名・説明・props の JSON Schema・呼べる行動（引数の JSON Schema）・版。精読 §3 の推しのまま。
- **props に文字を持たない**のが既定（数・日付・番号・列挙だけ）。本文は THTH の結果の中にあり、画面はそれを描くだけ。AI が画面に文を書く口を作らない。
- A2UI・json-render・Jev は第 1 弾では使わない。4 枚は道具に 1 対 1 で決まっていて、AI に部品を選ばせる場面が無い。選ばせる画面（調べた結果の組み立てなど）が要るときに、表から起こす。

### 1-4. 演出（適度に可愛く・masaru 11/27「どうせだったら適度に可愛く演出したいね」）

- 使える物（既定の CSP・ext-apps 仕様の「Restrictive Default」）: CSS のアニメーション・HTML に書いた SVG・data: で埋めた画像（GIF も可）。外の URL の画像・フォントは読めない。Web フォントは `font-src 'self'` だけなので埋め込みでは使えない見込み（未確認）。
- 推し: **動きの芯は CSS と SVG**（軽い・暗い画面に合わせられる・止められる）。GIF は 1 KB 前後の小さい飾りだけ。
- 可愛くする所: 読み込み中（跳ねる点）・一覧が出るとき（1 行ずつふわっと）・空っぽのとき・**押したあと**の「ぽん」（判子）・顔の小さな印（まばたき）。
- 消える時（masaru 11/27「消える時、もあると良さそう」）: 次の結果で行が減ったら、その行は縮みながら薄れて消える（0.3 秒）。**消えた物は痕を残す**: 消えたあとに「1 件 消えた（d-002）」の 1 行を、番号に取り消し線を付けて出す。ふっと消えるだけでは何が消えたか見落とすため。動きを減らす設定では、動かさずに消して痕の 1 行だけ出す。
  - 当てる所: 予定の一覧（絞り・取り消し・公開されて予定から抜けた）・確定のあと（カードが判子の 1 行に縮む）。削除（取り下げ）で消えた投稿は、痕の 1 行に「取り下げた」と書き、可愛い動きにしない。
- 可愛くしない所: **確定のカードの押す前**。押したくなる演出は、押す前に宛先・日時・本文を読む妨げになる。押す前は静かに、全文を見せる。
- `prefers-reduced-motion: reduce` では動きを止め、GIF を隠す（柵にする）。
- 確かめ（11/27・偽の host に既定の CSP を掛けて）: 顔（SVG・まばたき）・跳ねる点・行のふわっと・きらめきの GIF（786 バイト・data:）が出て、console の誤りは 0 件。消える時（行が縮んで消え、痕の 1 行が出る）も偽の host で写しを取った。本物の host では未確認（§6 の 2 で一緒に見る）。

## 2. stdio のままで出せる範囲

今の MCP は手元で起動する stdio（標準ライブラリだけ・JSON-RPC を手書き・`initialize` は `protocolVersion: 2024-11-05`・`capabilities: {tools: {}}`）。

仕様と Claude の手順書を読んだかぎり、**手元の stdio のサーバでも Claude のデスクトップは画面を出す**（公式の手順が `claude_desktop_config.json` の stdio の例で書かれている・未実測）。Claude Code は画面を出さず、文字で受ける。

stdio のまま足す物:

1. `initialize` の受け手: client の `capabilities.extensions["io.modelcontextprotocol/ui"].mimeTypes` に `text/html;profile=mcp-app` があるかを覚える。返す `capabilities` に `resources: {}` を足す。
2. `resources/list`・`resources/read`: `ui://thth/queue` など 4 枚の HTML を返す。HTML は wheel に同梱する静的な物（`pyproject.toml` の force-include に足す）。外のドメインを宣言しない（既定の CSP で外へ出ない）。
3. 道具の `_meta.ui.resourceUri`: 画面を付ける道具に足す。**client が対応を言ったときだけ**足す（言わない client には今と 1 字違わない一覧を返す。Claude Code・他の client の振る舞いを変えない）。
4. 画面だけの道具（`_meta.ui.visibility: ["app"]`）: C の「確定」用。§3。
5. 結果の形: 今は `content` の text に CLI の `--json` を入れて返している。画面のために `structuredContent` に同じ JSON を入れる。AI にどこまで見えるかは host 次第なので、**AI に見せたくない物は入れない**を決まりにする（今の結果に新しい情報を足さない）。
6. 画面の中の橋渡し（postMessage の `ui/initialize` ほか）: 公式の SDK は JS。THTH は依存 0 の決まりなので、(a) 橋を手で書いた小さな JS を HTML に埋める、(b) SDK の束を HTML に埋めて同梱する、のどちらか。推しは (a)（使う口が `ui/initialize`・結果の受け取り・`tools/call` の 3 つに限られる）。Python の依存は増えない。

手元の 3 つの道筋（手元の台帳・サーバ型の credential・`thth login` の遠くの道）は、道具の名前が違うだけで、画面は同じ HTML を使い回せる。

## 3. 確定のカード（C）の作り

- 1 段目は今と同じ（AI が呼ぶ → `confirm_required` と中身と digest）。結果を C が描く。
- 画面だけの道具 `thth_ui_confirm`（案）: 引数は **道具の名と digest と対象の番号だけ**（本文の欄を持たない）。サーバは digest を今の 2 段目と同じに確かめる。合わなければ今と同じ断り。
- 道具の説明にも 1 行: 「画面から押しても、人が押した証明にはならない。確かめは digest」。
- 正直に書くこと: 画面から来た呼び出しも、サーバには AI の呼び出しと同じ形で届く（精読 §1）。だから C は **「人が押した証明」ではない**。強くなるのは「見せたもの＝確かめたもの」の側だけ: 中身は AI の言い換えでなく THTH の結果そのものが描かれ、digest は画面が持ってくる。歯止めの強さは今の二段と同じで、弱くはならない。
- 描く順: 宛先の口座 → 日時 → 本文（全文・省略しない）→ digest の頭 8 字。長い本文で宛先と日時を画面の外へ押し出させない（精読 §5 の柵 2）。
- 記録: 画面からの確定は、記録の名乗りに「画面から」を足す（`via: "mcp-ui"` を案に）。
- `require_gate: true` の口座では、番号の欄を画面に置かず、今どおり AI が番号を付けて 2 段目を呼ぶ道を残す（番号は hub が出す物で、画面の入力にしない）。

## 4. リモート MCP と OAuth を待つ範囲

次は stdio では出せない。括り（第3・レーン ws）の `thth login` → リモート MCP の口（thth.me）→ OAuth の順を待つ。

| 待つ物 | 理由 |
|---|---|
| claude.ai（web・スマホ）・ChatGPT に画面を出す | コネクタは Anthropic・OpenAI の側から URL でつなぐ。手元の stdio には届かない |
| 画面の HTML の配り方の見直し | 遠くの口では thth.me が HTML を返す。中身は stdio と同じ物を使い回す（作り直しにならない） |
| 1 人の持ち主が複数の口座の括りを選ぶ画面 | 括りの login の上に載る |
| Worker（thth.me）に触る所すべて | 審査のあとの決まり |

部品の一式（§1-3 の表と 4 枚の HTML）は口に依らないので、stdio で先に作っても作り直しにならない（精読の前提の節と同じ）。

## 5. Meta 審査との関係

- 作るのは審査のあと（今の決め）。stdio の MCP は PyPI の版に入るので、出すのも tag の push で、審査のあとの版のまとまりに入れる（release はまとめて）。
- stdio の範囲（`mcp/`・`mcp/ui/`）は Meta の審査の道に触らないので、main に入れてよい（第24 11/27。main は本番を変えない）。審査の録画は本番の版で撮るので、release までは録画の説明に響かない。
- 画面が Meta の取得物（数字・返信）を描くのは、今の道具の結果がすでに会話の client に渡っているのと同じ範囲。新しい受け手（外の AI 提供者）は増えない。Jev を使わない第 1 弾では privacy の 1 文の追加も要らない。
