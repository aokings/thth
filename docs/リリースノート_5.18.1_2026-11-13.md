## 直したこと 1: 記事の口座の leave

記事の口座の `token` は、主体（`thth principal`）の鍵のパスを写したものです（`thth/account_cli.py` の add・`principals.check_account` の 4）。鍵の持ち主は主体で、1 つの主体を複数の口座（ブログ）が使います。5.18.0 までの leave は、その鍵を口座の物として数えていたので、次のように止まっていました。

| 口座の形 | 5.18.0 の止まり方 |
|---|---|
| 主体と口座の名が同じ（雛形の `demo-wordpress`） | 主体の鍵を消す対象に入れ、`revoke()` が記事の媒体を知らず `remote_revoke_unsupported` で止まる（消す前に止まるので鍵は残っていた） |
| 名が違う（雛形の `demo-hatena` と `demo-hatenablog`） | `credential_ownership_unproved` で止まる |
| 同じ主体の口座がほかにある | 進むが「他 account と共有の接続」と言い、遠隔の取り消しの案内が違う |

5.18.1 では次のとおりです（`thth/leave.py`）。

- 記事の口座の `token` は主体の物として、消す対象に入れず、読みもしません。退出の記録の `preserved` に `principal_token` を残します。同じ主体のほかの口座の有無によりません。
- 口座の物（台帳・state・口座の env・管理する repo）は今までどおり消します。
- 遠隔の取り消しは本人の手として `unconfirmed_manual` で終えます。THTH が WordPress に送る道（投稿・カテゴリー・タグ・users/me）にも、はてなの AtomPub にも、取り消しは入っていません。
- 5.18.0 で止まった退出（主体の鍵を消す対象に入れたまま `remote_pending` で止まった row）は、同じ leave を打ち直すと続きから進み、主体の鍵は消す対象から外します。
- 退出の記録（変更ログの `account_removed`）に主体の名を残します。完了の案内が、打ち直しのときも主体の鍵のことを言えるようにするためです。鍵の値は残しません。

### 完了の案内

`remote_unconfirmed:` の 1 行を媒体ごとに分けました（前は Threads・Bluesky の決め打ちで、Facebook・Instagram の口座にも同じ行が出ていました）。記事の口座では、2 行めに主体の鍵のことを出します。

WordPress の口座（主体 `alpha-wp` をほかの口座が使っていない場合）:

```
local_complete: alpha
remote_unconfirmed: WordPress のアプリケーションパスワードの取り消しは本人の手です（THTH が WordPress に送る道は投稿・カテゴリー・タグ・users/me で、取り消しは入れていません）。WordPress の管理画面の「ユーザー」→「プロフィール」の「アプリケーションパスワード」で、THTH に入れたものを取り消してください
principal_token_kept: 主体 alpha-wp の鍵は残しました（鍵の持ち主は主体で、口座の leave では消しません）。この主体を使う口座はもうありません。消すなら thth principal auth alpha-wp --by <名前> --forget で消せます
```

はてなブログの口座（主体 `alpha-hatena` を `beta` も使っている場合）:

```
local_complete: alpha
remote_unconfirmed: はてなの連携の解除は本人の手です（THTH ははてなに連携を外す要求を送りません）。はてなのアカウントの設定の連携アプリ（OAuth で許したアプリ）から THTH を外してください
principal_token_kept: 主体 alpha-hatena の鍵は残しました（鍵の持ち主は主体で、口座の leave では消しません）。この主体はまだ beta が使っています。消すとそちらも出せなくなるので、使い終わってから thth principal auth alpha-hatena --by <名前> --forget（consumer も消すなら --forget-consumer） で消せます
```

主体の鍵のファイルがもう無いときは「鍵のファイルはもうありません（消す物はありません）」と、主体の台帳が読めないときは `thth principal show <主体>` で確かめるように言います。

## 直したこと 2: WordPress の内向きのアドレス（6760757）

- 台帳を読む時点（`principals.valid_site_url`）: 試しの印（`THTH_TEST_ALLOW_HTTP=1`）が無ければ、loopback・`localhost`・IP の形のホスト（`0x7f.0.0.1`・`127.1` のように OS が IP と読む形も）を断ります（`site_url_invalid`）。site_url の欄が無い行も、blog_id が IP の形なら断ります。
- 送る時点（`httpsafe.public_opener()`）: 名前を引いた答えを全部見て、loopback・私用の網・link-local（169.254 のメタデータの口）・CGNAT・予約・マルチキャストなどが 1 つでもあれば、つながずに `wordpress_endpoint_rejected` で断ります。IPv6 の中の IPv4 もほどいて見ます。確かめた IP へそのままつなぎ（TLS の名前と Host は元の名前のまま）、名前を引き直さないので、答えを替える手（rebinding）の窓がありません。
- 使うのは WordPress の口だけです（`via=` を渡してよい所に `thth/adapters/wordpress.py` を足した）。店の口は定数のホストなので今のままです。
- 残る穴: 外のサイトが自分の側から内側へ取りに行くことは防げません。6to4（2002::/16）はすべて内向きとして断ります。

## 直したこと 3: 店の値段の上下（160c664）

- 比べるのは、前の写しと今の両方にある種類だけです。1 つでも下がりどれも上がっていなければ `price_down`、逆なら `price_up`、混ざれば `price_changed`（下書きは作らない）。種類の増減は `variants_changed`（下書きは作らない）。
- 写しと下書きに、Shopify と STORES では種類ごとの値段と ID を持ちます（下書きは 50 種類まで）。BASE は今までどおりです。
- 前の版の写しを読む最初の 1 回は上下を言わず `price_changed`（`snapshot_without_variants`）にし、`--accept` で写しを進めれば次から種類ごとに比べると知らせます（`diff --json` の `variant_note`）。
- 承認の読み直しは、下書きの頭の `from_store_variant_prices` で種類ごとに比べます。種類が増えた・減っただけなら知らせて通し、種類が減った値下げの下書きは断ります。
- Shopify の商品の問い合わせに種類（`variants(first: 20)`）を足しました。文は定数 2 本・変数は `first` と `after`・権限は `read_products` のままです。

## 直したこと 4: 販売が始まった（f6a0f69）

## 直したこと 6: remove の競り合い（c8e7cf8・6edee56）

- `remove.execute` は鎖を取ったあと一覧を作り直し、機械が既定の置き場に書く物（短い鍵・状態の置き場）は、確かめた一覧に無くても消します。人が確かめた物（鍵・台帳・残す物）が鎖の中で増えていたら、何も消さずに `store_remove_unconfirmed` にします。
- 文字の表示も、鎖の中で消した一覧に無い物を「消しました: 短い鍵（一段目のあと、取り直しの途中に書かれた物）」と言います。

## 直したこと 7: Shopify の点数（4e4dd4d）
