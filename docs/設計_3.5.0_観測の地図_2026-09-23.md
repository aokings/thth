# 設計 3.5.0: 観測の地図——話題（観測軸）をつないだ形で、集計の定点観測を持つ

2026-09-23 22:30。masaru「（集計値だけの定点観測を）1。トピックなどの観測軸に対してトポロジー的にデータを持たせたい」。

## 0. 約束（1 行）

**話題を「点」、話題どうしのつながりを「線」として、日ごとの集計値だけを積む。** 本文・投稿 ID・投稿者は 1 つも残さない。自分の投稿と広場の書き込みも同じ点に結ぶ。

## 1. 形（トポロジー）

- **点（観測軸）**: 監視語（`watch_words`）と、`thth topics` の話題の語彙。project ごとの集合。点は人が足す・消す（`thth admin map node add|remove <project> <語> --by`）。道具が他人の投稿から語を拾って点を増やすことは**しない**（他人の文から作った派生データを持たない・§5）。
- **線は 2 種類**:
  - `broader`／`narrower`（包含）: 「スペシャルティコーヒー ⊂ コーヒー」。人が張る（LLM が候補を出し、人が `--by` で確定）。
  - `co`（共起）: 点 A の検索結果のうち、点 B の語も含む投稿の本数。**数えるのはその場だけ**で、残すのは本数と分母。
- **層**: 同じ点に 3 つの層を重ねる。
  1. 世間の層（媒体ごと・日ごと）: 件数/要求数・異なり投稿者/username のある件数・上位 3 の占有率・直近の投稿までの時間（時刻そのものではなく時間差を丸めて）。
  2. 自分の層: その話題（`topic`）で出した投稿の数と、`measured` の views・likes・replies の中央値と n（自分の台帳から・既存の口）。
  3. 広場の層（3.4.0）: その話題に結んだ施策・気づき・追試の数と判定。

## 2. 集め方

- 1 日 1 回（`thth map collect <project>` を timer で・既定は**無効**・§6）。点ごとに媒体の検索を 1 回（Threads は `keyword_search`・Bluesky／Mastodon は既存の `where` と同じ口）。点が N 個なら 1 日 N 回×媒体。上限は project あたり 20 点。
- 共起は、点 A の検索結果（メモリの中）に点 B の語が含まれるかを数えて捨てる。**別の検索を増やさない**。
- 保存: VM の私有 `state/_map/<project>/<YYYY-MM>.ndjson`（0600）。1 行 = `{date, medium, node, n, requested, distinct, with_username, top3_share, latest_age_bucket}` か `{date, medium, edge: [A, B], co, denominator}`。**本文・post_id・username・author_key・permalink・時刻の生値は入れない**（試験と leak probe で固定）。
- 保持: 既定 180 日（`thth admin map retention <project> <日数> --by`）。超えた月は消す。退出で project の地図を消す。

## 3. 見方

- `thth map show <project> [--node <語>] [--since 30d] [--json]`: 点ごとの推移（層ごと）・隣り合う点（共起の強い順・包含）・変化の大きい線。
- `thth observe` に 1 行: 「地図: 伸びた点 <語>（+n%）・強まった線 <A>—<B>」（候補の列挙だけ・本文は作らない）。
- MCP `thth_map_show`（読むだけ）。
- 数字には分母・欠測は null と理由（`provider_timeout`・`budget_exhausted` 等）。

## 4. 段取り（ここが肝）

1. **先に出せるもの**（Meta の規約の論点が無い）: 点と包含の線の管理・自分の層・広場の層・`map show`。自分の台帳と広場だけから作る。
2. **規約の照合をやり直す**（下の §5）。材料は別の文書（`docs/照合_観測の地図_集計の定点観測_<日付>.md`）にまとめる。
3. 照合の結論が「集計値だけなら可・再審査不要」なら世間の層と共起を有効にする。「再審査が要る」なら Meta に説明を出す（masaru の判断）。それまで `map collect` の世間の層は**実装はしても既定で無効**（`THTH_MAP_WORLD=1` を管理者が入れたときだけ動く）。

## 5. 規約の論点（照合で確かめること）

- 審査のときの説明: 「検索は投稿者の異なり数・直近時刻・タグの割合といった集計だけを出す。本文は画面に 1 度出すだけで保存しない」。定点観測は「自動で毎日」「集計の履歴を持つ」という**追加の処理**になる。Platform Terms §3(a)(vii)（重要な変更の事前再審査）に当たるか。
- 集計値だけ（本文・ID・投稿者なし）の履歴が、Platform Terms §12(l) の個人データ（匿名化・集計・派生を含む）に当たるか。当たる場合の保持と削除の条件（§3(d)）。
- 共起の本数は「他人の投稿から作った派生データ」か。点の語は人が決めたもので、数えるのはその場だけ。
- Bluesky・Mastodon は Meta の規約の外だが、各サーバの利用規約と robots の扱いを同じ文書で確かめる。
- 2026-09-18 の照合（`docs/照合_MetaPlatformTerms_枝と語の観測_2026-09-18_Codex.md`）の保留理由（生データを保存しない実装が未実装・削除追随の方式が未定義）に、この設計がどう答えるか。

## 6. 試験

点と線の管理（人だけが足せる・上限・`--by`）・自分の層（既存の measured と一致）・広場の層・保存行に禁止項目が無い（leak probe）・保持で消える・退出で消える・世間の層が既定で動かない・共起の数え方（fake の検索結果）・`map show` の分母と null。単変異: 保存行に post_id を入れる／世間の層を既定で有効にする／共起で追加の検索をする／保持を無視する。

## 7. 判断（主セッションで決めたもの）

- 点は人が決める（道具が他人の文から語を拾わない）。
- 世間の層は照合が済むまで既定で無効。自分の層・広場の層・形（点と線）は先に出す。
- 版は 3.5.0（3.4.0 の次）。

masaru に残る判断は 1 つだけ: 照合の結論が「再審査が要る」だったときに、Meta に説明を出すかどうか（その時に材料を添えて伺う）。

## 8. 照合の結果を受けて足す条件（`docs/照合_観測の地図_集計の定点観測_2026-09-23.md`・09-23 23:10）

- 集計の履歴は Platform Data に**当たる**（T §12(l) の aggregated/derived）。保持は条件付きで可。再審査が要るかは条文から決められない（判断できない）。**審査の説明と privacy ページがいまの実態（運営者の VM・検索）と合っていない**ので、世間の層を有効にする前に両方を直す（3.5.0 とは別に、今すぐ直すべき既存の不一致）。
- 足す条件（照合 §6 の 11 項目を採る）: 小標本（n・distinct・co が 5 未満）は null・`small_sample`／点に @ハンドル・個人名・URL を入れさせない／search_type・limit・期間を固定して記録・0 件は `zero_or_filtered`／保持は日単位で削る／git に入れない・削除でバックアップやログも消える試験／削除要求の受付と project・期間単位の全消去／世間の層は project の中だけ（広場の外向け・他の持ち主・横断集計に出さない）／外部 LLM に渡すなら Service Provider 条件／Dashboard と privacy を直すまで `THTH_MAP_WORLD` は無効／Threads は API だけ（Web の自動取得はしない）／Mastodon の件数は「そのサーバで検索に出た数」と表示。
