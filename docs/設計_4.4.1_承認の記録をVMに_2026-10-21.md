### 監査（Fable 10/21）のあとに直したこと

公開まで抜ける道は見つからなかった。次を直した。
- 台帳が読めないとき、`cmd_revoke`・`server_writes.cancel_schedule` は status を見る前に断る（文言は「台帳が読めないので
  取り消しを受け付けられません」・thth.me は `ledger_unavailable`）。前は「承認されていません」・`already_draft` を返し、
  台帳を直すと承認が生き返った。

- `require_gate: true` の口座では、台帳に記録の無い repo の `status: approved` を draft に倒す（印 `approval_gate_missing`）。
  口座の台帳は `approval_ledger._requires_gate()` が JSON を直に読む（stat で控える・無ければ False・読めなければ True）。
- `require_gate: true` の口座では、`thth send --production`（`core.send_once` の入口）と thth.me の `send_request`
  （`server_writes.direct` の入口・その場・猶予・burst）も番号を求める（`approval_ledger.gate_refusal()`・`approval_gate_required`）。
  どちらも draft_put・repo への commit・ロックより前に断る。burst の順番待ちの `record` に gate を渡す。遠くの道の
  `thth send --approval` も VM に渡す。

## 決めたこと（推しで決めた所は【推し】）

- 置き場は `state/<account>/approvals.json`（口座ごと）。鍵は repo の中の相対パス（clone が違っても同じ原稿）。
- 読む側は重ねて見せる（overlay）。**台帳が repo の承認より優先**。台帳に何も無ければ repo のまま
  （移行期間: 4.4.0 までに repo に書いた承認はそのまま効く。新しくは repo に書かない）。
- 原稿が後で変わったら、select が今までどおり指紋で `approval_stale`（fail-closed は同じ）。
- 取り消しも台帳（repo の古い `status: approved` も台帳の取り消しで draft に見える）。
- 出たあとの原稿（post_id あり）は status を変えず、承認の控え（approved_sha・delivery など）が repo に無ければ足して見せるだけ。
- 【推し】台帳が読めないときは、その口座の「まだ出ていない承認済み」を draft に倒して見せ、承認・取り消しは断る。
- 【推し】承認の時点で原稿が commit と違えば断る（4.4.0 までは確定が原稿ごと commit していたので VM で直したものも通った）。
- 【推し】⑦ は「番号を必ず受け取り、形を見て、台帳に残す」まで。`hub approve verify` は THTH から呼ばない
  （verify の `--target` は承認ごとの自由な文で THTH には作れない。4.4.3 の「`--approval` で verify と close まで」で扱う）。
  鍵の名前は `require_gate`（例にあった `approval.require_gate` は、3.12.0 の古い項目 `approval` を読まずに通す決まりと
  ぶつかるので、上の段に置いた）。
- 【推し】burst の順番待ちも承認は台帳へ（原稿を新しく置く commit は今までどおり 1 本）。

## 問いの行方（親が 10/21 に決めた）

1. repo で人が status を approved 以外に書き戻した原稿は、台帳に承認があっても出さない（fail-closed）→ 作った（上の 5）。
2. VM で直しただけの原稿は承認を断る・文言は「手元で commit・push してから」→ 作った（上の 6）。

4. account を書き換えたときの手がかり → 文言に足した（上の 7）。
