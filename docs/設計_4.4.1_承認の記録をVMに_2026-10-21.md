## 決めたこと（推しで決めた所は【推し】）

- 置き場は `state/<account>/approvals.json`（口座ごと）。鍵は repo の中の相対パス（clone が違っても同じ原稿）。
- 読む側は重ねて見せる（overlay）。**台帳が repo の承認より優先**。台帳に何も無ければ repo のまま
  （移行期間: 4.4.0 までに repo に書いた承認はそのまま効く。新しくは repo に書かない）。
- 原稿が後で変わったら、select が今までどおり指紋で `approval_stale`（fail-closed は同じ）。
- 取り消しも台帳（repo の古い `status: approved` も台帳の取り消しで draft に見える）。
- 出たあとの原稿（post_id あり）は status を変えず、承認の控え（approved_sha・delivery など）が repo に無ければ足して見せるだけ。
- 【推し】台帳が読めないときは、その口座の「まだ出ていない承認済み」を draft に倒して見せ、承認・取り消しは断る。
- 【推し】承認の時点で原稿が commit と違えば断る（4.4.0 までは確定が原稿ごと commit していたので VM で直したものも通った）。
- 【推し】⑦ は「番号を必ず受け取り、形を見て、台帳に残す」まで。`hub approve verify` は THTH から呼ばない
  （verify の `--target` は承認ごとの自由な文で THTH には作れない。4.4.3 の「`--approval` で verify と close まで」で扱う）。
  鍵の名前は `require_gate`（例にあった `approval.require_gate` は、3.12.0 の古い項目 `approval` を読まずに通す決まりと
  ぶつかるので、上の段に置いた）。
- 【推し】burst の順番待ちも承認は台帳へ（原稿を新しく置く commit は今までどおり 1 本）。

## 決めきれていない問い（親に問う）

1. **人が repo で `status: draft` に戻しても止まらなくなる。** 4.4.0 までは repo の `status: approved` を手で draft に
   戻せば止まった。いまは repo は元から draft なので、止めるには `thth revoke`・thth.me の取り消し・status を
   draft／approved 以外にする・中身を変える（approval_stale）のどれか。これでよいか。
2. **VM で直した原稿を、そのまま承認できなくなる**（commit と違えば断る）。手元で commit・push してから承認する形。
   4.4.2（手元のファイルを読む）とつながる。これでよいか。
3. **投稿の書き戻し（status: posted・post_id）の commit は残る。** 今回は「承認の確定」だけを台帳にした。
   投稿・はてなの公開・incident の記録も利用者の repo に commit を積むので、配信の承認の先頭はそこでもずれうる。
   同じ考えで台帳に移すかは別の版で決める必要がある。
4. 原稿の account を書き換えると、新しい口座の台帳には承認が無いので「承認されていない」に見える（approval_stale ではない）。
   出ないことは同じ。board の言い方として足りるか。
