# 分析レポート schema v1

2.5.0 から入っているローカル機能。
既存の `after.answer` による集計を、LLM が再利用できる固定形式で包む。
サーバ、定期配信、前週比較、因果分析、推奨行動は今回の範囲に含まない。

## 呼び出し

```sh
thth analytics-report my-account --window-days 7 --min-n 5 --json
thth analytics-report --project my-project --window-days 7 --min-n 5
```

MCP `analytics_report` に渡す引数例:

```json
{"project": "my-project", "window_days": 7, "min_n": 5}
```

account / project はどちらか一方必須。project 内の account は別々に返し、
合計・媒体横断の順位は作らない。未知 project、読める account がない project は
エラー。既知の account に記録がない場合は、母数 0 と欠測・不足理由を返す。
window_days / min_n は 1 以上の整数（bool 不可）。既定は 7 日 / 5 件。
CLI は既定 Markdown、`--json` で JSON、MCP は同じ CLI の JSON を返す。

ローカルの account 設定と台帳を読むだけ。収集 API を呼ばず、git、原稿、承認、
台帳、アカウント設定を書き換えない。保存が必要な場合は利用者が出力を保存する。
本文・username・トークンを追加取得しない。投稿 ID、仮名 author_key、topic は
既存 after と同じ根拠データとして含む。

## JSON の契約

| フィールド | 内容 |
|---|---|
| `schema_version` | 整数 `1` |
| `report_type` | `activity_snapshot` |
| `generated_at` | 生成時刻、秒精度 ISO 8601、JST `+09:00` |
| `data_updated_at` | 現段階は `null`。生成時刻をデータの更新時刻と見なさない |
| `data_updated_at_reason` | 複数台帳の最終更新時刻を検証していない旨 |
| `period` | `start` / `end` / `start_inclusive=true` / `end_inclusive=true` / `timezone=Asia/Tokyo` / `basis=posted_at` / `window_days` / `mode=rolling` |
| `filters` | `account` / `project`。指定しなかった方は `null` |
| `min_n` | 中央値を返すための最小母数 |
| `by_account` | account 名をキーとする独立した集計 |
| `cannot_say` | project 解決時に読めなかった設定など、全体の制約 |
| `limitations` | 指標解釈・比較範囲についての固定の制約 |
| `provenance` | `source=own-ledgers` / `calculation=after.answer` / `advice=excluded` |

期間は生成時刻から正確に N 日さかのぼる rolling window。
暦週ではない。`posted_at` が開始・終了の両境界を含む投稿を数える。
計測された時刻をこの期間で切り出しているわけではない。
隣接したレポートを足し合わせると境界が重複し得るので合計しない。

各 `by_account` 節は既存 `after` の `summary` / `posts` / `engagements` /
`comparable` / `cannot_say` / `provenance` を保持する。
`posts.by_post` と `engagements.by_branch` に個々の根拠を保持する。
新たな集計式はない。`one_thing_to_change` は経験則による提案なので除外する。
既存 `provenance.updated` は生成時刻であり、レポートでは誤読を防ぐため除外する。
台帳破損・所有不明・時刻不明・欠測・母数不足は既存 after の `cannot_say` を維持する。

## LLM が守る解釈

1. まず `period` / `filters` / `min_n` / `limitations` を読む。
2. account ごとの `summary` と `cannot_say` を読む。
3. 必要な主張だけ `by_post` / `by_branch` の投稿 ID と測定条件に戻って確認する。
4. 母数や欠測を省かず、観測された差と原因の推測を区別する。

投稿の母集団は **所有が確認できた実測台帳の根投稿**。
SNS に存在する全投稿を網羅するとは限らない。`covered=false` / `null` は 0 ではない。
中央値の `n` は有効な指標が得られた件数であり、投稿総数とは異なる。

`marks=24` は正確な経過 24 時間を保証しない。
根投稿の `age_hours` / `marks_collapsed` も確認する。
返信の `replies_back_24h` は実測がない場合に返信台帳の累積件数へ
フォールバックするため、すべて 24 時間内の値とは限らない。
`reacted` は既存ロジックで観測された反応あり件数。
欠測を無反応と断定したり、母数から引いて反応なし人数に変換したりしない。

Markdown は同じ payload から期間・母数・中央値・不足理由・制約を要約し、
続いて字下げ JSON として全項目掲載する。
人向けの高度な編集済み週報ではなく、根拠・制約を欠落させず共有する最初の形式。
文字列を見出しや HTML として実行せず、投稿本文や username を読み足さない。
将来の互換性を壊す変更は schema_version を変更する。

## 前期間比較（V3-02）

`thth analytics-report ACCOUNT --compare-previous --window-days 7 --min-n 5 --json`
または MCP `analytics_report` の `compare_previous: true` を使う。
省略時は従来の `activity_snapshot` schema 1 を変えない。
比較は **`report_type: period_comparison`, `schema_version: 1`** という別契約。
利用側は report_type と schema_version の組で判別する。
Markdownも同一payloadから生成し、全文の構造化根拠を含む。

### 期間と母集団

生成時刻を一度固定し、投稿日時を基準に前期間 `[now-2N, now-N)` と
現在期間 `[now-N, now)` を比較する。開始を含み終了を含まないため境界の投稿は
重複しない。境界は Asia/Tokyo、Nはwindow_days。account・媒体を混ぜない。
根投稿は既存measured loaderが行のaccountで所有を確認し、根/返信を区別できる
実測投稿だけ。行間で返信分類やsourceが競合するものも根から除く。
根はsource=queue（既存loaderの旧形式既定を含む）に限定する。
絡み台帳にあるIDは根から除く。返信はaccount一致の絡み台帳を
母集団にし、同じIDを一度だけ数える。日時不正や重複IDで日時が競合した記録は
excluded_recordsに理由別件数を出す。SNS上の全投稿数ではない。

### 測定条件

- posted_atとcollected_atはtimezone付きISO日時としてparseする。
- 行自身のposted_atも投稿単位の日時と一致することを確かめる。
- collected_atが生成時刻を超える観測は使用しない。
- 差から計算した実経過時間が **24時間以上30時間未満**、marksが単独の24、
  collapsedでない観測だけ使用する。保存済みage_hoursは信用せず再計算する。
- 条件を満たす観測が複数あれば、実際の日時が最も早い一行を採用する。
  同時刻は行内容のソート順で固定する。後の行で欠測指標を補完しない。
- views/likes/repliesは有限・非負の数値だけ採用する。boolean・不正値はnull。
  返信台帳の累積件数による補完はしない。

母集団ごとにn_total、時間条件を満たすn_eligible、満たさないn_missingを出す。
n_missingは生成時点で24時間未満のn_immatureと、それ以外のn_incompleteに分ける。
各指標にも別途n_eligible/n_missingを出すため、時間条件は満たすがviewsが欠測という
状態を区別できる。evidenceにはID・投稿日時・採用観測時刻・実経過時間・値・
除外観測の理由別件数を保持する。本文やusernameは返さない。

両期間の当該指標の有効nがmin_n以上のときだけ中央値の差（現在−前期間）を返す。
ゼロは実測ゼロとして扱い、百分率は算出しない。欠測をゼロに置き換えない。
comparableは測定時間帯と最小母数の条件だけを指す。型・変更理由等を評価する既存の
`measured.comparability`とは別であり、施策の効果や因果関係の証明ではない。

`data_updated_at`は採用観測の最大collected_at、採用観測がなければnull。
`data_updated_at_scope: selected_observations`であり、全台帳の鮮度や最終採取試行を
表さない。壊れた台帳はincomplete_sources/cannot_sayに明示し、loaderが読めない
型の不正はエラーとして返す。読むだけで、採取・API通信・git操作・保存は行わない。

実測台帳と絡み台帳の投稿時刻が食い違う返信は `conflicting_measured_engagement_posted_at` に数え、返信母集団・欠測件数から除外する。

## schema_version 1 で追加された鍵（2.6.0）

A1: `posts.by_mark`, `posts.marks_by_post`, snapshot の各 `by_post[].marks`、比較・施策の各母集団の `by_mark` / `marks_by_post`。刻みは collect の表と同じ。各帯は `[mark, mark*1.25)`、最初の適格観測だけ。根の識別不能な旧 snapshot 行の marks は null。集計は所有確認済み根だけ。欠測は null、率・媒体間合計はない。

A5: 中央値の隣の `iqr/min/max/spread_reason`。指標ごとの n < min_n は全て null、n<4 は IQR のみ null。`measurement.quartile_method=tukey_hinges`、`quartile_algorithm=median_of_halves_excluding_odd_center`。昇順上下半分の中央値、奇数中央は除く。

A8: cannot_say_details は cannot_say と同順・同文の `{code,text}`。既存文字列は保持する。以下は同一語彙表（種類で区別）:

A2: `engagements.by_thread[]` は root_post ID 別の自分の replies。各返信に strict `marks` / `metrics_24h`、`author_replied_back`、`first_reaction_hours`。反応は相手と確認できる直接返信時刻のみ（like 時刻ではない）。author は返信先の仮名であり根作者とは限らない。未取得・識別不足は null。`by_thread_strata` は topic/form/hour_band 別 n と指標中央値・散らばり。root 不明・矛盾宣言を無理にまとめない。比較での by_thread は現在期間を対象とする。

A3: account ごとの `collection: {last_success_at,last_attempt_at,last_attempt_ok,source}`。採集 runs が無ければ null + collection_records_unavailable。status ok かつ collected が非負整数の採集完了だけ成功。ロック見送りは unknown。壊れた runs は coverage=incomplete + collection_records_incomplete。採集完了は新しい観測の存在を保証しない。既存 data_updated_at は不変。

A6: CLI `--compare-previous --by kind|hour_band|topic`、MCP/service/HTTP は `compare_previous:true, by:"..."`。各 population の `stratified` に previous/current/comparison と reconciliation（層の n_total 合計と全体）を追加。不明は unknown に保持。kind は現在の topic shelf の分類であり投稿当時の分類ではない。

A7: 根投稿の `shape_at`（24/72/168）。正確な cutoff 以前に採れた返信のみ。成功 fetch 不在・未到達は null。0 件取得成功は数値0。`last_observed_at` は最後に取得した時刻で cutoff ちょうどの完全な状態とは限らない。枝数/深さ/参加者/first_reply_min/author_reply_effect（既存 n<3 gate）を並べ、率・将来の growth/metrics は出さない。

追加理由コード: `collection_records_unavailable`, `collection_records_incomplete`, `collection_outcome_unknown`, `root_post_unknown`, `forecast_assumes_collection_runs`, `cursor_unreadable`, `no_previous_session_cursor`。運用の既存理由コード: `queue_missing`, `queue_unreadable`, `sent_unreadable`, `inflight_unreadable`, `notification_outbox_unreadable`, `run_notification_unreadable`, `timer_health_unknown`, `thread_runs_not_inspected`, `remote_queue_not_verified`, `approval_validity_not_verified`, `unresolved_replies_not_measured`。既存コードは元文字列を text に持つ。
