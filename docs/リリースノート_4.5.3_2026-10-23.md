# リリースノート 4.5.3（承認のやり直しの手数を減らす）

2026-10-23。[計画 4.4](計画_4.4_利用者の不満_2026-10-21.md) の 4.4.3（承認のやり直しの手数）を、版の数え方に合わせて 4.5.3 として出します。決め方は同じ計画の「4.4.3 の伺い」（本線と合意済み）。元の声は、こぴちゃ 第3 の 2・3・6（はてな記事 25 本の取り消しが 1 本ずつ、`while read` のループが 1 本で止まる、直すたびに取り消しからやり直し）。

## 変わったこと

- **`thth approve --digest-only`**: 1 段目で本文を出さず、束の digest を 1 行だけ標準出力に出します（hub の `hub approve ask --target` に渡す用）。ファイルを並べても digest は 1 つです。
  - lint の誤り（と、投稿済み・節が無い など）は標準エラーに出して終了コード 1。digest を出せたら 0。lint の警告・予定時刻の注意・確定に hub の番号が要ることは標準エラーに出ます。
  - `--json` を付けると、digest と lint の結果だけの JSON（`digest_only: true`・`bundle_digest`・ファイルごとの `digest`・`lint_warnings`。本文は入りません）。断るときも JSON を出します（`ok: false`・`problems`）。
  - `--confirm`・`--confirm-file` とは一緒に使えません（終了コード 2）。
  - 本文を人に見せるのは呼び手（hub）の側です。見せたあとで本文などが変われば、今までどおり `--confirm <digest>` は通りません。
- **`thth revoke` を複数本・ディレクトリ・`--account` に**:
  - ファイルを並べても、ディレクトリ（承認済みのものだけ拾う）でも渡せます。`-` を 1 つだけ渡すと、標準入力の 1 行に 1 本のパスを読みます。
  - 同期とロックは repo ごとに 1 回です。1 本ずつ結果を出し、取り消せない本（投稿済み・承認されていない など）は**その本だけ**断って、ほかは取り消します。1 本でも断れば終了コード 1。
  - `--account <口座>` を付けると、相対パスが別の repo と同じ名前でも、その口座の原稿に絞ります（「複数の repo に同じパス」で断っていた件）。`thth approve` の `--account` も同じ絞り方をします。
  - 1 本だけのときの出力（`--json` の形も）は今までと同じです。複数のときの `--json` は `revoked`・`refused`（理由つき）・`count`・`refused_count`。
- **標準入力は「-」を渡したときだけ読む（手元のラッパ）**: `while read f; do thth revoke "$f"; done < list` が 1 本で止まったのは、VM の thth ではなく、**手元のラッパ（`bin/thth-remote`＝`~/.local/bin/thth`）の ssh が標準入力を吸い上げていた**ためでした。ラッパは、引数に `-`・`…=-`・`--…stdin` があるときと、`send` で本文の引数（`--text`・`--text-file`・`--media`）が無いときだけ標準入力を VM へ渡し、それ以外は `ssh -n` にします。
  - VM の thth で、暗黙に標準入力を読むのは `thth send`（本文の引数が無いとき）だけでした。これは 4.4.2 で「`thth send <口座> … < <ファイル>` で通る」と案内した道なので残します（互換）。代わりに `--text-file -` でも標準入力を読めるようにしました（遠くの道の `send` も同じ）。
- **本文の差し替えは revoke 不要**: 承認済みの原稿の本文を直したら、`thth revoke` を挟まず `thth approve` の 2 段だけで承認し直せます（4.4.1 から確定が台帳の承認を新しい指紋で上書きするので、もとからできていました。試験で確かめました）。伝わっていなかったので、1 段目に「承認済みの原稿です（前の承認の時刻・名乗り・前の digest）。確定すると今の本文の承認に差し替わります（thth revoke は要りません）」と出すようにしました。`--json` では `replaces`。同じ中身のときは「同じ中身で承認済みです」と出ます。
  - ディレクトリを渡したときに拾うのは今までどおり下書きだけです。承認済みを承認し直すときは、ファイルを名指ししてください。
- **はてなブックマークの CLI の `--production` も `require_gate: true` に従う**: `thth bookmark add`・`delete`・`edit`・`batch` の 2 段目は、口座の台帳が `require_gate: true` なら hub の承認の番号（`--approval A261021-25`）が要ります。無ければ `approval_gate_required`、形が違えば `approval_invalid` で、打つ前（はてなに何も送らず、順番待ちにも置かない）に断ります。1 段目の「付けるなら」の命令に `--approval <番号>` が付きます。まとめて承認（batch）は番号をまとめのファイルに残します。thth.me の `bookmark_request`・`bookmark_batch_request`（Web の口）は求めません。`require_gate` の無い口座は今までどおりです。

## 入れなかったもの

- **THTH から hub を呼ぶこと**（`--approval` で hub の verify と close まで）。VM に hub は無く、THTH は外の人も使う道具なので、verify と close を一続きにするのは hub の側（hub が `thth approve --digest-only` と `thth approve --confirm` を包む）と決めました。

## 気をつけること（運用のレーンへ）

- **手元のラッパの差し替えが要ります。** 標準入力の直しは `bin/thth-remote` の中にあります。masaru の Mac の `~/.local/bin/thth` は、この版の `bin/thth-remote` で上書きするまで今のままです（VM の release とは別）。
- ブックマークに番号を求めるかは口座ごとに窓口が決めます（既定は求めない）。今 `require_gate: true` のはてなの口座はありません。

## 確かめた範囲

試験（全件）と柵 `tests/test_v453_approve_redo.py`（15 本）・`tests/test_v453_bookmark_gate.py`（7 本）。柵は 6 か所を 1 つずつ壊して赤を見ました（`--digest-only` の終了コード・`--account` の絞り込み・1 本目の断りで残りを止める・ラッパの `ssh -n`・前の承認の表示・ブックマークの gate）。手元のラッパは偽の ssh で確かめただけで、本物の ssh と VM では動かしていません。
