## 触ってはいけないもの・決まり

- `CLAUDE.md` のとおり。release の push は `git push origin "${sha}:refs/heads/release"`。試験は rc を見る（パイプを挟まない）。
- 公開は「台帳の承認 → `hub approve gate <id> --target <短い sha> --what "<ask と同じ文>" -- <台本>`」。
  - `--target` と `--what` は ask や record と同じ書き方にする。長い sha を渡すと `digest_mismatch` になる。
  - masaru が会話で言った承認は `hub approve record --said … --source … --replaces <頼みの番号>` で残す。
- auto mode は本番の push を止めることがある（10/21 の 4.4.0 の 1 回目）。止められたら別の書き方で通さず、止まって伺う。
- tag の push は、GitHub 側の一時の `remote rejected (failed)` がありうる。台本で 3 回まで押し直す形にしてある（scratchpad の release_4xx.sh の形）。
- VM の操作は `ssh wt 'env THTH_ROOT=/srv/thth /srv/thth/app/bin/thth …'`。
- お金が動くもの（X の予算）は、`hub approve record` で masaru の言葉を残してから gate を通す（A261022-3 の形）。
- 同じ checkout で運用のレーンも動く。`git add` はパスを明示する。push していない合流を main の checkout に置いたままにしない（運用のレーンの push に混ざる）。
- 秘密は `~/.config/thth/`（Mac と VM）。値を出さない。
