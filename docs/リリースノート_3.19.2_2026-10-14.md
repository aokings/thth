# リリースノート 3.19.2（X に書き込みを断られたら、自動の投稿を止める）

2026-10-14。

## 起きたこと

10/14 08:33 から、kopicha-x の予約投稿が X の投稿の口（`POST /2/tweets`）で 403 を返し続けた。runs には `x_publish_http_403: x_not_permitted` が 61 回残った。timer が 10 分ごとに同じ承認済みの原稿を投げ直したためである。読み取りは通っており、アカウント側の書き込みの制限（ロック）とみている。断られ続ける書き込みを投げ直すと、X の制限を長引かせるおそれがある。

## 変えたこと

- X が投稿を `x_not_permitted`（アカウント側の断り）で断ったら、その 1 回で、そのアカウントの**自動の投稿を止める**。止めた印は `state/<account>/publish_hold/held.json` に置く（0600・0700 の置き場・原子的な書き込み）。印が壊れていて読めないときは、止まっている側に倒す。
- 止まっている間、timer の run（`thth run`）はスレッド連投も含めて X に何も投げない。runs にも行を積まない（inflight で止まっている run と同じ扱い）。読み取り（採取）は今までどおり続ける。
- 手の `thth send` も、止まっている間は断る。下書きの確認（dry-run）の段から断る（inflight が残っているときと同じ流儀）。遠くの道の直接の公開は `account_stopped` で断る。
- 再開は人がする: X の画面で制限を解いてから `thth account resume <account> --by <名前>`。`--by` が無ければ断る。安全装置の止めを戻すのと同じ命令で、MCP からはできない。再開したあとも断られたら、1 回試しただけでまた止まる。
- 止まっていることは次の所で分かる:
  - 死活通知・運用通知の理由 `x_not_permitted`（次の一手 `fix_account_then_resume`）。止めたあとの run は同じ原稿の事象として束ねるので、運用通知のメールは増えない。
  - `thth board` の行（「自動の投稿を止めています」）と `--json` の `publish_hold`。
  - `thth morning` の今日の段（「自動の投稿を止めています: x_not_permitted」）。
  - `thth account status <account>`。
- 変更ログ（`_admin/accounts.ndjson`）に `publish_held`（止めた）と `publish_resumed`（戻した）を残す。

## 変えていないこと

- 対象は `x_not_permitted` だけ。`x_reply_not_engaged`（返信先に関わりが無い）と `x_duplicate_content`（同じ本文）は原稿ごとの問題なので、今までどおり止めない。
- X 以外の媒体は変えない。
- 安全装置の止め（`/activity` の「止める」・急な連投）とは別の印にした。あちらの理由の語は Worker の `/activity` が知っている語に限られ、増やすと Worker の出し直しが要るため。

## 判断したこと

- 手の `thth send` に「止まっていても 1 本だけ試す」指定は作らなかった。`thth account resume` で戻せば、断られた場合は 1 回でまた止まるので、それが 1 本だけ試すことに当たる。口を 2 つにしない。
