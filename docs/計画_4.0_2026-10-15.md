## 0. 一言で

**4.0 は「記事を 1 本書けば、ブログ・SNS・ブックマークへの出し方と、その後の反応まで THTH が持つ」道具にする。** あわせて、hub と h2d が名前で読める約束つきの JSON と出来事の口を出し、3.x で積もった名前と意味の食い違いを互換を崩してそろえる。

## 1. いまの THTH と、4.0 で変えたいこと

THTH は SNS（Threads・X・Bluesky・Mastodon）の「調べる・出す・測る」の CLI。利用者は自分の LLM から使う。人の承認なしの公開はしない・自動返信はしない・上限で暴走を止める、が芯。3.21〜3.22（10/15）で、媒体の原文が禁じていない絞りを外した（本文の全文・欄の追加・thth.me と MCP の口）。

出発点（masaru 10/13）は「フォロワーが 0 で、何を出しても反応が皆無な問題を破る」。点検と候補出しで見えたのは、**SNS の道具としての機能はもうほとんどある**こと。足りないのは次の 3 つ:

1. **「何のために出すか」＝記事が THTH の単位に無い**。投稿が記事と切れていて、SNS の数と記事の読まれ方（hub の検索・訪問の数）を結べない。反応ゼロの実体は「記事が読まれない」ことに近い。
2. **「いつ出すか」が人の予定（timer の時刻）にしか結びついていない**。世の中の出来事（値段の急変・発表）を起点に出す道が無い。
3. **人が手でやったこと（手の投稿・手の返信）が THTH の測りの外**にある。

## 2. 線引き（masaru 10/15 の決定）

| | THTH（声・ヘッドレス） | hub（場・見せる頭） | h2d（時と出来事） |
|---|---|---|---|
| SNS・ブログ・ブックマークへの読み書きと記録 | 持つ | — | — |
| 公開と予約（承認の二段・上限） | 持つ | — | 遅れ・止まりを見張って起こす |
| 記事の正本 | 持たない（どこに・どの版を出したかだけ） | — | — |
| ダッシュボード・媒体をまたいだ合計や順位 | **持たない**（材料を出すだけ） | **持つ** | — |
| 世の中の出来事を見張る・判定（Jev） | 持たない | — | **持つ** |
| 出来事を外に流す | **出す** | 受けて「行くべき所」に積む | 受けて起点にする |

- masaru「ダッシュボードやメディア間連携なんかは、ハブに譲っちゃう」（10/15）。
- Jev は向きで分ける（masaru 10/15）: **Jev → THTH**（判定・下書き・外の数字の分析・語の候補）は遠慮なく入れる。Platform Data ではないから。**THTH → Jev**（THTH が取った他人の投稿を渡す）は、Meta の条件（Platform Terms 3.c.ii・5.a）つきで、TypeSafe の規約の確認が先。

## 3. 4.0 の中身

### 3.1 目玉: 記事を正本に、届け先ごとに出し分け、直したら巻き取る

masaru 10/15「各媒体の記事部門の更新反映なんかを THTH で巻き取るのが良いのかも。コンテンツマーケティングセクションとして機能する感じ。新世代のブログツールみたいな」。

```
正本 = 記事（各レーンの repo の Markdown）
 → THTH が届け先ごとに出し分ける
     はてなブログ: 本文（AtomPub・予約・下書き）
     Threads／X／Bluesky／Mastodon: 告知と連投
     はてなブックマーク: セルクマ（自分の記事を自分の口座で・1 記事 1 回）
     （note は公開の投稿 API が無いので外す）
 → 記事を直したら、出した先の更新を巻き取る（ブログは書き換え、SNS は訂正か追記を人が選ぶ）
 → 記事ごとに反応を束ねる（SNS の数・クリック・ブックマークの数とコメント）→ 次の記事の種
```

- **新しさ**: 記事が単位であること（告知・連投・ブックマーク・ブログが 1 つの記事 id に結ばれる）。正本は利用者の repo に置き、THTH は写しを持たない。直したら巻き取る。反応が記事に戻る。既存の自動共有（題と URL を 1 本流すだけ）や Buffer 系（記事の単位が無い）には、この 4 つが無い（比較は案 §2-0）。
- **線**: THTH は流通と記録だけ。本文は repo（各レーンの LLM と人が書く）、画面は hub。「ブログツール」の言葉で THTH が本文や画面を持つ方へ膨らませない。
- **段階**:

| 段 | 中身 | 4.0 に |
|---|---|---|
| 0-1 | 記事の欄（原稿の `article`・`article_sha`）と、記事単位の束ね（`thth article`・`after --article`） | 入れる |
| 0-2 | 届け先の対応表と、記事から告知の原稿の雛形を置く口（本文は LLM） | 入れる |
| 0-3 | はてなブックマークの adapter（追加・削除・件数・コメント一覧）とセルクマ | 入れる（はてなの口座の決めが先・§5） |
| 0-4 | はてなブログの adapter（本文の公開・予約・書き換え・画像） | 4.0 の後半か 4.1 |
| 0-5 | 更新の追従（`thth article diff`・出した先ごとの候補・二段で確定） | 4.1 |

- **確かめる仮説（はてな）**: masaru の見立て「はてなブログのオーナーははてブの利用者でもあるので、はてなブログで露出すればブックマークをもらいやすい。最初の数件で新着に出れば、さらに広がる」。公式の仕組みとしては書かれていない（人気・新着の条件の公式の記述は「一定期間に多く集めた」「一定数以上」まで・調べ §3-4）。THTH は件数の API で記事ごとのブックマーク数の推移を測れる。はてなブログに出した記事と、SNS の告知だけの記事とで付き方を比べ、仮説を数で確かめる。露出を増やすために読者登録やスターを機械でばらまくことはしない。

### 3.2 出来事から投稿を起こす（推し 2）

masaru 10/15「コーヒーの値段が凄い上がったり、下がったりしたら、スレッズに報告したり出来ますよね？」。

- 流れ: h2d の感知（`http_json` のしきい値・`command_json`）→ 条件（`judge` で Jev に「流す価値があるか」）→ レーンの LLM を起こし、材料つきで下書き → THTH の承認の二段で人が出す。
- THTH 側に足す口: 下書きの出どころの欄 `origin`（承認の指紋には入れない・あとで「出来事起点の投稿」を測るため）、外から下書きや語の候補を置く口（Jev → THTH の受け口）。
- 公開の段は 3 案: (a) 下書きまで自動で、出すのは人／(b) Jev の「はい」で出す／(c) 型を前もって承認しておく（数値の差し込みだけ・上限・期限・止める口）。**推しは (a) で 1 か月回し、そのまま出せた率を見てから (c) を設計する。(b) は推さない**（人の承認なしの公開は THTH の芯に反する）。
- 値段の出どころ: kopicha の観測所の価格の履歴がいちばん確か。アラビカ先物を規約上使える API は未確認。
- 同じ型が他のレーンにも効く（関東の倍率の発表・music-research の新譜・headlesson の版）。記事の種の入口として 3.1 につながる。

### 3.3 柱 1: 約束つきの JSON と出来事の口（hub と h2d の両方に効く）

- `observe --json` などに版（schema）と名前つきの節を持たせる。今は hub も h2d も THTH の出力を**並び順**（`sections[4]` など）で読んでいて、THTH が表示を変えると両方が読めなくなる（10/9 地図 §4 の 1 番）。
- `thth events --since`（出来事の流れ: 新しい返信・言及・止まった口座・予算切れ・inflight・反応の急増・記事の公開）と `thth summary`（数の要約）。
- `collect`・`run` の終わりに、`h2d fires record` と `hub status post` で出来事を押す（h2d の起点・hub の「行くべき所」になる）。
- 古い並びは 1 版だけ残し、hub と h2d の担当に移ってもらう。

### 3.4 柱 2: 互換を崩してそろえる（4.0 でしかできない）

- **答えの欄の名前**: 同じ意味で名前が違う組が 13、同じ名前で意味が違うものが 12（調べ_JSONの欄）。壊れる範囲が大きいのは、時刻・断りの形・`post_id` の意味・件数・返信まわりの 5 組。3.18.0 と同じ「足して残す → 非推奨 → 4.0 で外す」で進め、台帳（ndjson）の鍵は変えない。
- **道ごとの意味**: 手元・thth.me・MCP で同じ命令の意味が違っていた。10/15 に誤送信（thth.me の `send` が `--production` 無しで出た）が起き、次は直した。
  - 3.21.1: thth.me の `send` は `--production` が無ければ出さない。
  - main `f9820bd`: thth.me の道が読まない旗は黙って捨てずに断る。`retract --already-gone` が本当に消す、`send --community` がタイムラインに出る、を止めた。
  - main（試験中）: thth.me の `retract` も二段にする。

  残りは、手元の `retract` に安全装置を掛ける、`schedule` の意味、help を道ごとに書き分ける、`account status` に止めの理由を載せる（調べ_道ごとの意味の差 §5）。

### 3.5 そのほかの候補（4.0 の中で順に）

- **A. 手で出したものも測る**（推し 3）: `collect` の母集団が THTH が出した投稿だけで、手の投稿・手の返信が `after`・`study` の分母に入っていない。
- **C. 届いているかの確かめ**: 自分の投稿が検索に出るかを確かめ、「届いていない」と「見られていない」を分ける（X の「人間か確認」中など）。
- **E. 出す前の点検**: おすすめに載りにくい形（同じ書き出し・@ の多さ）を lint で警告する。
- **B. 会話の受信箱・D. 試しを道具が回す**: 価値はあるが、既存の `unanswered`・`study` の言い換えにならない形が固まってから。

## 5. 決めること（masaru）

1. **はてなの口座をレーンごとにどう持つか**: レーンごとに別の主アカウントか、1 人の副アカウントか。規約の読みが割れる（主は原則 1 つ・副で同じページをブックマークするのは「過剰な最適化」・調べ §3-2）。作る前にはてなのサポートへ確かめるのを推す。どちらにしても「1 記事にブックマークするのは、出したレーンの 1 口座だけ」の柵を道具で持つ。
2. **出来事起点の公開の段**: (a) から始めて (c) を後で設計する、でよいか。
3. **Jev に THTH の取得物を渡す件**: TypeSafe の規約（入力を学習に使わない・保持期間）を確かめるか。Jev → THTH の向きは決定済み（遠慮なく）。
4. **4.0 の時期**: 14 日の判定（10/27〜28）のあと、11 月前半でよいか。

## 6. 外部レビューで見てほしいこと

1. **目玉（3.1）は「反応ゼロを破る」に効くか**。記事を単位にすることが SNS の反応の薄さの解になるのか、それとも別の問題（中身・相手選び）を見落としていないか。
2. **線引き（§2）は保てるか**。THTH が「ブログツール」として本文や画面を持つ方へ膨らむ危険を、この設計で防げているか。
3. **はてなの使い方（セルクマ・レーンごとの口座）**は規約と場の空気の両方で問題ないか。スパムに見える筋は無いか。
4. **出来事起点の (a)→(c) の進め方**は安全か。(c) で固定すべきものに抜けは無いか。
5. **互換を崩す範囲**（3.4）は適切か。足して残す期間・外す順・利用者（各レーンの LLM・hub・h2d）への知らせ方。
6. **順と時期（§4）**は無理が無いか。ほかに 4.0 に入れるべき・外すべきものは無いか。

確かめた深さ: 材料の 5 本はコードと repo を読んだもの（L1）と、媒体の公式の頁を読んだもの（L2）。実機では何も試していない。はてなの一部（フォトライフの OAuth・回数の上限・人気の条件）とアラビカ先物の API は未確認。
