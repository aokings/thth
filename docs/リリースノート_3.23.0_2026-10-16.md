# リリースノート 3.23.0（4.0 の柱の「足す」側・道ごとの意味の残り）

2026-10-16。[計画_4.0](計画_4.0_2026-10-15.md) の段「10/16〜の 3.x」のうち、外部レビュー（[レビュー](レビュー_計画4.0_外部_2026-10-16.md)）を待たずにできる分。どれも**足すだけ**で、既存の `--json` の鍵と並びは変えていない（安全装置の追加を除く）。

## 約束つきの JSON と出来事の記録（4.0 の柱 1）

- `observe --json` に `schema: "thth.observe/1"` と `sections_by_name.<名前>`（tool・unanswered・yesterday・world・today・next_steps）。hub と h2d が今の並び（`sections[4]` など）で読んでいる値が、名前でも同じに引けることを試験で固定した。並びの `sections` はそのまま残す（4.0 で、移行の確認と予告のあとに外す）。
- `board --json` に `schema: "thth.board/1"`。
- **`thth events <口座|project> [--since 24h] [--after <next_cursor>] [--json]`**: 記録（sent・返信の台帳・inbox・guard・publish_hold・inflight・X の予算）を読むだけで、出来事を並べる。各行に安定した `event_id`・`occurred_at`（発生）・`recorded_at`（記録）・`schema`。`--after` と答えの `next_cursor` で、遅れて記録された出来事も取りこぼさず、二度は返さない。他人の本文・username は入れない。受け手は `event_id` で重複を除く。
- **`thth summary <口座|project> [--json]`**（`thth.summary/1`）: 24h・7d の公開数と取り下げ数・反応の和・返していない返信の数・フォロワーの最新と前日差・止まっているか。
- 手元の MCP（`thth_events`・`thth_summary`）、サーバ型 MCP と thth.me の道にも出した。

## 道ごとの意味の残り

- **手元の `thth retract` にも安全装置**（1 日の削除の上限・急な連投・止まった口座）を、確認の番号が一致したあと・DELETE の直前に掛ける（`thth send` と同じ作り）。`--already-gone`（DELETE を呼ばない）には掛けない。**止まった口座の投稿を運営者が消すときは、先に `thth account resume <口座> --by <名前>` が要る。** モード 775 の置き場では、口座を止めずにその 1 件を断る。
- `account status`（thth.me の道と MCP も）に `publish_hold`（媒体の断りで止めた自動の投稿）を載せ、止めているのに「動いています」と出ていたのを直した。
- help を道ごとに書き分けた（send・retract・schedule に「thth.me の道では…」を 1 句ずつ）。
- thth.me の道の `schedule --at` は 5 分より過去を断る。サーバは読めない予約の時刻を「今」に倒さず断り、過去の時刻の 1 日の上限は今日の分として数える。
- 答えの別名（古い名前は残す）: `medium`（account・budget）、`permalink`（retract）、`usd_estimate`（X の費用の目安）、最上位の `generated_at`（thread・where・who・after・list show・community・trends・counts）。
- 小さな直し: MCP の `thth_settings` を key だけで呼ぶと落ちていた／Bluesky の `since` を文字列の大小で比べていた／朝の一枚の未回答の permalink がいつも空だった。
- SKILL と llms.txt の古い記述（添付は thth.me の道で使えない 等）を直した。

## 出し方

Worker（llms.txt）を先に deploy し、VM はあと。hub と h2d の担当には、名前の道（`sections_by_name`）と `thth events`・`thth summary` へ移ってもらうよう別に頼む。
