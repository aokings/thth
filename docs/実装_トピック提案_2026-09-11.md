## 設計から変えたところ（理由つき）

| 変更 | 理由 |
|---|---|
| **引用の文字 offset を省き、引用文字列の一致だけで検査する** | masaru 指示。空白の正規化ひとつでずれるので、脆いわりに得るものが少ない。改竄検知の目的は文字列一致で足りる |
| **既存 46 件を `legacy_note` の二級市民にせず、観測として全部読む** | masaru 指示「既存 22 語は活用する」。`audience` に書かれた「誰がいたか」は、取り直せない価値のある事実。**ただし当時の判断は「参考・アカウント未指定」として区別する**（§9 の趣旨は保つ） |
| **`by` から account を推測しない** | masaru 指示「不明な取得状況は推測で埋めない」。`claude（kopicha セッション）` から `kopicha-threads` を機械的に埋めると、**確かめていないことを確かめた形で残す**ことになる |
| **他アカウントの判断を「参考」として併記する** | 継承はしない（§8）が、隠すのも情報の損失。kopicha が `お茶` について書いた内容は、nigamilab が読む価値がある。**採らないが見せる** |

## 工程 1・2 の残件

- **旧 46 件に `--status` が無い。** 「検索結果 0 件」と書かれていても、取得条件の
  記録が無いので `empty` に変換しない（§9）。**出力に「取得結果を記録していません。
  『人がいない』と読み替えないでください」と注記する**形で据え置いた。
  各セッションが付け直すのは任意。
- **各アカウントの判断が 0 件から始まる。** 3 セッションに通知済み。
  `--account` を付けた記録が溜まるまで、`--advise` の「適合と判断した語」は空。
  **観測は全部見えるので、判断の材料は失われていない。**
- **`others_disagree()` が未使用のまま残っている。** 工程 4 で `topic_store` へ
  移すときに整理する。
