# 設計 3.1.0: 毎朝の一枚（morning）

2026-09-23。masaru「お願いします」。動機: App Review で開いた読む口（世間の検索・言及・他人のプロフィール・場所）が「あるだけ」で、masaru の毎日に束なっていない。招待の道（3.0）とは別の話で、masaru 自身が一人で回して便利になるための版。

## 0. 約束（1 行）

**「昨日から何があって、今日なにをすればよいか」を、道具が事実だけで 1 枚にする。** LLM は空欄を推測で埋めない。本文は作らない（作るのは人と LLM の会話の側）。

## 1. 入口

- CLI: `thth morning <project>`（project に属する全 account をまとめる）・`thth morning <account>`。`--json` は JSON だけ。
- MCP: `thth_morning {project|account}`（読む口・user scope）。
- skill の開始手順: **最初に `thth_morning` を呼ぶ**（`handoff-report --since-last-read` を包含するので、版の確認もこれ 1 回で済む）。呼んだら `--mark-read` 相当で栞を進める（`--no-mark` で進めない）。

## 2. 構成（上から順・各段は「取れなかった」を null＋理由で言う）

| 段 | 中身 | 材料（既存） |
|---|---|---|
| 0 道具 | 版・前回から変わったか・リリースノート・出せるもの表に変化があれば | `tool_version.summary`・`media_capabilities` |
| 1 返していないもの | 自分宛の言及と返信で未返答のもの: 誰から・何に対して・経過時間・permalink。media ごと | `unanswered`・`mentions`（Threads の言及は審査で部外者分が出る） |
| 2 昨日の自分 | 昨日（JST）出した投稿ごとの views／likes／replies／reposts と分母、24h 前と比べられれば差分 | `after`・`insights`・`measured` |
| 3 世間 | 監視語ごとに: 件数・異なり投稿者・上位 3 の占有率・直近時刻・**絡みに行く先 3 件**（permalink・返信有無・自分の履歴の有無）。本文は先頭 60 字の表示だけ | `where`（Threads は 40 s の timeout） |
| 4 予定 | 今日出る予定（approved・publish_at）・承認待ちの下書き・inflight／held・予算（X の読取／投稿の残り） | `queue`・`board`・`budget` |
| 5 次の一手 | 道具が出せる事実に基づく定型 3 種だけ: 「返す（1 の各行）」「絡む（3 の各行）」「出す（4 で今日の予定が無い account）」。本文は書かない | 1・3・4 の集計 |

- 表示は人向けの text と `--json`。JSON に絶対パス・本文全文・他人の username 以外の個人情報を入れない（leak probe の対象）。
- **読むだけ**: SNS 台帳に書かない（2.10 §1.4）。C3／C4 の規律: 世間の本文・post_id を保存しない（表示のみ）。栞（`handoff_cursor`）だけ進める。
- 数字には分母。取れないものは `cannot_say: <理由>`（`budget_exhausted`・`provider_timeout`・`scope_missing` など静的）。

## 3. 監視語

- 台帳に `watch_words: ["コーヒー", "自家焙煎"]`（account 単位・最大 5 語）。project 単位の既定は `accounts/<project>.watch.json`（任意）。
- `thth admin watch set <account> 語 語 … --by <名前>`／`watch show`（管理者・変更ログ `watch_set`・presence-only）。
- 語が無い account は 3 段を「監視語なし」で飛ばす（推測で語を選ばない）。

## 4. コストと回数

- 1 回の `morning` で叩く回数を JSON の `calls` に出す（media ごと・endpoint ごと）。Threads の世間検索は 1 語 1 回・言及 1 回・insights は昨日の投稿数だけ。
- X は読取予算（USD）が 0 なら 1〜3 段を `cannot_say: budget_exhausted` で飛ばし、4 段の予算行だけ出す。
- 世間検索の timeout は **40 秒**（今の 10 秒では Meta が返す前に切れる・2026-09-23 実測）。`THTH_THREADS_TIMEOUT_SECONDS` は従前どおり上書き可。

## 5. 実装の置き場

- `thth/morning.py`（束ねるだけ・各段は既存関数を呼ぶ・段ごとに try で囲み失敗を null＋理由に）。
- CLI `morning`・MCP `thth_morning`・skill 更新・`docs/使い方_プロジェクトのセッション向け_….md` の開始手順を「まず morning」に。
- 試験: 各段を fake で（成功・欠測・timeout・予算 0）、分母、`calls`、leak probe（絶対パス・本文全文なし）、栞が進む／`--no-mark` で進まない。単変異 6 本。
- 実機: masaru の 3 口座と kopicha で朝に 1 回。世間検索の 40 s。
