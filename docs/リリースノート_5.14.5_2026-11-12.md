# THTH 5.14.5（2026-11-12）

直しだけの版です。timer の run のロック待ちと、privacy の 2 か所の書き漏れを直しました。

## 直したこと

### timer の run のロック待ち（673a925・nigamilab #7582）

11/12 12:36、nigamilab-hatenablog の run が `account_locked` で exit 1 になりました。同じ repo の threads の run が同じ分に起きて repo のロックを約 70 秒持ち、待ちが 60 秒で諦めたためです。

- 待ちを 60 秒から 150 秒にしました。
- 1 回の run の中の段（投稿・反応・ブックマーク・採取）が、それぞれ 150 秒ずつ待つと、足して service の `TimeoutStartSec=300` を越えます。そこで 1 回の run に通しの締め切りを 1 つ持たせ（`core.RunWait`）、あとの段は残りの時間だけ待つようにしました。
- 柵: `tests/test_v317_run_lock_wait.py`（待ち ≥ 120 秒・待ち＋120 秒 ≤ service の timeout・`systemd/thth@.service` の値と一致）。

VM の service の設定（`systemd/thth@.service`）は変えていません。

### privacy の書き漏れ 2 つ（英日・`tools/build_site.py`）

コードが持っているのに privacy に書いていなかったものを足しました。約束を緩める直しではなく、今の作りの事実に合わせる直しです。

- **Marketing API の呼び出しの記録**: 「日ごとの数を直近 16 日分」に加えて、「直近 500 回の呼び出しそれぞれの時刻と成否」も持っています（`thth/meta/calls.py` の `RATE_WINDOW`。Meta の Marketing API の段の条件「直近 500 回の誤りの率」を数えるため）。中身や宛先は持ちません。
- **データの一覧の広告の項**: 「予算を下げる」だけでなく、「持ち主の二段確認のあと、上限の内側で広告セットの終了日や通しの予算を延ばす」（`thth ads extend`）を足しました。本文の「予算を上げるのも持ち主の二段確認のあとだけ」（5.14.4）と、一覧の項がそろいました。

施行日は 5.14.4 と同じ 2026-11-12 のままです。

ついでに `thth/ads/ops.py` の頭の注記「上げる口は無い」を、「上限を上げる口は無い。通しの予算と期間は `extend` が 2 段で延ばす（上限の内側だけ）」に直しました（動きは変わりません）。
