# 約束: 媒体 → 括りの対応表 `thth.workspaces/1`（2026-11-26 から）

THTH・hub・h2d の 3 つの部品の間の約束です。**この形がそろっていれば、THTH の版とは関係なく読めます。** 決めた経緯と理由は [設計_THTHアカウント（括り）_共通の層_叩き台_2026-11-26.md](設計_THTHアカウント（括り）_共通の層_叩き台_2026-11-26.md) の §1（masaru 11/26「推しで決める」）。

## 1. 置き場

- 正本は VM の 1 枚: `/srv/thth/workspaces.json`（持ち主 `wt`・`0644`・repo の外。THTH の版の入れ替えでは触られない）。
- 環境変数 `THTH_WS_MAP` があれば、その道を読む（試験のため）。
- 写しを持たない。Mac の側で引かない（hub も h2d も、判定は VM の上で 1 回）。
- 2026-11-26 15:18 に最初の 1 枚を置いた（括り `main` だけ・`unlisted: "main"`・媒体 16 = 設計 §1.2 の 14 個に `mindforest` と `watchtower`（h2d の古い名前）を足した物）。hub の名簿にあって表に無い名前（`soh`・`mac`・`wt-read`・`nigamilab-wt-*` など）は `unlisted` が拾う。2 つ目の括りを足す前に、本物の媒体かを見て足すか捨てる。置いた物の確かめ方は §5。

## 2. 形

```json
{
  "schema": "thth.workspaces/1",
  "updated_at": "2026-11-26T15:20:00+09:00",
  "unlisted": "main",
  "workspaces": {
    "main": {"owner": "masaru", "lead": "media-hub", "created": "2026-11-26"}
  },
  "media": {"asmon": "main", "h2d": "main", "kopicha": "main"}
}
```

| 欄 | 要るか | 意味 |
|---|---|---|
| `schema` | 要る | `"thth.workspaces/1"` だけ。ほかの値は「知らない形」として断る |
| `updated_at` | なくてよい | 書いた時刻（ISO 8601）。読む側は使わない |
| `unlisted` | 要る | 表に無い媒体の扱い。括りの名か `null`（どの括りでもない＝断る）。**括りが 2 つ以上なら `null` でなければ形の誤り** |
| `workspaces` | 要る・空は不可 | 括りの名 → `{owner, lead, created?}`。これ以外の欄は形の誤り |
| `workspaces.<括り>.owner` | 要る | 括りの持ち主（決める人）。hub の「返事待ち」の相手、承認の「誰が決めたか」 |
| `workspaces.<括り>.lead` | 要る | 括りの窓口の媒体（`媒体` か `媒体/レーン`）。h2d の急ぎの繰り上げと休みの知らせの先。`main` は `media-hub`（今の決め打ちと同じ） |
| `workspaces.<括り>.created` | なくてよい | `YYYY-MM-DD` |
| `media` | 要る | 媒体の名前 → 括りの名。先が `workspaces` に無ければ形の誤り |

名前の形:

- 媒体: `^[a-z0-9][a-z0-9-]{0,63}$`（h2d の owner の `/` より前、hub の project、repo の名前と同じ綴り）
- 括り: `^[a-z][a-z0-9-]{0,31}$`
- 持ち主: `^[a-z][a-z0-9_-]{0,31}$`

秘密（鍵・token・人の連絡先）は入れない。秘密らしい値があれば形の誤りとする。

## 3. 読み方（3 つの部品で同じ）

1. **読むたびに開く**（1 つの命令の中で 1 回）。覚えを作らない。
2. **ファイルが無い** → 全部の媒体を `main` として扱う。
3. **ファイルが壊れている**（JSON でない・`schema` を知らない・§2 の形の誤り）→ 新しく書く操作（規則・仕事・見張りを足す・変える、`jobs request`、`job once`）は断り、「対応表が読めない・管理者に知らせる」を返す。もう置いてある規則の発火と配送は続ける。**黙って `main` に倒さない。**
4. 媒体の括り = `media` にあればその値、無ければ `unlisted`。媒体の名前の形が違えば、括りは無し（`null`）。
5. 2 つの媒体が「同じ括り」= どちらも括りを持ち、それが等しい。片方でも `null` なら同じでない。
6. ほかの括りの物を名指ししたときの断りは、どこにも無い名前を名指ししたときと同じ符丁・同じ文にする（名前を当てて回る探りに答えない）。

## 4. 見本（3 つの部品の試験が読む 1 枚）

- [contracts/thth.workspaces.1/cases.json](../contracts/thth.workspaces.1/cases.json)。媒体の名前は架空。
- 1 件ごとに `file`（JSON の物）か `file_text`（壊れた文字列）か `file: null`（ファイルが無い）と、`valid`、期待する答え（`workspace_of`・`same_workspace`・`owner_of`・`lead_of`）がある。
- thth の答えの正本は `tests/test_workspaces_map.py`。hub と h2d は、この見本を自分の試験で読み、同じ答えを出すことを確かめる（写しを置くなら、thth の commit を添えて同じ物にそろえる柵を置く）。
- 見本を変えるのは thth の側だけ。変えたら hub と h2d の担当に知らせる。

## 5. 書き換え方と確かめ方

- 手で開いて直さない。`thth admin ws …` ができるまでは THTH の括りの担当が、`thth/workspaces_map.py` の `write`（形を確かめ、別の名前で書いて付け替える）か、同じ手順（別の名前で置いて `mv`）で置く。
- 確かめ: `ssh wt 'cat /srv/thth/workspaces.json' | python3 tools/workspaces_check.py -`（rc 0 で「OK: … 括り n・媒体 n」）。
- 媒体を別の括りへ移すことは、表の書き換えではしない（置き場のデータが付いてこない）。管理者の作業として別に段取りする。
- 2 つ目の括りを足すときは、同じ書き換えで `unlisted` を `null` にする（しないと形の誤りで書けない）。その前に、表に無い名前（hub の名簿にあって表に無い物）を足しておく。

## 6. 版を上げるとき

形を変えるときは `thth.workspaces/2` にし、読む側（hub・h2d）が両方を読めるようになってから書く側を替える。`/1` の読み手は `/2` を「知らない形」として断る（§3 の 3）。
