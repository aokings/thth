## 4. 決めたこと（設計から動かしたところ・理由付き）

1. **本文の上限を 140 → 暫定 280 コードポイント**。設計 §2 は「thth に既にある 280 の
   数え方があれば踏襲」と書いていますが、repo にあったのは `queuefile.MEDIA_LIMITS` の
   **140**（2017 年より前の数字）だけで、数え方（`count_text`）は存在しませんでした。
   140 のままだと**いまの本文を不当に断る**ので、設計の「無ければ暫定 280 code point」に
   寄せ、`XAdapter.count_text` はコードポイント、lint は毎回
   `warning: x_length_weighting_unverified` を添えます。**重み付き計数は実機の項目。**
2. **月間本数の上限はアカウントごとに効く**。数え上げのファイルが設計どおり
   `state/<account>/x-posts-<YYYY-MM>.json` なので、`--monthly N` は「その口座が
   その UTC 月に出せる本数」です。X のアカウントが 1 つなら見た目は同じですが、
   2 つ目を足したときに合算されません。**合算が要るなら次版で言ってください。**
3. **`duration_minutes` を宣言の欄として足した**。既存の poll は Mastodon の
   `expires_in`（秒）で、X は分です。**単位の取り違えは黙って別の投票になる**ので、
   欄そのものを分けました（`duration_minutes` は X 以外では拒否・X では必須）。
4. **読み取りの予算の口を 1 つ足した**（`budget_x.before_read`）。2.12 の状態機械は
   「token の POST → `/2/users/me` の GET」の形しか受けませんでした。adapter の
   `whoami`／`posts` は POST を伴わないので、**状態も欄も増やさずに**同じ機械を
   通す関数を足し、受ける path を `/2/users/me` と `/2/users/<id>/tweets` に限りました。
   0 件の応答（`meta` だけ）も「読めた」として確定します。
5. **MOV はこの版では送りません**（表は `unsupported: provider_format`・但し書きに
   `thth_sends_mp4_only_in_this_version`）。一次資料に動画の容器の一覧が無く、
   確かめていないものを `supported` と書かないためです。
6. **`whoami` も読取予算の中**（`/2/users/me` は従量の読み取り）。`recent_posts` は
   `user_id` が `.token` に無ければ断ります——**1 回の一覧で 2 回課金しない**ため。
7. **署名の「無い／合わない」は commit の生の header で分ける**。`git log --format=%G?` は
   手元の `gpg.format` 設定に左右され、設定していない clone では SSH 署名を署名として
   数えません（実際に untrusted 鍵の commit が `N` と出ました）。`git cat-file commit` の
   `gpgsig` の有無で判定し、読めなければ「合わない」側に倒します。
8. **`thth app set x` の書き先が変わりました**（世代の付いたファイル）。`media.write` を
   足したためで、旧無印はそのまま残ります。**masaru はもう一度 `thth app set x` を
   打つ必要があります**（打つまで添付は出せません・本文は旧 client のまま出せます）。
