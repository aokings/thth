# THTH 5.12.3（2026-11-05）

止まりの知らせをメディアハブに集約するための版（masaru 11/05「メディアハブに通知は集約しようぜ」）。11/03〜05 の X の止まりで、偽の「復旧」が出て、鍵の更新の失敗がどこにも届かなかった穴を塞ぐ。

## 契約の変わったところ（足すだけ）

- **`thth board --json`**: 各口座の行に `stuck` を足した。schema は `thth.board/1` のまま。止まっていなければ `null`、止まっていれば `{"code","since","what","fix"}`。秘密の値・本文・宛先は入らない。読むだけ。
  - 載るもの: 投稿の止まり（`publish_http_401` など）・鍵の状態（`token_refresh_failed`・`token_expired`・`token_expiring`・`token_incomplete`・`token_unreadable`）・held（`approved_but_held`）。
  - 通知の控えが読めないときは `incident_outbox_unreadable`（`since` は null）。止まっていないと読ませないため。
- 新しいメールは足していない。鍵の失敗でメールは出ない。

## 変えたこと

1. **偽の復旧を止める**（`thth/incident.py`）。公開が断られた止まりは、公開が成功したとき（run の結果か `sent` の記録）か、止まった原稿が queue から退いたとき（`not_after` を過ぎて二度と試みられない原稿を含む）にだけ解ける。間に別の止まりが挟まっても待ちは落ちない。何も試みなかった回では `recovered` を出さない。inflight・同期・ロック・held の解け方は変わらない。止まりを持ち越すので、控えの検査・復旧の結び先・30 日の畳みを「開いた止まり」で見る形に直した。
2. **鍵の止まりを控える**（`thth/maintain.py`・`thth/accounts.py`）。`thth maintain` が鍵の状態を控える（`--check` は控えない）。run の中の X の自動更新の失敗は `token-refresh-failure.json` に時刻だけ残し、次の run が拾う。

## 戻すときの注意

5.12.2 以前に戻すと、古い検査が新しい控えを壊れたと読む場合がある（止まりの間に notice が末尾に来ているとき）。

## 確かめ方

- 試験: `tests/test_incident_notifications.py`・`tests/test_maintain.py`。11/03 の並びを `test_11月3日の並びは止まり1回と本物の復旧1回だけ`・`test_11月3日の並びでstuckはsinceを保ち本当の成功で消える` で再現した。新しい柵は一度わざと壊して赤を見た。別の者（Fable）が v5.12.2 の検査と本物の並び 10 種を突き合わせて互換を確かめ、X の 2 時間の鍵で毎日の誤報が出ないことを再現した。指摘の 2 点（間に別の止まりが挟まる・`not_after`）を直した。
