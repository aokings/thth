# リリースノート 4.5.2（予約の在庫が薄いと前もって知らせる）

2026-10-23（夜の仕事・ナイトシフト）。10/19〜22 にこぴちゃ（Bluesky・Mastodon）と関東の予約が尽きて、投稿が止まりました。人が気づいたのは止まったあとでした。その再発の防止です。

## 変わったこと

- **`thth events` に新しい種類 `schedule_low`**（続いている状態・`ongoing: true`）。直近 7 日に THTH で公開している SNS の口座で、**承認済みの予約の最後が今から 48 時間より前**（または 1 本も無い）ときに出ます。在庫が戻れば消えます。
  - 数えるのは、承認済みで時刻が未来の予約です。下書きは数えません。返信待ちの行も数えません。
  - 付く欄: `ref`（`stock`）・`stock_hours`（最後の予約までの時間。無ければ 0）・`approved_future`（承認済みで未来の本数）・`floor_hours`（48）・`last_publish_at`（無ければ欄ごと無し）。
  - 出さない口座: 直近 7 日に公開していない口座（手でしか出さない口座・使っていない口座）・はてなブログ。
- 読むだけです。何も書かず、媒体の API も呼びません。`by_kind` に `schedule_low` が増えます。

## 受け取る側（h2d・各窓口）

- 既存の events の読み方のままで届きます。`event_id` は口座ごとに同じ（`stock`）なので、受け手は `event_id` で 1 度だけ扱い、消えたら解消として読んでください。
- 床の 48 時間と「動いている」の 7 日は、今は決め打ちです（`events_cli.STOCK_FLOOR_HOURS`・`STOCK_ACTIVE_DAYS`）。窓口ごとに変えたい要望が来たら、口座の設定にします。
