# THTH 5.12.1（2026-11-05）

5.12.0 の直し。書き戻しの push が落ちたあと origin が進むと同期が止まって自分で解けなかった件（関東の口座・11/04）と、5.12.0 の監査で「出したあとでよい」にした 3 件、運用からの知らせ 1 件（lint に口座名を付けたとき）。

## 契約の変わったところ

- **新しい符丁 `lint_takes_no_account`**: `thth lint <口座名> <原稿>` のように 1 つ目の引数が台帳の口座名で、その名前のファイルが無いときに、取り込む前に断る（rc 2）。同じ名前のファイルが本当にあれば、今までどおりそれを lint する。
- **`thth pull <口座>`**: 手元に残った THTH 自身の書き戻しの commit は、`--by` が無くても upstream の上に載せ直して push するようになった。人の commit は今までどおり押さず、並びも書き換えない（`--push-pending --by` の動きは変わらない）。
- 鍵の名前を変えたもの・消したものは無い。

## 変えたこと

1. **同期が自分で解ける**（`thth/writeback.py`）。未 push の commit がすべて THTH 自身の書き戻しで、upstream とも作業ツリーの変更とも同じファイルに重ならないときだけ、`sync_repo()` が載せ直して push し、今までどおり `HEAD == @{u}` を確かめて通る。ahead だけのときも同じ。
   - THTH 自身の commit は、題の形・触ったファイル・front-matter の差分が道具の書く欄と値だけ、の組で見分ける。合わないもの（題を真似た人の commit・改名・削除・2 ファイル・merge・submodule）は人の commit として扱う。
   - 人の commit が混ざる・重なる・rebase がぶつかる・push が落ちる・rebase の途中のときは、手元（HEAD・作業ツリー・stage の区別）を元のままにして止まり、どうすれば通るかを言う。障害記録の commit は対象外で、そう言い分ける。
   - 照合（validate）で止めた commit には手元だけの印 `refs/thth/push-held` を付け、載せ直さない。
   - 下見の経路（dry-run の投稿と束・承認の 1 段目・lint の探し直し）は push しない `sync_repo_no_push()` に分けた。
2. **控えの 14 日**（`thth/meter.py`）: ファイルが小さくても、先頭の行が 14 日より古ければ書くときに詰める。
3. **慣らしの符丁の選び**（`thth/shared_app.py`）: 当てたときと同じ `used + adds` で台帳の数を見る（今の道では `adds` はいつも 1 で、出る符丁は変わらない・備え）。
4. **遠くの道の入口の断り**（`thth/remote.py`）: 口 `remote` の「通すには」を出す（今の目録では出る文は変わらない・備え）。
5. **lint の口座名**（運用 #6892）: 上の符丁。関係のない全口座の「取り込んでも VM にありません」が並ぶ症状は出なくなる。
