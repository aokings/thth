# リリースノート 3.24.0（thth.me の鍵の道の予約を send と揃える）

2026-10-16。

- **thth.me の鍵の道の `thth schedule` は、`--production` が無ければ予約しない。** `--text` と `--at` なら下書きを置いて lint だけを通し、下書きの id と「予約するなら `--draft=<id> --production`」を返す。`--draft` だけなら何もせず断る（rc 2）。それまでは 1 回で本文を置いて予約まで行き、親の help の「読むだけ」とも食い違っていた（[調べ_道ごとの意味の差](調べ_道ごとの意味の差_2026-10-15.md) §1-3 の 11）。3.21.1 の `send` と同じ線（masaru 10/15「thth.me の send・retract を手元と揃える」の続き）。MCP の `thth_schedule_request` は今までどおり呼べば刻む（中で `--production` を付ける）。
- **過去の時刻の予約はサーバでも断る**（`invalid_draft` の `publish_at_past`）。手元の CLI の `--at` は 3.23.0 までに断っていたが、置いておいた下書きを `--draft` や MCP で予約すると、時刻が過ぎていれば timer の次の run ですぐ出ていた（§1-3 の 12）。5 分の猶予の内は「今」として受ける（猶予つきの send は未来の時刻なので変わらない）。

## 出し方

Worker は変わらない。VM（release）でサーバの断りが効く。CLI の `--production` は利用者が 3.24.0 を入れてから効く（PyPI の tag）。
