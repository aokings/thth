# THTH 5.12.4（2026-11-05）

不具合直しの版。`thth board` の遅さ、lint の取り込みの穴、`thth doctor` の文、5.12.1 の監査の後回し 3 件。

## 契約の変わったところ（足すだけ）

- **`notifications.json` の宣言 `hub_reads_stuck`**: `thth notifications config` の入力で入れ外しする（`true` で入り `false` で消える・真偽値以外は断る）。宣言があれば、止まりの知らせは hub が `thth board --json` の `stuck` で読むものとして数え、宛先が無くても「知らせる先が無い」と言わない。`notification_route.status` に `hub: true` が足され、board の `notification_configured` は「届く道がある」の意味で true になる。宣言が無い環境の鍵と文は今のまま。
- **`lint_takes_no_account`**: 引数のどれが口座名でも断る（末尾の `/` は無視）。`doors` に `mcp` を足した。
- 鍵の名前を変えたもの・消したものは無い。

## 変えたこと

1. **`thth board` を速くする**（`thth/writeback.py`・`thth/core.py`・`thth/managed_repo.py`）。原稿 1 本ごとに 2 回呼んでいた git を、`matches_synced_commit_many` の `cat-file --batch` にまとめた。判定は今までと同じバイト列の比べで、1 本の口も同じ判定を通す。読めない・出力が崩れた・件数が合わないときは全部を不一致にする（安全側）。読んだ中身は関数の中だけに置き、持ち越さない。手元の計測: 原稿 2,000 本で 53 秒・git 4,006 回 → 0.94 秒・8 回。
2. **lint の取り込み**（`thth/cli.py`）。`/` の付かない名前は、その名前が在る repo か queue_dir と同じ repo だけ取り込む。打ち間違いで全口座の repo を動かさない。
3. **`thth doctor` の文**（`thth/notification_route.py` ほか）。宣言があれば「止まりは hub が読みます」と言う。
4. **控えの 14 日**（`thth/meter.py`）。行の順序が崩れていても、日が変わる 1 行で詰めて時刻順に直す。
5. **MCP の `thth_lint` の断り**: 「通すには」を MCP の文にした。
