# リリースノート 4.4.1（承認は利用者の repo に commit を積まない・gate の番号の無い確定を断る）

2026-10-21。masaru 10/21「推しでよし」（[計画 4.4](計画_4.4_利用者の不満_2026-10-21.md) の ⑤ と ⑦）。設計は [設計 4.4.1](設計_4.4.1_承認の記録をVMに_2026-10-21.md)。

## 変わったこと

- **承認の確定は VM の承認の台帳に書きます。** `thth approve --confirm`・`--confirm-file`・`thth revoke`・thth.me の予約（猶予・返信の順番待ちを含む）と取り消しは、`state/<口座>/approvals.json` に書き、利用者の repo の原稿を書き換えず、commit・push もしません。4.4.0 までは確定のたびに repo に commit が積まれ、repo の先頭の commit に付けた配信の承認がずれていました（10/21 だけで 4 回）。
- 読み手（timer・board・queue・schedule・取り消し）は、repo の原稿に台帳の承認を重ねて見ます。指紋の照合は今までどおりで、承認のあとに中身を変えれば `approval_stale` で出ません。
- **4.4.0 までに repo に書いた承認（`status: approved`）はそのまま効きます。** 台帳の取り消しはそれも止めます。
- **⑦ hub の承認の番号**: 口座の台帳に `require_gate: true` を書くと、`thth approve --confirm … --approval A261021-25`（thth.me の道は `thth schedule … --production --approval …`）の番号の無い確定を断ります。番号の形（`A` と 6 桁・`-`・番号）が違っても断ります。番号は台帳に残ります。1 段目は断らず「確定に要る」と言います。番号の照合（`hub approve verify`）は THTH ではしません。
- **⑦ は公開の道にも掛かります**（監査のあと）: `require_gate: true` の口座では、`thth send --production`（`--approval` を付ける）と thth.me の `send_request`（その場・猶予・返信の順番待ち。任意の `approval`）も、番号が無いか形が違えば `approval_gate_required` で断ります。断るのは下書きを repo に置く前です。返信の順番待ちに並べたときは番号を台帳に残します。下見（`--production` の無い `thth send`）は断りません。
- **`require_gate: true` の口座では、台帳に記録の無い repo の `status: approved`（4.4.0 までの承認）は使いません。** draft として見せ、理由に「require_gate の口座では、台帳に記録の無い repo の承認は使いません」と出ます（今その設定の口座はありません）。
- **`require_gate: true` の口座では、gate の番号の無い台帳の承認も使いません**（設定を false から true にする前に積んだ承認）。理由に「require_gate の口座では gate の番号の無い承認は使いません。番号をつけて承認し直してください」と出ます。MCP の `thth_send_request`・`thth_schedule_request` も任意の `approval` を受け、遠くの CLI に `--approval` を渡します。
- **範囲の外**: はてなブックマークの `--production` と thth.me の `bookmark_request`・`bookmark_batch_request` は、4.4.1 では gate の番号を求めません（4.4.3 で決めます）。
- `thth approve`・`thth revoke` は、口座の `repo_dir` の外にある原稿（別の clone・手元の写し）を断り、口座の repo_dir を示します。
- **新しい命令 `thth approvals <口座> [--json]`**: 台帳の承認と取り消し（誰が・いつ・どの指紋で・どの番号で）を書き出します。repo から見えなくなった記録はここで見ます。

## 気をつけること（運用のレーンへ）

- **VM で直しただけの原稿は承認できません。** commit と中身が違えば「手元で原稿を commit・push してから」と言って断ります（4.4.0 までは確定が原稿ごと commit していたので通っていました）。
- **repo で人が status を書き換えると止まります。** 承認のときの repo の status（ふつうは draft）から書き換えた原稿（4.4.0 までの `status: approved` を draft に戻した、`withdrawn` にした、など）は、台帳に承認があっても出しません。理由に「承認のあと repo の status が書き換えられています」と出ます。repo が元から draft の原稿を止めるには、`thth revoke`・thth.me の取り消し・status を draft 以外にする・中身を変える、のどれかです。
- **原稿の account を書き換えると出ません**（変えた先の口座の台帳に承認が無い）。理由に「account が承認のときと違います（承認は <口座> の台帳にあります）」と出ます。もう一度 `thth approve` してください。
- **台帳が読めないとき**（壊れた JSON など）は、その口座のまだ出ていない承認済みを出さず、承認と取り消しも断ります。取り消しは status を見る前に断ります（`thth revoke` は「台帳が読めないので取り消しを受け付けられません」、thth.me の取り消しは `ledger_unavailable`）。読めない間は承認済みが draft に見えるので、「承認されていません」「already_draft」と答えると、台帳を直したときに承認が生き返るためです。
- **台帳の承認は、承認したときの repo の原稿にだけ重ねます。** 鍵は repo の中の相対パスなので、別の clone の同じパスの原稿には重ねません（台帳に残した repo と、原稿の repo の頂上を比べます）。
- `thth approve --json` と `thth revoke --json` は `recorded: "ledger"` を返します（`pushed` は null・取り消しは鍵ごと無くしました）。`--confirm-file` の「push に失敗したら押し直しの命令」は道ごと無くなりました。
- **変わらないもの**: 投稿の書き戻し（`status: posted`・`post_id`）・はてなの公開・incident・返信の収集は今までどおり repo に書きます（台帳に移すかは masaru に伺い中）。承認の指紋・Worker。Worker の deploy は要らない見込みです（`approval` の鍵は本文を中身を見ずに預かるだけ・読んで確かめただけ）。
