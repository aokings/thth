## 決めた形（なぜこうしたか）

- **main の 2 つの形を見分けるのは 1 か所だけ**（`thth/accounts.py` の `workspace_dir()`）。`ws/main/` があれば移したあと、無ければ移す前（今の本番と同じ）。移す台本は中身を `ws/.main-staging/` に集め、最後に 1 回の rename で `ws/main` にするので、半分だけの `ws/main/` は見えない。
- **移す・戻すの途中は印 `ws/.main-move/MOVING`** があり、新しい版は main を `workspace_moving` で断る（R11: 名指しの無い打ち方が、半分空の根を黙って main として読まない）。ほかの括りは止めない。
- **名指しの無い打ち方を main と読むのは期限つき**（R11）。期限は版の番号 `accounts.MAIN_DEFAULT_UNTIL = "6.1.0"`。版がそこに届くと試験が赤になり、段 6（VM の上では名指しが要る）の替えを促す。
- **移した物の元の場所には、開けないフォルダ（mode 000・空）を置く**（R2 (b)）。古い版（origin/main・5.31.0）を移したあとの置き場に当てると、台帳の置き場か止めの置き場が読めずに止まり、何も書かず、常駐は Worker に何も押し上げない（試験で確かめた）。印を置かないと、古い版は口座 0 の置き場として rc 0 で動き、常駐は空の要約を押し上げる（これも試験で確かめた・印が要る証拠）。
- **戻す順は「置き場を戻す → 版を戻す」**（R2 (a)）。版を先に戻すと、古い版が印にぶつかって止まる（黙っては動かない）が、その間は全部止まる。
- **台帳の道の直し**: `$THTH_ROOT` は「括りの根」と読むので、28 本（`$THTH_ROOT/repos/…`）は直さない。根からの絶対の道で移す物を指す所（叩き台の 1 本）は `$THTH_ROOT/…` に、`$THTH_ROOT` で共通の物（`private/` など）を指す所は絶対の道に、管理された repo の `.git/config` の origin（`<根>/state/<口座>/git-origin.git`）は `<根>/ws/main/state/…` に直す。直した所は帳面に残し、戻すときに 1 つずつ元に戻す（数が合わなければ止まる）。
- **共通の根に残す物**: `app/`・`venv/`・`private/`（レーンの鍵の表 `lane-keys.json` だけは括りへ）・`ws/`・`workspaces.json`・`notifications.json`・`state/` の `_admin`・`_webhook`・`_meta`・`_media`・`_app.lock`・`worker.json`。ほかは括りへ。振り分けの分からない物があれば台本は止まり、`--keep`（共通に残す）か `--move`（括りへ）で名指しするまで動かない。
- **消さない**: 退ける物（開けないフォルダ・空になった `ws/.main-staging`・前の帳面）は `ws/.main-move*` の下へ名前を替えて置く。
- token と env（`~wt/.config/thth/`）は動かさない（叩き台 §3 の段 5）。
- **記録の中の絶対の道も書き替える**（11/29 足した）。承認と止めの記録（`approvals.json`・`holds.json`・`inflight.json` など）は repo を `/srv/thth/repos/…` の絶対の道で持ち、原稿の repo と照らす。直さないと、移したあと承認も止めも無いものとされる（VM の写しで approved が 1096 → 1・[確かめ_VMの写しで段5と段6_2026-11-29.md](確かめ_VMの写しで段5と段6_2026-11-29.md)）。台本は移した記録の JSON・NDJSON の `"<根>/<移した物>…` を `"<根>/ws/main/<移した物>…` に替え、戻すときは逆にする（repos・logs・台帳の中は替えない）。`check` が「記録の道: N か所」を出す。
- 11/29 の写しの `check` で分かった振り分け: **`--keep notifications.json.bak-20261105 --keep notifications.json.bak-20261105-users --keep notifications.json.lock --keep state/_backup_2026-09-11`** を、夜の `check`・`move --dry-run`・`move` の 3 つに付ける（どれも共通の根の物か古い控え）。

## 止まる時間の見込み

**10〜15 分**（叩き台の見込みのまま）。内訳の根拠:

- 台本そのものは 1 秒かからない。同じディスクの上の rename だけで、データを写さない。手元の稽古（口座 3・括り 2・移す物 15）で、移す → 戻すを含む 56 件の試験が 3 秒ほど。本番は移す物が 50 前後（口座ごとの `state/<口座>/` が 29）になるだけで、rename の数が増えるだけ。
- 長いのは止める待ち: 走っている oneshot（`thth@…`・`thth-collect@…`）は `TimeoutStartSec=300` なので、最悪 5 分待つ。静かな時間（各口座の `quiet_hours`）に始めれば、ほぼ待たない。
- 確かめ（board・doctor・単位の数）と起こすで 5 分ほど。

## 夜

`ssh wt '…'` はログインの設定を読まないので、`thth` は `env THTH_ROOT=/srv/thth /srv/thth/app/bin/thth` と書く。プロセスを止めるのに `pkill`・`pgrep -f` は使わない（自分の命令の文字列に当たって ssh ごと止まる）。止めるのは systemctl の単位の名前で。

### 1. 止める

```
ssh wt 'systemctl list-units --all --plain --no-legend --no-pager "thth*" > ~/ws-move-units-before.txt; wc -l ~/ws-move-units-before.txt; env THTH_ROOT=/srv/thth /srv/thth/app/bin/thth board --json > ~/ws-move-board-before.json; ls /srv/thth/accounts | wc -l'
ssh wt 'sudo systemctl stop "thth*.timer"'
ssh wt 'for i in $(seq 1 36); do n=$(systemctl list-units --plain --no-legend --no-pager --state=active,activating "thth@*.service" "thth-collect@*.service" "thth-map@*.service" "thth-maintain.service" "thth-meta-keepalive.service" | wc -l); [ "$n" = 0 ] && echo idle && break; sleep 10; done'
ssh wt 'sudo systemctl stop thth-worker.service; systemctl list-units --plain --no-legend --no-pager --state=active,activating "thth*"'
```

見る値: 台帳の数（29 の見込み）を控える。待ちが `idle` で終わる。最後の命令が何も出さない（動いている thth の単位が 0）。`thth-approval-worker.service` が残っていれば同じく stop。

### 2. 移す

```
ssh wt 'cd /srv/thth/app && /srv/thth/venv/bin/python tools/ws_move_main.py check --root /srv/thth'
ssh wt 'cd /srv/thth/app && /srv/thth/venv/bin/python tools/ws_move_main.py move --root /srv/thth --dry-run'
ssh wt 'cd /srv/thth/app && /srv/thth/venv/bin/python tools/ws_move_main.py move --root /srv/thth'
```

（前の日に決めた `--keep`・`--move` があれば 3 つとも同じに付ける。）

見る値: `check` が `OK: 移せる形です`。`move` の最後が `OK: main を /srv/thth/ws/main へ移しました（移した物 N・道の直し M）`。

途中で落ちた・止めた（rc が 0 でない）とき: `status` でどこまで進んだかを見て、原因（NG の行）を直してから **同じ `move` をもう一度**打つ（続きから進む）。やめるなら「5. 戻す」へ。

### 3. 確かめる（読むだけ）

```
ssh wt 'cd /srv/thth/app && /srv/thth/venv/bin/python tools/ws_move_main.py status --root /srv/thth; ls -la /srv/thth /srv/thth/ws'
ssh wt 'env THTH_ROOT=/srv/thth /srv/thth/app/bin/thth board --json > ~/ws-move-board-after.json; python3 -c "import json;a=json.load(open(\"/home/wt/ws-move-board-before.json\"));b=json.load(open(\"/home/wt/ws-move-board-after.json\"));print(len(a.get(\"accounts\",a)), len(b.get(\"accounts\",b)))"'
ssh wt 'env THTH_ROOT=/srv/thth /srv/thth/app/bin/thth admin ws list; env THTH_ROOT=/srv/thth /srv/thth/app/bin/thth doctor <口座 1 つ>; env THTH_ROOT=/srv/thth /srv/thth/app/bin/thth approvals <口座 1 つ>'
```

見る値:
- `status`: `state=moved`・`ws/main: ある`・`ws/.main-staging: 無い`・`印 MOVING: 無い`。
- `ls -la /srv/thth`: `accounts`・`repos`・`logs` などが `d---------`（開けない印）。`private`・`state`・`app`・`venv`・`ws` は今のまま。
- board の口座の数が前と同じ（board の JSON の形に合わせて数え方を直してよい）。
- **`thth queue --json` の口座ごとの `counts` が「1. 止める」で控えた物と同じ**（承認と止めが残っている）。「1. 止める」の最初の命令に `env THTH_ROOT=/srv/thth THTH_WS=main /srv/thth/app/bin/thth queue --json > ~/ws-move-queue-before.json` を足して控える。approved が減っていたら起こさずに「5. 戻す」。`admin ws list` に main と新しい括りの両方。`doctor` が前の日と同じ答え。`approvals` が前の承認を見せる。

### 4. 起こす

```
ssh wt 'sudo systemctl start thth-worker.service; sleep 20; systemctl is-active thth-worker.service; journalctl -u thth-worker.service -n 30 --no-pager'
ssh wt 'sudo systemctl start $(awk "\$1 ~ /\\.timer\$/ && \$3 == \"active\" {print \$1}" ~/ws-move-units-before.txt); systemctl list-timers --all --no-pager "thth*" | tail -n 3'
ssh wt 'sudo systemctl start thth-collect@<口座 1 つ>.service; journalctl -u thth-collect@<口座 1 つ>.service -n 20 --no-pager'
```

見る値: worker が `active`・journal に `activity_owners_unavailable`・`workspace_moving`・`account_stop_state_unreadable` が出ない。timer の数が `~/ws-move-units-before.txt` の active な timer の数と同じ。collect が rc 0 で、`/srv/thth/ws/main/state/<口座>/` に書く（`/srv/thth/state/<口座>` は開けない印のまま）。次の刻み（10 分以内）で `thth@…` の journal が前の日と同じ形。止めている間に過ぎた予約は、最初の刻みで出る（今の作りのまま・R5）。

### 5. 戻す（どこかがおかしいとき。置き場を戻す → 版を戻す）

1. 「1. 止める」をもう一度（timer と常駐を止める）。
2. 置き場を戻す:
   ```
   ssh wt 'cd /srv/thth/app && /srv/thth/venv/bin/python tools/ws_move_main.py back --root /srv/thth --dry-run'
   ssh wt 'cd /srv/thth/app && /srv/thth/venv/bin/python tools/ws_move_main.py back --root /srv/thth'
   ```
   見る値: `OK: main を根へ戻しました（戻した物 N）`。移していた間にできた物（新しい sent・runs など）も一緒に根へ戻る。戻す先に物があれば止まる（中を見て決める）。落ちたら同じ `back` を打ち直す（続きから）。
3. 「3. 確かめる」の board・doctor を打ち、`/srv/thth/accounts` が読めて口座の数が前と同じ。
4. 「4. 起こす」。
5. 版も戻すときは、置き場を戻したあとで（release の枝を前の sha に。`git push origin ${sha}:refs/heads/release`・masaru の「出して」のあと）。

## hub との合わせ目（hub のコードと置き場は media-hub の担当・この書では触らない）

- hub は THTH を `thth board --json` で読む（R9）。**読みの形は移しても変わらない**。止めている 10〜15 分の間、hub の読みは古い答えのままか、`workspace_moving` で断られる。hub の側で「読めなかった」を 1 回の止まりとして数えないよう、時刻を前の日に知らせる。
- hub の置き場を同じ夜に移す（共通の層 §6 の段 J）なら、順は **THTH の「3. 確かめる」が済んでから hub を止めて移し、hub を起こしてから THTH の「4. 起こす」**。hub の読みが新しい置き場の THTH を最初に読むのが、確かめの済んだあとになる。
- 戻すときは逆に、hub を先に戻してから THTH の「5. 戻す」。
- hub のレーンを鍵の道に替える（段 6）のは別の日。この夜は ssh の道のまま。
- 段 6 で名指しの印 `ws/.name-required` を置く日は、その前に VM に入っている `thth-map@` の単位を置き直す（11/29 の写しで、古い単位に `THTH_WS_FROM_ACCOUNT=1` が無く、印のある置き場で断られた）。置く前に、入っている単位の ExecStart と Environment を読んで関門に当てる（確かめの書 §3 の判定）。

## まだの所

- 本番の置き場の今の形（`state/` の中の `_` で始まる物の全部・`repos/` の下の git の置き場）は、VM で `check` を打って初めて分かる。台本は分からない物で止まるので、前の日の `check` で決める。
- `state/_reports`（開発への報告の箱）は、今のコードが括りの根で引くので main と一緒に移る。叩き台 §2.1 は「共通」と書いていて食い違う。移しても main の読み書きは同じ所を見るので壊れないが、括りを越えて 1 つにするかは別に決める。
