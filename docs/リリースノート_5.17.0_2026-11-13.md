# THTH 5.17.0（2026-11-13）

Shopify の店を読む口を足した版です。BASE（5.15.0）と同じ `thth shop` の家族に、店の種類 `shopify` を足しました。設計は [設計_ShopifyとSTORESの口_2026-11-12.md](設計_ShopifyとSTORESの口_2026-11-12.md)（Fable。masaru 11/12 夜「迷ったり複雑なところはfableにふりつつ、私の回答はまたずにナイトシフトで」を受けて、推しの側で決めた。朝に覆せる）。

## 足したこと

| 命令 | すること |
|---|---|
| `thth shop add <店> --kind shopify --shop <ラベル> --project <p> --by <名前>` | Shopify の店を台帳に足す。ラベルは `<ラベル>.myshopify.com` の頭 |
| `thth shop token set <店> --auth client --by <名前>` | Dev Dashboard のアプリの Client ID と secret の 2 行を受ける（既定）。隠した入力か `--stdin` だけ |
| `thth shop token set <店> --auth token --by <名前>` | 既にある管理画面のカスタムアプリの固定の鍵（1 行）を受ける |

`whoami`・`items`・`diff`・`draft`・`remove` は BASE と同じ使い方です。

- 2026-01-01 から、Shopify の店の管理画面では新しいカスタムアプリ（固定の鍵）を作れません。新しい店は Dev Dashboard のアプリで、THTH は約 24 時間の短い鍵を取り直して使います（`~/.config/thth/store-<店>.access`・0600。取り直しは鎖をかけて 1 回だけ）。読む途中で 401 が返ったら、1 回だけ取り直して打ち直します。
- 求める権限は `read_products` だけです。無ければ前向きに断ります。余分な権限のある鍵は、断らずに知らせます（`--json` の `scopes_extra`。記録には数だけ）。
- Shopify は商品頁の URL が取れるので、下書きには商品頁の URL を載せます（BASE は店の URL）。
- 断りの目録に `store_org_mismatch`・`store_refresh_rejected`・`store_refresh_busy`・`store_shop_unknown`・`store_currency_unsupported` を足しました（どれも なぜ・通すには・もっと良く）。

## 守ること（柵にした）

- 網に出るのは `thth/shop/wire.py` だけ。行き先は道の表（`ROUTES`）の決まった道だけで、Shopify のホストは台帳のラベル＋`.myshopify.com` だけ。GraphQL の文は定数の 2 本だけで、注文と顧客は読みません。
- リダイレクトは、同じホストでも追いません（**BASE も同じに変わりました**。3xx は `store_request_rejected` で断ります）。
- 鍵（client secret・固定の鍵・短い鍵）は、引数・出力・ログ・記録・ほかのファイルに出しません。短い鍵のファイルにも、権限の名前の一覧は残しません。
- `thth shop remove` は、短い鍵も含めて消します。remove の最中に待っていた読みが、あとで鍵を書き戻すことはありません。
- 共通の網の守り `thth/httpsafe.py` を、release の関門の危ない領域（`net_guard`）に入れました。別の opener を渡せるのは `wire.py` だけで、型も検査します。

## privacy

「Online shops」の節を、共通の段・BASE の段・Shopify の段に分けました（英日）。「GET だけ」と言えるのは BASE だけになったので、そう書き分けています。`tests/test_privacy_matches_code.py` に、送り先・問い合わせの数・POST の道・短い鍵の置き場・権限・24 時間・リダイレクトを追わないこと・下書きに画像の URL を入れないことを結ぶ柵を足しました。施行日は 2026-11-12 のままです。

## 残したこと

- 本物の店で最初に確かめること（設計 §11）に足す: `write_products` だけの鍵で `accessScopes` に `read_products` が出るか（出なければ、既にある固定の鍵が読めるのに断られる）。
- 形を確かめられなかった断り（THROTTLED・ACCESS_DENIED・401 の本文・`shop_not_permitted`・402・423）は、HTTP の数と形の検査だけで決めています。
- `thth morning` は網に出ないので、鍵の取り直しが断られても朝の知らせでは気づけません。
- 「在庫 0 でも売り続ける」設定の商品は下書きになりません。店頭がパスワードで閉じているかは分かりません。500 件を超える店は読み切れません。
- 余分な権限を「断る」に替えるかは masaru の判断（替えるなら `cli.scope_note` の 1 か所）。
- STORES は 5.18.0 で足します。
