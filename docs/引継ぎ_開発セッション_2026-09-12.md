## 2. 配布の仕組み（いちばん大事な変更）

**`main` への push では本番は変わりません。** `release` を進める操作が配布です。

```
git push origin <検収済みの SHA>:refs/heads/main       # 保存
git push origin <同じ SHA>:refs/heads/release          # **配布**
```

**VM は `release` だけを追います**（`thth/selfupdate.py`）。`thth board` の先頭に
道具の版と、**確かめた時点**が出ます。

**切り替えの順番と待ち条件は設計 §3.2.1。** VM の upstream は
`origin/release` に付け替え済み（運用セッションが 2026-09-12 午前に実施）。

## 5. この repo の作法（引き継ぐ人へ）

- **全件テストは `python -m pytest tests/ -q -n auto`**（約 70 秒。`pytest-xdist` を
  入れてあります）。`| tail` で受けると**終わるまで 1 バイトも出ません。**
- **直したら変異をかける。** 直した箇所を戻して、**意図したテストが落ちること**を
  確かめる。**落ちなければ、そのテストは何も守っていません。**
- **変異の置換には必ず `assert` を付ける。** 今日 3 回、置換が当たっていないのに
  「通った＝効いていない」と読みかけました。
- **対象を絞って回さない。** 個別実行では 3 ファイルしか落ちず、全件で 8 件出た
  ことがあります。**全件を回すまで「通った」と言わない。**
- **1 つの検収対象に 1 つの変更。** 別件を混ぜると、判定が遅くなるうえ、**本体が
  未コミットのまま別の commit に紛れ込みます**（今日やりました）。
