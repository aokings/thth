## P1-1 収集の push 失敗が、復旧後も予約投稿を止め続ける

収集は commit してから push する。push に失敗すると `HEAD != @{u}` が残り、
`sync_repo()` がそれを拒否する。結果、**採取も投稿も恒久的に止まる**——origin が
直っても、**未 push の commit を送る経路がどこにも無かった。**

**直し方の線引きが要点。**「未 push があっても通す」にはしない——公開側の fail-closed が
弱まる。**未 push の commit が触ったパスを全部見て、`data/sns/` の下だけだったときに
限り**送り直す（`collect.push_pending_collection()`）。queue（`docs/sns/queue/`）を
触る未 push が 1 つでも混ざっていれば**送らずに人を呼ぶ**。

`thth run` は**投稿より先に**この復旧を呼ぶ（`collect.recover_pending()`）ので、
同じ実行の中で投稿が再開する。

## P1-2 公開済みなのに revoke が取り消し成功を返す

`post_id` と `status` を**ロックの外**で読んでいた。**ロックが守るのは書き込みだけで、
読んだ事実はその間に古くなる。** 検査の直後・ロック取得の直前に公開が完了すると、
`post_id` が付いているのに `draft` へ書き換え、**exit 0 で「取り消しました」と
返していた。**

**止められなかった投稿を、止められたと利用者に伝える。** 取り消しという機能で
最も避けたい嘘。第 4 巡・第 5 巡と同じ形でもある——**確かめた時点と使う時点が
離れていた。**

直し: **ロックの中で、同期してから読み直して検査する。** さらに
`commit_and_push()` の `pull --rebase` が別 clone の公開を持ち込むことがあるので、
**書き終えたあとにもう一度 `post_id` を見る。**

## P2-3 数の取得成功で、失敗した返信の再試行まで止まる

刻み（1h・6h・24h・72h・7d）を insights の記録だけから計算していた。**数が取れて
返信が失敗すると、その刻みは「済んだ」ことになり、返信は二度と取りに行かない。**
最後の刻み（168 時間）で起きると永久に取れない。

直し: **数と返信で済んだ刻みを別々に持つ。** 返信ファイルに `kind: fetch` の行を
足して「取りに行った」ことを残す（**返信 0 件の成功と、取得の失敗を区別する**ため。
これが無いと、毎回叩き直すか二度と叩かないかのどちらかになる）。`kind` を持たない
古い行は返信として扱う。

## P2-4 他の更新者が先に更新すると、旧コードをロード済みのプロセスは再実行されない

基準を「lock を取ったあとのディスクの HEAD」にしていた。**別プロセスが先に更新を
終えていると `before == after` になり、「進んでいない＝exec しなくてよい」と誤判定
して、古いコードを読み込んだまま走り続けた。**

**lock は git の更新を直列化するだけで、すでに読み込んだコードと更新後のファイルが
混ざることは防げない。** 直し: 基準を**このプロセスがコードを読み込んだ時点の版**に
する（`_loaded_rev()`。プロセスの寿命の中で 1 度だけ git を見て、以後は動かさない）。

## P2-5 書き戻しが、無関係な追跡済みファイルの stage 状態を消す

`commit --only` は実 index の他のエントリを残す（第 5 巡の対応）。ところが直後の
`pull --rebase --autostash` が、**staged も unstaged もまとめて退避して、戻すときは
全部 unstaged にする。** 中身は消えないが「stage してある／していない」の区別が消える。
**人が途中まで組み立てた commit が崩れる。**

直し: `git write-tree` で index を控えておき、rebase のあとに **stage されていた
パスだけ** `git restore --staged --source=<tree>` で戻す。控えられなければ復元も
しない（**壊すくらいなら何もしない**）。

**第 5 巡のテストは新規ファイルを stage する場合だけを見ていた。** 既に追跡されて
いるファイルの編集を試していなかった——**fixture が現実の一部しか作っていなかった**
（規約 11 の変種）。
