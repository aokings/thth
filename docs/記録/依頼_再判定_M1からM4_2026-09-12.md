## 1. M1（P1・公開経路）

**同じ穴を 3 段階ずつ掘り下げられました。**

    1 回目: 例外が出るか        → **JSON として読めれば通った**
    2 回目: JSON として読めるか → **形が合っていれば通った**
    3 回目: 形・型・値域が合うか → **中身の整合を見ていなかった**

直し方の線引き:

- **`pending` は null を持つのが正常**なので、「全項目を非 null にする」では
  閉じません（そちらの但し書きのとおり）。
- **`published` と名乗る段にだけ**、公開の事実を復元する項目
  （`post_id`・`posted_at`・`text_sha256`・`bundle_sha`）を要求します。
- 逆に、**公開の痕跡（`post_id`・`posted_at`）が残っているのに `published` で
  ない**のは矛盾として弾きます。
- **ファイル名と中の `run_id` の一致**も見ます（中身だけでは判らないので
  `unreadable_runs()` から渡します）。

**こちらのテストの fixture（`published` なのに `post_id` だけ）も、この検査に
引っかかりました。** 直しましたが、**検査が効いている証拠**として残します。
