## 3. CLI（§3.7 の表）

```
thth lint <file>                  # 形式検査。駄目な理由を 1 行ずつ。終了コード 0/1
thth queue [account] [--json]     # draft/approved/posted の一覧と「次に出るもの・いつ」
thth preview <file>               # 実際に投げる本文そのもの（媒体の節だけ。前後に何も足さない）
thth throw <account> [--now] [--production]   # 既定 dry-run
thth run <account>                # throw ＋（T3 で collect）＋ ログ ＋ runs ＋ last.json
thth board [--json]               # 骨だけ（アカウント・最終投稿・approved 待ち・inflight・型外）
```

- **`--production` を付けても、台帳に `production: true` が無ければ dry-run のまま**（fail-closed。env も token も無い T1 では必ず dry-run になる）。
- `--json` を付けた出力は 1 行 1 JSON か 1 個の JSON。MCP はこれを読む。
- 人が読む出力とは別に、**必ず機械可読の形を持つ**（watchtower `wt-evidence` と同じ流儀）。

### select の条件（§3.3・ここが T1 の心臓）

出す 1 件を選ぶ順序。**上から順に落として、残った中で `publish_at` 昇順、同時刻ならファイル名順で先頭 1 件**。

1. `post_id` が入っている → 落とす（**status より先に見る**。approved に戻されても出ない）
2. `thth:` が無い・front-matter が壊れている → 型外として落とす（失敗に数えない）
3. `account` が対象と違う → 落とす
4. `status != approved` → 落とす
5. `publish_at` が未来 → 落とす。`publish_at` に `+09:00` が無い → **型外＋「approved なのに型外」として board に出す**
6. いま静かな時間帯（台帳 `quiet_hours`）→ 全部落とす
7. 前回投稿から `min_interval_hours` 未満 → 全部落とす
8. 媒体の節が無い → `error="no_section"`／文字数超過 → `error="too_long(NNN)"`（**T1 検収 2026-09-09 で 2 つに分けると確定**。節が無いときは NNN が定義できないため）。どちらも落として runs に残す（status は approved のまま。**切り詰めない**）
9. 台帳 `hashtags: false` なのに本文に `#` 語がある → 落として `error="hashtag"`
10. `publish_at` から `stale_days`（既定 7）超 → 落として board に「要確認」
11. 同一アカウントで直近 30 日に投稿した本文と完全一致 → 落として `error="duplicate_text"`

### throw の順序（§3.3・§3.5）

```
lock（core）→ inflight あれば何もせず exit 1 → select → 無ければ「出すものが無い」で exit 0
→ inflight.json を書く（file・started・container_id=null）
→ [dry-run] 本文をログに出して inflight を消して終わり
→ [本番] コンテナ作成 → inflight に container_id → 30 秒待つ → 公開 → inflight に post_id
→ writeback（front-matter 3 行）→ git add <その 1 ファイルだけ> → commit → pull --rebase → push
→ push 成功後に inflight を消す（**push 失敗では消さない**）
```

## 4. 薄い MCP（読み取り 4 本だけ）

`mcp/server.py`（stdio）。tools は `thth_lint`・`thth_queue`・`thth_preview`・`thth_board` の 4 つ。

- **中身は CLI を `subprocess` で呼んで `--json` の出力を返すだけ。** 判断・整形・条件分岐を書かない。
- `thth_throw`・`thth_approve`・`thth_auth`・`thth_refresh` は **T1 では作らない**（`throw` は T4、`approve` 以下は永久に出さない・§3.7）。
- T1 の 4 本は repo を読むだけなのでトークン不要。**Mac 手元で ssh 無しに動くこと**。
