## 直したこと

`thth/topic_models.py`（登録）と `thth/topic_cli.py`（読取）の両方で、
`supersedes` を **`None` または `_REF_ID_RE.fullmatch` に合う文字列**に限りました。

**空文字列だけを塞がなかった理由**は、頂いた指摘のとおりです——**例外を足すと、
同じ形の穴が別の値でまた開きます。** 実際 `sha256:xyz`・63 桁・`sha256:` の無い
64 桁も、この 1 つの基準で塞がりました。

| 入力 | 登録 | 旧レコードの読取 |
|---|---|---|
| `null` | 通る | 診断しない |
| `sha256:` + 16 進 64 桁 | 通る | 正常な版関係 |
| `''` / `'   '` | **拒否** | **診断あり** |
| `sha256:xyz` / 63 桁 / `sha256:` 無し 64 桁 | **拒否** | **診断あり** |
| `[]` `{}` `0` `false` / 非空配列 | **拒否** | **診断あり**（V1 のまま） |

**見るのは表記だけです。** 形式が正しいが存在しない ID（`sha256:aaa…`）は通ります
——**参照先の実在性・循環検査・版グラフの再設計は対象外**との指示に従いました。
