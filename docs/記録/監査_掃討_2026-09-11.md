# 監査: 外部指摘を「同じ形が他に無いか」へ一般化した掃討 — 2026-09-11

外部の再検収（Codex・F1〜F8）を直したあと、**指摘 1 つ 1 つを形として取り出し、
repo 全体に同じ形が残っていないかを掃討した。** 実装の担当（Sonnet）に足を
走らせ、**報告は全部こちらで現物と突き合わせてから採用した。**

## 0. やり方

| 掃討した形 | 出どころ |
|---|---|
| **読めない・失敗したものを「制限なし」「問題なし」に落とす**（fail-open） | F1 |
| **要求した検査が黙って走らない**（名前だけの検査・0 回まわる for） | F2 |
| **存在だけ確かめて、意味の対応（account・版・対象）を見ない参照** | F8 |

**報告をそのまま採らない。** 3 本とも「場所・コードの引用・具体的な再現・確信度」を
書かせ、こちらで呼び出し元をたどって確かめたものだけを直した。**たどれなかった
ものは「たどれなかった」と書かせた。**

**自分の修正も逆監査に出した**（masaru 指示 2026-09-11）。主張 7 件を別の担当に
渡し、**反証を取りに行かせた。**

## 1. 直したもの

### 公開経路（`0f49548`）

- **未解決の公開を止める関門が、実行記録を読めないと開いていた。** `open_runs()` が
  読めないファイルを飛ばすので `has_unresolved()` が空を返す。設計 §8 は
  「破損と不存在は別状態」と決めているのに、**公開経路の実行記録だけその規約から
  外れていた。** `report.py` の board も同じ関数を使うので、**人が気づく経路も
  同時に塞がる。**
- **承認の「公開済みの段は変えられない」検査も同じ形で素通り**していた。
- **別 account の実行の続きとして出せた**（`identity_error()` が `run_id` と
  `rel_path` しか照合していなかった）。

**止め方は運用セッションの警告を 2 つ取り込んだ。**

1. **「ディレクトリが無い」は止めない。** 実行記録が 1 件も無いという確定した事実。
   混ぜると**連投の実績が無いだけの account で公開と承認が止まる。**
2. **fail-closed は運用を止める権限を道具に渡す。** エラーに**絶対パス・止まる範囲
   （連投だけ・単発は止まらない）・戻し方**を書き、**その文言をテストで固定した。**
   退避が本当に効くかも偽 API で公開させて確かめた。

### 編集記録（`ba411a2`）

- **別 account の判断を、自分の指摘の根拠にできた。** 記事と観測は account を
  持たない共有の事実なのでそのまま、**判断と検収は同じ account のものだけ**、
  **候補比較は account を解決できないので許さない。**
- **「無い」と「他所のもの」で文言を分けた。** 区別できないと直し方が決まらない。
- 検収の一覧に**出自の内訳**（試作由来と実運用を混ぜて数えないため）。

### 採取・診断（`d7a34d8`・`42619e1`）

- **HTTP 200 で `{"error": ...}` が返る形を見ていなかった。** `data` が無いので
  静かに 0 件になり、**「取れて 0 件」として台帳に残っていた。**
- **`thth doctor` の返信権限の検査が、全アカウントで永久にスキップされていた。**
  ラベルに注記を足したとき比較文字列を直し忘れ、`==` が永久に偽。
  **「投稿がまだ無いので試せない」と表示されるが、理由が事実と違う。**
  → **直した当日に、初めての陽性を拾った**（下記）。
- `thth lint <空ディレクトリ>` が無言で終了コード 0（`thth approve` には関門が
  あるのに lint だけ無かった）。
- **account の `media` を変えると連投の採取が無言で 0 件**になっていた。

## 2. 実地で確かめたこと（陽性対照）

**`threads_read_replies` の初めての陽性**（2026-09-11 22:14 JST）。masaru が
kopi_chaba の投稿へ返信を 1 件付け、直後の `thth doctor kopicha-threads` が
`○ 返信の取得 / 1 件 [{"id": …, "username": "aoking"}]` を返した
（運用セッターが VM で確認）。

- **経路は生きている。** これまで 10 回の `replies: 0` が無言の失敗だった疑いは
  実質消えた（`d7a34d8` の後の版で `○` なので、「200 だが中身は error」の筋も同時に消える）。
- **身内の返信なので成果としては数えない**（`aoking` は `masaru-threads` として
  台帳に載っている）。**経路の対照としてだけ使う。**

## 3. 残っている穴（直していない）

- **刻みと刻みの間に来た返信は、次の刻みまで台帳に現れない。** 実例が最初の
  1 件目で出た（22:14 に来た返信は 02:08 まで記録されない）。
  **168 時間を過ぎてから来た返信は永久に拾われない。** 刻みを増やすかは、
  返信が実際に付くようになってから決める（いま母数 1 件）。
- **board の `type_mismatch` が、壊れた原稿と正常な連投を混ぜている。**
  `malformed = fm.get("thth") != "1"` なので、**`thth: 2` の束が「型外」として
  数えられる。** 見た人は「直すものがある」と読むが、直すものは無い。
- `_collect_account_daily()` の 3 つの「今日は書かない」理由が同じ無言の
  `return None` に潰れている（確信度・中。読んだだけ）。
- `_known_ids()` が記録 1 件書くたびに全部の棚を読む（性能。Codex が
  「必須修正にしない」と書いたので触っていない）。

## 4. この監査自体の限界

- **掃討は「今日出た 3 つの形」しか見ていない。** 別の形の穴は探していない。
- 実行したのは**手元と隔離環境だけ**。VM の現物確認は運用セッターに依頼した
  ものを、**出所を明記して引用している。**
- 報告のうち**確信度・中で「読んだだけ」のものは直していない**（再現条件を
  こちらで確かめられなかったため）。
