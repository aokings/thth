## 2. やったこと

### 2-1. `tests/conftest.py` に autouse fixture `frozen_now_jst` を追加（根の対処）

`thth.jst.now_jst()` を `monkeypatch.setattr` で差し替え、既定で `2026-09-09 10:00
JST`（静かな時間帯 22:00〜07:00 の外）を返すようにした。`now` を渡さず
`jst.now_jst()` に頼る経路（`thth.core.throw_once()` 等）はすべて、これ以後
実行時刻に関係なく同じ値を読む。

個別のテストが別の時刻を試したいときは、fixture が返す setter を呼んで上書きする:

```python
def test_何か(frozen_now_jst):
    frozen_now_jst(datetime.datetime(2026, 9, 9, 23, 0, 0, tzinfo=jst.JST))
```

fixture の docstring に、なぜこれが要るか（2026-09-09 に見つかった「昼は必ず緑・
夜は必ず赤」の事故の経緯）を書いた。

autouse なので、**新しく書かれるテストも既定でこの恩恵を受ける**（これが再発
防止の本体・4 参照）。

### 2-2. 応急処置（`quiet_hours=None`）を戻した

前セッションが T3a で足した `quiet_hours=None` は、次の 5 箇所すべてから外し、
台帳の既定値（`["22:00", "07:00"]`）に戻した:

- `tests/test_roundtrip.py`（1 箇所）
- `tests/test_fake_api.py`（test_6・test_7・test_8・test_9 の 4 箇所）
- `tests/test_max_per_run.py`（4 箇所）

`tests/test_no_limits.py` の `quiet_hours=None`（6 箇所）は**外していない**:
このテストファイルは `quiet_hours: null`／`min_interval_hours: 0` という「制限
しない」設定そのものの意味を確かめるテストで、`quiet_hours=None` が偶然の
安定化策ではなく主題そのものだから。

外した 5 箇所のうち、`tests/test_max_per_run.py` の 4 箇所は元から
`core.throw_once(..., now=NOW)` で明示的に時刻を注入していたので、
`quiet_hours=None` は実際には不要だった（`now=NOW`＝`2026-09-09T10:00:00+09:00`
が既に静かな時間帯の外）。

### 2-3. `now` を渡さず `jst.now_jst()` に頼っていた 4 箇所に、明示的な `now=` を足した

`tests/test_roundtrip.py`・`tests/test_fake_api.py` の test_7/8/9 は、
`quiet_hours=None` を外すだけでは conftest.py の `frozen_now_jst` の**既定値**に
暗黙に依存する形になる（その既定値をたまたま静かな時間帯の外に選んだから通る、
という新しい形の「たまたま」）。これを避けるため、各テストのモジュール先頭に
`NOW = datetime.datetime.fromisoformat("2026-09-09T10:00:00+09:00")` を定義し、
`core.throw_once(..., now=NOW)` に明示的に渡す形にした。

**検証**: `conftest.py` の `frozen_now_jst` の既定値を一時的に
`2026-09-10T02:00:00+09:00`（静かな時間帯の中）に差し替えて全テストを再実行し、
この 4 箇所を含む在プロセスのテストが全件通ることを確認した（下記§4）。その後
既定値は `2026-09-09T10:00:00+09:00` に戻した。

### 2-4. サブプロセス越しの 1 件（`test_fake_api.py::test_6`）

`test_6` は `run_thth()`（`bin/thth` を別プロセスとして起動）を使う。
`monkeypatch.setattr(jst, "now_jst", ...)` はこのプロセス境界を越えられず、
サブプロセス側は本物の壁時計を読み続ける。これを完全に断つには、CLI に
テスト専用の時刻注入口（環境変数等）を足す必要があり、**本番コードの変更**に
あたる。今回は本番コードに触らない方針のため、既存の CLI フラグ
`thth throw --now`（`bypass_pace=True`。静かな時間帯・最短間隔の判定を無視する。
`thth/cli.py` に既にある機能で、今回新設していない）を使い、台帳は既定の
`quiet_hours`（22:00〜07:00）のまま、静かな時間帯の判定そのものを外した。
`test_6` が検査したいのは「公開成功直後の中断・次回 inflight で停止」であって
静かな時間帯の判定ではないので、この置き換えはテストの主題を変えていない。

**記録（判断に迷った箇所・直していない）**: `test_6` は依然として「実行してい
る本物の壁時計が `publish_at`（2026-09-09T08:00:00+09:00）より後であること」
（select 条件 5・`future`）には依存している。`--now`（`bypass_pace`）は静かな
時間帯・最短間隔の判定（条件 6・7）だけを無視し、条件 5 は無視しない。
`bin/thth` サブプロセスは `jst.now_jst()`（UTC を起点に固定 +09:00 で変換する
実装・システムの `TZ` には依存しない）を読むので、この 1 点だけは実行環境の
実時刻に残る依存が完全には断てていない。今回のセッション時点（2026-09-09
22:33 JST 前後）では `08:00` より確実に後なので問題は出ないが、理論上
「2026-09-09 の 00:00〜07:59 JST に実行される」ケースでは `test_6` だけこの
経路で `future` 落ちする可能性が残る。直すには CLI にテスト用の時刻注入口を
足すという本番コード変更が要るので、直さずにここに記録する。

### 2-5. 静かな時間帯を意図して覆うテストを追加（`tests/test_quiet_hours.py`）

- 静かな時間帯の中では、承認済みで期限も来ている投稿が出ない
- 静かな時間帯の外では、同じものが出る
- 日をまたぐ指定（22:00〜07:00）で 23:00 も 02:00 も「中」

  併せて確認）
- `quiet_hours: null`／`[]` なら深夜でも出る
- `frozen_now_jst` fixture 自体の既定値・上書き入口の確認（回帰防止）

## 4. 深夜相当での確認（仕上げの検証）

### 4-1. 実時刻がそもそも夜だった

上記§3 のとおり、実行時刻は実際に 22:00〜07:00 の中（22:33 JST）。この状態で
166 件全件緑・exit 0。

### 4-2. `frozen_now_jst` の既定値を「深夜相当（2026-09-10T02:00 JST）」に一時的に
差し替えて再実行

```
$ python3 -m pytest tests/ -q --deselect \
    "tests/test_quiet_hours.py::test_frozen_now_jstは既定で静かな時間帯の外を返す"
........................................................................ [ 43%]
........................................................................ [ 87%]
.....................                                                    [100%]
165 passed, 1 deselected
exit: 0
```

deselect した 1 件（`test_frozen_now_jstは既定で静かな時間帯の外を返す`）は、
「fixture の既定値が静かな時間帯の外であること」自体を確かめるテストで、既定値を
意図的に静かな時間帯の中へ差し替えるこの実験とは前提が矛盾するため除外した
（バグではない）。既定値は確認後 `2026-09-09T10:00:00+09:00` に戻し、その状態で
166 件全件緑を再確認済み（§3 のとおり）。

### 4-3. `TZ` を変えても結果が変わらないことの確認

```
$ TZ="America/New_York" python3 -m pytest tests/ -q ; echo "exit: $?"
........................................................................ [ 43%]
........................................................................ [ 86%]
......................                                                   [100%]
166 passed
exit: 0
```

`thth.jst.now_jst()` は UTC を起点に固定 `+09:00` へ変換する実装で、システムの
`TZ` に依存しないため、`TZ` を変えても結果は変わらない（Mac・Linux 両方で同じ
挙動になることの根拠）。
