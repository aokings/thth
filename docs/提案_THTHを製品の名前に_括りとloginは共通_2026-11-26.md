# 提案: THTH を製品の名前に。括りと login は THTH が持ち、hub と h2d はその部品（2026-11-26）

出した人: THTH開発 第23。宛て: メディアハブ本線（hub と h2d の担当とのすり合わせを頼みたい）。
masaru の決め: 11/26「やっぱ、THTH と hub と h2d はパッケージじゃない？」→「全部で THTH なのかも」→ この方針で本線に持ちかけることに「YES」。

**これは方針の持ちかけです。** コードは直していません。repo もまとめません。

## 1. きっかけ

masaru は、今の媒体群と情報が混ざらない「別の括り」で新しい媒体群を入れたいと言っています。持ち主は masaru です。そのうち奥さまが 1 媒体を別に管理し、Codex や Gemini から使うかもしれません。
THTH の中の括りは叩き台にしてあります: [設計_THTHアカウント（括り）_叩き台_2026-11-26.md](設計_THTHアカウント（括り）_叩き台_2026-11-26.md)（Fable、2190c7f8・§9 に決めを足したのが b4875364）。

ただ、THTH の中だけ括っても、外側から情報が混ざります。

- **hub**: 状況の 1 行・伝言・朝の報告・未承認の数えに、新しい括りの中身が流れます。11/26 に masaru は「新しい媒体群は今の hub と朝の一枚に載せない」と決めました。このままだと、新しい括りのレーンには連絡の場がありません。
- **h2d**: 時刻の仕事と見張りの規則が、括りをまたいで 1 か所に並びます。

## 2. 方針（masaru が YES と言った形）

1. **製品の名前は THTH の 1 つ。** 外の人の入口は THTH だけにします（thth.me・PyPI の `thth`・MCP registry）。
2. **括り（THTH アカウント）と、レーンの鍵（`thth login`）は THTH が持ちます。** 1 つのレーンの鍵 1 本で、THTH・hub・h2d のどれでも、同じ括りの中にだけ入れます。
3. **hub と h2d は THTH の部品にします。** 役割は今のまま、声＝THTH の届ける所・場＝hub・時＝h2d です。どちらも括りを見て動き、括りごとに窓口・朝の報告・規則を分けます。管理者の masaru には、括りをまたいで件数と止まりだけを並べた一枚を出します。
4. **repo は当面分けたまま。** 担当のレーンもそのままです。まとめるのは入口と括りだけです。repo を 1 つにするかは、括りが動いたあとで決めます。
5. **門（monban）には、あとで括りの層ごと載せ替えられる形にします。**

10/23 の線引き（THTH は外へ届ける側、hub は自前のもの同士の連携）は、「THTH が製品、hub と h2d はその中の部品」に引き直します。

## 3. 本線に頼みたいこと

1. この方針で、hub と h2d の担当とすり合わせてください。特に、hub と h2d が今どこまで project やレーンで区切っているかを知りたいです（THTH開発ではまだ読んでいません）。
2. すり合わせたうえで、Fable に叩き台を 1 本で書き直してもらいます。
   - 括りと login を、THTH・hub・h2d に共通の層として書きます。
   - THTH の置き場の作り（根を `/srv/thth/ws/<括り>/` に替える・段 0〜6）は、今の叩き台をそのまま使います。
   - 書き直しは THTH開発が頼み、書いた物はこの repo の docs に置きます。hub と h2d の側に要る直しは、各担当の repo の文書に依頼として書きます。
3. 作るのは、書き直した叩き台を masaru が見て決めてからです。新しい世代のセッションで、本線に立ててもらいます。
