# リリースノート 4.0.1（ブックマークの連投は記事と別に数える）

2026-10-17。masaru の頼み（10/17 夜）「ブクマの連投の制限は、スレッズなどより緩くして下さい」。設計は [S4 §19](設計_4.0_S4_告知とブックマーク_2026-10-17.md)。

4.0.0 では、はてなブックマークを記事と同じ主体の burst（30 分に 3 件）で数え、超えると主体を止めていた。ブックマークを 3 件続けるだけで、その主体のブログの公開まで止まった。

- **ブックマークは別の窓で数える。** 主体に `bookmark_burst`（既定 10 分に 10 件・付ける・消すの合計）。超えたら主体を**止めずに**、その 1 件だけ `burst_limit`（詳細 `bookmark_burst`・`next_at` は窓が空く時刻）で断る。人向けの 1 行は「主体は止めずに、この 1 件だけ断りました（次に打てるのは …）」。
- **記事の burst は記事だけを数える。** 主体の burst（30 分に 3 件）・口座の burst は今までどおり超えたら止める。ブックマークは数えない。
- **既定を上げた**: `daily_max_bookmarks` 3 → 30、`bookmark_same_host_daily` 1 → 3。自分の記事のブックマーク（`daily_max_self_bookmarks`）は 1 日 1 件のまま（はてなのスパムの指針）。
- `thth principal set <主体> bookmark_burst_count|bookmark_burst_minutes <値>`（`bookmark_burst <件数> <分>` でも）。`thth principal show` に「ブックマークの連投」の行。
- **`thth board`・`thth account` の token の行がはてなの口座で `config_error` と出ていた**（記録の見つけたこと 17）のを直した。はてなの口座は主体の token（OAuth・期限なし）を見て、在れば `ok/期限なし`・無ければ `no_token`（`thth principal auth <主体>` を勧める）・形が違えば `unreadable`。値は読み出さない。SNS の口座の表示は変えていない。
- 変えていないもの: 承認の指紋、1 URL に 1 回（`bookmark_once`・owner をまたぐ）、SNS の口座の burst。

## 出し方

VM だけでよい（Worker の変更は無い）。release の枝を進める → tag `v4.0.1`。

**台帳に書いた値が既定より勝つ。** 4.0.0 の雛形から作った主体の台帳には `daily_max_bookmarks: 3`・`bookmark_same_host_daily: 1` が書いてあるので、出しただけでは 3 件・1 件のまま。上げるなら VM で主体ごとに:

```
env THTH_ROOT=/srv/thth /srv/thth/app/bin/thth principal set <主体> daily_max_bookmarks 30 --by <名前>
env THTH_ROOT=/srv/thth /srv/thth/app/bin/thth principal set <主体> bookmark_same_host_daily 3 --by <名前>
```

`bookmark_burst` は 4.0.0 の台帳に無いので、出せば既定（10 分に 10 件）が効く。ブックマークで止まった主体があれば `thth principal resume <主体> --by <名前>` で戻す（4.0.1 は止まった印を消さない）。
