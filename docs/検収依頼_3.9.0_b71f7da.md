## 設計から外れた点・設計に書いていなかったので決めた点

1. **窓の前は投稿日の前の 3 暦日、窓の後は窓のあとの 7 暦日**に区切った（設計は「投稿日より前の日次」「窓の後」とだけ）。区切らないと、72 時間より離れて同じリンク先を使った過去・未来の投稿の窓のクリックが入る。さらに、同じリンク先を使うほかの投稿の 3 暦日の窓に入る日は前にも後にも数えず、外した日数を出す（`days_excluded_other_post_window`）。まだ閉じていない日・日次の無い日も数えず、日数を出す。
2. **行に goal を持たせない**（混ぜないことを形で固定するため）。
3. B3 の「原稿の topic・goal」は、原稿の topic を候補にし、その原稿の goal の本数を添える形にした（goal の語 reach/click… は検索の語にならないので候補にしない）。「反応が多かった topic」は 24h の likes＋replies の中央値（値のある投稿だけ・0 は出さない・上位 5）。
4. `--suggest` を `--also` 無しで打ったときは断らず、自分のデータの候補だけを出し、その場の候補は `reason: no_also` と 1 行。
5. 取れた投稿の username・author_key と同じ語は候補から外し、本文の URL と @名前 は数える前に外す（設計に無い網・名前を語として漏らさないため）。ひらがなは語の切れ目（「深煎り」は「深煎」）。
6. `more_may_exist` は媒体が返した行（手元の `--since`・`--also` などで絞る前）と要求数で見る。`rate_by_span` は `per_day` と同じ絞ったあとの行で数える。
7. 「直近 n 日」の n は `--since` の幅、無ければ取れた最古の投稿から今まで（切り上げ）。
8. `--per-post-clicks` も MCP の `analytics_report` には足していない（E は B について「MCP には足さない」。A は設計に書いていないので CLI だけにした）。
