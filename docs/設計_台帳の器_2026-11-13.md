# 設計（案）: 台帳の器 — 7 つのメディアの台帳と周りの仕組みを、1 つの共通の道具にまとめる

2026-11-13、Fable（設計と判断の役）。THTH開発 第16 からの依頼。**案**であり、決まりではない。

masaru が決めたこと（[構想 §9 の 9](構想_台帳ベースの総合サイト運営_2026-11-12.md)）:

1. THTH Throw Things の **Things が台帳の行**。
2. **各メディアの台帳を、THTH の台帳にそのまま移せる器にする。**「移さずにその場で読む」案は退けた。

masaru の意図（11/13 の追加。決めではなく、この書の向き）:

- これまでの集大成にする。移せる器で止めず、各メディアが別々に作った良い所を吸収し、弱い所は器の側で直し、違いは器の決まりに一般化して、共通の道具にする。
- 今の `thth register`（5.19.0）も、より良い形があれば作り替えてよい。
- 1 人が複数のメディアを持つ場合の持ち方と管理を考えておく。

この書のほかの所は、どれも推しと見立て。確かめた深さは §14 に分けて書いた。

## 0. 一枚で言うと

7 つのメディアを読むと、台帳はもう 1 つの型に寄っている。5 つ（染めと化学・にがみラボ・こぴちゃ・MMR・キョンシーラボ）は media-hub の「ラボの型」（`lab-model/`）から生まれた同じ表の組で、関東・学校台帳・中受の問は「1 枚の JSON や頁の頭に、欄ごとの出所と期限」を持つ。**共通の骨はすでにある。足りないのは、それを 1 つの道具が受け持つこと**で、今は点検・束の取り込み・出した URL の見張りの台本が repo ごとに写されて、少しずつ違ってきている。

器を次の形にする。

- **行の置き方は 2 つ。** 枚の行（1 行 1 枚。THTH の頭 ＋ 中身を元のまま）と、表の行（1 行 = 表の 1 行）。
- **台帳ごとに「憲法」と「種類の行」を持つ。** ラボの型の `lab.yaml` と表の決まりを、台帳の中の行にする。種類・欄・語・つながり・書き出し先を、コードでなく台帳が宣言する。
- **3 つの印を「裏付けの段」に広げる。** 推測 → 集めた → 別の者が確かめた → 本人が見た、と、否定。各メディアの語はこの段に対応づける。3 つの印はその粗い見え方として残す。
- **変えた跡は git から読み、訂正だけは跡として残す。**
- **書き出す口と、出した物の控え。** 頁の材料を書き、出した URL を失わない見張りまでを 1 つにする。
- **書く口と束の取り込み。** 表を安全に直す命令と、「集める → 別の者が検める → 取り込む」の流れを器が持つ。
- **健康と見直し。** 薄い所・古い所・試しのままの所を出す。台帳は勝手に書き換えない。
- **持ち主 → メディア → 台帳。** 共通の物は共通の台帳に 1 つ置き、各メディアから指す。

こぴちゃで最初に回す。7 つとも、影の写しで点検が通ることを 1 回の release の条件にする。

近くの 2 つ（器の形に効く所だけ）:

- **学校台帳（gakko）**: 出所を 3 段で持つ（ファイル → まとまり → 1 つの値）。状態は「写し・照合済み・要確認」。行の中に照合の記録（`checks[]`）・直しの記録（`changes[]`）・分からない所の一覧（`youkakunin[]`。値は null のまま、推測で埋めない）。制度は制度の側に対象を持ち、学校の側には番号だけを置く。
- **中受の問（chuju）**: 頁の頭に「確かめた日時と期限」（`ima`）を持ち、**期限を過ぎると表を伏せる**。頁の文は日付を直に書かず、台帳の値を `{{koyomi:…}}` で引く。分かれ道ごとの根拠（`konkyo`）と、当てはまる家・当てはまらない家（`taishou`）。既定は下書き。

## 2. 読み取れること

**共通の骨（すでにそろっている物）**

1. 点（もの）・名前・主張・根拠・出典・問い・観測、の表の組。5 つのメディアが同じ列。
2. 「1 行 1 事実」「原文を写さず要約」「根拠の場所は必須」「権利の印の無い出典は使わない」「弱い根拠だけなら上限つき」。
3. 書き手と別の者が確かめる。確かめた段を行に残す。
4. 行は消さず退役にする。出した URL は消さない。
5. 試し → 本採用 → 退役と、見直し日（指標の台帳・THTH の頭・点の `lifecycle_status`）。
6. 本人の言葉は本人が書く（憲法の一文の立場）。構想の「思いの層」と同じ物。

**メディアごとに違う所（§4 で一般化する）**

- 主張の状態の語が 4 つと 7 つ。読みの段の語も 2 通り（こぴちゃは collected・verified・rechecked、ラボの型は machine_read・integrator_checked・human_checked）。
- 根拠の種類・述語・点の種類はメディアごとに違う（MMR は役割の述語を 20 ほど足している）。
- 言語の持ち方（`_ja` と `_en` の 2 列・`_ja` だけ・別の置き場に英訳）。
- 出所の持ち方（別の表・欄ごとの並び・3 段）。
- 置き方（表・1 枚の YAML・1 枚の JSON・頭つきの .md）。
- 観測の列（染めの布と染料・キョンシーの版と言語・こぴちゃの毎朝の商品）。

**弱い所（§3・§5 で器の側で直す）**

- **台本の写しが増えて、ずれている。** 点検・取り込み・URL の見張りが repo ごとに在る。MMR の観測の表には、染めの列（布・染料）が型の写しのまま残っている。
- **表を手で直して壊す事故。** 染めと化学で文字列の置き換えが引用符を壊し、にがみラボは改行が CRLF の表を書き直すと全行が変わる。
- **確かめた跡が `notes` の欄に文で詰めてある**（こぴちゃの主張の notes に「中央 9/23: 3 者が確認」など）。機械で引けない。
- **訂正の記録が散っている**（MMR は `ledger.json`、学校台帳は行の中、ほかは commit の文）。
- **期限を持たない行が多い。** 期限で伏せるのは中受の問だけ。
- **THTH の今の台帳は、この骨をほとんど受けられない**（§6）。
- **こぴちゃの欄の名前が THTH の頭とぶつかる**（生産者と店の `kind`、店の `source`）。
- **メディアをまたぐ同じ物が、対応表の 1 枚に頼っている。** 同じ出典を 2 つのメディアが別の番号で持っていても、今は分からない。

## 3. 各メディアから吸収する物と、その出どころ

| 吸収する物 | 出どころ | 器での形 |
|---|---|---|
| 台帳の憲法（立場・柱・軸・出し口・形・権利の既定・網羅の上限・語の広げ） | media-hub `lab-model/lab.yaml`（元は染めと化学） | 台帳に 1 枚の「憲法の行」（§5.2）。一文の立場は本人が認めた行でなければ材料に使えない |
| 表の組と、変えない共通の語 | `lab-model/schema/data-dictionary.md` | 器が持つ「網の型」（§5.3）。語はメディアごとに足せる |
| 弱い根拠だけなら上限つき（`contextual_cap_types`） | 染めと化学・MMR・こぴちゃ | 憲法の行で種類を宣言し、点検が強制する |
| 読みの段（集めた → 別の者 → 統合の者 → 本人） | ラボの型の `extraction_status`、こぴちゃの verified・rechecked、学校台帳の「写し・照合済み」 | 裏付けの段（§5.3）。3 つの印をこの上の見え方にする |
| 調べたが確かめられなかった（`checked_unconfirmed`） | ラボの型の問いの表 | 否定の段の 1 つ。THTH の「違うと言った」と同じ扱い（消さず、聞き直さない） |
| 分からない所を機械で拾う（`youkakunin`・null のまま） | 学校台帳 | 行の「分からない欄」の宣言。穴の一覧に出す。推測で埋めた値を材料にしない |
| 欄ごとの出所・3 段の出所 | 関東・学校台帳 | 行の中の `sources[]` を根拠として読む読み方（§5.3） |
| 原文の短い引用（40 字まで）を確かめ直し用に持つ | 関東・ラボの型 | 根拠の `quote` の欄。既定で外に出さない |
| 値の線（対象 × 時点 × 項目 = 値・単位）と `as_of`・`valid_until` | 関東 → ラボの型、こぴちゃ | 主張の `value`・`unit`・時点の欄。期限は柵が読む |
| 期限を過ぎたら伏せる | 中受の問の `ima` | 見直し日を過ぎた行は書き出さない（今の柵の 6 番）を、頁の材料にも効かせる。伏せ方（行ごと・欄だけ）は種類で決める |
| 頁の文に値を直に書かず、台帳から引く | 中受の問の `{{koyomi:…}}` | 書き出しのときの差し込み（§5.6）。値が変われば使った頁が分かる |
| 当てはまる範囲を行が持つ | 中受の問の `taishou`、ラボの型の `scope`、MMR の「この曲か・一般か」 | 主張の範囲の欄を共通にし、材料に付けて渡す |
| 束の取り込みと守り（重なる番号を入れない・断られた物を入れない・取り込んだ印） | `lab-model/scripts/merge_staging.py` | `thth register merge`（§5.7） |
| 束の台帳（sha256・検めた者・状態） | MMR `ledger.json` | 取り込みの跡（§5.5） |
| 訂正は旧い値と sha256 を別に残す | MMR の `root_fixes_data`、学校台帳の `changes[]` | 訂正の跡（§5.5） |
| 健康の指標と「薄い点」 | `lab-model/scripts/health.py`、こぴちゃ `knowledge-health.mjs` | `thth register health`（§5.8） |
| 指標を育てる（生まれ・試し・退役・見直しの候補を出すだけ） | media-hub `設計_スコアボード` | 行の頭の `status` と見直し日はすでに同じ。見直しの決まりを health に入れる。指標そのものは hub に残す（§7.6） |
| 出した URL を失わない見張り | にがみラボの実装 → `lab-model/scripts/`、4 つのメディア | 出した物の控えと関門（§5.6） |
| 公開の写しと sha256 の一覧 | 関東の `manifest.json` | 材料の控え（§5.6） |
| 受け入れた物だけ出す（受け入れた日・誰が） | MMR `content/index.yaml` | 行の頭の `public` と認めた記録で受ける。別の一覧を持たない |
| 検索に出す範囲（index・noindex）を行が持つ | MMR・にがみラボの `search_visibility`、こぴちゃの商品頁の判定、中受の問 | 頭の任意の欄 `search`（§6） |
| メディアをまたぐ対応と姉妹リンク | media-hub `registry/`、こぴちゃ・にがみラボの `sister-links.csv` | 台帳をまたぐつながり（§5.4・§7.3）。リンクの表は対応から書き出す |
| 外の番号への対応（MusicBrainz など） | MMR `refs.csv` | 「外の同じ物」のつながり。点検は形だけ（外へ読みに行かない） |
| 外から取り込んだ値と、照らした日・当たり外れ | MMR `meta.csv`、こぴちゃの商品の catalog | 取り込みの行（構想 §3）。`source: register` の一般化（§6） |
| 図版と写真の台帳（権利・出典・クレジット・sha256・どの根拠に基づくか） | キョンシーラボ `images.csv`・`image_basis.csv`、にがみラボの図と写真の表 | 備え付けの種類「図版」。権利の印が無い図版は書き出さない |
| 内部の番号や作業の呼び名が、読者に見える欄に出ていないか | 染めと化学・にがみラボ・キョンシーラボ・中受の問 | 種類の行で「読者に見える欄」を宣言し、点検が番号らしい語を拾う |
| 書き手と検め手は別の者 | どのメディアも | 認めた記録・取り込みの跡に「誰が」を残し、同じ者の確かめを段に数えない |
| 個人の名前を点にしない・運営者の家族の名前を出さない | ラボの型・染めと化学 | 憲法の行の「入れない物」。点検が種類で止める |
| 原稿の URL に流入の印を付ける | MMR の入口の文書 | 台帳の器には入れない（投稿の側の話）。§7 の共通の決まりの行に置ける |

## 4. 一般化する違いと、固有として残す物

| 違い | 器の決まりにする形 |
|---|---|
| 主張の状態の語（4 語・7 語） | 語は台帳のまま。憲法の行で、語を器の 4 つの扱い（使える・上限つきで使える・両論を並べるなら使える・使えない）に対応づける |
| 読みの段の語 | 語は台帳のまま。裏付けの段（§5.3）に対応づける |
| 根拠の種類・述語・点の種類・主張の種類 | 共通の語 ＋ 台帳ごとの足し。上限つきの種類も宣言 |
| 言語 | 「読者に出る文の欄」に言語の印を付ける。2 列・1 列・別の置き場は、列の対応で受ける |
| 出所の持ち方（別の表・欄ごとの並び・3 段） | どれも「行（か欄）× 出典 × 場所 × 読みの段」に読み替える |
| 置き方（表・YAML・JSON・頭つきの .md） | 枚の行の中身の書き方と、表の行（§5.1） |
| 形（点を線でつなぐ・対象 × 時点 × 項目 = 値） | 値の線は主張の 1 つの形。憲法の `shape` は健康の見方を変えるだけ |
| 欄の名前のぶつかり・列の名前の違い（`object_text` と `object_text_ja`） | 頭と中身を分ける。列は対応で吸う |
| 改行（LF・CRLF）と引用の流儀 | 表ごとに覚えて保つ（§5.7） |
| 頁の作り（Astro・台本） | 器は「決まった場所へ材料を書く」まで。組み立てはサイトの側 |

**固有として残す物**（器に入れず、各メディアの repo と道具に置く）:

- 分野の言葉の点検（こぴちゃの評価語・染めと化学の表記の手引き・中受の問の親の言葉）。
- 観測の列の中身（布と染料・版と言語・商品の値段）。器は「観測の行で、だれが・いつ・何を・確かさの印」までを共通にする。
- 頁の型・デザイン・関門の中身（19 の関門・画面の柵）。
- こぴちゃの毎朝の商品の観測（VM が書く catalog と履歴）。量と拍子が別で、器に入れるかは別の話（§12）。
- MMR の曲の種の列と夜の仕事の進み。台帳ではなく仕事の列。
- キョンシーラボの物語と設定の資料。創作で、事実の台帳ではない（置くなら文の行として）。
- 関東の面をまとめる台本。

## 5. 器の形（案）

### 5.1 行の置き方を 2 つにする

**枚の行**: 1 行 = 1 枚の .md。上に THTH の頭、その下に**中身を元のファイルのまま**置く。

```
---
id: origin-brazil
kind: origin
status: 本採用
source: owner
confirmed: 本人が認めた
review_by: 2027-11-20
public: true
---
name: ブラジル
domain: coffee
aliases: [Brazil, ブラジル連邦共和国]
summary: …
```

- 中身は、種類の行が決めた書き方（文・YAML・JSON・頭つきの .md）で、元のファイルの最初の 1 字から最後の 1 字まで。THTH は中身を書き直さない。
- 頭と中身が別の場所なので、こぴちゃの `kind`・`source` とぶつからない。
- 今の店の種類（頭 ＋ 文）は「中身が文」の場合にあたり、今ある台帳は 1 字も直さずに読める。
- 頭を別のファイルに分ける形（中身は元の名前のまま・頭は表に持つ）は、頭と中身が離れてずれるので採らない。

**表の行**: 1 行 = CSV の 1 行。表のファイルは台帳のフォルダに置く。

- 頭の欄は、表の列と種類の行から決める。行ごとに頭を書かない。
- 番号を持たない表は、行に付く**子の表**（名前・タグ・概要）か、行と行を結ぶ**線の表**（言及・記事と主張の結び・図版と主張の結び）として宣言する。
- 上限は枚と別（叩き台: 1 つの表 20 万行・50 MB）。MMR の主張が 1.1 万行、外の番号が 1.5 万行ある。
- 主張を 1 件 1 枚の .md にばらす形は採らない（7 つを合わせて数万枚になり、どのメディアの道具も表を前提にしている）。

### 5.2 台帳の憲法と、種類の行

種類の決まりを、THTH のコードから台帳の側へ出す。台帳に 2 種類の行を置く。

**憲法の行**（台帳に 1 枚・`kind: charter`）: ラボの型の `lab.yaml` をそのまま受ける。

- 主題・一文の立場（**本人が書く。本人が認めた印が無ければ、材料にも下書きにも使えない**）・柱・引くための軸と許す値・観測の種類・出し口・形・言語・権利の既定・網羅の上限。
- 語の宣言: 主張の状態・読みの段・根拠の種類・述語・点の種類の語と、器の扱いへの対応（§4）。上限つきにする根拠の種類。
- 入れない物（個人の名前を点にしない、など）。
- 編集の考え・誰に届けたいか・扱わないこと（構想 §9 の 5 の「メディアの思いの層」）は、憲法の行の隣に思いの行として置く。

**種類の行**（種類ごとに 1 枚・`kind: kind`）:

```
---
id: kind-origin
kind: kind
status: 本採用
source: owner
confirmed: 本人が認めた
review_by: 2027-11-13
public: false
of: origin
place: 行/origins/*.md
content: yaml
required: name, domain, summary, updated
links: parent>origin, article>article
needs: 本人
export: src/content/origins/{name}.yaml
---
産地（国と地域）。こぴちゃの頁 /origins/<名前>/ の材料。
欄 name     文        要る   読者に見える
欄 calendar 数の並び  1〜12
```

- 宣言すること: 置き場・中身の書き方・要る欄・欄の型・読者に見える欄・分からないと書いてよい欄・つながり・既定で出さない欄・要る裏付けの段（`needs`）・二段で認めるか・見直しの既定の間隔・書き出し先。表の種類なら、番号の列と、頭の欄をどの列から取るか。
- 種類の行も行なので、認めた印・変えた跡・柵が同じように効く。**形を変えるのは意味を変えること**なので、憲法の行と種類の行を認める操作は二段にする（染めと化学の「列と語を変えるときは masaru に戻す」を柵にした形）。
- **備え付けの種類**を THTH が持つ: 今の店の 7 つ、網の型の表（点・名前・タグ・主張・根拠・出典・問い・観測）、図版、憲法、種類。台帳は備え付けを名指しして使い、足りない所だけ自分の種類の行で足す。新しいメディアは、備え付けを並べるだけで始められる。
- **THTH は憲法の行と種類の行に書かれた命令を実行しない。** 台帳はデータで、点検の中身は THTH のコードが持つ。
- 中身の点検の深さ: 文・JSON・CSV は標準の部品で全部見る。YAML は一番上の段の欄だけを読む小さな読み手を THTH に持つ（THTH は外の部品を足していない）。入れ子の中の型は、頁を作る側の点検（zod など）に任せる。

書き方の細かい所（頭の欄の名前・本文の「欄」の行）は叩き台。平たい頭に収まらなければ、中身を JSON にする道もある。

### 5.3 裏付けの段と、出所の網

今の 3 つの印は「この行を誰が請け合うか」を言っている。各メディアは同じことを、もう少し細かい段で持っている。**裏付けの段**を器の共通の物差しにする。

| 段 | 意味 | 各メディアの語 | 今の THTH |
|---|---|---|---|
| 0 推測 | だれも請け合っていない | unverified・needs_verification・仮説 | 推測 |
| 1 集めた | 書き手が出所から写した。書き手だけ | collected・machine_read・写し | — |
| 2 別の者が確かめた | 書き手と別の者が出所まで戻って確かめた | verified・rechecked・integrator_checked・照合済み | — |
| 3 本人が見た | 持ち主が自分で見て請け合った | human_checked・masaru の「見たよ」 | 本人が認めた |
| 否定 | 違う・確かめられなかった・原典に無かった | checked_unconfirmed・not_found・mismatch・refuted・要確認 | 本人が違うと言った |

- **種類ごとに「要る段」を決める**（種類の行の `needs`）。思い・店の事実・憲法の立場は「本人」。世の中の事実（主張）は「別の者」以上、が各メディアの今の決まり。害の大きい種類（営業の時間・入試の日付・安全や健康の数字）は「本人」か二段、と台帳が選べる。
- **3 つの印は見え方として残す**: 要る段に届かない＝推測、届いた＝認めた、否定＝違う。店主の台帳では今とまったく同じに見える。
- **裏付けは 2 通り**: 本人の一言（THTH の認めた記録に残る）と、出所の網（主張・根拠・出典の表に残る）。主張が材料に使える条件は、各メディアの今の決まりをそのまま器にする:
  - 主張の状態が「使える」か「上限つき」に対応する語で、
  - 支える根拠が 1 つ以上あり、その読みの段が要る段に届いていて、
  - その出典の権利の印が使える語で、
  - 期限（`valid_until`）を過ぎていない。
- **言い方の上限を材料に付けて渡す。** 弱い根拠だけなら上限つき・両論は並べるときだけ・自分の観測は「1 回だけ」「対照あり」などの印つき。3 つの印より細かい所は網が持つ。
- **同じ者の確かめを段に数えない。** 根拠の「集めた者」と「確かめた者」が同じなら段 1 のまま。今は各メディアの申し合わせで、柵になっていない。確かめた者を notes の文でなく欄に持つ（§6 の「跡」）。
- **関東・学校台帳の形**（行の中の `sources[]`）も同じ段で読む。「欄 × 出典 × 場所 × 読みの段」。
- **網の点検**: 主語と目的語の点が在る・根拠の主張と出典が在る・根拠の場所が空でない・権利の印が無い出典を使っていない・強さの上限を超えていない・宣言に無い語を使っていない・入れない物が入っていない。

### 5.4 行どうしのつながり

- 種類の行の `links` で「この欄は、どの種類の行の番号を指すか」を宣言する。表では列。
- 点検: 指す先が在る・種類が合う・親をたどって輪になっていない。指す先が退役なら知らせる。
- **番号は台帳の中で 1 つ**（今のまま）。こぴちゃの枚の行の番号は `<種類>-<ファイル名>` にする。こぴちゃの点の表がすでにこの付け方で、235 枚のうち 230 枚に同じ番号がある。
- 同じ番号が「枚の行」と「点の表の行」の両方にあるのは、**同じ物の 2 つの面**として受ける（点の表を「同じ番号の行に欄を足す表」と宣言する）。頁の無い点は表だけの行。
- **台帳をまたぐつながり**は `<台帳>:<番号>` と書く（§7.3）。相手の台帳が手元に無ければ「確かめられない」と言い、赤にはしない。
- **外の同じ物**（MusicBrainz の番号・DOI・店の頁の URL）は、形だけ点検する。外へ読みに行かない。
- 引く命令: `thth register links <行>`（指す行・指される行・付いている主張と根拠・使った先）。

### 5.5 変えた跡

- **土台は git**（構想 §3 の性質 4）。`thth register diff <前>..<後>` が、足した行・変わった行（どの欄か）・退役した行・消えた行を種類ごとに出す。表は番号の列で行を合わせる。
- **番号が消えたら赤**（`check --against <commit>`）。行は消さず退役にする、がどのメディアにも共通の決まり。
- **訂正の跡**を台帳の中に 1 つの表で持つ（追記だけ）: どの行のどの欄・旧い値の sha256・なぜ・誰が・いつ・どの出所で。読者に見せた事実を直したときだけ書く（誤字や整形は git だけ）。MMR と学校台帳が別々に持っている物を 1 つの形にする。頁に「直した日」を出すかは頁の側。
- **取り込みの跡**: 束ごとに、sha256・集めた者・検めた者・取り込んだ日・行の数（MMR の束の台帳）。
- **認めた跡**: 今は最後の 1 つだけ。認めた・外れた・違うと言った、を足していく形にする。
- git でない置き場の台帳は、跡が読めないと正直に言う。

### 5.6 書き出す口と、出した物の控え

`thth register export <台帳> --to <フォルダ>`（網に出ない・手元のファイルだけ）。

- 枚の行は、種類の行の `export` の道に**中身をそのまま**書く。表は**そのまま写す**。
- **差し込み**: 中身に `{{行の番号.欄}}` があれば、書き出すときに台帳の値を入れる（中受の問のやり方）。差し込みを使う種類だけ。使わない種類は 1 字も変わらない。
- **つながりから作る表**: 姉妹リンクのように、対応から決まる表は書き出しで作る（§7.3）。
- **材料の控え**（1 枚の JSON）: 書いたファイルごとの sha256・元の行の番号と指紋・台帳の commit・通した理由。時刻は入れない（同じ台帳からは同じ出力）。
- `--check`: 書かずに比べる。終了コードで赤緑。CI の柵。
- 書き出し先のファイルを THTH は消さない。余りは知らせる。
- **どの行を書くか**: 柵を通った行（§5.3）。移す前から公開していた中身は**基準**として通し、足した行・変えた行から柵が効く（§8.2）。`public: false` と出さない欄は、基準に在っても書かない。権利の印が無い図版は書かない。
- **出した物の控えと関門**（`thth register published`）: 出した URL を追記だけの控えに積み、build のあと「在る・転送がある・消した理由がある」のどれでもなければ赤。にがみラボの実装とラボの型の台本に判定を合わせ、今の 4 つの `published-urls.txt` をそのまま読む。各 repo の台本の写しを、これ 1 つに置き換えられる。
- **読者に見える欄の点検**: 内部の番号・作業の呼び名らしい語を拾う。分野の言葉の点検は各メディアに残す。
- 面をまとめて 1 枚にする組み立て・頁の型・サイトマップの点検は、器の口に入れない（サイトマップは media-hub の道具がある）。

### 5.7 書く口と、束の取り込み

表を手や置き換えで直して壊す事故を、器の側で無くす。

- `thth register row add|set <台帳> <種類> …`: 表に 1 行足す・1 欄直す。標準の csv の部品で読み書きし、**表ごとの流儀（改行・引用・列の順・末尾の改行）を保つ**。書いたあと、変わったのが触った行だけかを自分で確かめ、違えば書かずに断る。
- 枚の行は今のとおり（THTH が書くのは頭の決まった欄だけ）。
- `thth register merge <台帳> <束>`: 束（集めた行と、検めた者の判定）を取り込む。ラボの型の守りをそのまま: 判定が断りの行は入れない・重なる番号は入れずに知らせる・集めた者と検めた者が同じなら入れない・取り込んだあと点検が赤なら元に戻す・取り込みの跡を残す。`--dry-run` で数と問題だけ。
- 束の形（`bundle.json`・`verify.json`）はラボの型のまま受ける。こぴちゃの束（CSV の下書き）も受けられるかは作るときに見る。
- **THTH は集めない・検めない。** それは持ち主の LLM の仕事（構想 §9 の 4 の分け方）。器は、検められていない物が台帳に入らないこと、だけを受け持つ。

### 5.8 健康と見直し

`thth register health <台帳>`（読むだけ・台帳を書き換えない）。

- 網の健康（ラボの型）: 目的語が点である線の率・線が 0〜1 本の点・述語の偏り・開いた問いの数と閉じ方・読みの段の分布・時間の欄の有無・`--thin` で薄い点。
- 裏付けの健康: 段 1 のままの行・基準で通っただけの行・同じ者が確かめた行・権利の印の無い出典・期限が近い行。
- 見直しの候補（スコアボードの決まり）: 試しのまま見直し日を過ぎた・本採用で見直し日を過ぎた・長く動かない。**候補を出すだけ**で、決めるのは持ち主。
- 今の `register holes`（店主に聞く穴）は、この health の「持ち主に聞く分」として残す。
- `--json` の 1 行を hub が朝の 1 枚に束ねられる形にする（§7.4）。

### 5.9 今ある部品とのつなぎ方

| 今ある物 | 器を広げたあと |

| 3 つの印 | 裏付けの段の見え方（§5.3）。店主には今と同じに見える |
| 認めた記録（`confirmed.json`） | 「誰が・どう・どの段で」を持つ跡にする。機械ごとの記録なので、書き出しは記録のある 1 台でして、ほかは材料の控えで確かめる |

| 穴・問い | §6 |
| きっかけ | 変えた跡と期限がきっかけの元になる |

## 6. 今の THTH の台帳から変える所

5.19.0 は出たばかりで、使っているのは見本の店と例の台帳。変えるなら今がいちばん安い。互換は「今の台帳のファイルが 1 字も直さずに同じ結果で読める」を条件にする。

| 今の作り | 変える形 | なぜ | 互換 |
|---|---|---|---|
| 種類の決まりが Python の表（`kinds.RULES`）に店の 7 つ | 台帳の憲法の行と種類の行が宣言。THTH は備え付けの種類を持つ | 自前のメディアの種類を THTH のコードに書き足し続けられない | 7 つは備え付けとして残る |
| 台帳の種類が `media` か `store` の 2 つ（`ledger.KINDS`） | この区別をやめ、憲法の行が形を言う | 店とメディアの違いは種類の並べ方の違いで、器の違いではない | 控えの `kind` は読むが、動きを変えない |
| 行は 1 枚の .md だけ・頭は平たい行だけ | 枚の行（中身は元のまま）と表の行 | §1 のどの台帳も入らない | 今の行は「中身が文」の枚の行 |
| 頭の `source` が 4 語（owner・asked・guess・register） | 「誰が書いたか」の語として残し、`cited`（出所から集めた）と `observed`（自分の観測）を足す。`register`（レジから）は「外から取り込んだ」の意味に広げる | 何を根拠にしたかは網が持つ。`source` に両方を負わせない | 4 語はそのまま通る |
| `confirmed` が 3 語で、段が「推測」と「本人」の 2 つしか無い | 裏付けの段（§5.3）。頭の 3 語は見え方として残す | 別の者が確かめた、を受けられない。全部を masaru が認めるのは回らない | 店主の台帳は今のまま |
| 認めた記録が、行 → 最後の指紋 1 つ | 誰が・どう（本人の一言・別の者の確かめ・基準）・どの段で、を足していく跡 | 外れた・認め直したが残らない。同じ者の確かめを見分けられない | 今の記録は「本人の一言」の最後の 1 件として読む |
| `review_by` が行ごとに必須 | 種類の行に既定の間隔を書ければ、行では省ける。表の行は列（`valid_until` など）か既定から | 数千行に 1 つずつ日付を書けない | 書いてある行はそのまま |
| `public` が出す・出さないの 2 つ | そのまま。任意の欄 `search`（検索に出す・出さない）を足す | 出すが検索に出さない、が 4 つのメディアにある | 無ければ今のまま |
| 柵の答えが「使える・使えない」 | 使える・言い方の上限つき・使えない | 上限つきの主張を、言い切りで使わせない | 店の行は今と同じ答え |
| 既定で出さない欄・二段で認める種類がコードの表 | 種類の行が宣言 | 関東の原文の引用・入試の日付などを台帳が選べる | 備え付けの 7 つは今の値 |
| THTH が台帳に書くのは頭の決まった欄だけ | 枚の行はそのまま。表には `row add・set`・`merge` で書く | 表を手で直す事故を無くす | 今の決まりは枚の行でそのまま |
| つながりは思いの行の `about` だけ・点検なし | `links` の宣言と点検 | — | `about` は備え付けの思いの種類の `links` になる |
| 変えた跡は git 任せで、THTH は読まない | `diff`・`check --against`・訂正の跡・取り込みの跡 | 行が消えても気づけない | 足すだけ |
| 下書きの控え（`drafts.json`） | 「使った先の控え」に広げる（頁・貼る文も） | 行が変わったとき、直す先が分からない | 今の控えはそのまま読む |
| 問いの記録（持ち主に聞く）と、各メディアの問いの表（世の中に聞く）が別の作り | どちらも「問いの行」にする。聞く相手（持ち主・出所）を欄で分け、「違う・確かめられなかった」を同じ否定の段に置く | 同じ考え（聞き直さない・消さない）を 2 つ作らない | 今の問いの記録は読める。行にするのは持ち主が選ぶとき |
| `register holes`（店の穴） | `register health` の一部 | §5.8 | 命令は残す |
| 上限が行 5,000 枚・1 枚 64 KB | 枚はそのまま。表に別の上限 | — | — |
| 台帳は 1 つの project に 1 対 1 で控える | 持ち主の共通の台帳と、台帳をまたぐつながり（§7） | — | 今の控えはそのまま |

## 7. 1 人で複数のメディアを持つ場合

私たちが 1 人で 7 つ以上を持っているのが実例。外の利用者が 1 店で始めて増やす場合にも、同じ形で届くようにする。

### 7.1 階層

```
持ち主（THTH の利用者）
├─ 共通の台帳（持ち主に 1 つ。無くてもよい）
├─ メディア A（THTH の project）── 台帳（1 つ以上）・口座
├─ メディア B ── 台帳・口座
└─ …
```

- **メディア = 今の THTH の project。** 口座の台帳（`accounts/<名前>.json`）も台帳の控え（`registers/<名前>.json`）も、すでに `project` を持つ。media-hub の `media.yaml` も `thth_project` で指している。新しい層は作らない。
- **持ち主 = THTH の利用者**（資格の行の持ち主）。足すのは「共通の台帳」の控えだけ（project を持たない台帳）。
- 1 つのメディアが台帳を 2 つ以上持ってよい（例: こぴちゃの知識の台帳と、将来の商品の観測の台帳）。分ける理由は、書く拍子と書く者が違うとき。

### 7.2 共通の行の持ち方

**共通の台帳に 1 つだけ置き、各メディアの台帳から指す。写しを作らない。**

| 共通に置く物 | 例 | 注意 |
|---|---|---|
| 運営者の情報 | 運営者の名前・連絡の窓口・特定商取引法の表記 | 既定で出さない欄にする。家族の名前は入れない |
| 持ち主の思い | メディアをまたぐ編集の考え・扱わないこと | 本人が認めた行だけ |
| 口座の一覧 | SNS・はてな・店・Google のどの口座がどのメディアの物か | **鍵は入れない**（今の決まり）。名前と向き先だけ |
| 同じ物の対応 | 同じ化合物・同じ工程・同じ店・同じ生産者・同じ用語 | §7.3 |
| 同じ出典 | 同じ論文・同じ規格 | 下の「今ある物」 |
| 書き方の決まり | 表記・原稿の URL の印・読者に見える文の決まり | 文の行。点検は各メディア |
| 図版 | メディアをまたいで使う図・写真と権利 | 権利の印が要る |

- **指し方**: メディアの行の欄に `共通:<番号>` と書く（台帳をまたぐつながり）。書き出すとき、THTH が共通の行の出してよい欄を材料に入れる。書き出した材料は写しだが、正本ではない（材料の控えに元の行の番号と指紋が残る）。
- **今ある物は番号を変えない。** こぴちゃとにがみラボが別の番号で持つ同じ出典・同じ点は、**対応の行**（共通の番号 → 各メディアの番号）で結ぶ。media-hub の対応表の今の決まり（各メディアの番号は変えない）と同じ。**新しく足す共通の物から、共通の台帳に置く。**
- 同じ出典の見つけ方: `thth register health --across` が、DOI・URL が同じで番号の違う出典、読みの段や権利の印が食い違う出典を並べる。結ぶかは持ち主が決める。
- 共通の行を変えると、指しているメディアの材料が変わる。`thth register used 共通:<行>` で、どのメディアのどの頁が変わるかを先に見せる。

### 7.3 メディアどうしのつながり

- **対応の行**: 1 行 = 1 つの「同じ物」。各メディアでの番号を欄に持つ（今の `registry/concepts.csv` の形そのまま）。下位の物を別の行にしない・個人の名前と商品の名前は共有しない、も今の決まりのまま。
- **姉妹リンクは対応から書き出す。** 今は各メディアが `sister-links.csv` を持ち、片方向になりうる。対応の行に「どの頁からどの頁へ・一言」を持たせ、両方のメディアの書き出しで同じ対から作る。片方だけ、が起きない。
- 相手のメディアの頁が退役・転送になったら、出した物の控え（§5.6）で分かり、リンクの側に知らせる。
- 対応の行の置き場は §7.6。

### 7.4 管理の仕方

- **足す**: メディアの台帳のフォルダを作り（備え付けの種類を並べた憲法の行から始める）、`thth register add <台帳> --project <メディア>`。共通の台帳に、そのメディアの行（名前・URL・状態・台帳の名前）を 1 枚足す。
- **退役**: メディアの行を退役にする。台帳の行も出した URL も消さない（どのメディアにも「公開した URL は消さない」がある）。口座は止める（今の止めの印）。書き出しと出した物の関門は動かし続ける（頁は残るため）。
- **外す**: メディア単位の `leave`（下）。
- **鍵と口座**: **主体は持ち主に、口座はメディアに。** 今のはてなの作り（主体 = はてな ID 1 つと鍵、口座 = 主体 ＋ ブログ 1 つ）を、ほかの口にも広げる向き。Google は 1 つの主体（THTH の Google のアカウントは 1 つに寄せる、と 11/13 に決まっている）で、プロパティや店はメディアごと。止め・上限・ロックは主体に 1 つ（今のまま）。鍵は THTH の鍵の置き場で、台帳には入れない。
- **書ける範囲**: 器は手元のファイルに鍵を掛けられない。境は git の repo（メディアごと）と、各 repo の入口の文書が持つ。器が受け持つのは、(1) 跡に「誰が」を残す、(2) `diff` で「どの台帳のどの種類が変わったか」を出す、(3) 憲法の行・種類の行・共通の行の変更を二段にする、の 3 つ。レーンの名簿と割り当ては hub の物（§7.6）。
- **まとめて見る**: `thth register health --all --json` が、メディアごとに 1 行（行の数・裏付けの段の分布・赤の数・見直しの候補の数・期限の近い行）を出す。hub を持つ私たちは hub の朝の 1 枚が束ね、hub を持たない外の人は `thth morning` がそのまま並べる。
- **leave と持ち出し**:
  - メディア単位: その project の口座・台帳の控え・認めた跡・使った先の控えを消す（今の `leave` は、その project の最後の口座で台帳の控えを消す。これを「メディアを名指しして外す」に広げる）。台帳のフォルダは消さない。共通の台帳は残る。
  - アカウント単位: 全部のメディアと共通の台帳の控えを消す。
  - 持ち出し: 台帳はもともと持ち主のフォルダにある。持ち出す物は THTH の側の記録（認めた跡・使った先の控え・出した記録）で、`thth register state export` が台帳のフォルダに平文で書く。メディアを 1 つだけ持ち出す（譲る・分ける）ときは、そのメディアが指している共通の行を写して付ける（`--with-shared`）。出さない欄は付けない。

### 7.5 1 店・1 メディアで始めて、あとで増やす道

1. 最初は台帳 1 つ。共通の台帳は無い。今の 5.19.0 と同じ使い方で、何も増えない。
2. 2 つめを足すとき、THTH が「両方に同じ物がありそう」（運営者・店の住所・思い・口座）を並べる。
3. 持ち主が選んだ物だけ、共通の台帳へ移す。元の行は番号を変えず、「共通を指す行」になる。認めた印は、移した行でもう一度認める（中身の置き場が変わるため）。
4. 移さなくても動く。共通の台帳は便利のための物で、必須にしない。

### 7.6 hub との線

- **器・点検・書き出し・健康の数は THTH。メディアの指揮（どのメディアを・いつ・誰が・何で回すか）は hub。**
- hub に残す: レーンの名簿と呼び名（`callnames.yaml`・`posts.yaml`）・伝言・申し送り・承認の台帳（`hub approve`）・朝の 1 枚・スコアボード（指標の台帳と毎朝の値）・計測の道具（`gsc.py`・`cfa.py`）。
- THTH が出す: 台帳の健康と変えた跡の 1 行（hub が読む）。
- **重なる所が 2 つある。相談して決める**（構想 §7・§9 の 6）:
  1. メディアの一覧。hub の `media.yaml`（URL・状態・repo・計測のプロパティ・配信の project・`thth_project`）と、THTH の共通の台帳のメディアの行（名前・URL・状態・台帳）。推し: 名前・URL・状態は THTH の行を正本にし、hub は指揮に要る欄だけを持って `thth_project` で指す。hub を持たない外の人にも同じ形が届くため。
  2. 対応表。今は hub の `registry/`。推し: 形は THTH の対応の行にし、置き場は共通の台帳（§9 の 2 問め）。hub は読む側になる。
- 計測の数を行へ返す口（構想 §6 の「無い物」）は、この書に入れない。数は hub の道具が取り、行の頭の数の欄に書くのは THTH、という分け方を別の書で決める。

## 8. 移し方（こぴちゃを最初にする場合）

### 8.1 何を移し、何を移さないか

| 物 | 扱い | 理由 |
|---|---|---|
| `src/content/` の 296 枚 | 枚の行 | サイトの「もの」と頁の文 |
| `data/knowledge/` の 11 の表 | 表の行・子の表・線の表 | 出所の網 |
| `data/sister-links.csv` | 移す（のちに対応から書き出す） | §7.3 |
| `data/published-urls.txt`・`gone-urls.txt` | 出した物の控えとして読む（置き場はそのまま） | §5.6 |
| `data/knowledge/staging/` | 移さない | 検める前の作業の場 |
| 商品の catalog・値段の履歴・観測の状態 | 移さない | VM が毎日書く観測。器に入れるかは別の話 |
| `data/sns/` | **移さない** | ほかの人の投稿が入る（構想 §5） |

### 8.2 段取り

1. **相談**（コードなし）: こぴちゃのレーンに §8 と §10 を hub msg で渡し、都合（書く道具・CI・VM の時刻）を聞く。media-hub の本線に §7.6 を渡す。
2. **基準を決める**: こぴちゃの main のある commit。その `src/content/` と `data/knowledge/` の全ファイルの sha256 の一覧を作る。
3. **影で作る**（こぴちゃの repo には書かない）: `thth register adopt` が基準の写しを読み、repo の**外**（`~/Documents/thth-register-kopicha/` など。会話の置き場には置かない）に台帳を作る。憲法の行と種類の行は THTH開発が書き、こぴちゃのレーンが見る。
4. **影で確かめる**: §8.3 の 3 つ。こぴちゃの正本は元のまま。こぴちゃが進むたびに取り込み直す（片道だけ）。
5. **基準を認める**（masaru の承認 1 回）: 「移す前に公開していた中身を、基準として認める」。二段で、見せる物は基準の commit・行の数・一覧の sha256。跡には行ごとに「基準」と残る。
6. **向きを替える**（こぴちゃのレーンの 1 つの commit）: 台帳を repo に入れ、入口の文書に「正本は台帳。`src/content/` と `data/knowledge/` は書き出した写し」と書き、CI に `export --check` を足す。この commit では材料のファイルは 1 字も変わらない。
7. **書く道具の書き先を替える**（こぴちゃのレーン）: 網に書く道具の書き先を台帳へ（のちに `register row`・`merge` に寄せる）。読む道具はそのまま。
8. **柵を効かせていく**: 足した行・変えた行は柵を通る。基準で通っただけの行は health に出し、こぴちゃのレーンの拍子で確かめ直す。

**写しは repo に commit する**（build のたびに書き出す形にしない）。サイトの build が THTH に頼らず、戻すのが revert 1 つで済み、読む道具が今の場所のまま動き、認めた記録が 1 台にしか無くても回るため。代償は同じ中身が 2 か所に在ることで、CI の柵で受ける。`thth sync` で記録を運べるようになったら見直す。

### 8.3 「移す前と後で頁が 1 字も変わらない」の確かめ方

作った者と別の者（別のサブエージェントか Codex）が、命令を打ち直して確かめる。

1. **材料の一致**: 書き出した物と基準を、ファイルの一覧と sha256 で比べる。数・名前・全部の sha256 が同じ。
2. **頁の一致**: 同じ commit・同じ `node_modules`・同じ日に、(a) 基準のまま build、(b) 材料を書き出した物に差し替えて build。`dist/` の全ファイルの sha256 を比べる。先に (a) を 2 回 build して、もともと揺れるファイル（build の時刻が入る物・検索の索引など）を調べ、名前と理由を書き出す。それ以外は 1 つ残らず同じ、が条件。揺れが多すぎて比べにならなければ、止まって知らせる。
3. **柵を壊して赤を見る**: 影の台帳の 1 行を 1 字変える → `export --check` と `dist` の比べが赤。行を 1 つ消す → `check --against` が赤。表の 1 行を変える → 赤。

### 8.4 移す間、こぴちゃの運用を止めない

- **正本はいつも 1 つ。** 替える前は元の場所、替えたあとは台帳。両方に書く期間を作らない。
- 影の間、こぴちゃのレーンは何も変えずにいつものとおり書く。
- VM の毎日の観測は、移す物に触れない（直近 1 週間の VM の commit は約 490、content と網への commit は 2 週間で十数ファイル）。向きを替える push は VM が push する 04:00〜04:30 を避ける。
- 向きを替える commit は材料を変えない。**戻し方は revert 1 つ。**

### 8.5 どのレーンが何をするか

| だれ | すること |
|---|---|
| THTH開発 | 器・道具・柵・試験。憲法と種類の行の叩き台。影の台帳と §8.3 の証明。ほかの repo は**読むだけ** |
| こぴちゃのレーン | 種類の行を見て直す。台帳を repo に入れる commit・入口の文書・CI の柵・書く道具の書き先・main への push（こぴちゃの repo はこぴちゃのレーンの持ち場。push は即公開） |
| ほかのメディアのレーン | 影の点検で出た問題の一覧を受け取るだけ（この版では何も変えない） |
| masaru | §9 の 2 問・基準を認める・向きを替えてよいかの承認・THTH の release の「出して」 |
| 別の者 | §8.3 を打ち直して確かめる。Codex に頼むときは「ファイルを変更・削除・commit しない」と書く |
| media-hub の本線 | §7.6 の 2 つの相談 |
| THTH運用 | 動かない（器は手元で回る物で、VM の版を上げても本番の動きは変わらない） |

頼み方: 依頼の本文は THTH の repo の `docs/` に書き、hub msg で要点と道だけを送る。

## 9. 割れる判断（2 問）

### 1. 「そのまま」を、元のファイルを 1 字も変えずに包む形にするか、THTH の 1 つの形に開き直すか

- **包む（推し）**: 枚の行は中身を元のまま、表は表のまま。語も番号も各メディアのまま、憲法の行で器の段に対応づける。
  - 得る物: 頁が変わらないことを sha256 で言える。7 つのメディアの道具と決まりがそのまま使える。影で 7 つとも点検できる。
  - 払う物: 台帳の中に YAML・CSV・JSON が混ざる。器は憲法と種類の行を読む機械になり、作る量が増える。語がメディアごとに違うまま残る（対応で読む）。
- **開き直す**: どの行も「頭の欄 ＋ 文」の 1 つの形・1 つの語にそろえる。
  - 得る物: 形も語も 1 つで、外の店主にも素直。メディアをまたいだ集計が楽。
  - 払う物: 7 つを合わせて数万枚になる。どのメディアの道具も書き直す。書き出しは「読んだ値が同じ」までしか言えない。各レーンの手が長く取られる。
- **前提が変わると**: 「外の人に配る 1 つのきれいな形」を自前のメディアより先にするなら、開き直す側が強くなる（その場合も表は表のまま残すのを勧める）。包む形で始めても、あとで種類ごとに開き直せる。逆向き（開いた物を元の字に戻す）はできない。

### 2. メディアをまたぐ同じ物を、どこに持つか

- **共通の台帳に置き、各メディアから指す。今ある物は番号を変えず対応で結ぶ（推し）**: §7.2・§7.3。対応表は hub の `registry/` から、THTH の形の共通の台帳へ移す。
  - 得る物: 写しが増えない。hub を持たない外の人にも同じ形が届く。メディアを 1 つ譲る・外すが、台帳の単位でできる。
  - 払う物: 台帳をまたぐつながりを作る。共通の行を変えると複数のメディアの頁が変わるので、二段と「使った先」の見せ方が要る。対応表の持ち主が hub から変わるので、media-hub の本線との相談が要る。
- **全部を 1 つの大きな台帳にする**（メディアは台帳の中の区分）:
  - 得る物: つながりが全部台帳の中で、点検が単純。同じ出典は初めから 1 つ。
  - 払う物: 番号を付け替える（今の「各メディアの番号は変えない」を破る）。repo がメディアごとに分かれている今の作り（push が即公開のメディアと、承認つきのメディアが混ざる）と合わない。メディアを 1 つ外すのが難しい。
- **今のまま**（各メディアが持ち、対応表は hub）:
  - 得る物: 何も動かさない。
  - 払う物: 同じ出典の食い違いが見えないまま。外の人には対応の仕組みが届かない。
- **前提が変わると**: メディアを譲る・分ける見込みが無く、1 つの手で全部を回すなら、大きな 1 つの台帳の代償は下がる（それでも番号の付け替えは残る）。hub の本線が対応表を hub に残したいなら、形だけ THTH の対応の行にして置き場は hub の repo、でも器は同じに動く（共通の台帳の控えを hub の repo の中のフォルダに向けるだけ）。

## 11. 危ないこと

1. **サイトが壊れる・頁が変わる。** 柵を移した日から効かせると頁が欠ける。→ 基準で通す。向きを替える commit は材料を変えない。`dist` の sha256 を前後で比べる。
2. **出所が落ちる。** 表を読んで書き直すと全行が変わる（にがみラボと染めと化学で事故の記録）。→ 写すだけ・書くときは流儀を保ち、触った行だけが変わるのを自分で確かめる。根拠の無い主張（こぴちゃで 16 件）・権利の印の無い出典（34 件）は落とさず、見え方を「推測」にして残す。
3. **二重の正本になる。** 影の台帳に書く・替えたあとに写しへ書く・共通の行を各メディアに写す、のどれでも起こる。→ 影は片道。写しは CI の柵。共通の行は指すだけで、材料の控えに元の番号と指紋。
4. **語の対応を間違えて、弱い主張が「使える」になる。** → 対応は憲法の行に書き、二段で認める。段 3 で各メディアの今の点検と数を比べる。対応の無い語は「使えない」に倒す。
5. **「認めた」の重みが薄まる。** 基準をまとめて認める・別の者の確かめで通す、で、masaru が見ていない行が材料になる。→ 跡に「基準」「別の者」「本人」を分けて残す。害の大きい種類は台帳が「本人」を選べる。health に出す。
6. **認めた記録が機械ごと。** → 書き出しは 1 台で。ほかは材料の控えで確かめる。持ち出しの口を作る。`thth sync` で見直す。
7. **憲法と種類の行が攻め口になる。** → 命令を実行しない。道の宣言は台帳のフォルダと書き出し先の中だけ。
8. **共通の行の変更が、複数のメディアの頁を一度に変える。** → 二段。「使った先」を先に見せる。
9. **共通の台帳に運営者や家族の情報が入る。** → 既定で出さない欄。憲法の「入れない物」。持ち出しに付けない。
10. **器が重くなり、店主の台帳が難しくなる。** → 憲法の行も種類の行も無い台帳は今のまま動く。表・網・共通の台帳は、使う台帳にだけ見える。
11. **1 回の release が大きすぎて遠のく・確かめきれない。** 段 1〜9 は量が多い。→ main に段ごとに積み、段ごとに影の実物で確かめる。それでも重いなら、段 6〜8（書く口・健康・複数のメディア）を次の版に分ける道がある（masaru の「1 回」とぶつかるので、分けるなら聞く）。
12. **台本を置き換える途中で、結果が食い違う。** → 置き換える前に、同じ入力で今の台本と結果を比べる。食い違ったら、どちらが正しいかをそのメディアのレーンと決める。
13. **hub との線がぶつかる。** メディアの一覧と対応表が 2 か所になる。→ §7.6 の 2 つを先に相談する。決まるまで、THTH は hub の物を読むだけ。
14. **ほかの人の投稿や個人の情報が台帳に入る。** → `data/sns/` は移さない。`adopt` は宣言した置き場だけを読む。
15. **build の揺れで「同じ」が言えない。** → 先に同じ物を 2 回 build して揺れを知る。
16. **VM の push とぶつかる。** → 向きを替える push は時刻を避け、そのメディアのレーンが押す。

## 12. この案で決めていないこと

- 思いの層を、自前のメディアでどう聞いて貯めるか（構想 §9 の 2）。憲法の一文の立場はすでに本人が書いている。

- 学校台帳と中受の問を、いつ器に入れるか（関東と同じ時期が素直）。
