## 0. 芯

Things の正本として、器が持つ概念は **2 つ**にする。**記録**と**判断**。ほかの物（つながり・軸・見え方・索引・材料の控え・健康）は、この 2 つから導く。

### 0.1 記録

- **記録** = 番号・種類・中身。主張も根拠も出典も問いも、頁の文も、店の営業の時間も、監査の結果も、種類の違う記録。
- **番号**は「同じ記録」を指し続ける。中身が変わっても番号は同じ。
- **版**は中身の指紋で、**全バイトから取る。** 1 字でも変われば版が変わる。原物を 1 字も違わず戻せたかを見るのは、この指紋。欄を除かない（第 3 版は「進みの欄を除く」としていた。それだと、進みの欄だけが変わった原物を「同じ」と言ってしまい、戻す証明にならない）。
- **依る所の指紋**を、版とは別に取る。「この問いへの答えが依る欄と、指す先の欄」だけから取る指紋で、判断が効き続けるかはこちらで見る（§5.3）。
  - MMR の `queue.json` の 1 曲は 14 の欄を持つ。サイトが曲の頁に読むのは 9 つ（`ledger.ts` の `Seed`）で、`research_status`・`wave` は読まない。その 2 つは、次に調べる曲を選ぶ道具（`prepare_waves.py`）が読み、取り込みの道具（`accept_onepass.py`）が書き換える。VM が進みを書けば版は変わるが、曲の頁についての判断の依る所は変わらない。
  - こぴちゃの `article-claims.csv` は、主張の行の全部でなく `statement_ja` と状態だけから控えを取っている。今の THTH が「THTH が書く欄を除いた全文」で指紋を取るのも同じ考えで、どちらも依る所の指紋。
  - 依る所を宣言していない問いは、全バイトに依る（安全な側。要らない失効が増えるだけで、要る失効は落とさない）。
- **記録は、ほかの記録の番号を指す欄を持てる**（主張 → 点、根拠 → 主張と出典）。これが「つながり」。芯を別に立てない。
- 「同じ」は 3 つを分ける。
  - **同じ物**（世の中の物。ブラジルという産地）: 番号ではない。物を表す記録を 1 つ決め、ほかの記録が「について」で指す。
  - **同じ記録**: 番号。
  - **同じ場所**（どのファイルの何番め）: 番号にしない。並べ替えで変わる。

### 0.2 判断

- **判断** = 「どの記録のどの版（の組）について・どの問いに・誰が・何に照らして・いつ・台帳の語と条件・理由（種類と説明）・いつまで」。
- 本人が認めた・別の者が原典で確かめた・監査が通った・この出し口へ採った・基準として認めた・止める、はどれも判断。別々の仕組みにしない。違うのは、問いと、誰がと、照らした物。
- **版を持つのは、判断と来歴の控え。** ふつうの指す欄は番号で指す。
  - 判断は「見たときの版」と「依る所の指紋」を持つ。依る所が変われば、その判断は効かなくなる（古い判断として残る）。
  - **来歴の控え**は「あのとき、この記録のこの版を使った」という記録で、判断ではない（正しいと認めてはいない）。こぴちゃの `article-claims.csv`（2,650 行・本文 69 枚）は、記事が依っている主張の番号に加えて、**そのときの主張の文の指紋と状態**を持つ。番号だけにすると、主張が訂正されたあと、記事がどの文に依っていたかが分からなくなる。材料の控え（この世代は、この入力の版の組から出した）も同じ仲間。種類の違う記録として持ち、芯は増やさない。
- **書いてあるだけの状態は「観測」。判断ではない。**
  - 中に書いてある物（主張の状態・照合台帳の `shown`／`held`・下書きの印・店の頭の `confirmed`）を、器は「この版に、この状態が書かれていた」と控える。ここまでが観測で、使えるかの計算には入れない。
  - 判断として効くのは、次のどれかがあるときだけ: (1) **対象の版を示す検収の記録**（§5.3）、(2) **明示の受け入れ**（取り込みのときの基準・`judge`）。
  - なぜ観測で止めるか（こぴちゃの実物）: 主張 `c-term-tea-grade-ctc-res-milktea1-24` は、10/4 の commit `8ead0fc` で、水浸出物 17.3% を 17.1% に直した。状態は `supported` のまま。同じ commit で記事の側の控えも取り直してある。取り込みの道具（`knowledge-k1-merge.mjs` の 42〜46 行）は、文と状態を同時に書き換えられる。**状態が同じでも新しく確かめた場合があり、状態が変わっていても新しい文を確かめた証拠にはならない。** 最後の状態だけを見て、この 2 つは分けられない。
  - 第 3 版の「見つけたときの指紋と一緒に控え、中身だけが変わったら古いと言う」は取り下げる。文と状態が一緒に変わると、器には新しい承認に見えてしまう。
  - これで、今の THTH の「頭に印を書いただけでは使えない」と同じ線に戻る（頭の `confirmed` は観測、THTH の側の記録が判断）。
- **結論の 3 つ（よい・だめ・まだ）は、具体的な問いに答えるときの返し方。** 台帳の語を 3 つに置き換えて保存しない。
  - 判断が持つのは、台帳の語（染めと化学の 7 語など）と条件（範囲・限り）。憲法が「この語は、この問いには、どの結論・どの理由の種類にあたるか」を宣言し、問われたときに 3 つで返す。対応の宣言が無い語は、その問いには「判断が無い」。
  - 今の 3 つの印（本人が認めた・本人が違うと言った・推測）は、問い「本人はそうだと言うか」への 3 つの結論で、そのまま当てはまる。
  - 「推測」と「調べたが届かなかった」はどちらも**まだ**で、理由が違う。
  - **だめは、決着した判断。** 食い違う根拠があることは記録の事実で、それだけでは「だめ」にならない。
  - **理由は 2 つ持つ**: 機械が読む種類（台帳が宣言した語の中から）と、人が読む説明。決まりは種類を読む（§5.3）。

### 0.3 導く物

| 導く物 | 何から |
|---|---|
| **使えるか** | 決まり（憲法。これも記録で、本人の判断が付く）に、判断と判定の日時と用途を当てて計算する。保存しない |
| 9 つの軸（第 2 版） | 保存しない。記録の中身・指す欄・判断から読む問い（§5.3 の表） |
| 4 つの見え方（第 2 版） | 問いへの答えとしての 3 つの結論と、理由の種類 |
| 支えと反証の数 | 根拠の記録の指す欄から数える |
| 確かめの索引 | 判断の記録そのもの |
| 観測 | 記録の「状態の欄」を読んだ結果（版つき）。作り直せる |
| 材料の控え | 「この世代は、この入力の版の組から出した」という来歴の控え。封（§5.6）はこれに付く |
| 健康 | 記録と判断の数え方 |

### 0.4 Codex の 3 つの芯との違いと、3 回めでの決着

Codex は 2 回めで、芯を「番号と版を持つ記録」「版を指すつながり」「用途を限った判断」の 3 つにした。第 3 版は実物に当てて 3 か所に反対した。3 回めで Codex は芯 2 つを支持し、下のとおり決着した。

| 論点 | 決着 | 根拠（実物） |
|---|---|---|
| つながりを芯の 1 つにするか | **しない。記録の中の指す欄**（Codex が撤回） | 根拠は、場所・要約・読みの段を持ち、それ自体が確かめの対象になる。関係に説明や判断が要るときも「対応の記録」「根拠の記録」で表せる |
| つながりは版を指すか | **ふつうは番号。版も持つのは判断と来歴の控え**（Codex の「全部が版」も、第 3 版の「判断だけ」も強すぎた） | どの表も番号で指す（こぴちゃの根拠 6,995 本）。一方、こぴちゃの `article-claims.csv` は、使った主張の文の指紋を控えている。**第 3 版はこれを「記事の文の指紋」と読み違えていた**（控えているのは参照した主張の文） |
| 中に書いてある状態 | **観測として受ける。判断として効くには条件が要る**（第 3 版の「これも判断」は言いすぎ） | こぴちゃ `8ead0fc`（§0.2） |
| 判断を限るのは用途か | **問い**。用途は「出してよいか」の入力（Codex が撤回） | MMR は照合の結果（`shown`／`held`）と出し口（`public`／`public_song`）が別の欄 |

## 2. 読み取れること

**共通の骨（すでにそろっている物）**

1. 点・名前・主張・根拠・出典・問い・観測、の表の組。
2. 「1 行 1 事実」「原文を写さず要約」「根拠の場所は必須」「権利の条件を満たさない物は使わない」。
3. 書き手と別の者が確かめ、確かめた跡を残す。
4. 行は消さず退役にする。出した URL は消さない。
5. 試し → 本採用 → 退役と、見直し日。
6. 本人の言葉は本人が書く。

**メディアごとに違う所（§4 で一般化する。語をそろえるのでなく、軸と宣言で受ける）**

- 主張の状態の語と、その条件（`established` の条件は染めと化学とキョンシーで生きていて、MMR は廃止した）。
- 読みの段の語（キョンシーの `human_reviewed`、こぴちゃの verified・rechecked、MMR の 3 値）。
- 弱い根拠の扱い（MMR は報道と DB を一律に弱いとする決まりをやめた）。
- 出所の持ち方（別の表・欄ごとの並び・3 段）。置き方（表・YAML・JSON・頭つきの .md）。
- 出し口の数（MMR の照合台帳は 2 つ）。期限の意味（見直すだけ・伏せる）。
- 図版の条件（資料の図は利用の条件、再現図は根拠と生成の記録）。
- 出した URL の関門の厳しさ。

**弱い所（器の側で直す）**

- **点検の台本が、今の決まりと食い違っていても気づけない。** MMR の台本には廃止した条件が残るが、今の主張に `established` が無いので全件が通る。
- **表を手で直して壊す事故。** にがみラボの 33 枚は、CRLF だけが 12・LF が 20・**混ざっているのが 1 枚**（`topic-hubs.csv`）。染めと化学では文字列の置き換えが引用符を壊した。
- **取り込みが途中で止まると戻らない**（こぴちゃの K1 の取り込み）。
- **確かめた跡が `notes` の欄に文で詰めてある。** 機械で引けない。
- **未確認と否定が、道具によっては同じ扱いになる。**
- **対応表が「同じ物」と「関わりのある物」を分けていない。**
- **THTH の今の台帳は、この骨をほとんど受けられない**（§6）。
- **こぴちゃの欄の名前が THTH の頭とぶつかる**（`kind`・`source`）。

## 4. 一般化する違いと、固有として残す物

**語をそろえない。** 各メディアの語と番号はそのまま台帳に残し、問い・判断・名前付きの検査で受ける。

| 違い | 器の決まりにする形 |
|---|---|
| 主張の状態の語と条件 | 語は台帳のまま。状態ごとの条件を、憲法の記録が名前付きの検査で宣言する（「この状態なら、本人が原文を見た根拠が 1 つ以上」「独立した支える出典が 2 つ以上」など）。宣言しないメディアには効かない |
| 読みの段の語 | 語は台帳のまま。判断の「誰が・どう照らしたか」に対応づける。出典の性質（MMR の一次・二次、根拠の種類）は読みの深さではなく、出典と根拠の中身 |
| 弱い根拠の扱い | 上限つきにする種類を憲法の記録が宣言する。宣言が空なら上限なし（MMR） |
| 未確認・欠け・否定 | 結論（まだ・だめ）と理由で分ける。欠けの理由は中身 |
| 出所の持ち方 | どれも「行（か内側の単位）× 出典 × 場所 × 読み」に読み替える |
| 置き方 | 元のファイルのまま置く・ファイルの中の並び・内側の単位 |
| 出し口の数 | 種類の宣言が出し口を持ち、「出してよいか」の判断は出し口ごと・何としてか（事実として・留保として）ごと |
| 期限の意味 | 見直す日（中身）と、判断の「いつまで」。伏せ方は種類が宣言 |
| 図版の条件 | 図版の種類ごとの条件を宣言 |
| 出した URL の関門の厳しさ | 許す転送・二重の扱い・例外を台帳が宣言 |
| 言語・列の名前・改行の流儀 | 列の対応と、表のバイトを保つ書き方 |
| 枚の上限 | 種類ごとに宣言（既定は今の 64 KB） |

**固有として残す物**（器に入れず、各メディアの repo と道具に置く）:

- 分野の言葉の点検（評価語・表記の手引き・親の言葉）。
- 観測の列の中身。頁の型・デザイン。
- 各メディアの関門の中身（にがみラボの 32・中受の問の画面の柵）。**共通の点検が通っても、今ある関門は外さない。**
- 監査の回数や手順（何回読むか・だれが統合するか）。器が共通にするのは記録の索引だけ。
- こぴちゃの毎朝の商品の観測。
- キョンシーラボの物語と設定の資料（創作）。
- 関東の面をまとめる台本と、組み立ての知恵（合わせた定員を 1 つの回に配らない、など）。**ただし、値の対象の範囲と親の出典は器が持つ**（第 3 版は「内側の単位を指せるようにするまで」としていた。範囲を持たないと、男子の行への確かめが、男女を合わせた定員まで覆ってしまう。§5.1）。

## 5. 器の形（案）

### 5.1 記録の置き方 — 元のファイルをそのまま置く

**第 3 版で変えた。** 第 2 版は、元のファイルの上に THTH の頭を付けた .md にしていた。これだと、YAML や JSON を書く今の道具が、頭の付いたファイルを扱えない。頭に書いていた物は番号と判断だけなので、**頭を付けず、元のファイルを元の名前・元のバイトのまま台帳のフォルダに置く。**

- **種類**は置き場から決まる（種類の宣言の「この道のファイルはこの種類」）。
- **番号**は種類の宣言の決まりで取る: 中の欄・表の列・ファイルの名前・鍵。
- **番号の表**（番号 → 今の場所）だけを台帳に持つ。ファイルの名前が変わっても番号を引き継ぐため。名前が変わり中身の指紋が同じ記録を見つけたら、引き継ぐかを聞く。
- **目録**（番号・種類・版・場所の一覧）は、宣言とファイルから作り直せる物で、正本ではない。頭と中身が離れてずれる、という第 1 版の心配は、ずれる相手を持たないことで消える。
- **今の店の台帳（頭つきの .md）は、「番号と判断が中に書いてある」1 つの形**として、1 字も直さずに読める。
- **今の道具は、元の形式のまま読み書きできる。** 変わるのは道だけ。中身を書けば版が変わる。判断が効かなくなるのは、その判断の依る所が変わったときだけ（§0.1）。道具が状態の欄を書いても、それは観測で、新しい版への判断にはならない（§0.2）。

記録の取り方は 3 つ。

| 取り方 | 例 | 番号 |
|---|---|---|
| 1 つのファイル = 1 つの記録 | こぴちゃの YAML と記事・関東の 1 校の JSON・店の .md | ファイルの名前か中の欄 |
| 1 つのファイルの中の並び = 記録の並び | CSV の行・MMR の `queue.json`・`content/index.yaml`・`ledger.json` の束と訂正 | 番号の列。無ければ鍵 |
| 記録の内側の単位 | 関東の年度ごとの回の行と、その中の値・照合台帳の行 | 下 |

**内側の単位の指し方**（上から順に、使える物を使う）:

1. 元に番号があれば、それ。
2. 種類の宣言の**鍵**（欄の組）。鍵が台帳の中で 1 つに決まることを点検する。
3. 鍵で決まらない単位は、**鍵と中身の指紋**で指す。中身が同じ 2 つは区別しない（同じ中身への判断は、どちらにも当たる）。中身が変わった単位は別の指し先になり、前の判断は引き継がない。関東の重なる 37 組は、どの組も中身が違うので、今の 74 行は全部分けられる（志学館の 2025 年度Ａ・男子は、志願者 1 人の行と 4 人の行）。鍵で決まらない行では、行の中の値を 1 つ直しただけでも行の指し先が変わるので、その行の値への判断は全部引き継がない（「直した値の判断だけが外れ、同じ行のほかの値は効いたまま」になるのは、鍵で 1 つに決まる行）。**中身の指紋は、バイトでなく読んだ値から取る**（欄の名前の順に並べ直した値）。関東の年度の置き換えの道具は 1 枚を決まった字下げで丸ごと書き直し、今の入試結果 265 枚のうち 121 枚はその形とバイトで合わない。バイトで取ると、値が変わっていない行の判断まで外れる。
   **指紋の作り方（段 1 で決めた。中身の指紋と依る所の指紋に共通。キョンシーラボの根拠の行の指紋もこれで作る）**: 1 つの JSON の物を作り、値の中の改行だけを LF にそろえ（CRLF と CR を LF に。字下げ・前後の空白・ほかの字は変えない。値の外の行の終わりと字下げは、読んだ値に入らないので効かない）、**鍵の名前の順に並べ、区切りの空白なし・字を逃がさずに**書く（Python なら `json.dumps(値, ensure_ascii=False, sort_keys=True, separators=(",", ":"))`）。その UTF-8 のバイトの **sha256**（16 進 64 字）を指紋とする。数は JSON の書き方のまま（`296` と `296.0` は別）。どの値も**読んだ値**（表は引用を外したセルの字そのまま・JSON は読んだ値・YAML は全部を字として読んだ値。欠けた欄は null、空のセルは ""）。版（全バイトの sha256）とは別の物。作る JSON の物は、指す先で 3 つの形がある。
   - **記録への判断**: 欄の名前を鍵に、読んだ値をそのまま並べた物。欄は「その問いの依る欄 ＋ 状態の欄 ＋ 理由の種類の欄」（状態の欄と理由の種類の欄は宣言で外せない）。依る欄を宣言していない問いは、全バイトの版（`bytes:` を付けた版）に依る。中身を持つ検収の記録（こぴちゃの中央の行）の中身の指紋も、同じ欄で同じ形。中身は読んだ値のままで、空のセル "" も値として比べる（空でないことを求めるのは、宣言の `required` の欄だけ。既定は状態の欄）。
   - **内側の単位（行）への判断**: 欄の名前を鍵に、欄ごとに `{"value", "time", "sources"}` で包んだ物（`value` は読んだ値、`time` はその欄の時点か null、`sources` はその欄が依る親の出典の指紋を並べた列か []）。欄の選び方は記録と同じで、依る欄 ＋ 状態の欄 ＋ 理由の種類の欄（`not_values` に書いても外れない）。依る欄を宣言していない問いは、値の欄の全部のうち範囲が行の鍵と同じ物（範囲を別に持つ値は入れない）＋ 状態の欄 ＋ 理由の種類の欄。**行への判断は、この欄の値にだけ当たる**（依らない値は、変わっても判断が古くならないので、その値を使えるとは言わない）。同じ指し先に 2 つ以上の単位があるとき、比べるのは単位の全部の欄をこの包み方で作った中身の指紋で、親のまとまりの欄は時点と出典として値に効く分だけ入る（依らない注の違いでは断らない）。まとまりの時点は、値ごとの時点の表に無い値が 1 つでもある行だけ指し先に入れる（値の時点が優先）。
   - **値への判断**: `{"value", "scope", "time", "sources"}` の 1 つ（`scope` は範囲の札か、範囲の欄が無いとき判断に人が書いた範囲か null）。出典の指紋は、出典の 1 つ（出典の宣言に依る欄があればその欄だけ、無ければ全部の欄）を、この作り方で指紋にした物。
   実装は `thth/register/vessel.py` の `canonical`・`fp`・`record_depend`・`unit_depend`・`Value.depend`。固める試験は `tests/test_register_vessel.py` の `test_依る所の指紋の作り方は設計書に書いた形と同じ` と、3 つの形を実装を使わずに組んで `current_depend` と比べる `tests/test_register_vessel_holes.py` の `test_穴2_指紋の段落どおりの計算とcurrent_dependが記録と単位と値で一致する`。
4. **位置（何番め）では指さない。** 並べ替えや挿入で、前の確かめが別の値に移らないようにする。

### 5.2 憲法と、種類の宣言

- **憲法の記録**（台帳に 1 つ）と**種類の宣言**（種類ごと）を台帳に置く。THTH のコードに種類を書き足さない。
- **THTH が読む宣言は JSON にする**（標準の部品で入れ子まで読める）。各ラボの `lab.yaml` は元のまま記録として置き、憲法の記録が語の出どころとして指す。THTH が YAML を読まないと宣言が読めない、という形にしない。
- 憲法が持つ物: 主題・一文の立場（本人の判断が要る）・出し口・語（状態・読みの段・根拠の種類）と、その語がどの問いのどの結論にあたるか・**使えるかの決まり**（§5.3）・入れない物・**どの文書が決まりの正本か**（決まりがサイトのコードにあるときは、そのファイルと、定数や一覧の名前。キョンシーの「検索に出すか」は、決定が `lab.yaml` の決定 13、切り替えが `site/src/lib/indexing.ts` の `INDEXABLE`（全頁に効く 1 つの値で、点ごとの欄ではない）、出す記事は `articles.ts` の一覧、染めと化学の「図鑑の頁に出さない主張 13 件」は `entity-page-rules.ts`、関東の見出しの年度は `kanto_dataset.py` の定数）。台帳に書いてある欄とコードが食い違うとき（キョンシーの点 318 件は全部 `search_visibility: noindex` だが、頁はこの欄を読まず、全頁を検索に出している）、器はその欄を観測として控えるだけで、「出してよいか」の語としては読まない。どちらが今の決まりかはレーンが言う。
- 種類の宣言が持つ物: 置き場・形式・上限・番号の取り方と、欄の役。

| 欄の役 | 意味 |
|---|---|
| 鍵 | 内側の単位を指す（§5.1） |
| 値の範囲・時点・親の出典 | 値ごとに判断する種類で、欄ごとに言う（§5.1） |
| 指す欄 | 先の種類と、意味（§5.4）。来歴の控えなら、相手の版を控えた欄と、その指紋の取り方 |
| 状態の欄 | 中に書いてある状態（観測）。どの問いについての語か。語と結論・理由の種類の対応は憲法。**状態の欄は、その語が答える問いの依る欄に必ず入る**（宣言で外せない。外すと、状態だけを書き換えた版に前の判断が効き続け、狭まる向きの書き換えも見落とす）。段を上げる道具（キョンシーの `mark_checked.py`）は、検収の記録を一緒に出して新しい版へ結ぶ。仕事の進みの語（MMR の `research_status`）は内容の問いに答える語ではないので、ここには当たらない |
| 理由の種類の欄・説明の欄 | MMR の `held_kind` と `held_reason_ja` のような組 |
| 問いごとの依る欄 | その問いへの判断が依る、自分の欄と、指す先の欄。言わなければ全バイト（§0.1）。「進みの欄」という別の役は作らない（どの問いの依る欄にも入らない欄が、進みの欄にあたる） |
| 読者に見える欄・出さない欄 | 点検と出口が見る |
| 分からないと書いてよい欄・欠けの理由の欄 | 推測で埋めない |

- **組合せの条件は、THTH が備える名前付きの検査を、台帳が名指しして引数を渡す。** 台帳に式や命令は書かせない。THTH は宣言に書かれた命令を実行しない。

| 検査 | 意味 | 出どころ |
|---|---|---|
| 重ならない | 欄の組が 1 つ | にがみラボ |
| この状態ならこの欄が要る | 確かめた、と書くなら出典が要る | にがみラボ・キョンシーの図版 |
| この組は禁じる | この種類の根拠は、この種類の主張を支えない | キョンシー |
| 違う番号の出典が N 個 | 支える根拠の出典の番号が N 種類以上（独立かは見ない） | 染めと化学 |
| この判断が要る | 本人が原文を見た判断が 1 つ以上 | 染めと化学・キョンシー |
| 種類ごとに要る欄が違う | 資料の図は利用の条件、再現図は根拠と生成の記録 | キョンシーの図版 |
| 語はこの中から | 宣言に無い語を断る | どのメディアも |

- **YAML の中を読む部品**: 自前の読み手はやめる（第 2 版の案を取り下げ）。YAML の中を見るのは、追加の部品を入れた機械だけにする（`pip install thth[yaml]`）。入れていない機械では、YAML の記録は「置く・戻す・版を取る」までで、「中は見ていない」と言う。店主の台帳（頭つきの .md）は今のとおり追加なしで動くので、「入れれば必ず動く」は変わらない。
  - 読み方は、型を決めつけない読み（全部を文字として読み、型は宣言で見る）にする。`no` が偽になる・日付が勝手に日付の型になる、を避ける。重なる鍵は断る。
  - **受け入れる書き方と断る書き方の例を、作る前に決める**（重なる鍵・引用符・長い文・別名の参照・複数の文書）。7 つのメディアの今のファイルを全部通すのは、そのあとの確かめ。
- 憲法と種類の宣言も記録なので、判断が付く。形を変えるのは意味を変えることなので、本人の判断は二段。**依る欄を狭める宣言は、判断を長く効かせる向きの変更**なので、とくにここで見る（狭めすぎると、効いてはいけない判断が残る）。
- **備え付けの種類**: 今の店の 7 つ・網の型の表・図版・憲法・対応・判断。

### 5.3 問いと判断

**問い**（器が意味を知るのは 5 つ。台帳は足せる）:

| 問い | 何について | よい・だめ・まだ の例 |
|---|---|---|
| 読みは合うか | 根拠・値と、その原典 | 別の者が照らして合った／原典に無かった／まだ書き手だけ |
| 言えるか | 主張（強さと範囲つき） | 支持・上限つき／否定に決着／推測・両論が未決着 |
| 調べはどうなったか | 問い・仮説 | 話があることは確かめた／反証で決着／まだ・調べたが届かなかった（調べ直す条件つき） |
| 出してよいか | 記録 × 出し口 × 何として（事実として・留保として） | 採る／採らない／まだ |
| 止めるか | 記録（の版） | 止める（すぐ効く。§7.2） |

- 店の事実と思いの問い「本人はそうだと言うか」は、「言えるか」に本人が答える形。今の 3 つの印がそのまま結論になる。
- 台帳が足す問いの例: 「この 2 つの出典は独立か」（染めと化学が要るなら）。

**判断の記録**が持つ物:

- 対象: 番号と、**見たときの版（全バイト）**と、**依る所の指紋**。組でもよい。値なら、対象の範囲と時点も（§5.1）。集まりは目録の指紋で名指す。
- 問い。
- 答え: **台帳の語**（あれば。`preliminary`・`held` など）と**条件**（範囲・限り）。器の命令で足す判断は、結論（よい・だめ・まだ）をじかに書いてよい。
- 理由: **種類**（台帳が宣言した語）と**説明**（人が読む文）。
- 誰が・**どう照らしたか**（書き手だけ・別の者・統合の者・説明を聞いた・原文を見た。語は台帳のまま）。
- 照らした物の版（決まり・根拠・出典・親の出典）。
- いつ・いつまで・未解決の物・元の記録（監査の結果など）への指し。

**判断が成り立つ条件**（第 4 版で足した。§0.2 の線を、実際の道にした物）:

| 道 | 何があれば判断になるか | 実物 |
|---|---|---|
| 検収の記録 | 記録が**対象の版を示している**こと。版の示し方は 3 つ: 指紋を書いてある・**確かめた中身そのものを持っている**（その中身の指紋が、今の対象の依る所と合えば、その版への判断）・**確かめた側の commit を示している**（台帳が git にあり、その commit の対象を取り出せるとき。差の元の commit では足りない）。判定と、検めに渡した中身が別のファイルに分かれている束は、組にして「中身を持つ記録」として読む。**日付だけ・番号だけの記録は、版を示していない**（キョンシーの原文確認の記録 `original-check-log.md`・染めと化学の `owner-read.txt` と `recheck.json`・MMR の記事の一覧の `accepted`・関東の監査で `clean` とした年）。検収の道では判断にならず、基準の受け入れ（§8.2 の 5）が「その版に書いてあった状態」として 1 回で受ける | キョンシーの読者監査は、最後に監査した commit（`state.json`）と、確かめた行の番号を持つ。結果 1 枚ずつの `base` は差の元の commit で、確かめた側ではない（`reader_audit.py` の 75〜78 行）。行の文を持つのは指摘の引用と、最後の 1 回分の `scope.json` だけなので、前の回の結果が版を示せるかはレーンの答え待ち。関東の巡回の印（`events_commit`）と、にがみラボ・キョンシーの配信の承認（`hub approve … --target <commit>`）は commit。組で読む束は、こぴちゃの `verify_v.csv` と `verify_input.csv`、にがみラボの `VERIFY.md` と束の写し、染めと化学の `verify.json` と `bundle.json`（どの欄で突き合わせるかはレーンの答え待ち）。MMR の照合台帳の行は、読んだ頁の指紋（`page_sha256`）と日時と `checked_by` を持つ。こぴちゃの中央の判断（`staging/k1/central.csv`）は指紋を持たないが、**直したあとの文そのもの**と状態を持つ |
| 明示の受け入れ | 本人（か、決まりが認めた者）が、版を見せられて受け入れる | 取り込みのときの基準（§5.6）・`judge`・今の `confirm` |
| 決まりから導く | 憲法の決まりが「別の者の監査がよいなら出してよい」と言い、元になる判断が上のどちらかで成り立っている | キョンシー・MMR |

- **状態の欄が書き換わっただけでは、どの道にも当たらない。** 文が変わって状態が据え置かれても、状態が書き換えられても、新しい版には観測しか無い。使えるかの答えは「まだ（理由の種類: 新しい版への検収が無い）」。
- **結び直す口**: 正しく確かめ直した物まで失わせない。`thth register judge --carry <前の判断> --to <新しい版>` が、前の判断の元の検収の記録を、新しい版へ結ぶ**新しい判断**を足す（前の判断は書き換えない）。要る物は、誰が・何を見直したか・元の記録への指し。**中身を変えた者と同じ者は結べない**（下の「同じ者」の決まり）。
  - こぴちゃの `article-claims.mjs --ack <本文>` は、今ある結び直しの口。本文 1 枚の控えを一度に今の文へ取り直すが、誰が・なぜは残らない（`8ead0fc` では、主張を直した commit の中で控えも取り直している）。器では、同じ操作が「誰が・何を見直したか」の付いた判断になる。
- **器が見ていない間に 2 回変わったとき**: 台帳が git にあれば、間の版は取り出せて、観測は commit ごとに取り直せる。取り直せるのは観測までで、間の版への判断は、検収の記録が残っていなければ戻らない。
- **向きを替えたあとの毎日への効き方**（正直に書く）: 今の道具で主張の文を直すと、その主張は、新しい版への検収か結び直しが来るまで「事実として」は使えなくなる。`export --check` は「この直しで、頁から外れる記録 N 件」を、配る前に出す。外れるのを止めたければ、直しと検収を同じ便に入れる。

- **同じ者の判断は、別の者の判断に数えない**（書き手と照らした者が同じ）。
- 食い違う根拠は記録。「だめ」は判断。支えと反証が両方あって決着していない主張は**まだ**（理由の種類: 両論）。
- **語と結論の対応は、問いごと。** 染めと化学の `preliminary` は、「この資料はそう測ったか」と「一般にそう言えるか」で答えが違う。憲法は（語 × 問い）ごとに結論と理由の種類を言う。語を 3 つの同義語に置き換える表にはしない。
- 9 つの軸の行き先:

| 第 2 版の軸 | 第 3 版 |
|---|---|
| 在るか・欠けの理由 | 中身（欠けの理由の欄） |
| 何を読んだか・誰が確かめたか | 判断の「どう照らしたか・誰が」 |
| 支えと反証の数 | 根拠の指す欄から数える |
| ほかの資料との整合 | 反する根拠（記録）と、決着の判断 |
| 調べの結果 | 問い「調べはどうなったか」の判断 |
| 言える範囲 | 主張の中身 |
| 置き換え | 指す欄「置き換える」 |
| 期限 | 中身（見直す日）と、判断の「いつまで」 |

**使えるか**は、問い合わせのたびに計算する。入力は、記録・判断・決まり（憲法）・判定の日時・**用途（どの出し口へ・何として）**。答えは「使える（言い方の上限と範囲つき）」か「使えない（理由と、調べ直す条件）」。

- 決まりの例（どれも各メディアの今の決まりを写す。段 0 で確かめる）:
  - 店の事実を投稿に、事実として: 本人の「よい」があり、古くない。
  - こぴちゃの主張を頁の事実欄に: **今の決まりは、点に主張が 1 件でもあれば、状態で除かずに全部出し、主な根拠から L1〜L4 を付ける**（`knowledgeFacts.mjs` の `ledgerFactsFor`。`contested` と `unverified` も出る。`valid_until` を頁は読まない）。器はまずこれを写す（頁を変えない）。第 4 版までここに書いていた「言えるかがよいか上限つき・支える根拠に別の者の読みは合う・期限の内」は、設計_知識の網 §5.4 の文から組んだ形で、今の頁とは違う。どちらを今の決まりとするかは、こぴちゃのレーンの答え待ち。出典の権利の条件（`rights_status=unknown` を根拠に使わない）は今も点検が見ている。
  - 染めと化学の `established`: 本人が原文を見た判断が 1 つ以上と、違う番号の支える出典 2 つ（今は 0 件）。にがみラボの `established` は、2 つの判定を別に写す（レーンの答え 11/13）: 点検の柵（全文で確かめた支える根拠が 1 つ以上）は赤、手順の書の定義（複数の独立した研究で概ね一致）は報告（違う番号の出典の数）。今の 30 件のうち 19 件は支える出典が 1 つで、どちらかに寄せて器が答えを決めない。
  - MMR の照合台帳の行を曲の頁に、**留保として**: 結論が「まだ」で、**理由の種類**が、憲法の「注にしてよい種類」（`other_version`・`other_release`・`release_credits`・`conflict`・`role_differs`）に入るとき。`unresolved` は入らない。
  - 関東の値を頁に、事実として: その値の範囲・時点・親の出典についての判断があり、出そうとしている範囲と時点に合う（男女の合計の定員を、男子の定員として出さない）。
- 同じ記録が、事実としては使えず、留保としては使える。条件に届かない記録を一律に落とさない（落とすと、読者に要る留保まで消える）。
- **決まりは理由の説明文を読まない。** 読むのは種類だけ。説明は留保の文として読者に渡す側（出口が材料に付ける）。
- **決まりから導く判断**: 「別の者の監査がよいなら、出してよい」のような持ち主の決め（キョンシー・MMR）は、憲法の決まりにする。1 件ずつ「出してよい」を書かせない。
- 店主の台帳の頭の `confirmed` は今の 3 語のまま。

**判断の置き場**は §9 の 5（推しは、台帳に同梱して、受け入れた集まりに封）。

### 5.4 指す欄

- 記録は番号を指す。**来歴の控えだけは、番号に加えて相手のそのときの版も持つ**（§0.2）。
- 器が意味を知る指し方は少しだけ。メディアごとの述語（こぴちゃの 22・MMR の役割）は中身で、器は先が在るかだけを見る。

| 意味 | 例 | 器が見ること |
|---|---|---|
| について | 頁の文 → 点、図版 → 点 | 先が在る。同じ物の記録を引ける |
| 支える・反する・限る | 根拠 → 主張 | 数える。使えるかの決まりが読む |
| 含む・親 | 産地 → 国、内側の単位 → 記録 | **輪を禁じる** |
| 置き換える | 新しい記録 → 旧い記録 | **輪を禁じる**。旧いほうを使おうとしたら知らせる |
| 同じ・関わる・上位と下位 | メディアをまたぐ対応（§7.3） | 関係の種類を持つ |
| から作った（来歴の控え） | 頁 → 主張、下書き → 記録、材料 → 記録 | 使った先を引ける。**相手のそのときの版を控えていれば、今の版と比べて「見直す物」を出す**（こぴちゃの `--check` と同じ働き）。控えの取り直しは、誰が・何を見直したかの付いた判断（§5.3） |

- 輪を禁じるのは「含む・親・置き換える」だけ。主張どうしの往復は実際にあり、止めない。
- 先が無い・種類が違うは赤。先が退役か置き換え済みなら知らせる。
- 台帳をまたぐ指し方は `<台帳>:<番号>`。相手が手元に無ければ「確かめられない」。
- 外の同じ物（MusicBrainz の番号・DOI）は形だけ見る。

### 5.5 変えた跡

- 土台は、前の版を取り出せる置き場（ふつうは git）。台帳のフォルダが git の作業木なら、`thth register diff <前>..<後>` が、足した・変わった・退役した・消えた記録を出す。番号が消えたら赤。
- **元のファイルが git の外にあるメディアがある**（段 0 で分かった。MMR は表 15 枚・`queue.json`・`ledger.json`・記事の本文・照合の判定の記録が git の外（`.gitignore` が `/*` で始まり、許した物だけを追う）。関東も `features_book.csv` ほかが外）。そこでは「土台は git」が成り立たない。器の受け方: 台帳のフォルダ（影の段では repo の外の影のフォルダ）を git の作業木にして、取り込みのたびに版を控える。**取り出せる前の版は、器が取り込んだ時点からだけ。** それより前の版と、取り込みと取り込みの間の版は「取り出せない」と言う。基準は commit でなく、取り込んだ時点の目録の指紋で名指す。向きを替えるときに台帳をどの git に入れるかは、そのメディアのレーンとの最初の相談。
- **判断の記録は足していくだけ**（例外は、下の消す求めだけ）。これが確かめの索引になる。判断から、対象の版と、元の記録（キョンシーの監査の結果・こぴちゃの中央の判断・MMR の束の台帳）へ戻れる。「監査済み」と引けるだけでなく、**その判断が今の版に効くか**が分かる。
- 訂正は、旧い指し先と新しい指し先を結ぶ記録（旧い文と新しい文・なぜ・誰が）。出さない欄は指紋だけ。結び方は §5.1。
- 取り込みの跡（束ごとの sha256・集めた者・検めた者）。
- 元の記録は元のまま置く。索引だけにして元を捨てない。
- git でない置き場の台帳は、前の版を読めないと正直に言う（共通の行を版で指すには、前の版が取り出せることが要る。§7.2）。

**消す求め**（第 4 版で足した。第 3 版は「解いていない」としていた）:

器の約束は「原物と履歴を残す・判断は足すだけ」。持ち主が本当に消したい物（運営者の住所を書いてしまった、など）は、この約束の**例外**として受ける。芯は増やさず、種類の違う 4 つの記録にする。今の THTH も、消す求めを受け付けて照らす処理（`deletion.py`）と、退出して消す処理（`leave.py`。途中の段と、消した種類と数を記録する）を分けている。同じ分け方。

| 記録 | 持つ物 | 持たない物 |
|---|---|---|
| 1. 求め | 誰が・いつ・何を消したいか（番号と欄で言う） | 消したい中身そのもの |
| 2. 範囲の判断 | 消してよい範囲: どの番号の・どの欄の・どの版まで。本人の判断（二段） | — |
| 3. 実行の対象 | 実際に手を入れる場所の一覧: 今の本文・前の版・訂正の跡の旧い文・判断の理由の文・材料と材料の控え・共通の台帳・持ち出した写し | — |
| 4. 結果と残り | 場所ごとに: 消した・消していない・**確かめていない**。git の履歴・もう配った頁・ほかの clone・相手の手元は、確かめるまで「残っているかもしれない」のまま | — |

- **「出してはいけない」（止める）から、消すことを自動で導かない。** 止めるは出口の話で、原物は残る。消すには 1〜4 が要る。
- **「消した」の印を置いただけでは、消し終わりにしない。** 終わりと言えるのは、4 の一覧の全部の場所に結果が付いたとき。確かめていない場所が残るなら、「消し終わっていない」と言い続ける。
- **消したあとの記録に、消した中身を書かない。** 残すのは番号と、消した範囲（欄・版の数）だけ。**消した中身の指紋も残さない**（住所や電話のような短い値は、指紋から当て直せる）。その版を対象にした判断と来歴の控えは、対象の指紋を外して「対象を消した」と記す。
- **再現できなくなる範囲を、結果に書く。** 消した版を入力にしていた世代の判定は、もうやり直せない。「この番号を入力にしていた、いつからいつまでの世代は再現できない」を 4 に残す。「過去の判定を全部再現できる」とは、それ以後は言わない。
- 点検は、4 の記録に載った範囲の「判断の書き換え」と「指す先の切れ」を赤にしない。載っていない書き換えは、今までどおり赤。
- **git の履歴を書き換えるのは持ち主**（器はしない）。器がするのは、手を入れる場所の一覧を出すこと・今の本文と器の記録から消すこと・結果を受けて記すこと。

### 5.6 出口

仕組みは 1 つ（記録を決まった場所へ書く）。**命令は 2 つに分ける**（取り違えると、出さない物が公開の場所へ出るため）。扱う集まりを 3 つに分けて書く。

| 集まり | 中身 | だれが作るか | 何と比べるか |
|---|---|---|---|
| 原物 | 取り込んだ全部（内部の層も） | `restore` | 元のファイルと、数・名前・sha256 が全部同じ |
| build の入力 | 出し口ごとに、サイトの build と道具が読むファイル | `export` | 出し口の種類による（下） |
| 配る成果物 | 読者に届く頁（`dist/`） | サイトの build（器は作らない） | 向きを替える前と後で sha256 |

**出し口の種類**（憲法が宣言）:

- **内の道具が読む出し口**（こぴちゃの仮説・問い・作り手の言説の表など）: 選ばずに書く。読者には届かない。
- **読者に出る出し口**（頁を作る入力）: **ここで、使えない記録を除く。** 「出してよいか」と「使えるか」を、出し口と何としてかごとに判定する。

**(1) 元どおり戻す** `thth register restore --to <フォルダ>`: 全部を元の場所・名前・バイトで書く。保存できたことの証明と、持ち出し。

**(2) 材料を出す** `thth register export --outlet <出し口> --to <フォルダ> --as-of <日時>`

- 判定の日時は入力。同じ台帳・同じ日時なら同じ出力。
- **材料の控え**: 書いたファイルの sha256 と、**判定に使った入力の版の組**（記録・判断・決まり・共通の行の版・判定の器の版・判定の日時）。この組があり、**入力の中身を取り出せれば**、同じ判定をやり直せる。指紋が残っていることと、中身を取り出せることは別（MMR の照合台帳は読んだ頁の指紋を持つが、頁の本文は保存しない、と道具に書いてある。やり直せるのは、保存してある読み取りの結果からの機械の判定までで、原典に戻って読みを確かめ直せるとは限らない）。消した版があれば、その範囲はやり直せない（§5.5）。
- **封**: 材料の控えに付ける（下の「CI と承認」）。
- **旧い材料が残っていたら止まる**（一覧に無いファイルが書き出し先にあれば赤。THTH は消さない）。
- 留保として出す記録は、留保の理由を付けて書く（何として出すかを、サイトの側が取り違えないように）。
- 差し込み（`{{番号.欄}}`）は使う種類だけ。
- `--check`: 書かずに比べる。

**基準**（こぴちゃの向き替え）: 「基準の commit の時点で、**読者に出る出し口の入力に在った版**は、出してよい」という、集まりへの 1 つの判断（本人・二段）。内部の層は読者の出し口に無いので、基準が付かない。基準で公開できる物が増えることはない。足した記録・変えた記録は基準の外で、決まりのとおり判断が要る。

**CI と承認**: 一本の道にする（§9 の 5 の推し）。判断は台帳に同梱する。そのうえで、**受け入れた判断の集まり**を材料の控えに書き、鍵つきの封をする。

第 3 版の穴: 「よそで付いた判断は、手元で受け入れるまで効かない」と「CI は repo だけで判定する」がつながっていなかった。判断の行と材料を一緒に main へ入れると、受け入れの印を持たない CI だけが、その判断を効かせてしまう。同じ判断が、手元では未受け入れ、公開する機械では受け入れ済みになる。こぴちゃは main への push から build・配信まで進む（`observe.yml`）。今の THTH は、台帳の外の記録と指紋を照らすので（`fence.py`）、この食い違いは起きない。

- **封が持つ物**: 受け入れた判断の集まり（足していくだけの記録なので、「何行めまで」とその指紋で言える）・入力の版の組・決まりと判定の器の版・出し口と用途・判定の日時・出力の指紋・**世代の番号**（増えるだけ）。
- **鍵は持ち主に 1 つ。** 判断する者ごとには増やさない。秘密の鍵は THTH の側（台帳にも repo にも入れない）。今の THTH は、relay への署名に openssl を使っている（`relay.py`）。同じ道具で足り、Python の部品は増えない。
- **封を作るのは `accept`**（今の `confirm` と同じ二段）。手元の「どこまで受け入れたか」の印と封は、同じ物の 2 つの置き場にしない。封が印で、台帳と一緒に動く。
- **CI がすること**: (1) 封を公開鍵で確かめる (2) **封の中の判断だけ**を使って「使えるか」を計算し直す (3) 置いてある材料と比べる。封の外の判断の行は、あっても「広げる向き」には使わない。

**広げる判断と、狭める物を分ける**（Codex の「古い封で停止を巻き戻させない」を、決まりにした物）:

- **広げる**（使える物を増やす: よい・採る・受け入れ・基準）: 封の中にあるときだけ効く。
- **狭める**（使える物を減らす: 止める・だめ・期限が切れた・依る所が変わった）: **封を待たない。** CI は、repo の今の中身と、CI が動いている今の日時で、必ず見直す。封の日時より後に期限が切れた記録・封より後に足された「止める」・封より後に中身が変わった記録が材料に載っていれば赤。
- よそから来た「止める」も、受け入れを待たずに効く（効いている件数を見せる。本人が「止めない」と判断すれば外れる。それは広げる判断なので封が要る）。間違って狭まる害は、間違って広がる害より小さい。
- **「止める」の行そのものを消して、古い封に戻す**道が残る。CI は、前に配った世代の commit（出した物の控えに残す）と比べ、判断の記録が「前の続き」になっているか・世代の番号が戻っていないかを見る。戻っていれば赤。
- **公開鍵と確かめの処理を、配ろうとしている変更で差し替えさせない。** 公開鍵は repo の木の外（CI の変数）に置く。確かめるのは、版を止めて入れた THTH。
- **正直に書く残り**: CI の手順のファイル（workflow）は repo の中にある。main に書ける者がそれを書き換えれば、確かめを飛ばせる。履歴ごと書き換えれば「前の続き」の点検も抜ける。封が守るのは「手元と CI で、受け入れの線が同じ」ことと、うっかりと、よそから来た判断まで。repo の持ち主の権限そのものは守らない。
- CI を持たない持ち主（店主の台帳）は、何も足さなくてよい。封は手元で作られ、手元の柵が同じ封を読む。台帳が git の外にあって CI が読めないメディア（今の MMR。配信は手元の `deploy.sh`）も同じ道で、確かめる所は配信の手元の柵になる（「公開の直前に、封と公開鍵で確かめる所」は CI でなくてもよい）。openssl が無い機械では、封の代わりに THTH の側の印（今と同じ）を使い、「よその機械と CI では確かめられない」と言う。
- **狭めるだけなら、CI は封なしで材料を作り直せる**（期限が切れた記録を外して配る）。広げないので鍵が要らない。夜のうちに期限が切れて、毎朝の配信が赤で止まるのを避けたいメディアは、伏せ方の宣言で「CI が外して配る」を選べる。既定は「赤で止まる」（気づける側）。

**期限と伏せ方**:

- 見直す日（過ぎたら健康の候補に出すだけ）と、判断の「いつまで」（過ぎたら、その判断は効かない）を分ける。
- 今の柵の「見直し日を過ぎたら使えない」は、備え付けの店の種類ではそのまま残す。
- 伏せ方は種類が宣言する（記録ごと・欄だけ・表の中の行だけ）。
- **もう公開された静的な頁を、THTH は伏せられない。** 器の受け持ちは、判定の日時を入力に材料を作り直せること・健康に「期限が近い」「過ぎたのに最後の世代に載っている」を出すこと・期限を過ぎた材料が載った世代を配ろうとしたら関門が赤になること。作り直して配るのは各メディアの配信で、できなかったときに動くのはそのメディアのレーン。

**出した物の控えと関門** `thth register published`: 追記だけの控えと、build のあとの関門の仕組みを共通にする。厳しさ（許す転送・二重の扱い・例外）は台帳が宣言する。今ある各メディアの関門は、同じ入力で同じ結果になるのを確かめてから置き換える。

**読者に見える欄の点検**: 内部の番号・作業の呼び名らしい語を拾う。

### 5.7 書く口と、束の取り込み

- **元の形式の道具が、そのまま書ける**（§5.1）。器の書く口は、壊さないための口。
- `thth register row add|set …`: 表に 1 行足す・1 欄直す。レコードごとの元のバイトの範囲を覚え、変えるレコードだけを書き直す。触っていないレコードの sha256 を書く前後で比べ、違えば書かずに断る。
- `thth register merge <束>`: 判定が断りの行は入れない・重なる番号は入れない・集めた者と検めた者が同じなら入れない。**複数の表を 1 つのまとまりとして入れ替える。** 読み手には、入れ替えの前か後のどちらかが見え、半分ずつ混ざらない。途中で止まっても、続けるか戻すかが決まる。
- どの道で書いても、中身が変われば版が変わる。依る所が変わった判断は効かなくなり、器は「古くなった判断」を健康に出す。束の中の検収の記録が対象の版を示していれば（§5.3）、`merge` は取り込みと同時に、新しい版への判断として結ぶ。
- THTH は集めない・検めない。
- 今の privacy の約束（THTH が台帳に書くのは頭の決まった欄と問いの記録だけ）を変える（§10）。

### 5.8 健康と見直し

`thth register health`（読むだけ）。

- 網: 線の薄い点・開いた問いの数と閉じ方。
- 判断: 古くなった判断・**観測しか無い版**（状態は書いてあるが、その版への判断が無い）・結び直しの候補・書き手だけの読み・同じ者の確かめ・「まだ」の理由の種類ごとの数・調べ直す条件が満たされた問い・基準だけで通っている記録・範囲か時点が未宣言の値・見直す来歴の控え（相手の版が変わった）。
- 封: 受け入れ待ちの判断・よそから来て効いている「止める」・消し終わっていない消す求め。
- 期限: 見直す日を過ぎた・「いつまで」が近い・過ぎたのに最後の世代に載っている。
- 決まりの食い違い: 憲法の決まりに 1 件も当たらない検査（台本に残った廃止の条件が見える）。
- 共通の行の採り入れ待ち（§7.2）。
- 候補を出すだけ。`--all --json` の 1 行を hub が束ねられる。

## 7. 1 人で複数のメディアを持つ場合

### 7.1 階層

```
持ち主（THTH の利用者）
├─ 共通の台帳（持ち主に 1 つ。無くてもよい）
├─ メディア A（THTH の project）── 台帳（1 つ以上）・口座
└─ メディア B ── 台帳・口座
```

- メディア = 今の THTH の project。持ち主 = THTH の利用者。新しい層は作らない。
- 1 つのメディアが台帳を 2 つ以上持ってよい（書く拍子と書く者が違うとき）。

### 7.2 共通の記録の持ち方（決め: 共通の台帳に置いて指す）

**正本は共通の台帳に 1 つ。各メディアは、採り入れた版で使う。**

- メディアの記録は `共通:<番号>` で指す（番号）。**どの版を使うかは、そのメディアの「採る」という判断**が持つ（§0 のとおり、版を持つのは判断と来歴の控え）。
- 共通の記録を直しても、その瞬間に各メディアの材料は変わらない。健康に「採り入れ待ち」と出る。
- **まとめて採り入れる**: `thth register take 共通` が、進んだ共通の記録の差と、変わる頁を一度に見せ、1 回で採れる。メディアの数だけ同じ操作を繰り返さない。
- **止めるは、採り入れを待たない。** 共通の記録（の版）に「止める」の判断が付いたら、それを採っている全部のメディアの次の材料から外れる。もう出した先は「使った先」で知らせる。ふつうの直しと、急ぎの止めを混ぜない。
  - 止めるは狭める物なので、封も待たない（§5.6）。各メディアの CI が共通の台帳を読めるなら、そこで効く。読めない CI では、封を作る機械（共通の台帳が手元にある）が次の封に入れるまで効かない。**CI が共通の台帳を読めない朝に、配信を止めはしない**（共有の故障点を増やさない。本線が `media.yaml` で言ったのと同じ考え）。その代わり、健康に「共通の止めるを確かめられないまま配った」と出す。
- **前の版を取り出せること**が条件。共通の台帳は git に置く。git でない置き場では、版で指せないと断る。
- 材料の控えには、採った共通の版に加えて、その記録が指す根拠・決まりの版も入る（入力の版の組）。行だけ止めても、指す先が動けば判定は再現できないため。
- 写しは作らない。各メディアが持つのは判断だけ。

| 共通に置く物 | 共通にする範囲 | 共通にしない範囲 |
|---|---|---|
| 運営者の情報 | 名前・窓口・表記 | 既定で出さない。家族の名前は入れない |
| 持ち主の思い | メディアをまたぐ編集の考え | メディアごとの思い |
| 口座の一覧 | 名前と向き先 | 鍵は入れない |
| 同じ物の対応 | §7.3 | 各メディアの点の中身 |
| 同じ出典 | **書誌だけ**（題・著者・年・DOI・URL・権利の条件） | 読んだ所・支える主張・読みの判断・そのメディアで使ってよいか |
| 書き方の決まり・図版 | 文・図と権利 | 採るかは各メディア |

- 今ある物は番号を変えない。別の番号で持つ同じ出典・同じ点は、対応の記録で結ぶ。新しく足す共通の物から共通の台帳に置く。

### 7.3 メディアどうしのつながり

- **対応の記録**: 各メディアでの番号と、関係の種類（同じ・関わる・上位と下位）。今の対応表の 31 行は、移すときに 1 行ずつ見直す（柿渋の行は「同じ」ではなく「関わる」）。
- **姉妹リンクは別の編集の判断。** 対応から候補を出し、載せる対を「出してよいか」の判断として持つ。
- 置き場と移す時期は、本線の条件のとおり（§9 の 2）。

### 7.4 管理の仕方

- **足す**: 台帳のフォルダを作り、`thth register add <台帳> --project <メディア>`。共通の台帳にメディアの記録を 1 つ。
- **退役**: メディアの記録を退役に。記録も出した URL も消さない。口座は止める。
- **鍵と口座**: 主体は持ち主に、口座はメディアに（今のはてなの作りを広げる向き）。鍵は台帳に入れない。
- **書ける範囲**: 器は手元のファイルに鍵を掛けられない。境は git の repo と入口の文書。器が受け持つのは、判断に「誰が」を残す・`diff` で変わった台帳と種類を出す・憲法と種類と共通の記録への本人の判断を二段にする、の 3 つ。
- **まとめて見る**: `health --all --json` がメディアごとに 1 行。
- **外す範囲は 3 つ。**

| 範囲 | 命令（案） | 消える物 | 残る物 |
|---|---|---|---|
| 口座 1 つ | 今の `thth leave <口座>` | その口座の鍵・状態・記録 | **台帳の控えと判断（最後の口座でも残す。§6）**・メディア・ほかの口座 |
| メディア 1 つ | `thth project leave <メディア>` | そのメディアの全部の口座・台帳の控え | 台帳のフォルダ（判断の記録が中にあれば、それも）・共通の台帳・ほかのメディア |
| 持ち主の全部 | `thth owner leave` | 全部の口座・台帳の控え・主体 | 台帳のフォルダ |

- **持ち出し**: 判断は台帳に同梱なので、台帳のフォルダがそのまま持ち出しになる。メディアを 1 つ持ち出すときは、採っている共通の記録の、その版を付ける（出さない欄は付けない）。受け取った側では、付いてきた封は相手の鍵の物なので効かない。受け取った者が `accept` して、自分の鍵で封をし直す。

### 7.5 1 店・1 メディアで始めて、あとで増やす道

1. 最初は台帳 1 つ。今の 5.19.0 と同じ使い方。
2. 2 つめを足すとき、THTH が「両方に同じ物がありそう」を並べる。
3. 持ち主が選んだ物だけ共通の台帳へ移す。元の記録は番号を変えず、共通を指す記録になる。移した記録はもう一度判断する。
4. 移さなくても動く。

### 7.6 hub との線

- 器・点検・出口・健康の数は THTH。メディアの指揮は hub。
- 重なる 2 つ（メディアの一覧・対応表）は、本線の返事（§9 の 2）のとおり進める。
- 計測の数を記録へ返す口は、この書に入れない。

### 8.2 こぴちゃを最初にする段取り

1. **相談**: こぴちゃのレーンに §8 と §10 を hub msg で渡す。
2. **基準を決める**: こぴちゃの main のある commit。目録のファイルの sha256 の一覧を作る。

### 8.3 確かめ方

作った者と別の者が、命令を打ち直して確かめる。

1. **元どおり戻せる**（7 つ全部）: 取り込み → 戻す出口 → 目録のファイルと、数・名前・sha256 が全部同じ。
2. **build の入力が同じ**（こぴちゃ）: 出し口ごとに比べる。内の道具が読む出し口は、元と sha256 で全部同じ。読者に出る出し口は、基準の判断のもとで元と同じ（除く物があるメディアでは、「除いた物の一覧」と元との差がぴったり合う）。
3. **頁が同じ**（こぴちゃ）: 同じ commit・同じ `node_modules`・同じ日に、基準のまま build と、材料を差し替えて build。`dist/` の全ファイルの sha256 を比べる。先に同じ物を 2 回 build して、もともと揺れるファイルを名前と理由つきで書き出す。揺れが多すぎて比べにならなければ止まって知らせる。
4. **判定が同じ**（7 つ全部）: 段 0 で決めた「各メディアの大事な判定」の一覧について、器の答えが各メディアの**今の決まり**の答えと同じ。台本と同じ結果になるだけでは足りない（台本が古い所は、規則の正本に合わせる）。
5. **柵を壊して赤を見る**: 1 行を 1 字変える・記録を消す・表の 1 行を変える・期限を過ぎた日時で判定する・旧い材料を残す・**判断の無い記録を材料に手で足す**・並びを入れ替える（前の判断が別の値に移らない）・**文を直して状態を据え置く**・**文と状態を同時に書き換える**・**材料と控えと判断の行を一緒に書き換える（封は古いまま）**・**「止める」の行を消して古い封に戻す**・**親の出典だけを変える**、でそれぞれ赤か、正しく効かなくなる。逆に、**依る欄でない欄（進み）だけを変えても、判断は効いたまま**で、原物の版は変わる。

### 8.4 移す間、運用を止めない

- 正本はいつも 1 つ。影は片道。両方に書く期間を作らない。
- VM の毎日の観測は、移す物に触れない。向きを替える push は 04:00〜04:30 を避ける。
- 向きを替える commit は材料を変えない。戻し方は revert 1 つ。

- **前提が変わると**: こぴちゃの向き替えを急ぐ理由があれば、分ける側が強くなる。分ける場合でも、§10 の段 1〜3（読んで指す・戻して 1 回直す・短い 1 本の道）は 7 つの難しい例で先に通すのを勧める。

### 5. 判断の記録を、どこに置き、受け入れをどう運ぶか（聞く。§18）

今は THTH の側（その機械の `register_state/`）に置いている。理由は「頭の印は手でも LLM でも書けるので、頭だけでは信じない」。

第 3 版は「台帳の中に置く」と「THTH の側に置いたまま封を足す」の 2 つを並べ、前のほうを推した。Codex の 3 回めは、2 つの良い所を合わせる案を出した。実物（`fence.py`・こぴちゃの `observe.yml`・`relay.py`）で確かめて、**推しを替える**。

- **台帳に同梱し、受け入れた判断の集まりに鍵つきの封をする（推し。Codex も同じ）**: 判断の行は台帳のフォルダに足していく。`accept` が、受け入れた所までの集まりを材料の控えに書いて封をする。CI は封を確かめ、封の中の判断だけで判定をやり直す。狭める物（止める・期限）は封を待たない（§5.6）。
  - 得る物: 判断が台帳と一緒に動く。持ち出しが台帳のフォルダそのものになる。外れた・付け直したが git に残る。CI が判定をやり直せる。**手元と CI で、受け入れの線が同じになる。** 今の「台帳の側からは『認めた』を偽れない」も保てる（秘密の鍵は THTH の側）。第 3 版の推しは、これを手放す代わりに CI を通していた。
  - 払う物: 持ち主に鍵が 1 つ増える（今も relay 用の鍵を openssl で作っている。同じやり方）。CI を使う repo ごとに、公開鍵を CI の変数に 1 回置く（masaru の手か承認。こぴちゃは段 10、ほかは向きを替えるとき）。CI に THTH を版を止めて入れる。封の世代と「前の続き」を見る点検が増える。privacy の文を直す（判断の記録と封を台帳に書く）。
  - 守れない物（正直に）: main に書ける者が CI の手順のファイルを書き換える・履歴ごと書き換える（§5.6）。
- **台帳に同梱し、封は付けない。「main に入れる操作を、判断の受け入れとする」と決める**:
  - 得る物: 仕組みがいちばん少ない。鍵も CI の変数も要らない。
  - 払う物: 「手元で受け入れるまで効かない」を手放す。よそから来た判断の行は、main に入った時点で効く。正しい指紋の付いた判断の行を書けば通る。今の「偽れない」も手放す。
- **THTH の側に置いたまま、封だけ足す**（第 3 版の 2 つめ）: 取り下げる。判断が機械ごとのままで、持ち出しの口が別に要る。封を使うなら、判断を同梱しても CI は判定をやり直せる（「封を使うと CI はやり直せない」という第 3 版の書き方は誤り）。
- **前提が変わると**:
  - THTH は利用者とその LLM を疑わない道具、という立場（9/26）を「受け入れの線も要らない」まで広げるなら、封なしで足りる。そのときは、外の人に台帳を配る・受け取る使い方（ひな形の台帳・店の台帳を預かって手伝う）で、受け取った判断が main に入れただけで効くことを、受け取る側に言う必要がある。
  - main への push がそのまま公開のメディア（こぴちゃ）が無く、どれも承認つきの配信なら、封なしの害は小さくなる。
  - 封ありで始めて、あとで封なしに緩めるのは易しい（確かめをやめるだけ）。逆は、封の無い世代を全部受け入れ直すことになる。
- **この問いを待たずに進められる所**: 段 0〜2 は答えに依らない。答えが要るのは段 3（短い 1 本の道）から。

## 11. 危ないこと

1. **サイトが壊れる・頁が変わる。** → 基準の判断。向きを替える commit は材料を変えない。`dist` の sha256 を前後で比べる。
2. **出所が落ちる。** → 元のファイルを元のバイトのまま置く。書く口はレコードのバイトを保つ。
3. **二重の正本になる。** → 影は片道。写しは CI が判定からやり直して比べる。共通の記録は判断で版を持ち、写しを持たない。
4. **早くそろえて、各メディアの意味が消える。** → 語は台帳のまま。軸を保存しない。段 0 で決まりの正本を確かめる。
5. **前の確かめが、別の値に移る。** 並べ替え・挿入・ファイルの名前の変更・範囲の違う値が同じ行にある、で起こる。→ 位置で指さない。鍵で決まらなければ鍵と中身の指紋。値ごとに範囲と親の出典。訂正は名指しで結び、決められなければ引き継がない。段 1 で最初に確かめる。
6. **訂正と、次の時点の値を取り違える。前の年度の確かめが、次の年度の値に乗る。** → 時点は値ごと。取った日を時点の代わりにしない。同じ値が続いても引き継がない。
7. **「だめ」と「まだ」を取り違える。** 食い違う根拠があるだけで否定にする・届かなかった問いを否定にする。→ だめは判断だけ。まだには理由と調べ直す条件。
8. **条件に届かない記録を一律に落として、読者に要る留保が消える。** → 用途を「事実として・留保として」に分ける。
9. **基準で、内部の層まで公開できるようになる。** → 基準は読者の出し口の入力に在った版だけ。
10. **判断を偽れる・よそから来た台帳の判断が効く・手元と CI で受け入れの線が食い違う。** → §9 の 5。広げる判断は封の中だけ。狭める物は封を待たない。CI の手順や履歴を書き換える者は防げないと正直に書く。
    - **書いてあるだけの状態が、承認として通る。** 文と状態を同時に書く道具・状態を据え置いた訂正で起こる。→ 観測と判断を分ける。新しい版には検収の記録か受け入れ。
    - **依る欄を狭く言いすぎて、効いてはいけない判断が残る。** → 言わなければ全バイト。狭める宣言は本人の二段。
    - **向きを替えたあと、ふだんの直しで記録が頁から外れる。** → 配る前に「外れる N 件」を出す。レーンに先に言う（§8.2）。
11. **判断の重みが薄まる。** 基準・別の者の確かめで、masaru が見ていない記録が材料になる。→ 判断に、誰が・どう照らしたかを残す。害の大きい種類は台帳が決まりを選ぶ。
12. **憲法と種類の宣言が攻め口になる。** → 命令を実行しない。検査は THTH が備えた物だけ。道の宣言は台帳と書き出し先の中だけ。
13. **YAML を読み違える。** → 型を決めつけない読み・重なる鍵を断る・受け入れる例と断る例を先に決める。部品を入れていない機械では「中は見ていない」と言う。

**Codex に同意しなかった所**（2 つ。退けたのでなく、線の引き方が違う）:

1. **「よそから来た判断は、受け入れるまで無効」を、狭める判断にまで当てない。** Codex は外来の判断を一律に「受け入れるまで無効」として封でつないだ。この書は、よそから来た「止める」は受け入れを待たずに効かせる。理由: 封の役は「使える物を、受け入れなしに増やさない」こと。止めるを封の中に入れると、Codex 自身が挙げた「古い正しい封を使い回して停止を巻き戻す」道が、封の作りそのものから生まれる。狭める物を封の外に出せば、その道は封では起きない（残るのは、行を消す道だけ）。払う物は、よその者が「止める」を足して頁を落とせること。害の向きが小さいほうを選んだ。
2. **「公開の直前に、最新の停止の状態と照らす」を、共通の台帳については必ずとはしない。** 各メディアの CI が共通の台帳を読めない朝に配信を止めると、共通の台帳が全部のメディアの故障点になる（media-hub の本線が `media.yaml` で同じ心配を書いている。§9 の 2）。メディアの中の「止める」は必ず照らす。共通の「止める」は、読めれば照らし、読めなければ配って健康に出す。
