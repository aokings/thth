## 0. 一枚で言うと

7 つのメディアを読むと、台帳はもう 1 つの型に寄っている。5 つ（染めと化学・にがみラボ・こぴちゃ・MMR・キョンシーラボ）は media-hub の「ラボの型」（`lab-model/`）から生まれた同じ表の組で、関東・学校台帳・中受の問は「1 枚の JSON や頁の頭に、欄ごとの出所と期限」を持つ。共通の骨はすでにある。足りないのは、それを 1 つの道具が受け持つこと。

ただし、**骨が同じでも、決まりは同じではない**（第 2 版で直した所）。「調べたが届かなかった」と「違う」は別の物で、「本人が説明を聞いた」と「本人が原文を見た」も別の物で、同じ `established` でもメディアごとに条件が違う。早く 1 本にそろえると、各メディアが苦労して分けた意味が消える。

器を次の形にする。

- **行の置き方は 2 つ。** 枚の行（THTH の頭 ＋ 中身を元のまま）と、表の行（表の 1 行）。枚の内側の単位も指せる。
- **台帳ごとに「憲法」と「種類の行」を持つ。** 種類・欄・語・つながり・組合せの条件・出し口を、台帳が宣言する。入れ子も読む。
- **裏付けは、いくつかの軸で持つ。** 在るか・何を読んだか・誰が確かめたか・支えと反証の数・ほかの資料との整合・調べの結果・言える範囲・置き換え・期限。原語は残す。3 つの印は最後の見え方。
- **未確認と否定を分ける。** どちらも「今は材料に使えない」だが、理由と、調べ直す条件が違う。
- **出口は 2 つ。** 元どおり戻す出口（保存できたことの証明）と、公開する材料の出口（出してよい物だけ）。
- **変えた跡・確かめの索引・書く口・束の取り込み・健康**を器が持つ。
- **持ち主 → メディア → 台帳。** 共通の物は共通の台帳に 1 つ置き、各メディアは**採り入れた版**で指す。

release の条件は、7 つのメディア全部で「漏れなく取り込めて、元どおり戻せて、各メディアの大事な判定が同じ答えになる」こと。こぴちゃはそれに加えて頁が 1 字も変わらないこと。

## 2. 読み取れること

**共通の骨（すでにそろっている物）**

1. 点・名前・主張・根拠・出典・問い・観測、の表の組。
2. 「1 行 1 事実」「原文を写さず要約」「根拠の場所は必須」「権利の条件を満たさない物は使わない」。
3. 書き手と別の者が確かめ、確かめた跡を残す。
4. 行は消さず退役にする。出した URL は消さない。
5. 試し → 本採用 → 退役と、見直し日。
6. 本人の言葉は本人が書く。

**メディアごとに違う所（§4 で一般化する。語をそろえるのでなく、軸と宣言で受ける）**

- 主張の状態の語と、その条件（`established` の条件は染めと化学とキョンシーで生きていて、MMR は廃止した）。
- 読みの段の語（キョンシーの `human_reviewed`、こぴちゃの verified・rechecked、MMR の 3 値）。
- 弱い根拠の扱い（MMR は報道と DB を一律に弱いとする決まりをやめた）。
- 出所の持ち方（別の表・欄ごとの並び・3 段）。置き方（表・YAML・JSON・頭つきの .md）。
- 出し口の数（MMR の照合台帳は 2 つ）。期限の意味（見直すだけ・伏せる）。
- 図版の条件（資料の図は利用の条件、再現図は根拠と生成の記録）。
- 出した URL の関門の厳しさ。

**弱い所（器の側で直す）**

- **点検の台本が、今の決まりと食い違っていても気づけない。** MMR の台本には廃止した条件が残るが、今の主張に `established` が無いので全件が通る。
- **表を手で直して壊す事故。** にがみラボの 33 枚は、CRLF だけが 12・LF が 20・**混ざっているのが 1 枚**（`topic-hubs.csv`）。染めと化学では文字列の置き換えが引用符を壊した。
- **取り込みが途中で止まると戻らない**（こぴちゃの K1 の取り込み）。
- **確かめた跡が `notes` の欄に文で詰めてある。** 機械で引けない。
- **未確認と否定が、道具によっては同じ扱いになる。**
- **対応表が「同じ物」と「関わりのある物」を分けていない。**
- **THTH の今の台帳は、この骨をほとんど受けられない**（§6）。
- **こぴちゃの欄の名前が THTH の頭とぶつかる**（`kind`・`source`）。

## 4. 一般化する違いと、固有として残す物

**語をそろえない。** 各メディアの語と番号はそのまま台帳に残し、器の軸と名前付きの検査で受ける。

| 違い | 器の決まりにする形 |
|---|---|
| 主張の状態の語と条件 | 語は台帳のまま。状態ごとの条件を、憲法の行が名前付きの検査で宣言する（「この状態なら、本人が原文を見た根拠が 1 つ以上」「独立した支える出典が 2 つ以上」など）。宣言しないメディアには効かない |
| 読みの段の語 | 語は台帳のまま。「何を読んだか」と「誰が確かめたか」の 2 つの軸に対応づける |
| 弱い根拠の扱い | 上限つきにする種類を憲法の行が宣言する。宣言が空なら上限なし（MMR） |
| 未確認・欠け・否定 | 調べの結果・在るか・整合の軸で別々に持つ |
| 出所の持ち方 | どれも「行（か内側の単位）× 出典 × 場所 × 読み」に読み替える |
| 置き方 | 枚の行の中身の書き方・枚の内側の索引・表の行 |
| 出し口の数 | 種類の行が出し口を宣言し、採用は出し口ごと |
| 期限の意味 | 見直す日・使える期限・確かめ直しの期限を別の欄に。伏せ方は種類が宣言 |
| 図版の条件 | 図版の種類ごとの条件を宣言 |
| 出した URL の関門の厳しさ | 許す転送・二重の扱い・例外を台帳が宣言 |
| 言語・列の名前・改行の流儀 | 列の対応と、表のバイトを保つ書き方 |
| 枚の上限 | 種類ごとに宣言（既定は今の 64 KB） |

**固有として残す物**（器に入れず、各メディアの repo と道具に置く）:

- 分野の言葉の点検（評価語・表記の手引き・親の言葉）。
- 観測の列の中身。頁の型・デザイン。
- 各メディアの関門の中身（にがみラボの 32・中受の問の画面の柵）。**共通の点検が通っても、今ある関門は外さない。**
- 監査の回数や手順（何回読むか・だれが統合するか）。器が共通にするのは記録の索引だけ。
- こぴちゃの毎朝の商品の観測。
- キョンシーラボの物語と設定の資料（創作）。
- 関東の面をまとめる台本と、合わせた定員を 1 つの回に配らない、などの組み立ての知恵（器は内側の単位を指せるようにするまで）。

## 5. 器の形（案）

### 5.1 行の置き方

**枚の行**: 1 行 = 1 枚の .md。上に THTH の頭、その下に**中身を元のファイルのまま**置く。

```
---
id: origin-brazil
kind: origin
status: 本採用
source: owner
confirmed: 本人が認めた
review_by: 2027-11-20
public: true
---
name: ブラジル
domain: coffee
aliases: [Brazil, ブラジル連邦共和国]
summary: …
```

- 中身は、種類の行が決めた書き方（文・YAML・JSON・頭つきの .md）で、元の最初の 1 字から最後の 1 字まで。THTH は中身を書き直さない。
- 頭と中身が別の場所なので、こぴちゃの `kind`・`source` とぶつからない。
- 今の店の種類は「中身が文」の場合にあたり、今ある台帳は 1 字も直さずに読める。
- **上限は種類ごとに宣言する**（既定は今の 64 KB）。関東の入試結果は 142 KB の枚が実際にある。

**枚の内側の単位**: 1 枚の中に、対象・欄・年度ごとの値が並ぶ種類（関東の学校・MMR の照合台帳）は、種類の行が内側の道（`results[年度][回].applicants` のような）を宣言し、器が**索引**を作る。

- 内側の単位は `<行の番号>#<道>` で指せる。根拠・年度・確かめ・訂正・期限を、内側の単位に付けられる。
- 中身は包んだまま変えない。索引は中身から作り直せる物で、正本ではない。
- 枚全体に 1 つの「認めた」を付けるだけでは、関東の「欄ごとに年度が違う・前の年の値を残す」を受けられないため。

**表の行**: 1 行 = CSV の 1 行。表のファイルは台帳のフォルダに置く。

- 頭の欄は、表の列と種類の行から決める。
- 番号を持たない表は、**子の表**か**線の表**として宣言する。
- 上限は枚と別（叩き台: 1 つの表 20 万行・50 MB）。
- 主張を 1 件 1 枚にはばらさない。

**ほかの形のファイル**（MMR の `queue.json` や `content/index.yaml` のように、1 つのファイルに行の並びが入る物）は、「1 つの JSON か YAML の中の並び = 表」として宣言できるようにする。ファイルは包んだまま。

### 5.2 台帳の憲法と、種類の行

種類の決まりを、THTH のコードから台帳の側へ出す。

**憲法の行**（台帳に 1 枚）: ラボの型の `lab.yaml` をそのまま包んで受ける。

- 主題・一文の立場（本人が認めた印が無ければ使えない）・柱・軸・観測・出し口・形・言語・権利の既定・網羅の上限。
- 語の宣言と、軸への対応。状態ごとの条件。上限つきにする根拠の種類（空でもよい）。入れない物。
- **どの決まりが正本か**を書く（MMR なら規則の書）。段 0 でメディアごとに確かめる。

**種類の行**（種類ごとに 1 枚）が宣言すること:

- 置き場・中身の書き方・上限・番号の取り方。
- 欄と型。入れ子の道（`facts[].source`・`vocab.evidence_types`）も書ける。読者に見える欄・既定で出さない欄・分からないと書いてよい欄。
- つながり（§5.4）。内側の単位。
- **組合せの条件**（下）。
- 出し口と、採用の取り方（§5.6）。
- 要る裏付け（§5.3 の判定の名前）。二段で認めるか。期限の扱いと伏せ方。
- 表なら、頭の欄をどの列から取るか。

**組合せの条件は、THTH が備える名前付きの検査を、台帳が名指しして引数を渡す形**にする。台帳に式や命令は書かせない。最初に備える物（どれも実物に出どころがある）:

| 検査 | 意味 | 出どころ |
|---|---|---|
| 重ならない | 欄の組が台帳の中で 1 つ（同じ対象の中で並び順が重ならない） | にがみラボ |
| この状態ならこの欄が要る | 確かめた、と書くなら出典が要る | にがみラボ・キョンシーの図版 |
| この組は禁じる | この種類の根拠は、この種類の主張を支えない（表をまたぐ） | キョンシー |
| 独立した数が要る | 支える出典が N 個以上 | 染めと化学 |
| この段の根拠が要る | 本人が原文を見た根拠が 1 つ以上 | 染めと化学・キョンシー |
| 種類ごとに要る欄が違う | 資料の図なら利用の条件、再現図なら根拠・生成の記録・補った所 | キョンシーの図版 |
| 語はこの中から | 宣言に無い語を断る | どのメディアも |

- 検査を足すのは THTH のコードの仕事（版を上げる）。足りない検査は、段 0 の目録で先に洗い出す。
- **THTH は憲法の行と種類の行に書かれた命令を実行しない。**
- **入れ子を読む。** YAML は、決めた範囲（入れ子の対応と並び・1 行の並びと対応・長い文・注記）を全部読む読み手を THTH に持つ。範囲の外の書き方（別名の参照・型の札・複数の文書）は「読めない」と断る。外の部品は足さず自前で持つ（THTH は今、外の部品が 0。YAML の古い読み方の落とし穴も避けたい）。試験では、7 つのメディアの全部の YAML を、世の中の読み手の結果と突き合わせる（開発のときだけの部品）。JSON は標準の部品で道まで読む。
- 憲法の行と種類の行も行なので、認めた印・跡・柵が効く。形を変えるのは意味を変えることなので、認める操作は二段。
- **備え付けの種類**を THTH が持つ: 今の店の 7 つ、網の型の表、図版、憲法、種類、対応、採用。

### 5.3 裏付けは、いくつかの軸で持つ

今の 3 つの印は「推測・本人」の 2 段と否定しか持たない。第 1 版は 1 本の階段（推測 → 集めた → 別の者 → 本人）にしたが、実物はそれに収まらない。学校台帳の第 2 版と同じく、**互いに排他でない軸を同時に持つ**。

| 軸 | とる値（器の側の言葉） | 各メディアの語の例 |
|---|---|---|
| 在るか | ある・欠け（理由: まだ集めていない・資料に書かれていない・公表されていないと確かめた・当てはまらない・食い違いなどで決められない） | 学校台帳の `presence`・`missingReason`、null のままの値 |
| 何を読んだか | 書誌だけ・要旨・機械で本文・原文の該当の所 | `metadata_only`・`abstract_checked`・`machine_read`、MMR の一次・二次 |
| 誰が確かめたか | 書き手だけ・別の者・統合の者・本人が説明を聞いた・本人が原文を見た | collected・verified・rechecked・`integrator_checked`・`human_reviewed`・`human_checked`・学校台帳の照合 |
| 支えと反証 | 独立した支える出典の数・食い違う根拠の数・弱い種類だけか | `relation` と `evidence_type` から数える |
| ほかの資料との整合 | 食い違いなし・食い違いあり（どの行と）・比べていない | `contested`・学校台帳の `consistency`・`mismatch_open` |
| 調べの結果（問い・仮説） | まだ・調べている・話があることは確かめた・**調べたが届かなかった（何を調べたか・調べ直す条件）**・**反証がある**・本人が違うと言った | `unverified`・`documented`・`checked_unconfirmed`・`refuted`・本人が違うと言った |
| 言える範囲 | 対象・時点・条件 | `scope`・`as_of`・`taishou`・MMR の「この曲か・一般か」 |
| 置き換え | 生きている・置き換えられた（何に・いつから） | 学校台帳の `supersession`・退役 |
| 期限 | 見直す日・使える期限・確かめ直しの期限 | `review_by`・`valid_until`・`ima`・学校台帳の `recheck` |

- **原語は残す。** 軸の値は、台帳の語から憲法の行の対応で読む。対応の無い語は原語のまま持ち、判定では「使えない」に倒す。
- **持たずに計算する物**: 期限を過ぎたか・年度が合うか・催しが過ぎたか。判定の日時を入力にして計算する（§5.6）。
- **根拠の「原典に無かった」「食い違い」は、主張の否定ではなく、その根拠が支えにならないという記録。** 支えの数に入れない。主張が否定されるのは、反証の根拠があるときか、本人が違うと言ったとき。

**使えるかの判定**は、種類ごとに名前を付けた条件の組で決める（憲法の行と種類の行が宣言。§5.2 の検査を使う）。例:

- 店の事実・思い・憲法の立場: 本人が認めた記録があり、中身が変わっていない（今の柵と同じ）。
- 主張（こぴちゃ）: 状態が使える語・別の者が確かめた支える根拠が 1 つ以上・出典の権利の条件・使える期限の内。
- 主張（染めと化学の `established`）: それに加えて、本人が原文を見た根拠と、独立した支える出典 2 つ以上。
- 主張（MMR）: 規則の正本のとおり（本人の確認を求めない・報道と DB を一律に弱いとしない）。

**最後の見え方は 4 つ**にする。3 つの印に「まだ分からない」を足す。

| 見え方 | 意味 | 材料に |
|---|---|---|
| 推測 | 裏付けが条件に届いていない | 使えない |
| 認めた | 条件に届いた（言い方の上限・言える範囲つき） | 使える |
| まだ分からない | 欠け・調べたが届かなかった・食い違いが未解決・照合のあとに変わった | 使えない。**理由と、調べ直す条件を付けて返す** |
| 違う | 反証がある・本人が違うと言った | 使えない。消さずに残す |

- 「使えない」は共通でも、理由は分ける。調べたが届かなかった問いは、新しい資料が出たら調べ直してよい。本人が違うと言ったことは聞き直さない。
- 店主の台帳の頭の `confirmed` は今の 3 語のまま。「まだ分からない」は見え方にだけ現れる（頭に書かせない）。
- 同じ者の確かめを数えない（集めた者と確かめた者が同じなら「書き手だけ」）。
- 言い方の上限と言える範囲を、材料に付けて渡す。

### 5.4 行どうしのつながり

- 種類の行が「この欄（列・道）は、どの種類の行の番号を指すか」を宣言する。
- 点検: 指す先が在る・種類が合う・輪になっていない。指す先が退役か置き換えなら知らせる。
- 番号は台帳の中で 1 つ。こぴちゃの枚の行は `<種類>-<ファイル名>`（点の表と同じ付け方。235 枚のうち 230 枚に同じ番号がある）。同じ番号の枚の行と点の表の行は、同じ物の 2 つの面として受ける。
- **台帳をまたぐつながり**は `<台帳>:<番号>`。共通の行は**採り入れた版**（指紋）と一緒に指す（§7.2）。相手の台帳が手元に無ければ「確かめられない」と言う。
- **つながりに関係の種類を持つ**: 同じ・関わる・上位と下位・置き換え。対応の行（§7.3）で使う。
- 外の同じ物（MusicBrainz の番号・DOI）は形だけ点検し、外へ読みに行かない。
- 引く命令: `thth register links <行>`。

### 5.5 変えた跡と、確かめの索引

- **土台は git。** `thth register diff <前>..<後>` が、足した・変わった（どの欄か）・退役した・消えた行を種類ごとに出す。
- **番号が消えたら赤**（`check --against <commit>`）。
- **訂正の跡**（追記だけ）: どの行（か内側の単位）のどの欄・旧い文と新しい文（MMR のとおり、文そのものを残す。出さない欄の値は指紋だけ）・なぜ・誰が・いつ・どの出所で。読者に見せた事実を直したときに書く。
- **取り込みの跡**: 束ごとに、sha256・集めた者・検めた者・判定・取り込んだ日・行の数。
- **確かめの索引**（共通にするのは記録の形で、手順ではない）: どの範囲（行・欄・頁の行）を・どの版（commit か指紋）について・誰が（書き手と別か）・何に照らして・判定・**未解決の物**・直したあとに残った問題。その確かめが**どの版にだけ効くか**が分かる。
- **元の記録は包んで残す。** キョンシーの監査の結果・こぴちゃの中央の判断と直す前の文・MMR の束と訂正の台帳は、そのまま台帳に入れ（1 つのファイル = 行の並び、の置き方）、上の索引から指す。索引だけにして元を捨てない。
- **認めた跡**: 最後の 1 つでなく、足していく。
- git でない置き場の台帳は、跡が読めないと正直に言う。

### 5.6 出口は 2 つ

第 1 版は「そのまま写す」と「出さない行は書かない」を 1 つの口に置いていた。出さない行を落とせば元と同じにはならない。**働きが違うので分ける。**

**(1) 元どおり戻す出口** `thth register restore <台帳> --to <フォルダ>`

- 取り込んだ物を、元の場所・名前・バイトで全部書く。柵を通さない。
- 役目: **保存できたことの証明**（取り込み → 戻す → 元と sha256 が全部同じ）と、持ち出し・退避。
- 出さない行も含むので、公開の場所へ書くための物ではない。行き先が git の作業木の中で、その repo に元のファイルが無いときは、確かめを挟む。

**(2) 公開する材料の出口** `thth register export <台帳> --outlet <出し口> --to <フォルダ> --as-of <日時>`

- 柵（§5.3 の判定）と期限を通った物だけを、出し口ごとに書く。
- **判定の日時は入力**（既定は今）。同じ台帳・同じ日時なら同じ出力。期限で出力が変わるので、「同じ台帳なら同じ出力」とは言わない。
- **材料の控え**（世代ごとの一覧）: 書いたファイルごとの sha256・元の行（内側の単位）の番号と指紋・通した理由・判定の日時・**判定に使った憲法の行と種類の行と共通の行の版**・使った認めた跡の指紋。
- **旧い材料が残っていたら止まる。** 書き出し先に、今回の一覧に無いファイルがあれば赤（THTH は消さない。消すのは持ち主かレーン）。こぴちゃのように「フォルダの中を全部読む」サイトでは、省いただけでは古い材料が読まれ続けるため。新しい空のフォルダへ世代ごとに書く使い方も同じ命令でできる。
- **差し込み**: 中身の `{{行の番号.欄}}` に台帳の値を入れる（使う種類だけ）。
- **採用の記録**: 「どの行のどの版を、どの出し口へ採ったか・誰が・いつ」。頭の `public: true` は、出し口が 1 つの種類の略し書きとして残す。MMR の照合台帳の `public`・`public_song` は包んだ中身の欄のままで、種類の行が出し口に対応づける。
- 基準（§8.2）: 移す前から公開していた中身は基準として通し、足した・変えた行から柵が効く。
- `--check`: 書かずに比べる。

**CI が保証する範囲**を言葉で分ける。

- CI（記録の無い機械）が見るのは**一致**: 置いてある材料・控え・行の指紋・憲法と種類と共通の行の版が、互いに合っているか。
- **承認の照らし直し**（認めた跡の指紋と行の指紋）は、記録のある機械でだけできる。CI の出力には「承認は照らし直していない」と必ず出す。
- 控えは一致を見るための物で、信用の根ではない。「頭の印でなく THTH の側の記録を信じる」今の境（`fence.py`）を、控えで弱めない。

**期限と伏せ方**

- 3 つを分ける: **見直す日**（過ぎたら health の候補に出すだけ。指標や図鑑の頁）・**使える期限**（過ぎたら材料に使わない。値段・日程・「今」の表）・**確かめ直しの期限**（過ぎたら「まだ分からない」に倒すかを種類が選ぶ）。
- 今の柵の「見直し日を過ぎたら使えない」は、備え付けの店の種類ではそのまま残す（営業の時間を古いまま出さないため）。種類の行で選べるようにする。
- **伏せ方**は種類が宣言する: 行ごと・欄だけ・表の中の行だけ（中受の問は、表全体の期限と行ごとの締切を別に見る）。
- **もう公開された静的な頁を、THTH は伏せられない。** 器が受け持つのは 3 つ: (a) 判定の日時を入力に材料を作り直せること、(b) health が「N 日以内に期限が来る材料」と「期限を過ぎたのに最後の世代に載っている材料」を出すこと、(c) 期限を過ぎた材料が載った世代を配ろうとしたら関門が赤になること。
- いつ作り直して配るかは、各メディアの配信の拍子（こぴちゃは毎朝、ほかは承認のあと）。作り直せなかったときに動くのはそのメディアのレーンで、知らせは hub の朝の 1 枚（§7.4 の 1 行）。

**出した物の控えと関門** `thth register published`

- 追記だけの控えと、build のあとの関門の**仕組み**を共通にする。**厳しさは台帳が宣言する**: 許す転送の種類（30x 全部か、301・308 だけか）・頁と転送の二重を赤にするか知らせるだけか・理由つきの例外。
- 今の各メディアの関門は、同じ入力で結果が同じになるのを確かめてから置き換える。共通の点検が通っただけで、今ある関門を外さない。

**読者に見える欄の点検**: 内部の番号・作業の呼び名らしい語を拾う。分野の言葉の点検は各メディアに残す。

### 5.7 書く口と、束の取り込み

- `thth register row add|set …`: 表に 1 行足す・1 欄直す。
  - **表を読むとき、レコードごとの元のバイトの範囲を覚える。変えるレコードだけを書き直し、ほかは元のバイトをそのまま並べる。** 改行の流儀を表ごとに覚えるだけでは、混ざった表（にがみラボの `topic-hubs.csv`）を守れない。
  - 足す行の改行と引用は、直前のレコードの流儀に合わせる。
  - 書いたあと、触っていないレコードの sha256 が前と同じかを自分で確かめ、違えば書かずに断る。
- 枚の行は今のとおり（THTH が書くのは頭の決まった欄だけ）。
- `thth register merge <台帳> <束>`: 束を取り込む。
  - 守り: 判定が断りの行は入れない・重なる番号は入れずに知らせる・集めた者と検めた者が同じなら入れない。
  - **複数の表を 1 つのまとまりとして入れる。** 全部を横の場所に書いて点検し、通ったら入れ替える。途中で止まっても、次に動かしたとき「続けるか・戻すか」が決まる（入れ替えの控えを先に書く）。こぴちゃの今の取り込み（書いたあとに点検し、赤でも戻さない）を器で直す所。
  - 取り込みの跡と、確かめの索引（複数の検め・中央の判断・直す前の文）を残す。
- **THTH は集めない・検めない。** 器は、検められていない物が台帳に入らないことだけを受け持つ。
- これは今の privacy の約束（THTH が台帳に書くのは頭の決まった欄と問いの記録だけ）を変える。privacy の改訂と Worker の deploy が要る（§10）。

### 5.8 健康と見直し

`thth register health <台帳>`（読むだけ）。

- 網の健康: 目的語が点である線の率・線の薄い点・述語の偏り・開いた問いの数と閉じ方・読みの分布。
- 裏付けの健康: 書き手だけの行・基準で通っただけの行・同じ者が確かめた行・「まだ分からない」の行と理由・調べ直す条件が満たされた問い。
- 期限: 見直す日を過ぎた・使える期限が近い・過ぎたのに最後の世代に載っている。
- 決まりの食い違い: **憲法の行が宣言した条件に、1 行も当たらない検査**を知らせる（MMR の、廃止したのに台本に残る条件のような物が見える）。
- 見直しの候補を出すだけで、決めるのは持ち主。
- `--all --json` の 1 行を hub が朝の 1 枚に束ねられる。

## 7. 1 人で複数のメディアを持つ場合

### 7.1 階層

```
持ち主（THTH の利用者）
├─ 共通の台帳（持ち主に 1 つ。無くてもよい）
├─ メディア A（THTH の project）── 台帳（1 つ以上）・口座
└─ メディア B ── 台帳・口座
```

- **メディア = 今の THTH の project。** 口座の台帳も台帳の控えも、すでに `project` を持つ。新しい層は作らない。
- **持ち主 = THTH の利用者。** 足すのは共通の台帳の控えだけ。
- 1 つのメディアが台帳を 2 つ以上持ってよい（書く拍子と書く者が違うとき）。

### 7.2 共通の行の持ち方（決め: 共通の台帳に置いて指す）

**正本は共通の台帳に 1 つ。各メディアは、採り入れた版で指す。**

- メディアの行は `共通:<番号>` と、**採り入れた版の指紋**を持つ（採用の記録）。
- 共通の行を直しても、その瞬間に各メディアの公開の材料は変わらない。health に「共通が進んだ・採り入れ待ち」と出る。メディアごとに `thth register take 共通:<番号>` で採り入れ、変わる頁を先に見せる。
- 写しは作らない。正本は 1 つで、各メディアが持つのは「どの版を採ったか」だけ。材料は書き出しのたびに共通の台帳のその版から作る（共通の台帳が git なので、前の版を読める）。
- こうする理由: 公開の時期・承認・譲る・障害からの戻しを、メディアごとに分けられる（push が即公開のメディアと、承認つきのメディアが混ざっている）。
- すぐ全部に効かせたい物（運営者の表記など）の扱いは §9 の 3。

| 共通に置く物 | 共通にする範囲 | 共通にしない範囲 |
|---|---|---|
| 運営者の情報 | 名前・窓口・表記 | 既定で出さない。家族の名前は入れない |
| 持ち主の思い | メディアをまたぐ編集の考え | メディアごとの思いは各台帳 |
| 口座の一覧 | 名前と向き先 | 鍵は入れない |
| 同じ物の対応 | §7.3 | 各メディアの点の中身 |
| 同じ出典 | **書誌だけ**（題・著者・年・DOI・URL・権利の条件） | 読んだ所・支える主張・確かめた深さ・そのメディアで使ってよいか、は各メディア |
| 書き方の決まり・図版 | 文・図と権利 | 採るかは各メディア |

- **今ある物は番号を変えない。** 別の番号で持つ同じ出典・同じ点は、対応の行で結ぶ。新しく足す共通の物から共通の台帳に置く。
- 同じ出典の見つけ方: `health --across` が、DOI・URL が同じで番号の違う出典を並べる。結ぶかは持ち主。

### 7.3 メディアどうしのつながり

- **対応の行**: 1 行 = メディアをまたぐ 1 つの対応。各メディアでの番号と、**関係の種類**（同じ・関わる・上位と下位）を持つ。今の対応表の 31 行は、移すときに 1 行ずつ関係を見直す（柿渋の行は「同じ」ではなく「関わる」）。各メディアの番号は変えない・個人の名前と商品の名前は共有しない、は持っていく。
- **姉妹リンクは、対応とは別の編集の判断。** 対応があることと、頁から頁へリンクを張ることは別。対応から候補を出し、載せる対（どの頁からどの頁へ・一言）を行として認める。認めた対は両方のメディアの材料に同じように出る。
- 相手の頁が退役・転送になったら、出した物の控えで分かり、リンクの側に知らせる。
- 置き場と移す時期は、本線の条件のとおり（§9 の 2）。

### 7.4 管理の仕方

- **足す**: 台帳のフォルダを作り（備え付けの種類を並べた憲法の行から）、`thth register add <台帳> --project <メディア>`。共通の台帳にメディアの行を 1 枚。
- **退役**: メディアの行を退役に。台帳の行も出した URL も消さない。口座は止める。出した物の関門は動かし続ける。
- **鍵と口座**: **主体は持ち主に、口座はメディアに。** 今のはてなの作り（主体 = ID 1 つと鍵、口座 = 主体 ＋ ブログ 1 つ）を、ほかの口にも広げる向き。鍵は台帳に入れない。
- **書ける範囲**: 器は手元のファイルに鍵を掛けられない。境は git の repo と各 repo の入口の文書。器が受け持つのは、跡に「誰が」を残す・`diff` で変わった台帳と種類を出す・憲法と種類と共通の行の変更を二段にする、の 3 つ。レーンの名簿は hub の物。
- **まとめて見る**: `health --all --json` がメディアごとに 1 行。
- **外す範囲は 3 つ。言葉を分ける。**

| 範囲 | 命令（案） | 消える物 | 残る物 |
|---|---|---|---|
| 口座 1 つ | 今の `thth leave <口座>`（そのまま） | その口座の鍵・状態・記録 | メディア・台帳・ほかの口座 |
| メディア 1 つ | `thth project leave <メディア>` | そのメディアの全部の口座・台帳の控え・認めた跡・使った先の控え | 台帳のフォルダ・共通の台帳・ほかのメディア |
| 持ち主の全部 | `thth owner leave` | 全部のメディアと共通の台帳の控え・主体 | 台帳のフォルダ（持ち主の物） |

  - 今の `leave` は「その project の最後の口座」で台帳の控えも消す。これは残すが、メディアを外すのは名指しの命令に分ける。
  - **持ち出し**: `thth register state export` が、THTH の側の記録（跡・控え・出した記録）を台帳のフォルダに平文で書く。メディアを 1 つ持ち出すときは、採り入れている共通の行の、その版を付ける（出さない欄は付けない）。

### 7.5 1 店・1 メディアで始めて、あとで増やす道

1. 最初は台帳 1 つ。共通の台帳は無い。今の 5.19.0 と同じ使い方。
2. 2 つめを足すとき、THTH が「両方に同じ物がありそう」を並べる。
3. 持ち主が選んだ物だけ共通の台帳へ移す。元の行は番号を変えず、共通を指す行になる。移した行はもう一度認める。
4. 移さなくても動く。

### 7.6 hub との線

- **器・点検・出口・健康の数は THTH。メディアの指揮は hub。**
- hub に残す: レーンの名簿と呼び名・伝言・申し送り・承認の台帳・朝の 1 枚・スコアボード・計測の道具。
- 重なる 2 つ（メディアの一覧・対応表）は、本線の返事（§9 の 2）のとおり進める。VM の朝の集計が THTH の行を読めない朝は、前の日の値で黄にして続ける。
- 計測の数を行へ返す口は、この書に入れない。

### 8.2 こぴちゃを最初にする段取り

1. **相談**: こぴちゃのレーンに §8 と §10 を hub msg で渡す。

### 8.3 確かめ方

作った者と別の者が、命令を打ち直して確かめる。

1. **元どおり戻せる**（7 つ全部）: 取り込み → 戻す出口 → 目録のファイルと、数・名前・sha256 が全部同じ。
2. **公開の材料が同じ**（こぴちゃ）: 基準で全部通した公開の材料の出口が、元の材料と sha256 で同じ。柵で落ちる物があるメディアでは、「落ちた物の一覧」と元との差がぴったり合う。
3. **頁が同じ**（こぴちゃ）: 同じ commit・同じ `node_modules`・同じ日に、基準のまま build と、材料を差し替えて build。`dist/` の全ファイルの sha256 を比べる。先に同じ物を 2 回 build して、もともと揺れるファイルを名前と理由つきで書き出す。揺れが多すぎて比べにならなければ止まって知らせる。
4. **判定が同じ**（7 つ全部）: 段 0 で決めた「各メディアの大事な判定」の一覧について、器の答えが各メディアの**今の決まり**の答えと同じ。台本と同じ結果になるだけでは足りない（台本が古い所は、規則の正本に合わせる）。
5. **柵を壊して赤を見る**: 1 行を 1 字変える・行を消す・表の 1 行を変える・期限を過ぎた日時で判定する・旧い材料を残す、でそれぞれ赤。

### 8.4 移す間、運用を止めない

- 正本はいつも 1 つ。影は片道。両方に書く期間を作らない。
- VM の毎日の観測は、移す物に触れない。向きを替える push は 04:00〜04:30 を避ける。
- 向きを替える commit は材料を変えない。戻し方は revert 1 つ。

### 8.5 どのレーンが何をするか

| だれ | すること |
|---|---|
| THTH開発 | 器・道具・柵・試験。憲法と種類の行の叩き台。影の台帳と §8.3 の証明。ほかの repo は**読むだけ** |
| 各メディアのレーン | 段 0 で「今の決まり」と目録を確かめる（THTH開発が叩き台を出し、レーンが直す）。向きを替えるときの commit・入口の文書・CI・書く道具・push |
| masaru | §9 の 3・4。基準を認める。向きを替えてよいかの承認。privacy の改訂を含む release の「出して」 |
| 別の者 | §8.3 を打ち直して確かめる。Codex に頼むときは「ファイルを変更・削除・commit しない」と書く |
| media-hub の本線 | 対応表とメディアの一覧（条件は §9 の 2） |

### 1. 「そのまま」を、元のファイルを 1 字も変えずに包む形にするか、THTH の 1 つの形に開き直すか

**決め（masaru 2026-11-13）: 包む。**

- **包む（推し）**: 枚の行は中身を元のまま、表は表のまま。語も番号も各メディアのまま、憲法の行で器の段に対応づける。
  - 得る物: 頁が変わらないことを sha256 で言える。7 つのメディアの道具と決まりがそのまま使える。影で 7 つとも点検できる。
  - 払う物: 台帳の中に YAML・CSV・JSON が混ざる。器は憲法と種類の行を読む機械になり、作る量が増える。語がメディアごとに違うまま残る（対応で読む）。
- **開き直す**: どの行も「頭の欄 ＋ 文」の 1 つの形・1 つの語にそろえる。

### 3. 共通の行を直したとき、各メディアにいつ効かせるか（新しい問い）

- **メディアごとに採り入れる（推し）**: 各メディアは採り入れた版で指す。共通を直すと「採り入れ待ち」が出て、メディアごとに 1 つの命令で採り入れる（§7.2）。
  - 得る物: 公開の時期と承認をメディアごとに分けられる。共通の直しの間違いが、全部のメディアに一度に出ない。メディアを譲る・戻すが、版の単位でできる。
  - 払う物: 共通を直すたびに、メディアの数だけ採り入れの手が要る。採り入れ忘れで、メディアごとに古い版が残る（health に出るが、手は要る）。
- **直したらすぐ全部に効かせる**: 各メディアは番号だけで指し、次の書き出しで最新が入る。
  - 得る物: 手が 1 回で済む。運営者の表記のように、全部で同じでなければならない物に向く。
  - 払う物: 共通の 1 行の直しが、承認の要るメディアの頁も変える。こぴちゃのように push が即公開のメディアでは、次の朝に勝手に出る。間違えたとき全部を戻す。
- **前提が変わると**: 共通に置く物が運営者の表記と口座の一覧くらいで、メディアごとの承認の違いを気にしないなら、すぐ効かせるほうが楽。推しの形でも、種類ごとに「すぐ効かせる」を選べるようにはできる（運営者の表記だけ、など）。その場合、その種類の行を直す操作を二段にし、変わる頁を全部のメディアについて先に見せる。

### 4. 1 回の release の受け入れの線を、どこに引くか（新しい問い）

- **7 つ全部を条件にする（推し）**: 7 つのメディア全部で、目録に漏れがない・元どおり戻せる・大事な判定が今の決まりと同じ答えになる。こぴちゃはそれに加えて頁の一致。候補の版で影の運用を何日か繰り返し、途中で止める・続ける・戻すを確かめる（§10 の段 10）。

- **こぴちゃとラボ型の 4 つで出し、関東と MMR の固有の所を次の版にする**:

## 11. 危ないこと

1. **サイトが壊れる・頁が変わる。** → 基準で通す。向きを替える commit は材料を変えない。`dist` の sha256 を前後で比べる。
2. **出所が落ちる。** → 表はレコードのバイトを保つ。根拠の無い主張・権利の条件を満たさない出典は落とさず、見え方を変えて残す。
3. **二重の正本になる。** → 影は片道。写しは CI の一致。共通の行は版で指し、写しを持たない。
4. **早くそろえて、各メディアの意味が消える。** 未確認を否定にまとめる・説明を聞いたと原文を見たを同じにする・廃止した条件を共通の決まりに上げる、のどれも実物で起こりうる。→ 原語を残す・軸で持つ・段 0 で決まりの正本を確かめる・大事な判定の一覧を受け入れ条件にする。
5. **「認めた」の重みが薄まる。** → 跡に、基準・別の者・説明を聞いた・原文を見た、を分けて残す。害の大きい種類は台帳が条件を選ぶ。
6. **認めた記録が機械ごと。CI が承認まで見たように見える。** → CI は一致だけと出力に書く。承認の照らし直しは記録のある機械で。
7. **憲法と種類の行が攻め口になる。** → 命令を実行しない。検査は THTH が備えた名前付きの物だけ。道の宣言は台帳と書き出し先の中だけ。
8. **自前の YAML の読み手が読み違える。** → 範囲の外は断る。7 つのメディアの全部のファイルで、世の中の読み手と突き合わせる。
9. **古い材料が読まれ続ける。** → 公開の材料の出口は、一覧に無い旧い材料があれば止まる。
10. **期限を過ぎた頁が出たままになる。** THTH は公開済みの頁を伏せられない。→ 健康と関門で知らせ、作り直すのはそのメディアの配信。作り直せないときの持ち主はそのメディアのレーン。
11. **共通の行の直しが、採り入れ忘れで古いまま残る。** → 健康に「採り入れ待ち」。§9 の 3 の答えで扱いが変わる。
12. **共通の台帳に運営者や家族の情報が入る。** → 既定で出さない欄。憲法の「入れない物」。
13. **器が重くなり、店主の台帳が難しくなる。** → 憲法の行も種類の行も無い台帳は今のまま動く。
14. **1 回の release が大きい。** 形・判定・書く口・跡・出口・共通・外す、を同時に変える。→ 段ごとに main へ積み、段ごとの条件を通す。段 2 で器の置き方を先に固める。それでも重ければ §9 の 4。
15. **取り込みの途中で止まって表が壊れる。** → まとめて入れ替え、控えで戻す。止める試験をする。
16. **台本を置き換える途中で、結果が食い違う。** → 置き換える前に同じ入力で比べる。食い違いは「写したあとのずれ」か「そのメディアの決め」かを、レーンと分ける。今ある関門は外さない。
17. **privacy の約束を変える。** 表に書く口は、今の約束を広げる。→ 同じ版で privacy を直し、Worker を先に出す。
18. **hub との線がぶつかる。** → 本線の条件のとおり。読み手を同じ便で替える。
19. **ほかの人の投稿や個人の情報が台帳に入る。** → `data/sns/` は移さない。訂正の跡の旧い文は、出さない欄では指紋だけ。
20. **build の揺れで「同じ」が言えない。** → 先に同じ物を 2 回 build して揺れを知る。
21. **VM の push・VM の仕事の読み口とぶつかる。** → 向きを替える push は時刻を避ける。MMR の `queue.json` は VM の仕事の相談のあと。
