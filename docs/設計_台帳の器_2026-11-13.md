## 0. 芯

Things の正本として、器が持つ概念は **2 つ**にする。**記録**と**判断**。ほかの物（つながり・軸・見え方・索引・材料の控え・健康）は、この 2 つから導く。

### 0.1 記録

- **記録** = 番号・種類・中身。主張も根拠も出典も問いも、頁の文も、店の営業の時間も、監査の結果も、種類の違う記録。
- **番号**は「同じ記録」を指し続ける。中身が変わっても番号は同じ。
- **版**は中身の指紋（バイトから取る）。中身が 1 字でも変われば版が変わる。ただし、判断を書く欄と、仕事の進みを書く欄は指紋に入れない（今の THTH が「THTH が書く欄を除いた全文」で指紋を取っているのと同じ考え）。
- **記録は、ほかの記録の番号を指す欄を持てる**（主張 → 点、根拠 → 主張と出典）。これが「つながり」。芯を別に立てない。
- 「同じ」は 3 つを分ける。
  - **同じ物**（世の中の物。ブラジルという産地）: 番号ではない。物を表す記録を 1 つ決め、ほかの記録が「について」で指す。
  - **同じ記録**: 番号。
  - **同じ場所**（どのファイルの何番め）: 番号にしない。並べ替えで変わる。

### 0.2 判断

- **判断** = 「どの記録のどの版（の組）について・どの問いに・誰が・何に照らして・いつ・**よい／だめ／まだ**・理由・いつまで」。
- 本人が認めた・別の者が原典で確かめた・監査が通った・この出し口へ採った・基準として認めた・止める、はどれも判断。別々の仕組みにしない。違うのは、問いと、誰がと、照らした物。
- **版を縫い止めるのは判断だけ。** 記録どうしは番号で指す。判断は「見たときの版の組」を持つので、どれかが変われば、その判断は効かなくなる（古い判断として残る）。
- **結論は 3 つ**（よい・だめ・まだ）と理由。今の 3 つの印（本人が認めた・本人が違うと言った・推測）は、問い「本人はそうだと言うか」への 3 つの結論で、そのまま当てはまる。
  - 「推測」と「調べたが届かなかった」はどちらも**まだ**で、理由が違う。
  - **だめは、決着した判断。** 食い違う根拠があることは記録の事実で、それだけでは「だめ」にならない。
- **判断の在り方は 2 つ。** 中に書いてある物（主張の状態・照合台帳の「採った・採らなかった」・下書きの印・店の頭の `confirmed`）と、判断の記録（THTH が足していく）。包む決めなので、中に書いてある物は動かさない。器は、それを見つけたときの中身の指紋と一緒に控え、あとで中身だけが変わったら「古い」と言う（学校台帳の「照合のあとに変わった」）。

### 0.3 導く物

| 導く物 | 何から |
|---|---|
| **使えるか** | 決まり（憲法。これも記録で、本人の判断が付く）に、判断と判定の日時と用途を当てて計算する。保存しない |
| 9 つの軸（第 2 版） | 保存しない。記録の中身・指す欄・判断から読む問い（§5.3 の表） |
| 4 つの見え方（第 2 版） | 3 つの結論と理由 |
| 支えと反証の数 | 根拠の記録の指す欄から数える |
| 確かめの索引 | 判断の記録そのもの |
| 材料の控え | 「この世代は、この入力の版の組から出した」という記録 |
| 健康 | 記録と判断の数え方 |

### 0.4 Codex の 3 つの芯との違い

Codex は芯を「番号と版を持つ記録」「版を指すつながり」「用途を限った判断」の 3 つにした。向きは同じ。実物に当てて、3 か所を変えた。

| Codex の案 | この書 | 根拠（実物） |
|---|---|---|
| つながりを芯の 1 つにする | **記録の中の指す欄**にする | 根拠は、場所・要約・読みの段を持ち、それ自体が確かめの対象になる（どのメディアも根拠に番号がある）。つながりであり記録でもある物を、2 つの芯に分けられない |
| つながりは版を指す | **番号を指す。版を縫い止めるのは判断だけ** | どのメディアの表も番号で指している（こぴちゃの根拠 6,995 本は出典を番号で指す）。つながりが版を指すと、出典の題の誤字を 1 つ直すだけで、その出典を指す根拠が全部「古い」になる。包む決めとも合わない（列を足せない） |
| 判断は別の記録 | **中に書いてある判断も判断**として受ける | 主張の状態・`status: held`・`public` は表やファイルの中の欄で、外へ出せない |
| 判断を限るのは用途 | **問い**で限る。用途は問いの 1 つ | 「読みは原典と合うか」と「ここへ出してよいか」は、どのメディアでも別の欄になっている（主張の状態と下書きの印・照合の結果と `public`・THTH の `confirmed` と `public`）。正しさの判断に用途は無い |

### 0.5 難しい実物を、芯に当てた結果

| 実物 | 芯での形 |
|---|---|
| キョンシーの「調べたが届かなかった」問い 75 件 | 問い「調べはどうなったか」に**まだ**。理由と、調べ直す条件 |
| キョンシーの `human_reviewed` 507・`human_checked` 8 | 同じ問い「読みは合うか」への、照らし方の違う 2 種類の判断（説明を聞いた・原文を見た） |
| 染めと化学の `established` | 決まり: 本人が原文を見た判断が 1 つ以上、かつ、違う番号の出典が 2 つ以上。**「独立の 2 系統」とは言わない**（台本が数えているのは違う番号の数。独立かは別の問いで、判断が無ければ「まだ」） |
| MMR の廃止した条件 | 決まりは憲法の記録。台本ではなく、規則の書を写す |
| MMR の照合台帳の「採らなかった」452 行 | 問い「この担当はこの版の物か」に**まだ**、理由つき（別の版の記載 108・盤全体の記載 143・食い違い 19 ほか）。**事実としては出せないが、理由によっては留保の注として出せる**（理由が「未解決」の 171 行は注にも出さない） |
| MMR の `public` と `public_song` | 問い「出してよいか」を出し口ごとに |
| 関東の入試結果の回の行 7,460 | 行に番号が無い。年度・回・日・時間帯・性別・科目を鍵にしても、3 枚で 37 行が重なる。**鍵と中身の指紋で指す。位置では指さない**（§5.1） |
| 関東の「欄ごとに年度が違う・前の年の値を残す」 | **時点は鍵の一部。** 値を直すこと（訂正 = 同じ記録の新しい版）と、次の年の値が来ること（別の記録）を分ける |
| こぴちゃの枚と点の表の同じ番号 | 2 つの記録。枚が点を「について」で指す（第 2 版の「同じ物の 2 つの面」は取り下げ） |
| こぴちゃの往復する主張（ブラジル → 品種、品種 → ブラジル） | 輪を禁じるのは「含む・親・置き換える」の欄だけ。主張どうしの往復は止めない |
| こぴちゃの内部の層（仮説・作り手の言説・届かなかった問い） | 記録として保存する。読者の出し口への「出してよいか」の判断が無いので出ない。基準もそこには付けない |
| にがみラボの混ざった改行 | 版はバイトの指紋。書き直さない |
| MMR の `queue.json`（曲の情報と仕事の進みが同じ行） | 進みの欄を版から除く。VM が進みを書いても、曲の情報への判断は古くならない |
| 中受の問の期限 | 判断の「いつまで」と、判定の日時 |
| 「監査が通れば聞かずに出してよい」（キョンシー・MMR）・基準 | 決まり（憲法）から導く判断と、集まり（目録の指紋で名指す）への 1 つの判断 |

**芯に収まらず、決まりを足した所**: 中に書いてある判断（0.2）・時点を鍵に入れること・進みの欄。**まだ収まっていない所**: 消す求め（記録を残す作りと、持ち主が本当に消したい物。§11 の 22）。

## 2. 読み取れること

**共通の骨（すでにそろっている物）**

1. 点・名前・主張・根拠・出典・問い・観測、の表の組。
2. 「1 行 1 事実」「原文を写さず要約」「根拠の場所は必須」「権利の条件を満たさない物は使わない」。
3. 書き手と別の者が確かめ、確かめた跡を残す。
4. 行は消さず退役にする。出した URL は消さない。
5. 試し → 本採用 → 退役と、見直し日。
6. 本人の言葉は本人が書く。

**メディアごとに違う所（§4 で一般化する。語をそろえるのでなく、軸と宣言で受ける）**

- 主張の状態の語と、その条件（`established` の条件は染めと化学とキョンシーで生きていて、MMR は廃止した）。
- 読みの段の語（キョンシーの `human_reviewed`、こぴちゃの verified・rechecked、MMR の 3 値）。
- 弱い根拠の扱い（MMR は報道と DB を一律に弱いとする決まりをやめた）。
- 出所の持ち方（別の表・欄ごとの並び・3 段）。置き方（表・YAML・JSON・頭つきの .md）。
- 出し口の数（MMR の照合台帳は 2 つ）。期限の意味（見直すだけ・伏せる）。
- 図版の条件（資料の図は利用の条件、再現図は根拠と生成の記録）。
- 出した URL の関門の厳しさ。

**弱い所（器の側で直す）**

- **点検の台本が、今の決まりと食い違っていても気づけない。** MMR の台本には廃止した条件が残るが、今の主張に `established` が無いので全件が通る。
- **表を手で直して壊す事故。** にがみラボの 33 枚は、CRLF だけが 12・LF が 20・**混ざっているのが 1 枚**（`topic-hubs.csv`）。染めと化学では文字列の置き換えが引用符を壊した。
- **取り込みが途中で止まると戻らない**（こぴちゃの K1 の取り込み）。
- **確かめた跡が `notes` の欄に文で詰めてある。** 機械で引けない。
- **未確認と否定が、道具によっては同じ扱いになる。**
- **対応表が「同じ物」と「関わりのある物」を分けていない。**
- **THTH の今の台帳は、この骨をほとんど受けられない**（§6）。
- **こぴちゃの欄の名前が THTH の頭とぶつかる**（`kind`・`source`）。

## 4. 一般化する違いと、固有として残す物

**語をそろえない。** 各メディアの語と番号はそのまま台帳に残し、問い・判断・名前付きの検査で受ける。

| 違い | 器の決まりにする形 |
|---|---|
| 主張の状態の語と条件 | 語は台帳のまま。状態ごとの条件を、憲法の記録が名前付きの検査で宣言する（「この状態なら、本人が原文を見た根拠が 1 つ以上」「独立した支える出典が 2 つ以上」など）。宣言しないメディアには効かない |
| 読みの段の語 | 語は台帳のまま。判断の「誰が・どう照らしたか」に対応づける。出典の性質（MMR の一次・二次、根拠の種類）は読みの深さではなく、出典と根拠の中身 |
| 弱い根拠の扱い | 上限つきにする種類を憲法の記録が宣言する。宣言が空なら上限なし（MMR） |
| 未確認・欠け・否定 | 結論（まだ・だめ）と理由で分ける。欠けの理由は中身 |
| 出所の持ち方 | どれも「行（か内側の単位）× 出典 × 場所 × 読み」に読み替える |
| 置き方 | 元のファイルのまま置く・ファイルの中の並び・内側の単位 |
| 出し口の数 | 種類の宣言が出し口を持ち、「出してよいか」の判断は出し口ごと・何としてか（事実として・留保として）ごと |
| 期限の意味 | 見直す日（中身）と、判断の「いつまで」。伏せ方は種類が宣言 |
| 図版の条件 | 図版の種類ごとの条件を宣言 |
| 出した URL の関門の厳しさ | 許す転送・二重の扱い・例外を台帳が宣言 |
| 言語・列の名前・改行の流儀 | 列の対応と、表のバイトを保つ書き方 |
| 枚の上限 | 種類ごとに宣言（既定は今の 64 KB） |

**固有として残す物**（器に入れず、各メディアの repo と道具に置く）:

- 分野の言葉の点検（評価語・表記の手引き・親の言葉）。
- 観測の列の中身。頁の型・デザイン。
- 各メディアの関門の中身（にがみラボの 32・中受の問の画面の柵）。**共通の点検が通っても、今ある関門は外さない。**
- 監査の回数や手順（何回読むか・だれが統合するか）。器が共通にするのは記録の索引だけ。
- こぴちゃの毎朝の商品の観測。
- キョンシーラボの物語と設定の資料（創作）。
- 関東の面をまとめる台本と、合わせた定員を 1 つの回に配らない、などの組み立ての知恵（器は内側の単位を指せるようにするまで）。

## 5. 器の形（案）

### 5.1 記録の置き方 — 元のファイルをそのまま置く

**第 3 版で変えた。** 第 2 版は、元のファイルの上に THTH の頭を付けた .md にしていた。これだと、YAML や JSON を書く今の道具が、頭の付いたファイルを扱えない。頭に書いていた物は番号と判断だけなので、**頭を付けず、元のファイルを元の名前・元のバイトのまま台帳のフォルダに置く。**

- **種類**は置き場から決まる（種類の宣言の「この道のファイルはこの種類」）。
- **番号**は種類の宣言の決まりで取る: 中の欄・表の列・ファイルの名前・鍵。
- **番号の表**（番号 → 今の場所）だけを台帳に持つ。ファイルの名前が変わっても番号を引き継ぐため。名前が変わり中身の指紋が同じ記録を見つけたら、引き継ぐかを聞く。
- **目録**（番号・種類・版・場所の一覧）は、宣言とファイルから作り直せる物で、正本ではない。頭と中身が離れてずれる、という第 1 版の心配は、ずれる相手を持たないことで消える。
- **今の店の台帳（頭つきの .md）は、「番号と判断が中に書いてある」1 つの形**として、1 字も直さずに読める。
- **今の道具は、元の形式のまま読み書きできる。** 変わるのは道だけ。中身を書けば版が変わり、その版についての判断は自動で効かなくなる。

記録の取り方は 3 つ。

| 取り方 | 例 | 番号 |
|---|---|---|
| 1 つのファイル = 1 つの記録 | こぴちゃの YAML と記事・関東の 1 校の JSON・店の .md | ファイルの名前か中の欄 |
| 1 つのファイルの中の並び = 記録の並び | CSV の行・MMR の `queue.json`・`content/index.yaml`・`ledger.json` の束と訂正 | 番号の列。無ければ鍵 |
| 記録の内側の単位 | 関東の年度ごとの回の行・照合台帳の行・記事の 1 文 | 下 |

**内側の単位の指し方**（上から順に、使える物を使う）:

1. 元に番号があれば、それ。
2. 種類の宣言の**鍵**（欄の組）。**時点（年度・`as_of`）がある物は、時点を鍵に入れる。** 値を直すこと（同じ記録の新しい版）と、次の時点の値が来ること（別の記録）を分けるため。鍵が台帳の中で 1 つに決まることを点検する。
3. 鍵で決まらない単位は、**鍵と中身の指紋**で指す。中身が同じ 2 つは区別しない（同じ中身への判断は、どちらにも当たる）。中身が変わった単位は別の指し先になり、前の判断は引き継がない。
4. **位置（何番め）では指さない。** 並べ替えや挿入で、前の確かめが別の値に移らないようにする。
5. 訂正の跡は、旧い指し先と新しい指し先を**名指しで**結ぶ（器が位置や似かたから推し量らない）。

こぴちゃの「記事と主張の結び」は文の指紋を、キョンシーの読者監査は行と文を使っている。中身の指紋で指すのは、すでにあるやり方を器に寄せた物。

- 大きさの上限は種類ごとに宣言する（既定は今の 64 KB。関東に 142 KB の枚がある）。表は別（叩き台: 20 万行・50 MB）。

### 5.2 憲法と、種類の宣言

- **憲法の記録**（台帳に 1 つ）と**種類の宣言**（種類ごと）を台帳に置く。THTH のコードに種類を書き足さない。
- **THTH が読む宣言は JSON にする**（標準の部品で入れ子まで読める）。各ラボの `lab.yaml` は元のまま記録として置き、憲法の記録が語の出どころとして指す。THTH が YAML を読まないと宣言が読めない、という形にしない。
- 憲法が持つ物: 主題・一文の立場（本人の判断が要る）・出し口・語（状態・読みの段・根拠の種類）と、その語がどの問いのどの結論にあたるか・**使えるかの決まり**（§5.3）・入れない物・**どの文書が決まりの正本か**。
- 種類の宣言が持つ物: 置き場・形式・上限・番号の取り方と、欄の役。

| 欄の役 | 意味 |
|---|---|
| 鍵・時点 | 内側の単位を指す（§5.1） |
| 指す欄 | 先の種類と、意味（§5.4） |
| 判断の欄 | 中に書いてある判断。どの問いの、どの語が、よい・だめ・まだ か |
| 進みの欄 | 仕事の進み。版に入れない |
| 読者に見える欄・出さない欄 | 点検と出口が見る |
| 分からないと書いてよい欄・欠けの理由の欄 | 推測で埋めない |

- **組合せの条件は、THTH が備える名前付きの検査を、台帳が名指しして引数を渡す。** 台帳に式や命令は書かせない。THTH は宣言に書かれた命令を実行しない。

| 検査 | 意味 | 出どころ |
|---|---|---|
| 重ならない | 欄の組が 1 つ | にがみラボ |
| この状態ならこの欄が要る | 確かめた、と書くなら出典が要る | にがみラボ・キョンシーの図版 |
| この組は禁じる | この種類の根拠は、この種類の主張を支えない | キョンシー |
| 違う番号の出典が N 個 | 支える根拠の出典の番号が N 種類以上（独立かは見ない） | 染めと化学 |
| この判断が要る | 本人が原文を見た判断が 1 つ以上 | 染めと化学・キョンシー |
| 種類ごとに要る欄が違う | 資料の図は利用の条件、再現図は根拠と生成の記録 | キョンシーの図版 |
| 語はこの中から | 宣言に無い語を断る | どのメディアも |

- **YAML の中を読む部品**: 自前の読み手はやめる（第 2 版の案を取り下げ）。YAML の中を見るのは、追加の部品を入れた機械だけにする（`pip install thth[yaml]`）。入れていない機械では、YAML の記録は「置く・戻す・版を取る」までで、「中は見ていない」と言う。店主の台帳（頭つきの .md）は今のとおり追加なしで動くので、「入れれば必ず動く」は変わらない。
  - 読み方は、型を決めつけない読み（全部を文字として読み、型は宣言で見る）にする。`no` が偽になる・日付が勝手に日付の型になる、を避ける。重なる鍵は断る。
  - **受け入れる書き方と断る書き方の例を、作る前に決める**（重なる鍵・引用符・長い文・別名の参照・複数の文書）。7 つのメディアの今のファイルを全部通すのは、そのあとの確かめ。
- 憲法と種類の宣言も記録なので、判断が付く。形を変えるのは意味を変えることなので、本人の判断は二段。
- **備え付けの種類**: 今の店の 7 つ・網の型の表・図版・憲法・対応・判断。

### 5.3 問いと判断

**問い**（器が意味を知るのは 5 つ。台帳は足せる）:

| 問い | 何について | よい・だめ・まだ の例 |
|---|---|---|
| 読みは合うか | 根拠・値と、その原典 | 別の者が照らして合った／原典に無かった／まだ書き手だけ |
| 言えるか | 主張（強さと範囲つき） | 支持・上限つき／否定に決着／推測・両論が未決着 |
| 調べはどうなったか | 問い・仮説 | 話があることは確かめた／反証で決着／まだ・調べたが届かなかった（調べ直す条件つき） |
| 出してよいか | 記録 × 出し口 × 何として（事実として・留保として） | 採る／採らない／まだ |
| 止めるか | 記録（の版） | 止める（すぐ効く。§7.2） |

- 店の事実と思いの問い「本人はそうだと言うか」は、「言えるか」に本人が答える形。今の 3 つの印がそのまま結論になる。
- 台帳が足す問いの例: 「この 2 つの出典は独立か」（染めと化学が要るなら）。

**判断の記録**が持つ物: 対象（番号と版。組でもよい。集まりは目録の指紋で名指す）・問い・結論・理由・誰が・**どう照らしたか**（書き手だけ・別の者・統合の者・説明を聞いた・原文を見た。語は台帳のまま）・照らした物の版（決まり・根拠・出典）・いつ・いつまで・未解決の物・元の記録（監査の結果など）への指し。

- **同じ者の判断は、別の者の判断に数えない**（書き手と照らした者が同じ）。
- **中に書いてある判断**（§0.2）は、宣言の「判断の欄」から読む。器は見つけたときの中身の指紋を控える。
- 食い違う根拠は記録。「だめ」は判断。支えと反証が両方あって決着していない主張は**まだ**（理由: 両論）。
- 9 つの軸の行き先:

| 第 2 版の軸 | 第 3 版 |
|---|---|
| 在るか・欠けの理由 | 中身（欠けの理由の欄） |
| 何を読んだか・誰が確かめたか | 判断の「どう照らしたか・誰が」 |
| 支えと反証の数 | 根拠の指す欄から数える |
| ほかの資料との整合 | 反する根拠（記録）と、決着の判断 |
| 調べの結果 | 問い「調べはどうなったか」の判断 |
| 言える範囲 | 主張の中身 |
| 置き換え | 指す欄「置き換える」 |
| 期限 | 中身（見直す日）と、判断の「いつまで」 |

**使えるか**は、問い合わせのたびに計算する。入力は、記録・判断・決まり（憲法）・判定の日時・**用途（どの出し口へ・何として）**。答えは「使える（言い方の上限と範囲つき）」か「使えない（理由と、調べ直す条件）」。

- 決まりの例（どれも各メディアの今の決まりを写す。段 0 で確かめる）:
  - 店の事実を投稿に、事実として: 本人の「よい」があり、古くない。
  - こぴちゃの主張を頁に、事実として: 「言えるか」がよいか上限つき・支える根拠に、別の者の「読みは合う」・出典の権利の条件・期限の内。
  - 染めと化学の `established`: 上に加えて、本人が原文を見た判断と、違う番号の出典 2 つ。
  - MMR の照合台帳の行を曲の頁に、**留保として**: 結論が「まだ」で、理由が注にしてよい種類のとき。
- 同じ記録が、事実としては使えず、留保としては使える。条件に届かない記録を一律に落とさない（落とすと、読者に要る留保まで消える）。
- **決まりから導く判断**: 「別の者の監査がよいなら、出してよい」のような持ち主の決め（キョンシー・MMR）は、憲法の決まりにする。1 件ずつ「出してよい」を書かせない。
- 店主の台帳の頭の `confirmed` は今の 3 語のまま。

**判断の置き場**は §9 の 5（推しは台帳の中）。

### 5.4 指す欄

- 記録は番号を指す。版は指さない（§0.4）。
- 器が意味を知る指し方は少しだけ。メディアごとの述語（こぴちゃの 22・MMR の役割）は中身で、器は先が在るかだけを見る。

| 意味 | 例 | 器が見ること |
|---|---|---|
| について | 頁の文 → 点、図版 → 点 | 先が在る。同じ物の記録を引ける |
| 支える・反する・限る | 根拠 → 主張 | 数える。使えるかの決まりが読む |
| 含む・親 | 産地 → 国、内側の単位 → 記録 | **輪を禁じる** |
| 置き換える | 新しい記録 → 旧い記録 | **輪を禁じる**。旧いほうを使おうとしたら知らせる |
| 同じ・関わる・上位と下位 | メディアをまたぐ対応（§7.3） | 関係の種類を持つ |
| から作った | 頁 → 主張、下書き → 記録、材料 → 記録 | 使った先を引ける |

- 輪を禁じるのは「含む・親・置き換える」だけ。主張どうしの往復は実際にあり、止めない。
- 先が無い・種類が違うは赤。先が退役か置き換え済みなら知らせる。
- 台帳をまたぐ指し方は `<台帳>:<番号>`。相手が手元に無ければ「確かめられない」。
- 外の同じ物（MusicBrainz の番号・DOI）は形だけ見る。

### 5.5 変えた跡

- 土台は git。`thth register diff <前>..<後>` が、足した・変わった・退役した・消えた記録を出す。番号が消えたら赤。
- **判断の記録は足していくだけ。** これが確かめの索引になる。判断から、対象の版と、元の記録（キョンシーの監査の結果・こぴちゃの中央の判断・MMR の束の台帳）へ戻れる。「監査済み」と引けるだけでなく、**その判断が今の版に効くか**が分かる。
- 訂正は、旧い指し先と新しい指し先を結ぶ記録（旧い文と新しい文・なぜ・誰が）。出さない欄は指紋だけ。
- 取り込みの跡（束ごとの sha256・集めた者・検めた者）。
- 元の記録は元のまま置く。索引だけにして元を捨てない。
- git でない置き場の台帳は、前の版を読めないと正直に言う（共通の行を版で指すには、前の版が取り出せることが要る。§7.2）。

### 5.6 出口

仕組みは 1 つ（記録を決まった場所へ書く）。**命令は 2 つに分ける**（取り違えると、出さない物が公開の場所へ出るため）。扱う集まりを 3 つに分けて書く。

| 集まり | 中身 | だれが作るか | 何と比べるか |
|---|---|---|---|
| 原物 | 取り込んだ全部（内部の層も） | `restore` | 元のファイルと、数・名前・sha256 が全部同じ |
| build の入力 | 出し口ごとに、サイトの build と道具が読むファイル | `export` | 出し口の種類による（下） |
| 配る成果物 | 読者に届く頁（`dist/`） | サイトの build（器は作らない） | 向きを替える前と後で sha256 |

**出し口の種類**（憲法が宣言）:

- **内の道具が読む出し口**（こぴちゃの仮説・問い・作り手の言説の表など）: 選ばずに書く。読者には届かない。
- **読者に出る出し口**（頁を作る入力）: **ここで、使えない記録を除く。** 「出してよいか」と「使えるか」を、出し口と何としてかごとに判定する。

**(1) 元どおり戻す** `thth register restore --to <フォルダ>`: 全部を元の場所・名前・バイトで書く。保存できたことの証明と、持ち出し。

**(2) 材料を出す** `thth register export --outlet <出し口> --to <フォルダ> --as-of <日時>`

- 判定の日時は入力。同じ台帳・同じ日時なら同じ出力。
- **材料の控え**: 書いたファイルの sha256 と、**判定に使った入力の版の組**（記録・判断・決まり・共通の行の版・判定の器の版・判定の日時）。この組があれば、同じ判定をやり直せる。
- **旧い材料が残っていたら止まる**（一覧に無いファイルが書き出し先にあれば赤。THTH は消さない）。
- 留保として出す記録は、留保の理由を付けて書く（何として出すかを、サイトの側が取り違えないように）。
- 差し込み（`{{番号.欄}}`）は使う種類だけ。
- `--check`: 書かずに比べる。

**基準**（こぴちゃの向き替え）: 「基準の commit の時点で、**読者に出る出し口の入力に在った版**は、出してよい」という、集まりへの 1 つの判断（本人・二段）。内部の層は読者の出し口に無いので、基準が付かない。基準で公開できる物が増えることはない。足した記録・変えた記録は基準の外で、決まりのとおり判断が要る。

**CI と承認**: 一本の道にする。判断が台帳の中にあれば（§9 の 5 の推し）、CI は repo だけで「使えるか」を計算し直し、置いてある材料がその結果と同じかを見る。判断の無い記録を材料に足しても、計算し直しで落ちる。判断を THTH の側だけに置く場合は、記録のある機械が作る封（鍵つき）を CI が確かめる形が要る（§9 の 5）。

**期限と伏せ方**:

- 見直す日（過ぎたら健康の候補に出すだけ）と、判断の「いつまで」（過ぎたら、その判断は効かない）を分ける。
- 今の柵の「見直し日を過ぎたら使えない」は、備え付けの店の種類ではそのまま残す。
- 伏せ方は種類が宣言する（記録ごと・欄だけ・表の中の行だけ）。
- **もう公開された静的な頁を、THTH は伏せられない。** 器の受け持ちは、判定の日時を入力に材料を作り直せること・健康に「期限が近い」「過ぎたのに最後の世代に載っている」を出すこと・期限を過ぎた材料が載った世代を配ろうとしたら関門が赤になること。作り直して配るのは各メディアの配信で、できなかったときに動くのはそのメディアのレーン。

**出した物の控えと関門** `thth register published`: 追記だけの控えと、build のあとの関門の仕組みを共通にする。厳しさ（許す転送・二重の扱い・例外）は台帳が宣言する。今ある各メディアの関門は、同じ入力で同じ結果になるのを確かめてから置き換える。

**読者に見える欄の点検**: 内部の番号・作業の呼び名らしい語を拾う。

### 5.7 書く口と、束の取り込み

- **元の形式の道具が、そのまま書ける**（§5.1）。器の書く口は、壊さないための口。
- `thth register row add|set …`: 表に 1 行足す・1 欄直す。レコードごとの元のバイトの範囲を覚え、変えるレコードだけを書き直す。触っていないレコードの sha256 を書く前後で比べ、違えば書かずに断る。
- `thth register merge <束>`: 判定が断りの行は入れない・重なる番号は入れない・集めた者と検めた者が同じなら入れない。**複数の表を 1 つのまとまりとして入れ替える。** 読み手には、入れ替えの前か後のどちらかが見え、半分ずつ混ざらない。途中で止まっても、続けるか戻すかが決まる。
- どの道で書いても、中身が変われば版が変わり、前の版への判断は効かなくなる。器は「古くなった判断」を健康に出す。
- THTH は集めない・検めない。
- 今の privacy の約束（THTH が台帳に書くのは頭の決まった欄と問いの記録だけ）を変える（§10）。

### 5.8 健康と見直し

`thth register health`（読むだけ）。

- 網: 線の薄い点・開いた問いの数と閉じ方。
- 判断: 古くなった判断・書き手だけの読み・同じ者の確かめ・「まだ」の理由ごとの数・調べ直す条件が満たされた問い・基準だけで通っている記録。
- 期限: 見直す日を過ぎた・「いつまで」が近い・過ぎたのに最後の世代に載っている。
- 決まりの食い違い: 憲法の決まりに 1 件も当たらない検査（台本に残った廃止の条件が見える）。
- 共通の行の採り入れ待ち（§7.2）。
- 候補を出すだけ。`--all --json` の 1 行を hub が束ねられる。

## 7. 1 人で複数のメディアを持つ場合

### 7.1 階層

```
持ち主（THTH の利用者）
├─ 共通の台帳（持ち主に 1 つ。無くてもよい）
├─ メディア A（THTH の project）── 台帳（1 つ以上）・口座
└─ メディア B ── 台帳・口座
```

- メディア = 今の THTH の project。持ち主 = THTH の利用者。新しい層は作らない。
- 1 つのメディアが台帳を 2 つ以上持ってよい（書く拍子と書く者が違うとき）。

### 7.2 共通の記録の持ち方（決め: 共通の台帳に置いて指す）

**正本は共通の台帳に 1 つ。各メディアは、採り入れた版で使う。**

- メディアの記録は `共通:<番号>` で指す（番号）。**どの版を使うかは、そのメディアの「採る」という判断**が持つ（§0 のとおり、版を縫い止めるのは判断）。
- 共通の記録を直しても、その瞬間に各メディアの材料は変わらない。健康に「採り入れ待ち」と出る。
- **まとめて採り入れる**: `thth register take 共通` が、進んだ共通の記録の差と、変わる頁を一度に見せ、1 回で採れる。メディアの数だけ同じ操作を繰り返さない。
- **止めるは、採り入れを待たない。** 共通の記録（の版）に「止める」の判断が付いたら、それを採っている全部のメディアの次の材料から外れる。もう出した先は「使った先」で知らせる。ふつうの直しと、急ぎの止めを混ぜない。
- **前の版を取り出せること**が条件。共通の台帳は git に置く。git でない置き場では、版で指せないと断る。
- 材料の控えには、採った共通の版に加えて、その記録が指す根拠・決まりの版も入る（入力の版の組）。行だけ止めても、指す先が動けば判定は再現できないため。
- 写しは作らない。各メディアが持つのは判断だけ。

| 共通に置く物 | 共通にする範囲 | 共通にしない範囲 |
|---|---|---|
| 運営者の情報 | 名前・窓口・表記 | 既定で出さない。家族の名前は入れない |
| 持ち主の思い | メディアをまたぐ編集の考え | メディアごとの思い |
| 口座の一覧 | 名前と向き先 | 鍵は入れない |
| 同じ物の対応 | §7.3 | 各メディアの点の中身 |
| 同じ出典 | **書誌だけ**（題・著者・年・DOI・URL・権利の条件） | 読んだ所・支える主張・読みの判断・そのメディアで使ってよいか |
| 書き方の決まり・図版 | 文・図と権利 | 採るかは各メディア |

- 今ある物は番号を変えない。別の番号で持つ同じ出典・同じ点は、対応の記録で結ぶ。新しく足す共通の物から共通の台帳に置く。

### 7.3 メディアどうしのつながり

- **対応の記録**: 各メディアでの番号と、関係の種類（同じ・関わる・上位と下位）。今の対応表の 31 行は、移すときに 1 行ずつ見直す（柿渋の行は「同じ」ではなく「関わる」）。
- **姉妹リンクは別の編集の判断。** 対応から候補を出し、載せる対を「出してよいか」の判断として持つ。
- 置き場と移す時期は、本線の条件のとおり（§9 の 2）。

### 7.4 管理の仕方

- **足す**: 台帳のフォルダを作り、`thth register add <台帳> --project <メディア>`。共通の台帳にメディアの記録を 1 つ。
- **退役**: メディアの記録を退役に。記録も出した URL も消さない。口座は止める。
- **鍵と口座**: 主体は持ち主に、口座はメディアに（今のはてなの作りを広げる向き）。鍵は台帳に入れない。
- **書ける範囲**: 器は手元のファイルに鍵を掛けられない。境は git の repo と入口の文書。器が受け持つのは、判断に「誰が」を残す・`diff` で変わった台帳と種類を出す・憲法と種類と共通の記録への本人の判断を二段にする、の 3 つ。
- **まとめて見る**: `health --all --json` がメディアごとに 1 行。
- **外す範囲は 3 つ。**

| 範囲 | 命令（案） | 消える物 | 残る物 |
|---|---|---|---|
| 口座 1 つ | 今の `thth leave <口座>` | その口座の鍵・状態・記録 | **台帳の控えと判断（最後の口座でも残す。§6）**・メディア・ほかの口座 |
| メディア 1 つ | `thth project leave <メディア>` | そのメディアの全部の口座・台帳の控え | 台帳のフォルダ（判断の記録が中にあれば、それも）・共通の台帳・ほかのメディア |
| 持ち主の全部 | `thth owner leave` | 全部の口座・台帳の控え・主体 | 台帳のフォルダ |

- **持ち出し**: 判断が台帳の中にあれば、台帳のフォルダがそのまま持ち出しになる。メディアを 1 つ持ち出すときは、採っている共通の記録の、その版を付ける（出さない欄は付けない）。

### 7.5 1 店・1 メディアで始めて、あとで増やす道

1. 最初は台帳 1 つ。今の 5.19.0 と同じ使い方。
2. 2 つめを足すとき、THTH が「両方に同じ物がありそう」を並べる。
3. 持ち主が選んだ物だけ共通の台帳へ移す。元の記録は番号を変えず、共通を指す記録になる。移した記録はもう一度判断する。
4. 移さなくても動く。

### 7.6 hub との線

- 器・点検・出口・健康の数は THTH。メディアの指揮は hub。
- 重なる 2 つ（メディアの一覧・対応表）は、本線の返事（§9 の 2）のとおり進める。
- 計測の数を記録へ返す口は、この書に入れない。

## 8. 移す物の目録と、移し方

### 8.1 目録（段 0 で確かめて確定する。下は今わかっている分）

2. **基準を決める**: こぴちゃの main のある commit。目録のファイルの sha256 の一覧を作る。

5. **基準を認める**（masaru の判断 1 回・二段）: 「基準の commit の時点で、読者に出る出し口の入力に在った版は、出してよい」。見せる物は基準の commit・出し口ごとの記録の数・目録の指紋。内部の層（仮説・作り手の言説・届かなかった問い）には付かない（§5.6）。

8. **柵を効かせていく**: 足した・変えた行は柵を通る。

写しは repo に commit する（build のたびに書き出す形にしない）。サイトの build が THTH に頼らず、戻すのが revert 1 つで済み、判断が台帳の中にあれば、CI が repo だけで判定をやり直せる（§5.6・§9 の 5）。

### 8.3 確かめ方

作った者と別の者が、命令を打ち直して確かめる。

1. **元どおり戻せる**（7 つ全部）: 取り込み → 戻す出口 → 目録のファイルと、数・名前・sha256 が全部同じ。
2. **build の入力が同じ**（こぴちゃ）: 出し口ごとに比べる。内の道具が読む出し口は、元と sha256 で全部同じ。読者に出る出し口は、基準の判断のもとで元と同じ（除く物があるメディアでは、「除いた物の一覧」と元との差がぴったり合う）。
3. **頁が同じ**（こぴちゃ）: 同じ commit・同じ `node_modules`・同じ日に、基準のまま build と、材料を差し替えて build。`dist/` の全ファイルの sha256 を比べる。先に同じ物を 2 回 build して、もともと揺れるファイルを名前と理由つきで書き出す。揺れが多すぎて比べにならなければ止まって知らせる。
4. **判定が同じ**（7 つ全部）: 段 0 で決めた「各メディアの大事な判定」の一覧について、器の答えが各メディアの**今の決まり**の答えと同じ。台本と同じ結果になるだけでは足りない（台本が古い所は、規則の正本に合わせる）。
5. **柵を壊して赤を見る**: 1 行を 1 字変える・記録を消す・表の 1 行を変える・期限を過ぎた日時で判定する・旧い材料を残す・**判断の無い記録を材料に手で足す**・並びを入れ替える（前の判断が別の値に移らない）、でそれぞれ赤か、正しく効かなくなる。

### 8.4 移す間、運用を止めない

- 正本はいつも 1 つ。影は片道。両方に書く期間を作らない。
- VM の毎日の観測は、移す物に触れない。向きを替える push は 04:00〜04:30 を避ける。
- 向きを替える commit は材料を変えない。戻し方は revert 1 つ。

## 11. 危ないこと

1. **サイトが壊れる・頁が変わる。** → 基準の判断。向きを替える commit は材料を変えない。`dist` の sha256 を前後で比べる。
2. **出所が落ちる。** → 元のファイルを元のバイトのまま置く。書く口はレコードのバイトを保つ。
3. **二重の正本になる。** → 影は片道。写しは CI が判定からやり直して比べる。共通の記録は判断で版を持ち、写しを持たない。
4. **早くそろえて、各メディアの意味が消える。** → 語は台帳のまま。軸を保存しない。段 0 で決まりの正本を確かめる。
5. **前の確かめが、別の値に移る。** 並べ替え・挿入・ファイルの名前の変更で起こる。→ 位置で指さない。鍵で決まらなければ鍵と中身の指紋。訂正は名指しで結ぶ。段 1 で最初に確かめる。
6. **訂正と、次の時点の値を取り違える。** → 時点を鍵に入れる。
7. **「だめ」と「まだ」を取り違える。** 食い違う根拠があるだけで否定にする・届かなかった問いを否定にする。→ だめは判断だけ。まだには理由と調べ直す条件。
8. **条件に届かない記録を一律に落として、読者に要る留保が消える。** → 用途を「事実として・留保として」に分ける。
9. **基準で、内部の層まで公開できるようになる。** → 基準は読者の出し口の入力に在った版だけ。
10. **判断を偽れる・よそから来た台帳の判断が効く。** → §9 の 5。うっかりと、受け入れていない判断は効かない。わざとは防げないと正直に書く。
11. **判断の重みが薄まる。** 基準・別の者の確かめで、masaru が見ていない記録が材料になる。→ 判断に、誰が・どう照らしたかを残す。害の大きい種類は台帳が決まりを選ぶ。
12. **憲法と種類の宣言が攻め口になる。** → 命令を実行しない。検査は THTH が備えた物だけ。道の宣言は台帳と書き出し先の中だけ。
13. **YAML を読み違える。** → 型を決めつけない読み・重なる鍵を断る・受け入れる例と断る例を先に決める。部品を入れていない機械では「中は見ていない」と言う。
14. **古い材料が読まれ続ける。** → 一覧に無い旧い材料があれば止まる。
15. **期限を過ぎた頁が出たままになる。** → 健康と関門で知らせる。作り直すのはそのメディアの配信。
16. **共通の記録の採り入れ忘れ。急ぎの止めが待たされる。** → 採り入れ待ちを健康に。止めるは待たない。
17. **器が重くなり、店主の台帳が難しくなる。** → 宣言の無い台帳は今のまま動く。追加の部品も要らない。
18. **1 回の release が大きい。** → 段 1〜3 で芯を先に固める。それでも重ければ §9 の 4。
19. **取り込みの途中で止まって、半分ずつ混ざる。** → まとめて入れ替える。止める試験をする。
20. **台本を置き換える途中で、結果が食い違う。** → 同じ入力で比べ、「ずれ」か「決め」かをレーンと分ける。今ある関門は外さない。
21. **privacy の約束と `leave` の動きを変える。** → 同じ版で privacy を直し、Worker を先に出す。リリースノートに書く。
22. **消す求めに応えられない。** 記録を消さず、版と判断を足していく作りは、持ち主が本当に消したい物（運営者の住所を書いてしまった、など）と合わない。git の履歴にも残る。→ この書では解いていない。台帳は持ち主の物なので、消すのは持ち主の git の操作になる。器の側で要る口（その番号を「消した」と記して、指す先の切れを赤にしない）は §12。
23. **hub との線・VM の push・VM の仕事の読み口とぶつかる。** → 本線の条件のとおり。向きを替える push は時刻を避ける。MMR の `queue.json` は相談のあと。
24. **ほかの人の投稿や個人の情報が台帳に入る。** → `data/sns/` は移さない。
25. **build の揺れで「同じ」が言えない。** → 先に同じ物を 2 回 build して揺れを知る。

2. **内側の単位を「鍵、だめなら鍵と中身の指紋」で指し、時点を鍵に入れる、は実物で回るか。**
   - 関東の重なる 37 行・MMR の照合台帳の行・こぴちゃの記事の文で、判断が誤って引き継がれる例、要るのに失われる例。
   - 訂正のたびに旧い指し先と新しい指し先を名指しで結ぶ手間は、各メディアの今の直し方（道具が上書きする）に乗るか。乗らないなら、どこまで器が推し量ってよいか。
   - 「値の訂正」と「次の時点の値」を、鍵に時点を入れるだけで分けきれるか（年度をまたいで同じ値が続く・時点の欄が無い値）。

3. **判断の記録を台帳の中に置く案（§9 の 5）で、何が守れなくなるか。**
   - 今の「台帳の側からは偽れない」を手放す代償を、実際の事故の形で（どの操作で、何が出てしまうか）。
   - 「よそで付いた判断は、受け入れるまで効かない」は、CI（受け入れの印を持たない機械）と両立するか。CI は repo の判断をそのまま信じる、でよいか。
   - 鍵つきの封を足す案と比べて、どちらが少ない仕組みで、公開の前に「判断の無い世代」を止められるか。
