# 調べ: `--json` と MCP の答えの欄の名前（2026-10-15）

## 0. この調べについて

- 範囲: 手元の命令の `--json`（posts・replies・measured・mentions・topics --search・where・thread・who・unanswered・queue・schedule・board・account・doctor・analytics-report・observe／morning・list show・community search・trends・counts・send・retract・like／repost）、`thth/server_reads.py`、`thth/server_writes.py`、`mcp/server.py`。
- 確かめた深さ: **コードを読んだだけ。動かしていない。** 行番号は 2026-10-15 の main（589b438）のもの。ファイルの変更・commit はしていない。
- MCP は、手元の道では CLI の `--json` をそのまま返す（`mcp/server.py:1333-1573`）。サーバの道の読む口は CLI の関数を呼ぶだけ（`server_reads.py:1-18`）。だから答えの欄は **CLI と同じ名前の問題を引き継ぐ**。MCP 独自の違いは「断りの書き方」（§4）と、同じ名前で形が違う `queue`・`schedule`（§2）だけ。
- 前提: 3.18.0 で一度「足すだけ」の揃えをしている（`id`→`post_id`、`message_id`→`post_id`、`reply_id`。古い名前は非推奨で残し、4.0 で外す候補。`tests/test_v3180_json_names.py`、`docs/リリースノート_3.18.0_2026-10-12.md:11`）。以下は、その後に残ったものと、3.18.0 が手を付けていない所。

## 3. 時刻の書き方の違い

| 書き方 | 例 | どこ |
|---|---|---|
| JST の ISO（`+09:00`・秒まで）。`jst.iso()` | `2026-10-15T09:00:00+09:00` | `generated_at`／`fetched_at`／`updated`／`window.since`／`window.until`／`last_fetch_at`／`last_reply_collected_at`／`collection_stale_since`（unanswered）／台帳の `collected_at`／`observed_at`／`retracted_at`（サーバ）／`next_at`（collect_too_soon、`server_reads.py:230`） |

## 5. そろえる案

方針の前提: ① 3.18.0 と同じ「**足して残す→非推奨→4.0 で外す**」を守る（hub の observe・各レーン・MCP を壊さない）。② **台帳（ndjson）の鍵は変えない**。変えるのは答えの層だけ。③ 媒体の時刻の綴りをそろえない決まり（`base.py`）は、変えるなら別に裁定が要る。

## 6. 壊れる範囲が大きい上位 5 組

1. **時刻（§1-4・§3）**: 鍵が `timestamp`／`posted_at`／`at`／`sent_at` の 4 つ以上、綴りも 6 通り。台帳・`since`・`continue_from`・after／analytics が読む。直すなら `timestamp_jst` を足す。
2. **断りの形（§4）**: 8 通り。`error` を日本語の文として読む手順が最も多い。
3. **投稿 id の意味（§1-1・§2）**: `post_id` が 4 つの意味。SKILL.md・llms.txt・各レーンの手順が前提にしている。
4. **件数（§1-6）**: `n`／`count`／`counts`／`n_total`／`denominator`／`*_count`。鍵の数が最も多く、`n` を読む手順が多い。
5. **返信まわり（§1-8・§1-9・§2 の `replies`）**: `replies` が 5 つの意味、`replied` と `already_replied` の形が 3 通り。SKILL.md が `replied` の三値を使い分けるよう書いている。

## 7. 確かめきれていないこと

- 動かして出力を取ってはいない。鍵は生成の側のコードから拾った。実際の答えに入る鍵（特に mentions の生の行をそのまま写す部分）は、媒体ごとに増減する。
- `morning` の未回答の項目の `permalink`（`morning.py:328`）は、元の unanswered の行に `permalink` が無い（`unanswered.py:192-195`）ので **常に null** になっている疑い。読んだだけで、動かして確かめていない。
- MCP のサーバの道の答えのうち、plaza・map・report・admin 系は今回の範囲に入れていない（`plaza_*`・`admin_*` は別の鍵の体系）。
- 利用者側の壊れる見込みは、skills/thth/SKILL.md・llms.txt・tests（約 450 ファイル）の書き方からの推定で、hub や各レーンの実際の手順は見ていない。
