# リリースノート 3.20.0（X の本文を X の数え方で数えて、超えたら止める）

2026-10-15。

## 変えたこと

- X の本文の長さを、X の公式の数え方（twitter-text v3 の「重み付きの長さ」）で数えるようにした。
  - 日本語・全角などは 1 字で 2、半角の英数字・記号などは 1（U+0000–U+10FF・U+2000–U+200D・U+2010–U+201F・U+2032–U+2037 が 1、ほかは 2）。
  - URL は長さによらず 23。`https://` の無い `thth.me` のような裸のドメインも URL として 23 と数える（X と同じ）。
  - 絵文字は、家族の絵文字・肌色・異体字セレクタの付いたものも含めて、並び 1 つで 2。
  - 数える前に NFC に正規化する。上限は 280。
- 280 を超えた X の本文は、lint・approve・send（dry-run を含む）・スレッド（束）・予約の選び出し（select）で**止める**。警告ではない。表示は「284/280（X の重み付き）」の形。
- `send` と `approve` の一段目の行は「文字数: 284/280（x・X の重み付き）」になった。
- 2.14 からの「暫定・重み付け未確認」の注記と、lint が毎回添えていた `warning: x_length_weighting_unverified` をやめた。
- kopicha-x と asmon-kanto-x の両方に効く（媒体が X のアカウントすべて）。

## きっかけ

10/15、kopicha-x の原稿を `send` が「文字数: 160/280（x・codepoint（暫定・重み付け未確認））」と出して通したが、X のアプリに貼ると 284/280 で、全角 2 字ほど超えていた。THTH は字の数（コードポイント）で数えていて、日本語を X の 2 倍で数えていなかった。masaru「THTH にその機能があるべきでは？」。

## 数え方の出典

- twitter/twitter-text（コミット 30e2430d90cff3b46393ea54caf511441983c260）の `config/v3.json`（280・100・200・23 と 1 になる範囲）、`js/src/parseTweet.js`（数え方の手順）、`js/src/extractUrlsWithIndices.js` と `js/src/regexp/`（URL の見つけ方と TLD の一覧）。
- 絵文字の見分け方は、twitter-text が使っている twitter/twemoji-parser（コミット f8312f35fdee0e79874bb50213c4544c14fa759b・v14.0.0）の正規表現。
- 依存は足していない。TLD の一覧と絵文字の正規表現は `tools/generate_x_text.py` が上の固定した版のファイル（sha256 を照合）から `thth/adapters/_x_text_data.py` に書き出す。数える本体は `thth/adapters/x_text.py`。

## 確かめたこと

- twitter-text の conformance から、`validate.yml` の v3 の重み付きの長さの例 22 件と方向制御文字の例 2 件、`extract.yml` の URL の抜き出しの例 108 件を全部 `tests/fixtures/twitter_text_v3_weighted.json` に写し、全件一致（`tests/test_v3200_x_weighted_length.py`）。
- 数え方を元のコードポイントに戻すと、新しい試験が 8 件赤になることを見た。

## 合わせきれていない所

- X のサーバが今どの版の TLD 一覧と絵文字表で数えているかは公開されていない。ここは固定した版（TLD は 2021-10 の twitter-text、絵文字は Unicode 14 までの twemoji-parser 14.0.0）に合わせている。それより新しい TLD の裸のドメインや、新しい絵文字の並びは、X と少しずれることがある。
- 投票の選択肢（25 字）は、これまでどおりコードポイントで数える暫定のまま（X がそこをどう数えるかは確かめていない）。
- アカウントの台帳の `char_limit` で X の上限を上書きした場合は、その数を重み付きの上限として使う。
