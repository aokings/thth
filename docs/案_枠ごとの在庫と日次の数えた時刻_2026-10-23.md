# 案: 1 日の本数の在庫切れと、日ごとの数の「数えた時刻」（2026-10-23・THTH開発 第9）

元: メディアハブ本線 第9 の依頼（masaru 10/23「頼みます」）。関東の Threads（asmon-kanto-threads）は 10/21 から朝・夜の枠の原稿が尽き、1 日 4〜5 本が 2 本に減った。昼・夕の原稿は 10/29 まであるので、4.5.2 の `schedule_low`（口座の最後の予約が 48 時間より手前か）は鳴らない。

## 1. 1 日の本数の在庫切れを知らせる

### 関東の現物（VM で 10/23 08:4x に読んだ）

- 公開した根の投稿（返信は除く）: 10/14〜10/20 は 1 日 4〜5 本（8 時・12:30・17:30・19 時・21 時）。10/21・10/22 は 2 本（12:30・17:30）。
- 承認済みの予約: 10/23〜10/29 は毎日 12:30・17:30 の 2 本（10/25 だけ 20 時を足して 3 本）。
- 枠の時刻は窓口がよく動かしている（10/9〜12 は 7・10・15 時があり、10/14 から 8・19 時に替わった）。

### 推し: 「1 日の本数」で鳴らし、空いた時間は説明に添える

新しい続いている状態 `schedule_thin` を `thth events` に足す（`schedule_low` と並べる）。

- 物差し: 直近 7 日に公開した根の投稿の 1 日あたりの本数（平均）。
- 見る日: 今日・明日・明後日。今日は「今日もう出た本数＋今日の残りの承認済み予約」、明日・明後日は承認済み予約の本数。
- 鳴る条件: どれかの日が物差しの 6 割を切る（物差しが 2 本以上の口座だけ）。
- 説明の 1 行: 「10/24 は 2 本（直近 7 日は 1 日 3.9 本）。空いた時間: 8 時台・19 時台・21 時台」。空いた時間は、直近 7 日に 3 日以上使った時間帯のうち、その日に予約が無いもの。
- 窓口がわざと本数を減らしたときは、`thth account set <口座> stock_daily_min <本数>` で物差しを決め打ちにできる（決め打ちがあれば平均を使わない）。

関東に当てると: 10/16〜22 の平均は 3.9 本、6 割は 2.3 本。10/23〜25 の予約は 2・2・3 本で、10/23・10/24 で鳴る。この形が前からあれば、10/19 の時点で 10/21 の予約が 2 本しか無かったなら、そこで鳴っていた（10/19 の予約の様子は確かめていない）。

### 退けた案

- **枠（時間帯）ごとに鳴らす**: 窓口が時刻を動かすたびに「8 時の枠が空いた」と鳴り続ける。時間帯は説明に添えるだけにする。
- **在庫の時間（48 時間）だけを延ばす**: 本数が減ったことは時間では見えない（関東は 10/29 まで届いている）。

### 前提が変わったら

- 窓口が本数を週ごとに大きく変える運用になるなら、7 日の平均は遅れて追いつく（わざと減らしたあと、決め打ちが無いと 3〜4 日鳴り続ける）。そのときは決め打ちを既定にするか、平均を 3 日に縮める。代償は、急に減ったのを見逃しやすくなること。

### 見込み

半日ほど。`events_cli._stock_events` の隣に 1 つ足し、柵（試験）と全件・監査を通す。版は 4.5.x の次の番号。出すのは masaru の「出して」のあと。

## 2. 日ごとの数に「いつ数えたか」を残す

### 分かったこと

- **数えた時刻は台帳にもう書いてある**（`collect.py` の `_collect_account_daily`・行の `collected_at`）。`thth measured` が読むときに落としていた。直すのは表示と JSON に出すだけ。
- 日ごとの数は「閉じた前日」を、翌日 0 時台の最初の採取で 1 回だけ取り、取り直さない。関東の 10/22 は 10/23 00:03:12 に数えた。
- **10/22 の 1,153 は数え終わる前の値ではなかった**: 10/23 08:4x に同じ日を読むだけで取り直すと（台帳には書かずに）、10/20 = 12,387（台帳は 12,384）、10/21 = 14,451（14,450）、10/22 = 1,153（1,153）。0 時台に取った値と、朝に取り直した値はほぼ同じ。1,153 は Meta がそう返している数。

### 推し

- `thth measured` の日ごとの行に `collected_at` を出す（人向けの表示にも「数えた 10/23 00:03」）。小さいので 1 の版に入れる。
- 取り直し（翌々日にもう一度取る）は今は入れない。上のとおり 0 時台の値と朝の値の差は 1〜3 だった。差が大きい日が見つかったら改めて。

### 見込み

1 時間ほど（1 の版に入れる）。
