# 依頼: こぴちゃの向き替え（台帳の器 段 10 の 10-5）

- 頼む先: こぴちゃのレーン（こぴちゃ 第11）。本線（メディアハブ本線 第13）を通して出す。
- 頼む者: THTH開発 第19
- 日付: 2026-11-15
- 前提: THTH 5.21.0 が出ている（11/15 06 時台。PyPI の 5.21.0・MCP registry の latest 5.21.0・VM `thth 5.21.0 (ec06e3d)` を確かめた）。器の直しの中身は `docs/リリースノート_5.21.0_2026-11-14.md`。

## 目的

こぴちゃの記事と知識の表（`src/content/` と `data/knowledge/`）の正本を、repo の中の台帳のフォルダに移す。repo の根の 2 つは、受け入れ（`thth register accept`）が書き出す写しにする。そのあと、普段の訂正 1 件を器の道で配信まで通し、手間を今の道と比べる（10-6・判定）。

段 10 の判定は 1 点: **普段の訂正 1 件が、前より短い手間で配信まで通ったか**。

## できあがりの条件

1. **台帳を repo の中に置く。** フォルダ名はレーンで決めてよい（試しでは `register/`）。中身は、今の `src/content/` と `data/knowledge/` のうち、宣言の置き場（`place`）に当たるファイルと、`.thth/` の宣言。宣言は THTH の `tools/register_decls/kopicha/` を写して使う（`kinds/`・`outlets.json`・`constitution.json`）。写したあとは、こぴちゃの repo の物が正本になる。
   - 台帳は、repo の外の写しから書き戻して作らない。repo の今の commit から作る（10-1 で、外の写しから材料を戻すと、写したあとのこぴちゃの変更を黙って消すと分かった）。
2. **出し口は 2 つ、どちらも書き出し先は repo の根（`dest: "."`）。** `site`（読者）と、`tools`（内・`dest_shared_with: ["site"]`）。この形は 5.21.0 の器で通ることを確かめてある（`85c015012` の写しで、両方とも確かめが緑・古い材料 0・repo の根は元と 1 バイトも同じ）。
3. **基準を、向き替えの commit で取り直す。** 基準の 1 文は masaru が認めた（`docs/基準_台帳の器_段10_こぴちゃ_2026-11-14.md`）。向き替えの commit で同じ台本を回し、**その commit・数・指紋を判断の記録と封に書く**。数が大きく変わっていたら（記録が 1 割より多く増減する・違う枚が出る）、封の前に止めて本線へ出す。
4. **最初の封のあと、repo の根が元と 1 バイトも違わない**こと（`diff -rq` で違うのは台帳のフォルダだけ）。違えば止めて本線へ。
5. **入口の文書に正本を書く。** `src/content/` と `data/knowledge/` は書き出した写しで、直すのは台帳の中、と 1 行。
6. **CI に確かめを足す。** thth 5.21.0 を入れて `thth register verify` と `thth register export --check` を回し、赤なら止める。封の確かめに使う公開鍵は CI の変数に置く。**repo の設定なので、masaru の手か承認で置く**（秘密の鍵は CI にも repo にも置かない）。
7. **書く道具の書き先を台帳に替える。** 今 `src/content/` と `data/knowledge/` に直に書いている台本・道具は、台帳の中に書くか `thth register row set` などを使う。直に根へ書くと、次の確かめで赤になる（それが柵）。
   - 11/15 にこぴちゃが空の rights を 34 件埋めた（`caaeed20b`・hub #7845）。THTH の宣言の見込み（`media.json` の `k4_8_warn` 79）は古い commit の数で、今は 0 が正しい。警告の数が減るのは 1 割の決まりで止める理由にしない（記録の増減ではない）。
8. **判断と封は、こぴちゃのレーンの LLM がする**（本線と合意済み・11/14）。直した者と検める者を分けるかは、こぴちゃの今の V・T（別の係の検収）の型に合わせる。基準（条件 3）だけは masaru が認めた 1 文に従う。

## 10-6（判定）でしてほしいこと

向き替えのあと、普段の訂正を 1 件、実際の道具で配信まで通す。物差しは 10-2 と同じ（`docs/受け入れ_台帳の器_段10_2026-11-14.md` の表）:
- 人が読む・決める・打つ回数、待ち、頁から外れた物、確かめの深さ。
- 下見（10-2）では、器で増える命令は 9（確かめ 3・判断 2・受け入れ 4）、LLM が打って約 35 秒、人の手間は 0 の見込み。

結果は「通った／通らない」と数を、本線と THTH開発へ。通らなければ、どこで手間が増えたかを書く。

## 止まる所（直す前に本線へ）

- 器が断る（`register_*` の断り）・確かめが赤のまま理由が分からない → 器の不具合かもしれない。直さずに `thth report file` か hub msg で THTH開発へ。
- 条件 3 の数が 1 割より多く動く、条件 4 で根が元と違う。
- 途中で穴が出ても、直しを重ねて段 10 を延ばさない（本線の決まり）。
