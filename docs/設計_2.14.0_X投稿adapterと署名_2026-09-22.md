# 設計 2.14.0: X の投稿 adapter と release の署名

2026-09-22。masaru の裁定「2.14 進めましょう」（3.0 の前に X を生やす）。実装は Claude 内の writer（Opus 5）・独立監査は別の Opus 5・判断は Fable。一次資料は本書 §7 に固定（Claude が 2026-09-22 09:50 JST に docs.x.com から取得した抜粋。ページに更新日表示なし）。

## 0. 要件

- **投稿できるものは全部 thth で**（2.13 §0 と同じ規律を X に）: 本文・返信・画像（4 枚まで）・GIF（1）・動画（1）・投票・返信制限・alt。引用は **X の自己サーブ tier では不可**（公式: "Quote-posting … requires an Enterprise plan"）なので `unsupported: provider_tier_enterprise_only` として表に載せる（「API に無い」とは書かない）。
- **費用の規律**（2.12 の予算口の延長）: X の書込みは tier の月間上限（Free／Basic／Pro で異なる・Developer Portal の表示が根拠）に従う。**thth は自分の投稿数を数え、月の上限に達したら `cannot_say: post_budget_exhausted` で止める**。上限は `thth admin budget x-posts --monthly <本数> --by masaru`（管理者 scope・変更ログ・既定 0＝投稿しない）。読取予算（USD）は 2.12 のまま別枠。
- **秘密は人も LLM も触らない**: 2.11 の `thth auth`（PKCE・預かり所）をそのまま。scope に `media.write` を足すので **client の世代**（C8 と同じ・scope 集合の hash 付きファイル名）で旧 client を保全し、旧 pending は `auth_restart_required`。
- **release の git 署名**（2.11 §9 の裁定・SSH 署名）: `release` を進める commit を配布担当（Claude の Mac）の SSH 鍵で署名し、VM の self-update は `THTH_REQUIRE_SIGNED_RELEASE=1` のとき署名を検証する（`selfupdate.verify_release_signature` は 2.10 で骨がある）。board の「署名: 未確認」を「署名: 確認済み（鍵 ID）」に。

## 1. 認可（2.11 の骨・scope の追加）

- `auth_x.SCOPES` = `tweet.read tweet.write users.read offline.access` **＋ `media.write`**（公式: `/2/media/metadata` は `media.write`。upload も同じ scope と推定・実測で確定）。
- client ファイル: `x.<origin sha>.<必要 scope 集合の sha 先頭 8>.env`（C8 の Mastodon と同じ規則・`authclients.path_for` を媒体非依存に）。旧無印は read-only。
- refresh: `offline.access` の refresh token を `maintain` が回す（2.11 で実装済みか確認・無ければここで）。
- App の登録: masaru が Developer Portal で App を作り（Free tier で可・callback `https://thth.me/callback/`・User authentication settings で Read and write・Type: Web App）、`thth app set x --by masaru` で client id と secret を **tty から**入れる（値は chat に出さない）。

## 2. 投稿（`thth/adapters/x.py`・`x_media.py`）

| 操作 | endpoint | 備考 |
|---|---|---|
| 投稿 | `POST /2/tweets` `{text, reply:{in_reply_to_tweet_id}, poll:{options, duration_minutes}, media:{media_ids, tagged_user_ids}, reply_settings}` | `text` は media があれば空可。`reply_settings ∈ following/mentionedUsers/subscribers/verified`。`quote_tweet_id` は送らない（tier）。`for_super_followers_only`・`geo`・`card_uri`・`direct_message_deep_link` はこの版では未対応（理由付き） |
| 削除 | `DELETE /2/tweets/:id` | `retract` に対応（user 50/15 min） |
| 本人 | `GET /2/users/me` | `whoami`・auth 後の本人照合（2.11 済み） |
| upload | `POST /2/media/upload/initialize {media_type, total_bytes, media_category}` → `POST /2/media/upload/{id}/append`（`segment_index`・5 MB 以下の chunk・multipart）→ `POST /2/media/upload/{id}/finalize` → `processing_info` があれば `GET /2/media/upload?command=STATUS&media_id=` を `check_after_secs` で poll（pending→in_progress→succeeded/failed） | category `tweet_image`（5 MB）・`tweet_gif`（15 MB）・`tweet_video`（既定 20 分／8 GB・Premium 125 分／16 GB） |
| alt | `POST /2/media/metadata {id, alt_text:{text ≤1000}}` | 画像・GIF に必須（thth の規律）。動画の alt は API 上あるか実測で確定 |

- **digest**: 2.13 の規律どおり（本文・添付の元 sha／公開 sha・alt・順序・poll・reply_settings を canonical に）。
- **bytes**: 2.13 の sanitize（画像は Orientation と ICC 以外の metadata を落とす・動画は bytes 不変で位置 metadata は拒否）。
- **上限**: 公式値を一次に（画像 5,000,000？ "5 MB" の単位は未定義 → 暫定 SI 5,000,000・GIF 15,000,000・動画は既定 8 GB のうち thth の transport 上限 1,000,000,000）。本文 280 は公式ページに明記が無い（"Text Length Rule: Not specified"）→ 既存の `x` 文字数規則（thth に既にある 280 の数え方があれば踏襲・無ければ暫定 280 code point・weighted 計数は実測項目）。
- **durable intent**・**unknown は再 POST しない**・**held**（upload 後の承認変更）は 2.13 の Threads/Bluesky と同じ骨（`media_delivery` に X を足す）。
- **rate limit**（公式・tier 差なし表記）: `POST /2/tweets` user 100/15 min・app 10,000/24 h、`media/upload` user 500/15 min、`metadata` 500/15 min、`DELETE` 50/15 min、`users/me` 75/15 min。429 は `retry-after`／`x-rate-limit-reset` を静的理由 `provider_rate_limited` で保持し待たない（次の run で）。
- **月間投稿数**: `state/<account>/x-posts-<YYYY-MM>.json`（UTC 月）に成功した投稿と結果不明の投稿を数え（両方が枠を消費）、`budget x-posts` の上限で止める（上限は account ごと・App 単位の tier 上限は運用文書）。tier の実上限は Developer Portal の数字を masaru が入れる（既定 0）。

## 3. 読む口（この版の範囲）

- `posts`（自分の投稿一覧）・`retract`・`whoami`。`where`／`mentions`／`insights` は **読取予算（USD）が 0 の既定では動かない**（2.12 の規律）。実装は次版（X の読取は従量なので、予算を masaru が入れてから）。

## 4. 網羅表（`media_capabilities.py` に `x` を追加）

image supported（4）・gif supported（1）・video supported（1）・poll supported（2〜4・5〜10080 分）・reply supported・reply_settings supported・alt supported・quote `unsupported: provider_tier_enterprise_only`・link `body_only`・thumbnail/captions `unsupported: provider_format`・tags `body_only`・visibility_private `unsupported: provider_format`・aac_adts/asf は他媒体と同じ・offset_styling `unsupported: provider_format`。

## 5. 署名

- 配布担当の Mac: `git config gpg.format ssh`・`user.signingkey ~/.ssh/thth-release.pub`・`commit.gpgsign` は **release へ push する commit だけ**（`git commit -S` を配布手順に）。allowed_signers を VM の `~/.config/thth/allowed_signers`（600）に置き、`selfupdate.verify_release_signature` が `git verify-commit` 相当（`gpg.ssh.allowedSignersFile`）で確かめる。
- `THTH_REQUIRE_SIGNED_RELEASE=1` を VM の timer の環境に入れる（配布担当）。無署名の release は **VM が取り込まず** board に `behind_release: signature_missing`。既定は検証しない（2.10 の設計どおり・入れるのは配布担当）。
- 鍵の生成は masaru の Mac で `ssh-keygen -t ed25519 -f ~/.ssh/thth-release`（秘密鍵は Mac から出ない）。

## 7. 一次資料（抜粋・取得 2026-09-22）

- `POST /2/tweets`（https://docs.x.com/x-api/posts/creation-of-a-post）: scopes `tweet.write users.read tweet.read`。`text` "Required unless media is provided"。`reply.in_reply_to_tweet_id` `^[0-9]{1,19}$`。`quote_tweet_id` "requires an Enterprise plan … not available on self-serve"。`poll.options` 2–4 choices 1–25 chars、`poll.duration_minutes` 5–10080。`media.media_ids` 1–4 "up to 4 photos, 1 animated GIF, or 1 video"。`media.tagged_user_ids` ≤10。`reply_settings` enum `following, mentionedUsers, subscribers, verified`。動画 既定 20 min/8 GB・Premium 125 min/16 GB。
- chunked upload（https://docs.x.com/x-api/media/quickstart/media-upload-chunked）: `POST /2/media/upload/initialize`・`/2/media/upload/{id}/append`（`segment_index`・`media`）・`/finalize`・`GET /2/media/upload?command=STATUS&media_id=`。chunk "at or below 5 MB"（server max 8 MB）。`tweet_image` 5 MB・`tweet_gif` 15 MB・`tweet_video` 20 min/8 GB（Premium 125 min/16 GB）・`subtitles` 1 MB。STATUS: pending→in_progress→succeeded/failed・`check_after_secs`。
- metadata（https://docs.x.com/x-api/media/metadata-create）: `POST /2/media/metadata` scope `media.write`。`id` `^[0-9]{1,19}$`、`alt_text.text` ≤1000。
- rate limits（https://docs.x.com/x-api/fundamentals/rate-limits）: `POST /2/tweets` app 10,000/24 h・user 100/15 min。`POST /2/media/upload` app 50,000/24 h・user 500/15 min。`POST /2/media/metadata` 同。`DELETE /2/tweets/:id` user 50/15 min。`GET /2/users/me` user 75/15 min。tier 別の月間上限はこのページに無い（Developer Portal の表示が根拠）。

## 8. masaru の裁定（はい／いいえ）

1. 引用は tier の理由で未対応（表に理由付き）。
2. 月間投稿数の上限は管理者が入れる・既定 0（入れるまで X は投稿しない）。
3. 読む口（where／mentions／insights）は次版（読取予算が 0 の間は動かない）。
4. release の署名は「配布担当の Mac の SSH 鍵・VM は env で検証を有効化」。
5. X App は masaru が Developer Portal で作り、`thth app set x --by masaru` で tty から入れる（値は chat に出さない）。
