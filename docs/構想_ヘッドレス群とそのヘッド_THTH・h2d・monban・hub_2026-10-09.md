# 構想: ヘッドレス群とそのヘッド（THTH・h2d・monban・hub）— 2026-10-09

書いた人: THTH開発（代行・DustyCave・Claude Opus 5.5）。masaru との 10/9 の会話をまとめたもの。headlesson（ヘッドレスアプリの専門メディア兼カタログ）に渡す。

**この書の位置づけ**: 構想と事実のまとめ。**作ることはまだ何も決めていない**（§8）。事実には出典（各 repo のファイル）を付け、推測・提案はそう書く。

## 0. 一文で

masaru が作ってきた 4 つのヘッドレスな道具（THTH・h2d・monban・hub）は、役割を分けるだけでなく、**任せる代わりに相手に無い力を授け合う**ことで大きな suite になりうる。並べると、どれも最後に「人が決める」ところで止まっていて、その場所がばらばら。**足りないピースは、ヘッドレス群のための薄いヘッド——人の判断が要る瞬間だけを持つ「決める場所」**だと考える。

### それぞれの強み（他の 3 つが持っていないもの）

- **THTH**: 4 つの SNS との読み書き。公開の守り（承認の指紋に本文・宛先・時刻を含む 2 段の確認、1 日の上限と連投の停止、二重に出さない inflight）。自分の声の記録（送った・採った・絡んだ・反応）。仮名の鍵（author_key）で相手を数える。有償の読み取りの予算と使用ルール（X）。Meta の審査を通った実績。
- **h2d**: 時刻と出来事を合図に動く。Web・コマンド・ファイル・サービスを見張る感知。セッションを起こす。宣言で書ける外部の動作（GitHub・Cloudflare）。Mac の鍵を Mac の外に出さずに使う。過去の出来事でレシピを試せる。不確かな書き込みは送り直さず人に決めさせる。
- **monban**: 外の人を確かめる（キー・ブラウザでのログイン許可・OAuth と PKCE）。受信ポートを開けずにサーバを使わせる（ハウスが取りに来る）。遠くの MCP の入口。持ち主の停止・失効・鍵の回転。
- **hub**: セッション間の伝言と起こし方（呼び鈴・中継・代行）。返事待ちと決める 1 枚。申し送り。約束と期日。朝の報告（Search Console・Cloudflare の数字・SNS の観測）。

## 2. 重なりと、今日見えた痛み

同じ種類の仕組みを、複数の道具が少しずつ持っている。

| 種類 | 持っている道具 | 10/7〜10/9 に起きたこと |
|---|---|---|
| 時刻に動かす | THTH（queue＋timer）・h2d（cron・待ち・起こす）・hub（期日） | X の定時の投稿を「h2d に起こしてもらって手で出す」と決め、同じ日に「THTH の予約で出す」に取り下げた。h2d 側には「THTH に頼んで出す動作」が相談待ちで残っている（h2d `docs/台帳_取りこぼした用事.md`） |
| 人を確かめる・鍵・承認 | THTH（招待・login・鍵の預かり・承認のページ）・monban（THTH 3.14.3 から写した）・h2d（鍵の登録表） | monban は THTH から写して作られたが、THTH はまだ monban を使っていない（差し替えは「判定のあと」＝今） |
| 安全装置 | THTH の guard・monban の guard（写し） | 2 つに分かれている |
| 連絡・報告 | THTH の報告の口・hub の伝言 | THTH の報告の口は開発側に知らせが来ない。9/25 の報告が 2 週間返事なしだった |
| 記録 | THTH の admin_log・runs・各台帳／h2d の runlog／monban の ledger（写し）／hub の run | 形も置き場もばらばら |
| 見張り | THTH の毎朝の一枚・h2d の感知・monban のパルス・hub の朝の集計 | **h2d も hub も THTH の毎朝の一枚の JSON を「何番目の節か」で読んでいる**（h2d `config/sensors/thth-kanto-*.json`・media-hub `hub/snsobs.py`）。THTH が表示の並びを変えると、両方の見張りが黙って止まる |

そして、どれも最後は「人が決める」で止まる。その場所がばらばらで、多くはチャットの中だった。

- THTH: 投稿の承認（確認番号の 2 段）。
- h2d: 結果が不確かな書き込みを、人が `rules resolve` で決める。
- monban: 持ち主が止める・失効させる・鍵を回す。
- hub: masaru に決めてもらうこと（`waiting_on_masaru`・`decide`）。

10/9 の例: 投稿の承認はセッションの会話で、Meta の審査結果はスマホのブラウザで、GitHub のログインは Mac でないとできなかった（スマホからは進められず、公開が数時間止まった）。

## 3. THTH 4.0 の想像（提案・未決）

3.x の THTH は「SNS に出す道具」。4.0 は「その人の声が、どこで・誰に・どう届いたかを、本人と本人の LLM が回し続けるための道具」。出す → 採る → 見る、が別々の口から 1 本の輪になる。

1. **会話が単位になる**: 投稿ではなく会話を 1 つのものとして持つ。自分の根・絡みに行った先・言及・各 SNS の返信が 1 つの受信箱に並び、返していないものが漏れない（10/7〜10/8 の不具合——刻みのすき間・絡みに行った先の返事の取りこぼし・外で出した投稿が見えない——はどれも「会話を追い切れていない」ことから来ていた）。
2. **試すことが道具に入る**: 「この型を試す → いつ・どこで出す → 何で測る → いつ判断する」を先に宣言し、道具が出し分け・数え方・判断の日の知らせまで持つ。因果を言い切らないための証拠の段（L1〜L5）を出力に付ける。
3. **外の人が自分の LLM で使うのが本線になる**: Meta の承認で、テスターでない人も入れる。利用者の LLM が CLI と MCP だけで最後まで回せることを中心にする（masaru の方針「THTH は道具の提供者。利用者とその LLM を疑わない」）。

4.0 で互換を崩す候補: JSON の欄の名前の統一（`id`・`message_id`・`post_id` の混在）、台帳の様態の分け方（「同席専用」と「予約あり」が人を迷わせた）、有償の読み取りを媒体の例外でなく芯に入れる。

## 4. 役割分担ではなく交換（masaru 10/9「任せる代わりに、相手に持っていない機能を授ける」）

| 組み合わせ | THTH（や片方）が手放す | 代わりに得る | 相手が得る |
|---|---|---|---|
| **THTH × monban** | 招待・ログイン・鍵の預かり・承認のページ・Worker の大半 | **遠くから MCP でつなぐ道**（claude.ai などのコネクタから OAuth で入る）。THTH は持っていない | **本物の住人**（Meta の審査を通った家が住む）。THTH の 2 段の承認を、どの家でも使える「承認」として |
| **THTH × h2d** | 自前のタイマーと見張り（死活通知の URL・毎朝の一枚を誰かが読みに来る形） | **出来事で動く投稿**（サイトが更新された・値段が動いた → 投稿案。出すときの守りは THTH に残る） | **SNS という目と手**（返信が来た・言及された・語が急に増えた を感知に。承認つきで SNS に出す動作） |
| **THTH × hub** | 報告の口の受け箱と返事の管理 | **サイト側の結果**（Search Console・Cloudflare の参照元）。投稿 → 訪問まで THTH の中で追える | **外の利用者の声**（アカウントごとの不具合・要望・つまずき）。身内だけだった hub に外からの入口 |
| h2d × monban | monban の自前の見張り | — | h2d がハウスの脈を感知し、止まったら直す動作を回す |
| h2d × hub | hub の期日の見張り | — | hub の約束を h2d が時刻で見張り、破れそうなら本人を起こす（書くだけから守らせるへ） |

例外の推薦: **SNS の予約は THTH に残す**。公開の時刻は承認の指紋（`publish_at` を含む）・ガード・inflight と一体で、外から叩くと「二重に出さない」を 2 か所で守ることになる。h2d は「予約が止まった・遅れた」を見張って起こす側に回る（今の h2d の感知と同じ筋）。

## 5. 足りないピース: ヘッドレス群のヘッド

### 5.1 何か

エージェントと道具が頼んでくる「人の判断が要ること」を、人が 1 か所で見て、決めて、止める場所。スマホで完結する。**全部を操作できる管理画面ではない。**

| | よくある管理画面 | このヘッド |
|---|---|---|
| 見せるもの | 道具の状態の全部 | 人に決めてほしいことだけ |
| できること | 設定・作成・操作の全部 | 承認する・直して返す・却下する・止める |
| 中に持つもの | 処理の仕組み | 持たない。決めたことを各道具の正しい口に返すだけ |
| 止まったとき | 全体が使えない | 道具はそのまま動く。決めるのが遅れるだけで、**勝手に承認されることはない** |

THTH の「Web は見る・止める・鍵だけ」を、ヘッドレス群全体に広げた形。

### 5.2 入ってくるもの・返す先

| 道具 | 頼んでくること | 決めたことの返し先 |
|---|---|---|
| THTH | 承認待ちの投稿（本文・宛先・時刻・確認番号）、取り下げ | `approve --confirm <digest>`・`retract --confirm` |
| h2d | 結果が不確かな書き込み、レシピの承認 | `rules resolve` |
| monban | この機械に鍵を渡すか、停止・失効 | 持ち主の操作 |
| hub | どちらにするか・進めてよいか | `hub answer` |

### 5.3 原則（案）

1. **持たない**: 投稿を書く・計画を立てる・判断の材料を作るのは LLM と道具の仕事のまま。
2. **見せたものと違う中身は通らない**: 承認は見せた中身に縛る（THTH の確認番号の考え方）。直したら新しい承認になる。
3. **止まっても安全**: ヘッドが落ちても、道具は自分の守りで動き続け、承認待ちは承認待ちのまま。
4. **人でも LLM でも同じ口**: 人がスマホで押しても、使う人の LLM が本人の方針の範囲で返しても、同じ記録が残る。
5. **誰が決めたかを確かめる**: 本人確認は門（monban）が持つ。期限が来そうなら時（h2d）が知らせ、記録は場（hub）に残る。

### 5.4 交換の形で見ると

4 つの道具とも、自前の「人に聞く画面」を持たなくてよくなる（THTH の /activity と承認のページ、monban の持ち主の画面、hub の返事待ち）。代わりに、どの道具も「人の判断を、スマホで、すぐに、記録つきで受け取る口」を得る。「人が気づくまで止まる」が「数分で返ってくる」に変わる。ヘッドは 4 つを一番よく使う客でもある。

### 5.5 なぜアプリになりうるか

エージェントに仕事を任せる人は、これから必ず「頼まれごとが散らばる」問題に当たる。SNS に限らない。THTH の 2 段の承認（見せたものと違う中身は通らない）は、その答えの芯として、もう Meta の審査を通って動いている。外の人が自分の LLM で道具を使うとき、このヘッドが入口になる。

### 5.6 最初の 1 往復（tracer の案）

THTH の承認待ちの投稿が 1 本、スマホのヘッドに届く → 押す → 確認番号つきで THTH に返り、時刻に出る → 結果がヘッドと hub に残る。

### 5.7 もう一つの候補（2 番目）

「何を言うか」の素材と根拠の台帳。関東の学校のデータ・kopicha の豆の値段などを、出典と鮮度つきで 1 か所に持つ。THTH の投稿の材料、h2d の感知の対象、hub の測る対象になる。媒体ごとに中身が違うので、汎用のアプリとしてはヘッドより遠い。

## 6. 寄せる順（提案・未決）

1. **約束事を先に**: THTH の毎朝の一枚の JSON に版と名前つきの節を持たせ、h2d と hub は名前で読む（THTH 側だけで済み、一番危ういつなぎ目を塞げる）。
2. **THTH × hub の 1 往復**: 報告の口に入った報告が hub の伝言で開発に届く。hub のサイトの数字を THTH が読める。門や鍵に触らないので Meta への説明は変わらない。
3. **ヘッドの tracer**（§5.6）。
4. **THTH × monban**: 遠くの道を monban に寄せる。効き目は一番大きいが、鍵と承認の持ち主が変わるので、プライバシーポリシーと Meta への説明を直してから。
5. 記録と guard の共通化は、互換を崩してよい THTH 4.0 の機会に。

## 7. 気をつけること

- **一つが止まると全部が止まる形にしない**。今の THTH は単独で予約を出せる。つなぎ目が切れたら「落とさない・二重に出さない」側に倒す。
- **Meta に説明した作り**: 審査では「THTH が鍵を預かり、承認のページを持つ」作りで説明した。鍵や承認を monban・ヘッドへ移すなら、プライバシーポリシーと次の審査での説明を合わせて直す。
- **THTH の取得物を外の AI 提供者に渡さない**（10/5 の判断・Meta への約束）。h2d の判定の層（Jev）とつなぐときも同じ。X の取得物はモデルの学習に使わない（X Developer Agreement III(A)(k)）。
- monban の申し送り（10/5）に、THTH の Worker が 1 日約 5 万行を書いている件が masaru の判断待ちで残っている。門の差し替えの前に片付ける。
- monban は外の参加者 0 人・0.4 系は未配備。h2d は 0.1.0。suite の中で成熟度が揃っていない。

## 8. 決まっていること・決まっていないこと

決まっていること（masaru・日付つき）:
- 10/9: 単純な役割分担では意味が薄い。任せる代わりに相手の力を伸ばす・授ける形を考える。
- 10/9: §4 の交換は「全部惹かれる」。
- 10/9: この書を headlesson に渡す。

決まっていないこと:
- suite を 1 つの製品（名前・入口・説明を 1 つ）にするか、ゆるい連合（単独で使え、約束事でつながる）にするか。書いた人の推薦はゆるい連合から。
- ヘッドを作るか・名前・どこが持つか（独立のアプリか、monban の一部か）。
- §6 のどこから始めるか。
