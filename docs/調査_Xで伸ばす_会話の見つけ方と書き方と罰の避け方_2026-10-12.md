# 調査: X で伸ばす——会話の見つけ方・書き方・罰の避け方（2026-10-12）

書いた人: THTH開発（委任の writer）。依頼: masaru 10/12「X にあったフォロワーの増やし方、インプのとりかたをドンドン試して研究しつつ、ペナルティーを受けないようにしないといけません」「指南も THTH の語彙として持っておくと、みんな助かるはず」。対象: @kanto_asmon（asmon-kanto-x）と @kopichaba（kopicha-x）。どちらもフォロワー 0・1 本の表示が数件〜数十件。強みは独自のデータ。

証拠の強さ: **L1** 原文・自分のコード／**L2** 公開コード・公式資料／**L3** 報道・二次／**L4** マーケ系ブログ／**L5** AI の返答。X API は叩いていない（有償）。

## 0. 3 行の要約

1. 罰の線は規約が明文です（L1）。**人が一本ずつ見て確定する THTH の道は「自動化」に当たらず**、禁じられているのは「検索語だけを根拠にした自動返信」「自動のいいね」「同じ文の繰り返し」「無差別のフォロー」です。
2. 公開コード（L2）から言えるのは、**返信・引用・DM 共有・リンクのコピーが重く、ブロック・ミュート・報告・興味なしが桁違いに重い負**だということ。フォロワー 0 では自分の投稿は他人のタイムラインにほぼ出ないので、**まず他人の会話への返信で届く**のが筋です。
3. 足りないのは道具より運用です。疑問の形の検索語・返信欄の探索・「答えられるか」での並べ・採否の記録を **SKILL と使い方**に書き、14 日の試しで 1 つずつ変えて測ります。ただし **X の自分の投稿の数字を THTH はまだ採っていない**（§5）ので、測る口を先に決める必要があります。

## 1. 罰を受けない線

出典: X Automation rules（https://help.x.com/en/rules-and-policies/x-automation ・2026 年 4 月更新・10/12 に親セッションが全文を読んだ・L1）。「自動化」の定義は「a person が能動的に行わずに繰り返す行為」。

| やらない | AI が文を作る自動返信ボット（X の書面承認が要る） | II.B.3 | LLM が下書きしても、出すのは人が一本ずつ |

## 2. X で表示と会話が増える仕組み

### 2.1 公開コードから言えること（L2・https://github.com/xai-org/x-algorithm ・README は 2026-08-13 版、9/18・9/29 更新。param.rs の既定値は「primary production values」と書いてあるが、本番と同じとは書いていない。Grok のプロンプト等は非公開）

- 候補は 2 系統。フォロー中の新しい投稿（Thunder）と、フォロー外（Phoenix retrieval・SimClusters・popular posts）。順位は閲覧者ごとの行動確率の重み付き和。
- 重み（既定値・param.rs。**確率に掛かる。生の件数ではない**）: Favorite 0.5・Reply 5.0・相互フォローの間の返信 +15.0・Retweet 1.0・Quote 5.0・Share 2.0・DM で共有 5.0・リンクのコピー 20.0・作者をフォロー 4.0・Click 0.3・リンクを開く 0.2・プロフィールクリック 0.0・Dwell 0.05／負: 興味なし -47.52・ミュート -58.8・ブロック -31.2・報告 -234.0・読まずに流す -0.02。
- 後段の調整: 同じ作者の 2 本目以降を減衰／フォロー外の割引、**フォロー中の作者の返信と再投稿にも割引**／表示が少ない作者の後押し（`ColdStartImpressionThreshold` 200・`ColdStartSlotMin/Max` 15〜16 ＝ 200 表示未満の作者の投稿を 15〜16 番目あたりへ持ち上げる）／48 時間より古い候補は外す（`SimclustersMaxCandidateAgeHours` 48・新規作者の cold start は 2 時間）／フォロー外の返信と再投稿は `OONRetweetReplyFilter` で外す／`NewUserMinEngagementFilter`（既定 off）。
- README・param.rs に**リンクの罰・Premium の後押しの項目は無い**。リンクは `OpenLinkWeight` 0.2 という行動の 1 つとしてだけ出る。

### 2.2 重みから読める実務（数字は L2・読みは THTH の推測）

| 読み | 根拠 | 実務 |
|---|---|---|
| 会話が続く返信が重い。相互フォローの間はさらに重い | Reply 5.0・+15.0 | 返信が返る文を書く。会話が続いた相手とは相互フォローになると次が届きやすい |
| 「人に送りたくなる」が最も重い | リンクのコピー 20.0・DM 5.0・Quote 5.0 | 独自データの表・数字は「誰かに送る」動機になる。1 本で完結する形に |
| 押し付け・誘導・連投は逆効果 | 興味なし -47.52〜報告 -234.0（いいね 0.5 の 100〜500 倍） | 1 人の「興味なし」が数十のいいねを消す。宣伝の型・@の乱用・同じ文は避ける |
| 連投は効きにくい | 作者の多様性の減衰 | 1 日 1〜2 本の根投稿で足りる。残りは返信に回す |
| 鮮度は 48 時間 | 48h・cold start 2h | 出した直後の反応が要る。深夜に出して朝に見る、は不利の可能性（時間帯は §5 で測る） |
| フォロワー 0 の根投稿はほぼ届かない | 候補はフォロー中かフォロー外の推薦。推薦はフォロー外の割引つき | 新規作者の後押し（200 表示未満）はあるが、閲覧者の興味と合う投稿が要る |
| フォロー外の返信は他人のホームに出ない | `OONRetweetReplyFilter` | **返信は相手とその会話を見ている人に届く経路**。ホームで伸びるものではない。だから「返信欄の読者」を選ぶ |
| プロフィールクリックは重み 0 | ProfileClick 0.0 | 順位には効かないが、フォローの前段。測る指標としては残す |

### 2.3 言えないこと（未確認）

- **リンクの罰**: 公式ページには無い。X の製品責任者（Nikita Bier）が 2026-05 に「リンクは投稿を落とさない」、Musk が 2026-07 に「1 年以上前からやっていない」と返信した報道（L3・https://ppc.land/x-drops-year-old-link-penalty-musk-tells-zuckerberg-on-platform/ ）。正式な発表は無い。「2025 年 10 月に罰をやめた」という又聞きは裏が取れなかった。→ **リンクの有無は §5 で自分で測る**。ただし API の料金は URL 付きが 0.200 USD（本文だけの 13 倍・10/6 調査）で、これは罰でなく費用の問題。
- **Premium の返信の優先表示**: 報道では「Premium は返信欄で上に出る」（L3〜L4）。help.x.com を 10/12 に取得できず（403）。「most relevant」の並びの中身は公開コードの範囲外。
- 検索（recent search）の並びと、閲覧者の「おすすめ」の候補にどう入るかは、公開コードの home-mixer の範囲外。
- アカウント単位の表示制限が今かかっているか（ChatGPT の仮説 4・L5）。確かめ方は §5.3。

## 3. THTH の X の探し方に足りないもの

今の `thth where`（L1・`thth/where_cli.py`・`thth/adapters/x.py`）: 語をそのまま `query` に渡す（演算子は付けない）・`--recent`（recency／既定 relevancy）・`--since`・`--also`（結果の本文で絞るだけ）・`--exclude-engaged`（絡みの台帳にある相手を除く）・`--max-per-author`・`--suggest`（語の候補・保存しない）。X は 1 回 既定 10・最大 25 本、1 日 60 本、月 15 USD。`thth thread` は `conversation_id:` 検索で最大 50 本。**順位付けはしない。自動の出向きはしない。**

| 足すもの | 中身 | 置き場 | 芯とのぶつかり |
|---|---|---|---|
| 疑問の形の検索語と演算子 | 語をそのまま渡すと再投稿・他言語・引用が混ざって 25 本を食う。`"豊島岡" 算数 lang:ja -is:retweet -is:quote` のように**疑問を含む言い回し**（「どうやって」「おすすめ」「迷って」「教えて」「?」）と絞りを足す。X の検索演算子は 1 語に対して `-is:retweet` 等をそのまま書けるので、**道具は何も変えなくてよい** | SKILL と使い方（演算子の例を 5 つ置く）。道具に `--ja`（`lang:ja -is:retweet` を足す）を足すのは任意 | 無し |
| 返信欄を探す | 質問は根投稿より返信欄に出やすい（L5）。`thth where` で根を見つけ、`thth thread <id>` で枝を読む、の 2 段。枝は 1 回 50 本で 1 日の上限 60 本の大半を食う | 使い方: 「1 日 where 2 回（20 本）＋ thread 1 回（〜40 本）」の配分を書く。道具に `thread --limit`（枝の上限を 50 より小さく）を足すと配分しやすい | 無し。`--limit` は読む本数を減らすだけ |
| 20〜30 アカウントの返信欄を見る | `from:@名前` や `to:@名前` を語に書けば今の where で検索できる（演算子）。**アカウントの一覧を THTH が持つのは**別の話（台帳に他人の名前を持つことになる） | 一覧は project 側の docs（kopicha／asmon-kanto）に置く。THTH には持たせない | **ぶつかる**: 他人の名前の一覧を THTH の台帳に置くのは「本文・username を残さない」線に触れる。project 側に置くなら無し |
| 「答えられるか」での並べ | 手持ちのデータで答えられる順に並べたい（L5）。where が順位を付けると芯（並べるだけ・選ぶのは LLM）と**ぶつかる** | 並べるのは呼ぶ側の LLM。SKILL に「選ぶ基準」を書く（§3.1） | **ぶつかる**。道具には入れない。masaru の判断に回す（§6 決定 2） |
| 採った・捨てたの記録と翌日への反映 | 採った（返信した）は `engagements` にある（`found_by: where_to_appear`）。**捨てた理由は台帳に書けない**（`verdict`・`reason` は禁止鍵）。語ごとの当たり率は `--also` の表示だけで保存しない（3.9.0 §E・Meta への説明の申請まで） | 捨てた理由は project 側の日誌（本文は写さず、語と「答えられなかった／宣伝だった／古い」の符丁だけ）。翌日の語は人と LLM が決める | **ぶつかる**: 日をまたいで貯めるのは 3.9.0 §E で止めている。語と当たり率だけなら Meta の線とは別（X）だが、同じ規律で扱うなら masaru の判断 |
| 60 本/日の配分 | 既定 10 本の where を 6 回でも、25 本を 2 回＋thread 1 回でもよい | 使い方に配分の例を 2 つ書く。`x_read_cost` の 1 行が毎回出るので、道具は足りている | 無し |
| 出す時刻 | `publish_at` で予約できる | 使い方: 時間帯の比較（§5） | 無し |

### 3.1 選ぶ基準（SKILL に書く・LLM と人の運用）

1. 疑問が書いてある（「?」「どう」「おすすめ」「迷」）。2. 手持ちのデータで**数字つきで**答えられる。3. 48 時間以内（公開コードの鮮度）。4. 相手が宣伝・bot でない（本文に URL と @ だけ、など）。5. 同じ相手に 7 日で 2 回以上行かない（`--exclude-engaged`）。6. 1 日 2〜3 本。ノルマにしない。足りない日は出ない。

## 4. 書き方の語彙（THTH の語彙として持つ案）

### 4.1 一次資料と規約から言える原則

| 原則 | 根拠 |
|---|---|

| 1 本で完結。続きはリンクでなく返信で | リンクの罰は未確認だが、URL 付きの作成は 0.200 USD（L1・料金表）。「詳しくはこちら」は II.B の「surprise」に近い |

### 4.2 独自データのアカウントの出し方（ChatGPT の指南を枠に入れた・L5）

- **読者の疑問から始める形**: 「出題頻度の報告」でなく「過去問をどの年から解くか迷っている人へ」。「産地別の取扱店舗数」でなく「同じ豆が店で 1.4 倍違う。どこで買うか」。
- **データを「判断にどう使えるか」で伝える**: @kanto_asmon は「受験勉強の判断」（何年分・どの単元を優先）、@kopichaba は「購入の比較判断」（店舗間の価格差・価格の変動）。
- 読者: @kanto_asmon＝中学受験家庭・塾講師・受験情報の発信者。@kopichaba＝自家焙煎の愛好家・コーヒーと茶葉の購入者。
- 10/12 に ChatGPT へ追加のアイデア（検索の工夫・最初の 100 人・書き方の型・重みからの逆算・表示制限の確かめ方）を頼んだ。答えが来たらここと §3・§5 に足す（枠）。

## 5. 試し方（研究の段取り）

### 5.1 THTH が測れるもの・測れないもの（L1・`thth/collect.py`・`thth/measured.py`）

- **X の自分の投稿の数字（views・likes・replies）を THTH はいま採っていない**。`collect` は `PAID_READS` の媒体（X）で数も返信も読まない（設計 10/8 運用 1・3）。`thth/x_metrics.py`（応答を views/likes/replies/reposts/quotes/bookmarks に写す純粋関数）はあるが、どこからも呼ばれていない。Owned Reads は 1 本 0.001 USD（料金表）で、他人の投稿（0.005）とは別の段。
- 採れているもの: 出した時刻・`text_length`・`has_link`（`sent`）・`goal`・`reply_to`・`found_by`（`engagements`）。
- X の画面でしか見えないもの: プロフィール訪問・詳細のクリック・ブックマーク（API にはある）・表示制限の有無。

→ 試しの前に、**X の自分の投稿の数字を採る口**（1h・6h・24h・72h の刻みで Owned Reads）を作るかどうかを決める（§6 決定 1）。作らない場合は X の Analytics 画面から手で表に写す（14 日 × 2 アカウント × 1 日 3 本 ＝ 84 本を 2 回見る）。

### 5.2 記録の表（投稿 1 本に 1 行・ChatGPT の案を THTH の欄で読み替えた）

| 欄 | THTH で | 手で |
|---|---|---|
| post_id・account・posted_at・has_link・text_length・goal・found_by | `sent`・`engagements` | — |
| method（api／manual） | THTH を通った＝api。手で出したものは `sent` に無い | manual の行は手で足す |
| format（従来型／読者の疑問から型） | front-matter に欄が無い。`topic` に符丁（`q-` 接頭）を入れれば `--by topic` で分けられる | — |
| impressions_24h・48h・likes_48h・replies_48h・bookmarks | 決定 1 で採る口を作れば `measured`（刻みは 24h・72h。48h は無いので 72h で代用するか刻みを足す） | X の Analytics から |
| profile_visits・detail_clicks | API に無い（非公開指標） | X の画面 |
| 表示制限の有無 | 無い | §5.3 |

主指標: **48h（代用 72h）の表示の中央値**。副指標: 表示 50 未満の本の割合、返信からの会話の続き（相手の返事＝`engagements` に相手の返事が載るのは Threads だけ。X は `replies --refresh` で手で採る）。

### 5.3 14 日の段取り（ChatGPT の案を土台に・1 回に変えるのは 1 つ）

| 日 | 変えること | 見るもの |
|---|---|---|
| 1〜3 | 何も変えない（基準値）。**表示制限の除外**: ログアウトした別のブラウザで `from:kanto_asmon` を検索して出るか、自分の返信が相手の枝にログアウトで見えるか、Settings の Account status（表示されるなら）を見る | 基準の表示・制限の有無 |
| 4〜7 | 人が選んだ会話への返信を 1 日 2〜3 本足す（§3.1） | 返信の表示・相手の返事・プロフィール訪問 |
| 8〜11 | 根投稿の半分を「読者の疑問から型」に（`topic` の符丁で分ける） | 型ごとの表示の中央値 |

| 15 | 判断。差が中央値で 2 倍以上なら採る。それ未満は「差は見えなかった」と書いて次の 14 日へ | — |

時間帯は 14 日では分からない（1 帯あたりの n が足りない）。`after_you_posted` の `one_thing_to_change` が各帯 `min_n` を満たすまで、`publish_at` を 3 帯に散らして続ける。

### 5.4 2 アカウントで比べる

同じ日に同じ条件を両方に当てる（片方だけ変えると分野の差と混ざる）。規約 I.A の「複数アカウントで同じ文」に触れないよう、題材と文は別々に。

## 6. masaru に決めてほしいこと

1. **X の自分の投稿の数字を採る口を作るか**（Owned Reads 0.001 USD/本・1 日 3 本 × 2 アカウント × 4 刻みで月 1 USD 弱）。推し: **作る**。作らないと 14 日の主指標が手写しになり、試しが続かない。
2. **「答えられるか」での並べと、語の当たり率の日またぎの保存を、X でも芯（並べるだけ・保存しない）のままにするか**。推し: **芯のまま**。並べるのは LLM、記録は project 側の日誌（語と符丁だけ）。道具は変えない。
3. **Premium は 14 日の後に判断**（返信で表示が増えるなら、返信の優先表示に払う意味を 1 アカウントだけ 1 か月で測る）。推し: **14 日待つ**。先に買うと返信の効果と混ざる。

## 8. ChatGPT の追加の案（10/12・L5）と確かめたこと

masaru が追加で頼んだ答えの前半（1 検索・2 最初の 100 人・3 書き方の型の途中まで）。後半（3 の残り・4 重みからの逆算・5 表示制限・最初の 2 週間の 3 つ）は届いたら足す。

### 8.1 検索の演算子（X の資料で確かめた・L2・https://docs.x.com/x-api/posts/search/integrate/operators ）

| 演算子 | API の recent search で | 注 |
|---|---|---|
| `lang:ja`・`is:reply`・`is:quote`・`is:retweet`・`has:links`・`has:images`・`is:verified` | 使える | **単独では使えない**（ほかの語と組む） |
| `from:`・`to:`・`conversation_id:`・`list:` | 使える | 単独で使える |
| `min_likes:`・`min_reposts:`・`min_replies:` | 使える | recent・全期間とも |
| `min_faves:`・`min_retweets:` | **使えない（400）** | X の画面の検索だけの名前。ChatGPT の案はこれを書いていた → `min_likes:` に読み替える |

query の長さは self-serve で 512 字。

**§3 の「20〜30 アカウントの返信欄」が解ける**: X のリストに分野の相手を入れ（X の上で masaru が管理）、`list:<リストの id> lang:ja` で検索すれば、THTH は他人の名前の一覧を持たずに済む（§3 の表の「ぶつかる」が解ける。リストの公開・非公開と、他人をリストに入れる行為の規約 II.D「bulk or indiscriminate」には注意。手で少数なら該当しない）。

### 8.2 検索の案（ChatGPT・演算子は上で直した）

- 優先: ①競争の少ない専門語（`"豊島岡" "場合の数" lang:ja -is:retweet`・`"エチオピア" "生豆" lang:ja -is:retweet`）③返信そのもの（`"算数" "過去問" is:reply lang:ja`）⑤変化の言葉（`"入試" "傾向変わった" lang:ja`・`"コーヒー豆" "高くなった" lang:ja`）⑧有望なときだけ `conversation_id:` で枝を読む。
- ほか: ②反応のある投稿（`"過去問" min_likes:3 lang:ja -is:retweet`）④宣伝を除く（`-has:links`）⑥引用（`is:quote`・議論への便乗は危険 中）⑦画像つき（`has:images`）。
- 0 件のときは、同義語を足すより、固有名詞を残して条件を 1 つずつ外す（失敗の理由が追える）。
- 60 本の配分の案: 高精度の検索 25・直近の変化 15・有望な枝 10・新しい語の探索 10。枝は 1 回で 50 本返るので `thread` に上限を足すか、件数を見て止める（§3）。

### 8.3 最初の 100 人まで（ChatGPT・推測が中心）

- **固定ポストを「データの目次」にする**・プロフィールに「フォローする理由」（継続して何が分かるか）を書く。順位の加点の根拠は無い（プロフィールクリックの重みは 0）が、来た人がフォローを決める材料になる。固定ポストの文の案（ChatGPT）: 関東「関東の中学入試、過去問を年単位で比較しています。学校ごとの出題分野、問題数、出題傾向の変化を…受験勉強の判断に使えるデータを、学校別に継続公開します。」kopicha「同じコーヒー豆、店によっていくら違う？ 国内の販売店の…価格を定期的に記録しています。店舗間の価格差や変化を、実際の観測データから紹介します。」
- 独自データでの引用投稿（同意・宣伝だけは不可・危険 中）／分野の X リスト（8.1）／コミュニティ（規則が許すときだけ・危険 中）／「今週の変化」の定期連載（毎回中身が違うこと・I.A）／1 投稿 1 結論の短いスレッド（2〜4 本）／Threads と X でフォローする理由を分ける。
- 時間帯は固定の推奨をせず、朝 6〜9・昼 12〜14・夜 19〜23 の 3 帯で 2 週間記録（§5.3 と同じ）。

### 8.4 書き方の型（ChatGPT・途中まで）

意外性のある数字を先頭に／差分だけを伝える（先週より・前年より）／ランキングでなく分布（中央値・件数）／例外から入る（一般化しない）／観測範囲を冒頭に（「対象 37 店・10/12 朝時点」）／小さなグラフ（軸の誇張に注意）／調査方法は別の投稿に（1 本目は発見、2 本目は条件、3 本目は限界）／返信は「1 事実＋1 解釈」。均質化は文をランダムにするのでなく、**見せ方の型を複数持つ**ことで防ぐ。→ §4 の語彙の候補（SKILL に型の名前で置く）。

### 8.5 続き（2〜5・ChatGPT・L5。前の 8.3・8.4 と重なるものは省いた）

**最初の 100 人（追加）**: 引用ポストで独自の分析を足す（例「この学校について過去 22 年の算数の出題構成を調べています。構成が安定していることと難易度が一定であることは別」）。引用で元の読者に届く保証は無い。固定ポストは「サービスの紹介」でなく「代表的な発見 3 件＋データの範囲」で、30 秒で価値が分かるもの。受験・コーヒーの行事に合わせる（無関係なトレンドへの便乗はしない＝I.A）。測るのは直後の反応より 48 時間後のフォローへの転換。

**書き方: 「発見の種類」で型を選ぶ（THTH の語彙の芯にしたい）**。語尾や口調をランダムに変えるのでなく、書く前に発見の種類を決め、種類で組み立てを選ぶ。**データの多様さが文の多様さになる**。

| 発見の種類 | 中身 | 例（ChatGPT・数字は実データで確定してから） |
|---|---|---|
| 例外 | 長年の傾向から外れた年・店 | 「例年の傾向だけで対策すると見落とすもの。○○中の社会で、通常と違う出題の年度を整理しました」 |
| 比較 | 学校間・店舗間の差 | 「同じ産地の豆でも店ごとに価格差。内容量を 100g 換算、販売条件を揃えて比較」 |
| 変化 | 前回からの増減 | 「今週の値上がりは全銘柄に共通か。前週と同じ条件で観測できた商品だけで比較」 |
| 安定 | 長く変わらない特徴 | 「豊島岡の算数第 1 回。22 年分で大問 6・小問 18 の構成が続いていた。時間配分の練習の材料に」 |
| 分布 | 平均では見えない偏り | 中央値・件数・幅 |
| 実用 | 学習・購入の判断への使い方 | 「何年分を・どの単元から」「どこで買うか」 |

書く前に持たせる材料（ChatGPT の案）: `finding_type`・`primary_claim`・`evidence_ids`・`observation_date`・`comparison_basis`・`caveats`・`reader_benefit`・`format`。LLM への制約: 数字は取得済みのデータからだけ／データに無い因果を足さない／毎回「調べてみました」「驚きです」で始めない／不要な問いかけ・反応の誘導を付けない／分けるのは 1 本で分かりにくいときだけ／数字の多さより判断に役立つ差。→ THTH では原稿の front-matter に `finding` の欄を足すか、SKILL の型の名前として置くかを決める（§6 の決定の候補）。lint にできるのは「書き出しの決まり文句の繰り返し」（直近 N 本で同じ書き出し）くらい。

**引用されやすい形**: 「22 年分調べた」より「22 年間で大問 6・小問 18 が共通」。説明を足さなくても意味が通じる 1 文に、範囲・年度・集計方法を添える。

**重みを直接狙わない（やってはいけない）**: 返信の重みが高いから無理に質問で終える／引用の重みが高いから議論を煽る／共有の重みが高いから URL を多く貼る／フォローの重みが高いからフォローバックを誘う。どれもミュート・ブロック・報告を招く。いいね・返信・共有の交換を組むのは規約違反（危険 高）。負の重みは尺度が揃っているとは限らないので「報告 1 回＝返信何回」の計算はできない。

**表示制限の確かめ方（ChatGPT の A〜C・D 以降は届いたら）**: 少ない表示と表示制限は別（フォロワー 0 なら推薦に入っていないだけのことが多い）。A 投稿の URL がログアウトや別の通常アカウントから開けるか → B `from:kanto_asmon` を「最新」で検索して出るか → C 出ないときは固有の文・投稿 id・時刻で確かめ直す（出ないことだけで制限と断定しない）。予防: 同じ文・同じ URL の反復を見張る／同じ相手への繰り返しの接触を防ぐ（`--exclude-engaged`）／API のエラー・削除・制限の知らせを記録する。**制限が疑われても別アカウントで回避しない（危険 高）**。

### 8.6 表示制限の確かめ方の続きと、最初の 2 週間（ChatGPT・L5。これで答えは全部）

**3 つの状態を分ける**（排他ではなく、調べる順の分かれ道）:

| 状態 | 調べること |
|---|---|
| A 投稿の URL を直接開けない | 非公開・削除・アカウントの制限・閲覧の条件 |
| B URL では開けるが検索に出ない | 検索の反映の遅れ・検索の品質の絞り |
| C 検索には出るが表示が少ない | 推薦の候補に入っていない・接点が少ない。**フォロワー 0 なら C は不自然ではない** |

確かめ方: 別の通常アカウントやログアウトで URL を開く／「最新」で固有の文言を検索／`from:` で検索／検索に出るまでの時間を記録／X からの制限の知らせ・異議の案内を見る／API と手動の投稿で検索に出るかを比べる（同じ文は出さない）。外部の「シャドウバン判定」サービスは使わない（ログイン情報を渡す危険・誤判定）。

ChatGPT の案 `visibility_audit`（投稿ごとに `direct_url_accessible`・`search_exact_match`・`search_from_account`・`restriction_notice`・表示 24h/48h）: URL と検索の確かめは**人がログアウトで見るのが確か**で、THTH の道具にするより、各プロジェクトの日誌の欄にするのが軽い。`search_exact_match` が false でも、それだけで制限と判定しない。

**守る線（規約と保守的な運用）**: 同じ・ほぼ同じ内容を繰り返さない／複数のアカウントで同じ会話に集中して入らない（関東と kopicha は分野が別なので通常は起きない）／検索で見つけた相手に定型の返信を大量に送らない／関係の薄い投稿に自分のサイトのリンクを貼らない／フォロー・いいね・返信の交換を組まない／自分の投稿への反応を人工的に増やさない／制限を受けても別のアカウントで回避しない。

**最初の 2 週間で試す 3 つ（ChatGPT の選び）**: 1 位 検索の精度（固有名詞×専門語で、取得 1 本あたりの有用な会話の数を測る）。2 位 独自データの引用ポスト（返信だけに頼らず、自分のタイムラインにも情報が残る）。3 位 プロフィールと固定ポスト（少ない訪問をフォローにつなぐ土台）。Premium はまだ要らない。

**段階ごとの数（どこで詰まったかが分かる・漏斗）**: 取得した本数 → 返信・引用に向く候補 → 人が採った → 実際に出した → 48 時間の表示 → プロフィール訪問 → フォロー。率は「候補 ÷ 取得」（検索の精度）・「採用 ÷ 候補」（LLM の選びの精度）。見つからない＝検索の問題、見つかるのに採らない＝選びの問題、読まれるのにフォローされない＝プロフィールと中身の合い方の問題。ブロック・ミュート・報告は API で取れない（画面で分かる範囲だけ）。

### 8.7 14 日の段取りを 1 本にする（§5.3 を置き換える案・THTH開発の推し）

フォロワー 0 では根投稿はほとんど届かない（§2.2）ので、ChatGPT の後半の案（探す・会話に入る・受け皿を整える）を主にし、§5.3 の根投稿の比較は 15 日目以降に回す。

| 日 | すること | 記録（どこに） |
|---|---|---|
| 1〜2 | 表示制限の確かめ（8.6 の A〜C）・プロフィールと固定ポストを「代表的な発見 3 件＋データの範囲」に | 状態 A/B/C・基準の表示（日誌） |
| 3〜5 | 検索の語を 8 種類、少しずつ（1 日 60 本の中で・§8.2 の演算子） | 語ごとの取得数と有用な候補の数（日誌・本文は写さない） |
| 6〜10 | 当たった語で、返信と引用を人が 1 本ずつ（1 日 2〜3 本・§3.1 の基準・「発見の種類」で書く） | 出したもの（THTH の `sent`・`engagements` に自動）・表示（決定 1 の口があれば THTH、無ければ画面から） |
| 11〜14 | 当たった探し方に寄せる | フォローの純増・プロフィール訪問（画面） |
