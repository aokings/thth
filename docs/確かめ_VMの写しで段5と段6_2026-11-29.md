#### 原因【読】

承認と止めの記録は、項目ごとに repo を絶対の道で持つ（`approvals.json` の `repo` が 5748 か所・`holds.json`・`inflight.json` の `file`・`draft_path` も同じ形）。コードはこの道を原稿の repo の頂上と realpath で照らす（`thth/approval_ledger.py` 342 行・487 行・553 行）。移すと原稿は `ws/main/repos/…` に、記録は `/srv/thth/repos/…` のままになり、合わない。

- 承認: 照らせないので無いものとされ、require_gate の口座では下書きに戻る → 承認済みの予約が出なくなる。
- **止め: 照らせないので無いものとされる → 止めていた投稿が出る恐れがある。** こちらのほうが危ない。
- 前の手順書の稽古（移す前と後のファイルの hash を比べる）では拾えなかった。数え直しの確かめが要る。

#### 直し（2c7bc503 で作った）

移す台本の「道の直し」を、括りへ移した記録（`state/<口座>/` の下の JSON）の中の絶対の道にも広げる。`<根>/<移した物>/` を `<根>/ws/main/<移した物>/` に書き替え、`back` では逆に書き替える。帳面に頼らず、道の頭で書き替えるので、移していた間に新しく書かれた行も戻せる。柵: 試験の中の稽古で、承認と止めの数が移す前・移したあと・戻したあとで同じこと。直したら、この写しでもう一度 1 往復する。

### 3. 段 6 の名指しの印【動】

写しに `ws/.name-required` を置き、VM に入っている単位の ExecStart と Environment を読んで、枝のコードの関門（`cli._enter_account_workspace` → `cli._require_workspace_name`）に当てた。

| 単位 | 名指し | 関門 |
|---|---|---|
| `thth@<口座>`（thth-run） | main | 通す |
| `thth-map@<project>` | 無し | **断る** |
| `thth-maintain` | 無し | 通す |
| `thth-meta-keepalive` | 無し | 通す |
| `thth-worker` | 無し | 通す |
| `thth-approval-worker` | 無し | 通す |

- VM に入っている `thth-map@` の単位は古い作りで、`Environment=THTH_WS_FROM_ACCOUNT=1` の行が無い（枝の `systemd_gen` は出す）。**印を置く前に、`thth-map@` の単位を置き直す**（開く日の単位の置き直しと同じ日でよい）。置き直さずに印を置くと、地図の集めが毎日断られる。
- 印を置く段 6 の作業の手順に、「入っている単位を読んで関門に当てる」を先に打つ 1 行として入れる（この書の上の判定を、そのまま本番の単位で打つ）。
