# リリースノート 4.3.0（返信はまとめて出す）

2026-10-19。masaru「返信対応が即時じゃなくて、スケジュールになっちゃうのがちょっとモヤります」「返信が 10 分おきに出る、みたいなオペレーションになるからです」への直し。設計は [上限と連投の柵の「返信の扱い（4.3）」](設計_上限と連投の柵_2026-10-17.md)。

## 起きていたこと

レーン（kopicha など）は人への返信を queue の原稿（`reply_to:`／`reply_to_file:` と `publish_at`）で書き、何本もまとめて承認しています。timer（`thth run`・10 分ごと）は 1 回に `max_per_run`（既定 1）本しか出さないので、まとめて承認した返信が 10 分おきに 1 本ずつ出ていました。投稿の間隔（`min_interval_hours`・kopicha-mastodon と kopicha-bluesky は 6 時間）も返信に掛かっていました。

## 変わったこと

- **timer は時刻の来た返信を 1 回でまとめて出します。** `max_per_run` は投稿（返信でないもの）にだけ掛かります。返信は返信の窓（下）に入るだけその回で出し、超えた分は queue に残って次の回が出します（口座は止めません・`publish_at` は書き換えないので承認の指紋は変わりません）。返信どうしの間は 3 秒置きます。1 回の実行で返信に使う時間は 150 秒までで、超えたら残りは次の回です（Threads は 1 本に 30 秒以上かかるので、1 回でおよそ 4 本）。
- **返信には投稿の間隔（`min_interval_hours`）を掛けません**（timer でも）。返信を出したあとの投稿は今までどおり間隔を待ちます。静かな時間帯（`quiet_hours`）は返信にも掛かります。
- **承認したその場で送ります。** `thth approve --confirm` と `--confirm-file`（2 段目）で確定し push まで通った原稿のうち、返信で `publish_at` が今か過去のものは、同じ命令の中で timer と同じ道（ロック・同期・承認の照合・返信の窓）で出します。出力は「<口座>: 承認して N 本送りました・M 本は返信の窓を超えたので HH:MM ごろの timer で出ます」（`--json` は `sent_now`）。送らないのは、本番でない口座・`scheduled: false`・はてな・媒体の断りで止めた口座・timer が動いている最中（そのときは timer が出します）。投稿と未来の時刻の返信は今どおり timer が時刻に出します。
- **返信の窓は返信だけを数えます。** 柵の行 `reply.burst` は返信だけを数え、既定は 10 分に 10 件（媒体の特性の台帳の Threads・X・Bluesky・Mastodon に根拠つきで置きました。10 という数は媒体の文書には無い THTH の線で、どの媒体の API の上限よりも内側です）。投稿の窓 `post.burst`（10 分に 3 で口座を止める）は返信を数えなくなりました。返信を何本出しても口座は止まりません。1 日の上限（`post.daily`）は今までどおり返信も数えます。

## 変わらないもの

承認の指紋・投稿の振る舞い（1 回 `max_per_run` 本・投稿の窓で止める）・はてなのブログとブックマーク・スレッド連投・断りの符丁。thth.me の `send_request` は今もその場で出し、`schedule_request` は予約のまま timer が出します。MCP には承認の道具がありません。

## 確かめた範囲

試験（偽物の媒体と本物の git の一時 repo）と、柵を 1 つずつ壊して赤を見たこと。本番の媒体ではまだ確かめていません。

## レーンへの使い方の案内

**返信は `publish_at` を今か過去にして、まとめて承認すれば、その場で出ます。** 1 段目 `thth approve <原稿…>` で本文を見せ、2 段目 `thth approve <原稿…> --confirm <束の digest> --by <名前>`（または `--confirm-file`）。返信の窓（10 分に 10 件）を超えた分と、Threads で 150 秒に収まらなかった分は、次の timer（10 分以内）で出ます。急がない返信は今までどおり未来の `publish_at` で予約できます。
