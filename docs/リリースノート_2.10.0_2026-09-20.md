# THTH 2.10.0 リリースノート（プロジェクトのセッション向け）

2026-09-20。VM の `thth` は 2.10.0 になっています。kopicha のセッションが 9/19 夜に書いた使い勝手レポート（11 件のつまずき・6 件の案）への答えと、「開始時に版とリリースノートを確かめる」流れが入っています。設計は `docs/設計_2.10.0_使い勝手と版の確認_2026-09-20.md`。

## 開始時にやること（新しい流れ）

```bash
thth handoff-report <account> --since-last-read --json
```

出力の `tool` に、今の版・前回読んだときの版・変わったか・読むべきリリースノートのパスが入ります。`tool.changed_since_last_read` が true なら `tool.notes_root` 配下の `tool.release_notes` を読んでから作業してください。前回の版は既読の栞（`--mark-read --by <名前>` を打ったときだけ保存）から来るので、初回や栞が無いときは `null` と最新 1 本です。

## つまずきへの答え

- **`where` はオプションを語の前に置けます。** `thth where <account> --recent --limit 12 玉露` が通ります。`--word <語>` で語を明示もできます。
- **Bluesky の投稿は Web の URL で指せます。** `thread`・`send --reply-to`・`after --reply-to`・`replies --post` に `https://bsky.app/profile/<handle>/post/<rkey>` を渡せます。handle は公開 API で DID に解決し、台帳には従来どおり `at://` で残ります。`where` の人向け表示にも `post_id` が並びます。
- **`--json` の標準出力は JSON だけ。** 進捗と断りは標準エラーです。手元のラッパは ssh なので、JSON だけ取るときは `2>/dev/null` を付けてください。
- **dry-run の `send` はロックを取りません。** 採集の timer が走っていても即座に digest が出ます。書く口（`send --production`・`approve`・`replies --refresh`・`revoke`・`retract`）は `--wait <秒>` でロックが空くのを待てます（省略時は従来どおり即断り）。
- **Mastodon の 403 は理由を言います。** 検索なら `read:search`、通知なら `read:notifications` が要ると案内し、`account add`／`token set` の時点で必要な scope 一覧を出します。`doctor` が search と notifications の probe を持ち、`admin tokens` に不足の推定が並びます。
- **`who` は 1 度に 1 人。** 複数渡すと人数と一緒にそう断ります。
- **`approve` はディレクトリを渡せます**（前からです）。`--account <name>` でその account の draft だけに絞れます。glob は手元で展開されるので使わないでください。
- **一段目に字数が出ます。** `文字数: 181/300（bluesky・grapheme）` のように、媒体の数え方と上限つきです。超過なら digest は出ません。
- **相対パスは repo からも探します。** `approve`・`preview`・`lint`・`revoke` で、VM の cwd に無ければ登録された repo の root からの相対として探し、1 つに決まれば使います（どの repo を使ったかを標準エラーに出します）。複数あれば候補を出して止まります。

## 新しい口

```bash
thth mentions <account> --json                 # Threads・Bluesky（mention/reply/quote）・Mastodon（mention）を同じ鍵で。読むだけ
thth unanswered <account> --since 7d --json    # 自分の根投稿への他者の返信のうち、自分の返信が台帳のどこにも無いもの
thth where <account> 玉露 --since 3d --exclude-engaged --max-per-author 2 --json   # 新しさ・既に絡んだ相手の除外・同じ相手の上限
thth study add <施策JSON> <post_id|queueのパス> --by <名前> [--baseline]        # 施策 JSON に post_id を足す（commit はしない）
```

- `unanswered` の `verified: ledger_only` は、枝を読みに行かず台帳だけで判断した印です。`cannot_say` と `collection_stale_hours` を必ず見てください。`handoff-report` にも同じ件数が `unanswered` として載ります。
- `where` の各行に `reply_count`（枝の返信数・取れなければ `null`）が付き、除外した数は `dropped` に出ます。
- `analytics-report` の by_mark に `reposts` が並びます（3 媒体とも採れた値・欠測は `null`・媒体をまたいで足しません）。

## 変わらないこと

承認の 2 段・digest・`--production`・読む口が SNS 台帳に書かない規律。本文と相手名を含まない最小の運用記録（runs）は従来どおり残ります。
