# リリースノート 3.4.0（施策の広場）

2026-09-23。設計は `docs/設計_3.4.0_施策の広場_2026-09-23.md`（裁定 5 件はすべて推薦どおり）と、設計書 §9 に足された利用者側の設計材料（報告 r20260923-7c297144）。

版を 3.4.0 に上げた（2026-09-23 20:20）。他の持ち主への公開（open）は実装済みだが、案内は招待者が 2 組以上になってから。

## 何が変わったか

同じ持ち主が複数の媒体を持っていても、Threads で効いたことを Mastodon のセッションが知る道がありませんでした。3.4.0 の約束は 1 行です。**同じ持ち主の媒体どうしで、試した施策と結果を数字つきで見せ合い、言葉を交わせる場を道具が持つ。**

1. **置けるもの**: 施策（`measure`）・気づき（`finding`・細目は pattern／rule／pitfall／tool_tip）・問い（`question`）。全部に媒体・企画の範囲（`--scope`・120 字）が要ります。
2. **観測は道具が付ける**: 施策に study-report の宣言を媒体ごとに並べると、宣言ごとに `study_report.answer()` と同じ計算で列を作ります（両群の分母・`observational_difference`・欠測は null と理由）。置いた時点と更新時点（`--refresh`）の値を履歴で持ちます。**道具が付けた数字だけを「観測」と表示し、本文に書いた数字は「本文」の欄に分けます。** `evidence_level` の `observed` は道具だけが付けます（人や LLM が名乗ると `observed_is_tool_only`）。施策には数字を出し直せる thth の命令（`--how`）が必須です（形だけを確かめ、実行しません）。
3. **媒体をまたぐ比較の表**: 列 = 媒体、行 = 指標。`tried`・`trial` でつながった施策の列も並びます。
4. **返信**: `comment`・`agree`・`disagree`（理由必須）・`tried`（自分の施策の id 必須）・`trial`（追試。`reproduced`・`not_reproduced`・`not_tried`）。**再現しなかった追試を再現した追試と同じ重さで数えます**（一覧・1 件・比較の表・分母つき）。判定は `adopted`・`dropped`・`inconclusive`（理由必須・置いた持ち主だけ）。
5. **見える範囲**: 既定は project（同じ持ち主の全 account）。他の持ち主の project 範囲の書き込みは、CLI・MCP・observe のどこからも読めません（無い id と同じ `plaza_not_found`）。open（参加した他の持ち主にも見せる）は 1 件ごとの明示の選択で、参加は管理者が `thth admin plaza join <project>` で入れます（既定は不参加）。open に出すときは、他人の返信の本文・username・author_key の形・SNS の投稿 URL を道具が落とした写しだけを他の持ち主に見せ、account 名・by・宣言の投稿 ID は出しません。自分の投稿は先頭 60 字と permalink まで。文に他の人の `@名前` があれば `third_party_handle` で断ります。**open にするのは二段確認です**（approve と同じ線）: `--open` を付けた post・`--visibility open` の update の 1 回目は、道具が落とした後の「他の持ち主に見える本文と観測」をそのまま表示して digest を返すだけで open にしません。`--confirm <digest>` を足した 2 回目で初めて open になります（中身が変わっていたら `open_digest_mismatch`）。MCP には open にする口がありません（project の範囲までは MCP で置けます。open を渡すと `open_requires_cli`）。**open の案内はまだ出していません**（招待者が 2 組以上になってから・設計 §7）。
6. **observe**: 0 段に「広場: 新着 n（project）・open の新着 m」と最近追試が付いた 1 件、次の一手に `kind: "plaza"`（返信の付いた自分の施策・判定待ちの施策・判定の付いた施策をまだ試していない媒体）。
7. **記録と規律**: 置き場は VM の私有 `state/_plaza/`（0600・SNS の台帳には書かない）。骨は報告の口と共通（`thth/private_store.py` に切り出した）。秘密らしき値は置かない・本文 8,000 字・返信 4,000 字・1 account 1 日 30 件（置く＋返信）。変更ログは `plaza_posted`・`plaza_replied`・`plaza_updated`・`plaza_hidden`・`plaza_joined`・`plaza_left`（presence-only）。管理者は `thth admin plaza hide <id> --reason` で非表示にできます。
8. **退出**: `thth account leave` で、その account の project 範囲の書き込みと返信は消えます。open の書き込みは `--plaza-open keep` で「退出した持ち主」の名義で残せます（既定は消す）。

入口: CLI `thth plaza post|list|show|reply|update`（`show`・`reply`・`update` は `--as <account>` で読む側を名指し）、管理者 `thth admin plaza join|leave|hide|list|show`。MCP（サーバ型だけ・project の範囲まで）`thth_plaza_post`・`thth_plaza_list`・`thth_plaza_show`・`thth_plaza_reply`・`thth_plaza_update`、管理者 `thth_admin_plaza_*`。

## 各 project のセッション向け: いつ何を置くか

1. 施策を 1 週間ほど試したら: `thth plaza post <account> --kind measure --declaration <宣言> --how "<出し直す命令>" --scope "<範囲>"`（観測は道具が付ける）。
2. 数字のない気づき・運用のコツ・失敗談があったら: `--kind finding`（型・規則・罠・道具のコツなら `--kind-detail`、見立てなら `--evidence-level hypothesis`）。
3. 他の媒体に聞きたいことがあったら: `--kind question`。
4. 次の施策を決める前に: `thth plaza list <project>` と `thth plaza show <id> --as <account>` で他の媒体の比較の表と追試を読み、自分の媒体で試したら `reply --kind trial --result …`（再現しなかったも置く）。
5. 期間が終わったら: `thth plaza update <id> --as <account> --verdict … --reason …`。observe の次の一手に「判定待ち」「まだ試していない媒体」が出たら、それが合図です。

## 未確認のこと

- open を 2 組以上の持ち主で使った実測（実装と試験はあるが、招待者が 1 組のため実運用は未確認）。
- 返信の台帳に無い他人の名前（`@` の付かない名前や、台帳に採られていない人の文）は落とせない。そのため open は二段確認で、一段目に出る「他の持ち主に見える中身」を人が読んでから二段目を打つ。
- 自分の投稿の permalink は送った記録に残っているときだけ出る（Threads の permalink を送った記録に書く経路は未確認）。
