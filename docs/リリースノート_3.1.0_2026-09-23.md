# リリースノート 3.1.0（毎朝の一枚）

2026-09-23。設計は [設計 3.1.0](設計_3.1.0_毎朝の一枚_2026-09-23.md)。masaru「3.1.0 配って」（同日 08:40）で版を上げた。3.0.0（招待の道の記録・新機能なし）の直後の版。

## なぜ

App Review で開いた読む口（世間の検索・言及・他人のプロフィール・場所）が「あるだけ」で、毎日に束なっていませんでした。**昨日から何があって、今日なにをすればよいか**を、道具が事実だけで 1 枚にします。

## 入った 4 つ

### 1. `thth morning <project|account>`（MCP `thth_morning`）

```bash
thth morning kopicha --json          # 栞を進める（既定）
thth morning kopicha --no-mark       # 進めない
```

6 段（道具・返していないもの・昨日の自分・世間・予定・次の一手）を 1 枚に。既存の口（`handoff-report`・`unanswered`・`mentions`・`measured`・`where`・`schedule`・`queue`・`budget`）を**束ねるだけ**で、新しい集計は作りません。

- **段ごとに独立**。1 段が落ちても他の 5 段は出ます。落ちた段は `{"value": null, "cannot_say": "<理由>"}`——理由は `provider_timeout`・`budget_exhausted`・`scope_missing`・`no_watch_words`・`not_supported`・`unavailable` の 6 語だけ（provider の文面は外に出しません）。
- **数には分母**。取れないものは `null` で、`0` とは混ぜません。
- **`calls`** に媒体ごと・endpoint ごとの回数。言及 1 回／account・語の検索 1 回／語。
- **X の読取予算が 0 なら 1〜3 段を飛ばし**、4 段の予算の行だけ出します。
- **読むだけ**。SNS 台帳には書かず、進むのは栞（`handoff_cursor`）だけ。`--no-mark`・サーバ型 MCP では進みません。
- **`--json` に絶対パス・本文全文を入れません**。本文は先頭 60 字の抜粋だけ（`thth where` と同じ）。
- **「次の一手」は候補の列挙だけ**（masaru 裁定 §7-1）。`body` という鍵はどこにも出ません。

読み方の 1 枚: [毎朝の一枚](使い方_毎朝の一枚_3.1.md)。

### 2. 監視語（`thth admin watch set|show`・MCP `thth_admin_watch_set`）

```bash
thth admin watch set kopicha-threads コーヒー 自家焙煎 --by masaru
thth admin watch show kopicha-threads
```

台帳の `watch_words`（**最大 5 語・1 語 40 字**・loader が他の項目と同じ入口で検査）。**語は管理者が入れます**（masaru 裁定 §7-2）——道具は選びません。語が無い account は 3 段を `no_watch_words` で飛ばします。変更は `watch_set` として管理記録に残りますが、**語そのものは残しません**（presence-only）。

### 3. 世間の検索だけ 40 秒

`GET /keyword_search` の socket 締切を **40 秒**に（`SEARCH_TIMEOUT_SECONDS`）。他の口は 10 秒のまま。2026-09-23 の実測で、10 秒では Meta の索引引きが間に合わず、**切られた側からは 0 件と区別が付きませんでした**。環境変数 `THTH_THREADS_TIMEOUT_SECONDS`（この版で入れた上書き）は両方をまとめて上書きします。

### 4. 開始手順

skill と `docs/使い方_プロジェクトのセッション向け_2026-09-09.md` の開始手順を「**まず `thth_morning`**」に。`handoff-report --since-last-read` を包含します。
