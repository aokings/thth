# THTH 5.28.1（2026-11-23）

5.28.0 のあとの直しをまとめた版です。監査は `docs/監査_5.28.1_2026-11-23.md` です。

privacy の頁と Worker（`callback/`）は変わりません。Worker の deploy は要りません。

| 件 | 中身 |
|---|---|
| Meta の権限を保つ道具（keepalive） | 読む権限は、見張りの印（台帳の `advanced`）が無い Standard の権限も 25 日で最小の読みを打ちます。今までは見張る権限だけを打っていたので、FB・IG の読む権限（例 `pages_manage_metadata`）が使われないまま日が経っても、打つ先が 0 件でした（11/23 運用が見つけた）。Meta の審査は申請の前 30 日に権限ごとの成功した呼び出しを求めるので、使える読みは保っておきます。知らせ（使われていない権限の 1 行）は今までどおり見張る権限だけです |
| keepalive の読みを 2 つ足した | Instagram の `threads_business_basic`（`connected_threads_user` を読む）と `instagram_manage_upcoming_events`（予定を読む）。鍵に乗っていない口座では断られ、`permission_keepalive_denied` と残るだけです（成功に数えません） |
| keepalive で打てない読む権限 | 認可のときだけ使う・相手や id が要る、などで打てない 15 の権限は、理由を表（`permission_watch.NO_KEEPALIVE`）に書きました。読む権限は「打てる」か「表に載る」かのどちらかでないと試験が落ちます |
| 二段確認の一段目を断りに数えない | Meta の書く口（`dm send`・`brand`・`events` など）と、`edit`・`retract`・`inflight`・`shop`・`link`・`register` の route と erase で、一段目（digest を見せて止まる段）のたびに report_channel へ「断られた」と出ていました。一段目には印を付け、断りに数えません |
| タイアップ投稿の断り | 書き方の誤り（印が無いのにブランドの id だけ・id の形が違う・ストーリーと一緒）の断りに、なぜ・直し方・より良くする一手を日本語で添えました。頭の英語の符丁は今までどおりです |
| タイアップ投稿の表示 | dry-run と承認の表示に「タイアップ: 「タイアップ」の印を付けて出します（ブランドの Instagram id: …）」の 1 行を出します |
| 使い方の文書 | `skills/thth/SKILL.md` と `README.md` にタイアップ投稿の口を足しました |
| IG のストーリーズを読む | `thth posts <IG の口座> --stories` で、自分の口座の 24 時間以内のストーリーズの id・時刻・URL を出します（読むだけ）。Threads から共有したストーリーズの id を知るためです。thth.me の鍵の道では読まず、付けたまま打つと断ります |
| `account set` の `instagram_linked` | `thth account set <Threads の口座> instagram_linked true\|false --by <名前>` で、Threads の投稿を IG にも共有できる印を置けます（運営者の CLI だけ・変更ログに残る）。今までは台帳の JSON を手で直していました |
| keepalive の打つ口座の選び方 | 打てる口座の中から選びます。名前順の先頭が広告の口座だと、IG の読み（`threads_business_basic`）の打つ先が 0 件になっていました（監査 L1） |
| healthcheck の理由の読み | 長い数字（IG の id など）の途中の 3 桁を HTTP の番号と読みません（監査 L2） |

残した点:

- `threads_business_basic` は、本番の IG の口座のどの鍵にも乗っていません（doctor で #100）。使うには `thth auth` で鍵を取り直します（人の手の作業）。
- 本物の Meta では、足した 2 つの読みをまだ打っていません。
