# リリースノート 3.16.0（X の自分の投稿の数字・thread --limit・Threads の where --tag／--author）

2026-10-12。masaru 10/12 の決定（`docs/調査_Xで伸ばす_会話の見つけ方と書き方と罰の避け方_2026-10-12.md` §6.1 の 1 と 5）。**下書き・未配布**（push・release・tag は masaru の一言で）。

## 足したこと

- **X の自分の投稿の数字（Owned Reads）**: `thth collect`（timer）が、X のアカウントで THTH から出した投稿（`sent/` に記録があり、取り下げていないもの）だけについて、`GET /2/tweets?ids=…&tweet.fields=public_metrics,created_at,author_id` を刻みを跨いだぶんまとめて 1 回（100 本まで）叩き、`x_metrics.normalize_owned_metrics` に通して `measured` の台帳に足す。刻みは Threads と同じ 1・6・24・72・168・720 時間。指標は views・likes・replies・reposts・quotes・bookmarks（`shares` は X に無いので `null`）。`author_id` が自分でない行は落とす。本文・username は頼まない（`tweet.fields` に text が無い）。
- **費用**: Owned Reads は返ってきた 1 本ごとに 0.001 USD（料金表）。台帳は別のファイル `state/_admin/budget_x_owned_reads.json`。作法は他人の投稿の読み取りと同じ（読む前に本数×単価を押さえ、応答の本数で確定、読めなければ押さえたまま）。1 日 60 本（`x_daily_reads`）には数えない。月の X 予算（`thth admin budget x`）の合計には入る（本人確認・他人の投稿・自分の投稿の 3 つで分け合う）。
- `thth admin budget x` と `thth doctor <X アカウント>` に内訳の行（他人の投稿・自分の投稿の数字）。`--json` は `owned_read`（doctor は `x_costs`）。
- **`thth thread <account> <post_id> --limit N`**（X で 10〜50・既定 50）。1 日 60 本の中で枝の本数を配分するため。範囲外は要求も予約もせずに rc=2。MCP `thread_read` に `limit`。Threads・Bluesky・Mastodon では受けて効かせない（読み取りが無料で、見せる量は既存の `--max-messages`。adapter の読み方を変えると既存の振る舞いが変わるため）。`--json` の `provenance.read_limit` に効いたかどうか。

- **`thth where` の Threads に `--tag`・`--author <username>`**（調査「Threads で伸ばす」§7 決定 1・masaru 10/12「ふたつともやる」）。Threads の `GET /keyword_search` に `search_mode=TAG`・`author_username` を渡すだけ。何も保存しない（本文と username は今までどおり返すだけ）。`--json` の語の節に `query`。MCP `where_to_appear` に `tag`・`author`。X・Bluesky・Mastodon の account では検索せずに `cannot_say`（X は語に `#タグ`・`from:` を書く・Bluesky と Mastodon は `by_tag` を既に返す・`--author` は未対応）。旗を付けなければ要求は今までと同じ。
- 使い方の文書の「トピック検索の権限が降りてこない・ブラウザで確かめる」を、10/9 の承認に合わせて直した。

## 見積もり

2 アカウント × 1 日 3 本 × 6 刻み × 0.001 USD ＝ 1 日 0.036 USD、30 日で約 1.1 USD（上限側。UTC の同じ日の重複控除で 1h と 6h が 1 回分になれば減る）。

## 気をつけること

- 予算が尽きると、X の採取は毎回「採取の誤り」になる（数は採れていない・刻みは進まず次の回で読み直す）。
- X の画面で消した投稿（THTH の取り下げを通っていない）は応答に返らず、刻みの窓（38 日）の間、採取の誤りに 1 行出続ける。
- 手で X の画面から出した投稿は `sent/` に無いので採らない。
- 実 API では未確認: 全件が見つからないときの応答の形（`data` が無く `errors` だけ）と、その課金。0 本で確定にしている。

## 変えていないこと

- 他人の投稿（返信・枝）は timer から読まない（設計 10/8 運用 1・3）。自分の投稿の数字は別の段（設計 10/8 に追記）。
