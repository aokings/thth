# リリースノート 4.3.1（止めた口座では timer は何も出さない）

2026-10-20。masaru 10/20「止めた口座では timer も返信を出さないように直して」、続けて予約の投稿も止めることに「それでよいです」。設計は [返信の扱い（4.3）](設計_上限と連投の柵_2026-10-17.md) の「4.3.1 の追記」。

## 直したこと

- 安全装置か持ち主が止めた口座（止めの印 `guard/stopped.json`・`thth account status` で見える）では、**timer は予約の投稿・返信・スレッド連投のどれも出しません**。4.3.0 までは承認の場の送りと thth.me・CLI の道だけが止めの印を見ていて、timer は止めた口座でも時刻の来た原稿を出していました（3.21.0 から「timer の予約の原稿には掛けない」としていた所）。
- 原稿は queue に残ります（`publish_at` も指紋も変えない）。`thth account resume <口座> --by <名前>` で戻せば、次の timer で出ます。
- timer の log は「<口座> は止まっているので出しません（予約の投稿・返信は queue に残ります。戻すのは thth account resume …）」と言い、終了コードは 0 です（止まっていることは失敗ではない・死活通知を鳴らさない）。runs には書きません。
- 採取（読むだけ）とはてなのブックマークのまとめは今までどおり timer で回ります（ブックマークはそれぞれの安全装置が見る）。
- 止めの印を置けない置き場（モードの緩い置き場など）では、運営者の CLI と同じく印を読みません（印はそこに無い）。印が読めないときは止まっている側に倒します。

## 変わらないもの

承認の指紋・断りの符丁・Worker。Worker の deploy は要りません。

## 気をつけること（運用のレーンへ）

止めた口座に予約の投稿があると、戻すまで出ません。戻したあとの最初の timer で、時刻の過ぎた投稿は `max_per_run` 本ずつ・返信はまとめて出ます。
