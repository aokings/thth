## 5. 撮れない 5 区間を原文で調べた（11/18 夜・masaru「調べて」）

権限の一覧（[Permissions Reference](https://developers.facebook.com/docs/permissions)）には 5 つとも今も載っていて、廃止の印は無い。撮れないのは名前が変わったからではなく、**このアプリから申し込む口が無い**ため。区間ごとの原文と推しは次のとおり（読んで確かめただけ・Dashboard の画面は 11/18 夕に見たもの）。

| 区間 | 原文で分かったこと | 推し |
|---|---|---|
| meta-embed（Meta oEmbed Read）・th-embed（Threads oEmbed Read） | Meta の告知 [Tokenless Access to Meta oEmbed APIs（2026-06-15）](https://developers.facebook.com/blog/post/2026/06/15/tokenless-access-to-meta-oembed-apis/): oEmbed（Threads・Instagram・Facebook の投稿と動画）は**鍵なしで呼べるようになり、公開の物を埋め込むのにアプリレビューは要らなくなった**。鍵つきも使え、上限が高い見込み | **申請から外す**。審査が要らないので撮らない。THTH の埋め込みの口を鍵なしでも呼べるようにするのは別の段 |
| fb-who（Page Public Metadata Access）と fb-search（Page Public Content Access） | [PPMA の原文](https://developers.facebook.com/docs/features-reference/page-public-metadata-access/): PPMA は PPCA に置き換わる。**PPCA と同じ申請、または PPCA が承認済みなら PPMA は申し込めない**。どちらも事業の確認（Business Verification）が要り、追加の契約が要ることがある | **PPCA だけ申し込み、PPMA（fb-who）は外す**。事業の確認の状態を録画の前に見る |
| fb-cta（`pages_manage_cta`） | 一覧に項目はあるが、Dashboard のどのユースケース（ページ・Messenger・Live Video など）の権限の表にも出てこない | **外す**。口が無いので申し込めない |
| fb-dm-profile（`pages_user_gender`・`pages_user_locale`・`pages_user_timezone`） | Messenger のユースケースでは「テスト準備完了」になったが、Facebook Login for Business の構成の選択肢に出ない。構成で認可する THTH の鍵には乗らない | **外す**（計画 §3.4 ④ でも落とす推しだった） |
| ads-network（`read_audience_network_insights`） | 用途は、アプリの持ち主が自分の Audience Network の枠の成績を読むこと。Audience Network のユースケースの中は public_profile だけで、AN の枠（property）の登録が先に要る見込み【推】 | **外す**。THTH は AN の枠を持たない |
| ads-shop（`commerce_account_read_settings`） | [コマース API の設定（2026-06-28 更新）](https://developers.facebook.com/documentation/ads-commerce/commerce-platform/api-setup): **システムユーザーの鍵**で求める権限として、catalog_management・business_management・commerce_manage_accounts などと並ぶ。カタログ API のユースケースの中は catalog_management だけ | **外す**。ショップの設定を読むのは今の catalog_management と ig-shop で足りる |

- 事業の確認（Business Verification）は済んでいた: Business Suite のセキュリティセンターで「株式会社吾徳の認証・元の認証日 Sep 13, 2026・認証済み」（11/18 夜に内蔵ブラウザで見た）。PPCA の前提はそろっている。
