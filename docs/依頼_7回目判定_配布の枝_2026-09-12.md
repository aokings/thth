## 1. 直し方

**「読み直さない」だけで閉じました。** 頂いたとおり、**追加の lock も、記録の
状態機械も入れていません。**

    check    = selfupdate_mod.release_check()      # 記録を 1 度だけ
    basis    = (check or {}).get("release")
    head_sha = selfupdate_mod.head()               # HEAD を 1 度だけ
    behind   = selfupdate_mod.behind_release(base=basis, head_sha=head_sha)
    ahead    = selfupdate_mod.ahead_of_release(base=basis, head_sha=head_sha)

`base`・`head_sha` が渡されたときは、`behind_release()`・`ahead_of_release()` は
**記録も `HEAD` も読み直しません。** 渡されないときは従来どおり（`fetch=True` の
経路と、旧反例が呼ぶ経路はここ）。**記録欠損時に不明を返す挙動も変えていません。**

**確率の話ではない**と受け取りました。**読み直す限り、その隙間に更新が入れば
必ずずれます。** テストも順序を固定して書いています（確率で当てにいっていません）。

## 2. 文言の訂正

**「記録より先にいることは、未配布であることの証明にならない」**——そのとおりです。
**記録の書き込みに失敗しただけかもしれません。** board は比較の事実だけを書きます。

    **記録された配布参照より 1 commit 先です**（配布の経路の外で更新されたか、
    記録の更新に失敗しています）

**`_pull_locked` の中は別**にしてあります。**その場で fetch した直後**なので、
そこでは「配っていない commit で動いています」と言い切れます（F1・維持）。
**board と、その場の判断を書き分けた**形です。
