# リリースノート 3.25.0（返信の連投は止めずに順番待ち）

2026-10-16。kopicha のレーンの頼み（masaru 10/16）。

masaru が「ぜんぶOK」と言った Threads の返信 4 件を `thth send --reply-to` で続けて出したら、3 件目のあとに急な連投（burst・10 分に 3 件）で口座 kopicha-threads が止まり、予約まで止まった。

- **返信（reply_to があるもの）は burst で口座を止めない。** その 1 件を queue に承認済みで置き、`publish_at` を burst の窓が空く時刻（窓の中で最も古い公開・削除 ＋ burst の分 ＋ 1 分）にして、timer に出させる。答えは手元・VM の CLI が `action: queued`・`publish_at`（rc 0）、thth.me の道が `status: queued`・`reason: burst`・`publish_at`。人向けの 1 行は「burst に当たったので HH:MM（JST）に出す順番待ちに並べました。止めていません」。
- **続けて並ぶ返信は後ろへずれる。** 先に並んだ返信がまだ先にあれば、窓が空いていても追い越さない。時刻は「並んだ返信も出来事として数えて、窓に収まる最初の時刻」（`guard.burst_slot`）。timer は 1 回に 1 件ずつ出す。
- **投稿（返信でないもの）は今までどおり止める。** 1 日の上限（`daily_limit`）は返信でも並べずに断る（その日の公開 ＋ 並べた承認済みで数える。予約と同じ数え方）。
- **並べられないときは止めずに断る。** timer に載っていない口座（`scheduled: false`）と添付のある返信は、口座を止めずに `burst_limit`（`next_at` は窓が空く時刻）で断る。`burst_limit` は thth.me の道の断りの名前にも載せた。
- **承認の扱い。** `--production`（手元は digest の `--confirm` のあと）・`send_request` で頼まれた時点で承認されている（3.12.0）。queue には `thth approve` と同じ `approved_fields` で刻み、印 `queued_for: burst` を足す（承認の指紋 `compute_approved_sha` は変えていない・印は指紋に入らない）。手元・VM の CLI の道は `approved_via: cli`・`approved_by` は `THTH_ACTOR`（無ければ `thth send`）で、原稿 `burst-reply-<日時>-<id>.md` を commit・push する。thth.me の道は `held_send` と同じ draft_put ＋ schedule。
- **timer は順番待ちの返信に最短間隔（`min_interval_hours`）を掛けない**（返信には掛けない裁定 (a) と同じ）。ほかの原稿は今までどおり。
- **見分け。** `/activity` に「順番待ち（急な連投の返信）」の行（kind `queued`・取り消せる）、`thth schedule` に「← burst の順番待ち（返信）」、`--json` の行に `queued_for`。
- はてなの口座は対象外（返信が無い）。SNS のほかの動きは変えていない。

## 出し方

Worker が先・VM があと。VM が要約に kind `queued` を載せるので、Worker を先に出さないと（知らない kind で要約ごと断り）`/activity` が古いままになる。利用者の CLI（thth.me の鍵の道）の表示「順番待ちに並べました」は 3.25.0 を入れてから（古い CLI でも並ぶこと自体は VM で効く。表示が「出しました post_id None」になるだけ）。
