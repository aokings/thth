2. 「他人の返信・username の扱いは project 範囲と同じ規律」は、**owner の範囲でも写しを作らず原本を見せる（project と同じ）・道具が自分から他人の返信や username を写さない**と読んだ（`--from` は集計の数字だけ・投稿ごと・枝ごとの行は写さない）。open の二段確認（他人の情報を落とす）の対象外は設計どおり。
3. 組の登録は `set` が組の project を**置き換える**。1 つの project は 1 つの組だけ（`plaza_owner_conflict`）。組の名前は台帳の名前と同じ文字の範囲。台帳に 1 本も無い project 名は断る（綴りの違いで空の組を作らない）。`unset` で組ごと解く。変更ログの diff は組の有無と project の数だけ（project 名は入れない）。
4. B1 の「同じ持ち主の他の媒体」は、**observe の対象の account が書いたものでない**、自分の project と組の他の project の書き込み（open の写しは入れない）で、置いてから 30 日以内・未読のもの。observe が出した 1 件は「読んだ」に控える（翌日以降は出さない）。同じ日にはもう出さない（`picked_today`）。`thth observe --no-mark` では控えない。サーバ型の 1 枚は栞を進めないが、この控えは残す（同じ 1 件を翌日も出さないため）。
5. B1 の「選び方」は重なりの数（自分の project の地図の点・これから出す原稿の goal と topic・題か範囲に含むか）の多い順、同じなら新しい順。原稿は front-matter だけを読む（本文は読まない）。
6. B2 の topic の重なりは、題か範囲（scope）に原稿の topic を含むか（地図の広場の層と同じ照合）。広場の書き込みは topic の欄を持たないため。その account が書いた書き込みは並べない。1 件に出すのは id・題（先頭 60 字）・媒体・重なりの種類（goal・topic）。読めなければ「広場: 言えない: <理由>」で承認は止めない。
7. B3 の案内は足りないものだけ（組に入っていなければ組の命令、open に参加していなければ join の命令）を一覧の先頭に 1 行。両方そろっていれば出さない。
8. B4 は `ask before-you-post` に `--goal` を足した（MCP の `before_you_post` にも `goal`・説明文は動かしていない）。「他の媒体」は台帳の媒体と違う書き込み、「観測」は道具が付けた観測の列の差と両群の分母（3.4.0 と同じ計算）。
9. C1 の `--from analytics-report|after` の引数は置く account と同じ project の account。期間の既定はその命令と同じ（analytics-report 7 日・after 30 日・`--from-window-days` で変える）。`--how` を省けば出し直しの命令で埋める。`--body-file` は任意（下書きの下に足す解釈）。下書きの数字は観測の欄が正なので「本文に書かれた数字」には数えない。open の写しの道具の数字は account 名と命令を落とす（how は従前の写しで見える）。
10. C1 の `--from study-report` は measure だけ（宣言は施策の観測の列になるため）。MCP は `from_tool: study-report` と `declarations` の 1 つ目。how は `thth study-report <パス>`（ホームと `$THTH_ROOT` は畳む）。
11. C2 の commit は「その文書を最後に変えた commit」（`git log -1 -- <path>`）。未追跡・commit していない変更がある文書は断る（どの版か言えないため）。題は最初の `# ` 見出し、無ければファイル名。秘密の検査は写す部分（先頭 4,000 字）に `plaza.post` と同じ検査。
12. C3 は自分の project の報告（project の無い account は自分の account の報告）。写すのは実装側の返事だけで、報告した側の追記は写さない。返事は 6,000 字で切る（本文 8,000 字に解釈を足す余地）。題は報告の題。
13. D1 の「study の期間が終わった」は**広場の施策の `until`** とした（裁定 1・宣言 JSON の形は変えない）。宣言のある施策は観測の取り直し、無い施策は `--from after` で置く命令を出す。「配分を変えた週」は、前回の観測より後に閉じた週（月曜 0 時 JST に閉じる）で、目的ごとの本数の割合（4 語と `none` の割合・`unrecorded` は数えない）のどれかが前の週から 20 ポイント以上動いたとき。候補は置いた account の observe にだけ出す。
14. D2 の「追試の結果を足す」は、期日のあとに同じ持ち主（同じ project）の追試が付けば消える。
15. D3 は置いた account 以外の返信を数える（project 全体の observe では project の外の返信だけ）。分母は置いた書き込みの数と、そのうち知らせのあった数。
16. E の「2 媒体以上」は裁定 2 のとおり: 元の書き込みが observed なら置いた媒体と再現した追試の媒体の和集合（置いた媒体＋他の 1 媒体で 2）、stated・hypothesis は再現した追試の媒体の異なり数。追試が置いた媒体と同じなら媒体は増えない。open の写しと非表示は入れない。本文は出さない（題・範囲・出し直しと id）。MCP の digest は credential の project か、それを含む組の名前だけ。
17. 設計に無いが足したもの: 退出（`account leave`）でその account の「読んだ」の控えを消す。

## 裁定（主セッション 09-24）

1. study の期間は広場の施策の `until` だけでよい（宣言 JSON の形は変えない）→ 実装はそのまま。リリースノートの「未確認のこと」に、repo の宣言だけで回している施策の期間の終わりは次の一手に出ないことを書いた。
2. digest は、置いた媒体を 1 と数えてよいのは `evidence_level: observed` の書き込みのときだけ（「置いた媒体＋再現した追試 1 媒体」で 2）。stated・hypothesis は再現した追試の媒体が 2 つ以上。各行に数え方 → `2762bf5`・試験 2 本・M6。

いま判断が要る点はありません。
