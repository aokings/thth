# 施策レポート v1

2.5.0 から。入力契約は[施策の振り返り設計](設計_v3_施策の振り返り.md)。

```sh
thth study-report /path/to/project/study.json --min-n 5 --json
thth study-report /path/to/project/study.json --min-n 5
```

MCPは `study_report` に `file` と任意の `min_n` を渡す。MCPでは従来のfile引数と
同様、設定済みaccountのrepo_dir配下だけを許可する。CLIは任意のローカル通常
ファイルを読み取る。API、git、投稿、承認、通知、施策ファイルの保存を行わない。

## 宣言の検証

JSONの上限は1MiB、各群1000ID。schema_versionは整数1のみ。設計例の全トップ
キーを必須とし、未知キー・重複キー・非有限数・不正型・ID重複・群の重複を拒否。
文字列の上限はid/account/by=256文字、hypothesis/change=4000文字、ID=2048文字。
空白だけの文字列は不正。入力文字列を指示として実行しない。

`decision` はstatus必須、by/atのみ追加可能。adoptedはby/atが必須。
日時はtimezone付きで生成時刻以前。proposedのby/atは任意だが、指定すれば同じ
検証を行う。proposedは台帳を読まず、observations/comparison/data_updated_atを
nullにする。adoptedでもdecision_provenanceはuser_declared_unverifiedであり、
本人確認・投稿承認・変更が実際に行われたことの証明ではない。

## 観測との結合

report_type=study_review、schema_version=1。declarationとobservationsを分離する。
明示IDだけを対象とし、期間レポートの既定7日などで古いbaselineを落とさない。
baselineはposted_at < decision.at、changedはdecision.at <= posted_at < generated_at。
IDの存在・所有が確認できない場合はunknown_or_unowned_idに統一し、別accountの
値や存在確認を返さない。根/返信分類と実測行の選択は期間比較の共通関数を使う。
根投稿として確認できないものや採用日時の前後が違うものはexcludedに理由を返す。

各群はn_requested/n_excludedと、時間条件対象のn_total/n_eligible/n_missing、
未成熟n_immature/未採取等n_incompleteを持つ。指標別にも有効・欠測の件数がある。
測定条件は[期間比較](分析レポート_v1.md#前期間比較v3-02)と同じ24時間以上30時間
未満。未来観測・collapsed刻み・日時矛盾を使わず、最初の有効観測を一件だけ採用。
返信累積台帳による補完や欠測のゼロ化は行わない。evidenceに採用観測日時・実経過
時間・指標・除外観測理由を含む。投稿本文やusernameを追加しない。

両群がmin_nを満たす指標だけ、中央値の差changed−baselineを返す。
interpretation=observational_difference。因果効果、成功/失敗、推奨ではない。
型の真正性や交絡は未検証。採用観測の最大時刻だけをdata_updated_atとして返し、
全台帳の鮮度や最終採取試行とは区別する。読めない台帳はincomplete_sourcesに明示。
Markdownは同じpayloadから生成し、全文JSONをインデントしたコードとして含む。

## schema_version 1 で追加された鍵（2.6.0）

各観測群の `by_mark/marks_by_post`、中央値の隣の `iqr/min/max/spread_reason`、measurement の四分位定義。n<min_n は全て null、n<4 の IQR は null。上下半分の中央値、奇数中央を除く。既存キーは変更しない。

A8: `cannot_say_details: [{code,text}]` は既存文字列列と同順・同文。コード一覧は分析レポート文書を参照。

A9: `eligibility_forecast` は changed 群の未成熟だけを対象に posts_immature / all_eligible_at / basis=posted_at_plus_24h。最終投稿+24h という予定で採集保証ではない。未成熟が無い・未採用は null、予定があれば forecast_assumes_collection_runs を cannot_say に添える。
