## 1. `thth topics` の views は「実行時点の値」— そのとおりです

`account_report.topic_performance()` は **投稿ごとに API を叩いて数を読みます**
（`adapter.insights(post_id)`）。**台帳の刻みではなく、打った瞬間の値**です。

一方、`thth topics --advise` などが使う `_measured_views_by_topic()` は
**`24 in marks` の行だけ**を台帳から拾います（24 時間時点の値）。

**つまり同じ `thth topics` の中に、2 系統の数字があります。** あなたが混ぜたのは、
**混ざる形で出していたから**です。**時点を書きます。**

## 2. **同じ「トピック」が 2 つあります**（こちらが見つけた本題）

| 口 | 何を「トピック」と呼んでいるか | 出どころ |
|---|---|---|
| `_measured_views_by_topic()` | **原稿由来の記録値**（front-matter `topic:`） | 台帳（24h の刻み） |
| `topic_performance()` | **API 観測値**（`topic_tag`） | API（`fields=…,topic_tag`） |

**別物が、同じ名前で、同じ表に並んでいます。**

**訂正**（masaru 指摘 2026-09-12）: こちらは当初これを「**Threads が勝手に付けて
いるタグ**」と書いた。**付与の主体は確かめていない。** 正しい区別は
**「原稿由来の記録値」と「API 観測値」**であって、**誰が付けたかは別の問い**。

**`specialtycoffee` / `coffee` は API 観測値として実在します。** あなたの
「ローマ字の語が並んでいる」という違和感は当たっていて、**原因はハッシュタグの
拾い上げではなく、2 系統が混ざっていること**でした。

**これが効くところ**: 「トピック選びの効果」を測るとき、**原稿に書いた語の効果と、
API が返してきた語の効果を、同じ表で比べています。** **混ぜたまま「この型は効く／
効かない」と言うと、何を変えれば結果が変わるのかが分からなくなります。**

**さらに時間条件も揃っていません**（masaru 指摘）。**`24 in marks` は「24 時間
ちょうどに採った」ではありません。** 行には実際の `age_hours` があり、
`6.16h で 42` のように**刻みの名前と実経過時間はずれます。** 出所が同じでも、
**実経過時間が違う値を並べて中央値を出すのは比較になりません。**
