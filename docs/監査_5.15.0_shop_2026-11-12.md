   - ちょうど 500 件の店は「読み切れない」になる（5 頁めが 100 件で終わるため。探りで `store_read_incomplete`）【動】。501 件以上の店は基準が取れず、`diff` も `draft` も使えない。断りの文は「開発のセッションへ相談」で、利用者の側に通る直し方が無い。家族の店の商品数を先に見ておく【未】。
   - 頁をまたぐあいだに店の並びが変わると、1 件を読み飛ばして `removed` と言うことがありうる（順番を指定していない）。まれ。`order=created` などを付けると減る【未】（BASE の並びの既定は見ていない）。
   - 写しには在庫の数がそのまま入る（最新の 1 枚だけで履歴は無い）。設計 §4.2 の「1 個ずつの動きは売上の写しになる」に寄せるなら、写しは「在庫あり・なし」だけにできる。`items --json` も在庫の数を出す。

6. 【動】**網の例外の 1 つが断りにならず、そのまま上がる。** `default_transport` は `URLError`・`OSError`・`ValueError` を `store_unavailable` にするが、応答の途中で切れたときの `http.client.IncompleteRead`（`HTTPException` の仲間）は拾わない。探りでは例外がそのまま出た。鍵は例外の文に入らないので漏れはしないが、前向きな断りにならない。`http.client.HTTPException` を拾う組に足すとよい。

7. 【読】**同じホストの中のリダイレクトは追う。** `check_url` が見るのは最初の URL だけで、BASE が `apiv2.thebase.com` の別の道へ 3xx を返せば、鍵を付けたまま追う。相手は BASE 自身で、応答からは許した欄しか取り出さないので害は見当たらない。柵を固くするなら、この口だけリダイレクトを追わない。

8. 【読】**鍵の権限（scope）は見分けられない。** BASE に scope を問う口が無いので、書く権限つきの PAT を渡されても気づけない（設計 §4.5 に書いてある）。コードは GET しか打たないので、害は「漏れたときに大きい」だけ。`thth shop add` の案内と `store_scope_missing` の「もっと良く」が、読むだけの権限で作るよう頼んでいる。店主向けの 1 枚でも同じことを書く。

9. 【読】【動】**断りの目録（19 個）の質。** 19 個とも「なぜ・通る直し方・もっと良く」が揃い、試験が縛る。実際の出方も 3 つ見た【動】（1 行目に符丁となぜ、（）に詳細、次の行に直し方と打つ命令、その次に一手）。責める言い方は無く、鍵を保存しなかった・写しを進めなかった、と今の状態を言う文が多いのがよい。直すと良くなる所:
   - `store_token_expired` は「置いてある鍵の期限が過ぎた」と「`token set --expires` に過去の日を渡した」の 2 つに使う。後ろの場合、なぜの文（「鍵の期限を過ぎています」）は打ち間違いのときに当たらない。「渡した期限の日が今日より前です」の場合を 1 文足す。
   - `store_draft_nothing` は「写しがまだ無い」と「選んだ違いが無い」を 1 つの文で言う。（）の `no_baseline` で見分けられるが、直し方が 2 通り並ぶので、写しが無いときは別の符丁にすると迷わない。
   - `store_read_incomplete` は通る直し方が「相談」だけ。上限（500 件）を文に書くと、利用者が自分の店に当てはまるか分かる。
   - `store_draft_rejected` の「もっと良く」は名前の長さだけ（上の 4）。
   - `store_ledger_invalid` の「運営者が控えを取ってから消し」は、消す命令が無い（上の直したほうがよい 1）。
   - 「BASE が提供するものではない」の 1 行は、3 つの断り（`store_token_rejected`・`store_api_changed`・`store_request_rejected`）と `add`・`whoami`・親の助けに入っている。BASE の窓口へ行きそうな所に絞ってあり、筋は通る。
   - `https://developers.thebase.com/`（PAT を作る所）と `https://apiv2.thebase.com/docs/changelog/` は、実物を開いて確かめていない【未】。
   - 断りのあとの報告の 1 行は `thth report file <account> …` と出る。店の命令では口座が無いので、`<account>` に何を入れるかが分からない。小さいが、初めての人はここで止まる。
