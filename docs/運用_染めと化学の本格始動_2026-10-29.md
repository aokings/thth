## 2. はてなブログとはてなブックマークで masaru の手が要る所

手順の正本は `docs/手順_はてなの口座とOAuthの登録_2026-10-16.md`。今の 5 つのレーン（kopicha・関東・MMR・nigamilab・キョン研）を見ると、レーンごとにはてな ID 1 つ・主体 1 つ（`principals/hatena-<レーン>.json`）・ブログ 1 つ。OAuth アプリは 5 つとも同じ THTH のアプリを使っている（consumer のファイルが 5 つとも同じ中身であることを、値を出さずに `cmp` で確かめた）。

masaru の手が要る所:

1. **はてな ID を作る**（手順 §1）。メインのアカウントのサブアカウントとして作る形（キョン研と同じ）。ID はブログの URL に出るので、名前を決める（例 `sometokagaku`）。サブアカウントが何個まで作れるかは、設定ページで見る。
2. **ブログを作る**（手順 §2）。そのサブアカウントでログインして「ブログを作成」。URL はあとで変えられない。**記事を書く前に、基本設定の編集モードを「Markdownモード」にする**（記事ごとに固定されるので、あとから変えられない）。
3. **THTH の認可**。運用が `thth principal auth hatena-sometoka` を打つと、はてなの認可の画面の URL が出る。masaru がそのサブアカウントでログインしたまま「許可」を押し、出た確認コード（verifier）をターミナルの欄に入れる（10/20 の MMR・nigamilab と同じ形）。

masaru の手が**要らない**所:

- OAuth アプリの登録（手順 §3）は済んでいる。既存のアプリの consumer を写す（`cp -p`・値は見ない）。
- 主体と口座の台帳づくり（`principal add`、それに必ず `principal set … bookmark.lanes sometoka`。空で作られて、10/20 にブックマークが断られた）、`account add … --media hatenablog`、`thth doctor`（AtomPub・フォトライフ・ブックマークの 3 つ）、timer。
- 原稿の置き場は Threads と同じ sparse の写しを使う（`data/hatena/reactions` も写す）。

## 3. 順番の推し

1. 運用: 原稿の置き場を VM に写し、`sometokagaku-threads` の `repo_dir` を直す（今すぐできる・本番は変わらない）。
2. masaru: 利用者の通知先を決める → 運用が config と試し送り。
3. masaru: はてな ID とブログ（Markdown にする）→ 運用が台帳 → masaru が認可の「許可」と verifier。
4. 染めと化学 第9 の原稿と出し方が揃い、masaru が「出して」→ 運用が `production`・`scheduled` を true にして timer を置く。
