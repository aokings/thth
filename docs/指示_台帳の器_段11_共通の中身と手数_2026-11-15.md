## 入れる物

### A. 共通の台帳の備え付けの種類を 3 つ足す（今は operator・account・correspondence）

1. **出典**（書誌だけ）: 題・著者・年・掲載誌・DOI・URL・読める範囲（`access_status`）・権利の条件。各媒体の `sources.csv` と同じ欄の名前に寄せる（こぴちゃ `data/knowledge/sources.csv`・NIGAMI `data/sources.csv` の頭を読む）。DOI か URL のどちらかは要る。
2. **根拠の 1 行**: 出典（共通の出典を指す）・その中の場所（頁・表・図）・要約・数値と単位と条件（あれば）。媒体の切り口と、使ってよいかの判断は入れない。
3. **公開の約束**: 媒体の名前と、about の今の文を写した約束の文（例 NIGAMI の「広告・スポンサー・提供品を受けない・銘柄を薦めない」）。読者に見える文は変えない。

- 各媒体の記録から `共通` の記録を指して、版は `take` が持つ形が今の器で通るかを確かめる（段 3・段 8 の試験を読む）。通らない所があれば直す。
- `thth register add … --common` で写されること。すでに共通の台帳がある所へは、足した種類を入れる道（再び add・または明示の命令）を用意する。前の共通の台帳を壊さない。

### B. R1: 訂正の 1 本の命令

- 仮の名 `thth register fix <台帳> <種類:番号> --set 欄=値 … --reason-text … --by …`（名前は器の命令の並びに合わせて決めてよい）。
- 書く → 判断が要る記録を名指し → 判断を足す → 受け入れの 1 段めを示す。**外れる 0・入る 0・新しい判断だけ**、かつ宣言（出し口か憲法）で許したときだけ、同じ命令の中で封まで進める。それ以外は 1 段めで止めて一覧と digest を出す。
- 柵は弱めない。判断の記録・封・CI の確かめは今のまま。

### C. R2: 出し口を全部 1 回で

- `verify`・`accept`・`export` に `--outlet all`（宣言の全部の出し口）。結果は出し口ごとに分けて出す。1 つでも赤なら全体が赤。

### D. R3: こぴちゃの報告 #7899 の 3 つ

1. `export --check` が違い（`differs`・`stale`・`mixed`・`pending_takes` など）を見つけたら 0 以外で終わる。今は 0。
2. `THTH_ROOT` のフォルダが無いとき、記録の置き場で `register_log_unavailable` で止まる。CI で困らないよう、作ってよい所は作る（作れないときだけ断る）。
3. `row set` が `.thth/kept/` に全部のファイルの控え（こぴちゃで 307 ファイル・14 MB）を作る。台帳が git の repo の中にあるときは、git の履歴と二重になる。変わったファイルだけ控える・git の中では控えを省く、などで育たないようにする。`diff`・`health` など控えを読む所を壊さない。

### E. 見出しだけの表を書き出さない穴（11/15 NIGAMI の写しで見つけた）

- にがみラボの `data/loves/records.csv` は見出しの 1 行だけ（記録 0）。読者の出し口の種類に入っているのに、受け入れが書き出さない（書き出す道が `vessel.all_records` から作られるため。`route.py` の「記録ごとの表とファイル」）。そのため repo の根の同じファイルが「旧い材料」になり、受け入れの 2 段めが `register_material_stale` で止まる。頁がそのファイルを読むなら、書き出さないと build が壊れる。
- 直し: 出し口の種類の置き場に当たる表のファイルは、記録が 0 でも見出しのまま書き出す（指紋も封に入れる）。試験を足す（直す前は赤）。

### F. 直した記録に依る、ほかの記録を名指しする（11/15 NIGAMI の写しで見つけた・考察 2.2 と本線の 11/29 の数 3 の芯）

- にがみラボの写しで根拠 `evidence:ev-bitter-tas2r` の `finding_paraphrase` だけを直すと、`verify` は根拠を名指しで赤にする（`no_inspection_for_new_version`）が、その根拠が支える主張 `claim:clm-bitter-tas2r` は名指しされない。今の「依る欄」（問いの `depends`）は同じ記録の中の欄だけで、記録をまたがない。
- 入れる物: 直した記録（版が変わった記録）と、指す欄（`pointers`）でつながった記録（指す側・指される側、1 段）を「影響の候補」として出す。`verify`・`fix`（B）・`take`（共通の台帳の採り入れ）・`health` の出力に。共通の記録の版が進んだときは、それを指す各媒体の記録も候補に出す（考察 §4.2）。
- 候補は判断を自動で無効にしない（赤にはしない）。名指しして、判断し直すかを LLM の係が決められるようにする。宣言で「この問いは、指す先の版にも依る」と書いたときだけ赤にする形を足してよい（推しで決めてよい）。
- 試験: 根拠を直すと主張が候補に出る・共通の出典を直すと 2 つの媒体の根拠と主張が候補に出る（直す前は出ない）。
