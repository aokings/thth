# リリースノート 4.2.2（1 件の断りでまとめを止めない・sparse-checkout の repo）

2026-10-18。kopicha の本番（VM・kopicha-hatenablog）で起きたことの直し。設計は [S4 §24](設計_4.0_S4_告知とブックマーク_2026-10-17.md)（ブックマーク）と [S6 §17](設計_4.0_S6_反応を記事へ戻す_2026-10-17.md)（sparse-checkout）。

## 起きたこと

1. まとめ承認の 14 件目（コメントに半角「%」）と 26 件目（「%」は無い）で、はてなのブックマークの POST が 401 を返した。同じ token でほかの札・`/rest/1/my` の GET は通る。断られた 2 件はどちらもタグとコメントを合わせた長さが付いた札の最大を超えていた。**原因が「%」か長さかは確定していない。**
2. THTH はこれを認可の問題（`hatena_auth_rejected`）として止め、**10 分ごとに同じ札を 57 回打ち直し**、まとめ全体が止まった。
3. はてなの反応の採取が、repo の sparse-checkout の定義の外（`data/hatena/reactions/`）に書こうとして `git add` が断られ続けた。

## 直したこと

- **1 件だけの 401/403 はその札だけ外す**: POST が 401/403 なら、同じ run の中で `/rest/1/my` を GET して token を確かめます。通ればその札だけの断り（`hatena_rejected_item`・まとめはその札を外して進む・打ち直さない）、GET も断られたら今どおり認可の問題（`hatena_auth_rejected`・`thth principal auth … --force` の案内）。1 件ずつの `add`・`edit` でも文を分けました。
- **断られそうな札の予告（断らない）**: `thth bookmark add`・`edit`・`batch` の 1 段目と `thth lint <札のファイル>` で、コメントかタグに半角「%」がある札（`bookmark_percent_maybe_rejected`）と、`[タグ]…コメント` の形で 135 字か 343 バイトを超える札（`bookmark_length_maybe_rejected`）を予告します。承認の指紋は変わりません。媒体の特性の台帳に観測（確かさ low）を足しました。
- **止まったら打ち直し続けない**: はてなに打って止まったまとめは、60 分は次の run も打ちません。直したらすぐ流すには `thth bookmark batch-resume <口座> --by <名前>`（新しい命令・1 段・札と承認は変えない）。主体の止めなど、打たずに止まる止めは今どおり次の刻みで見直します。
- **sparse-checkout の repo**: 定義の外には記録を書かず、理由と直し方（`git -C <repo> sparse-checkout add <dir>`）を言います。`git add --sparse` で載せると次の同期で git がファイルを作業ツリーから消し、追記の台帳を上書きするため使いません。はてなの反応の採取・SNS の採取は書く前に、THTH が repo に書くほかの道は `git add` の前に確かめます。

## 変わらないもの

承認の指紋・SNS の口座の振る舞い・今の断りの符丁。足した断りの符丁は `hatena_rejected_item`。

## 確かめた範囲

試験（偽物の HTTP と本物の git の一時 repo・はてなには出ない）と、柵を 1 つずつ壊して赤を見たこと。**本物のはてなで、断られる原因が「%」か長さかは確かめていません**（全角の「％」の札・短くした札を本番で試して決めます）。

## 出したあと（運用のレーンへ）

- VM の kopicha の repo で `git -C <repo> sparse-checkout add data/hatena/reactions` を打つ（打つまで反応の採取は止まったまま・`thth run` の log に案内が出ます）。前に書けずに残った台帳も次の run で載ります。
- 止まっているまとめは、4.2.2 を取り込めば次の run で断られた札をもう一度 1 回だけ打ち、また 401 ならその札だけ外して進みます（待たせたくなければ `thth bookmark batch-resume kopicha-hatenablog --by <名前>`）。

## 出し方

VM だけでよい（Worker を出し直す要は無い）。release の枝 → tag `v4.2.2`。
