## 現状（2026-09-10 実測）

| 権限 | テスターのトークンで | 用途 |
|---|---|---|
| `threads_basic` | **効く** | 自分の投稿一覧・本人確認 |
| `threads_content_publish` | **効く** | 予約投稿の公開 |
| `threads_manage_insights` | **効く** | 表示回数・いいね等の収集 |
| `threads_read_replies` | **効く** | 返信の収集 |
| `threads_keyword_search` | **500**（降りてこない） | **トピックに人がいるか確かめる** |
| `threads_manage_mentions` | **500** | 言及を拾う |
| `threads_profile_discovery` | **500** | 公開プロフィールを読む |
| `threads_location_tagging` | **500** | 位置情報 |

Meta は権限が載っていないトークンに対し、403 ではなく**中身のない 500**を返す。
効く 4 つ・効かない 4 つがきれいに割れたので、トークンの scope の問題と判断した
（トークンの再発行では変わらない）。

## 手順（Meta のドキュメントと Dashboard で確認）

1. **ビジネスポートフォリオをリンク**（`/apps/<id>/verification/`）— **未着手**
2. **ビジネス認証** — 法人の書類。日数がかかる（「審査中 10 日以上」の報告あり）
3. **アプリを「公開」にする** — 開発中のアプリは上級アクセスを受け取れない
4. **アプリレビュー**（権限ごと）— 画面録画の提出は 2026-05 に廃止
5. **データの取り扱いに関する質問**

`1回のAPIテスト呼び出しの完了` は済み（2026-09-10 の検証で緑になった）。

**3 が唯一、いま動いているものに触れる段。** 1・2 は触れないので、先に進めてよい。
3 に進む前に、テスターの投稿が公開モードでも続くことを確かめること。

## 申請に書く事実

**アプリの性格**: 1 つの法人が運営する 4 つの Threads アカウント
（苦味研究所・アスモン関東・コピチャ・運営者個人）に、**自社で書いた記事の告知を
予約投稿する**ための内部ツール。第三者に提供していない。

**なぜ `threads_keyword_search` が要るか**（これが本命）:

Threads はフォロワーがいなくてもトピック経由で読者に届く。実測では、フォロワーが
ほぼ 0 のアカウントでも、人が集まっているトピックに載せた投稿は 202〜574 回表示され、
人のいないトピックに載せた投稿は 1 回だった（**約 400 倍**）。

したがって「そのトピックに人がいるか」を**投稿する前に**知る必要がある。現在は
運営者が 1 語ずつブラウザで Threads の検索画面を開いて目視している。**この確認を
API に置き換えたい。** 具体的には、投稿を作る前に候補のトピックを検索し、
直近の投稿の有無と話題の中身を見て、合わないトピックを外す。

**書き込みは行わない。** 検索結果に対する返信の公開（この権限が許す機能）は使わない。

**なぜ `threads_manage_mentions` が要るか**: 自社アカウントへの言及に気づいて返信する
ため。現在は言及に気づく手段がない。

**なぜ `threads_profile_discovery` が要るか**: 返信すべき会話の相手が誰かを確かめるため。

**なぜ `threads_location_tagging` が要るか**: 現時点で用途が無い。**申請しない**
（必要のない権限を求めるのは却下の主な理由）。

**データの扱い**: 取得したデータは自社の git repository（非公開）にのみ保存し、
第三者に提供しない。トークンは運用サーバの `~/.config/`（600）に置き、外部の
サービスに預けない。削除要求とアクセス取り消しの受け口は `https://thth.me/`
（`/data-deletion`・`/deauthorize`）に用意済み。

## 判断の記録

**なぜ取りに行くか**（masaru 2026-09-10）: 法人があるので書類仕事で済む。損が小さい。

**ただし急がない理由**: ブラウザでの目視は 1 語 1 分弱で、実際に運用が回っている
（asmon は 14 語を数時間で確認し、47 本を確認済みトピックに載せ替えた）。
確かめた結果は `thth topics --note` に溜まって全プロジェクトで共有されるので、
**同じ語を二度調べる必要がない。** 認証が通らなくても運用は止まらない。
