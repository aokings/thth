# 調べ: X の投稿を他のサイトに載せる決まり（2026-10-21・THTH開発 第7）

頼み: 本線 第6（MMR が、アーティスト本人の公式アカウントの投稿を、曲の頁の出典＝本人の言葉に使う）。
読んだ原文（10/21）:
- X Developer Policy https://docs.x.com/developer-terms/policy.md
- Display Requirements https://docs.x.com/developer-terms/display-requirements.md

原文は予告なく変わることがある、と原文自身に書いてある。載せる前に、上の 2 つをもう一度開いて確かめる。

この書は、規約が禁じていないことを狭めるためのものではない。原文が求める「載せ方」に合わせるための書。

## 結論（載せ方は 2 つのどちらか）

### A. 埋め込み（publish.x.com の embed）— 推し

- 規約は、埋め込みを強く勧めている。
- 名前・@handle・時刻・X のロゴ・編集・削除・非公開化が、X の側で自動的に今の状態に保たれる。そのため、下の「消された投稿の扱い」をサイトの側で回さなくてよい。
- 注意点は 2 つ。
  - 頁が X の script を読み込む（表示の速さ・外部への通信）。
  - 1 日の表示が 1000 万を超えるサイトは、X に連絡が要る。MMR の規模では当たらない。

### B. 自分で表示する（本文を頁に書く）

規約の表示の決まりを、すべて満たす。

- **作り手**: 顔の画像・表示名・`@handle`（@ をつける）。それぞれ、その人の X のプロフィールへのリンクにする。
- **本文**: 作り手の下に置き、**書き換えない**。要約や抜き出しで変えた文は「投稿」として出さない。地の文で言い換えて紹介するのは、その頁の文章であって、投稿の表示ではない。
- **時刻**: 必ず出し、その投稿の固定リンク（permalink）につなぐ。
- **X のロゴ**: 右上の見える所に置く。
- **操作**: 返信・リポスト・いいねの印を置くか、時刻の横の「View on X」のリンクで代える。ほかの SNS の操作はつけない。
- **中の要素**: @メンションはプロフィールへ、ハッシュタグは X の検索へ、リンクは `display_url` を出して t.co へつなぐ。
- **編集された投稿**: 「編集された」と示し、時刻を今の投稿につなぐ。
- **出どころ**: X が出どころだと分かるようにする（ロゴ・リンクで満たせる）。

## 消された投稿・非公開になった投稿の扱い（B のとき特に）

- 手元に持った X の中身は、今の状態に合わせて保つ。消された・非公開（保護）になった・凍結された投稿は、手元からも消すか直す。
- 時限は「できるだけ早く」。X か持ち主から消してほしいと言われたら、**24 時間以内**。
- 表示に使う本文は、X の API で今の版を取り直したものにする（埋め込みでないとき）。
- MMR の運用の案（推し）: 載せた投稿の id の一覧を持ち、週に 1 回 `GET /2/tweets?ids=`（100 本ずつ・返った本数×0.005 USD）で生きているかを見る。返らなかった id は頁から外す。350 曲×数本なら 1 回 10 USD 前後。この見張りの費用と手間が要らないのが、A の利点。

## 配ること（再配布）

- 他の人や他の道具に X の中身を渡すときは、原則として投稿の id（Post ID）だけを渡す。
- 本文ごとの受け渡しは、人の手で 1 日 500 本まで。
- 頁に載せて公開するのは「表示」で、上の表示の決まりの側。

## 見当たらなかったこと

- 頁で本人の言葉を出典として引くこと自体を禁じる文は、Policy に見当たらなかった。
- 宣伝に使う（商品やサービスを売るために人の投稿を使う）ときは、本人の同意が要る、とある。曲の解説の出典はこれに当たらないと読むが、広告の頁に使うなら確かめる。
- AI の学習に使うことについて、Policy の本文には決まりが見当たらなかった（Developer Agreement は読んでいない）。
