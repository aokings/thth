# リリースノート 3.13.0（承認ページを消す）

2026-09-26。設計: `docs/設計_3.13.0_承認ページを消す_2026-09-26.md`。

見方の一行（masaru・09-26 昼）: **THTH は、SNS を調べ・投稿し・予約する CLI ツール。** だから LLM が操作しやすい。MCP と skill はその補助。thth.me とサーバは、CLI を外の人にも届ける裏方。

masaru の決定: 「不要なところに置かれた金庫なんて邪魔なだけ」。承認ページは選べる設定としても残さず、消す。

**配る順: Worker が先、VM（release）があと。** 3.12.0 の VM は deploy の間も旧 path を叩くので、Worker は 1 版の間だけ旧 path を受ける。

## 何が変わったか

### 1. 承認の関所が無くなった（段 1）

- 公開・返信・削除・予約は、持ち主の LLM か CLI が頼んだら**その場で行う**。安全装置（最短間隔・1 日の上限・連投で停止・夜間・猶予）は変わらない。
- 無くしたもの: `https://thth.me/approve/…`・`https://thth.me/pending`（どちらも 404）、口座の設定 `approval`（none/publish/all）、MCP の `thth_approval_request`・`thth_request_status`、CLI の `thth admin approval request`、招待の `--approval`。
- 台帳に古い `approval` の項目が残っていても読まない（`thth account status` は「古い項目 approval（無視）」と 1 行）。3.11 以前の招待の口座も、この版から承認なしで動く。
- 終わっていない承認 job（`state/<口座>/approval-jobs/*.json`）は、常駐の起動時に `status: expired`（`approval_page_removed`）に書き換えて残す（消さない）。
- 招待の完了ページの「保存して…開く」は `/activity` へ。
- 残すもの: masaru の手元の `thth approve`（自分の repo の 2 段・承認の指紋 `thth/approval.py`）は別物で、変えていない。

### 2. 「承認」の名を外した（段 2）

動きは変えず、名前だけ改めた。旧名は 1 版の間 alias・読み替えで受ける（help に deprecated）。

| 旧 | 新 |
|---|---|
| `thth approval-worker`・`thth systemd --approval-worker`・`thth-approval-worker.service` | `thth worker`・`--worker`・`thth-worker.service`（古い unit は alias で動き続け、`thth board` が入れ替えを促す） |
| `thth admin approver` | `thth admin secret` |
| `thth/approval_jobs.py`・`thth/approval_relay.py` | `thth/worker.py`・`thth/relay.py` |
| Worker `ApprovalPerson`・`ApprovalAccount`・`approval.js`・`approval-object.js` | `Person`・`Account`・`person.js`・`person-object.js`（DO は migration `v7-rename-person` の `renamed_classes` で中身そのまま） |
| VM→Worker の署名つき relay の path `/approval/{person,account,deletion,invite,activity}/*` | `/relay/v/…`（Worker は 1 版の間だけ旧 path も受ける。署名の文字列 `thth-approval-v1` は版ずれで壊さないため変えない） |
| Worker のエラー本文 `approval_unavailable`・`approval_failed`・`approver_exists` | `relay_unavailable`／`activity_unavailable`／`storage_unavailable`・`secret_failed`・`person_exists`（VM は読んでいない） |
| `admin_approval_*` の理由コード（`admin draft put`） | `admin_draft_*` |
| `APPROVAL_PUBLIC_KEY`・`APPROVAL_{PUBLIC,VERIFY,JOB}_LIMIT`・`THTH_APPROVAL_BASE_URL` | `RELAY_PUBLIC_KEY`（`RELAY_PUBLIC_KEY ?? APPROVAL_PUBLIC_KEY` の順で読む）・`RELAY_*_LIMIT`（`namespace_id` は同じ）・`THTH_RELAY_BASE_URL`（旧名も読む） |
| 「承認 secret / Approval secret」 | 「口座の secret / Account secret」（`/activity` に入る・鍵を発行する・止めたのを戻すための本人確認） |

変えなかったもの: admin_log の過去の event 名（`approver_set` 等）、`state/<口座>/approval-jobs/` の置き場、旧い記録 `approval-worker.json`（読める）。`bin/thth-remote` の tty 判定を `admin secret set`／`admin approver set` に合わせて直した（元は当たっていなかった）。

### 3. 文書・規約（段 3）

- 利用規約・privacy: 「毎回本人が承認する」の約束を外し、「持ち主が自分の CLI か AI アシスタントで頼んだときだけ動く・安全装置は持ち主が決める・`/activity` で見る・止める・鍵を発行する」を事実どおりに書いた。施行日はこの版の deploy の日。
- `llms.txt` の冒頭: "human-approval gate" → CLI ツール。
- `docs/導入_招待されたら.md` と `docs/運用_招待する側.md`、skills: 承認ページ・承認待ち一覧・`approval` 設定の記述を外した。
- 申請の手順（`docs/手順_Meta申請_世間の層_2026-09-24.md`）に「承認ページを前提にした部分は使わない」の印。書き直しは外向け CLI の設計と一緒に。録画 0 の道具 `tools/appreview_rec0.sh` は消した。

## 運営者が deploy のあとにすること

1. **Worker を先に deploy**（必須）。新しい Worker は新旧どちらの path も受ける。VM が先に 3.13.0 になると `/relay/v/` を古い Worker が受けられず、招待・`/activity`・退出の relay が通らない。
2. **VM の release**。古い unit `thth-approval-worker` は alias で新しい版のまま動き続ける。`thth board` に「古い unit 名で動いています」と出る。
3. **unit の入れ替え**（root で 1 度だけ・`docs/運用_招待する側.md` §6）:
   ```sh
   thth systemd --worker --credentials /srv/thth/private/report-credentials.json > /tmp/thth-worker.service
   sudo install -m 0644 /tmp/thth-worker.service /etc/systemd/system/thth-worker.service
   sudo systemctl disable --now thth-approval-worker
   sudo systemctl daemon-reload
   sudo systemctl enable --now thth-worker
   ```
4. **Worker の公開鍵の置き替え**（急がない。置き替えるまでは旧名で動く）: `thth admin relay-key show --by masaru` の値を `wrangler secret put RELAY_PUBLIC_KEY` で置き、そのあと `wrangler secret delete APPROVAL_PUBLIC_KEY`。
5. 次の版（3.13.1 以降）で外すもの: Worker の旧 path `/approval/*` の受け口、`APPROVAL_PUBLIC_KEY` の読み替え。
