# リリースノート 3.13.0（承認ページを消す）— 下書き

2026-09-26。設計: `docs/設計_3.13.0_承認ページを消す_2026-09-26.md`。

見方の一行（masaru・09-26 昼）: **THTH は、SNS を調べ・投稿し・予約する CLI ツール。** だから LLM が操作しやすい。MCP と skill はその補助。thth.me とサーバは、CLI を外の人にも届ける裏方。

masaru の決定: 「不要なところに置かれた金庫なんて邪魔なだけ」。承認ページは選べる設定としても残さず、消す。

**配る順: Worker が先、VM（release）があと。** 3.12.0 の VM は deploy の間も旧 path を叩くので、Worker は 1 版の間だけ旧 path を受ける。

## 何が変わったか

### 1. 承認の関所が無くなった（段 1）

- 公開・返信・削除・予約は、持ち主の LLM か CLI が頼んだら**その場で行う**。安全装置（最短間隔・1 日の上限・連投で停止・夜間・猶予）は変わらない。
- 無くしたもの: `https://thth.me/approve/…`・`https://thth.me/pending`（どちらも 404）、口座の設定 `approval`（none/publish/all）、MCP の `thth_approval_request`・`thth_request_status`、CLI の `thth admin approval request`、招待の `--approval`。
- 台帳に古い `approval` の項目が残っていても読まない（`thth account status` は「古い項目 approval（無視）」と 1 行）。3.11 以前の招待の口座も、この版から承認なしで動く。
- 終わっていない承認 job（`state/<口座>/approval-jobs/*.json`）は、常駐の起動時に `status: expired`（`approval_page_removed`）に書き換えて残す（消さない）。
- 招待の完了ページの「保存して…開く」は `/activity` へ。
- 残すもの: masaru の手元の `thth approve`（自分の repo の 2 段・承認の指紋 `thth/approval.py`）は別物で、変えていない。

### 3. 文書・規約（段 3）

- 利用規約・privacy: 「毎回本人が承認する」の約束を外し、「持ち主が自分の CLI か AI アシスタントで頼んだときだけ動く・安全装置は持ち主が決める・`/activity` で見る・止める・鍵を発行する」を事実どおりに書いた。施行日はこの版の deploy の日。
- `llms.txt` の冒頭: "human-approval gate" → CLI ツール。
- `docs/導入_招待されたら.md` と `docs/運用_招待する側.md`、skills: 承認ページ・承認待ち一覧・`approval` 設定の記述を外した。
- 申請の手順（`docs/手順_Meta申請_世間の層_2026-09-24.md`）に「承認ページを前提にした部分は使わない」の印。書き直しは外向け CLI の設計と一緒に。録画 0 の道具 `tools/appreview_rec0.sh` は消した。
