# THTH 5.14.0（2026-11-09）

5.13.0 のあと、2026-11-08〜11-09 の開発をまとめて出す版です。中心は 3 つあります。

- Meta の 1 回の申請に向けて、新しい口を足しました。対象はブランドとクリエイター、会話の出来事、認可のときのメール、商品タグ、WhatsApp です。
- 本物の Meta で打って分かったことを直しました。
- privacy の文を今のコードに合わせました。

新しい断りの符丁は 14 個です。`since` はこの版で "5.14.0" にそろえました。

## 新しい口（Meta の申請のため）

ここに足した口は、どれも偽の Graph の試験で確かめました。**本物の Meta ではまだ打っていません**（下の「本物でしか分からないこと」）。

- **ブランドコンテンツとクリエイター**（`thth brand …`・2949689・`thth/meta_brand.py`）
  - Instagram と Facebook のブランドコンテンツの承認を読み書きします。
  - クリエイターマーケットプレイスでクリエイターを探します。
  - 6 権限ぶんの最小の口です。書く口は二段の確認つきです。
- **会話から起きた出来事を Meta に送る**（`thth dm event`・1c5a5e0・`thth/meta_events.py`）
  - 会話から起きた購入などの出来事を送ります。
  - 相手の id や金額はファイルに残しません。二段の確認つきです。
  - WhatsApp の側は、dataset の path を確かめるまで断りで止まります。
- **認可のとき 1 回だけ読むメール**（1c5a5e0）
  - 持ち主が Meta で認可するとき、メールを 1 回だけ読んで見せます。保存はしません。
  - 外の人の招待の範囲にはまだ載せていません。Worker の認可の範囲を直すのが先です。
- **Instagram の商品タグ**（`thth shop …`・e500d33・`thth/meta_shop.py`）
  - タグを付けられるかを確かめ、投稿に商品を付けます。
  - Meta にタグを外す口が無いので、外す命令はありません。
- **WhatsApp**（`thth wa add|auth|numbers|templates|template create|send|stop`・2c388f4・`thth/wa/`）
  - 広告と同じ形で、専用の台帳 `waba/<名前>.json` と専用の認可を持ちます。
  - 送れるのは承認済みのテンプレートだけです。自由文は送りません。
  - テンプレートの作成と送信には、`thth dm send` と同じ型の柵を付けました。二段の確認・production・止めの印・1 日の上限・ロックです。送った数を記録から読めないときは、送らない側に倒します。
  - ただし `dm send` が会話の窓の開いた相手にだけ送れるのと違い、`wa send` は持ち主が渡した番号に送ります。相手の同意（opt-in）は持ち主が取ります。
  - 送った相手の番号と本文は、どのファイルにも残しません。

## 直したこと

- **Instagram のいいね**（a15a287）
  - 口を `POST|DELETE /{ig-user-id}/likes` に `media_id` を渡して打つ形にしました。
  - 5.13.0 の形は、本物では code 100・subcode 33 で断られていました。
- **Facebook のページ検索**（a15a287）
  - Authorization Error を、「機能の審査が要る」という断りにしました。
  - subcode 33 のときに、認可のし直しを勧めないようにしました。
- **subcode 33 の文面**（監査 5.14.0）
  - 投稿だけを前提にした言い方をやめ、「この操作の対象の id が無いか、この鍵から見えない」と言うようにしました。
- **`brand promote` に `--sponsor` だけを渡したとき**（監査 5.14.0）
  - 黙って読むだけで終わっていました。いまは `brand_args_invalid` で断り、通る打ち方を示します。
- **未承認の数え上げ**（c43875e・運用 #7293）
  - 予約を使わない口座（`scheduled: false`）を 0 と数えるようにしました。
- **申請の台帳**（163b0fd）
  - 成功の呼び出しを作れない 5 権限を、理由つきで DROPPED へ移しました。
  - WhatsApp の 2 権限は、口ができたので PLANNED から外しました。残りの PLANNED は 3 です。

  - id・時刻・種類・数だけの通知: Threads と、Instagram のコメント・ストーリー。

  - 返信・数・再投稿といいね、求めたときの検索と会話の読みを書きました。

  - 答えは「持ち主（と持ち主が選んだ AI の助手）に見せるだけで、THTH は保存しない」と書きました。

- 関門（`tools/release_gate.py`）が、施行日が未設定のまま出すのを止めるようにしました。符丁は `release_privacy_date_unset` です。

## 出すときに一緒にすること

- `tools/build_site.py` の `PRIVACY_EFFECTIVE` に deploy の日を入れて生成し直し、commit します。
  - そのあと CI と関門を通します。施行日が入っていないと、関門が止めます。
- Worker を先に deploy し、VM はそのあと（release の枝）に出します。tag `v5.14.0` で PyPI と MCP registry に出ます。
- WhatsApp・メール・出来事の権限を外の人の招待に載せるのは、Dashboard の構成ができてからです（masaru の手）。この版では載せていません。
- 出したら、運用（SageFinch）に知らせます。
