# URL の使用を限定した期間（masaru 裁定 2026-09-12・5 番）

## なぜ要るか

`clicks` は **URL ごとの内訳（`clicks_by_url`）しか無く、どの投稿が生んだクリックかは
台帳に無い**。同じ URL に過去の投稿・プロフィール欄・外部からの流入が乗る。

**ある期間、ある URL を 1 本の投稿にしか載せなければ、その期間の `clicks_by_url` は
その投稿に帰属できる。** その期間を記録できるようにするのがここ。

**宣言だけで条件が守られたとは扱わない。** 期間が終わったら**実績と照合**し、
照合できるまでは `照合` 欄を空にしておく（空欄＝未照合。**「守られた」ではない**）。

## 書き方

1 期間 1 行。**終わってから書くのではなく、始める前に書く**（後から書くと、
都合のいい期間だけが残る）。

| 欄 | 書くこと |
|---|---|
| `account` | 対象アカウント（`kopicha-threads` など） |
| `URL` | 対象 URL。**同一性の扱いも書く**（下記） |
| `開始`・`終了` | JST・ISO8601。終了未定なら `終了` は `(未定)` |
| `制約` | その期間に守ること（例: この URL を載せる投稿は 1 本だけ） |
| `例外` | 制約の外に置くもの（例: プロフィール欄の固定リンクは外せない） |
| `投稿 ID` | **実際に出た投稿の ID**。出てから書く |
| `照合` | 期間後に実績と突き合わせた結果。**未照合なら空** |

### URL の同一性

**どこまでを「同じ URL」と見なすかを、期間ごとに書く。** 既定は次のとおり。

- **クエリ・フラグメントを落として比較する**（`?utm_*`・`#...` は同じ URL と見なす）
- **末尾の `/` の有無は同じ**と見なす
- **短縮 URL・リダイレクタは別の URL**（台帳には踏まれた先ではなく載せた URL が並ぶ）
- `http` / `https` は同じと見なす

既定と違う扱いにするなら、その行の `URL` 欄に併記する。

## 照合のしかた

期間が終わったら、次の 2 つを突き合わせる。**片方だけでは足りない。**

1. **載せた側**: その account の queue のうち `status: posted` で `posted_at` が期間内、
   かつ本文にその URL を含むものを数える。**1 本でなければ制約は守られていない。**
2. **踏まれた側**: `data/sns/insights/account/<account>-<年月>.ndjson` の期間内の行から、
   その URL の `clicks_by_url` を拾う。

**1 が 1 本のときだけ、2 をその投稿に帰属させてよい。** 2 本以上あったら、
**その期間は比較材料にしない**（クリックは分けられない）。

**`照合` 欄には「守られた／守られなかった」と、載せた側の本数を書く。**
**「守られなかった」も消さずに残す**——守れない条件だったという観測。
