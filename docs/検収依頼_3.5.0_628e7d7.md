## 設計から外れた点・解釈した点

1. **外部 LLM への受け渡し（照合 §6-8）は、`THTH_MAP_WORLD` の 1 つのスイッチに畳んだ**。集めるのも見せる（CLI・MCP・observe）のも同じスイッチで、有効にする前提に Service Provider の条件を含めると `map_view.world_enabled()` の説明とリリースノートに書いた。LLM に渡る口だけを別のスイッチで閉じる形は作っていない（CLI の出力もセッションの LLM が読むため、口で分けても境界にならないと読んだ）。
2. **世間の検索は `where_cli.answer()` を呼ばず、同じ計算（`threads_read_cli.search_material()`）と同じアダプタの入口を使った**。`answer()` は Bluesky・Mastodon でタグの検索を追加で呼び、自分の履歴を読み、本文の先頭と permalink・post_id を返すので、「点ごとに検索 1 回」「本文を持たない」に合わない。
3. **広場の書き込みは語の一致で点に結ぶ**（title か scope_note に点の語が含まれる・NFKC と大文字小文字を畳む）。広場の記録に `topic` の欄は足していない（3.4.0 で置いた書き込みもそのまま結べる・記録の形を変えない）。語が短いと取りすぎる（「茶」が「喫茶」にも当たる）。
4. **退出は「止める前」に地図を消す**。最後の account なら project の地図を丸ごと、他の account が残るならその媒体の集計の行だけ（点と線は残る持ち主のもの）。完了した退出の記録には project が残らないので、完了後に消すと再試行で project が分からなくなる。地図の置き場が壊れていれば何も止めずに `map_cleanup_incomplete`（変更ログの事前検査と同じ筋）。
5. **共起は向きのある本数**（点 A の結果のうち B を含む本数・分母は A の n）。co が 0 の線は行を作らない（A の行が読めれば 0 と読める）。
6. **observe の「伸びた点・強まった線」は世間の層の行だけから決める**。無効のあいだは点と線の数と `world_layer_disabled` だけが出る。
7. **LLM が包含の線の候補を出す口は作っていない**（設計 §1「LLM が候補を出し、人が `--by` で確定」）。skill に「候補を人に出すのはよいが、あなたが点を足さない」と書いた。点と線を足す口は MCP に出していない。
8. **systemd の timer（`thth systemd` の生成）には map collect を足していない**。世間の層は既定で無効なので、有効にするときに管理者が timer を書く。collect は 1 日 1 回を自分で守る（同じ日・同じ媒体の行があれば叩かない）。
9. 変更ログの `map_purged` は削除の依頼と退出の両方で書く（退出は `by` に退出の実行者）。
10. 地図を読む CLI（`thth map show`）は `read_coordination` の読む口の一覧に足していない（広場の CLI と同じ扱い）。
