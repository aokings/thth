## 設計から外れた点・決めたこと

1. **判定のコードだけの変更は一段**（件 3 (a)）。依頼の「判定のコードだけの変更で写しが変わらないなら一段」を、「写し＝他の持ち主に見える文・観測の列・伏せた数。判定のコード（adopted 等の静的な符丁）は写しに数えない」と読んだ。コードは他の持ち主にも見えるが、他人の情報が混ざりようがない。二段目の照合はコードも含む見える姿の全部。
2. **MCP から写しが変わる open の更新も `open_requires_cli`**（件 3 (a)）。依頼が MCP の断りを明記しているのは (b) の返信だけ。MCP には二段目（`confirm`）が無いので、写しを変える更新は (b) と同じく人の CLI に回した。写しが変わらない更新は MCP から従前どおり一段。
3. **同じ持ち主の返信も、対象が open なら二段**（件 3 (b)）。open の 1 件への返信は、書いた持ち主のものでも他の持ち主に写しで見えるので、依頼の「open の書き込みへの返信は…二段」を返信する側の持ち主を問わず当てた。
4. **退出の記録があれば sudo を叩き直さない**（件 1）。「`sudo -n` で 1 回だけ試み」を、leave を打ち直しても 1 回と読んだ。止め残しは記録の命令で運用者が止める。3.5.0 以前に完了した退出（`timers` 無し）を打ち直すと、1 回だけ試す（kopicha-server-mastodon のように手で止めた後なら `no_units` か、unit file が残っていれば `disable --now` の空打ち）。
5. **orphan の判定から `disabled` の unit file を除いた**（件 1）。`disable --now` の後も unit file は `/etc/systemd/system` に残り `list-unit-files` に出るので、除かないと止めた後も orphan と言い続ける。unit file の削除は道具ではしない。
6. `by_account` から台帳の無い account（退出済み）を外した（件 1）。以前は `leave.names()` の account も `timer()` で観測して timers.json に書いていた。依頼の「timers.json から台帳の無い account の記録を消す」に合わせ、その account は `orphans` だけに出る。
