## 1. Bluesky 側でやること（masaru の手・**L3**）

1. Bluesky のアカウントを 1 本作る（無料）。handle は `<なまえ>.bsky.social`。
2. 設定 → プライバシーとセキュリティ → **App Passwords** で 1 本発行する。
   形は `xxxx-xxxx-xxxx-xxxx`。**発行画面を閉じると二度と表示されません。**
3. **アカウントのパスワードは使いません。** App Password は管理画面から取り消せますが、
   アカウントのパスワードは取り消せません。`thth auth` は App Password の形でないものを
   **loud に断ります**（`allow_any_password` は `auth_interactive()` の Python 引数で、
   **CLI からは通りません**——App Password の形でなければ断る・**L1**）。

## 2. 台帳（`accounts/<account>.json`）

Bluesky で足す項目は 2 つだけです（設計 v2 §4.2「台帳と登録」・**L2 相当の設計判断**）。

| 鍵 | 値 | 備考 |
|---|---|---|
| `media` | `"bluesky"` | `REGISTRY` の登録名。**知らない `media` は知っている一覧を添えて断られます** |
| `service` | `"https://bsky.social"` | 自前 PDS を使うならその URL。既定はこれ |
| `handle` | `"<なまえ>.bsky.social"` | 人向けの URL（`https://bsky.app/profile/<handle>/post/<rkey>`）を組み立てるのに使う（**L3**） |
| `char_limit` | 省略可 | 省略すると媒体の既定 **300**（**L2**: `app.bsky.feed.post.text` は maxGraphemes 300） |

`queue` の節の名前は媒体名なので **`## bluesky`** です。1 つの queue ファイルに
`## threads` と `## bluesky` を並べれば、2 つの account がそれぞれ自分の節を拾います。

**`topic` は Bluesky には無いので黙って無視されます**（設計 v2 §4.2。Threads と
Bluesky で同じファイルを共有できるようにするため・**L1**）。

## 3. 認可とトークン

```
thth auth <account>
```

handle と App Password を聞きます（**値は画面にも log にも出ません**）。中身は
`com.atproto.server.createSession` で 1 回検証してから
`~/.config/thth/<account>.token`（600）に書きます（**L1**: 検証は
`thth.adapters.bluesky.auth_interactive()`。書き込みは呼び手）。

トークンの中身:

```json
{"identifier": "<handle>", "app_password": "<App Password>",
 "did": "did:plc:…", "handle": "<handle>",
 "no_expiry": true, "obtained_at": "2026-09-13T12:00:00+09:00"}
```

- **`no_expiry: true` は「判らない」ではなく「期限を持たない」の印**です。Threads の
  ような 60 日の延長（`refresh_access_token`）はありません。`maintain` はこれを見て
  `token_state: ok` / `remaining_days: null` と言い分けます（設計 v2 §4.2）。
- アダプタは**実行ごとに 1 回** `createSession` を叩いて `accessJwt` を得ます
  （**L1**）。呼び出し上限は 30/5 分・300/日と読んでいます（**L3**）。10 分刻みの
  timer なら足ります。
- 取り消したいときは Bluesky の管理画面で App Password を revoke してください。
  `.token` を消すだけでは Bluesky 側に鍵が残ります。

## 4. 確かめる

```
thth doctor <account>      # createSession → app.bsky.actor.getProfile の 2 件（L1）
thth throw <account>       # --production を付けなければ dry-run が既定。何も送らずに選ぶところまで（L1）
```

`doctor` が `createSession ○ / getProfile ○` なら通っています。落ちたときの `detail`
には**秘密が入りません**（App Password も `accessJwt` も `***` になります・**L1**）。

## 5. Threads と違うところ（読む前に知っておくこと）

| こと | Threads | Bluesky | 証拠 |
|---|---|---|---|
| 投稿 | コンテナ作成 → 30 秒待つ → 公開の 2 段 | `com.atproto.repo.createRecord` の 1 発。**コンテナも待機もありません** | **L2** |
| リンク | 本文に URL を書けば勝手にリンクになる | **`facets`（UTF-8 の**バイト**位置）を付けないとリンクになりません。**アダプタが本文から URL を拾って付けます | **L2**（`app.bsky.richtext.facet#byteSlice` は「UTF-8 のバイト、start は含み end は含まない」と明記） |
| 返信 | `reply_to_id` だけ | `reply: {parent: {uri,cid}, root: {uri,cid}}` の両方が要ります。**親が返信ならその根を引き継ぎます**（親を根にすると同じ話の続きが別スレッドに生えます） | **L2** |
| 文字数 | 500（絵文字は UTF-8 バイト） | **300 grapheme** | **L2** |
| views | 取れる | **取れません。**`app.bsky.feed.defs#postView` に views に当たる項目がありません | **L2** |
| 指標 | views・likes・replies・reposts・quotes・shares | **likes・replies・reposts・quotes だけ** | **L2** |
| 期限 | access token に 60 日 | **無し**（App Password） | **L2** |

**views が無いことの影響**: 実測の行は `views: null` になり、`comparable_views` は
理由「媒体に views が無い」で**除外して数えます**（**捨てない・数える**・設計 v1 §3.2.2、
設計 v2 §4.2「採集と実測の媒体差」）。**媒体をまたいで比較はしません**（設計 v2 §2.1）。

## 7. VM で実物を試す手順

1. 手元（Mac）で台帳 `accounts/<account>.json` の `handle`/`instance` を実在の
   アカウントに直す。必要なら `production: true` にする。commit して `main` へ
   push し、**masaru の一言で `release` を進める**（設計 §3.2.1）。**VM で
   pull コマンドは打たない**——VM は `thth run` の中で `release` を自分で
   `merge --ff-only` して追う（`main` を引かない）。
2. VM で認可する（値は画面にも log にも出ない）。
   - Bluesky: `ssh -t wt 'thth auth masaru-bluesky'`
   - Mastodon: `ssh -t wt 'thth token set masaru-mastodon'`
3. `ssh wt 'thth doctor <account>'` で通っているか見てから
   `ssh wt 'thth throw <account>'`（`--production` を付けなければ dry-run が
   既定。何も出ない）。台帳の `production: true` が配布済みなら
   `ssh wt 'thth throw <account> --production --now'`（ここで初めて 1 件
   出る）。1 時間後以降に `ssh wt 'thth collect <account>'`・
   `ssh wt 'thth replies <account>'` で採る。
4. 原稿は queue に `## bluesky` / `## mastodon` の節を持つファイルを
   `thth approve` で承認しておく。
