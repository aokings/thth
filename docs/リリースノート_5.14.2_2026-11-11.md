## 直したこと

- **実行記録に書けないときは画面に知らせる**（`thth/meta_write.py` の `record_failed`・`thth/wa/cli.py`）
  - Meta に書いたあとに実行記録（runs）が書けないと、今までは黙っていました。いまは「注意: 実行記録（runs）に書けませんでした…この実行は記録に残っていません」と stderr に出します。
  - WhatsApp の送信では、あわせて「この 1 通は今日の通数に入っていません」と出します（1 日の上限は runs で数えるため）。
- **privacy の X の項の柵を両向きにした**（`tests/test_privacy_matches_code.py` の `_x_mismatches`）
  - 今までは「口があるのに文が無い」だけを縛っていました。いまは「口が無くなったのに文が残る」も赤にします。
- **危ない領域に広告の書く口と認可を足した**（`tools/release_gate.py` の `DANGER_AREAS`）
  - `ads_write`: `thth/ads/graphwrite.py`・`ops.py`・`budget.py`
  - `oauth`: `thth/oauth.py`・`thth/ads/auth.py`
  - `thth/adapters/facebook.py`・`instagram.py` の `_write` は入れていません。読む口と同じ大きなファイルで、入れると読みの直しのたびに監査が要るためです（表の注に書いた）。
- **運用通知の表示を静かにした**（`thth/cli.py` の `_notify`・運用 11/10 の知らせ）
  - メールの宛先が無く、止まりを hub が拾う口座（`hub_reads_stuck`）では、「運用通知に未完了があります」を出しません。中身は `thth notifications status` に今までどおり出ます。
  - 同じ repo の別の口座の回と錠がぶつかったとき（kopicha-ig と kopicha-threads は同じ分に回る）は、「完了できませんでした」でなく「次の回に回します（`incident_notification_busy`）」と言います。hub が拾う口座では黙ります。ほかの例外は今までどおりです。
- **はてなの記事の commit の確かめが、git の索引の食い違いで止まらないようにした**（`thth/hatena_entry.py` の `committed_commit`・にがみラボ 11/10 の知らせ）
  - `git log` が「commit-graph にあるのに object に無い」で落ちたら、commit-graph を使わずに辿り直します。
  - それでも読めないときは、今までどおり `article_not_committed` です。断りの文に「commit してあるのに出るときは、次の取り込みのあとに打ち直す・治らなければ git fsck」を足しました。
- **試験の揺れを直した**（`tests/kept_bytes.py`）
  - 「何も残さない」試験が、git の reflog の時刻（1762737001）の中の数字を目印（7001）と取り違えて、CI がたまに落ちていました。reflog は文の所だけを見ます。
