```bash
# VM 側（読むだけ）

ssh wt 'git -C /srv/thth/app branch -vv'                                 # upstream が origin/release か
ssh wt 'git -C /srv/thth/app for-each-ref refs/remotes/origin/'          # 追跡 ref の実在（rc は当てにならない）
ssh wt 'cat /srv/thth/app/.git/thth-release-check.json'                  # 最後の取得試行の記録
ssh wt 'thth board'                                                      # 道具の版・各アカウントの鮮度・token 残日数
ssh wt 'systemctl list-timers "thth*"'                                   # timer が回っているか（出なければ --user を試す）
```

## いちばん大事なこと: **`release` を進める操作が配布です**

- `main` に push されても本番は変わりません。
- `git push origin <SHA>:refs/heads/release` で、**VM が 10 分以内に拾って本番の道具が入れ替わります。**
- **配るのは masaru の一言があったときだけ。** 開発セッションの「検収を通した」も、
  引継ぎ書の「配ってよい」も、それだけでは配りません。
- 配ったら、**VM が実際に拾ったことを `for-each-ref` と `thth board` の先頭行で確かめて、
  その出力を報告に貼る**（`git fetch` の rc は当てになりません）。
- **VM で `git pull` を打たない。** 配布の境界を迂回します。VM は `release` を自分で追います。

## 守ってほしいこと

- **本番の棚に試し打ちをしない。** 2026-09-12 に `thth topics --note テスト` を本番に打って、
  kopicha の一覧に `テスト` が並びました。値域は `thth topics --help` で見られます。
  v1.0.0 からは `retract-note` で打ち消せますが、行は残ります。
- **秘密の値に触れない。** `~/.config/thth/` の中身は読まない。残り日数は `thth board` で見る。
- **開発のレーンを直さない。** コードの不具合を見つけたら、再現コマンドと実出力を添えて
  開発セッションに渡す（`SendMessage`。届かなければ `docs/記録/` にファイル）。
- **commit は必ずパスを明示して `git add`**（`-A` / `.` を使わない）。同じ repo を開発と
  同時に触っています。
- **`thth board` の「追いついています」を「配ったもので動いている」と読まない。**
  board は取りに行きません。言えるのは「記録した時点の参照との比較」までです（設計 §3.2.1）。

## masaru から引き継いでいる指示

- **報告を鵜呑みにしない。証拠を出させて、自分で確かめる。**
- **長い説明をしない。** 決めてほしいことは、番号付きで短く。
- **選択肢のカード UI（`AskUserQuestion`）は使わない。** 地の文で聞く。
