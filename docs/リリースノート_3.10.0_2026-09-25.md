# リリースノート 3.10.0（招待リンク）— 下書き

2026-09-25。設計は `docs/設計_3.10.0_招待リンク_2026-09-25.md`、背景は `docs/計画_Meta申請_2026-09-25.md` の #1（Meta の審査員が自分のテスト口座で入れる道）。

版はまだ上げていない（3.9.1 のまま・tag なし）。**Worker（`callback/`）の deploy が要る**（Durable Object `InviteObject` の追加と migration `v5-invite`・`/invite/*` の経路）。deploy は masaru の一言で主セッションが打つ。deploy 前に `thth admin invite create` を打つと、Worker が知らない道なので `invite_registration_rejected` で止まる（招待は作られない）。

## 何が変わったか

1. **招待リンク**: `thth admin invite create --media threads --project <p> --label <控え> --expires 30d [--production] --by <名前>`。招待 URL（`https://thth.me/invite/<code>`）を tty に 1 回だけ出す。VM に残すのは code の SHA-256 だけ。期限は 1〜90 日（既定 30 日）・1 回だけ使える・`thth admin invite revoke <id>` でいつでも取り消せる・`thth admin invite list` は code も hash も出さない。
2. **本人が自分で進める道**: 招待のページ（何が起きるか・求める権限・privacy と利用規約）→「Threads で認可する」→ VM の常駐（`thth approval-worker`）が拾って認可の session を作る → 本人が Threads で承認 → VM が token に換えて口座 `inv-<project>-<6 桁>` を用意（handle は認可した人から・`--production` の招待なら production: true）→ 完了のページで承認 secret を 1 回だけ表示。secret は Worker の中で作り、VM も運営者も見ない。
3. **規律**: 同じ Threads 口座に 2 つ目は作らない・持ち主の組に入っている project では作らない（口座を用意する直前にも見る）・使われた／切れた／取り消された招待は 410・常駐が 2 分拾わなければ本人のページに「運営者に連絡を」、遅れて拾ったら管理者に運用通知を 1 回。
4. **変更ログ**: `invite_created`・`invite_used`・`invite_revoked`（subject は `invite-<id>`）と、口座の `account_added`・`token_set`（`via_invite`）・`approver_set`（via http・secret を見届けたとき）。
5. **預かり所の戻り**: 招待の認可から `/callback/` に戻ったときは「招待のページ（最初に開いたタブ）に戻ってください」と出す（従来の `thth auth` の戻りは変えていない）。

## 招待を作って渡す手順（運営者）

1. Worker を 3.10.0 に deploy してあることを確かめる（主セッション）。
2. `ssh -t` で VM に入り `thth admin invite create --media threads --project <p> --label <控え> --expires 30d --production --by masaru`。
3. tty に 1 回だけ出た URL を本人に渡す（公開の場・LLM の会話には貼らない）。
4. 管理者の通知（`account_added`）か `thth admin invite list` の `used` で、口座 `inv-<p>-<6 桁>` ができたのを確かめる。
5. 資格情報に `{"accounts": {"<口座名>": "<p>"}, "writes": true, "actor": "<口座名>"}` の 1 件を足し、そのセッションで下書きを置いて承認 URL を本人に届ける。

詳しくは `docs/運用_招待する側.md` の §10、招待された人向けは `docs/導入_招待されたら.md` の §6。
