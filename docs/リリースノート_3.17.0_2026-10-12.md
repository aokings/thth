# リリースノート 3.17.0（X の非公開リスト `thth list`）

2026-10-12。依頼は関東レーン、masaru 10/12「リストは作ってほしい」。**X のアカウントならどれでも使える**（今は asmon-kanto-x と kopicha-x）。**使う前に各アカウントで `thth auth <account> --by <名前>` を打ち直す**（下の「認可」）。**下書き・未配布**（push・release・tag は masaru の一言で）。

## 足したこと

- **`thth list create <account> <名前> [--description 説明] --by <名前>`**: `POST /2/lists` を 1 回。**`private` は常に true**（公開のリストを作る旗は設けない）。名前 1〜25 字・説明 100 字まで（範囲外は要求の前に rc=2）。
- **`thth list add|remove <account> <list_id> <人…> --by <名前>`**: `POST /2/lists/:id/members` {user_id}・`DELETE /2/lists/:id/members/:user_id` を 1 人 1 回。人は数字の id か `@handle`。**1 回 10 人まで**（11 人以上は rc=2 `too_many_members`・SNS に送らない）。重複は 1 回にまとめる。途中で断られたら止まり、`done`（済んだ人）と `not_done`（送っていない人）を返す。検索結果から自動で足す経路は無い。
- **`thth list show <account> <list_id> [--limit N]`**: `GET /2/lists/:id/tweets` を 1 回（既定 10 本・最大 25）。返す形は `thth where` の行と同じ（`preview` は 1 行・`text` の鍵は無い）。**本文は返すだけで保存しない**（runs には件数だけ）。続きがあれば `cannot_say` に一言（続きは読まない）。
- **認可**: `list.read`・`list.write` を `OPTIONAL_SCOPES` に足した（3.15.0 の `like.write` と同じ形。認可の URL にだけ足し、client の世代は変えない）。**3.17.0 より前のトークンには無い**ので、使う前に `thth auth <account> --by <名前>`。無いと分かっているトークンでは API を叩く前に rc=2 `scope_missing`。
- X 以外の account は rc=2 `unsupported_on_platform`（`--json` の `cannot_say` に理由）。MCP には足していない。

## 費用（月の X 予算 `thth admin budget x` に入る・推定であって請求額ではない）

- 書き込み: List: Create 0.010 USD・List: Manage（足す／外す）0.005 USD／要求。台帳は別のファイル `state/_admin/budget_x_list_writes.json`（単位 0.005 USD・作るは 2 単位）。作法は読み取りと同じ（要求の前に押さえる・断りの応答は 0 で確定・応答が読めなければ押さえたまま「不明」）。1 日 60 本（`x_daily_reads`）には数えない。
- `@handle` の id 引き（`GET /2/users/by/username/:username`）: 本人確認と同じ台帳で 1 回 0.010 USD。
- `show`: 他人の投稿の読み取り（Posts: Read・1 本 0.005 USD）。1 日 60 本にも数える。
- `thth admin budget x` と `thth doctor <X アカウント>` に「非公開リストの書き込み」の行。`--json` は `list_write`。

## 書き込みの作法

`thth like` と同じ: `--by` 必須・台帳に `production: true` が無ければ SNS に送らない・account のロック・**再試行しない**（結果不明は不明のまま言う）。

## 決まり（道具では守らせきれないので、各セッションが守る）

- 非公開リストだけ。人が選んだ少数だけを入れる（X Developer Guidelines「No bulk or indiscriminate additions」）。
- **足された相手に X が通知するかは未確認**。

## 確かめていないこと

- 実 API では未試験（試験は偽の HTTP）。応答の形（`data.id`・`data.is_member`）は一次資料どおりに読んでいる。
- 断りの応答（4xx）に料金が掛かるかは未確認（0 で確定にしている）。
- 検索の `list:` 演算子は使っていない（階層ごとの可否が一次資料に無い）。
