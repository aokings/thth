## 2. 共通の層

### 2.1 何が共通か・今どこまであるか

```
共通の層（THTH が持つ）
  ① 括りの台帳           /srv/thth/workspaces.json            置いた（本番・括りは main だけ）
  ② レーンの鍵           thth login --lane                    枝にある（6.0.0・12/4 の予定）
  ③ 鍵から括りを決める口   VM に 1 つ。鍵 → 括り・レーン・持ち主   枝にある。媒体はまだ決まらない（§2.2）
  ④ 部品の通り道          鍵で来た頼みを、印を立てて hub・h2d に渡す   まだ無い（§2.3・段 T1）

部品（今の repo のまま・今の担当のまま）
  声 = THTH の届ける所    括りのフォルダの中で動く              枝にある（段 0〜5 の台本まで）
  場 = hub               印があれば括りごとの置き場で動く        済（H1〜H4）。印を立てる者が居ない
  時 = h2d               括りの中だけを判定する                 まだ 0 行。12/9 に最初の判定（D1）
```

- hub と h2d は鍵そのものを見ません。鍵を確かめるのは THTH の口（③）の 1 か所だけです（11/26 masaru「寄せる」・初版 §8.2 問い 2）。答えの書 §4 も同じ形（案 A）を推しています。
- 「印があれば分かれる」所まで hub はできています。足りないのは**印を立てる者**です。印を立てるのは、VM の上では THTH の常駐（④）、Mac の上では hub の入口（鍵のファイルの控えから・R2）の 2 つだけにします。
- 門を monban に寄せるかは、**本線が masaru に聞いています**（答え §1.1 の問 4・推しは「今はしない」）。この版は、どちらに決まっても変わらない形で書いています。③の口が 1 か所なら、あとで寄せるときに替えるのは口の中身と鍵のファイルの `issuer` だけです（前の書 §4.7）。

### 2.2 レーンの鍵と媒体（枝を読んで確かめたこと）

初版 §2.2 は「鍵の行に媒体を足す」と書きました。枝のコードを読んだ結果、**未着手**です。

- 鍵の行は `{sha256, expires_at, revoked, actor, workspace, lane, writes}` の 7 つで、媒体の欄がありません【読: 枝 `thth/lane_keys.py` 8 行・25 行】。
- 鍵を出すときに VM が確かめるのは「その括りの持ち主か」（対応表の `owner_of`）だけで、「その媒体はその括りの物か」は見ていません【読: 枝 `thth/activity.py` 26〜27 行・481〜521 行】。
- レーンの名は自由な文字列です（`[a-z0-9][a-z0-9-]{0,80}`）。鍵のファイルの名前を `<repo>` か `<repo>-<レーン>` にする約束はありますが【読: 枝 `thth/remote.py` 51 行の注記】、VM はその形を確かめません。コネクタの鍵のレーンは `connector-…` です【読: 枝 `thth/server_passthrough.py` 36 行】。
- 通り道が命令を打つときに立てる環境変数は `THTH_WS` と `THTH_ACTOR` だけです【読: 枝 `thth/server_passthrough.py` 277〜279 行】。`THTH_MEDIUM`・`THTH_KEY_ID` を立てる所は枝の `thth/` にありません【動: 語で探して、関係のない注記 1 件だけ】。

**媒体が要る理由**: hub は、印に媒体があれば `--project` をその媒体に固定し、別の名指しを断ります。媒体が無いと、この固定を飛ばします【読: media-hub `hub/wsmark.py` 120〜131 行】。つまり媒体の無い印では、同じ括りの中のほかの媒体の名前で 1 行を書けます。括りをまたぐ漏れではありませんが、初版 §2.5 の (3)（11/25 の、窓口の行が別のレーンに書き換わった件）の手当て 2「鍵で来た 1 行は媒体とレーンを鍵から取る」が効きません。h2d も、見える範囲と書ける範囲を媒体で判定します（答え §2.2）。

**推しの形（段 T2・12/8 のあと）**:

- 媒体は**鍵を出すときに決めて、VM に控える**。`thth login --lane <レーン> --medium <媒体>`（`--medium` が無ければ、レーンの名の頭が対応表の媒体に当たるかを見て、当たらなければ聞く）。VM は「その媒体は、その括りの物か」を対応表で確かめ、違えば出しません（初版 §2.2 のとおり）。
- **控える場所は鍵の行でなく、隣の新しいファイル**にします（例: `ws/<括り>/private/lane-media.json`。鍵の hash → 媒体・hub と h2d に渡すレーンの名）。鍵の行に欄を足さない理由は前の書の R1 と同じ形です: 6.0.0 の読み手は行の欄が 7 つちょうどでないと、その括りの表をまるごと読めなくします【読: 枝 `thth/lane_keys.py` 42 行・69〜73 行】。欄を足したあとで 6.0.0 に戻すと、その括りのレーンの鍵が全部止まります。隣のファイルなら、古い版は無視するだけです。
- 控えの無い鍵（6.0.0 のうちに出した鍵・コネクタの鍵）は、**THTH の命令は今のとおり通り、部品の通り道だけ断ります**（「この鍵は hub と h2d に通れません・`thth login --lane` をやり直す」）。コネクタ（claude.ai など）から hub・h2d を打たせない、という既定もこれで付きます。
- 手元の鍵のファイル（`~/.config/thth/lanes/<レーン>.json`）にも `medium` を表示のための控えとして足します。手元の読み手は `url` と `key` しか取らないので、欄が増えても古い CLI は読めます【読: 枝 `thth/remote.py` の `load`】。
- **6.0.0 には何も足しません。** 12/5 の受入で出すレーンの鍵は、T2 が出たあとに login をやり直せば控えが付きます。

選ばなかった形: 「レーンの名前（`<repo>-<レーン>`）から、使うたびに媒体を割る」。鍵の表は変えずに済みますが、媒体の名前にも `-` が入るので（`media-hub`・`music-research` など）、対応表にあとから媒体を足すと、同じ鍵の媒体が黙って変わることがあります（`asmon` のレーン `kanto-data` と、あとから足した媒体 `asmon-kanto` のレーン `data`）。出すときに 1 回決めて控える形なら、あとから変わりません。答えの書 §3.4・§7 が「THTH括りに確かめる」とした問いへの、この版の答えです。作るときに THTH括りが違う形を選んだら直します。

### 2.3 部品の通り道（まだ無い・段 T1・12/8 のあと）

鍵を持つレーンの道は、THTH・hub・h2d で 1 本です（決まっている）。THTH の命令の分は枝にあり、部品へ渡す分がありません。

```
レーンのセッション（Mac）
   thth --lane <レーン> …        ─┐
   thth --lane <レーン> hub …     ├─ 鍵 ─▶ thth.me（Worker・括りの束）─▶ VM の常駐
   thth --lane <レーン> h2d …     ─┘                                      │ ③ 鍵 → 括り・媒体・レーン・鍵の id
   （hub の入口と h2d の MCP の口も、中でこの道を呼ぶ）                       ▼
                                             THTH の命令: 括りのフォルダに入って打つ（今の通り道）
                                             hub・h2d の命令: 印を立てて、VM の hub・h2d を打つ（新しく作る）
```

作る物（THTH の側）:

1. **VM の受け口**。今の通り道（`ws_command`【読: 枝 `thth/server_passthrough.py` `execute`】）の隣に、部品へ渡す操作を 1 つ足します（名前は作るときに決める・ここでは仮に `part_command`）。開くのは、括り・レーン・**媒体の控え**（§2.2）がそろった鍵だけです。
2. **立てる印**は、hub がもう読んでいる 4 つにそろえます: `THTH_WS`・`THTH_MEDIUM`・`THTH_LANE`・`THTH_KEY_ID`【読: media-hub `hub/wsmark.py` 3 行・20 行】。h2d には、今の判定がそのまま効くように `H2D_ACTOR_MEDIUM` と `H2D_ACTOR`（`thth:<括り>/<媒体>` の形）も立てます（初版 §2.3 のまま）。呼ぶ側が付けてきた同じ名前の環境変数は、VM が鍵から決めた値で必ず上書きします（初版 §7 の柵「印の出どころ」）。
3. **通してよい命令の一覧は、部品が自分で持ち、自分で断ります。** hub はもうそうなっています（読む 6: `roster`・`status list`・`promise list`・`note list`・`approve list`・`callname list`／書く 8: `status post`・`promise add`・`approve ask`・`note add`・`handoff put`・`handoff get`・`decide`・`pulse`。`hub answer` は通さない）【読: `hub/wsmark.py` 24〜33 行】。THTH は一覧の写しを持ちません（正本を 2 つにしない）。THTH の側で見るのは、渡してよい部品の名前（`hub`・`h2d` の 2 つだけ）と、引数の形（数と長さ・制御文字なし）だけです。h2d は、一覧が MCP の口の中にあるので、CLI の側に同じ関門を作ってもらいます（§4 の D2）。
4. **hub が要る 3 つの控えを運ぶ**。今の Mac の入口は、ssh に `HUB_CWD`・`HUB_SESSION`・`HUB_HOST_SESSION` を載せています【読: `hub/bin/hub-mac-wrapper` 113 行】。通り道でも、この 3 つを頼みの中身として運びます（印とは別。部品が要ると言った名前だけを通す表にする）。標準入力で本文を渡す命令（申し送りなど）があるか、あるなら 48 KB に収まるかは【未】で、付録 A で hub の担当に聞きます。
5. **手元の入口**: `thth --lane <レーン> hub …`・`thth --lane <レーン> h2d …`。hub の Mac の入口（`hub …`）と h2d の MCP の口は、レーンの鍵のファイルが決まれば中でこの道を呼びます（R2・D2）。レーンは今の打ち方（`hub status post …`）のまま打てます【推】。
6. **Worker は変えずに届く見込み**です。Worker は操作の名前を形（英小文字と `_`）で見るだけで、名前の一覧を持ちません【読: 枝 `callback/src/api.js` 20 行・77 行】。VM の常駐と Mac の CLI を変えるだけで載ります【推: 括りの束が新しい操作も同じに運ぶかは、作るときに手元の `wrangler dev` で往復して確かめる】。これが、答えの書 §7 の「通り道が Worker を変えずに載るか」への今の見立てです。審査の間に VM と CLI を出してよいかは §9 の決めること 1 です。

道の限りは前の書 §5.6 のままです（頼み 48 KB・間の空いた 1 発目は最長 10 秒ほど待つ）。hub の 1 行がこの待ちで困らないかは測っていません（答え §7）。12/5 の受入で、運用のレーンを 1 本鍵に替えて THTH の命令の待ちを測る予定があるので【読: 枝の段取りの 12/5 の行】、その数を hub の 1 行の見立てにそのまま使います（道が同じなので・【推】）。受入に作業は足しません。

### 2.4 伝言だけは道が違う（今の姿に直した）

伝言箱（hub messenger）は VM でなく masaru の Mac の中にあり、VM の口（③）を通りません（答え §2.1）。

   - `ssh:`・`local:` の「全部」を、「印が無ければ main・括りの名指しがあればその括り・管理者の旗があれば全部（一覧だけ）」に替えてください。括りが main だけの間は今と同じに動くこと。
   - MCP の口は、レーンの鍵のファイルがあれば頼みを `thth --lane <レーン> h2d …` に流し、`H2D_MCP_MEDIUM` を見ない形にしてください。立っていて鍵の媒体と違えば、口の起動を断ってください。
3. **D3 送り先を括りごとに**（hub の括りごとの常駐 R3 のあと）
   - 起こしの宛先は、規則の `owner` の括りの名簿から引いてください。引いた名乗りがその括りの名乗りの台帳に無ければ、送らずに止めて知らせてください。
   - 急ぎの繰り上げと休みの知らせの先（今は `media-hub` の決め打ち）を、対応表の `workspaces.<括り>.lead` にしてください。main の値は `media-hub` なので、今と同じに動きます。
4. **D4 件数の口**: 括りごとに、規則の数・休んでいる規則の数・失敗した仕事の数・届かなかった起こしの数だけを返す命令を 1 つ。出来事と配送の記録に括りの印を付けてください。
