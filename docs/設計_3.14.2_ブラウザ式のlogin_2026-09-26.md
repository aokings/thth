## 0. なぜ

3.14.0 の通し確認（09-26 夕・masaru の Mac）で、`thth login` の手数が多かった。「`/activity` で鍵を発行 → 表示された長い文字列をコピー → ターミナルに貼る」。masaru:「まだ鍵の入力が必要とかなの？」「どこに鍵があるの？」。ログイン自体は 1 台 1 回で避けられないが、**貼る作業は無くせる**。`gh auth login` と同じ形にする。

## 1. 使う側から見た形

```
$ thth login
ブラウザで許可してください: https://thth.me/login/XXXX-XXXX（10 分有効）
（ブラウザが開かなければ上の URL を開いてください）
待っています…
保存しました: ~/.config/thth/remote.json（inv-…）
```

ブラウザ側 `https://thth.me/login/XXXX-XXXX`: 口座名と口座の secret を入れて「この機械に鍵を渡す / Allow this device」。押すと「渡しました。ターミナルに戻ってください」。鍵は画面に**出ない**。

- 招待の完了ページでは今までどおり secret（と鍵）を 1 度だけ出す。**鍵の表示は残す**（ブラウザ式が使えない環境の逃げ道・`thth login --stdin`）。
- `/activity` の「LLM の鍵を発行する」も残す（発行し直し・取り消し）。

## 2. 作り（Worker と CLI だけ・VM は変えない）

```
CLI: code = 乱数 8 字（表示用 XXXX-XXXX）・poll_token = 乱数 43 字
  POST /api/v1/login/start {code_hash, poll_token_hash}      → 202 {url, expires_at}
  ブラウザを開く（webbrowser.open・失敗しても URL を出す）
  GET  /api/v1/login/poll/<code>  Authorization: Bearer <poll_token>  を 2 秒おき・最長 10 分
     → 202 {status: waiting} / 200 {key, account}（1 度だけ・返したら消す） / 410 expired / 404
Worker:
  Login DO（新・code_hash で引く・10 分で消える）: {poll_token_hash, status, key?, account?}
  GET  /login/<code>  → form（口座名・口座の secret・「この機械に鍵を渡す」）。script なし・CSP・no-store。
  POST /login/<code>  → Person DO で secret を照合（/activity と同じ・5 回で 15 分）→ 鍵の発行（今の rotate と同じ: Worker が bearer を作り、hash を VM への action `rotate` に載せる・前の鍵は無効）→ Login DO に key と account を 1 度だけ置く → 「渡しました」
  回数制限: /login/* は RELAY_PUBLIC_LIMIT（IP）・poll は API_KEY_LIMIT 相当（code ごと 60 回/分）。
VM: 変えない（rotate の action を今までどおり拾い、次の sync で鍵の表に載せる）。
```

- 鍵は Login DO に最長 10 分・CLI が受け取った時点で消す。Worker は記録しない。
- CLI は受け取った鍵を `redact.register_secret` に登録し、`remote.json`（0600）に書く。`account` も書き、`thth account status` の口座名の省略に使ってよい（**今回は省略は作らない**・書くだけ）。
- `thth login --stdin`（貼る道）は残す。`thth login --no-browser` で URL だけ出す。

## 3. 小さな直し

1. `/activity` の「設定を変える」の値の欄に `autocomplete="off"`（パスワード管理がユーザ名を入れる・09-26 のスマホの画面）。secret の欄は `current-password` のまま。
2. masaru の Mac のラッパ `bin/thth-remote`（`~/.local/bin/thth`・VM 行き）: `login`・`logout` と、`~/.config/thth/remote.json` があって**口座の台帳が VM に無い**命令を… は判定できない（ラッパは VM の台帳を知らない）。→ ラッパは **`login`／`logout` だけ手元の `thth`（pip）に渡す**。それ以外は今までどおり VM。遠くの道の確認は `python -m thth …` か pip の絶対パスで（文書に 1 行）。運営者だけの事情なので最小。

## 5. 決めたこと（推薦で進める）

- code は 8 字（`XXXX-XXXX`・大文字と数字・紛らわしい文字を除く）。poll は別の 43 字の token で守る（URL を見た人が鍵を取れない）。
- 鍵の発行は今の rotate と同じ（前の鍵は無効）。login のたびに発行し直す（1 台 1 鍵ではなく口座 1 鍵。2 台目で login すると 1 台目は切れる）。**複数の機械で使う人が出たら見直す**（鍵を複数持つ設計）。
