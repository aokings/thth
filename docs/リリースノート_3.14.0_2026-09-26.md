# リリースノート 3.14.0（外向け CLI——厚い CLI・薄い MCP・skills が包む）

2026-09-26。設計: `docs/設計_3.14.0_外向けCLI_2026-09-26.md`。

見方の一行（masaru）: **THTH は、SNS を調べ・投稿し・予約する CLI ツール。** だから LLM が操作しやすい。MCP と skill はその補助。thth.me とサーバは、CLI を外の人にも届ける裏方。

**配る順: Worker が先、VM（release）があと。** 新しい VM は `/api/v1` の受け渡しを sync に載せるが、古い Worker はそれを知らない（壊れない・依頼が届かないだけ）。逆に新しい Worker に古い VM が当たると、鍵の表が来ないので `/api/v1` は 401 を返す（壊れない）。

## 何が変わったか

### 1. 外の人が `thth` を打てば運営者と同じことができる（段 3）

```
pip install thth
thth login                       # 鍵を tty で 1 度だけ（引数では受けない・~/.config/thth/remote.json 0600）
thth posts <口座>                # 自分の投稿
thth send <口座> --text "…" [--reply-to <id>] [--topic <語>] [--dry-run]
thth schedule <口座> --text "…" --at <ISO 時刻>
thth retract <口座> <post_id>
thth replies / measured / collect / mentions / topics --search / profile / location search
thth account status <口座> / thth account set <口座> <項目> <値>（締める向きだけ）
thth queue <口座> / thth logout
```

- 手元に口座の台帳があれば手元の道、無くて `remote.json` があれば**遠くの道**（thth.me 経由で自分の口座）。両方あれば手元が先・`--remote` で遠くを指す。判定は `thth/remote.py` の 1 か所。
- 命令の名前・引数・`--json` の形は手元の道と同じ。人向けの表示も同じ関数（`show_posts` 等に切り出した）。遠くの道の `send` は rehearsal を挟まない（サーバが lint と安全装置で断る）。
- 遠くの道に無い命令（`throw`・`run`・`auth`・`approve`・`account add`・`admin *`・手元のファイルを読む命令・添付）は `remote_unsupported`（rc 2）。
- HTTP: 25 秒・202 なら `/result/` を 1 秒おきに最長 90 秒（超えたら `remote_pending`）・401 は `invalid_key`／`key_expired`・429 は `Retry-After` で 1 回だけやり直す・網の失敗は `remote_unavailable`。鍵は読んだ直後に伏せ字に登録し、出力に出ない。
- 手元の道にも旗を足した（`send --text/--dry-run/--json`・`collect --json`・`replies/measured/mentions --limit`・`posts/mentions --refresh`）。既存の出力と rc は変えていない。

### 2. MCP は CLI の写し（段 3）

- `remote.json` があれば、`thth-mcp` は `thth_send_request`・`thth_schedule_request`・`thth_retract_request`・`thth_posts`・`thth_replies`・`thth_measured`・`thth_collect`・`thth_mentions`・`thth_topics_search`・`thth_profile`・`thth_location_search`・`thth_account_status`・`thth_settings`・`thth_draft_list` 等 15 本を出し、中身は `thth <命令> … --json` を呼ぶだけ。判断・HTTP・鍵は MCP に無い。
- VM の上の in-process の道（`server_mode`・運営者の admin）は残す。外の人向けの `ssh … thth-mcp-invitee` は案内しない。

### 3. thth.me の `/api/v1`（段 2）

```
POST https://thth.me/api/v1/<operation>   Authorization: Bearer <鍵>   body {"account", ...}（48 KB）
  200 VM の JSON そのまま（断りは {"error","reason"?,"next_at"?}）／202 {"status":"pending","request_id"}（20 秒超）
  401 invalid_key・key_expired／429 too_many_requests（口座の pending 8 件）・rate_limited（鍵 60 回/分・IP 120 回/分）
GET  https://thth.me/api/v1/result/<request_id>   200／202／404
```

- VM に外から入る口は無い。Worker は依頼を口座の束（`Account` DO）に最長 120 秒預かり、VM が署名つき sync で取りに来て行い、結果を押し上げる（結果は 10 分で消える）。依頼と結果の中身は記録しない。
- sync に**鍵の表**（sha256・口座・期限）を載せ、Worker が先に断る（権威は VM・もう一度確かめる）。
- 待ちがあれば VM は 2 秒ごとに取りに来る（無ければ 10 秒）。体感 2〜5 秒。
- 冪等（`request_id`・`state/<口座>/requests/<id>.json`）。記録は `via: api`＋鍵の id。
- 招待の完了ページに、口座の secret と**アシスタントの鍵**を 1 度だけ出す（`/activity` の発行し直し・取り消しは今のまま）。

### 4. VM の読む口（段 1）

利用者 scope の資格で `posts`・`replies`・`measured`・`collect`（口座ごと 10 分に 1 回・`collect_too_soon`）・`mentions`・`topics_search`・`profile`・`location_search`。中身は今の CLI の関数（`thth/server_reads.py`）。範囲外は書く口と同じ `scope_unavailable`。媒体の失敗は `upstream_unavailable`（URL・path・token を落とす）。

### 5. 文書（段 5）

- privacy: 命令の道（`/api/v1`）の段と保持（依頼 120 秒・結果 10 分・鍵は hash だけ）。施行日はこの版の deploy の日。
- `docs/導入_招待されたら.md`: `pip install thth` → `thth login` → 命令の一覧。`skills/thth/SKILL.md`: 「遠くの道」の節。`docs/運用_招待する側.md` §7。
- 申請の手順（`docs/手順_Meta申請_世間の層_2026-09-24.md`）: 前置き・審査員の手順・録画 0 を CLI の形に。**貼るのはこの版の配布のあと。完了ページの実物を見て文言を直す。**

## 運営者が deploy のあとにすること

1. **Worker を先に** deploy（`API_KEY_LIMIT`・namespace 21401 が入る。secret の追加は無い）。
2. **VM の release**。常駐（`thth-worker`）が新しい版で起き直すと、次の sync から鍵の表が届き、`/api/v1` が通り始める。
3. 確かめ: masaru の Mac で `pip install -U thth` → `/activity` で鍵を発行 → `thth login` → 数十秒後に `thth account status <口座>`。
4. 3.13.0 の残り（急がない）: `RELAY_PUBLIC_KEY` への置き替え・旧 path `/approval/*` の受け口の削除は 3.14.1 以降。

## 決めたこと・見直しの候補

- `thth send --text <文>` を足した。`cmd_send` の元の方針「本文を引数で受けない」と食い違う（設計 §2 に合わせた）。masaru が「引数で受けない」を保つなら `--text-file`・標準入力だけに戻す。
- `via` は遠くの道をすべて `api`（cli／mcp の区別は付けていない）。
- 遠くの `thth queue` は `draft_list` の形（手元の `queue --json` と違う）。`send --dry-run` は下書きが 1 本残る。
