# リリースノート 3.11.0（承認待ちの一覧ページ）— 下書き

2026-09-25。設計は `docs/設計_3.11.0_承認待ちの一覧ページ_2026-09-25.md`、背景は `docs/手順_Meta申請_世間の層_2026-09-24.md` の §2.3（承認 URL を審査員に届ける道が無かった）。

版は上げていない（`thth/VERSION`・`server.json` は 3.10.0 のまま・tag なし）。**Worker（`callback/`）の deploy が要る**（`/pending` と `/pending/*` の経路・`run_worker_first` の追加・承認 session の `listed`）。Durable Object のクラスと migration は増やしていない（既存の `ApprovalPerson` と `ApprovalSession` に足した）。deploy は masaru の一言で主セッションが打つ。

**順番: Worker を先に deploy し、そのあとで VM に release を入れる。** 3.11.0 の VM は承認の登録（create）に `listed: true` を乗せる。3.10.0 の Worker はこの鍵を知らないので登録を断り、job は `failed`（`approval_registration_rejected`）になる。Worker が先なら、3.10.0 の VM（`listed` なし）もそのまま通る。

privacy の施行日（`PRIVACY_EFFECTIVE`）は触っていない。文は直したので、deploy のときに主セッションが日付を決める。

## 本人向け: 承認待ちの見方

1. `https://thth.me/pending` を開き、ユーザ名（招待の口座では口座名 `inv-…`）と承認 secret で入る（パスワード管理が入れてくれる）。
2. 自分あての承認待ちが並ぶ（種類・本文の先頭 60 字・添付の有無・期限まで何分）。「開く」で承認ページに進み、同じ secret で承認する。
3. 一覧に出た承認は最大 24 時間待つ。一覧から開いた承認ページは開いてから 10 分で切れる（切れたら一覧から開き直す）。承認すると一覧から消える。

## 何が変わったか

1. **承認待ちの一覧（Worker）**: `https://thth.me/pending`。ユーザ名と承認 secret で入る（照合は承認ページと同じ PBKDF2 100,000）。一覧の session は 10 分、cookie は `Secure; HttpOnly; SameSite=Strict; Path=/pending`。ページは承認ページと同じ CSP・no-store・no-referrer・script なし、POST は Sec-Fetch-Site で同一 origin を確かめる。流量は承認ページと同じ上限（1 IP 120/分）。Worker は閲覧を記録しない。
2. **自分の分だけ**: 一覧の索引と session はその人の person object にだけ置き、本文は置かない（本文は承認ページの session にだけある）。一覧の行と一覧から開く承認ページは、session の側でも「その人あての承認か」を確かめる。
3. **失敗回数**: 一覧に入る secret の間違いは一覧だけの回数で数え、5 回で一覧を閉じる（`thth admin approver unlock` で戻る）。名前を知るだけの人が承認そのものを止められないよう、承認ページの失敗回数とは分けた。
4. **期限の延長**: 一覧に出す承認は最大 24 時間待つ（既定の 10 分は変えていない）。承認ページの 10 分は開いた時点から数え直し、job の期限は越えない。画像を添えた承認は延ばさない（画像の表示の capability が 10 分より延ばせないため・一覧には出る）。
5. **VM の印**: 承認 job に `listed`（既定で付ける）。`thth admin approval request` は既定で一覧に出し、「承認待ちの一覧」の行を出す（`--no-list` で従来どおり URL だけ・10 分）。MCP／HTTP の承認の道も既定で一覧に出し、返り値に `pending_url`。変更ログの diff に `listed`。
6. **常駐の間引き**: 残りが 10 分より長い一覧の job は、Worker への問い合わせを 10 秒に 1 回にする（待っている job の数で承認 relay の流量の上限を食い潰さない）。そのため、一覧から承認してから実行が始まるまで最大で 10 秒ほど余分にかかることがある。
7. **承認ページの英語**: 補足の見出し（媒体・返信先・公開予定・削除する投稿・削除理由・話題・公開オプション）を「日本語 / English」に。招待の完了ページは「承認ページの URL は運営者から届きます」を、一覧の案内に直した。
8. **承認前の注意書きを外す**: `thth profile` と `thth location search` が引けたときに出していた「標準アクセスでは…」の注意書き（と `--json` の `standard_access_note`・`note`）を外した。API が断ったときの断りの文は残す。
9. **privacy**: 認可の始まり方を「招待リンクのボタン（本人）か、運営者の `thth auth`」の 2 通りに。承認ページの保持に「一覧に出したものは最大 24 時間」と一覧の段落、保持の表に一覧の 10 分。
10. **申請の文**: 試験の手順の 4〜7 を「一覧から開く」に（英日）。§2.3 を決定済みに。keyword_search の説明に、見つけた公開投稿の枝を求めに応じて見せ（保存しない）承認つきで返信することを書いた。

## deploy の手順（主セッション）

1. `callback/` で Worker を deploy する（migration は無い）。
2. `https://thth.me/pending` がログインの画面を返すこと（assets の 404 でないこと）を確かめる。
3. privacy の `PRIVACY_EFFECTIVE` を決め、`python tools/build_site.py` を通してから、同じ deploy に載せる（または次の deploy）。
4. VM に release を入れる（Worker のあと）。
5. 招待の口座で `thth admin approval request … --send` を 1 本出し、本人の一覧に出ることを確かめる。
