## 1. 「済み」の線（先に決める）

段 4 が済みと言えるのは、次の 4 つが全部そろったとき。検収は 1 回だけ。中・軽は宿題に回して段 5 へ進む。

3. **今の決まりと同じ答え**: 「決まりの実物」の各行のうち、§2 の部品で言える決まりは全部宣言に書いてあり、器が数えた違反の数が「今の数」と同じ。指す欄の「先が無い」の数も同じ。小さな見本で、違反の行を 1 つ足すと赤になる。

重い穴 = 宣言の値で命令が走る・例外で `check` 全体が止まる・今の決まりが赤にする物を器が緑にする（言えると分類した決まりで）・今の実物に無い違反を器が出す。

## 2. 検査の部品（種類の宣言の `checks`）

設計の 7 つの名前付きの検査を、実物の決まりに当てて形にした。7 つのままでは言えず、少し足せば言える決まり（指してくる行を数える・値の形・この状態なら空・どちらか一方）がどのメディアにも同じ形で出るので、部品に入れた。**式・正規表現・命令は書かせない。** 値の形は THTH が備えた名前から選ぶ。

種類の宣言（`thth.kind/1`）に `checks` の並びを足す。1 つの検査は JSON の辞書で、決まった欄だけを受ける（知らない欄・知らない検査の名前は `DeclarationError("checks")`）。

### 2.1 どの検査にも付く欄

| 欄 | 意味 |
|---|---|
| `check` | 部品の名前（下の 9 つ） |
| `id` | この検査の呼び名（`NAME` の形。種類の中で重ならない。結果に出る） |
| `level` | `error`（既定・赤）・`warn`（知らせる）・`review`（見直しの候補）。赤にするのは `error` だけ |
| `when` | この記録が条件に合うときだけ検査する（条件の形は 2.2）。無ければ全部 |
| `note` | 人が読む注（器は読まない） |

### 2.2 条件の形

`{"<欄>": <試し>, …}`。全部が合えば合う（かつ）。「または」は書けない（検査を 2 つ書く）。試しは次のどれか 1 つ:

- `{"in": ["語", …]}`・`{"not_in": ["語", …]}`（前後の空白を落とした字で比べる。語は 256 個まで）
- `{"blank": true}`・`{"blank": false}`（空白だけも空）

欄は、表なら列の名前、JSON・YAML の枚なら頭の段の鍵。値が字でない物（辞書・並び）は、`blank` だけが使える。

### 2.3 部品の一覧

| 部品 | 引数 | 赤になるとき | 設計の 7 つ | 実物の例 |
|---|---|---|---|---|
| `unique` | `fields`（欄の組）・`fold`（`"lower"` だけ。小文字にして比べる）・`skip_blank`（既定 true。組の全部が空の行は見ない） | 同じ種類の中で組が重なる | 重ならない | にがみ `(entity_id, sort_order)`・`lower(doi)` |
| `required` | `fields` | `when` に合う記録で、欄のどれかが空 | この状態ならこの欄が要る・種類ごとに要る欄が違う | キョンシー J-25・J-28 |
| `empty` | `fields` | `when` に合う記録で、欄のどれかが空でない | （足した。「この状態ならこの欄は空」） | キョンシー J-14・MMR M-C13・にがみ N4-33 |
| `one_of` | `fields`・`mode`（`at_least_one`・`exactly_one`） | 埋まっている欄の数が合わない | （足した） | こぴちゃ K4-5・MMR M-V20・`url` か `doi` |
| `words` | `field`・`in`・`allow_blank`（既定 false） | 値が語の中に無い | 語はこの中から（`when` と合わせて、種類ごとの語） | J-3・J-26 |
| `shape` | `field`・`shape`（下の名前）・`prefix`（決まった頭の字。40 字まで）・`allow_blank`（既定 true） | 値が形に合わない | （足した。値の形） | 番号・日付・URL の頭 |
| `forbid_pair` | `via`（この種類の、宣言済みの指す欄）・`target`（先の記録への条件） | `when` に合う記録が指す先に、`target` に合う記録がある | この組は禁じる | J-11・J-24・J-33 |
| `count` | `from`（`{"kind": "<種類>", "via": "<その種類の指す欄>"}` = この記録を指してくる行。または `{"units": true}` = この記録の内側の単位）・`where`（数える行への条件）・`distinct`（その欄の違う値の数を数える。空は数えない）・`min`・`max` | 数が `min` より少ない・`max` より多い | 違う番号の出典が N 個（`distinct`）。指してくる行の数（足した） | J-19・J-20・J-21・J-30・MMR M-C23 |
| `judged` | `question`（問いの名前）・`min`（既定 1）・`how`（照らし方の語。無ければ問わない） | この記録に、今効いている「よい」の判断が `min` 個に足りない | この判断が要る | 見本の台帳で試す（今の実物は、原文を見たかを欄の語で持つので `count` で比べる） |

**値の形の名前**（`shape`）: `slug`（`^[a-z0-9]+(-[a-z0-9]+)*$`）・`slug_loose`（`^[a-z0-9][a-z0-9-]*$`）・`date`（`YYYY-MM-DD`）・`date_partial`（`YYYY`・`YYYY-MM`・`YYYY-MM-DD`）・`lang`（`^[a-z]{2,3}$`）・`http_url`（`http://` か `https://` で始まる）・`https_url`・`positive_int`・`sha256`（16 進 64 字）。日付は形だけ見る（在る日か・今日と比べる、はしない）。

**「全部がこの語の中」の決まり**（キョンシー J-22・染めと化学 S-V17・MMR M-V17: 根拠の全部が弱い種類なら赤）は、`count` で「弱い種類でない根拠が 1 つ以上」と言い換える。`when` は `established`・`supported`。根拠が 0 の主張は「根拠が 1 つ以上」の検査（J-19 の形）が別に赤にするので、答えは同じ。言い換えたことを `note` に書く。

### 2.4 守る線

- 1 つの種類に検査は 64 個まで。`fields` は 16 欄まで。
- どの部品も、記録の数に比例する手間で終わる（先に索引を作る。2 重の繰り返しにしない）。こぴちゃの主張 6,114・根拠 6,995 で `check` が数秒で終わること。
- 検査の結果は `check` の出力に `checks` として出す: 検査ごとの数と、違反の記録（種類・番号・検査の呼び名・理由の語。1 つの検査につき 50 件まで、残りは数だけ）。`error` が 1 件でもあれば `check` は赤（今の `check` の rc の決まりに合わせる）。
- `forbid_pair` と `count` は、宣言済みの指す欄だけをたどる。たどるのは 1 段（指す先・指してくる行）。2 段以上は書けない（言えない決まりとして残す）。
- 指す先がよその台帳（`<台帳>:<番号>`）で手元に無いときは、違反にせず「確かめられない」と数える。
- 宣言が読めないとき（形が違う）は、今の宣言の断りと同じ道（宣言の場所と語）。

## 3. 7 つの宣言と、実物での確かめ

- 宣言は THTH の repo の `tools/register_decls/<メディア>/`（`kinds/*.json` と `constitution.json`）に置く。各メディアの repo には書かない（段 1〜9 の間、ほかの repo に書かない）。向きを替える段 10 で、各レーンが自分の repo の `.thth/` に置く元になる。
- 種類・番号の欄・指す欄・語は「決まりの実物」の §1〜§3 から。検査は §4 の行ごとに、§2 の部品で言える物を全部書く。検査の `id` に、決まりの実物の番号（`j_19` など）を入れる。
- 実物での確かめは `tools/register_stage4_realcheck.py`（各メディアの repo を読むだけ。宣言は `open_vessel` の `decl_base` で当てる。作業の写しが要るときは `/Volumes/NexDev/Developer/thth-work/` の下）。出す物: メディアごとに、読めた記録の数・例外 0・指す欄の「先が無い」の数・検査ごとの違反の数と、「今の数」との突き合わせ（合う・合わない）。
- 「今の数」と合わない所は、直す前に理由を分ける: 宣言の誤り・器の誤り・決まりの実物の数え違い・今の台本と決まりの文の食い違い（例: にがみラボの `established` は台本が出典を数えていない）。最後の 1 つは器を曲げず、「レーンに聞く物」として一覧に載せる。

## 4. 言えない決まりの扱い（固有として残す）

§2 の部品で言えない決まりは、器に入れない。各メディアの台本が正本のまま残り、器は段 7（関門）で、その台本の結果を同じ入力で比べる。理由の種類は次の語で書く:

| 語 | 意味 | 例 |
|---|---|---|
| `text` | 文の中の語・数字・字数を見る | 禁止語・疑問形の題・本文の中の数の照合 |
| `number` | 数値を比べる・範囲を見る | 長さの差が 2 秒以内・BPM 40〜220 |
| `outside` | 台帳の外を見る（repo のファイル・build の出力・外への問い合わせ・git の履歴） | 画像のファイルが在る・URL が 200 |
| `far` | 表を 2 段以上またぐ・集まりどうしが等しい・含む | 点 ← 主張 ← 根拠・照合台帳の取りこぼし |
| `version` | 前の版と比べる（段 5 の跡・来歴の控えで扱う） | 出典の URL を変えたら止める |
| `other` | 上のどれでもない（何が足りないかを書く） | 1 欄の中の番号の数の上限 |

一覧は `docs/固有として残す決まり_台帳の器_2026-11-14.md` に、メディアごとの表で。`other` が同じ形で 3 つ以上のメディアに出たら、部品に足す候補として末尾に書く（この段では足さない）。
