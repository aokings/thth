### 段 1: 糸の段の語彙

- **媒体 `ads`（広告）**: `- boost: ads need=1` が書ける（今までは `stage_medium_unknown` で断っていた）。数は広告の口座の記録（`thth ads boost`・`thth ads activate` の記録）を読むだけで、Meta は呼ばない。始めた広告が `done`、PAUSED で作っただけの広告が `pending`。糸に結ぶのは、押し出した元の投稿の id が糸の原稿の `post_id` か、広告の印の `utm_campaign` が糸の原稿の名前のもの。`budget_minor` は始めた広告の通しの予算の和（最小単位の整数）。**使った額は持たない**（`spend_minor: null`・`ads_spend_not_recorded`・使った額は `thth ads insights` で見る）。project に広告の口座が無ければ `done: null`・`ads_account_missing`。
- **はてブの段の `target=own|external`**: 自分の記事（セルクマ）か他人のページかを分けて数える。`- selfbm: hatena_bookmark target=own need=1`。`target` の無い段は今までどおり両方を数え、`stages[].by_target` に内訳だけ足した。`target=own` の段は、糸のはてなブログの配信 id を `--delivery` で付けた自分の記事のブックマークも数える。
- **段の日本語の名**: `promote`（告知）・`selfbm`（セルクマ）・`boost`（広告）を足した。`stages[].label` に日本語の名、端末の表示は `promote（告知） 1/3`。ダッシュボードの型（`skills/thth/dashboard/`）にも同じ名と広告の媒体名を足した。
- **出力の先頭に skill `thth-flow`**: `thth scenario`・`thth scenario show`・`thth dashboard <project> campaign <id>` の端末の出力の 1 行目が skill の 1 行。`--json` には `skill`（`name`・`path`・`command`・`text`）。`thth scenario skill` が場所、`thth scenario skill --print` が全文を出す。
- `thth.scenario/1` は鍵を足しただけ（`skill`・`stages[].label`・`stages[].by_target`・`stages[].target`・広告の段の `budget_minor` ほか）。名前を変えた鍵・消した鍵は無い。承認の指紋は変わらない。

### 段 3 の THTH 側: `thth scenario site-import <project> --file <json>`

- hub（SEO レーン）が GA4 を読んで作る `hub.site_visits/1` の JSON（1 サイト 1 ファイル）を受け取り、`state/<project>/site_visits/<サイト>_<窓の終わりの日>.json` に控える。同じサイトと窓の終わりの日は上書き（二度入れても増えない）。窓の終わりがいちばん新しい控えをサイトごとに読む。
- 断るもの（何も控えない・rc 2・`--json` は `{"ok": false, "code": …}`）: schema 違い（`site_visits_schema_unknown`）・未来の窓（`site_visits_window_future`）・from が to より後（`site_visits_window_invalid`）・負の数（`site_visits_negative`）・数が整数でない（`site_visits_invalid`）・サイトの名前の形（`site_visits_site_invalid`）・未来の generated_at（`site_visits_generated_in_future`）。
- 結び方: GA4 の campaign → 原稿のファイル名（拡張子なし）→ 原稿の札 `thread:` → 糸。原稿の repo の相対パスの末尾を `-` でつないだ形（MMR の `threads-drafts-features-2026-11-02` の形）も試す。大文字と小文字は区別しない。
- 結ばれないもの（`""`・`(organic)`・`(direct)` などの GA4 の値・原稿が無い・札が無い・2 本の糸にまたがる）は `untied_campaigns` に数だけ（campaign の数・訪問の和・理由ごとの数）。名前は出さない。
- `thth scenario show <project> <id> --json` の `site_visits` と `thth dashboard <project> campaign <id> --json` の `outcomes.article_visits` に「本記事への訪問（GA4・hub 経由）」: `sessions`・`engaged_sessions`・`as_of`・サイトごとの窓・`by_medium`（social と paid）・campaign ごとの行。窓の違うサイトは足さない（`windows_differ`）。
- 取れない数は 0 と言わない: 控えが無い project は `site_visits_not_imported`、取れなかった窓（rows が null・`unknown_reason`）は `site_visits_unavailable`、糸の原稿の印の訪問が無ければ `no_tied_campaign`。
- 控えのある project では、`dashboard campaign` の `outcomes.cannot_say.article_clicks`（`article_clicks_not_connected`）を外す。`as_of.site_visits`（いちばん新しい控えの generated_at）をどの階層の `as_of` にも足した。
- 控えるのは決めた鍵だけ（ほかの鍵は捨てる）。`landing_page` は `?` と `#` から後を落とす。`unknown_reason` は符丁の形（英小文字・数字・`_`）だけ控え、ほかは `unknown`。
- 遠くの道（thth.me）には出していない（hub は VM で打つ）。
