## トピックの下調べを、トピックで絞った検索につなぐ

苦味の研究所（nigamilab）の依頼（`nigamilab/docs/sns/依頼_THTH_トピックの下調べ_2026-11-03.md`）。masaru の言葉は「ちゃんと下調べして届けたい人に届く投稿をする必要があります」。いままでの `thth topics <account> --search <語>` はキーワード検索で、本文に語を含む投稿を返すだけだった。その語を**トピックに付けた**投稿がどれだけあるかは分からず、topic_advice もこの結果をトピックの使用例に数えない（正しい）。

### 足したこと

- **`thth topics <account> --search <語> --tag`**（Threads だけ）: Threads の検索に `search_mode=TAG` で問い、その語をトピックに付けた投稿の**件数・投稿者の数（重複なし）・最新と最古の時刻**だけを出す。本文・username・post_id は画面にも json にも出さない（`where --aggregate` と同じ作り）。`--recent`・`--since`・`--until`・`--media`・`--limit` と組める。
  - 応答の行に `topic_tag` が付いていて別の語なら数えない（`n_label_other`）。付いていない行は TAG で問うた答えとして数え、`n_label_absent` に別に数える（検索の応答に `topic_tag` が付くかは一次資料で未確認）。
  - **0 件と「読めなかった」を分ける**: 0 件は `status: "empty"`（その条件で 0 件・人がいないとは限らない）。読めなかったときは `status: "cannot_say"`・`cannot_say: {kind, message}`・`counts: null`（終了コードは今までの `--search` と同じ 1／2）。
  - json の欄: `status`・`cannot_say`・`counts`（`n`・`distinct_authors`・`latest_at`・`oldest_at`・`n_with_timestamp`・`n_label_matched`・`n_label_other`・`n_label_absent`）・`n_returned`・`more_may_exist`・`storage`・`observation_id`・`kept_counts`・`note_hint`。
- **`--keep`**（`--tag` と一緒に）: 数を**下調べの観測**として残す（`state/topic_advice/observations`・`search_mode: topic_tag`・`provider: threads_api`・`samples` は空）。残す数は `where --keep` と同じ決まり——**5 未満の数は欠測（null）、件数が 5 未満なら内訳と日付も欠測、時刻は日付（JST）に丸める**。0 件は `status: empty`、読めなかったとき（権限・応答の異常）は `permission_denied`／`unavailable` として数なしで残す。返る `observation_id` は候補比較の `observation_refs` に書ける。
  - 形の柵: 数だけの観測は許可リストの鍵だけ（本文・username・post_id・仮名の入る鍵があれば保存しない）・5 未満の値・正確な時刻を断る（`topic_models._check_tag_counts`）。
- **topic_advice が数える**: 数だけの観測の件数をトピックの使用例（`MIN_SAMPLES`）に、投稿者の数を `MIN_AUTHORS` に数える。**キーワード検索の結果とは混ぜない**（`search_mode: topic_tag` かつ `provider: threads_api` の観測だけ・読む側でも確かめる）。数だけの観測どうしの投稿者は足さない（同じ人を二度数えうるので、いちばん多い 1 件）。5 未満で欠測の数は「残していない」と言う（0 人とも言わない）。
- **判定は人か LLM**: 合うかどうか（`--note <語> --verdict alive|mismatch|dead`）は数では決まらない。出力の `note_hint` に、`--status` と観測 ID と数（同じく 5 未満は欠測・日付だけ）を入れた `--note` の 1 行を出す。
- 遠くの道（thth.me の鍵・`topics_search` の `tag`・`keep`）と MCP の `thth_topics_search`（`tag`・`keep`・`since`・`until`・`media`）に同じ引数を出した。
- `--keep` を `--tag` なしで、`--tag`・`--keep` を `--search` なしで使うと断る（黙って普通の検索や一覧に落とさない）。

## 広告の内訳で、反応が 0 件の区分が「不明」と出るのを直す

masaru 11/03「直して」。本番の 5.6.3 で `thth ads insights kopicha-ads --since 2026-11-01 --until 2026-11-03 --by age-gender` が、反応の無い区分を「いいね・リアクション 不明・リンククリック 不明」と出した。Meta は反応が 1 件も無い区分では `actions` の欄ごと返さない。

### 直したこと

- `actions` を頼んだ読みで、**同じ読みのほかの行に `actions` が返っていれば**、欄の無い行は 0 と見なす（反応・リンククリック・頁が開いた数）。json の行に `actions_absent_as_zero: true`、`site.why` に `actions_absent_as_zero`。`actions`（生の行）は null のまま（Meta が返したとおり）。
- **読み全体で `actions` が 1 行も返らないときは「不明」のまま**（`engagement: null`・`engagement_unknown: "actions_missing"`）。頼めたのか・Meta が出さなかったのかを区別できないため。内訳なしの 1 行の読み（口座の合計）もこちら。
- 欄が壊れている（並びでない）行は、ほかの行に `actions` があっても不明のまま（`actions_unreadable`）。
- 内訳なしでも複数行の読み（`--level campaign`・`adset`・`ad`）には同じ決まりを当てた（ほかの行に `actions` があれば頼めている）。

### 確かめ方

- 試験 `tests/test_ads_insights_engagement.py`（`test_読み全体でactionsが1行も返らないときは0でなく不明`・`test_内訳で反応の無い区分はactionsの欄が無くても0`・`test_内訳で全区分にactionsが無ければ不明のまま`・`test_内訳なしでも複数行の読みなら欄の無い行は0`・`test_欄が壊れている行は0にしない`）と `tests/test_ads_reads_563.py` の内訳の試験を新しい決まりに書き直した。決まりの判定をわざと「常に 0」「常に不明」に壊して赤を見た。

### 本番で確かめること

- 同じ `thth ads insights kopicha-ads --since 2026-11-01 --until 2026-11-03 --by age-gender` で、反応の無い区分が 0 と出ること。
