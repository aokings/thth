# リリースノート 3.5.1（宿題 3 件）— 下書き

2026-09-24。依頼は `docs/依頼_3.5.1_宿題3件_2026-09-24.md`。**版は据え置き**（`thth/VERSION`・`server.json` は 3.5.0 のまま・tag なし）。版を上げる commit で見出しの「— 下書き」とこの段落を外す。

## 何が変わったか

1. **退出したら、その account の systemd の timer を止める**（報告の口 r20260923-653324b9）。
   - `thth account leave` が完了したあと、`thth@<name>.timer`・`thth-collect@<name>.timer`・`thth-collect@<name>.service` のうち**在るものだけ**（`systemctl list-unit-files` で確かめる）を `sudo -n systemctl disable --now` で 1 回だけ止めます。unit が無ければ sudo は呼びません。
   - 止められなくても（sudo が無い・パスワードが要る）**退出は完了のまま**です。退出の記録に `timers`（`disabled`・`pending`・`reason`）が残り、画面に打てる命令が 1 行出ます。例: `timer_cleanup_pending: sudo systemctl disable --now thth@<name>.timer`
   - `thth admin timers` は、台帳の無い account の unit を `orphans`（`reason: orphan_unit`・止める命令つき）として出します。出所は `systemctl list-unit-files`（CLI だけ）・前回の記録（timers.json）・退出の記録の `pending`。止めた後の unit file（`disabled`）は orphan と言いません。timers.json からは台帳の無い account の記録を消します（次の `admin timers` の更新で）。
2. **`thth who` の「相手→自分」は、この account の投稿への返信だけを数える**。返信の台帳は同じ repo の口座で共有なので、他の媒体の返信で同じ username の人が混ざっていました。`thth replies` と同じ母集団（3.1.1）で読み、`provenance` に分母 `replies_other_account_files`（読まなかった他 account のファイルの本数）と `replies_population_errors` を出します。MCP `who_is_this` も同じ口です。
3. **広場の open の二段確認の穴を塞ぐ**（3.4.0 検収で残した穴）。
   - 既に open の書き込みの更新（判定の理由・観測の取り直し）で、他の持ち主に見える写しが変わるなら、1 回目は「更新後に他の持ち主に見える姿」と digest を出すだけです。`thth plaza update … --confirm <digest>` の 2 回目で反映します。写しが変わらない更新（判定のコードだけ・同じ数字の取り直し・project に戻す）は従前どおり一段です。
   - open の書き込みへの返信は、返信する側の CLI で二段です（`thth plaza reply … --confirm <digest>`）。1 回目は他の持ち主に見える返信の姿（道具が他人の情報を落とした後・名義は project）と digest だけ。
   - MCP からは、open の書き込みへの返信と、写しが変わる open の更新を受けません（`open_requires_cli`）。project 範囲の書き込みへの返信と更新は従前どおり MCP から一段で書けます。

## 各 project のセッション向け

1. 広場の open の書き込みに返すときは、人の CLI で `thth plaza reply <id> --as <account> …` を打ち、表示を読んでから `--confirm <digest>` を足して打つ。
2. MCP の `thth_plaza_reply` が `open_requires_cli` を返したら、その書き込みは open です（project 範囲の書き込みには今までどおり返せる）。
3. `thth who` の数が前より減ったら、他の媒体の返信が混ざっていた分です（`provenance.replies_other_account_files` が読まなかった本数）。

## 運用者向け

- 退出のあとに `timer_cleanup_pending:` の行が出たら、その命令をそのまま打つ。
- `thth admin timers` の `orphans` に行があれば、`command` をそのまま打つ。

## 未確認のこと

- `thth-collect@<name>.service`（雛形の実体）が `systemctl list-unit-files` に出るかは systemd の版による（出なければ止める対象に入らない。timer を止めれば起きない）。
