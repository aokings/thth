# THTH 5.32.0（2026-11-28）

鍵を入れる口の取り違えを、人が見ていなくても止まるように固めた版です（monban の秘密の入力口の前提・11/27）。あわせて、monban の家の秘密の係から呼ばれる口 `thth secret accept` を足しました。本番の台帳とのずれは THTH運用 第9 が 11/27 に確かめて 0 件（31 口座とも handle あり・user_id ありの 1 口座は一致）。監査は `docs/監査_5.32.0_2026-11-28.md`。Worker（`callback/`）は変わりません。

| 件 | 中身 |
|---|---|
| 口座の token（`thth token set`） | 台帳の handle が空なら保存しません（`token_handle_missing`）。台帳に user_id があれば、それも照合します。以前は handle が空だとどの口座の鍵でも入りました |
| WordPress の鍵 | 書く前に `users/me` を読み、台帳の wp_user と合ったときだけ書きます。合わなければ今の鍵を置き換えません |
| 店の token | 別の店の鍵を `--force` で覆せなくしました。初回は今のまま受け、その鍵の店が以後の照合の元になります |
| はてなの主体の鍵 | `thth principal auth` に `--begin`（認可の URL）と `--stdin`（確認の文字列）を足しました。`--consumer --stdin` は確かめてから書きます |
| `thth secret accept <種類> <受付> --by <名乗り>`・`thth secret kinds --json` | 新しい口。値は標準入力だけで受け、中の断りを決めた終了コード（0/3 置いた・10〜19 置いていない・70 思わぬ落ち）に直して返します。本人の口だけの印を持ちます |
| Meta 申請の録画 | 受信箱・DM・コメントを読む 8 区間は、試しの口座（shitami-fb・shitami-ig）でしか撮れない柵を `tools/appreview_rec.sh` に入れました |
| 括りの共通の層 段 A | 対応表 `thth.workspaces/1` を読む口と検査（`tools/workspaces_check.py`）。読むだけで、本番の動きは変わりません |
