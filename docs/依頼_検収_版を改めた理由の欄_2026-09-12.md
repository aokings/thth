## 1. 直したこと

**検収記録には `disposition_reason` があるのに、仮説には版を改めた理由を書く欄が
ありませんでした。** 運用セッションは当座 `claim` の末尾に書いていて、**本人が
「置き場所として間違っている」と自覚していました**——`claim` は主張そのものの欄
なので、版の運用メモが混ざると**次に読む人が主張の一部として読みます。**

- **`supersedes` を書くなら `supersede_reason` も要る**（空文字列・空白だけは
  「書いた」に数えない）
- **版を改めていないのに理由だけは書けない**（何の理由か判らない）
- **一覧にも出す**——出さないと「差し替わっている」ことは読めても
  「**何を間違えていたか**」が読めません。そこがいちばん価値のある部分です
- **キー自体は任意**（既存の入力を一斉に書き換えさせない）。ただし**無ければ
  `null` で埋めてから内容 ID を計算**します——書いた記録と書かなかった記録で
  ID が変わると、**同じ仮説が 2 件に見える**ため

## 2. **判定をお願いしたいこと**

1. **`supersedes` があるとき必須にしたこと。** 任意欄にしておく選択もありました。
   **理由が無い版の差し替えを拒むのは「足しすぎ」ではないか。**
2. **任意欄を `null` で埋めてから内容 ID を計算していること。** 既存の保存済み
   記録は `supersede_reason` を持たないので、**同じ中身を再登録すると別 ID に
   なります**（旧: キー無し／新: `null`）。**これを避ける手はありますが、避けると
   「欄の有無で ID が変わる」を別の形で残すことになります。** どちらが良いか。
3. **`REVIEW_OPTIONAL` は宣言だけで機械では効いていません**（grep で確認：
   定義箇所以外に参照がありません）。今回 `HYPOTHESIS_OPTIONAL` を作りましたが、
   **これも `build_hypothesis` の中でしか使っていません。** 揃えるべきか、
   このままで良いか。
