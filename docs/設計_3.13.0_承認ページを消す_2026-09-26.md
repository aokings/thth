# 設計 3.13.0: 承認ページを消す（2026-09-26）

状態: **下書き（masaru の確認待ち）**。確認が取れたら段に割って作る。

## 0. 見方の一行と決定（masaru・2026-09-26 昼）

> THTH は、SNS を調べ・投稿し・予約する **CLI ツール**。だから LLM が操作しやすい。MCP と skill はその補助。thth.me とサーバは、CLI を外の人にも届ける裏方。

- 「不要なところに置かれた金庫なんて邪魔なだけ」。承認ページは**選べる設定としても残さず、消す**。
- 3.12.0 の「口座ごとに none / publish / all を選ぶ」は前のセッションの夜間の裁定で、masaru は認めていない。
- masaru 自身の手元の `thth approve`（自分の repo の queue に置く二段）は別物で、この版では触らない。

## 1. 消すもの（利用者から見える形）

| 何 | 今 | 3.13.0 |
|---|---|---|
| 承認ページ `https://thth.me/approve/<token>` | 公開・削除を本人が secret で押す | **無くす**（404） |
| 承認待ちの一覧 `https://thth.me/pending` | 一覧から承認ページを開く | **無くす**。招待の完了ページの「保存して承認待ちの一覧を開く」は `/activity` へ |
| 口座の設定 `approval`（none/publish/all） | 台帳の項目・`thth account set … approval`・MCP `thth_settings` の `approval` | **無くす**。台帳にあっても読まない（`account status` で「古い項目」と 1 語） |
| MCP `thth_approval_request` | 承認 job を作る（none の口座では予約に流す） | **無くす**。予約は `thth_schedule_request` だけ |
| CLI `thth admin approval request` | 承認要求を運営者が置く | **無くす** |
| 招待の `--approval` | 審査員向けに all | **無くす** |
| 「承認 secret」という呼び名 | 招待の完了ページ・`/activity`・文書 | **「口座の secret」**に改める（`/activity` に入る・鍵を発行する・止めたのを戻す・緩める、のための本人確認。公開には使わない） |
| 録画 0・`tools/appreview_rec0.sh`・申請の文 §2.1〜§2.3 の承認の流れ | — | **消す／書き直す**（外向け CLI の設計と一緒に） |

公開・返信・削除・予約は、**LLM や CLI が頼んだらそのまま行う**（3.12.0 の `approval: none` の道が唯一の道になる）。安全装置は変えない。

## 2. 残すもの（名前だけ改める）

「承認」の名を持つが、承認の関所ではなく裏方の部品として使われているもの。**動きは変えず、名前だけ「承認」を外す**（3.13.0 の段 2・機械的な改名）。

| 今の名 | 何をしているか | 新しい名 |
|---|---|---|
| `thth approval-worker`・systemd `thth-approval-worker` | 招待の完了を拾う・`/activity` の要約を押し上げる・`/activity` で頼まれた操作（止める・戻す・鍵）を行う・版が動いたら自分で終わる | `thth worker`・`thth-worker` |
| `thth/approval_relay.py` | VM→Worker の署名つき要求（`OPAQUE`・鍵の置き場・`signed_request`）。招待・退出・添付・削除の受け口が使う | `thth/relay.py` |
| Worker の `ApprovalPerson`（DO） | 持ち主ごとの入り口: `/activity` の要約・操作・secret の照合・回数制限 | `Person` |
| Worker の `ApprovalAccount`（DO） | 口座ごとの束（退出・添付の後始末） | `Account` |
| Worker の `ApprovalSession`（DO） | **承認ページの本文の預かり**。消す（§1） | — |
| `APPROVAL_PUBLIC_KEY`（Worker の変数）・`APPROVAL_*_LIMIT`（回数制限の名前） | VM の署名の検証・回数制限 | `RELAY_PUBLIC_KEY`・`RELAY_*_LIMIT`（wrangler の名前を変えるだけ・値は同じ） |
| `hold_minutes`（取り消しの猶予） | 持ち主が選ぶ安全装置（既定 0）。承認ではない | 残す |

## 3. 消したあとの台帳と既存の口座

- 台帳の `approval` は読まない。既存の `inv-…` の口座（3.11 以前の招待・録画用の `inv-jiangshi-lab-fce905`）は、この版から承認なしで動く。持ち主に知らせる相手は今いない（masaru の口座と録画用だけ）。
- 承認 job の置き場 `state/<口座>/approval/*.json` に残っているものは、起動時に `expired` にして残す（消さない・記録）。
- Worker の DO に残っている承認 session は、期限（10 分）で自然に消える。deploy の順は Worker が先・VM があと（VM が `/pending` 用の要約を押し上げなくなる）。

- 利用規約・privacy: 「Approve each post yourself」「Human approval pages」の段を外し、「持ち主が自分の CLI か AI アシスタントで頼んだら行う。安全装置は持ち主が決める」に改める（下書き `docs/下書き_利用規約とprivacyの3.12改訂_2026-09-26.md` を土台に、承認の記述を全部落とす）。施行日は配布の日。
- `callback/public/llms.txt` の冒頭 "human-approval gate" → 「CLI ツール。LLM はそれを代わりに打つ」。
- `docs/導入_招待されたら.md` と `docs/運用_招待する側.md`、README、skills の「承認」の記述（117+30 か所）を改める。
- 申請の文（`docs/手順_Meta申請_世間の層_2026-09-24.md`）§1.1 の前置き・§2 の試験の手順・§5 の録画 0 は、**外向け CLI の設計（次の版）と一緒に書き直す**。この版では「承認ページを前提にした文は使わない」の印だけ付ける。
