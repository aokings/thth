## 1. 共通の前置き（各権限の説明の先頭に貼る）

```
THTH is an open-source command-line tool for publishing and managing posts on a person's own social media accounts. People usually drive it through their own AI assistant (for example Claude Code): the assistant runs the same commands a person would type. The operator (gotoq) runs the server side: people connect their own Threads account on Meta's authorization screen and receive a personal key; they do not run a server or a Meta app of their own. With that key, the `thth` command on their own computer acts on their own account through the operator's server. THTH acts only when the account's owner (or the owner's assistant) asks for it, and never posts, replies or deletes on its own. Because an assistant can make mistakes, every account has safety limits that the owner controls: a minimum interval between posts, daily caps on posts and deletions, and an automatic stop when too many actions happen within ten minutes. An assistant can only tighten these limits; loosening them, resuming a stopped account and issuing or revoking the key are done by the owner on https://thth.me/activity with their account secret, where they also see everything that was published or deleted. THTH itself sends no data to AI providers; what a command shows is passed to the owner's assistant only when they use one. Access tokens reach the operator's server through the authorization flow, are kept in owner-only files, are redacted from logs and output, and are never returned to the command or to assistants; the key is shown once and only its hash is kept. Privacy policy: https://thth.me/privacy/ — Terms: https://thth.me/terms/
```

## 2. `threads_basic`（前置きの後に続けて貼る）

```
threads_basic identifies the Threads account THTH acts for and lets the owner see their own posts. When the account is connected, THTH reads its user ID and username (/me) and keeps them with the account, so every later action is bound to that account; `thth doctor <account>` repeats this check and shows what the token can do. `thth posts <account>` lists the account's own recent posts (ID, link, time and text) so the owner can check what is live and choose a post to reply to or delete. Before a reply is sent, THTH may read the one post being answered to record a one-way key for its author; the text of that post is discarded.

Screencast: review0.mp4 at 0:00–1:13 (authorization) and 2:47–3:05 (`thth posts`: the account's own posts). The whole video is one reviewer flow: invitation → Threads authorization → `thth login` → commands → the owner's activity page.
```

## 2. `threads_content_publish`（前置きの後に続けて貼る）

```
THTH publishes a post when the owner asks for it: through their own AI assistant or the `thth` command on their own computer (`thth send <account> --text …`), which sends the text and THTH publishes it, or schedules it when the account has a scheduler. The text, with its topic tag, reply target, place and attachments if any, is sent unchanged through the container-then-publish flow. Before publishing, THTH checks the account's safety limits (minimum interval, daily cap, quiet hours, burst stop) and refuses with the time when it may try again. Images have location and other embedded metadata removed before upload, and attachments reach Threads through short-lived links. The resulting post ID and link are recorded in the account's post history on the operator's server.

Screencast: review0.mp4 at 3:05–4:45 (`thth send` publishes; the post is then shown in the Threads app). The whole video is one reviewer flow: invitation → Threads authorization → `thth login` → commands → the owner's activity page.
```

## 2. `threads_manage_replies`（前置きの後に続けて貼る）

```
THTH uses threads_manage_replies to post the owner's replies: to replies under their own posts, to mentions of their account, or to a public post they chose to join. A reply names the post it answers (`thth send <account> --text … --reply-to <post_id>`) and is sent when the owner asks for it through their own assistant or command, the same way as a post. Replies count toward the daily cap and the burst stop. THTH never replies on its own. It does not hide replies or change the reply settings of existing posts.

Screencast: review0.mp4 at 4:45–6:10 (`thth send --reply-to`; the reply is shown under the post in the Threads app). The whole video is one reviewer flow: invitation → Threads authorization → `thth login` → commands → the owner's activity page.
```

## 2. `threads_read_replies`（前置きの後に続けて貼る）

```
THTH reads the conversation under the owner's own posts so they can see who answered and decide whether to reply. Its collection (`thth collect`) fetches the full reply tree of each recent post at fixed ages after publishing, from 1 hour to 30 days, and saves each reply's username, text, time and link in the account's records on the operator's server. `thth replies <account>` shows these replies, and `thth unanswered <account>` lists the ones not yet answered. `thth thread <account> <post_id>` reads a branch on request and saves nothing. The saved replies are kept until the account leaves THTH.

Screencast: review0.mp4 at 6:10–6:35 (`thth replies --refresh` reads the replies to the account's posts). The whole video is one reviewer flow: invitation → Threads authorization → `thth login` → commands → the owner's activity page.
```

## 2. `threads_manage_insights`（前置きの後に続けて貼る）

```
THTH measures how the owner's posts were received so they can learn which topics and forms work for them. Its collection reads each post's views, likes, replies, reposts, quotes and shares at fixed ages after publishing (1 hour, 6 hours, 1, 3, 7 and 30 days), and once a day reads the account's metrics for the previous day (views, likes, replies, reposts, quotes, followers and link clicks). The numbers are saved in the account's records on the operator's server and shown to the owner with `thth measured <account>`, `thth topics <account>` and the daily observation summary. If the owner chooses, figures computed from their own metrics can be posted on THTH's plaza, which by default is visible only within the same project; showing a post to other owners requires joining and a two-step confirmation.

Screencast: review0.mp4 at 6:35–7:20 (`thth collect` fetches the metrics; `thth measured` shows them). The whole video is one reviewer flow: invitation → Threads authorization → `thth login` → commands → the owner's activity page.
```

## 2. `threads_delete`（前置きの後に続けて貼る）

```
THTH deletes a published post only when the owner asks for it: through their own AI assistant or the command `thth retract <account> <post_id>` (on the operator's own accounts the command first shows the post and a digest and deletes only when that digest is confirmed). Deletions have their own daily cap and count toward the burst stop, so a malfunctioning assistant cannot delete an account's history. THTH sends one DELETE request for that post ID and reports success only when Threads confirms it. The time, the person and the reason are added to the account's record of that post. THTH never deletes posts on its own.

Screencast: review0.mp4 at 7:20–8:02 (`thth retract` deletes; the post is gone in the Threads app; `thth posts` no longer lists it). The whole video is one reviewer flow: invitation → Threads authorization → `thth login` → commands → the owner's activity page.
```

## 3. 試験の手順（Test instructions / How to access）

```
**How to test THTH (about 10 minutes; a terminal with Python 3.12 or later is needed)**
You need a Threads test account and a password manager (or another safe place) for two values shown once. Each link below is valid only during the review and can be used once; if a link says it is no longer valid, use the next one.
- Invitation 1: `<INVITE_URL_1>`
- Invitation 2: `<INVITE_URL_2>`
- Invitation 3: `<INVITE_URL_3>`
1. Open an invitation link. The page "Invitation to THTH" explains what will happen and lists the permissions requested. Press "Threads で認可する / Authorize with Threads".
2. After a few seconds the page shows "Open Threads authorization". It opens in a new tab: log in with your Threads test account and allow the permissions. Go back to the first tab; it continues on its own (within 10 minutes).
3. The page "Your account is ready" shows your Threads username and your THTH account name (like `inv-review-a1b2c3`). Press "Show account secret" and save the two values the next page shows once: the **account secret** (under "Account secret"; used on https://thth.me/activity) and the **assistant key** (under "Assistant key"; used by the `thth` command).
4. In a terminal: `pip install thth` then `thth login`. It opens https://thth.me/login/… in your browser: enter your account name and account secret and press "Allow this device"; the terminal then says it saved the key. (If a browser is not available, run `thth login --stdin` and paste the assistant key from step 3.) From here every step is one command; replace `ACCOUNT` with your THTH account name.
5. `thth posts ACCOUNT` — lists your own recent posts (threads_basic).
6. `thth send ACCOUNT --text "Testing THTH for Meta App Review."` — publishes and prints the post ID and link (threads_content_publish). Check the post in the Threads app.
7. `thth send ACCOUNT --text "A reply, sent the same way." --reply-to <post ID from step 6>` — publishes a reply (threads_manage_replies). Check it under the post.
8. `thth replies ACCOUNT --refresh` — reads the replies to your posts (threads_read_replies).
9. `thth collect ACCOUNT` then `thth measured ACCOUNT` — fetches and shows the post metrics (threads_manage_insights). Metrics may still be zero for a new post; the command shows the numbers Meta returned.
10. `thth retract ACCOUNT <post ID from step 6>` — deletes the post (threads_delete). It disappears from Threads; `thth posts ACCOUNT` no longer lists it.
Optional: `thth topics ACCOUNT --search coffee` (keyword search, aggregate figures only), `thth mentions ACCOUNT`, `thth profile ACCOUNT threads`, `thth location search ACCOUNT "Menlo Park"`. `thth account status ACCOUNT` shows the safety limits and today's counts. https://thth.me/activity (username = account name, password = account secret) shows what was published and deleted and lets you stop the account.
Nothing is published, replied to or deleted unless you (or an assistant you connect with your key) run a command. The safety limits refuse a post sooner than 6 hours after the previous one (`too_soon`), except replies; during the review this limit is set to 0 for test accounts so that steps 6 and 7 run back to back.
**After the review** the operator removes your test account from THTH (`thth account leave`), which deletes its data on the operator's server. You can also remove THTH from your Threads settings and run `thth logout`.
```

### `threads_keyword_search`

```
THTH uses keyword search so the owner can see what people are saying about a topic before posting or joining a conversation. On request (`thth topics <account> --search <word>`, `thth where <account> <words>`), and in the daily observation summary using up to 5 keywords the operator sets for the account, it shows counts, distinct authors, the latest time and, for individual posts, the author, a link and the first 60 characters; these results are shown for that request only, and their text and authors are not saved. Separately, the observation map, which is off by default and turned on by the operator, searches at most once a day for topic keywords that a person registered for a project (at most 20; @handles, URLs and personal names are refused). From those results it saves only daily figures per keyword for at most 180 days: the number of posts, distinct authors, the share of the three most frequent authors, a rounded age of the latest post and co-occurrence counts, with any number below 5 stored as missing. It never saves post text, post IDs, usernames or links, shows the figures only within that project, and deletes them when the project leaves or on request. When the owner wants to join a conversation found this way, THTH can show that public post's thread on request (`thth thread <account> <post_id>`, read on the spot and not saved) and reads the one post being answered when a reply is prepared; any reply the owner makes is handled like a post (section on threads_manage_replies).
```

### `threads_manage_mentions`

```
THTH retrieves public mentions of the owner's own Threads account so they can see who is talking to them and decide whether to answer. Its collection saves each mention (username, text, time and link) in the account's records on the operator's server. `thth mentions <account>` shows current mentions on request and marks the ones already answered, and the daily observation summary lists the ones not yet answered. Any answer is a reply the owner sends the same way as a post; THTH never replies automatically. Saved mentions are kept until the account leaves THTH.
```

### `threads_profile_discovery`

```
THTH looks up public Threads profiles on the owner's request so they can understand the accounts in their conversations, for example someone who replied to or mentioned them, or an account posting on the same topic, before deciding whether and how to engage. `thth profile <account> <username>` (and `thth who <account> @username --profile`) requests only public fields: username, name, profile picture, biography, follower count, total likes, quotes, reposts and views, and verification status. The result is shown for that request and is not saved. THTH does not look up profiles on its own.
```

### `threads_location_tagging`

```
A draft may name a place. `thth location search <account> <name>` shows up to 5 candidate places (name, address, city, country and ID), and the owner writes the chosen place into the draft. The place name and ID are shown with the text before it is sent, and only that post carries the tag. THTH never infers or adds a location on its own, and location search results are not saved.
```
