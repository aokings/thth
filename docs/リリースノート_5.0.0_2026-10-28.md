# リリースノート 5.0.0（キャンペーン・シリーズと、会話の中のダッシュボード）

2026-10-28。はてなブックマーク・はてなブログ・自社の記事・SNS を一続きで回し始めると、どこかの段が抜けたり、出したものがどの話にも結ばれていなかったり、動いていた話が止まったまま忘れられたりしがちです（masaru 10/28「抜けたり漏れたり忘れたりしちゃいがち」）。5.0 は、THTH が「どの話がどの段で止まっていて、次に何が要るか」を数えて出す版です。原稿を書くのも段を進めるのも、今までどおり窓口の LLM と承認です。THTH は書きません。

設計: [設計_5.0_シナリオと一覧_2026-10-28.md](設計_5.0_シナリオと一覧_2026-10-28.md)。

## 変わったこと

### キャンペーンとシリーズ（段 1）

- 窓口の repo の `docs/sns/scenarios/<id>.md` に宣言を置けます（`thth_scenario: 1`）。
  - **キャンペーン**（`kind: thread`）: 1 つのテーマが リサーチ（はてなブックマーク）→ 仮説（はてなブログ）→ 本記事（自社の記事）→ SNS 告知 → エンゲージ と進みます。段の並びと、窓口が書く出来事の行（`researched`・`article_published` など）を持ちます。
  - **シリーズ**（`kind: series`）: 決まった枠（曜日と時刻）で出し続ける定期投稿です。`slots`・`stock_floor`・`material_remaining`。行事の型は `deadline: true`。
- 原稿の front-matter に `thread: <id>`・`series: <id>` を 1 行書くと結ばれます。**承認の指紋には入りません**（あとから付けても承認し直しは要りません）。lint は予告だけで断りません。
- `thth scenario <project|口座> [--json]`・`thth scenario show <project> <id>`・`thth scenario lint <project>`。`--json` は `thth.scenario/1`。現在地は毎回、今ある台帳から数え直します（新しい台帳は作りません）。
- シリーズのストックは「回」で数えます（同じ枠に Threads と X の両方があって 1 回）。枠の時刻は前後 15 分まで同じ回とみなします。
- `thth events` に 2 種類: `scenario_stalled`（キャンペーンが `stale_after_days`〈既定 7 日〉動いていない）・`series_low`（シリーズの承認済みストックが目安を切った）。hub の朝の一枚に載せられます。
- 宣言を 1 つも置いていない口座は、出力も振る舞いも 4.5.6 と同じです（events の種類の数え〈`by_kind`〉に 0 件の 2 種類が増えるだけ）。

### 会話の中の 3 階層のダッシュボード（段 2）

- thth.me に画面は作りません。**利用者の LLM が会話の中に描きます。** THTH は中身を `--json` で出し、画面の型を skill と一緒に配ります。
- `thth dashboard [--json]`（全メディア）・`thth dashboard <project> [--json] [--full]`（メディア）・`thth dashboard <project> campaign <id>`・`thth dashboard <project> series <id>`。`--json` は `thth.dashboard/1`。
- 要対応は 1 本の列（`attention[]`）で、押したときの指示文（`actions[].prompt`）も THTH が作ります。LLM はそれを受けて CLI を動かします。取り下げと公開の承認そのものはダッシュボードに置きません。
- インプレッションとエンゲージメント率は口座をまたいで足しません（口座ごとに並べます）。取れない数（ブログ PV・本記事へのクリック）は「—」と理由です。
- 型は `skills/thth/dashboard/` の 4 つ。`--json` の答えを 1 か所に貼るだけで描けます。見た目の直しは型の commit だけで済み、release は要りません。
- thth.me 経由（遠くの道）でも `thth dashboard <口座>` が使えます。鍵の口座の範囲だけが見えます。
