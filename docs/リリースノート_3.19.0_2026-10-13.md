# リリースノート 3.19.0（X のコミュニティ・トレンド・語ごとの投稿数）

> **10/13 の注記（先に読む）**: X のコミュニティは 2026 年 5 月から廃止・非推奨（masaru が X の画面で確認。作成の口が無い。docs.x.com の changelog には記述なし）。関東が 14 語で探して中学受験のコミュニティは 0。**新しく作ることはできないが、今あるコミュニティへの投稿は温存して試す**（masaru 10/13。通るかは未試験）。`community search`・`--community` はそのため残す。トレンド・語ごとの投稿数は影響なし。

2026-10-13。依頼は関東レーン #1933、masaru 10/13「X のコミュニティを試してみて」。背景: X の自己サーブ API では、呼ばれていない相手への返信（2026-02-23〜）・いいね・フォロー・引用（2026-04-16〜）が使えない（docs.x.com/updates/changelog・`docs/調査_Xで伸ばす_…_2026-10-12.md` の訂正と §10）。コミュニティへの投稿は、自分の投稿のまま届く先を広げる候補。**X のアカウントならどれでも使える。認可のやり直しは要らない**（tweet.read・users.read・tweet.write はいまのトークンにある）。**下書き・未配布**（push・release・tag は masaru の一言で）。

## 足したこと

- **`thth community search <account> <語…> [--limit N] [--json]`**: `GET /2/communities/search` を 1 回（語は空白でつないで 1 回だけ）。行は公開の欄だけ——id・名前・説明（1 行・280 字まで）・人数（member_count）・join_policy・access・作成日・URL。既定 10 件・最大 25 件（X の下限が 10 なので、10 未満でも 10 件分を押さえる）。**返すだけで保存しない**（runs には件数だけ・語も名前も書かない）。X 以外は rc=2 `unsupported_on_platform`（`cannot_say` に理由）。
- **`thth send <account> --community <id>`**: `POST /2/tweets` の body に `community_id`。**digest に入る**（dry-run で見せた digest でなければ送らない）。値が無いときの digest は今までと同じ。
- **queue の front-matter `community_id: <id>`**（timer が出す原稿）: **承認の指紋に入る**（値があるときだけ末尾に足す任意項目・`location_id` と同じ形。既存の `approved_sha` は 1 つも変わらない・指紋の版は 2 のまま）。承認の一段目に「X のコミュニティ <id> に出ます」と出る。
- 断る形（lint・select・send・adapter の 4 か所で同じ門）: X 以外の媒体の原稿に `community_id`／19 桁までの数字でない／**返信（`reply_to`・`reply_to_file`）と同時**。連投（`thth: 2`）にも書けない（2 段目以降は自分への返信なので）。lint の符丁は `invalid_publish_option`、select は `community_id_invalid`。
- **sent の記録に `community_id`**（自分の投稿のメタデータ・あとで数字をコミュニティごとに見るため）。collect（Owned Reads）は今のまま。
- 添付つきの投稿が断られたときも、添付なしと同じ流儀で X の文面を短く残すようにした（`media_publishing_http_403: x_unknown_refusal（…）`）。

## 参加していないコミュニティ

- **参加の API は無い**（docs.x.com の索引にコミュニティは「Get Community By Id」「Search Communities」と、create-post の `community_id` だけ。join の口は無い）。**参加は X の画面で一度だけ**、先にしておく。
- **「自分が参加しているか」を示す欄も無い**（`community.fields` は access・created_at・description・id・join_policy・member_count・name の 7 つ）。送る前には分からないので、送って X の断りを 3.18.2 の流儀で残す（`x_publish_http_403: x_unknown_refusal（type=… / title=… / detail=…）`）。符丁 `x_community_not_member` は実機の文面が取れてから足す（推測で文面を決めない）。

## 費用（月の X 予算 `thth admin budget x` に入る・推定であって請求額ではない）

- 探す: Community: Read **1 件 0.005 USD**（返ってきたコミュニティの数）。台帳は別のファイル `state/_admin/budget_x_community_reads.json`。作法は他人の投稿の読み取りと同じ（要求の前に押さえる・断りの応答は 0 で確定・応答が読めなければ押さえたまま「不明」）。**1 日 60 本（`x_daily_reads`）には数えない**——あれは他人の**投稿**を読んで返す出向きの決まりで、コミュニティの一覧は投稿ではない（Owned Reads・リストの書き込みと同じ扱い）。`thth admin budget x` と `thth doctor` に「コミュニティの検索」の行（使った月だけ）。`--json` は `community_read`。
- 出す: 普通の投稿と同じ（Post: Create 0.015 USD・URL 付きは 0.200 USD）。月間投稿数の上限（`thth admin budget x-posts`）に数える。

## 決まり（道具では守らせきれないので、各セッションが守る）

- **宣伝の禁止など、各コミュニティの規則は人が読んで守る。**
- X の自動化の決まり（bulk・無差別の投稿の禁止）に従う。検索の結果へ機械的に出さない。同じ本文を複数のコミュニティへ流さない。

## 確かめていないこと

- 実 API では未試験（試験は偽の HTTP）。自己サーブの tier で `community_id` 付きの投稿と検索が通るかは資料に条件が書かれていない。
- 参加していないコミュニティへの断りの文面（実機で取れたら符丁にする）。
- 検索の応答の欄の中身（join_policy・access の値の語彙）は資料に説明が無い。表示はそのまま出す。
- コミュニティの URL（`https://x.com/i/communities/<id>`）は X の画面の形に合わせた（資料には無い）。
- 断りの応答（4xx）に料金が掛かるかは未確認（0 で確定にしている）。

# 同じ 3.19.0 の追加: トレンド `thth trends` と語ごとの投稿数 `thth counts`

masaru 10/13「両方やって」。どちらも X だけ（X 以外は rc=2 `unsupported_on_platform`・`cannot_say` に理由）・1 回の命令で要求は 1 回（続きは読まない）・**返すだけで保存しない**（runs には件数だけ）・MCP には無い。

## 足したこと

- **`thth trends <account> [--woeid N] [--max 1〜50] [--json]`**: `GET /2/trends/by/woeid/:woeid`（`trend.fields=trend_name,tweet_count`）。既定は日本（23424856）・20 件。投稿数が返らないトレンドは `null`（0 にしない）。
- **`thth counts <account> <語> [--granularity hour|day] [--json]`**: `GET /2/tweets/counts/recent`（直近 7 日・既定 day）。区間ごとの `post_count` と合計（`meta.total_post_count`）。語は空・制御文字・512 字超を要求の前に断る（512 字は rate limit の表の「512 query length」）。X の検索の演算子（`lang:ja` など）はそのまま書ける。`minute` は受けない（7 日を分で割ると 1 回で返りきらない）。

## 費用（月の X 予算 `thth admin budget x` に入る・推定であって請求額ではない）

- 料金表（**L1** docs.x.com pricing「Charged per request」）: **Trends 0.010 USD／request**・**Counts: Recent 0.005 USD／request**。要求 1 回を 1 単位として、種類ごとに別の台帳（`state/_admin/budget_x_trends.json`・`budget_x_counts.json`）に押さえ→確定（断りの応答は 0・応答が読めなければ押さえたまま「不明」）。**1 日 60 本（他人の投稿）には数えない**。`thth admin budget x`・`thth doctor` に「トレンド」「語ごとの投稿数」の行（使った月だけ）。`--json` は `trends_read`・`counts_read`。

## 確かめたこと・確かめていないこと

- 資料の security は両方とも OAuth2UserToken か BearerToken（L1）。**tier の条件は資料に書かれていない**（未確認）。
- rate limit（docs.x.com rate-limits の表・L1）: trends は app ごと 75／15 分、counts は app ごと 300／15 分。**利用者ごとの欄はどちらも「—」**——いまのトークン（利用者の OAuth2）で通るかは実機で未確認。断られたら X の文面が `x_trends_http_403: x_unknown_refusal（…）`／`x_counts_http_…` で残る。
- 実 API では未試験（試験は偽の HTTP）。応答の欄は資料どおり（`post_count`・`total_post_count`）に読み、古い名前（`tweet_count`・`total_tweet_count`）も読む。
- 断りの応答（4xx）に料金が掛かるかは未確認（0 で確定にしている）。
