## 今の登録の流れ（`docs/導入_招待されたら.md` §2 より）

1. 招待の URL を開く → 「THTH への招待」
2. 「Threads で認可する」を押す → 数十秒待つ
3. 「Threads の認可ページを開く」→ **新しいタブ**で Threads → 許可
4. 「受け付けました」→ **最初のタブに戻る** → 数十秒で「用意ができました」
5. 「アカウントのシークレットを表示する」→ **1 度だけ**、アカウント名（`inv-…`）・アカウントのシークレット・API キーの **3 つ**をパスワードマネージャーに保存
6. ターミナルで `pip install thth` → `thth login` → ブラウザで `/login/…` → アカウント名とシークレットを入れて「このデバイスにキーを渡す」
7. `thth account status <アカウント名>` で確かめる
8. （アシスタントを使うなら）`claude mcp add thth -- thth-mcp` とスキル

## 読んで気づいた引っかかり（候補・新しいセッションで現物を撮って確かめる）

1. **1 度だけの値が 2 つある**: アカウントのシークレットと API キー。ふつうは `thth login` がキーを受け取るので、利用者が API キーを保存する場面はほとんど無いのに、5 で両方を見せて「別々に保存」と求めている。
2. **キーの呼び名が揺れている**: 「API キー」（導入の書・login.js）・「アシスタントキー / assistant key」（invite.js）・「LLM のキー」（activity.js）。「アカウントのシークレット」の前後に余計な空白も（invite.js 64 行）。
3. **タブの行き来**: 3〜4 で新しいタブを開いて、元のタブに戻って待つ。
4. **アカウント名が覚えにくい**: `inv-jiangshi-lab-aea471` のような名前を、シークレットと一緒に打たせる（6）。
5. **日本語と英語が同じ行に並ぶ**: 「LLM のキーを発行する / Issue a key for your LLM」の形が全画面にあり、読みにくく見た目も重い。
6. **段の数が多い**: ブラウザ → ターミナル → ブラウザ → ターミナル と 2 往復する。
7. 見た目: 素の HTML に近く、書体・余白・色の決まり（デザイントークン）が無い。
