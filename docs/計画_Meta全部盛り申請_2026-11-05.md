## 0. 先に結論

- **申請するもの: 権限 38（説明の差し替え 10・新しく Advanced 21・masaru の判断つき 7）・機能 11・段 1（Marketing API の Full）・webhook の購読 3 系統（§1.7 の数え上げ）。** Threads の 10 権限は承認済みなので「説明の差し替え」として出す。判断つき 7 が落ちれば権限 31。
- **今の THTH に呼ぶ口が無く、申請のために最小の口を作るもの: 12**（§1 の「作る口」の列・§4 の段 2〜4）。原文が「録画に映っていない権限は承認しない」【一次 11/05】と言うので、口の無い権限は出しても落ちる。だから「全部盛り」は「全部の口を最小でも作ってから 1 回で出す」の意味になる。
- **masaru に判断を出す点は 5 つ**（§3.4・§1 末尾）: ①`pages_messaging`・`pages_utility_messaging`・`instagram_manage_messages`・機能 Human Agent（推し: 入れる・最小の口つき）、②`ads_mcp_management`（公式の広告 MCP のユースケースを THTH のアプリに足す・推し: 入れる）、③`publish_video`＋機能 Live Video API（推し: 入れる・録画に実配信が要る）、④`pages_user_gender`・`pages_user_locale`・`pages_user_timezone`・`email`（推し: 落とす。原文の理由と代償は §1.9）、⑤`leads_retrieval`（推し: 入れる・読む口だけ）。
- **masaru の手は 3 回に収める**（§5）: (a) Dashboard で構成と機能を揃える日、(b) 録画の日、(c) 提出の日。(a) と (c) は同じ日にできる可能性があるが、録画の前に自社口座の再認可（D）が要るので (a) が先。
- **大事な制約は 4 つ**（§3）: 録画は権限を使う操作を映す／提出の 30 日以内に権限ごとに成功の呼び出し／承認後も 28 日・90 日の不使用で止まりうる／再同意は 90 日。どれも原文を §3 に引いた。

## 3. 大事な制約を正直に

### 3.1 録画は権限を使う操作を映す。試せない権限は落ちる

- Platform Terms 7(e)(iii): 「開発者のアプリが28日の期間内に使用またはアクセスしなかったプラットフォームのAPI、権限または機能がある場合」「弊社は、開発者への通知の有無にかかわらず、そのAPI、権限または機能に対する当該アプリのアクセス権の一時停止または取り消しを行うことがあります。」【一次 11/05・terms】

### 3.4 masaru に判断を出す点（推しつき）

- 代償: writer 2〜3 日【推】・privacy に「メッセージの本文は保存しない・相手の id は 24 時間の窓の判定に要る分だけ」の段・録画 2 本・**28 日の不使用で止まりうる**（自社に DM が来なければ使わない）→ 止まったらその権限だけ出し直し（1 週間前後）。審査で「over-requesting」と見られる危険は、口が本物で録画に映れば原文の条件を満たす【推】。

**② `ads_mcp_management`＋ユースケース「広告 MCP サーバーで広告を作成・管理」**
