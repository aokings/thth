# THTH 5.15.0（2026-11-12）

ネットショップ（BASE）を読む口を足した版です。設計は [設計_ショップとWordPressの口_2026-11-12.md](設計_ショップとWordPressの口_2026-11-12.md)（masaru 11/12「ショップ優先」「推しの通りで OK」）。WordPress の口は 5.16.0 に分けました（枝 `wip/wordpress-5.16.0`）。

## 足したこと

`thth shop` に、店を読む動詞を足しました。今の Instagram の商品タグの動詞（eligibility・catalogs・products・tags・tag）は、名前・引数・出力とも変えていません。

| 命令 | すること |
|---|---|
| `thth shop add <店> --kind base --project <p> --by <名前>` | 店を台帳に足す（`stores/<店>.json`・0600） |
| `thth shop token set <店> --expires YYYY-MM-DD --by <名前>` | BASE の個人用アクセストークンを受け取る（隠した入力か標準入力だけ・`~/.config/thth/store-<店>.token`・0600） |
| `thth shop whoami <店>` | 鍵の確かめ（店の ID・名前・URL・公開しているか） |
| `thth shop items <店>` | 商品の一覧 |
| `thth shop diff <店> [--accept]` | 前の写しとの違い（新しい・再入荷・値下げ・売り切れ・公開の切り替え）。読むだけで、写しを進めるのは `--accept` のときだけ。初めは基準を取るだけ |
| `thth shop draft <店> --to <口座> (--item <id> \| --kind …)` | 違いから投稿の下書きを 1 本（上限 3 本）作る。承認されていない形 |
| `thth shop remove <店> --by <名前>` | 二段確認で、店の台帳・写し・鍵を消す |

- 鍵の期限は `token set` のときに受け、`thth morning` が 14 日前から知らせられます（店の台帳がある機械の morning だけで、その機械の口座の台帳に同じ project の口座があるときに限ります。VM の morning には出ません。本物の手元の機械では未確認）。
- `thth approve` は、店の下書き（頭に `from_store:` がある原稿）を確定するときに商品を 1 回読み直し、値段・公開・買えるかが変わっていれば `store_item_changed` で断ります。店の台帳が無い機械（VM など）では読み直さずに 1 行知らせて通します。
- `thth leave` は、project の最後の口座が抜けるとき、打った機械にある店の分も消します。店の鍵は手元の機械にだけ置くので、VM で打つ `leave` は手元の分を消しません。手元の分は `thth shop remove` で消します。
- 誰が足し・鍵を置き・下書きを作り・外したかを、鍵を入れずに変更の記録に残します（動きの名前は `shopread_` で始まる）。
- 断りの目録に `store_*` の符丁を足しました（どれも なぜ・通すには・もっと良く の 3 つ）。

## 守ること（柵にした）

- BASE に送るのは `apiv2.thebase.com` への GET だけで、道は `/api/user` と `/api/items` の 2 つ。網に出る部品を使うのは `thth/shop/wire.py` だけ。
- 注文とお客さんの情報は読まない。店主の情報は店の ID・名前・URL・公開しているかだけを残し、メールなどは捨てる。
- 非公開の商品は写しに ID と非公開であることだけ。下書きは公開で買える商品だけ。店が公開前なら作らない。
- 鍵は引数で取らず、出力・ログ・ほかのファイルに出さない。
- 写しを進めない間は、日をまたいでも同じ違いの下書きは 1 本だけ。別の店の鍵に替えたら写しを捨てて基準を取り直す。

## privacy

「Online shops (BASE, read-only)／ネットショップ（BASE・読むだけ）」の節を英日に足しました。施行日は 2026-11-12 のままです。読み直しは鍵のある機械で承認を確定するときだけ・投稿の時刻には読まない・`leave` は打った機械の分だけ、という条件も書きました（2 本目の監査の危ない 1・2）。`tests/test_privacy_matches_code.py` に 16 項を足しました。コードの値と結んだのは、送り先のホスト・道の数（英日）・鍵の置き場（英日）・注文の道が無いこと・期限の知らせの日数（英日）で、残りは文の断片を縛るだけです（読み直しと leave の条件・注文を読まない日本語）。leave の条件の文をわざと消して赤、戻して緑を見ました。

## 残したこと

- 商品頁の URL の組み方は公式で確かめられないため、下書きには店の URL を載せます。
- 下書きに画像は載せていません（今の queue の画像の欄が repo の中のファイルしか受けないため）。
- ちょうど 500 件以上の商品がある店は、読み切れない扱いになります（1 回に 100 件 × 5 頁まで）。
- 店の動詞は、MCP と thth.me の道にはまだ出していません。
- 2 本目の監査の直したほうがよい 1（承認の一段目にも「読み直せない」を出す）・2（鍵を VM に置けないことをコードで縛る）・3 の残り（写しの欄・消す 3 種を文と結ぶ）は、5.16.0 以降に回しました。
