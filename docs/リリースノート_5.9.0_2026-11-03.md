# THTH 5.9.0（2026-11-03）


## 次の糸の種（設計 効果測定と連動 §3 段 5「戻りの輪」）

書き手: THTH開発の書き手（Opus）。設計の正本は `docs/設計_効果測定と連動_2026-11-03.md` の段 5。masaru の 11/03「段5をもう作れないかな？」で前倒し（1 週間使ってから順を決めるのはやめ、材料が既にある合図から並べる）。

**読むだけ・書かない・選ばない。** 選ぶのは窓口と人。THTH は数の多い順に並べるだけ。Meta も GA4 も呼ばない。契約と schema は増えない（`thth.scenario/1` に `report_type: "scenario_seeds"` を足しただけ）。

### 足したこと

- **`thth scenario seeds <project> [--days N（既定 28）] [--limit N（既定 5）] [--json]`**: 次の糸の種を、合図ごとの 4 つの列で並べる。窓は今から `--days` 日前まで（投稿の時刻・糸を閉じた日で数える。窓の外は数えない）。
  1. **返信の多かった投稿**: 自分の投稿（queue の原稿で投稿済みのもの・連投は先頭）の 24h の「返ってきた返信」。`thth after` と同じ 1 本の計算（`after_cli.reaction_lookup`）。行は数・媒体・口座・原稿の名前・糸（あれば）・投稿の頭（自分の原稿の冒頭 60 字）・投稿の時刻。
  2. **訪問の多かった告知**: 5.7.0 の `site_visits` の控えで、原稿に結べた campaign の sessions（原稿ごとに足す）。行は原稿のパス・糸（無ければ null）・sessions・engaged_sessions、列に `as_of`。**取り込みが無ければ列ごと `cannot_say: ["site_visits_not_imported"]`**（0 と言わない）。GA4 の窓が `--days` の窓と重ならない控えは `outside_window`、取れなかった窓は `site_visits_unavailable`、新しい窓が取れず前の窓の数を出すときは `stale: true` と「新しい窓は取れなかった・前の窓の数」。GA4 の窓は hub が決めるので、`--days` より広い控えも丸ごと使う（表示に 1 句）。原稿に結べない campaign（`not_a_campaign`・`no_manuscript`・`ambiguous`）は並べず名前も出さず、サイトの節の `untied`（`campaigns`・`sessions`・`by_reason`＝`site_visits.tie_rows` の `untied_campaigns` と同じ形）に数だけ。表示は「原稿に結べない campaign n（訪問 m・名前は出さない）」。
  3. **よく見られた投稿**: 24h の views（1 と同じ計算）。
  4. **閉じた糸の続き**: 窓の中で閉じた糸の、宣言にあって使わなかった媒体（`plaza_from._tried_media`＝プラザの「試していない媒体」と同じ計算）。段の本数が読めない媒体（広告の口座が無い・はてなの口座が無いなど `done: null`）は「使わなかった」に入れず `media_unknown` に分ける。
- **並べ方は数の多い順だけ**（各列に `sort_basis`）。重みづけ・点数・合成の順位は作らない。投稿の列は**媒体ごと**、訪問の列は**サイトごと**に並べる（媒体をまたいで順位を作らない＝`thth after` の規約 5・GA4 の窓はサイトで違う）。同じ数は投稿の新しい順・原稿のパスの順・閉じた日の新しい順。
- 投稿の列の `posts` は「窓の中で反応の数を引けた本数」（表示は「数を引けた n 本」）、`n` はそのうち値の取れた本数。窓の始まりちょうどの投稿は入る（`thth after` と同じ `since <= 投稿 <= 今`）。
- **n が 5 に満たない群は中央値も比べも言わない**（`median: null`・`comparable: false`・`cannot_say` に `below_min_n:<媒体>`、表示は「n=1（5 未満）なので中央値と比べは言えない・並びは数の順だけ」）。5 以上なら中央値（と p25・p75）を添える。
- 0 の行は種として並べない（数 `n` には入れる）。実測が読めない投稿は数えず、`skipped_counts` に符丁ごとの本数（0 と混ぜない）。
- **出さないもの**: 他人の返信の本文と username（数だけ）・他人の投稿・広告の費用の比べ（閉じた糸の結果は 5.8.0 のプラザにある）。
- **先頭と次の一手**: 出力の 1 行目は skill `thth-flow`（`--json` は `skill`）。各列の末尾に「種にするなら: 糸の宣言を書く（skill thth-flow の『糸を始める』）」の 1 行（`--json` は `next`）。`thth scenario <project>` の一覧の末尾に `次の糸の種: thth scenario seeds <project>（…）` の 1 行（`show` には出さない）。
- 断り: project を省いた `thth scenario seeds` は usage で断る（rc 2）。`--days` は 1〜400・`--limit` は 1〜50（外は `seeds_days_invalid`・`seeds_limit_invalid`）。無い project は `target_unknown`。`--days`・`--limit` を seeds 以外に付けると usage で断る。
- skill `thth-flow` に §6「糸を始める（次の糸の種）」を足した（読み方と、種を選んだら宣言を書く手順）。skill `thth` の scenario の節に 1 行、json の欄の表（`docs/調べ_JSONの欄_2026-10-15.md`）に `scenario_seeds` の行。

### 設計から変えた所

- **MCP には足さない（確定）。** MCP（`mcp/server.py`）には scenario の道具が無く、道具の一覧は増やさない約束（`tests/test_mcp.py` で固定）なので、CLI が主。設計の書の段 5 の「MCP」の行もそう直した。

### 確かめ方

- 試験 `tests/test_v590_scenario_seeds.py`（21 件。監査のあとに 5 件: project 省略の usage・訪問のサイトの節の鍵の集合と結べない campaign の数（ambiguous の道を含む）・取れなかった窓・stale の表示・窓の始まりちょうどの投稿）と golden `tests/fixtures/scenario_seeds_v590_golden.json`。設計の「試験で縛る」: 他人の返信の本文と username が出ない（本物の返信の台帳から・差し替えた反応の計算の外の鍵からも）／窓の外は数えない（投稿・閉じた糸・訪問の控え）／n<5 の比べを言わない／取り込みが無いときの `cannot_say`／`--json` の形の golden。ほかに並べ方・`--limit`・閉じた糸の続き・範囲の外の断り・何も書かない・読めない実測を 0 と混ぜない。
