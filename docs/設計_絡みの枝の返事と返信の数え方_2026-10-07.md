# 設計: 絡みの枝の返事・刻みの間の返信・リンクから id（2026-10-07）

書いた人: THTH開発（代行・DustyCave）。配布は Meta の判定の凍結が解けてから。

## 元になった報告

- つまずき `r20261007-0ca85418`（関東）: 刻み（1h・6h…）の間に付いた返信が台帳に無く、`unanswered` が 0 件と答えた。
- 要望 `r20261007-4b57e1ee`（kopicha）: 他人の根に付けた自分の返信に返事が付いても、`unanswered`・`observe` に出ない。`who` の接触が 0 回。リンクから id を引きたい。

## 分かったこと（10/7 に VM で読むだけで確かめた）

| 呼び方 | 件数 |
|---|---:|
| 自分の返信 18104771633221226 の `/conversation` | 0 |
| 同じ返信の `/replies` | 1（相手の返事そのもの） |
| 相手の根 18106468039963947 の `/conversation` | 32 |

- 収集は自分の返信も採る対象にしていて、刻み 1h・6h で採りに行っていた。ただ Threads の `/conversation` は根の投稿でしか枝を返さないので、毎回 0 件だった。
- `who` の 0 回は再現しない。正しい名前（`@onomichi_neko_coffee`）なら接触 2 回と出る。0 回だったのは、切れた名前で引いたため。相手からこちらへの向きが 0 件なのは、上の取りこぼしのせい。
- 刻みを待たずに採り直す口（`--refresh`）はすでにある。それなのに SKILL に「明示されたときだけ使う」と書いてあったので、運用側は `collect`（刻みが来ないと何もしない）を打っていた。

## 決めたこと

1. **Threads で自分の返信を採るときは `/replies`**（`ThreadsAdapter.branch_replies()`）。返信先は queue の `reply_to` と `sent/` の `reply_to` から決める。根は今までどおり `/conversation` で採る。自分の根のスレッドの中の返事は、根の会話で採れているので枝の台帳には入れない（`root_post` が自分の投稿なら落とす）。Bluesky・Mastodon は変えない（返信から下の部分木がもう取れている）。
2. **`unanswered` は自分の返信の台帳も読む**。数えるのは、その返信に**直接**付いた返信だけ。同じ返信が根の台帳と枝の台帳の両方にあっても 1 件と数える。
3. **人向けの表示は、台帳が見ている時刻を件数の後に必ず書く**。今採るなら `--refresh` とも書く。SKILL と使い方の書き方を改める（commit 1633896）。
4. **Threads の投稿リンク**（`https://www.threads.com/@<user>/post/<符号>`・threads.net も）**を id にする**。Threads には符号から id を引く API が無いので、返信の台帳の permalink と突き合わせる。媒体には問い合わせない。共有リンク（`/share/…`）は名前つきの理由で断り、開いたあとのアドレスを求める。通る口は `postid.for_account()` の 1 か所（thread・replies --post・send --reply-to・after・遠くの道）。

## Meta の申請との関係

新しい権限は要らない。`/replies` は申請済みの `threads_read_replies` で読む口で、向ける先は自分の返信（自分のコンテンツ）だけ。他人の根の会話を丸ごと読む呼び方は増やしていない。

## しないこと（今回）

- 刻みの間隔を縮める。h2d の返信の知らせは台帳から作るので、刻みの間は出ないまま。
- 共有リンクの転送先を読むこと（threads.com への認証なしの問い合わせ）。
