# THTH 5.33.0（2026-11-28）

5.32.0 の監査（`docs/監査_5.32.0_2026-11-28.md`）の軽い 11 件と気づき 3 つの直しと、X の読み取りの見積もりの直しをまとめた版です。監査は `docs/監査_5.33.0_2026-11-28.md`。Worker（`callback/`）は変わりません。

## 鍵の入口（監査 5.32.0 の軽い 1〜11）

| 件 | 中身 |
|---|---|
| `thth account set <口座> user_id <番号>` | 台帳の user_id を直せる口。handle と同じく鍵が無いときだけ受けます（鍵があれば `user_id_locked_by_token`、`-` で外す）。断りの文が勧める命令は、そのまま打てば通ります |
| 口座の token の番号の照合 | 台帳の user_id が空なら、今の鍵の user_id と比べます。置いたとき台帳が空なら、鍵と同じ取引で台帳に user_id を書きます（落ちれば鍵ごと戻す） |
| fb・ig の別のページ・口座の鍵 | `token_unusable` でなく `token_account_mismatch` として断ります |
| `thth secret accept` の答え | 符丁だけの行も拾う（Bluesky の handle 無しは 14）・鍵を書いたあとに落ちたら 3（置いた）・rc 3 に断りの案内を出さない・App ID は数字だけ |
| `thth secret kinds --json` | 各行に `checked`（置く前に何を確かめるか。App Secret と thth.me の鍵は形だけ）。はてなの consumer は token があるとき、置き換えの前に知らせます |
| 店の鍵 | 前の鍵が読めないときは写しの店で照合します。照合の元が無いとき、人の見ていない口（`secret accept`）は `store_token_unreadable` で断り、人の手の `thth shop token set` は初めての鍵と同じに受けます |
| 対応表（`thth.workspaces/1`）の検め | 型の違う値でも落ちずに誤りとして返します |
| 断りの目録 | 鍵の入口の新しい符丁 20 を目録に載せ、棚卸しが `_out(`・`err(` の口も数えます |

## 監査 5.32.0 の気づき

- 鍵の入口 3 つ（`thth/principal_cli.py`・`thth/authpassword.py`・`thth/appconfig.py`）を release の関門の危ない領域に足しました。
- はてなの預け（認可の途中の `auth_pending.json`）を、口座を畳むときと `--forget` のときに捨てます（その主体を使う口座が残っているときは捨てない）。
- WordPress の「鍵があれば `--force` なしで置き換えない」を試験で縛りました（コードは変わらない）。

## X の読み取りの見積もり（X から 11/6 の知らせ「expansions will count toward usage」）

| 件 | 中身 |
|---|---|
| expansions で付く物 | includes の user は 1 件 0.010、media などは 0.005 で、別の台帳（`budget_x_expansions.json`）で押さえて確定します。月の上限は他の台帳と分け合います。値段の決まっていない expansion は頼まずに断ります（`expansion_not_priced`） |
| 自分の投稿の一覧（`recent_posts`） | 1 回 0.010 でなく、返った投稿 1 本ごと 0.005 |
| 自分の投稿の数字（`GET /2/tweets`） | 0.001 でなく 0.005（X の料金表の Owned Reads の表に無いので多めに倒す）。前の版の行は前の単価のまま読めます |
| where・thread の金額の行 | 投稿の分と投稿者の分の内訳を出します |

出所と未確認の所は `docs/調べ_X_expansionsの数え方_2026-11-28.md`。docs.x.com の料金表は 11/28 の時点でまだ expansions を書いておらず、数え方は X の docs の repo の書きかけ（PR 520）に拠ります。
