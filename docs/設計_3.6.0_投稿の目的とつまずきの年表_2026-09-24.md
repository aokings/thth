# 設計 3.6.0: 投稿の目的（goal）で束ねて比べる・つまずきの年表

2026-09-24。masaru「宿題を順番に進めて」の 4 つ目。材料は kopicha の設計材料（報告 r20260923-7c297144 §4）と、kopicha が原稿の本文メモに書き始めた「目的: 誘導／フォロー」（09-24 時点で queue の 19 本）。

## 0. 約束（1 行）

**投稿ごとに目的を 1 つ書けば、道具が目的ごとに、その目的に合う物差しで比べる。** 目的は人と LLM が決め、道具は推測しない。

## A. 投稿の目的 `goal:`

### A1. 原稿の書き方
```yaml
goal: reach        # reach（表示）| click（サイト誘導）| follow（フォロー）| reply（会話）
```
- 値は 4 つの固定語（lint で断る・`goal_invalid`）。無ければ `none`（数えるときは「目的なし」の層）。
- **承認の指紋に入れない**。目的は測り方の札で、公開される中身ではない。承認後に書き換えても `approval_stale` にしない（書き換えは runs と sent に「目的の変更」として残す）。
- 本文のメモ（「目的: 誘導」）は読まない。front-matter の `goal:` だけが正（推測で拾わない）。
- `thth send`（同席）は `--goal` で渡し、`sent/` に残す。連投（`thth: 2`）は束に 1 つ。

### A2. 目的ごとの物差し
| goal | 主な物差し（投稿単位） | 分母・欠測 |
|---|---|---|
| reach | 24h・72h の views（Threads）、likes＋reposts（Bluesky・Mastodon） | 媒体に無い指標は null と `metric_unavailable` |
| click | リンク先別のクリック（Threads の account 日次 `clicks` を**投稿単位には割らない**。投稿単位のクリックは一次資料に無い→`cannot_say: per_post_clicks_unavailable`）。代わりに、その日に click 目的の投稿が 1 本だけの日に限って日次の clicks を並べる（`basis: single_click_post_day`） | 1 日に 2 本以上あれば言わない |
| follow | 投稿単位のフォローは API に無い（3.3.0 の照合・報告 r20260923-08050195）。日次の followers の増分を、follow 目的の投稿が出た日と出ていない日で並べる（観察の差・因果とは言わない） | n と「観察の差」の印 |
| reply | 24h の replies と、返信した人の異なり数（自分を除く） | |

- `thth analytics-report --compare-previous --by goal`（既存の `BY_CHOICES` に `goal` を足す）。
- `thth observe` の昨日（前回の観測から）の段に、投稿ごとの `goal` を表示し、目的ごとに主な物差しを先頭に出す。
- 観測の地図（3.5.0）の自分の層に、点×目的の表（その話題で目的ごとの本数と主な物差しの中央値）。
- 広場（3.4.0）の施策に `goal` を持てる（媒体をまたいで「reach の型は…」を比べる）。

## B. つまずきの年表

- `thth report timeline <project|account> [--since]`（MCP `thth_report_timeline`・読むだけ）: 報告の口の記録（置いた時刻・種類・題・閉じた版）と、リリースノートの「報告 id」「〜の実測から」を日付で並べる。**材料は道具の中の記録と repo の docs だけ**（推測で埋めない）。
- 各行: `{date, kind: report|release, id, title, closed_in_version, days_to_close}`。project の範囲だけ（他の持ち主の報告は出さない）。
- 集計: 最初の報告から数えた日数ごとの件数（「始めて 2 週間でどれだけつまずくのが普通か」）と、報告から閉じるまでの日数の中央値と n。
- 招待者が増えたら、新しい持ち主の最初の 2 週間に「先輩の年表の中央値」を 1 行で出す（open に参加した持ち主の年表だけ・件数と日数の集計だけ・題は出さない）。

## C. 試験

A: lint（4 語以外を断る）・指紋に入らない（書き換えで approval_stale にならない・runs に変更が残る）・send の `--goal`・`--by goal` の層と分母・click と follow の「言えない」と観察の差の印・observe と地図の表示。B: timeline の並びと集計・project の外を出さない・リリースノートの id を拾う。単変異 5 本（goal を指紋に入れる／本文メモから目的を拾う／click を投稿に割る／follow を因果と書く／timeline に他の持ち主の報告を出す）。

## D. 判断（主セッションで決めたもの）

- 目的は 4 語の固定。指紋に入れない（中身ではなく札）。
- click と follow は、投稿単位の数字が一次資料に無いことを「言えない」と言い、日次との並べ方は観察の差として出す。
- 版は 3.6.0（3.5.1 の次）。
