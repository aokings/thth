## 何が変わったか

1. **click を投稿単位で**（A1）: あるリンク先を前後 72 時間で 1 本の投稿しか使っていないとき、Threads の account 日次 `clicks_by_url` のそのリンク先の、投稿から 72 時間のクリックをその投稿のものとして出します（`basis: unique_url_72h`）。日次の粒度なので 72 時間は**投稿日（JST）を含む 3 暦日**の和です（`window: post_day_plus_2`・3 暦日が閉じるまでは `window_open`）。クリック率は clicks_72h / views_24h（分母つき）。`--by goal` の click・observe の「前回の観測から」・地図の自分の層に出ます。
   - 言わないとき: 同じリンク先を前後 72 時間に 2 本以上（`url_shared_72h`）・リンクが無い（`no_link`）・プロフィールのリンクと同じ（`profile_link`。台帳の任意項目 `profile_links` に書いたもの）。リンク先が記録に無い投稿（段のリンク先を控える前の連投・THTH を通していない投稿・添付のリンク先を控える前の記録）は `link_unrecorded`、近くにそういう投稿があれば `nearby_link_unrecorded`。
   - リンク先の照合はスキーム・末尾の `/`・`utm_*` を外し、大文字小文字はホストだけ畳みます。
   - 公開の記録（sent）に添付のリンク先 `link_urls` を控えるようにしました（本文の URL は従前どおり `text` から読みます）。連投（`thth: 2`）の実行記録にも段ごとの `link_urls`（本文の URL と添付のリンク先）を残し、照合では連投の段も「リンク先が分かる投稿」として扱います。控える前の連投は従前どおり厳しい側です。
   - lint: 同じ account で同じリンク先を前後 72 時間に使う click の原稿が 2 本以上あれば `warning: url_shared_72h`（断りません）。「同じ日の click 2 本」はこの条件で置き換えました——同じ日でもリンク先が違えば測れます。
   - **本文に札（utm）を付けて書き換える形は入れていません**（承認の指紋の規律）。
2. **follow の「比べる日が無い」**（A2）: follow の投稿が出た日／出ていない日の片方が 0 日（または min-n 未満）なら `cannot_say: no_comparison_days` と事実の 1 行（「follow の投稿が毎日出ていて、出ていない日がありません（直近 n 日）」）。推奨はしません。
3. **週の表**（A3）: `thth analytics-report <account> --weekly-goals [--weeks 6]`。月曜始まり（JST）の週ごとに、目的ごとの本数と followers の増分（前週の日曜の値と週の最終日の値の差・欠測は null と理由）。観察の表で、因果とは言いません。
4. **`thth account` の診断を分ける**（B1）: 「run を止めるもの」（token・inflight・production・repo の未 push など）と「run が自分で直すもの」（repo が upstream より遅れているだけで ahead 0 → 「次の run が取り込みます（遅れ n commit）」）。後者は「投稿できません」に入りません。判定は board に足した `repo_sync` と同じ関数です。承認済みで出られない原稿は別の段「出られない原稿（held）n 本: 名前」に出し、account は「投稿できます」のまま（他の原稿は出せる・数は board の `held_count` と同じ）。
5. **`collection_stale_hours` の数え始め**（B2）: 実装で確かめた定義は「根投稿ごとの最後の取得の成功（0 件の成功を含む）のうち最も古いもの」。observe の返信の段に `collection_stale_basis`・`collection_stale_since`・いちばん新しい取得・返信が 1 件以上取れた時刻と、「返信の取得: …」の 1 行。失敗した試行は台帳に残らないので数えていません。
6. **承認の確定待ち**（B3）: `thth approve` の 1 段目で `state/<account>/approve_pending.json` に控えを残します（本文は残さない）。queue・board・observe で not_approved を `awaiting_confirm` と `not_requested` に分け、「確定待ち n 本（最短の publish_at）」。publish_at まで 3 時間を切ったら observe の次の一手（`kind: confirm_due`・確定の命令の 1 行）と運用通知（増えたときだけ）。1 段目の表示の先頭と末尾に「確定するまで出ません」。
7. **lint・preview・approve が手元の Mac のパスを受ける**（B4）: `…/docs/sns/queue/<file>` に切り出せれば VM のパスに読み替えて 1 行言います。VM 側の clone が遅れていれば「VM 側は古い（thth pull で取り込めます）」、approve は digest が VM の本文で出ることを明示します。
8. **where**（C）: `--also <語>`（同じ検索結果を本文の語で絞るだけ・追加の検索なし・「25 件中 also に合ったもの 4 件」）。0 件は `zero_or_filtered`（本当に無いか媒体が語を受け付けなかったかは区別できない。Threads はセンシティブと判断した語の検索に空の配列を返すと文書にある。短い語・形容詞の扱いは一次資料に記載が無い＝未確認）。`--aggregate [--lexicon <file>]` は語ごとの件数・期間・1 日あたり・問いの形・lexicon の分類ごとの件数だけ（本文・username・author_key・post_id は返さない・検索語は数える前に外す）。**表示だけで保存しません**——保存するなら Meta への説明の申請のあとで（世間の層と同じ条件）。

## 各 project のセッション向け

1. click の投稿はリンク先を投稿ごとに分ける（同じリンク先を前後 72 時間に使うと `url_shared_72h` で測れない・lint が知らせる）。プロフィールのリンクは台帳の `profile_links` に。
2. click の数は `thth analytics-report <account> --compare-previous --by goal --json` の click の `per_post`（clicks_72h・クリック率・投稿日を含む 3 暦日）で読む。
3. 週ごとの目的の配分と followers は `thth analytics-report <account> --weekly-goals --weeks 6`（観察の表）。
4. `thth approve` の 1 段目だけでは出ない。observe の次の一手に `confirm_due` が出たら本文を確かめて `--confirm`。
5. `thth where` は `--also` で絞る・0 件は「無い」と言わない・`--aggregate` は数だけで保存しない。
