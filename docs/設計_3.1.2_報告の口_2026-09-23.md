# 設計 3.1.2: 報告の口（不具合と要望を道具で受け取る）

2026-09-23 11:20。masaru「バグ、要望レポートの口を thth に持たせて実装側が受け取れるようにして下さい」。動機: kopicha セッションの報告が、セッション間メッセージでは承認待ちのまま期限切れになり（09-21 と 09-23）、文書を人が運ぶ形になっていた。**報告は道具の中に置き、実装側（THTH 開発のセッション＝管理者 scope）が道具で読む。**

## 0. 約束（1 行）

**利用者のセッションが 1 回の呼び出しで報告を置け、実装側は `admin` の口と毎朝の一枚でそれを見落とさない。** 報告の本文に秘密が混ざっていたら置かない。

## 1. 入口

| 誰 | CLI | MCP | 何を |
|---|---|---|---|
| 利用者（project のセッション） | `thth report file <account> --kind bug\|request --title … --body-file …`（`--repro-file` 任意） | `thth_report_file {account, kind, title, body, repro?}` | 報告を 1 件置く。`report_id` が返る |
| 利用者 | `thth report list <account\|project>`・`thth report show <id>` | `thth_report_list`・`thth_report_show` | 自分の project の報告と、実装側の返事を読む |
| 実装側（管理者 scope） | `thth admin reports list [--status open]`・`show <id>`・`reply <id> --by <名前> --text-file …`・`close <id> --by … --reason fixed\|wontfix\|duplicate\|invalid --version <版>` | `thth_admin_reports_list`・`thth_admin_reports_show`・`thth_admin_reports_reply`・`thth_admin_reports_close` | 全 project の報告を読み、返事と状態を書く |
| 実装側 | `thth admin reports export --to <私有の dir> --by …` | — | 開いている報告を Markdown で書き出す（私有の置き場に置いて git で追う用。**公開 repo には置かない**——THTH の repo は公開で、本文は利用者が書いた文。masaru 裁定 09-23） |

## 2. 記録

- 置き場: `$THTH_ROOT/state/_reports/<report_id>.json`（0600・VM の私有・**SNS 台帳には書かない**）。`report_id` = `r` + 日付 + 先頭 8 字の乱数。
- 1 件の形: `{schema_version, report_id, at, kind, title, body, repro, project, account, medium, reporter, via, tool_version, status, replies: [{at, by, text}], closed: {at, by, reason, version} | null}`。
  - `reporter` は MCP なら資格情報の `actor`、CLI なら `--by`（無ければ断る・`by_required`）。
  - `tool_version` は道具が入れる（報告した時点の版）。
  - `body` は 8,000 字・`repro` は 4,000 字・`title` は 120 字まで。超えたら `report_too_long`。
- **秘密の検査**: `redact.looks_like_secret()` 相当（token・Bearer・`sk-`・32 桁以上の hex 等・既存 `redact` の型）に当たったら **置かずに `secret_detected`** で断る（伏せ字にして置かない。置く側が直す）。
- 制限: 1 account につき 1 日 20 件（`report_rate_limited`）。同じ title＋body の sha が 24 時間内にあれば `duplicate_report` で断り既存の id を返す。
- 変更ログ: `report_filed`・`report_replied`・`report_closed`（`admin_log`・presence-only・本文は入れない）。
- 利用者 scope は**自分の project の報告だけ**読める。`admin` は全部。

## 3. 実装側が見落とさないために

- `thth morning`（管理者の資格情報のとき）の 0 段「道具」に **「報告: 開いている n 件（新規 m 件）」** を出し、`next_steps` に `kind: "report"` を足す（開いている報告 1 件につき 1 行・`report_id` と種類と題の先頭 60 字だけ・本文は載せない）。masaru の毎朝の一枚に載る。
- `handoff-report --since-last-read` の `tool` に、**自分の project の報告への返事**（前回から増えた分）を出す。報告した側が返事を見落とさない。
- `thth admin reports export --to <私有の dir>` で Markdown（1 件 1 ファイル・`<report_id>_<title>.md`）を書き出す。私有の置き場で commit して追う（**公開 repo には置かない**・既定の行き先を持たない・masaru 裁定 09-23）。閉じたら close で版を書き、リリースノートに拾う。

## 3.5 受け口の存在を LLM 側に返す（masaru 09-23 11:35「実行して結果を受けるタイミングなどに分かるように」）

報告の口は、**使う側の LLM が存在を知っていなければ無いのと同じ**。文書に書くだけでは足りないので、道具の応答そのものに載せる。

| どこで | 何を返すか |
|---|---|
| **断るとき**（CLI の rc≠0 の理由行・MCP の `isError` 応答・`cannot_say` を返す段） | 理由の後ろに静的な 1 行 `report_channel: thth report file <account> --kind bug\|request（MCP: thth_report_file）` を添える。JSON では `report_channel: {"cli": "thth report file <account> …", "mcp": "thth_report_file", "when": "unexpected_or_unsupported"}`。文面は固定・秘密も本文も含めない |
| **`handoff-report --since-last-read` の `tool`** | 常に `report_channel` を出す（開始手順で必ず読む場所）。加えて自分の project の報告の状態（開いている n 件・返事 m 件） |
| **`thth morning` の `limitations`** | 末尾に 1 行「不具合と要望は report の口へ（thth_report_file）」 |
| **MCP の `tools/list`** | `thth_report_file` の description に「道具が断った・結果が期待と違った・欲しい形がある、のどれかならこれで置く」。**書く道具・読む道具すべて**の description 末尾に「うまくいかなければ `thth_report_file`」の 1 句 |
| **CLI の `--help`** | `thth report` の説明と、`thth --help` の末尾 1 行 |
| **skill と `docs/使い方_プロジェクトのセッション向け_….md`** | 開始手順に「断られたら・違和感があれば report の口」を 1 行 |

- 成功の応答には載せない（毎回出すと読み飛ばされる）。載せるのは**断り・cannot_say・開始手順の 3 場面**。
- 文面は 1 種類・静的（試験で固定・変異 1 本）。

## 4. 変えないもの

- 承認の二段・digest・読む口が SNS 台帳に書かない規律。報告は SNS の台帳ではなく道具の台帳。
- 秘密は人も LLM も触らない（本文に混ざれば置かない）。

## 5. 試験

file → list → show の往復（CLI と MCP）・利用者 scope が他 project を読めない・秘密で断る・長さで断る・重複で既存 id・返事が `handoff-report` に出る・morning（admin）に件数・export の Markdown に絶対パスも秘密も無い（leak probe）・変更ログ 3 種。単変異 6 本（project の絞り・秘密検査・重複検査・長さ・返事の表示・断りの案内文）。
