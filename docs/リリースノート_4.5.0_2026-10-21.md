# リリースノート 4.5.0（X の全期間の検索）

2026-10-21。設計は [設計 4.5.0](設計_4.5.0_Xの全期間の検索_2026-10-21.md)。

## 変わったこと

- **新しい命令 `thth archive <口座>`**: X の他人の公開投稿を、2006 年 3 月からの全期間から読みます（`GET /2/tweets/search/all`）。`--from <handle> --title <曲名>` で `from:<handle> "<曲名>" -is:retweet` を組み立てます（曲名の中の引用符は空白にします）。`--query` で語をそのまま渡すこともできます。行は `post_id`・`url`・`created_at`・`text`・`author_username` です。保存しません。
- **本数は必ず縛ります**: 1 回 10〜100 本（既定 10）・総本数 10〜500（既定 20）・ページ 1〜50（既定 5）。`next_token` を辿っても総本数を超えて頼みません。範囲外の指定は要求の前に断ります（rc=2 `x_archive_limit`）。
- **件数だけ `--count-only`**（`GET /2/tweets/counts/all`・1 回 0.010 USD・31 日ごとに 1 ページ）。窓を数えきるのに `--max-pages`（既定 1）より多くのページが要るときは、要るページ数と推定 USD を言って要求の前に断ります。全期間を数えると約 245 ページ（約 2.45 USD）なので、「当たりが 0 なら読まない」には `--max-total 10` の検索のほうが安い（0 本なら 0 USD）です。
- **予算**: 課金は返った本数で数え、台帳 `budget_x_archive_reads.json` と `budget_x_counts_all.json` に残ります（`thth admin budget x --json` の `archive_read`・`counts_all_read`）。`--json` の `x_read_cost` に今回の本数・回数・推定 USD・今日の本数と上限・今月の使用と上限が出ます。月の上限は今の X の予算と分け合います。
- **1 日の本数は別の枠 `x_archive_daily_reads`**（X の口座だけ・**既定 0＝読まない**）。`thth account set <口座> x_archive_daily_reads <本数> --by <名前>` で開けます。今の `x_daily_reads`（既定 60）は緩めず、全期間の読みはそちらに数えません。
- **timer・collect・morning・maintain・worker・map からは叩きません**（要求も予約もせずに `x_archive_unattended`）。MCP の道具にもしていません。

## 気をつけること（運用のレーンへ）

- 既定のままでは読めません。月の X 予算と `x_archive_daily_reads` の両方が要ります。開けるのは masaru の判断です（設計 §5 に命令の形）。
- 結果が不明なとき（応答が読めない）は押さえた本数のまま数え、投げ直しません。2 ページ目より後で止まったときは、それまでの行と `stopped` を返します。

## 確かめた範囲

試験（全件・偽の X）と、`tests/test_v450_x_full_archive.py` の柵を 1 つずつ壊して赤を見たこと。本物の X では叩いていません（従量の契約で全期間の検索が通るか・件数のページの並びは未確認）。
