## 第 8 段: 承認ページで添付を見せる（Worker＋VM）

- `approval_request`／`send_request` の session `create` に **添付一覧**を足す: `attachments: [{index, role, kind, format, public_sha256, public_size, width, height, duration, alt, preview_capability}]`（本文・context と同じ 10 分の論理保存）。typed attachment（poll・quote・link・text・gif）と `post_options` は **canonical JSON の文字列**として `typed:` に。
- 画像は **preview capability**（第 4 段の `purpose=preview`・承認 session と同じ寿命 600 s・`/m/<cap>`）で `<img>` 表示。動画は「動画 mm:ss・sha256 先頭 12 桁」の文字だけ（先頭フレームは作らない・C2 の bytes 不変規律）。音声は「音声 mm:ss・sha256 先頭 12」。
- ページの CSP は `img-src 'self'` を足すだけ（script 無し・inline style のみ・`no-store`・`no-referrer` は従前）。preview capability は **承認ページの HTML にだけ**現れ、status／receipt／journal には出ない。
- digest は第 1 段のまま（添付の sha・alt・順序・typed を含む）。ページの「digest:」表示は変えない。
- VM 側: `approval_jobs.create` が `media.manifest_for` の結果から一覧を作り、画像だけ `media_relay.grant(subject, 'preview')` を発行して URL を載せる。preview の発行に失敗したら**画像なしで登録せず**、`approval_registration_unknown` で止める（人が見ていないものを承認させない・§1-2）。
- 試験: Miniflare で `create` → `GET /approve/<token>` の HTML に `<img src="/m/…">`・alt・sha 先頭 12・typed の JSON が出る／preview が status と receipt に出ない／期限後 410／CSP。Python で preview 発行失敗時に session を作らない。変異 3 本（alt 抜き・preview を status に出す・失敗時に登録）。

## 第 9 段: 招待者の upload（MCP の書く口）

- MCP `thth_media_upload_url`（`writes: true` の資格情報・利用者 scope）: `{kind: image|video|audio, size, sha256, mime}` を受け、第 4 段の upload session（`kind=source`・600 s・complete 一度・100 MB 超は multipart）を VM が署名で開き、**一回限りの PUT URL**（`/media-upload/<subject>`）と `media_id`（= subject）を返す。URL は応答にだけ出る。
- `thth_media_complete {media_id}`: VM が `complete` → 署名付き `read` で取り出し → **sanitize（第 1 段）→ 公開 sha を計算** → managed repo の `docs/sns/media/<public sha>.<ext>` に置く（git add・commit は `draft_put` と同じ transaction）。応答は `{media_id, public_sha256, kind, format, width, height, duration, warnings}`。sanitize で断られたら静的理由（`location_metadata_present` 等）を返し、R2 の source は `invalidate`。
- `thth_draft_put` の `media: [{media_id, alt}]`: media_id は **同じ actor・同じ account** が complete したものだけ（他人・他 account は `media_owner_mismatch`）。以後は第 1 段の原稿と同じ（front matter に `media: [{file, alt}]`）。
- 承認されなかった添付: source は complete から 600 s、public snapshot は draft が消えたら（`retract`／失効）R2 から `invalidate`。lifecycle 24h は backstop。
- 試験: fake Worker で URL 一回限り・別 actor の media_id 拒否・sanitize 失敗で repo に置かない・complete 二度目 409・`draft_put` の digest に public sha が入る。変異 3 本（owner 検査抜き・sanitize 抜き・二度目の complete 許可）。

## 第 10 段: 記録と観測・tool の網羅表

- `sent`／`insights` の行に `media: [{sha256, kind, alt_present, remote_id}]`（第 2〜6 段で入っているか確認・無ければ足す）。`analytics-report --by attachment_kind`（C6・`image`／`video`／`audio`／`carousel`／`poll`／`quote`／`link`／`gif`／`none`）。
