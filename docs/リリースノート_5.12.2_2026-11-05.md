# THTH 5.12.2（2026-11-05）

X の投稿と読み取りが 11/03 から止まっていた件の直し。契約は変わらない。

## 起きたこと

- 2026-11-03 00:53 に X の予算の台帳 `state/_admin/budget_x.json` が 262,361 バイトになり、256 KiB（262,144）を超えた。
- `server_files.replace_at` が古い中身を既定の上限で読んでいたので、読む側の上限（16 MiB）より先に `server_file_too_large` で書き込みを断った。予算の予約が書けず、予約を通る X の鍵の更新（`thth refresh`・`thth maintain`）が失敗し、2 時間の鍵が切れて投稿が `x_publish_http_401` になった（kopicha-x・asmon-kanto-x の鍵とも 11/03 0 時台で切れた）。
- 自分の投稿の数字の台帳 `budget_x_owned_reads.json` も 10/26 に 262,157 バイトで同じ上限に当たり、11/01 から採取の `server_file_too_large` が続いていた。

## 変えたこと

- `thth/server_files.py` の `replace_at`: 古いファイルの大きさでは断らない。安全な通常のファイルかどうかの検査（`O_NOFOLLOW`・持ち主・権限）と、`new`・`expected` の照合は今までどおり。大きさの上限は読む側のもの（webhook の 64 MiB の控えも同じ穴が塞がる）。

## 確かめ方

- 試験: `tests/test_v212_budget.py` の `test_ledger_over_256kib_still_saves_and_reserves`・`test_replace_at_keeps_expected_and_new_checks_for_large_files`。古いコードに戻すと 2 件とも `server_file_too_large` で赤になるのを見た。
- VM の 5.12.1 で `budget_x.user_read('kopicha-x')` を打ち、同じ符丁で落ちるのを見た。

## 本番で未確認のこと
