# リリースノート 3.14.3（審査員が踏む穴の直し）

2026-09-27 夕。設計: `docs/設計_3.14.3_録画で見つけた穴_2026-09-27.md`。Meta の App Review（09-27 提出）の審査員が招待の口座で踏む穴を先に塞ぐ。新機能は無し。**配布のあとは判定まで凍結。**

**配る順: Worker（穴 2・masaru の手）→ VM の release → tag（PyPI）。** 古い Worker のままでも VM と CLI は動く（login ページが自分で待たないだけ）。

## 直したこと

1. **招待の口座の記録置き場**（穴 1）: 口座を作った直後に managed repo を用意する（失敗しても口座は作り、変更ログ `managed_repo_init_failed`）。依頼の入口で「`.git` が無く中身が空か `data/` だけ」の置き場は直してから進む（`managed_repo.recover`）。→ `collect` が招待の口座で通る。
2. **公開の時間切れ**（穴 3）: `threads_publish` の読み取りの締切 10 → 30 秒。時間切れ・5xx のあとは container の状態を 20 秒後から 5 秒おき・合わせて 60 秒見て決着（PUBLISHED なら一覧から post_id）。rehearsal が inflight で止まったら `publication_unconfirmed`（`reason: inflight`・次の一手つき）で断る（`invalid_draft` に丸めない）。遠くの道に `thth inflight <口座>` と `thth inflight <口座> resolve --published <id>|--not-published [--confirm <digest>]`（operation `inflight_status`・`inflight_resolve`・digest の 2 段は手元と同じ）。
3. **login ページの待ち**（穴 2）: 招待の完了の直後に VM がその人の要約を 1 回すぐ押し上げる（409 でも 5 分待ちに入らない）。Worker の `/login/<code>` は口座の様子が届くまで 5 秒ごとに自分で再読み込みして待つ（script 無し）。
4. **運営者の CLI**（穴 4・7）: 入口で `umask 077`。符丁だけの ValueError は traceback でなく `符丁: 次の一歩` の 1 行（rc 2）。`leave_incomplete` は理由と path・`chmod -R go-w` を添える。
5. **録画の道具**（穴 5）: `send` の出力を `tee` で画面にも出す。
