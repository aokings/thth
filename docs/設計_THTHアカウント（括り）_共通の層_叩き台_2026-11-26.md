## 1. 先に決める物: 媒体 → 括りの対応表

h2d が 12/9 に `jobs request` と `job once` を配備します。h2d の棚卸しは「今の予定のまま作ると媒体の層までしか持たない。その前に対応表と判定の重ね方を決める」と書いています【読】。この節だけで決められるように書きます。**ここが決まれば、h2d は §2 以降を待たずに作れます。**

### 1.1 推しの形（一目で）

| 決めること | 推し |
|---|---|
| 置き場 | VM の THTH の共通の根に 1 枚。`/srv/thth/workspaces.json`（括りのフォルダ `ws/` の外・repo の外） |
| 持ち主（正本） | THTH。形を決めるのは THTH開発、中身を書き換えるのは管理者の命令（`thth admin ws …`）だけ。hub と h2d は読むだけで、写しを持たない |
| 括りの台帳との関係 | **同じ 1 枚**。括りの名・持ち主・窓口と、媒体の対応を 1 つのファイルに書く（正本を 2 つにしない） |
| 鍵（表の左の列） | 媒体の名前。hub の project、h2d の `owner` の `/` より前、repo の名前、名乗りのファイルの頭、の 4 つは今も同じ綴りです【読】。これを 1 つの名前の空間にする |
| 単位 | 媒体。レーン（`asmon/kanto` の `kanto`）は媒体の括りに付いていく。1 つの媒体が 2 つの括りにまたがることは無い |
| 名前の重なり | 媒体の名前は全部の括りを通して 1 つだけ（前の書 §2.2 の口座の名前と同じ理屈・同じ代償） |
| 今の物の初期値 | 今ある媒体を全部 `main` に名指しで並べる（下の 14 個）。表に無い名前も、括りが `main` の 1 つだけの間は `main` |
| 表に無い名前 | `unlisted` の欄で決める。初めは `"main"`。**2 つ目の括りを足すのと同じ操作で `null`（断る）に替える** |

### 1.2 形（例）

**置いた（11/26 THTH括り 第1）**: 形の正本は [約束_括りの対応表_thth.workspaces.1.md](約束_括りの対応表_thth.workspaces.1.md)。VM の `/srv/thth/workspaces.json` に最初の 1 枚がある。以下は決める前の例。

```json
{
  "schema": "thth.workspaces/1",
  "updated_at": "2026-11-27T09:00:00+09:00",
  "unlisted": "main",
  "workspaces": {
    "main": {"owner": "masaru", "lead": "media-hub", "created": "2026-11-27"}
  },
  "media": {
    "asmon": "main",
    "chuju": "main",
    "gakko": "main",
    "h2d": "main",
    "headlesson": "main",
    "jiangshi-lab": "main",
    "kopicha": "main",
    "mashiro2": "main",
    "media-hub": "main",
    "monban": "main",
    "music-research": "main",
    "nigamilab": "main",
    "sometokagaku": "main",
    "thth": "main"
  }
}
```

2 つ目の括りを開いたあとの姿（名前は仮）:

```json
{
  "schema": "thth.workspaces/1",
  "unlisted": null,
  "workspaces": {
    "main":  {"owner": "masaru", "lead": "media-hub"},
    "<新>":  {"owner": "masaru", "lead": "<新しい媒体群の窓口の媒体>"}
  },
  "media": {
    "asmon": "main",
    "<新しい媒体 1>": "<新>",
    "<新しい媒体 2>": "<新>"
  }
}
```

欄の意味:

- `media`: 媒体の名前 → 括りの名。JSON の鍵なので、同じ媒体を 2 行書けません（1 媒体 1 括りが形で守られる）。
- `workspaces.<括り>.owner`: 括りの持ち主（決める人）。hub の「返事待ち」の相手と、承認の「誰が決めたか」はここから引きます（§3）。
- `workspaces.<括り>.lead`: 括りの窓口の媒体（要るなら `媒体/レーン`）。h2d の「急ぎの繰り上げ」と「休みの知らせ」の送り先です。今は `media-hub` の決め打ちなので【読: h2d の棚卸し】、`main` の値を `media-hub` にすれば今と同じ動きです。
- `unlisted`: 表に無い媒体の名前をどう扱うか。`"main"` か `null`（断る）。
- 秘密は入れません。鍵・token・人の連絡先は書かない物とします。

初期値の 14 個の出所【動】: media-hub の `callnames.yaml`（37 行）に出てくる project を数えた物です。h2d の規則と見張りの `owner` に出てくる媒体（`asmon`・`h2d`・`kopicha`・`media-hub`・`monban`・`music-research`・`sometokagaku` の 7 つ）は、全部この 14 個に入っています【動】。名乗りのファイルだけがあって呼び名の台帳に無い名前（`mindforest`・`watchtower` など）は、`unlisted` が拾います。置く前に、hub の名簿（`hub roster`）と突き合わせて足りない名前を足します。

### 1.3 誰がどう引くか

- **引く場所は VM**。hub も h2d も、Mac からは `ssh wt` で VM の本体を呼ぶ作りです【読: hub の `hub/bin/hub-mac-wrapper`・h2d の `h2d/remote.py`】。判定は VM の上で 1 回だけ行い、Mac に写しを置きません。
- **引き方はファイルを直に読む**。道の既定は `/srv/thth/workspaces.json`、環境変数 `THTH_WS_MAP` で替えられる（試験のため）。THTH の命令を呼んで引く形にしないのは、THTH の括りの版（6.0.0）が出る前に h2d が 12/9 に使い始めるからです。**ファイルの形（`thth.workspaces/1`）が 3 つの repo の間の約束**で、THTH の版とは切り離します。
- **読むたびに開く**（1 つの命令の中で 1 回）。部品の側に覚えを作りません。
- **ファイルが無いとき**: 全部の媒体を `main` として扱う。今の本番はこの状態なので、h2d と hub は、ファイルが置かれる前に読む側のコードを出しても何も変わりません。
- **ファイルが壊れているとき**（JSON でない・`schema` を知らない・`media` の先が `workspaces` に無い）: 新しく書く操作（規則・仕事・見張りを足す・変える、`jobs request`、`job once`）は断り、「対応表が読めない・管理者に知らせる」を返す。もう置いてある規則の発火と配送は続ける（括りの検めは置いたときに済んでいるため）。黙って `main` に倒しません【推: どこまで続けるかは h2d の担当と詰める】。
- **書き換え**: 手で開いて直さない。`thth admin ws add <括り>`・`thth admin ws media add <括り> <媒体>` が、形を確かめ、別の名前で書いてから名前を付け替える（途中の姿を読ませない）。この命令ができる前（6.0.0 の前）は、最初の 1 枚を THTH開発が 1 回だけ置き、形を確かめる小さな検査を一緒に走らせます。
- **媒体を別の括りへ移す**ことは、表の書き換えではできない物とします（置き場のデータが付いてこないため）。命令は断り、管理者の作業として別に段取りします。

### 1.4 h2d が 12/9 に入れる判定（これだけで足りる）

h2d の棚卸しの「中で済む所」【読】を、表の言葉で書くとこうなります。

| 所 | 重ねる判定 |
|---|---|
| `jobs request`・`job once` | 頼む者の媒体の括りと、仕事の `owners` の媒体の括りが同じ。違えば断る |
| 規則の `owner` と、呼ぶ仕事・使う鍵の `owners` | 同じ括り |
| きっかけ（`when.fire` の `project`） | 購読する出来事の媒体が、規則の `owner` と同じ括り |
| 起こし（`wake.to`） | 宛先の媒体が、規則の `owner` と同じ括り |
| 見える範囲（`viewer_for_actor`）・書ける範囲（`check_monban_write_owner`） | 今の媒体の判定はそのまま。`share_with` と `public` で見える先を、同じ括りの中に限る |

- 括りが 1 つ（`main`）の間は、どの判定も断りません。**12/9 の配備で本番の動きは変わりません。**
- 断り方は、前の書 §4.5 にそろえます。ほかの括りの物を名指ししたときの断りは、どこにも無い名前を名指ししたときと同じ符丁・同じ文にします（名前を当てて回る探りに答えない）。
- `owner` が `h2d` の規則（28 本【動】）は仕組みの側の物です。`h2d` を `main` に置けば今と同じに動きます。新しい括りで仕組みの規則が要るときは、管理者が括りを名指しして置きます（§4）。

### 1.5 ほかの置き場を選ばなかった理由

| 案 | 選ばなかった理由 |
|---|---|
| h2d-config の中に 1 枚 | 括りの持ち主が h2d になり、「括りは THTH が持つ」（masaru 11/26）と合わない。hub も h2d の repo を読むことになる |
| media-hub の `media.yaml` に欄を足す | `media.yaml` は hub が数える媒体の一覧で、鍵は媒体 id（`kanto`・`mymusic` など）。project の名前とは別の綴り【読】。新しい媒体群は「今の hub に載せない」（前の書 §9）ので、載せない物の名前をここに書くことになる |
| thth の repo に追跡されるファイルとして置く | 新しい媒体群の名前が repo の履歴に残る。thth の repo は外に見せる前提で書かれている【読: `tests/test_docs_links.py` の注記】ので、置き場は VM にする |
| 括りごとの `ws/<括り>/ws.json` に媒体を書く | `ws/` は THTH の段 1 より前には無い。12/9 に間に合わない。対応を知るのに全部の括りを歩くことにもなる |

`ws/<括り>/ws.json`（前の書 §2.1）は残しますが、中身は括りの名だけにします（フォルダと台帳の食い違いを見つけるため）。持ち主と媒体は台帳の 1 枚に書きます。

hub の媒体 id（`kanto` など）と project の名前の結び付けは、今も `media.yaml` の中で hub がしています【読】。対応表には project の名前だけを書き、媒体 id は hub の中で引きます。THTH の project の名前（`asmon-kanto` など）は対応表に書きません。THTH の中の括りは、置き場のフォルダで決まるからです（前の書 §2）。食い違いは §7 の柵で見ます。

## 2. 共通の層

### 2.1 何が共通か

```
共通の層（THTH が持つ）
  ① 括りの台帳           /srv/thth/workspaces.json（§1。括り・持ち主・窓口・媒体）
  ② レーンの鍵           thth login --lane（前の書 §4。鍵は 1 つの括りにだけ結び付く）
  ③ 鍵から括りを決める口   VM に 1 つ。鍵 → 括り・媒体・レーン・持ち主・鍵の id・期限
  ④ 部品の通り道          鍵で来た頼みを、括りの印を立てて hub・h2d に渡す

部品（今の repo のまま・今の担当のまま）
  声 = THTH の届ける所    括りのフォルダの中で動く（前の書）
  場 = hub               括りの印を見て、括りごとの置き場で動く（§3）
  時 = h2d               括りの印と対応表を見て、括りの中だけを判定する（§4）
```

hub と h2d は、鍵そのものを見ません。鍵を確かめるのは THTH の口（③）の 1 か所だけです。h2d は今も「判定は CLI の 1 か所・MCP と monban は判定を写さない」作りなので【読: h2d の `h2d/mcp_server.py` の冒頭】、同じ考えを 1 段上に重ねます。

### 2.2 レーンの鍵に足す物

前の書 §4.3 の鍵の行（持ち主・レーンの名・期限・取り消しの印）に、**媒体**を足します。

- 鍵の行: 括り・媒体・レーン・持ち主・期限・取り消しの印。媒体とレーンは、hub と h2d が今使っている書き方（`asmon` と `kanto`）にそろえます。前の書 §4.1 の鍵のファイルの名前（`<repo>-<レーン>.json`）は、hub の名乗りのファイルと同じ付け方なので【読】、そのまま媒体とレーンになります。
- 鍵を出すとき、VM が「その媒体は、その括りの物か」を台帳（①）で確かめます。違えば出しません。
- これで、鍵 1 本から「どの括りの・どの媒体の・どのレーンか」が VM の側で決まります。呼ぶ側が名乗る必要が無くなります。

### 2.3 どの入口でも鍵から括りが決まる仕組み

呼ぶ者は 3 種類です。

| 呼ぶ者 | 括りの決まり方 | 証し |
|---|---|---|
| **鍵を持つレーン**（Mac や奥さまの機械） | VM の口（③）が鍵から決める | 鍵。呼ぶ側の引数や環境変数では変えられない |
| **VM の中で自分で動く物**（口座の timer・h2d の規則の tick と配送・hub の毎朝の集計） | 扱う物の持ち主から決める。THTH は口座のフォルダ、h2d は規則の `owner` の媒体 → 台帳、hub は括りを順に回る | 鍵は要らない（VM の中の物） |
| **ssh で入った人**（管理者・移すまでの masaru のレーン） | 名指し。§2.5 | 証しは無い（VM に入れる者は何でもできる。前の書の前提 8） |

鍵を持つレーンの道は、THTH・hub・h2d で **1 本**にします（§8 の問い 2）。

```
レーンのセッション
   thth …              ─┐
   thth hub …           ├─ 鍵 ─▶ thth.me（Worker・括りの束）─▶ VM の常駐
   thth h2d …（MCP も） ─┘                                      │ ③ 鍵 → 括り・媒体・レーン
                                                               ▼
                                         THTH の命令: 括りのフォルダに入って動く
                                         hub・h2d の命令: 括りの印を立てて、部品を打つ
```

- **括りの印**は、VM の常駐が部品を打つときに立てる環境変数です。`THTH_WS`（括り）・`THTH_MEDIUM`（媒体）・`THTH_LANE`（レーン）・`THTH_KEY_ID`（鍵の id）。h2d には、今の `H2D_ACTOR_MEDIUM` と `H2D_ACTOR`（`thth:<括り>/<媒体>` の形）も一緒に立てます。h2d の今の判定はそのまま効きます【読: `viewer_for_actor` は媒体があれば媒体で絞る】。
- **通してよい命令は、部品が自分で決めます。** h2d には MCP のための許可の一覧（読む・書く）がもうあります【読: `ALLOW_READ`・`ALLOW_WRITE`】。hub にも同じ一覧を作ります（`status post`・`roster`・`handoff`・`promise`・`approve ask`・`note` など）。THTH の常駐は、一覧に無い命令を渡しません。
- **手元の入口**: 製品の名前は 1 つなので、`thth hub …`・`thth h2d …` の形を案にします。hub の Mac の包み（`hub-mac-wrapper`）と h2d の MCP は、レーンの鍵のファイルがあればこの道を使い、無ければ今の ssh の道を使います。今のレーンの打ち方（`hub status post …`）は変えずに済みます【推】。
- **道の限り**は前の書 §5.6 と同じです（頼み 48 KB・1 発目は最長 10 秒ほど待つ）。hub の 1 行や伝言の要点は入りますが、続けて何十発も打つ仕事では待ちが響きます。`main` のレーンは、前の書の段 6 まで ssh の道を並べて残します。

### 2.4 伝言だけは道が違う

hub の伝言箱（hub messenger）は VM でなく **masaru の Mac の中**にあります【読: `hub/messenger/store.py` の置き場・`hub-mac-wrapper` の注記】。名乗りのファイルも Mac の `~/.config/agent-mail/` です。VM の口（③）を通りません。

- masaru の括り同士: 伝言箱と名乗りの置き場を、括りごとに別のファイル・別のフォルダにします（§3 の段 H4）。どの括りの箱を開くかは、レーンの鍵のファイルの `workspace` の控えで決めます。同じ Mac の同じ利用者なので、これは取り違えを防ぐ柵です（前の書 §0 の言い足し 2 と同じ）。
- 奥さまの括り: 奥さまの機械に、奥さまの括りの伝言箱だけがある形になります。機械が別なので、ここで初めて壁になります。
- **括りをまたぐ伝言は、作りません**（§8 の問い 3）。

### 2.5 h2d の棚卸しが挙げた危ない所への手当て

h2d の棚卸し §3 の 1〜3 です【読】。

**(1) MCP の名乗りが環境変数だけ**（口を起動した側が好きな媒体を名乗れる）

- MCP の口は、起動するときにレーンの鍵のファイルを読み、頼みを §2.3 の鍵の道に流します。媒体は VM が鍵から立てます。
- 鍵で動く口では、`H2D_MCP_MEDIUM` を見ません。立っていて鍵の媒体と違えば、口の起動を断ります（黙ってどちらかを選ばない）。
- 鍵の無い口（今の `main` の ssh の道）は、括りが 1 つの間は今のまま動かします。2 つ目の括りを開いた時から、書く道具は鍵のある口だけに出します。

**(2) ssh の素通し**（`ssh:`・`local:` は全部見える・書ける）

- 新しい括りのレーンには、初めから ssh を渡しません（前の書 §9 問 3 の決め）。壁はこれです。

- h2d の「`ssh:`・`local:` は全部」の判定は、「印が無ければ `main`、名指しがあればその括り、管理者の旗があれば全部（一覧だけ）」に替えます。hub にも同じ決まりを置きます。3 つの部品で同じ言葉・同じ旗にします。

**(3) 名簿の上書きで宛先が外へ出る**（11/25 夜〜11/26 朝。kopicha 本線の行の名乗りが別のレーンの名乗りに書き換わり、h2d の起こしが別のセッションに届いた【読: h2d の棚卸し】）

### 6.1 段 K: リモート MCP と OAuth（叩き台は THTH括り 第3・11/27。作った形に直した・同じ日）

なぜ要るか: 今の THTH の MCP は手元で起動する stdio だけで、遠くから呼べる道は `thth.me/api/v1` だけ【読: 精読_GenerativeUI §前提】。claude.ai（web・スマホ）や ChatGPT から THTH を道具として呼ぶ・画面（MCP Apps）を出すには、コネクタとしてつながるリモート MCP が要る。画面の部品そのものは THTH画面（レーン mcp-ui）の領分で、この節は口と入り方だけ。

**決まった（THTH開発 第24・2026-11-27）: 認可サーバは thth.me に自前で置く。** 比べたもう 1 つは monban の入口を認可サーバにする形。自前を選んだ理由: 同意の画面が括りの login と 1 枚で済み、審査の説明（THTH の利用者が THTH の画面で許す）も単純。持ち主と括りの表を monban と二重に持たない。

**作った形（枝 `worktree-ws-stage-d`・本番不変・試験と手元の `wrangler dev` で確かめた）**

| 所 | 作った形 |
|---|---|
| MCP の口 | `POST https://thth.me/mcp`（MCP 2025-11-25 の Streamable HTTP・JSON の答えだけ。GET の SSE は 405）。`initialize`・`ping`・`tools/list`・`tools/call`。token が無い・形が違う・期限切れ・取り消し済みは 401 と `WWW-Authenticate: Bearer resource_metadata="https://thth.me/.well-known/oauth-protected-resource/mcp"`・`cache-control: no-store`・本文は `{"error":"unauthorized"}` だけ（`callback/src/mcp.js`） |
| 守る物の表 | `/.well-known/oauth-protected-resource`（と `/mcp` 付き）。`resource` は `https://thth.me/mcp`、`authorization_servers` は `https://thth.me`（RFC 9728） |
| 認可サーバの表 | `/.well-known/oauth-authorization-server`（RFC 8414）。`code` だけ・PKCE は S256 だけ・client の秘密は持たない（`none`）・`client_id_metadata_document_supported: true`（CIMD が第一。claude.ai の名乗りは `https://claude.ai/oauth/mcp-oauth-client-metadata`・戻り先 `https://claude.ai/api/mcp/auth_callback`）。DCR（`/oauth/register`）は予備で 30 日。scope は `read`・`write`・`offline_access`。resource indicators は `/mcp` 以外を断る（`callback/src/oauth.js`） |
