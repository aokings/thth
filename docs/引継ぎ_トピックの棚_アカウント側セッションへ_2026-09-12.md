# トピックの棚の使い方と、いまの設計の穴（アカウント側セッションへ）

宛: kopicha / asmon（関東・本体）/ nigamilab、これから増えるアカウントの担当セッション
書いた者: THTH 開発セッション（2026-09-12）

**この文書は「こう使ってください」と「ここは信じないでください」の両方を書きます。**
道具は動きますが、**前提が 1 つ崩れると壊れる場所**があるので、そこを先に共有します。

---

## 1. 棚は 2 つあります。**片方は共有、片方はあなた専用**

`thth topics` が読み書きしているのは `state/topics.json` の 1 ファイルですが、
**中身は 2 種類**です。

| | 何を書くところか | 誰のものか |
|---|---|---|
| **観測**（`audience`・`kind`） | **その語の場に誰がいたか・何の話をしているか** | **全アカウント共有** |
| **判断**（`verdict`） | **その語がうちに合うか**（`alive` / `mismatch` / `dead`） | **記録した account のもの** |

**分けてある理由**は、`お茶` が分かりやすいです。

- **観測**: 「茶葉・淹れ方・茶器の話をしている人がいる」——**どのプロジェクトから見ても同じ**
- **判断**: 茶葉を売る kopicha には **合う**。苦味の研究をする nigamilab には **合わない**

**「誰がいるか」は共有できるが、「合っているか」はプロジェクトごとに違う。** これが
設計の芯です（設計 §4.2・§8）。

### あなたがやること

```bash
thth topics <account> --note <語> \
   --verdict alive|mismatch|dead|unknown \
   --status ok|empty|permission_denied|unavailable|rate_limited|partial \
   --kind 行動|年度付き|一般名詞|カテゴリ|抽象|専門語|固有名|つながり型|自作 \
   --audience "誰がいたか" --by "<あなた>"
```

**`--account` は `<account>` の位置で自動的に入ります。** 判断はあなたのものとして
記録され、**他のアカウントの当たり率には混ざりません。**

**`--status` を省かないでください。** これが **「取りに行って 0 件だった」（`empty`）**と
**「引けなかった」（`permission_denied` など）**と**「まだ見ていない」（省略）**を
分けます。**`dead`（人がいない）と `empty`（取れて 0 件）は別のこと**です。

**この一覧がずれていないかは、テストが見ています**
（`tests/test_value_domains_shown.py`）。**型や判定を足したら、この文書も直さないと
テストが落ちます。** 一覧の正本は `thth topics --help` です。

## 2. **信じてよいこと / 信じてはいけないこと**

### 信じてよい

- **`thth topics <account> --advise` の「適合判断」は、あなたの account の判断だけ**で
  数えています。**自分がまだ判断していない語では**、他 account の判断が**参考として
  別に出ます**（分母に入りません）。**判断済みの語の行には出ません。**
- **実測（views）は、出所と実経過時間が揃ったものだけ**を比較に使っています。
  揃わなかったものは**捨てずに「比較に使えなかった N 件」として出ます。**
- **`--advise` の観測は、観測者ごとに全部並びます**（2026-09-12 夜に変えました）。
  1 語につき**画面は 2 件＋「ほか k 件」**（総数 − 2）、`--json` は `observations`
  （最大 5 件・新しい順）と `observations_more`（**`--json` に載せなかった件数＝
  総数 − 5**。画面の「ほか k 件」とは基準が違う別の数です）。**全部は
  `thth topics history <語>`** で読めます。
- **観測の出どころは 3 通りに書き分けてあります。** 他 account の観測なら
  `（**acct** の観測）`、自分の観測には何も付かず、account の記録が無ければ
  `（account の記録なし）`と出ます（`（**asmon-kanto-threads** の観測）` のように）。
- **打ち消した行は、どの読み口にも出ません**（`--advise` / `suggest` の証拠 /
  型ごとの集計）。**行は消えません**——`history` に「打ち消し済み」として残ります。

### 信じてはいけない

- **「参考（比較には使えません）」の行の中央値。** 経過時間がばらばらの投稿を
  混ぜた数です。**同じ行に `経過 3.0h〜332.2h` のように幅が出ている**ので、
  **幅が広ければ比べられません。**
- **`thth topics <account>`（`--advise` なし）の views。** これは**打った瞬間に
  API から読んだ値**で、台帳の 24 時間時点の数とは**別の数**です。画面の先頭に
  そう書いてあります。**並べて比べないでください。**
- **他 account が書いた `audience` の中の「実績」。** §3 を読んでください。
- **`--advise` の画面に出ている 2 件が全部だとは限りません。** 3 人以上が
  書いていれば「ほか k 件」と出ます。**数えるときは `history` か `--json` を
  見てください。**

## 3. 穴 1: **共有の棚に、account 固有の話が書かれています**

実際にこういう行があります。

```
中学受験［行動］ — 受験親のやりとり。自アカウントの既存 6 投稿が全部この語で views 202〜574
```

- 前半「受験親のやりとり」＝ **共有できる事実**
- 後半「自アカウントの 6 投稿が 202〜574」＝ **その account の実績**

**後半が共有の棚に乗っています。** あなたがこれを読んで「この語は伸びる」と受け取ると、
**他所の実績を自分の見込みにしたこと**になります。

**しかもこの数字には、いつ測ったかも、経過時間も書かれていません。**
（実際、この「202〜574」は**経過 12.8〜13.8 日の累計**で、経過の短い投稿とは
比べられません。2026-09-12 に判明しました。）

### なぜそう書かれるのか

**書いた人が悪いのではありません。置き場が無いからです。**

実績を書く正しい場所（実測の台帳）は**数字しか置けません**。「6 投稿が 202〜574
だった」という**話**を書く場所が、いまは自由文の欄しかありません。

### いまどうなっているか

- **2026-09-12 に、`audience` を出すときは必ず「誰が書いたか」を添えるようにしました。**
  他所の実績だと**見れば分かります。**
- **同じ日の夜に、観測者ごとに全部並べるようにしました**（§4）。他所の実績を
  書いた行が、あなたの観測を**押しのけることはもうありません。** どちらも並びます。
- **文面から機械で見分けることはできません。**「受験親のやりとり」と「自分の 6 投稿が…」を
  区別するプログラムは書けません。**だから、並べて出どころを見せるところまでが道具の
  仕事**で、読み分けはあなたの仕事です。

### あなたにお願いしたいこと

**`--audience` には「その場に誰がいたか・何の話をしているか」だけ書いてください。**
**自分の投稿がどうだったかは書かないでください。** 実績は台帳（`thth measured`）に
あり、そちらには出所も経過時間も付いています。

## 4. 穴 2（**塞ぎました**）: 観測は「最後に書いた人が勝つ」——**だった**

**2026-09-12 夜に直しました。** 以前は `state/topics.json` を語ごとに最後の 1 行だけ
読んでいたので、**あなたが `コーヒー` の観測を書き直すと、前に書いた人の観測が画面から
消えていました**（行は残るのに、読まれるのは 1 行だけ）。

**いまは観測者ごとに最新を 1 行ずつ、全部並べます。**

- **観測者の鍵は `account`**。無ければ `by`、それも無ければ `(記録なし)`。
  **同じ人が `--account` 有りと無しで書くと、2 人に数えられます**（`account` と `by` は別の鍵）。
  「ほか k 件」を人数として読まないでください（監査 1・2026-09-12）。
- **同じ観測者の古い行は代表になりません**（その人の最新だけが並びます）。
  古い行は消えず、`thth topics history <語>` で全部読めます。
- **画面は 1 語 2 件まで**（＋「ほか k 件」＝総数 − 2）。`--json` は `observations` に
  最大 5 件と `observations_more`（**`--json` に載せなかった件数＝総数 − 5**。画面の
  「ほか k 件」とは基準が違う別の数です）。**観測者が増えると 1 語の行数が増えるので、
  上限を置きました。**

```bash
thth topics history コーヒー          # 全観測者・全行（新しい順）
thth topics history コーヒー --json
```

**`--json` の鍵が変わりました**（設計 v1.0.0 §1 規則 4）。

| 旧 | 新 |
|---|---|
| `audience`（**廃止**） | `observations[].audience` |
| `audience_account`（**廃止**） | `observations[].account` |
| `audience_by`（**廃止**） | `observations[].by` |
| —— | `observations[].note_id` / `checked_at` / `status` / `kind` |
| —— | `observations_more`（画面に出していない件数） |

**名前を変えたのは意図的です**（規約 5）。**据え置くと、古い読み手が「1 語 1 観測」の
つもりで読み続けます。**

### あなたにお願いしたいこと

**自分が現物を見ていない語の観測を、書き加えないでください。**

**「古い」ことと、「確かめていないものを足す」ことは別です。** 前者は古いだけですが、
後者は**確かめていないものが共有の棚に並びます**（もう上書きにはなりませんが、
**あなたの名前で 1 行増えます**）。

観測を書くのは、**実際にブラウザでその語を開いて、誰がいるかを見たとき**だけに
してください（`https://www.threads.com/search?q=<トピック>&filter=topic`・要ログイン）。

## 5. 穴 3（**塞ぎました**）: 間違えて記録すると消せない——**だった**

**2026-09-12 夜に打ち消しの口を入れました。** 観測者ごとに並べると、**誤記録は
「その観測者の最新」として残り続けます**——以前は後から上書きすれば画面から消えたので、
**並べるようにしたぶん、消えにくくなりました。** だから一緒に入れました。

```bash
thth topics --note テスト --verdict dead --by 運用
#   記録 ID: sha256:1f0c…（記録すると返ります）

thth topics retract-note sha256:1f0c… --reason "値域を試した誤記録" --by 運用
```

- **`--reason` と `--by` は必須**です（なぜ・誰が打ち消したかを残します）。**`--by` は
  環境変数 `THTH_ACTOR` でも指定できます**（省略するとそちらを見ます）。
- **行は消えません。** 打ち消しの行が 1 本増えるだけで、`topics.json` の行数は
  減りません。`thth topics history <語>` に「**打ち消し済み**」の印つきで残ります。
- **読み口からは全部消えます**——`--advise`（画面・`--json`）、型ごとの集計、
  `suggest` が読む参考観測、判断（`judgment`）、型（`kind`）。
- **記録 ID（`note_id`）は行の中身から決まります。** だから `note_id` を持たない
  古い行にも、読むときに同じ ID が付きます。**昔の誤記録も打ち消せます。**
- 二度は打てません（すでに打ち消してあれば、そう言って断ります）。

**`thth topics retract` は別の棚**（構造化の `observations`）のもので、**こちらには
効きません。** 語の棚は `retract-note` です。

**`history` / `retract-note` という名前の account があると位置引数の形は曖昧で断られます。**
そのときは `--history <語>` / `--retract-note <note_id>` のフラグ形を使ってください（監査 1・2026-09-13）。

**台帳が壊れているときは、読むのも書くのも rc=2 で止まります**（「トピックの台帳が壊れています」）。
以前は「記録はありません」と偽り、次の記録で全行が消える形でした。`history --json` と `--advise --json` の
`shelf_broken_rows` は、形が合わず読めなかった行の数です。0 でなければ `state/topics.json` を人が見てください。

**それでも、試すときは本番に打たないでください。** 値域を知りたいだけなら
`thth topics --help` で全部出ます（そちらが正本です）。

## 6. 穴 4: **人が増えると壊れます（測りました）**

いまの棚は **1 ファイルに全アカウント・全語・全履歴**を入れ、**読むたびに全部読み、
書くたびに全部書き直します。**

| 規模 | ファイル | `--advise` 1 画面 | 記録 1 件 |
|---|---|---|---|
| **いま**（4 アカウント・50 語） | 0.1 MB | **0.0 秒** | 一瞬 |
| 20 アカウント・200 語 | 2.3 MB | **1.0 秒** | — |
| 100 アカウント・500 語 | **28.7 MB** | **13.4 秒** | **0.70 秒** |

**書き込みは鍵を握ったまま行います**（2026-09-12 に、同時実行で記録が消えるのを
防ぐため入れました）。100 アカウント規模では **1 件 0.70 秒 × 待ち上限 5 秒＝同時に
7 人まで**しか通らず、**残りは断られます。**

### もっと本質的な壊れ方

**「誰がいるかは共有の事実だから 1 枚のメモでよい」という前提が、人が増えると
成り立ちません。**

- 同じ `コーヒー` でも、**豆屋・焙煎家・研究者で「誰がいるか」の読みが違います。**
  どれも間違いではありません
- **これは §4 で塞ぎました**（観測者ごとに並べる）。**ただし塞いだのは「消える」
  ことだけ**で、下の 2 つは残っています
- **人数分だけ行が増えます。** 画面は 2 件で切っているので、**100 人いれば
  「ほか 98 件」**になります。**選ぶ材料としては役に立ちません**
- **知らない人の観測を信じる理由もありません。** いまの仕組みに「誰を信用するか」は
  ありません

**判断はアカウントごとに分けたのに、観測は分けていません。** 4 アカウントで、しかも
中の人が同じうちは成り立ちます。**ジャンルが被る他人同士では成り立ちません。**

**さらに現実には、100 人なら 100 個の別インストールになります。** そうすると
`state/topics.json` は各自のものになり、**共有は最初から起きません。**

**つまり「共有の棚」が機能するのは、いまの「同じ VM・同じ repo・中の人が同じ
4 アカウント」という条件の下だけです。**

## 7. 困ったときに見るもの

| 知りたいこと | 打つもの |
|---|---|
| いまの語と判断 | `thth topics <account> --advise` |
| これから出す本数がどの語に賭かっているか | `thth topics <account> --plan` |
| 型ごとの傾向 | `thth topics <account> --learned` |
| **その語を誰がどう見たか（全観測者・全行）** | `thth topics history <語>` |
| **誤記録を打ち消す（消さない）** | `thth topics retract-note <note_id> --reason … --by …` |
| 実測の生データ | `thth measured <account>` |
| 返信 | `thth replies <account>`（取り直すなら `--refresh`） |
| **`thth topics <account> --plan` でも、自分の判断が無い語の観測には `・<観測者> の観測` が付く**（2026-09-12 夜。開発セッションがいま実装中。出力は `**未確認**（<audience>・<観測者> の観測）` の形） | `thth topics <account> --plan` |

**数字を根拠にするときは `--json` を見てください。** 人向けの表示は読みやすさを
優先していますが、**`--json` には分子・分母・単位・除外の内訳が構造化して入ります。**
