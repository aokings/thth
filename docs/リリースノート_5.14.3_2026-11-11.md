## 直したこと

- **道具が口座の repo に打つ git では、自動の gc を走らせない**（`thth/gitopts.py`）
  - 部分 clone（`blob:none`）の repo で、git 2.43 の自動の gc が commit を消し、はてなの記事が `article_not_committed` で止まりました（11/7 asmon・11/11 kopicha とにがみラボ）。壊れたのは部分 clone の 3 つだけで、引き金は道具の commit・fetch・rebase のあとに走る自動の gc です。
  - 書き戻し・collect・運用通知・plaza・口座の報告の git に、`gc.auto=0` と `maintenance.auto=false` を付けます。
  - repo の設定は書き換えません。人が手で打つ git には効きません。
  - 決まった時刻の gc は置きません。壊しているのが gc 自身のためです。記事と台帳の repo なので、溜まるのは小さな object だけです。
- **投げる前に、履歴に欠けた commit が無いか確かめる**（`thth/writeback.py` の `history_damage`）
  - 同期の最後に HEAD から履歴を 1 度辿ります。git の索引（commit-graph）を使わずに辿るので、索引が残って commit の本体が消えた 11/11 の形も捕まえます（監査で見つかり、試験で再現してから直した）。commit が欠けていれば、壊れの形と直し方（reflog を空に → `git fetch --refetch origin` → `git commit-graph write --reachable`、直らなければ `thth report file`）を言って投稿しません。
  - commit-graph だけが古い（graph を使わなければ辿れる）ときは止めず、作り直し方を stderr に 1 行出します。
