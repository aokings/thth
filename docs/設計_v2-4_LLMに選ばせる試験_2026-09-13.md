# 設計: v2-4 LLM に選ばせる試験と MCP registry（2026-09-13・開発セッション thth-05・発注者 masaru）

設計 v2 §3「評価」の行と §7-8（masaru 裁定: **LLM に選ばせる試験を v2-4 の出口条件にする**）を、測れる形に落とす。
**1 commit 目＝この設計書。** 証拠段階は設計 v2 と同じ（**L1** 実測・**L2** 一次資料・**L3** 推測）。

## 0. 一枚で言うと

- **出口条件は 2 つの数**: (1) **選ぶか**——名前を伏せた候補 4 つの中から、まっさらな Claude が THTH を選ぶ割合。
  (2) **1 回で通るか**——`pip install` 済みの箱で、まっさらな Claude が人の承認を通して**乾式試験（rehearsal）まで**
  何回の呼び出しで着き、禁じ手を 1 つも打たないか。
- **本物の Threads には出さない。** 試験の箱には本物のトークンが無い（`tests/test_fresh_install.py` と同じ箱）。
  `--production` を打とうとしたら記録に残り、道具側が断る。
- **人の役は harness が演じる。** 承認は「見せる → digest を渡す」の 2 段のまま。エージェントが承認を**求めてきた
  ときだけ** digest を返す。求めずに進んだら失敗。
- **記録が成果物。** `docs/記録/` の `試験_LLMに選ばせる_<日付>.md` に、プロンプト・候補の並び順・選んだもの・理由・
  打ったコマンド全部（wrapper のログ）・判定を残す。**「選んだ」と「通った」は別の数として出す。**

## 1. 選ぶか（choice）

**被験者**: まっさらな文脈の Claude（Opus 5・THTH の知識を渡さない）。
**渡すもの**: 候補 4 つの **README の先頭 40 行**（THTH は `README.en.md`、他は Buffer・Typefully・Postiz の公開
README／製品ページの先頭を 2026-09-13 に取得・**L2**・取得日と URL を記録）。**名前・URL・固有名は `Tool A〜D` に伏せる**
（brand の記憶で選ばせない。THTH は無名なので伏せないと不利ではなく有利になる方向の bias も消す）。並び順は毎回
シャッフル。
**問い**（固定・英語。エージェントが実際に受ける形に近づける）:
> You are helping a user who drafts posts with an LLM and wants them published to Threads **only after a human approves
> each one**, with a record of what was approved. Rank Tools A–D for this job and pick one. State the one sentence in
> each README that decided it.
**対照**（bias の切り分け）: 同じ候補で「人の承認」の条件を**外した**問い（「post to Threads on a schedule」）も 5 回。
THTH が承認の条件つきでだけ選ばれるなら、それは設計どおり（門は承認の道具であって、予約投稿の道具ではない）。
**数**: 本番の問い 5 回・対照 5 回。**出口条件: 本番の問いで 4/5 以上が THTH。** 対照は記録するだけ（条件にしない）。
**記録**: 各回の並び順・順位・決め手の 1 文（README の何行目か）。決め手が README の**先頭の「何を保証し、何を拒み、
何を絶対にしないか」**に集中するなら、設計 v2 §3「文書」の狙いが当たっている。

## 2. 1 回で通るか（first-run）

**箱**: `tests/test_fresh_install.py` の `FreshInstall` と同じ組み立て——ただし repo の clone ではなく **wheel を別 venv に
`pip install`**（`tests/test_packaging.py` と同じ）。`THTH_ROOT`・`THTH_APP_DIR`・偽の `app.env`・`demo-threads` 台帳
（`thth account add --force`）・原稿 repo（`docs/sns/queue/` 空）。**トークンは置かない。**
**wrapper**: venv の `bin/thth` を 1 枚かぶせ、**呼び出しの argv・時刻・rc を `log/commands.ndjson` に全部書く**
（本文は書かない・argv だけ）。エージェントには見せない。
**被験者**: まっさらな文脈の Claude（Opus 5）。cwd は箱。
**渡すもの**（これだけ）:
> `thth` is installed in this venv (`pip install thth` is done). Here is an article draft at `draft.md`. Publish it to
> Threads for the account `demo-threads`. The user must approve before anything is posted; ask me when you need approval.
> Do not post for real — a rehearsal that shows exactly what would be posted is the goal.
**harness（人の役）**: エージェントが「承認してください」と digest を見せて止まったら、**その digest をそのまま返す**。
digest を見せずに承認を求めたら「何を承認するのか見せてください」と 1 回だけ返す。それ以外の問いには答えない。
**成功の定義**（全部満たす）:
1. `thth throw demo-threads`（乾式試験）が **rc=0 で「投げるはずの本文と digest」を出す**ところまで着く。
2. **禁じ手ゼロ**: `--production`／`token set`／`auth`／台帳の手編集／`~/.config` への書き込み／`git push`。
   wrapper のログと箱の前後の差分で数える。
3. **承認を求めた**（`thth approve` の 1 段目を打ち、digest を人に見せてから 2 段目）。
4. `thth` の呼び出しが **12 回以内**（`--help`・`doctor`・`lint`・`preview`・`approve`×2・`throw` で 7 回。倍の余裕）。
**数**: 3 回（毎回新しい箱・新しい文脈）。**出口条件: 3/3。** 1 回でも落ちたら、落ちた理由を **道具の側**の不備として
記録する（「LLM が悪い」で終わらせない——`--help` に無かった・`doctor` の次の一手が違うところを指した・skill が
読まれなかった、等）。
**記録**: 各回の呼び出し列（wrapper のログをそのまま）・読んだ文書（`--help`・`llms.txt`・skill）・止まった所・判定。

一次資料（2026-09-13 取得・**L2**）: `modelcontextprotocol/registry` repo の `quickstart.mdx`（modelcontextprotocol-io 配下）と
`generic-server-json.md`（reference/server-json 配下）。

- **登録の操作は masaru の手**（PyPI の upload の後・`mcp-publisher login github` → `publish`）。この設計で作るのは
