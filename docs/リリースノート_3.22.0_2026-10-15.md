# リリースノート 3.22.0（Bluesky・Mastodon の言及を保存・Bluesky の取り下げと返信の制限・招待を Mastodon にも）

2026-10-15。[点検_絞りすぎ_2026-10-15](点検_絞りすぎ_2026-10-15.md) の (B) のうち、3.21.0 で入れなかった中・弱の段（B-15・B-19・B-20・B-21・B-28）。B-29（観測の地図を既定で動かす）は masaru の判断待ちなので触っていない。**他人の投稿を保存しない**決まりは、言及の inbox（B-15）のほかは変えていない。

## 言及を 3 媒体とも保存する（B-15）

- Bluesky・Mastodon の言及も、Threads と同じく `data/sns/inbox/<YYYY-MM>.ndjson` に保存し、返信の門（queue の `reply_to: <message_id>`）に載せる。それまでは求められたときに表示するだけだった。媒体の原文に保存を禁じる条は無い。
- Bluesky は言及と引用（返信は返信の台帳に入るので inbox には置かない）。Mastodon は公開・未収載の言及だけ（DM に近い可視性は今までどおり読まない・B-27）。通知の種類は `mention_kind` に残る。採取は 10 分ごとなので、直近 3 日だけを引き、重複は `message_id` で除く。
- プライバシーの文（英・日）の「Bluesky と Mastodon の言及は保存しません」を直した。

## Bluesky の取り下げ（B-19）

- `thth retract` が Bluesky でも動く（それまで「未対応」）。一次資料（bluesky-social/atproto の lexicon `com.atproto.repo.deleteRecord`・`getRecord`）を 10/15 に読んだ。deleteRecord は「無い記録を渡しても成功」で返るので、先に getRecord で在るかを見る（無ければ `post_missing`・deleteRecord は呼ばない）。自分の repo の `app.bsky.feed.post` の uri だけを受ける。その投稿の threadgate も消す。

## Bluesky の返信の制限（B-28）

- 原稿の `post_options` の `reply_control`（Threads と同じ語: `accounts_you_follow`・`mentioned_only`・`followers_only`・`parent_post_author_only`・`everyone`）が Bluesky でも効く。`app.bsky.feed.threadgate`（lexicon を 10/15 に読んだ）を、投稿と **1 つの `com.atproto.repo.applyWrites`** で作る（投稿は出たのに制限が付かない、が起きない）。rkey は TID（仕様 specs/tid）で VM が作る。
- 返信には付けられない（threadgate は根の投稿だけ）。付けた原稿は何も送らずに `unsupported_attachment: bluesky/reply_control_on_reply` で断る。

## 招待を Mastodon にも（B-20）

- `thth admin invite create --media mastodon --instance https://<サーバー> --project … --by …`。押されたら常駐がそのサーバーに THTH の client を（無ければ）登録し、本人はそのサーバーで認可する（S256・戻り先は thth.me/callback/）。口座の handle は認可した人の acct から。同じサーバーの同じ人に 2 つ目は作らない。
- 招待のページ（thth.me）は媒体の名前とサーバーを出す。Worker は Mastodon の招待の認可 URL を「招待を作ったときのサーバーの /oauth/authorize で、戻り先が thth.me/callback/」だけ通す。
- **Bluesky はまだ招待しない。** App Password を thth.me のページで受けることになり、招待のページの「トークンはこのページを通りません」が崩れるため。入れるなら atproto の OAuth で（別の段）。

## 招待の口座を timer に載せる口（B-21）

- 運営者の CLI だけ: `thth account set <口座> scheduled true --by <名前>`。招待の口座は `scheduled: false` で作られ、予約と猶予が `schedule_unavailable` で断られていた（直すには ssh で JSON を書き換えるしかなかった）。timer の置き方（`thth systemd <口座>`）を同じ画面で言う。`false` に戻すのは猶予（`hold_minutes`）が 0 のときだけ。MCP と thth.me の口からは変えられない。

## 出し方

Worker（招待のページ・招待の Durable Object・プライバシーの文）を先に deploy し、VM はあと。古い Worker に新しい VM から Mastodon の招待を作ると `invite_registration_rejected`（Worker が `media: mastodon` を断る）。
