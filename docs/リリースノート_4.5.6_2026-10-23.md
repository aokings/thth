# リリースノート 4.5.6（原稿に「出さない期限」を書ける）

2026-10-23。関東（asmon-kanto-threads）が、学校説明会・文化祭・体育祭など、受験を考える小学生が参加できる行事を配信し始めます。行事には日付があります。予約が詰まって遅れたり、口座が止まったり（10/23 の kopicha は inflight で 1.5 時間止まりました）すると、終わった行事や締め切った申し込みを告げてしまうおそれがありました。いままでの THTH には原稿の期限が無く、`publish_at` は「この時刻より後に出す」だけでした。構想 5.0 §4.6 の「出さない期限」を、5.0 を待たずに足しました。

## 変わったこと

- **queue の原稿の front-matter に `not_after:` を書けます**（任意）。`publish_at` と同じ形（`+09:00` 必須）です。**この時刻を過ぎたら、THTH はその原稿を出しません。** 書かなければ今までどおりです。

  ```markdown
  ---
  thth: 1
  account: asmon-kanto-threads
  publish_at: 2026-10-24T08:00:00+09:00
  not_after: 2026-10-25T10:00:00+09:00
  status: draft
  ---

  ## threads

  あす 10 時から〇〇中学の説明会です。予約はお済みですか。
  ```

  例: 25 日 10 時に始まる説明会の案内を 24 日 8 時に予約しておくと、予約が詰まって 25 日 10 時を過ぎてしまったときは出ません。申し込みの締め切りの案内なら、締め切りの時刻を `not_after` に書きます。
- **期限は承認の指紋（digest）に入ります。** 期限を延ばしたら承認し直しです。期限を書いていない原稿の指紋は 1 バイトも変わりません（いま承認済みの原稿で、承認し直しが要るものはありません）。
- **lint**: 形が違う・`publish_at` より前なら誤り（`invalid_not_after`）。今より前なら警告で、承認はできますが出ません。はてなブログの配信原稿には使えません（誤り）。
- **`thth approve` の 1 段目**に「期限      : 出さない期限 2026-10-25 10:00」と出ます。過ぎていれば「期限を過ぎているので確定しても出ません」と出ます。
- **出す道のすべてで見ます**: timer（`thth run`）・`thth throw`・承認の場の送り（返信）。
  - 過ぎた原稿は書き換えません（approved のまま残ります）。口座も止めません——その原稿を外して、次の原稿へ進みます。
  - **公開の直前にもう一度見ます。** Threads は container を作ってから公開まで待ちます。その間に期限をまたいだら公開しません（公開要求を送らない・inflight は消す）。run の始めに選んだあと、返信を出していた間に期限を過ぎたときも同じです。
  - 添付つきの原稿: 添付を上げる前に過ぎていれば同じく出しません。添付を上げて container を作ったあとにまたいだときは、今までの「公開の前に止めた」と同じ `media_held`（inflight を残す）になります。媒体には出ていないので `thth inflight <口座> resolve --not-published` で解きます。
- **連投（`thth: 2`）**は根の front-matter の `not_after` を見ます。途中の段で過ぎたら残りの段は出しません（実行は止まり、期限を延ばして承認し直せば同じ実行の続きから出ます）。期限を過ぎて止まった束は次の run から候補にしないので、1 本の原稿の道を塞ぎません。
- **出なかったことが見えます**:
  - `thth queue`: 「いま出ない: <原稿> — not_after_passed（出さない期限を過ぎたので出しません）」
  - `thth schedule`: 「← 出さない期限を過ぎました（出しません）」。`--json` の行に `not_after`・`expired` が増えます。
  - board・`thth morning`・死活通知: 承認済みなのに出られない原稿（held）の新しい区分 `not_after_passed`（例 `approved_but_held: not_after_passed 1`）。
  - `thth events`: 新しい種類 `not_after_passed`。起きた時刻は期限、`ref` は原稿の名前、`not_after`・`publish_at` が付きます。`by_kind` に 1 つ増えます。
  - runs: 公開の直前に外したときは `skip`・`not_after_passed` の行が残ります。
- **thth.me の道と MCP**: `thth schedule <口座> --text … --at … --not-after …`（遠くの道）と、MCP の `thth_draft_put` の `not_after` で下書きに書けます。期限を過ぎた下書きは予約しません（`invalid_draft: not_after_past`）。

## 受け取る側（関東・各窓口）

- 期日のある原稿には `not_after` を書いてください。行事の始まり、または申し込みの締め切りです。書かないと、今までどおり遅れても出ます。
- held の区分が 1 つ増えました（`not_after_passed`）。期限を過ぎた原稿は、要らなければ取り下げ（`status: withdrawn` か削除）、出し直すなら `not_after` を直して承認し直してください。取り下げるまで held に名前が残ります。
- events の受け手は、`not_after_passed` を「出ないまま終わった」として読んでください（続いている状態ではありません。`event_id` は口座・原稿・期限から決まります）。

## 確かめた範囲

柵 `tests/test_v456_not_after.py`（14 本）。期限の前は出る・過ぎたら出ない・口座を止めず次へ・run の時刻で選んでも壁時計で過ぎていれば出さない・公開の直前（container のあとの待ち）で期限をまたいだら公開しない・連投（候補から外す・途中の段で止める）・lint・指紋（期限の無い原稿の指紋が変わらない）・schedule と events と queue に見える・approve の 1 段目。実装を 1 つずつ壊して赤を見ました。指紋の golden に見本を 2 つ足しました（既存の行は変わっていません）。全件の試験も通しました。VM の本物の口座では、まだ動かしていません。

## 監査で直したこと（Fable 10/23・読むだけの監査）

- Threads の本文だけの原稿で、公開の応答が分からず inflight が残ったあと、次の run の自己解決が FINISHED（出ていない）の同じ container を公開する道で、期限を見ていなかった。期限を過ぎていれば公開せず、inflight を解いて口座を先へ進める（runs に `not_after_passed`・`remote_finished_not_after`）。
- `thth schedule <口座> --draft <id> --not-after …`（thth.me の道）は、期限を黙って捨てて予約していた。`--draft` と `--not-after` は一緒に使えない、と断る（期限は下書きを置くときに付ける）。
- 残したこと: 添付つきの Threads で、container を作ったあとの待ちの間に期限をまたぐと `media_held` で inflight が残り、`thth inflight <口座> resolve --not-published` で解くまでその口座は止まる（出てしまう側ではなく止まる側）。
