## 1. いま動いているもの: 2.11.0（Codex 実装中）

秘密を人が触らない auth。預かり所（thth.me・Durable Object）・Mastodon の自動登録・X の auth・`app set --by`・`token set --stdin` の Bluesky 対応。Claude が担うのは預かり所の deploy（masaru の一言）と監査・配布。masaru が担うのは X の開発者ポータルで App を作ること（急がない）と、配布後の kopicha-mastodon の `thth auth` による入れ直し。

## 2. 3.0 までに要る設計（まだ書いていない）

1. **X の adapter（2.12.0 候補）**: 投稿・返信・自分の投稿の実測（views は取れる）・`where`／`mentions`。**費用の裁定が先**（現行の X API は従量課金。読み取りの量をどこまで許すか、masaru の裁定）。auth の骨は 2.11.0 で揃う。
2. **Bluesky の atproto OAuth（DPoP）**: 2.11.0 で延期。client metadata の配信・PAR・DPoP 鍵の管理・全 API 呼出しへの DPoP。Python の依存ゼロを守るなら暗号は `cryptography` の任意依存にするか、標準ライブラリで足りる範囲に限るかの裁定。
3. **C3／C4（Meta Platform Terms・据え置き中）**: C3 = 絡んだ他人の枝の 24h／72h 観測、C4 = 語の 1 日 1 回の観測。`docs/照合_MetaPlatformTerms_枝と語の観測_2026-09-18_Codex.md` の保留（生データを保存しない実装が未実装・削除追随の方式が未定義）。App Review の結果が出てから、規約の照合をやり直して裁定。3.0 に入れるかは masaru。
4. **共有型か道具型か**: いまは道具型（各自が自分の Meta アプリを登録し、thth.me は秘密を持たない預かり所だけ）。3.0 の導入文書はこの前提で書く。共有型（masaru のアプリで他人も認可）は App Review・費用・責任が masaru に集まるので、3.0 では採らない——この裁定を文書に固定する。
5. **配布物の署名**: tag に署名（GitHub の署名 commit か sigstore）し、VM の selfupdate が検証して `board` に「署名: 確認済み」を出す。小さい版で先に。
