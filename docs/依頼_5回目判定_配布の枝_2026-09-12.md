## 2. 直し方（出力契約の変更）

**board は取りに行きません。だから「いま」を言いません。**

    道具: <head>  配布の枝: `release`
      最後に記録された取得試行: 2026-09-12T08:10:00+09:00（成功）
      そのとき記録した配布参照 abc1234 と一致しています
      **現在の remote の配布状況は、この画面では確認していません**

**記録が更新も削除もできず古い成功が残っていても、この文は嘘になりません**
——「そのとき、こうだった」しか言っていないためです。

失敗記録が読めるときは、そのまま出します。

      最後に記録された取得試行: <時刻>（**失敗**——<理由>）
      **いまの配布状況は未確認です**

**F1（先行の警告）は維持**しています。`ahead` があれば遅れより先に出します
（「そのとき記録した配布参照より N commit 先」と、比較の基準を明示した上で）。
**F4（試行時刻の表記）も維持**しています。

### JSON

**鍵の名前ごと変えました**（規約 5）。`behind_release` のままだと、**古い読み手が
「remote に対する現在の遅れ」として読み続けます。**

| 旧 | 新 |
|---|---|
| `behind_release` | `behind_cached_release` |
| `ahead_of_release` | `ahead_cached_release` |
| — | `comparison_basis: "cached_ref"` |
| — | `remote_current_verified: false` |
| `release_check` | （そのまま） |

**`remote_current_verified` は board では常に `false`** です——board は取りに行かない
ので。**定数でも出します**。これが無いと、`behind_cached_release: 0` だけを読む
読み手が同じ結論に戻ります。

**「常に何も分からない」にはしていません。** 時刻・参照 SHA・比較数は残ります。
**分かる範囲を保存時点に限定した**のであって、情報を捨てていません。
