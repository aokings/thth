## できあがりの条件

1. **台帳を repo の中に置く。** フォルダ名はレーンで決めてよい（こぴちゃは `register/`）。中身は、今の `data/` と `schema/` のうち宣言の置き場に当たるファイルと、`.thth/` の宣言。宣言は THTH の `tools/register_decls/nigami/` を写す（`kinds/`・`outlets.json`・`constitution.json`）。写したあとは、にがみラボの物が正本になる。
   - 台帳は repo の今の commit から作る。外の写しから材料を書き戻さない。
   - 写しの作り方の見本: THTH の `tools/register_stage11_nigami_shape.py` の `build_ledger`。
2. **出し口は 2 つ、どちらも書き出し先は repo の根**（`dest: "."`）。`data/published-urls.txt` は関門の控えなので、両方の出し口で `ignore`（宣言に書いてある）。
3. **基準を、向き替えの commit で取る。** `judge --baseline --outlet site` の数と commit を、判断の記録と封に書く。写しでは 36,796 件。記録の数が 1 割より多く違えば、封の前に止めて本線へ。
4. **最初の封のあと、repo の根が元と 1 バイトも違わない**こと（`diff -rq` で違うのは台帳のフォルダだけ）。**build した頁が前と同じ**こと。**公開した URL が 1 つも減らない**こと（`data/published-urls.txt` と照らす）。違えば止めて本線へ。
5. **入口の文書に正本を書く。** 根の `data/` と `schema/` は書き出した写しで、直すのは台帳の中、と 1 段落。
6. **配信の関門に確かめを足す。** にがみラボには GitHub の CI が無く、配信は `scripts/ops/deploy.sh` → `gates_main.sh`。ここに `thth register verify <台帳> --outlet all --material .` と `export --check` を足し、赤なら配信しない（`--outlet all` は 5.22.0 から。それまでは site と tools を 1 回ずつ）。
   - 封の鍵: 配信もこの Mac で打つので、この Mac の持ち主の鍵（こぴちゃの段 10 で作った `~/.config/thth/register_seal.pem`）が、そのまま封と確かめに使える。**新しい鍵は要らない見込み。** 別の機械で配信するなら、そのときに本線へ（masaru の「はい」が要る）。
7. **書く道具の書き先を台帳に替える。** `data/` に直に書いている台本（`apply_translations_en.py`・`apply_upgrades.py`・`register_figure.py`・`gate_i18n_pairs.py` ほか。数はレーンで数える）を、台帳の中に書く形にする。根に直に書くと、次の確かめで赤になる（それが柵）。
8. **判断と封は、にがみラボのレーンの LLM がする。** masaru の手が要るのは、基準の 1 回だけ。

## 一緒に測ってほしい物（判定 11/29 の材料）

- **配信の前の人の確かめで、1 回に何を読んでいるか**を 1 回だけ数える（`hub approve` の承認 1 回で、masaru が見る物の数と種類）。器の封の差分（前の封から変わった記録だけ）を見せる形で、それがどれだけ減るかを比べる材料にする。
- **頁の道から台帳の記録の番号を引ける割合**を、向き替えた日に 1 回測る。頁の種類ごとに、引けない頁がどの種類かを名前で言えればよい。
- 向き替えのあとの普段の訂正 1 件で、人の手・器の命令・機械の秒・頁から外れた物を数える（こぴちゃの 10-6 の表と同じ物差し）。
