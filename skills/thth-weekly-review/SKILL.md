# THTH — 週の振り返り（thth-weekly-review）

THTH は数を並べるだけで、原因と次の手は出さない。決めるのはあなたと、あなたの持ち主（人）。回す輪は 2 つ:

- **シリーズの輪（毎週）**: 口座とシリーズ（`thth scenario` のシリーズ・札の無い原稿は「未分類」）ごとに、伸びた・止まった・落ちたを見て、次の週に変える所を 1 つ決める（型・時刻・本数・続けるかやめるか）。下の P → D → C → A。
- **糸の輪（糸ごと）**: 動いている糸は毎週、段が止まっていないかだけを見る。糸を閉じたら、宣言した仮説と結果を照らし、次の糸の種から次の糸を 1 つ選ぶ（下の「糸の輪」）。

- いつ: 週が閉じたあと。日曜の夜の投稿も 24 時間を越える**月曜の夜より後**に打つと、数が欠けずにそろう（それより前は未成熟の投稿が「数えていない」に並ぶ）。
- 何を: 口座 1 つなら口座の名前、まとめて見るなら project の名前。

```
thth review weekly <口座> --study <先週の施策JSON>
thth review weekly <project> --json
```

`--week <YYYY-MM-DD>` で過ぎた週を見られる（どの曜日でもその週の月曜にそろう）。材料は口座・シリーズ（`series`）・糸（`campaigns`）の 3 つの単位で並び、次の糸の種（`seeds`）も同じ束に入る。命令ひとつずつの詳しい使い方は skill `thth`、糸の段の型は skill `thth-flow`。

## P（計画）: 先週決めた変更を読む

- 先週の A で書いた施策 JSON を `--study` で渡す（何本でも）。材料の「先週の宣言（study）」に、変えた群と比べる前の群の本数と中央値の差が出る。単独で読むなら `thth study-report <施策JSON>`。
- 宣言が無ければ「宣言なし」と書いて C へ進む。次の A で 1 つ宣言する。

## D（実行）: 変更が原稿に入っているか

- `thth queue <口座>` と `thth schedule <口座>` で、宣言した期間に出た原稿と出る原稿を見る。宣言した変更（型・時刻帯・リンクの有無・goal・長さ）が、その期間の原稿に入っているかを 1 本ずつ確かめる。
- 何週も先まで承認済みの原稿を並べているときは、特にここで止まる。変更の始まりの日より後に出る原稿を直すか、始まりの日をずらして新しい施策 JSON で宣言し直す。
- 入っていない原稿が多かった週は、それも結果の 1 行に書く（変えていないものの効き目は読めない）。

## C（確かめ）: 材料を読む

上から順に読む。`--json` の欄の名を（）に書く。

1. **落ち込みの印**（`drop`・`drop_streak`・`drop_detail.signals`・まとめは `drop_units`）: 週の表示の和か、フォロワーの増えが、前の 2 週の平均の半分を切ったら立つ（シリーズと糸は表示の和だけ）。どの数がどれだけ（`value`・`previous_average`・`ratio`）かを読む。
2. **シリーズごと**（`series[].by_account`）: どのシリーズが伸び、どれが落ちたか。未分類が大きいときは、まず原稿に `series:` を付けると次の週から分かれる。
3. **週の並び**（`weeks`）: その週と前の 4 週。本数（根・自分への返信・他の人への返信）が減ったのか、1 本あたりが減ったのかを、1 本あたりの中央値（`per_post_24h`）と見比べる。
4. **当たりと外れ**（`top`・`bottom`）: 表示の上位 5 本と下位 5 本の原稿。型・topic・goal・時刻帯・リンクの有無・添付で、当たりに共通して外れに無いものを探す。
5. **層**（`strata`）: 型・時刻帯・goal・添付の種類（リンクは `link` の層）ごとの、その週と前の週の中央値。本数が少なく中央値が出ない層（—）の差は読まない。
6. **先週の宣言の結果**（`studies`）: 観測の差で、効き目の証明ではない。変えた群の本数が足りなければ「まだ言えない」と書き、同じ宣言をもう 1 週続ける。
7. **数えていない投稿**（`not_counted`）: 24 時間に満たない投稿と、24 時間の数が採れていない投稿。0 と読まない。多いときは数がそろってから読み直す。

媒体・口座をまたいで和や順位を作らない（材料も作らない）。

## A（次の手）: 1 つだけ決めて宣言する

- 次の週に変えるのは **1 つだけ**（型・時刻帯・リンクの有無・goal・長さのどれか）。同じ週に 2 つ変えると、どちらが効いたか読めない。
- 決めた根拠の数字を 1〜3 行添える（材料の欄の名と値。例「当たり 5 本のうち 4 本が朝・外れ 5 本のうち 4 本が夕」）。
- 宣言は期間の形で書く。始まりの日は次の週の月曜:

```
thth study add <施策JSON> --since <YYYY-MM-DD> --account <口座> --hypothesis <仮説> --change <変えること> --by <名前>
```

- 比べる前の群は、始まりの日の前の 7 日（`--baseline-days` で変える）。終わりを決めるなら `--until <YYYY-MM-DD>`（その日を含む）。
- 置き場の例: 各 repo の `study/<口座>/<YYYY-MM-DD>_<短い名>.json`。フォルダは先に作る。同じ名前のファイルには書かない（変更 1 つに JSON 1 つ）。次の週の P はこれを `--study` で渡す。
- 宣言したら、次の週に出る原稿に変更が入るように直す（D に戻る）。

## 糸の輪（キャンペーン）

- **動いている糸**（`campaigns[]` の `state` が active・stalled・done）: 毎週見るのは、段が止まっていないか（`stage`・`stalled`）と、その週の数（`by_account` の表示と返信・`this_week` のクリックと訪問）だけ。止まっていたら `next` の 1 行を進める。全部の段が済んだ糸（done）は閉じるかを決める。
- **閉じた糸**（`state: closed`）: `result` に宣言した段の結果と、糸の期間の本数・表示の和と中央値・クリック・訪問が、どの閉じた糸も同じ形で並ぶ。宣言の仮説（`goal_text`）と照らして「当たった・外れた・言えない」を 1 行で書き、ほかの閉じた糸と見比べる。
- **次の糸を 1 つ選ぶ**: 次の糸の種（`seeds`・`thth scenario seeds <project>` と同じ）から 1 つ。選んだ根拠の数を 1〜3 行添えて、宣言を `scenarios/<id>.md` に書く（書き方は skill `thth-flow`）。訪問の控えが無い（`site_visits_not_imported`）のは 0 ではない。

## 落ち込みの印が立ったら

- `drop: true` の週は、**その週のうちに本線へ伝える**（その project の SNS をまとめる人かセッション）。中身は、単位（口座・シリーズ・糸）・どの数がどれだけ下がったか・続いた週の数・当たりと外れの要点・次の週に変える 1 つ。
- 自分の判断で直せないこと（本数を大きく変える・型を総入れ替えする・媒体をやめる）は決めずに、本線と持ち主（人）に渡す。
- `drop_streak` が 2 以上なら、同じ手をもう 1 週続ける前に本線に相談する。
- 印は機械の比べで、悪いという判断ではない。前の週に跳ねた投稿があっただけの時もある（前の週の当たりを `--week` で見る）。

## 結果の 1 行を残す

- 自前の連絡の仕組み（hub など）が**あれば**、結果の 1 行を送る。例: `<口座> 11/16 の週: 表示 8,526（前 2 週の平均の 0.19 倍・落ち込み 2 週目）・次の週は <変えること>（<施策JSON>）`。
- 無ければ、運用の記録か施策 JSON の隣に同じ 1 行を書く。
- 変えた群が 24 時間を越えて結果が出たら、プラザに置くと同じ持ち主のほかの SNS が読める（置き方は skill `thth` のプラザの節）。

## THTH の外の仕事

毎週の起こし（月曜に口座ごとに `thth review weekly` を打ち、担当を起こす・`drop: true` の口座は本線も起こす）は、見張りの仕組みの仕事。THTH は材料を出すだけで、誰も起こさない。
